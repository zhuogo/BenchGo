# 项目设计

本目录保存项目当前及未来的目标设计，包括系统概述、愿景、产品目标、业务规则、页面交互和验收条件。初始化时仅提供本文档，具体模块随需求明确逐步建立。

## 设计与实现

设计呈现最新确定的目标形态，能力可能已经实现，也可能尚待开发。实际进度通过 `.draftgo/worklog.md` 和项目实例检查。愿景提供方向，本轮任务范围由用户需求确定。

变化时直接修订正文，保持一套有效设计；不并列维护原版与新版，不追加迭代流水账。正向描述应具备的能力，不设置“不做什么”清单。未确定的设想标为待明确，不能自行扩写成确定需求。

## 文档组织

- 产品目标明确后创建 `01 产品概述/README.md`，记录愿景、用户、场景和核心流程。
- 每个模块使用稳定编号的文件夹，例如 `02 客户管理/README.md`。编号用于定位，不代表优先级或开发阶段。
- 简单模块只需 README；复杂后按需拆出 `01 需求与规则.md`、`02 页面与交互.md` 等文件，不预建空目录。
- 公共规则出现实际需要后集中定义，模块通过链接引用。新增、移动或拆分文件时更新索引。
- 模块记录目标、流程、规则、验收条件和未决问题；按需补充数据关系、权限、依赖。需要追踪的需求使用稳定编号，供工作项引用。
- 动态接口契约通过 CLI 实时发现，不复制 schema、凭据或响应快照到文档。

## 页面与 UI

涉及页面的模块说明页面用途、路由、关键操作及加载、空数据、错误等状态。简单内容直接写入模块 README。

独立 UI 稿按需制作，用于确定视觉方向、复杂布局或用户要求的方案讨论。普通页面与小修改可以直接基于实际页面实现，不强制先画稿。

实际产生视觉资料时创建模块内 `UI/`，保存目标稿、原型、参考图或标注材料，并在页面说明中注明用途和对应页面。视觉稿与文字保持一致，不堆积中间版本。验收截图通过 CLI 的 `.draftgo/artifacts/` 机制保存。

描述位置模糊时，先定位页面、区域和具体元素；必要时利用实际截图标注候选并澄清。截图帮助定位和验收，不作为默认的整页重建依据。

## 阅读与维护

Agent 通过索引读取当前模块及相关公共规则，不默认加载全部设计或日志。用户最新明确要求与旧设计冲突时同步修订，有歧义才澄清。公共规则变化时检查受影响模块。

不得为了迁就实现擅自删减需求或降低验收条件。修复实现偏差无需修改正确设计。交付时核对设计与结果，将完成范围和证据写入 worklog。

## 工作记录与历史

`.draftgo/worklog.md` 是任务状态的唯一记录，保存设计引用、进度、阻塞、下一步和完成证据。Design 不重复维护进度看板。项目采用 Git 时由 Git 保存文档历史；Git 回退不自动回退实例资源。
