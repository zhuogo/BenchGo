# 模型与外部工具统一使用设计

状态：统一入口、原生 Harness 会话接入、订阅识别、按会话供应商路由、外部工具设置区和系统 Harness 生命周期管理已有实现基础；工具内登录引导、会话分支与跨工具记录呈现仍需按本文实施。本文描述目标体验，并标注当前边界，不把规划能力当作已实现。

## 产品定位

小角是多工具 AI 编程工作台。用户只安装小角，即可在同一入口使用 Codex、Claude Code、Pi、OpenCode 及其他已接入 Harness；小角统一提供项目、模型选择、会话列表、审批、停止、恢复和协作体验，底层继续调用各工具的原生 Harness 能力。

小角不要求用户先安装 DeepSeek Harness 或 CC Switch。DeepSeek Harness 是小角可使用的一个引擎来源，不是使用其他 Harness 的前置条件。CC Switch 等外部管理器可以共存，但不是小角的依赖。

模型与工具设置属于小角的独立产品层，Agent 委派属于会话运行层；两者在界面和服务契约上解耦。

## 首次使用路径

1. 用户安装并打开小角，进入工作台，不先要求理解 Harness、供应商或配置文件。
2. 小角自动发现系统中已安装的 Codex、Claude Code、Pi、OpenCode 等工具，显示真实路径、安装来源、版本、重复安装和登录状态；未安装工具提供官方安装方式的入口。
3. 用户创建项目或选择已有项目。
4. 用户选择工具、账号或供应商、模型，然后开始新会话。
5. 若选择官方订阅，小角引导用户完成对应工具的官方登录；若选择 API 供应商，小角在小角会话内完成配置并按会话注入。
6. 用户无需手动复制 API Key、设置环境变量或编辑各工具配置文件即可开始工作。

## 信息架构

工作台负责当前项目和会话：新建会话、选择工具和模型、查看消息与工具活动、处理审批、停止、恢复、归档和继续工作。

设置负责外部工具和模型资源：

- 外部工具：系统安装状态、真实路径、安装来源、版本、重复安装、登录状态、能力检测、默认快捷设置和原生工具入口。
- 供应商与模型：第三方 API 供应商、凭据引用、模型目录、协议兼容性和适用工具。
- 订阅账号：Codex、Claude Code 等官方登录状态，以及对应工具的登录/退出入口。
- 会话与记录：原生记录扫描范围、导入规则、隔离会话目录和记录共享选项。
- 高级同步：预览、备份、确认后写入原生配置；默认不自动同步。

设置区是工具配置的唯一用户入口，但不把所有工具的配置文件伪装成同一种格式；每个工具先显示检测与登录状态，常用配置由 BenchGo 内置，高级快捷项和原生 JSON 折叠展示，并标注真实能力、登录来源和可修改范围。

## 会话模型

每个小角会话都有小角会话 ID，并保存 tool、原生 session/thread ID、项目目录、模型、供应商路由、会话模式和状态。小角负责统一列表、搜索、状态、审批、停止、恢复和归档；Codex、Claude Code、Pi、OpenCode 继续负责原生上下文、工具协议和长期历史。

原生会话是可恢复的事实来源。小角保存关联关系和运行事件，不复制一份伪造的原生历史；原生记录缺失或损坏时显示明确原因，不自动创建替代会话。

同一原生会话同一时间只允许一个写入者。用户从终端或其他客户端正在运行同一会话时，小角只能只读观察、等待其结束或要求用户确认接管，不能静默抢占。

## 账号与模型供应商

模型选择器必须显示来源，不把官方订阅和 API 供应商混为一类：

- GPT · Codex 订阅：使用 Codex 官方 ChatGPT 登录。
- Claude · Claude Code 订阅：使用 Claude Code 官方登录。
- DeepSeek · 第三方 API：使用小角管理的 API 供应商凭据。

官方订阅由对应 Harness 提供认证和请求能力。小角可以发起官方登录、检查登录状态并在小角会话中调用对应 Harness，但不复制 OAuth 凭据、不把订阅转换成通用 API Key。

订阅有工具边界：Codex 订阅只能用于 Codex，Claude Code 订阅只能用于 Claude Code；未登录、登录失效、账号类型不匹配时拒绝创建会话，并提示用户回到对应工具完成登录。

第三方 API 供应商由小角统一管理。供应商配置保存供应商 ID、端点、凭据引用、模型和协议能力；密钥不进入会话列表、前端响应、日志或原生历史。

## 供应商切换与会话连续性

切换供应商不修改正在运行的会话，也不覆盖旧会话的模型和账号绑定。

同一 Harness 支持原生动态换模时，可以在当前会话切换模型；如果供应商、认证模式或原生上下文发生变化，则创建新的原生会话。

新会话可显示“从某会话继续”，并携带项目目录、用户确认的摘要或选定消息；它必须标记为新会话，不能伪装成跨供应商共享的原生上下文。旧会话保留，可随时回到原供应商继续。

## 原生配置与隔离

小角会话默认使用进程级环境、命令行覆盖或每会话隔离目录，不修改用户在终端中使用的工具全局配置。Codex 使用 `CODEX_HOME`，Claude Code 使用 `CLAUDE_CONFIG_DIR` 等会话级隔离变量；隔离的是小角会话配置，不是 Harness 可执行文件。小角内选择供应商或模型只影响小角创建的新会话。

用户安装小角前已有的 Codex、Claude Code、Pi、OpenCode 可以继续独立运行；其账号、默认模型、配置文件、插件和历史不因小角安装或正常使用而改变。

设置区可提供“同步到原生工具”作为显式高级操作：先展示将修改的文件、字段、当前校验和、备份方式和影响范围，用户确认后才写入；写入前再次检查外部变化，冲突时拒绝覆盖。恢复必须写入逆向备份。

小角不与 CC Switch 或其他管理器后台双向同步同一份配置。用户同时使用多个管理器时，谁执行了显式同步，谁就成为该次写入的来源；小角必须在下次读取时重新检测并提示外部变化。

## 记录可见性

- 官方订阅会话：使用对应工具的原生账号和历史目录，小角与原工具可以读取同一份记录。
- 导入原生会话：只建立小角索引和原生句柄映射，不复制历史；导入前必须确认原写入进程已停止。
- 小角 API 隔离会话：记录默认由小角管理的隔离目录保存，原工具不会自动看到；提供“在对应工具中打开”“导出摘要”或“共享目录”时，必须明确说明共享范围和并发限制。
- 小角事件记录：用于实时状态、审批和短期回放，不替代各 Harness 的长期历史。

删除小角列表项、归档小角会话、删除原生历史和删除项目文件是四个不同操作，界面不得合并为一个“删除”。

## 外部工具设置区

每个工具设置页固定展示以下信息：

1. 工具名称、官方入口、系统安装状态、真实路径、安装来源、版本、重复安装和能力状态。
2. 登录状态和账号来源：官方订阅、API Key、未登录或不可检测。
3. 小角会话默认方案：默认模型、推理强度、上下文/并发等已验证快捷项。
4. 原生配置状态：只读检测文件路径、存在状态、外部修改和最近一次同步时间，不默认展示密钥和完整文件内容。
5. 会话记录：原生历史发现、导入、隔离目录和共享说明。
6. 高级操作：登录、退出、按安装来源安装、更新、卸载、恢复、预览同步和备份管理。

设置页必须区分“保存小角方案”和“同步到本机工具”：前者只影响小角新会话，后者才可能改写原生配置。

## 工具差异与能力表达

小角统一入口不承诺各 Harness 功能完全等价。工具卡片和会话页应显示能力标签，例如是否支持动态换模、原生恢复、实时 steer、审批问题、历史发现和隔离配置。

不支持的能力必须明确提示并提供替代路径；不能把普通文本发送伪装成原生命令，不能把 API 供应商伪装成官方订阅，不能把“检测到配置文件”当成“已登录”。

## 数据与安全边界

小角数据目录保存会话索引、原生句柄、路由快照、幂等收据、短期事件和备份元数据；凭据由现有凭据服务或对应 Harness 管理。小角不维护 Harness 独立副本、专用安装前缀或副本凭据。

会话路由在创建时固化供应商、模型、协议和认证模式，后续修改默认方案不影响已有会话。会话恢复时重新验证路由和订阅状态，失效则拒绝静默切换到其他供应商。

## 系统 Harness 生命周期管理

BenchGo 完全参照 CC-Switch 的管理侧思路，管理用户系统中的真实 Harness 安装，不复制可执行文件，也不把 BenchGo 安装目录伪装成系统工具。发现结果必须包含命令解析后的真实路径、版本、安装来源、平台、可执行性和登录状态；同一工具存在多个安装时全部列出并标记当前命中路径、优先级和冲突。

安装、更新和卸载必须绑定已识别的安装来源。支持的来源适配器包括官方安装器/自更新命令、npm/pnpm/bun 全局包、Homebrew formula/cask、uv/uvx 及平台包管理器；适配器按平台能力清单启用，不能用裸 `npm install` 替代未知来源。安装使用工具官方推荐方式，完成后重新探测并返回路径、版本和来源。

更新只调用命中安装的原来源命令：npm 系列使用同一 Node/package manager，Homebrew 使用对应 formula/cask，官方原生安装使用其更新命令，uv 使用原环境；来源未知或无法确认归属时拒绝自动更新并给出原安装方式。更新前后均重新探测，版本未变化或路径变化必须报告失败/冲突。

卸载是针对具体安装实例的破坏性操作。先生成包含路径、来源、包名/公式、将执行命令和保留范围的预览，用户确认后再次探测并校验路径、版本和来源未变化，再执行来源适配器。未知来源、路径不在可确认归属范围、权限不足或探测结果变化时拒绝卸载。卸载只移除 Harness 安装本身，必须保留用户配置、账号/OAuth、历史、插件、项目文件和 BenchGo 会话索引；工具声明的官方清理动作也必须单独展示并确认。

生命周期操作具备互斥锁、超时、取消和幂等收据；完成后统一刷新工具目录和登录/能力状态。权限不足时提供用户可执行的官方命令或系统授权入口，不静默提权。Windows、macOS、Linux、WSL 分别记录路径和来源边界；WSL 工具与宿主工具视为不同安装实例，不跨环境卸载。CC-Switch 可共存，但 BenchGo 不读取其私有状态、不做后台双向同步。

## 当前实现与后续实施

已实现基础：Codex、Claude Code、Pi、OpenCode 原生会话接入；小角会话索引和原生句柄映射；官方订阅状态识别与工具边界；第三方供应商按会话路由；外部工具设置区的方案保存、预览、备份、显式应用和恢复；系统工具检测与复用；用量扫描与原生历史读取。同一 Harness 的会话分支复用 Harness 原生 fork。原生配置同步后保存文件校验和与时间，设置区只读提示后续外部修改，不自动合并或写回。

待实施或需完善：小角内统一发起 Codex/Claude 官方登录（当前可检测登录并提示用户回到对应 CLI 登录，不能把不同 Harness 的登录流程伪装成统一 OAuth）；供应商切换后的跨工具新会话、用户确认摘要迁移；隔离会话向原工具打开/导出的完整用户路径；官方安装器、自更新命令及更多平台包管理器适配；真实 Windows 全新安装、权限、WSL 和多工具并行使用验收。当前已落地 npm、uv、Homebrew 的来源探测与生命周期操作，未知来源保持只读保护。

CC Switch 仅作只读参考，当前参考 pin 为 `reference/cc-switch@7da2553`。借鉴其配置切换和管理器共存经验；BenchGo 保持小角会话路由与原生工具配置分离，显式同步增加外部修改提示，不引入隐式全局切换、双向同步或 CC Switch 运行依赖。

实现时不得修改 deepseek-harness/ 子模块源码；优先通过插件、服务和配置组合实现。涉及原生配置写入时，必须同步更新设置区文案、备份/冲突测试和工具兼容说明。

## 验收标准

1. 全新 Windows 用户只安装小角即可发现、安装或接入至少一个外部 Harness，并完成第一轮会话。
2. 已有 Codex/Claude Code 用户安装小角后，原终端命令、账号、默认模型和历史继续可用。
3. 小角内切换供应商不会改变运行中会话；旧会话可恢复，新会话显示真实供应商来源。
4. 官方订阅登录不泄露 OAuth，不转换 API Key，并且只能用于对应 Harness。
5. 小角 API 隔离会话不会覆盖原生全局配置；记录可见性和共享方式在界面中可理解。
6. 显式同步原生配置具备预览、校验和、备份、冲突拒绝和可恢复验证。
7. Codex、Claude Code、Pi、OpenCode 的差异能力、失败原因和未支持项均有明确反馈。
8. 工具管理能列出真实路径、来源、版本和重复安装；安装、更新按来源执行并在前后重新探测。
9. 卸载必须先预览、二次探测和确认；未知来源、归属不明、路径变化或权限不足时拒绝破坏性操作，并验证配置、账号、历史和项目文件保留。
10. BenchGo 不创建或维护 Harness 独立副本；会话级 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 隔离仍可用，且不影响用户原生工具。
11. Windows、macOS、Linux、WSL 的路径、权限和安装来源边界有明确提示；OpenAPI/MCP 的工具状态、安装计划、生命周期结果与本文字段一致。
