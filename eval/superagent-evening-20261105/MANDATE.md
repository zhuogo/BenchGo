## 失败状态保留补充（2026-11-05）

`attention-1-attempt-3` 的回答后续做出现 `UNAVAILABLE`，随后为 `EVIDENCE_UNVERIFIED`、resultVersion=0。原运行器无条件删除隔离目录；现存快照不能恢复原工单的持久会话，因此不得声称该次可原会话续做。

后续新运行把完整隔离状态放入该次证据目录的 `isolated-state/`，失败、异常或中断时保留，成功且主配置校验通过后才删除。状态可能含任务正文和其他敏感运行数据，不提交或共享；排障、续做和保留期限由操作者决定，确认无需续做后仅手动删除该次 `isolated-state/`。续做前必须先验证原 Ticket、Assignment、Run 和 session 均可恢复，不能以新单冒充。

恢复入口约束：加载器启动前只读核对保留数据库、原工单、唯一 Assignment、唯一 Run 和对应持久会话；不接受身份不完整或不一致的快照。恢复记录另存，不覆盖原始证据，沿用原配置并以内存注入现有凭据；只对明确处于 paused 的原工单调用正式恢复，其他状态仅观察后台原有调度，不重复回答、建单或调整。加载器启动可能触发后台调度，故恢复是会发模型请求的显式操作。无法核实持久身份、存在多个 Run 或非暂停状态需要主动干预时停止并保留，不宣称恢复成功。
