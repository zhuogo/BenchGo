# SuperAgent

BenchGo 总助手源码包 `@benchgo/superagent`，统一构建进 `benchgo-plugin`，不单独安装。

主聊天优先，项目聊天押后。以下说明模块入口；模块职责与详细设计入口见[SuperAgent 设计](../../docs/06-superagent/设计.md)，整体流程见[总架构](../../docs/总架构.html)。

- `src/`：对话引擎、任务编排、记忆、审批、通知、文档与产物服务。
- `client/`：总助手对话、旁聊、资源和任务界面。
- `test/`：对应业务及界面验证。

插件入口 `src/plugin.mjs` 依赖 BenchGo 基础服务、Harness 聚合的 `commander` 服务及官方会话服务。启用后提供 `assistant` 服务；停用后释放总助手会话、定时器、事件监听、数据库和 HTTP 路由。已委派给 Harness 的任务及持久化数据继续由各自服务管理。

公共模型管理和界面组件直接复用 BenchGo；语音适配直接复用 Voice。`assistant` 工具名、HTTP 路径及存储标识保留原协议，已有会话与记忆按当前存储继续使用。

主聊与旁聊共用 SuperAgent 模型设置和受控聊天发布：Router 可直接正常结束文本回答，由官方 completed 回合确认后展示，也可通过 `assistant_reply` 显式发布；工具过程留在后台。Worker 正常结束即保存结果并记完成；Router 收到完成信号后读结果、用自己的话表达，正式稿经 outbox 交付原来源。完整边界见 [对话交互](../../docs/06-superagent/对话交互.md)与[结果与交付](../../docs/06-superagent/结果与交付.md)。自由主动机会推送与通知偏好尚未开放，显式定时委派仍按任务交付。

Router 同时负责聊天与总调度。任务受理后，由当前 Router 以自己的口吻说明要做的事和完成后反馈，沿用普通文本终答或 `assistant_reply`，随情境自然表达；默认省略内部调度、Worker 身份和任务编号。当前回合结束后用户可继续对话，后续由运行时完成或阻塞信号触发。渠道显式人类请求的受理回复复用同次 Router 研判 `replyText`，经准入复核后随任务持久入队并去重；没有正文时不补模板。交流原则见[Router 对话准则](../../docs/06-superagent/Router对话准则.md)。

## 宠物身份与形象

SuperAgent 本身就是宠物助手与 Router，默认无名，不增加陪伴 Agent 或第二套记忆。主人档案为 `USER.md`，自身身份和人设为 `IDENTITY.md`、`SOUL.md`。

在身份 → 形象中组合基准表情/装饰/配色，或上传自己的主图与表情；先预览再应用，支持取消、恢复上一版和默认。选择“让 AI 帮我设计”进入已有聊天，生成产物经 `assistant_pet` 预览和应用。首页、聊天和侧栏共用身份形象；已有 HTML 名片优先显示，当前需展开 HTML 编辑、清空并保存才恢复默认形象，旧的模式选择提示尚待同步。

运行及待确认状态可切换基准表情；形象页可预览短动作，但聊天名片固定静态，尚未接入计算出的 action 与原创角色短表情。图像生成需配置可用供应商，不支持参考图局部换装；桌面悬浮尚未实现。边界见[身份与形象](../../docs/06-superagent/身份与形象.md)。

任务执行统一由 `orchestration-store.mjs` 落册、`assignment-worker.mjs` 调度和 `assignment-executor.mjs` 接入官方 Harness。`desktop-delegation-service.mjs` 处理桌面来源；`goal-checklist.mjs` 只维护供 AI 长期参考的目标清单，不创建任务或执行队列。

Task、Assignment、Run、Result 与 Delivery 共同承载委派执行、结果和通知；环境操作从第一次探查起委派并创建 Task，Router 的专属产品管理和协调调用留在当前官方会话。任务只有 running / waiting / completed 三态：Worker 正常结束且结果已保存即 completed，含义是“跑完并有结果”，没做成由 Router 读结果后直说；送达另记，发送失败仅补投已保存的回复，发送未知先核实，不重跑 Worker。

聊天看板与任务详情共用执行动态投影，以简约任务线展示执行者公开撰写的动作摘要、真实状态与时间，不重复显示 Worker 身份；历史缺失和过期记录明确说明，交互边界见[任务列表设计](../../docs/02-工作台与Agent/任务列表交互.md#聊天任务线与执行动态)。

Router 通过只读工具 `assistant_tasks` 查询任务：`list` 支持 `status`、`projectId` 和 `limit`/`offset` 分页，按返回的 `nextOffset` 继续；`get` 按 `id` 读取执行结果及待处理问题。本机主人在主聊或手动旁聊可查询各来源任务，内部通知回合仍按原会话归属读取。查询直接复用任务数据库，不触发执行或审批，也不授予跨会话答复、修订或新执行权限。

Router 与 Worker 的官方权限固定为 `danger-full-access + never`，覆盖新建、恢复和权限校正，进程内子代理按官方机制继承。角色装配、业务控制与独立 Watchdog 的边界见[模型与上下文](../../docs/06-superagent/模型与上下文.md#自有会话角色装配)。

## 书面规则准入

默认保持手动模式。需要机器消息自动创建任务时，在资源 → 档案的 AGENTS.md 中定义规则，例如：

```markdown
## rule: ci-check
仅检查本群 CI 失败原因并提交证据；不得部署或修改生产环境。
```

然后在资源 → 接入 → 多平台中配置允许的群、机器发送人 Open ID，启用 `ci-check` 并选择自动模式。规则 ID 按标题原文匹配；空规则、未定义 ID、重复定义不能作为授权。人类群消息仍须 @；此类群聊机器消息始终为 inferred，不能通过 @ 升权。机器规则仅授权创建任务，挂靠与停止已有任务仍需主人显式指令。禁用规则、切回手动或删除名单会在后续执行边界撤销授权，不撤销已经发生的外部操作。

此能力已通过本地配置/UI/Router/Worker 回归；真实飞书端到端验收仍未完成。

## 结果与交付

任务准入研判按线程独立推进，慢线程不阻塞其他线程；同线程仍保持单批次和租约。辅助模型的“研判与复盘”用途覆盖任务准入研判，保留只读原文工具，未勾选时跟随主模型。Router 保留专属产品管理、任务协调与已装配的上下文工具；文件、命令、网页、技能、插件和 MCP 等环境操作从第一次探查起统一交给 Worker。普通委派不额外询问创建任务许可，实际受控动作仍复验授权。能力装配见[模型与上下文](../../docs/06-superagent/模型与上下文.md#自有会话角色装配)，分工见[任务与执行](../../docs/06-superagent/任务与执行.md#router-与持续主会话)。官方 Schedule 四工具已接入助手作用域，定时协调不创建即时执行任务。

结果只有一份：Worker 的最后一段话，写清做成了什么、产出在哪、还剩什么问题；完整过程留在官方执行会话。没有独立的自检步骤、自检记录或结构化失败上报，也不设内容评分模型。结果保存与送达分别记账，任务详情只有一块“结果”及投递状态。宿主仅检查归属、有效执行身份和当前要求编号，不评价正文质量。完整规则见[结果与交付](../../docs/06-superagent/结果与交付.md)。

后台记忆/技能整理队列只消费已完成且已送达的任务；结果写明没做成的，不提炼成功经验。

## 自建技能

主模型与辅助模型在资源 → 身份 → 模型同页配置首选、备用及用途。用途包括看图、压缩、总结、研判与复盘；未配置或未勾选时跟随当前主模型。看图与总结已接入服务和聊天工具 assistant_analyze_image / assistant_summarize，不代表已有独立操作按钮。请求冻结配置与模型原始 ID，瞬态故障同模型重试一次，随后按配置尝试备用；结构或空摘要质量失败可直接回主模型。压缩失败片段缓冲丢弃，官方摘要记录实际模型。拒绝或取消不触发回退。

学习复盘将有真实用户来源且符合学习规则的记忆直接保存，无需逐条确认；在资源 → 记忆的时间线中查看、补充、编辑或遗忘。`assistant_memory` 直接执行当前用户要求的记账，不另开模型动作任务或审批。学习关闭、排除、纠正和遗忘屏蔽继续有效。自建技能仍生成候选：在工具 → 技能中查看正文与来源、批准或拒绝；批准后通过官方 Harness skills 目录发现和加载，不复制第三方技能或建立额外安装体系。未启用官方技能服务时明确提示，不能发布或恢复技能。

实际的 `skill` 工具加载与用户 `/技能名` 调用记录使用，目录预览不计数。空闲整理仅处理自建且未固定的技能：14 天未使用标记待整理，30 天归档；不自动删除。可固定、恢复归档或从历史快照恢复正文，操作携带当前版本以拒绝过期修改。自动 LLM 合并关闭。
