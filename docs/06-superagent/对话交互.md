# SuperAgent 对话交互

本文维护人可见的聊天与工作简报。持续收件和 Router 生命周期见[任务与执行](任务与执行.md)，结果与投递见[结果与交付](结果与交付.md)，名片与形象见[身份与形象](身份与形象.md)。

## 围绕用户的事情表达

人格、表达方式、工具前说明、真实不确定与适度主动统一见[Router 对话准则](Router对话准则.md)。本文只维护聊天与组件交互。

## 聊天与正式发布

聊天复用官方输入、草稿、发送、取消、审批与渲染能力，QuietChat 只作受控投影，不建第二套聊天系统。主聊优先，旁聊隔离来源与上下文，资源页承载身份、任务、记忆、产物、接入和系统文件。

| 事项 | 规则 |
| --- | --- |
| 会话加载 | 按需订阅：当前对话由原会话容器持有，后台只保留运行中或待交互的会话，不因打开助手恢复全部闲置旁聊。历史索引按官方事件水位增量更新，分页不反复扫描工具轨迹 |
| 用户消息 | 发送后立即显示；运行中插话与排队消息沿用官方 inbox，只显示正文，不附加收到、排队提示；入账后接管同一消息且不重复。未被接收进回合的输入保留官方队列顺序，撤回后跟随官方记录消失 |
| 不进聊天的内容 | 内部调度、恢复指令、执行输入通知、工具参数与输出、推理、系统提示和 Worker 执行过程；真实过程在原执行会话查看 |
| 流式正文 | 普通 Router text 作为正文流式显示，绑定真实 session / turn / request。等待工具或派工前的简短回应沿同一 text 流，不增设假回复或额外模型调用；表达规则见[回应与行动相连](Router对话准则.md#回应与行动相连) |
| 正式出口 | `assistant_reply` 或官方 completed 回合的公开正文 |
| 分泡 | 同一轮按实际模型消息 / step 分成多个气泡，不按空行或 token 拆分，也不把整轮拼成一个。实时流与历史使用同一分段身份，正式消息原位接管，刷新、重连和分页不重复或重新合并 |
| 取消与失败 | 清除未提交正文，已提交正文保留；流式片段不代表任务完成 |
| 工具拒绝 | 单次工具拒绝是真实工具结果，供 Router 纠正并自然说明，不把整轮标成模型连接失败；只有回合或 Agent 真实失败才进入失败呈现 |

工单的状态变化、结果和待批事项以事实信号进入所属 Router 的持久消息队列，由 Router 自然说明：优先处理人类消息，不打断当前回合，不生成新工单；发布前复检当前状态与授权，已过期的说明被抑制，同一事件幂等。聊天不渲染通用的工单等待或“系统状态”块，状态、刷新和执行入口统一在任务列表与工单详情；真实提问与审批卡保留各自语义。工单三态与结果交付见[结果与交付](结果与交付.md)，修订、暂停与停止见[任务与执行](任务与执行.md#工单跟进与目标)。

新回复和主动通知支持本机提示音，入口在“身份 → 回复提示音”，可静音与试听。按消息身份去重，历史加载、重连和流式片段不反复响；浏览器首次交互或试听后解锁播放，界面如实显示等待交互、就绪或失败。它不依赖 Voice，也不启动语音朗读。

### 左侧旁聊与 IM 列表

左侧会话区域提供「旁聊 / IM」双选切换：旁聊只列用户手动创建的旁聊，IM 只列真实已连接渠道的既有来源会话。连接判定、来源键与镜像规则见[统一会话与原路交付](链接与渠道.md#统一会话与原路交付)。

- 切换只改变左侧列表，不改变主聊、已打开会话、草稿或看板范围，也不创建 session、请求模型或发送消息。
- 切换行是紧凑分段控件，与右侧新建和折叠按钮垂直居中；收起列表后点击任一分段即展开对应列表。
- IM 条目显示「飞书私聊 · 联系人」或「飞书群聊 · 群名称」，右侧只留活动时间，完整来源在悬停说明中查看。
- 空列表区分尚未连接与尚无来源会话，并保留接入入口。断开连接只影响筛选和可发送性，原会话与历史仍可查。
- 渠道消息沿用普通聊天气泡，正文上方不重复渠道名或“收到消息 / 已交付”标签；发送失败按真实结果提示。
- 工作台来源会话中的主人手写消息按原文发往该渠道，不猜任务、不调用 Router。

### 顶部身份与活动指示

主聊与旁聊顶部只保留当前助手形象、姓名与真实工作状态，不渲染自定义 HTML 名片。顶部状态与消息尾部指示共用同一活动投影，不从名字、头像动作或选中态推测运行状态。

| 状态 | 呈现 |
| --- | --- |
| 模型等待与推理 | 轻量三点指示，不显示技术过程句 |
| 搜索或调用工具 | 简短的“搜索中”或“工作中”，不暴露工具名、参数和协议值 |
| 正文生成 | 保持已输出内容，不以活动提示替代正文 |
| 待答、待审批、重试故障、连接错误 | 保留原交互及恢复入口 |
| 活动结束 | 立即清除忙碌指示；减少动态偏好下改为静态指示 |

### 执行会话与直接插话

Router 主聊、手动旁聊与 IM 入口在 SuperAgent 内；Worker 和官方子代理在工作台侧栏、项目与未分组会话中可见，可打开原会话并直接输入。原工单的内部查看区进入同一官方 Session，底层工作区、模型和历史不因入口改变。界面细节见[任务列表交互](../02-工作台与Agent/任务列表交互.md)。

- 目录依据持久归属和官方 parentSession 关联，不按标题猜测；归属未知或读取失败显示真实加载和重试，不创建替身。
- 打开与输入复用原 SessionProvider、官方消息及输入，不复制 transcript。返回保留草稿、滚动及详情上下文。
- Worker 的直接输入进入原工单输入账，与主旁聊共用顺序和消费记录；应用时机、暂停和扩权规则见[任务与执行](任务与执行.md#工单跟进与目标)。官方子代理的输入遵循官方生命周期。
- 暂停、停止、已完成与失效运行按真实状态展示可用操作及原因；直接输入不能绕过任务状态和审核。
- 工单完成后保留同一会话入口、消息和产物，不自动归档；查看不恢复归档或重跑执行。
- 打开未归档的主聊或旁聊时，若其官方 Session 曾被普通列表归档，通过官方工作区接口恢复同一身份；只处理当前 Router。

问答卡：

- 工单提问卡以可选项为主要操作，不默认选择；正文只留真实问题、选项和必要说明，技术原因留在 Attention 诊断。无选项时直接提供自由答复，补充说明按需展开且收起不丢草稿。
- 提交中防重复，失败保留所选内容与草稿并可重试；已答或失效时收起输入。答案绑定原问题和版本。
- 已作答的问答显示用户侧气泡，含问题与所选答案；跳过的标注已跳过，未答、失败或格式不符不伪造记录。

消息工具栏在宽容器中位于正文两侧，窄容器中位于正文下方，从流式开始预留位置，显隐不改变正文宽度和滚动高度；悬停、聚焦时显示，触屏常显。复制、时间与用量取真实记录，缺失显示未记录。本地表情回应按稳定消息键持久化，不发往渠道，也不授予权限。气泡和渐显见[前端视觉规范](../02-工作台与Agent/前端视觉规范.md)。

### 结构化交互回复

交互回复复用基础层内部装配的 `plugins/interactive/`。Router 可按内容选择表单、选项、表格或图表，在原正文内渲染；普通文字仍由官方 Markdown 渲染。

协议是受限的 BenchGo UI v1 白名单数据，不接受模型脚本、表达式、任意 HTML 或网络动作。表单与选项通过官方会话提交桥作为普通用户消息回传，保留草稿和失败重试；它们不批准动作、不录入秘密，也不替代绑定原问题编号的工单问答。空数据、未闭合生成、格式错误和可交互数据分别给出真实反馈，渠道能力不足时附普通文字等价内容。

### 资源文件浏览

- 产物页用一个页眉承载标题、刷新和视图切换，分类、名称筛选及批量选择在同一工具区；筛选只覆盖已加载数据，分页未结束时说明范围。
- 下载沿用可信文件 URL，保留原查询参数与片段。刷新或失败时保留上次文件、筛选和有效选择；首次加载、真实空目录和读取失败分开呈现。
- 系统文件只读浏览，目录往返恢复各自的筛选、滚动位置和焦点。
- 文件预览在原资源页内展开，不伪装成模态弹窗，返回或 Escape 恢复原列表位置与焦点；产物与系统文件共用同一预览组件，预览失败可重试。

### 权限与安全输入交互

主聊与旁聊不展示 Harness 权限档位，也不要求用户为日常对话选择访问模式。审批规则只在[权限与对外审批](任务与执行.md#权限与对外审批)维护，这里只定呈现。

审批呈现分三层，三层关联同一个真实请求，不新建审批账或授权：

| 层 | 呈现 |
| --- | --- |
| Router 提醒 | Worker 的动作进入正式待批后向所属 Router 发事实信号，Router 用自己的话说明为用户准备了什么、需要批准哪一步。不抢占在途回合，不固定文字；同一请求不重复入队，已决定或工单失效时抑制未发表的提醒 |
| 原官方审批卡 | 挂在 Router 对应提醒处，随对话流呈现，不置顶、不弹窗。用户核对实际对象、最终正文与附件、金额、影响及提交参数后选择“允许本次”或“拒绝” |
| 「任务 → 审核」聚合 | 聚合当前档案主聊、未归档旁聊及其有效 Worker 的全部待批事项，可跳转对应卡片；只作查找与兜底，不混入待提问、任务成果或技能候选 |

- 三处复用同一个官方 PendingApproval、SessionProvider 与卡片；同一会话有多项等待时遵循官方交互顺序。一处答复后其他入口立即失效。
- 卡片绑定冻结快照，一次只允许执行此件；内容变化显示失效并重新出卡。停止、撤权或执行替换后旧卡失效，迟到点击不能提交。
- 仅当前档案经官方传输认证的 owner 人端可列出和作答；呈现和点击时均复核所属会话、工单归属、现行授权、工具面、租约及执行代际。
- 信号、提醒或卡片可见都不构成批准，Router 不能替用户批准。已发表的提醒保留为聊天历史。
- 部分来源连接失败时保留其他已核实的审核项，按来源显示标题、失败阶段和错误详情；未连接来源的待批情况标为未知，不显示成“无待审核”。重试只重连原会话。
- 审核页只在页头右侧保留一个刷新入口，无待批时显示空态。
- 来源不支持可验证审批卡时，跳回任务审核入口，不以普通文字“同意”冒充批准。

没有可用高危通道时显示接管点：保留已完成的准备、页面或应用定位、待提交对象与内容及用户最后一步，明确标注“尚未提交”，提供打开原位置或继续接管的入口。用户完成后展示待核实或真实结果；取消或接管失败保留可恢复入口。只有依赖该提交的部分等待，其余已授权工作继续。

凭据缺失时显示安全输入或用户接管入口，流程见[保险库与安全输入](链接与渠道.md#保险库与安全输入)。安全输入不使用聊天文本框，普通问题卡不收集密码；录入完成与动作批准分别反馈，卡片只显示脱敏摘要。

### 暂存身份与重连

- 聊天正文复用官方实时 Session 流；业务变化复用 execution-facts Remote 的 chat、delivery、result、attention 事件，100ms 合并后触发历史对账。30 秒刷新只在页面可见时兜底，后台不轮询。
- 流式优先读取官方顶层 `assistant_reply` 的 runningCalls / PartialArguments.text；否则按官方 turn 边界和已接收用户节点的 seq，从同请求的持久 assistant 节点读取公开 text，再追加当前未结算 step 的 `partial.blocks` 中 kind=text。同轮接收新的用户插话会切换请求边界。
- history 的可选 activeReply 提供当前 turn / request，前端核对真实 session / turn / request 后才显示正文；排队未接收、其他会话、已结束回合或嵌套调用不能串入。
- 正文从 partial 结算为官方 assistant 节点后沿用同一段身份。含工具调用的节点只提取 text；工具、空片段和纯思考阶段不删除此前的公开正文。合成中断节点和取消 / 错误回合不冒充最终回复，不缓存第二份回复正文。
- 工具错误不伪装成模型断连；连接错误保留消息和草稿，并提供原会话重连。
- 渠道经统一 outbox 调用来源适配器发送，是否支持图片、卡片、增量发布及回执以适配器能力声明为准。

## 首页与快捷起草

空会话展示正式形象、真实任务简报和三项快捷起草；有会话时展示 QuietChat 发布投影。

| 区块 | 内容 |
| --- | --- |
| 需要关注 | 最多 2 项：等待信息、受阻、效果未知或投递失败。关注不等于可直接批准 |
| 正在推进 | 最多 3 项真实执行，排除已完成、暂停与停止中 |
| 最近完成 | 最多 2 项已完成工单，送达状态单独呈现 |
| 快捷起草 | 用官方 InputActions 插入可编辑文本，不自动发送、不覆盖已有草稿 |

首页与实时任务面板共享官方执行事实增量流及 tickets / goalList 缓存，健康连接按变化更新，不做周期全量拉取；断线有界退避，隐藏时暂停，最后订阅卸载后取消请求。已有有效快照时传输波动保留原内容；首次加载失败、操作失败与领域错误给出真实反馈，不把未知说成无任务。主聊和旁聊侧均显示全部工单。设置只提交变更字段，冲突保留草稿。首页直接审批与模型生成的每日总结待实施。

## 实现与验收边界

已实现（源码接线，安装版未据此验收）：

- 受控历史投影、按真实 step 分泡的实时与历史投影、显式回复接管、共用活动状态与顶部简洁身份、消息工具栏、本地回应、提示音和工作简报。
- 「旁聊 / IM」切换与渠道会话的显示、回复桥。
- 审核聚合入口、Router 自然提醒、提醒下挂原官方卡、看板定位原提醒；渠道发起任务的待批可由本档案 owner 在审核页查看，渠道端审批卡未实现。
- 问答接入官方 ask_user_question 与 user-question-reply 来源，持久绑定原 Attention，即时与迟到答案幂等回原单。
- 执行会话目录复用官方 AgentLoop、JSONL 持久化、Session Query 与客户端目录管理器。
- 浏览器组件验证覆盖四态、1440 / 390 宽度、明暗主题和减少动态，使用受控服务响应，不代表真实模型请求、网络重连或物理桌面已通过。

待实施：完整的接管导航、安全输入衔接、首页直接审批、每日总结。

待验证：

- 官方各输入入口、附件、重连、连续请求和真实桌面重启。
- 同一回复不重复气泡、取消 / 失败保留已提交正文、跨会话不串流、问答与跳过记录真实。
- 审批三层的安装版路径：Router 先提醒、同一请求卡片挂流、聚合可跳转、批准 / 拒绝后其他入口同步失效、重启不重复消费单次批准、旧卡不能批准新动作。
- 冷会话直接输入接回原 Run，已完成会话的调整路径。
- 渠道会话经实际 `FixedChatView → QuietChat` 入口的入站、已送达回复、历史与实时去重、刷新和重连。
- 四态、键盘与触屏、窄容器、明暗主题、减少动态、保存冲突和草稿保护；最终视觉由用户验收。
