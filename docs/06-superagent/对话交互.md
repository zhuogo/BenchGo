# SuperAgent 对话交互

本文维护人可见的聊天与工作简报。持续收件和 Router 生命周期见[任务与执行](任务与执行.md)，交付业务见[自校验与交付](自校验与交付.md)，名片与角色见[身份与形象](身份与形象.md)。

## 聊天与正式发布

复用官方输入、草稿、发送、取消、审批与渲染能力，QuietChat 只作受控投影，不创建第二套聊天系统。主聊优先，旁聊隔离来源与上下文，资源页统一承载身份、任务、记忆、产物、接入和系统文件。

渠道会话出现在工作台统一会话列表，带来源标记，可打开并直接回复；呈现可采用旁聊形态，实现复用工作台会话、输入与历史机制，不为飞书或其他渠道创建专属会话实现。适配器不保存自身对话状态；渠道与桌面访问同单时，输入、状态、投递记录与关单条件只认同一工单账。桌面主人手写回复按原文发送、不猜任务或调用 Router；提交保留真实 desktop-owner actor 与 desktop 来源，由 deliveryTarget 指向原渠道目标，不冒充远程发言人。渠道协议与来源标注只在[链接与渠道](链接与渠道.md)维护；会话桥与原文回复已接线，真实账号和完整界面仍待验证。

普通 Router text 可作为正文或进度流式显示，必须绑定真实 session/turn/request；正式出口为 assistant_reply 或官方 completed 回合的有效终答。显式发布按请求幂等，正式消息替换同一暂存身份，取消/失败清除未提交正文，流式片段不是任务完成。

工具参数、工具原始返回、推理、系统提示和 Worker 执行 transcript 不转贴到 Router 主聊或旁聊正文；真实执行过程仍在所属执行会话按官方渲染规则查看。用户始终与 Router 对话。Worker 轻量自校验后将成果原稿保存到工单并发完成信号，Router 主动自然提醒已完成，自行选择摘要或完整回复，再向原来源交付；原稿保留在工单详情。回复按对话需要组织，不固定工单报告、标题前缀或系统状态文案，不另加“交付通知”卡框、成果验收分页或已读按钮。Router 负责表达与交付，不重派、不做内容验收；追问时可读取原稿直接回答。选项和动作审批保持各自语义，动作审批集中入口见下文。

桌面主聊和旁聊中的执行受阻、等待恢复等状态由所属 Router 根据真实事实自行决定如何自然说明。状态事件携带工单、状态、要求编号、执行归属及受控原因，成果完成事件同时提供已保存结果引用；不传异常堆栈。通知复用原会话持久消息队列，优先处理人类消息，不打断当前回合，不生成新工单。Router 可按表达需要读取已存成果，不因此验收或重派；派发与正式发布均复检当前状态和授权，状态已经改变则抑制过期说明。说明按同一状态事件幂等，技术原因与真实执行会话入口保留在工单详情。

聊天容器消息不渲染通用工单等待或“系统状态”块，包括“等待你的答复”、重复问题、“刷新状态”“停止工单”和“查看执行会话”。真实提问与授权卡保留原问题、作答及批准语义，不能随通用状态块一起移除。工单状态、刷新、停止和执行入口统一放在任务列表及工单详情。Router 状态说明无硬文案兜底；暂时无法生成回复时保留真实待交付或异常记录，恢复后只重试表达或投递，不重跑 Worker。真实状态始终可在任务列表与详情查询。Router 的自然状态说明继续正常发布。消息发送失败仍独立呈现，不能与工单状态一起隐藏。渠道投递继续遵循原来源归属，不把渠道故障转发到无关主聊。

普通任务调整作为插话直接写入原工单输入账本，Worker 在下一工具边界将新要求整份切换生效，不打断在途工具；版本号只在后台记账，不要求用户先暂停或确认。暂停中的工单只接收修订，不自动续跑。询问进度或细节只回答，不改要求；超 Mandate 扩权交 Router，才进入真实用户确认及新授权版本流程。Worker 问题经 Router 逐级处理，确需用户决定才发绑定问题编号的选项卡，答复回原单；只暂停受影响部分，其余独立且已授权工作可继续，不能用默认值替代批准。

### 执行会话与直接插话

工单的实际 Worker 执行会话归所属项目工作区，不涉及项目的任务归官方「未分组」（按最近活动排序）；会话列表带工单标记，点击进入同一个官方会话，不复制日志或另建聊天。聊天容器消息不提供“查看执行会话”入口，用户从任务列表打开工单详情进入原执行会话；列表名称、工单标记与真实会话归属一致。

未闭单 Worker 即使停止运行、等待输入或等待交付，原执行会话也须保持可发现，不等用户点击详情才恢复。客户端已接官方 `api-session/removed` 事件，按现有执行会话投影核对归属后调用 `sessions.refresh()` 恢复持久会话目录；事件合并为单在途请求与单待办批次，不增加轮询或另一套会话状态。遇到移除前已在途的官方目录请求，目录仍缺原 ID 时最多补一次刷新。BenchGo 自有侧栏按官方目录减去所有项目显式成员获得未分组，合并到“最近”并共用排序、归档和过滤；不把执行目录伪挂默认项目。工单与渠道标记各共用同一组件和数据源，在官方与自有侧栏扩展槽呈现，不修改官方组件。闭单继续使用官方归档；详情先恢复归档显示、刷新目录，再打开原 ID，不新建会话或重启 Worker。

用户始终与 Router 对话；执行会话提供真实过程查看与直接插话入口，直接输入同样进入 Router 跟进协调及原工单输入账本，与主旁聊共用顺序和消费记录，不能形成第二个对话对象或两套要求。普通调整在下一工具边界整份切换，不中断在途工具；暂停中只收件。超 Mandate 的要求由 Router 请求用户确认或分新单，Worker 不自行扩权。执行会话中的问答仍受原授权和问题编号约束，不能借直接输入绕过审批。执行会话可收起，工单确认关单后自动归档，关联执行会话通过官方机制归档进工单记录，保留同一会话入口、消息和产物；不得删除记录或把已结束会话冒充仍在执行。

已作答的选项卡问答显示用户侧气泡，含问题与所选答案；跳过题标注已跳过，未答、失败或格式不符不伪造记录。问题等待时提供明确作答提示，答案绑定原问题和版本。

工单提问卡以可选项为主要操作，说明与选中状态有清晰层级，不默认选择。提问卡及原来源正文只保留真实问题、选项和必要说明，Router 自动核对的技术原因与系统状态保留在 Attention 诊断，不拼入问题正文。补充说明按需展开且收起不丢草稿；无选项时直接提供自由答复。提交中防重复操作，失败保留所选内容与草稿并允许重试；已答或失效时收起输入。复用主题与共享组件，兼顾窄屏、明暗主题、键盘和触控；不再附加通用状态卡。

消息工具栏固定在正文两侧，显隐不改变间距和滚动高度；悬停/聚焦/浮层显示，触屏常显。复制纯文本、时间与用量取真实记录，缺失显示未记录。本地表情回应按稳定消息键持久化，不发送渠道，也不授予权限。

首页展示真实待关注、推进中与完成任务，快捷起草可编辑、不自动发送或覆盖草稿。设置只提交变更字段，冲突保留草稿；空、加载、错误、有数据四态和窄容器、明暗主题、减少动态均须验证。通用视觉遵循[公共前端规范](../02-工作台与Agent/前端视觉规范.md)。

### 资源文件浏览

产物页使用一个页眉承载标题、刷新和视图切换，分类、已加载文件名称筛选及批量选择放在同一工具区；筛选只覆盖已加载数据，分页尚未结束时须说明范围。下载沿用可信文件 URL，保留原查询参数与片段，再设置下载参数，不用字符串拼接破坏路径。刷新或失败时保留上次文件、筛选和有效选择，错误只提供一个明确重试入口；首次加载、真实空目录和读取失败分开呈现。

系统文件继续只读浏览；目录往返恢复各自筛选、滚动位置和原触发项焦点。文件预览在原资源页内展开，暂时隐藏列表及重复页头，不伪装成模态弹窗；返回或 Escape 恢复原列表位置与焦点。产物与系统文件共用同一预览组件及主题、四态规则，预览失败可重试，不丢失原列表状态。

### 权限与安全输入交互

主聊与旁聊不展示 Harness 权限档位，也不要求用户为日常对话选择访问模式。Main Agent 默认具备内部完整能力，继续承担 Router 职责；环境执行仍委派 Worker。统一许可与逐层裁剪规则只在[权限与对外审批](任务与执行.md#权限与对外审批)维护。

工作台的「任务 → 审核」集中呈现当前档案主聊、未归档旁聊及其有效 Worker 的真实官方待审批请求；不把待提问、任务成果或后台技能候选混作动作审核。列表提供事项、所属会话与真实审批原因，选中后用原官方卡核对实际网站或接收对象、最终正文与附件、商品/金额、影响及适用提交参数，提供“允许本次”“拒绝”。同一会话有多项等待时遵循官方当前交互顺序，前一项处理后后续项再出现，不自建第二队列。卡片绑定冻结快照，一次只允许执行此件；内容变化显示失效并重新出卡，不以“点击确认”代替最终内容核验。高危类别、逐次审批和免审范围只在[权限与对外审批](任务与执行.md#权限与对外审批)维护。

桌面主聊或旁聊的 Worker 高危动作进入正式待批后向所属 Router 发事实信号，Router 在现有消息队列中自然提醒用户前往「任务 → 审核」，不抢占在途用户回合，不固定提醒文字，也不把审批卡塞到聊天容器顶部。信号只关联原审批与工单，既不产生许可，也不允许 Router 替用户批准；准备动作尚未请求审批时不提醒，同一请求不重复入队，已决定或工单失效时抑制尚未发表的过期提醒。已发表的自然提醒保留为聊天历史，不随审批结束消失。

审核入口复用执行会话的同一个官方 PendingApproval、SessionProvider 与卡片，不新建审批记录或复制批准令牌。仅当前档案的可信 owner 人端可列出和作答；呈现和点击时均复核所属会话、工单归属、现行授权、工具面、租约及执行代际。停止、撤权或执行替换后旧卡失效，迟到点击不能提交。原官方会话中的卡片保持可查，与审核入口结算同一请求，一处答复后其他入口立即失效；不隐藏或替换官方当前会话审批组件。无待批时呈现清晰空态，读取失败提供重试且不产生许可。审核是动作授权，不增加任务内容验收层。

来源连接须同时核对官方引用的就绪结果与 Session 打开状态；就绪 Promise 返回不等于日志已可读。部分来源失败时保留其他已核实的审核项，并按来源展示标题、失败阶段和原始错误详情供排查；未连接来源的待批情况明确为未知，不显示成“无待审核”。重试只重新连接原会话，不创建替身或推定批准；渠道日志与显示镜像的恢复边界见[统一会话与原路交付](链接与渠道.md#统一会话与原路交付)。

没有可用高危通道时显示接管点，保留已完成准备、真实页面/应用定位、待提交对象与内容及用户最后一步，明确标注“尚未提交”；提供打开原位置/继续接管入口，不提供脚本自动提交批准。用户完成后展示待核实或真实结果，取消及接管失败保留可恢复入口，不能伪造已提交。终端和浏览器仍可继续其他已授权工作，只有依赖该高危提交的部分等待。

其他可精确匹配的网站动作可提供整站持续授权，明确精确 origin、动作类别、期限和撤销入口；自用场景可明确勾选较宽的常规敏感类别，卡片始终显示四类高危例外。只有范围内且仍有效的动作可复用，并与当前工单 Mandate 两道门叠加，执行全程留痕、受撤销控制。拒绝、撤销、过期或动作变化后的卡保持真实状态，不允许重复提交旧答案。来源不支持可验证审批卡时，提供跳回已认证桌面 / Link 审批页的入口，不以普通文字“同意”冒充批准。

资源中提供授权管理入口，展示真实站点、动作类别、期限、授权人、创建时间、审计记录与有效 / 撤销状态，支持撤销整站授权；凭据条目管理继续由保险库承担，不把“删除凭据”当作唯一撤权方式。授权记录重载后与实际动作匹配一致，列表只展示脱敏元数据。

凭据缺失时显示安全输入或用户接管入口，具体流程见[保险库与安全输入](链接与渠道.md#保险库与安全输入)。安全输入不使用聊天文本框，普通问题卡不收集密码；录入完成与动作批准分别反馈。卡片只显示脱敏摘要，秘密不进入正文、模型上下文或日志。

### 暂存身份与重连

流式优先读取官方顶层 assistant_reply 的 runningCalls / PartialArguments.text，否则读取 partial.blocks 的 kind=text，两路复用 `reply:<requestId>` 消息身份。history 的可选 activeReply 提供当前 turn/request，前端核对真实 session/turn/request 才显示正文。

history 刷新延迟时，仅允许已被官方接收的用户节点与持久回执按 seq/rpcId 关联；排队未接收、另一会话、已结束回合或嵌套调用不能串入。成功 publication 可桥接刷新间隔，已提交回复不因随后停止而消失。渠道经统一 outbox 调用来源适配器发送；文本、图片、卡片、增量发布及回执是否支持以适配器能力声明为准，不能由桌面流式能力推定。

## 首页与快捷起草

空会话展示正式形象、真实任务简报和三项快捷起草；有会话时展示 QuietChat 发布投影。官方内容容器和输入框继续复用，原始执行 transcript 留在详情。

- 需要关注最多 2 项，展示等待信息、受阻、效果未知或投递失败；已送达的结构性失败以失败历史展示，用户可回话继续或调整，关注不等于可直接批准。
- 正在推进最多 3 项，区分运行、自校验与待交付，排除已关闭、暂停与停止中；最近完成最多 2 项，只展示成功结果已确认送达后关闭的任务。
- 阶段与摘要绑定当前要求版本；任务、记忆和档案跳回既有入口。
- 快捷起草用官方 InputActions 插入可编辑文本，不自动发送、不覆盖已有草稿；草稿继续由官方输入框管理。

首页与实时任务面板共享 tickets / goalList 请求和缓存，每 10 秒更新；隐藏暂停，最后订阅卸载后取消请求。失败显示真实原因并标明保留的旧数据，与加载及真实无任务分开。窄容器单列，动效尊重减少动态。逐任务定位、首页直接审批与模型生成每日总结未实现。

## 实现与验收边界

受控历史投影、正式流式、消息工具栏、本地回应和工作简报已有实现；官方各输入入口、附件、重连、连续请求和真实桌面重启仍须完整验证，不能用接口或浅渲染测试替代。

授权管理入口、站点许可创建/重载/撤销与脱敏审计已接线；业务动作使用正式 Harness 单次审批。当前站点类别仅 login/private-upload，仍无内置执行适配器；支付/改密/删号走 handoff，完整接管导航和安全输入衔接仍待完善。验收覆盖宽窄屏四态、失败重试、撤销后重载及真实用户卡操作；权限实现边界只在[任务与执行](任务与执行.md#实现与验收边界)维护。

动作审核集中入口复用官方每会话当前 PendingApproval；Router 自身的当前会话原生审批组件仍可见，不替换官方组件。高危自然提醒接入桌面所属 Router；渠道发起任务的同源待审批会话可由本档案 owner 在审核页查看，但不据此宣称已实现渠道端审批卡或新增跨渠道提醒投递。真实验收需分别覆盖列表可达、原请求批准/拒绝、其他入口同步失效、Router 自然提醒及无顶部固定块，不能由页面渲染推定真实动作已提交。

普通插话共用持久输入账本、原执行下一工具批次整份切换、暂停只收件和扩权真实批准已完成服务端接线。问答接入官方 ask_user_question 与 user-question-reply 来源，保留原消息身份并持久绑定原 Attention；即时与迟到答案幂等回原单，普通问答只续 Router、不新建工单，跳过不授权或续 Worker。验收覆盖问题投递、卡片作答、原单续跑，以及 Worker 层级和不同渠道。

执行会话目录恢复复用官方 AgentLoop、JSONL 持久化、Session Query、列表投影和客户端目录管理器；定位既有 session，不创建替身或重启 Worker。无项目会话归“最近”，带工单标记，确认关单后工单与关联执行会话自动归档，历史入口仍可查。验收应覆盖 Worker 停止与在途目录请求竞争、原会话打开、归档与恢复。自检、Router 表达交付和送达关单的边界只在[自校验与交付](自校验与交付.md#实现与验收边界)维护。安装共享依赖应指向宿主同一实例，启动登记不得重建错误影子副本；安装及重启验收核对这些不变量。

桌面工单状态通知已有 Router 持久消息队列、发布前状态与授权复检以及同事件去重基础。Router 不可用时不补固定事实摘要、系统状态文案或通用等待卡；任务列表与详情保留真实状态，后续只恢复表达或投递。验收覆盖明暗主题、窄屏、四态及无硬文案的完成提醒；真实提问/授权卡可操作，任务详情状态与控制可达。

渠道统一会话列表、来源标记、打开与直接回复路径也须验证四态及重连：同一来源会话不重复创建，不维护渠道专属历史或第二份工单状态；发送经唯一 outbox，回执回同单，不把本地显示成功当原渠道送达。

验证同一回复不重复气泡、取消/失败清除暂存且保留已提交正文、跨会话不串流、问答选项与跳过记录真实、复制/时间/用量来源可靠、本地回应不外发。检验四态、键盘与触屏、窄容器、明暗主题、减少动态、保存冲突和草稿保护；视觉由用户最终验收。

补验 Worker 保存原稿并通知后 Router 主动自然提醒、按对话自选摘要或完整回复，原稿在详情可查、追问按需读取不重派；无固定工单报告、标题前缀、状态文案或硬兜底，待交付与已送达不混同。成功成果回复送达后 completed，结构性失败由 Router 按真实情况说明，送达后 failed；偶发故障退避，生成失败只重试表达、投递失败只补投回复，均不重 Worker。用户回话可在失败原单继续或调整，超时核实执行并从 checkpoint 原单恢复，效果未知不盲重跑。验证两处插话共用输入账本、下一工具边界整份切换且不打断在途、暂停只收件、越权交 Router、结束收纳、叫停与撤权立即拦截后续动作，旧问题不能回答新问题。

审批与安全输入须使用真实主聊、旁聊及支持的原来源核验：「任务 → 审核」有入口并覆盖空、加载、错误、有数据四态，无待办时提供空态而不造审批卡，加载与操作时防重复提交，错误提供可恢复原因与重试；有数据时核对动作、授权范围、脱敏内容与操作结果。Worker 高危待批由 Router 自然提醒，主聊顶部无固定审批块；用户前往审核页或原官方会话处理同一请求，一处答复后其他入口失效。另验四类高风险逐次审批不吃整站授权、原来源回复免审、整站范围与期限可见、许可与 Mandate 双闸门及审计撤销、拒绝/撤权在下一动作前生效、重启恢复不重复消费单次批准、旧卡不能批准新动作，效果未知时先核实而不靠再次点击重放。安全输入保留自身秘密协议，不混入普通审批正文。
