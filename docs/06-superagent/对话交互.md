本文维护人可见的聊天与工作简报。持续收件和 Router 生命周期见[任务与执行](任务与执行.md)，交付业务见[自校验与交付](自校验与交付.md)，名片与角色见[身份与形象](身份与形象.md)。

## 围绕用户的事情表达

人格、围绕用户事情表达、工具前必要说明、真实不确定与适度主动统一见[Router 对话准则](Router对话准则.md)。本文件只维护聊天与组件交互，不重复保存表达规则。

## 聊天与正式发布

会话加载采用按需订阅：当前对话由原会话容器持有，后台只保留运行中或待交互会话，不因打开助手恢复全部闲置旁聊。资源状态与当前会话打开并行请求；历史索引复用既有有界缓存，按官方事件水位增量更新模型、结束原因和图片元数据，分页不反复扫描工具轨迹。此路径已实现；隔离性能与浏览器夹具不能代替安装版实际点击耗时验收。

复用官方输入、草稿、发送、取消、审批与渲染能力，QuietChat 只作受控投影，不创建第二套聊天系统。主聊优先，旁聊隔离来源与上下文，资源页统一承载身份、任务、记忆、产物、接入和系统文件。

主聊与旁聊中的真实用户消息发送后立即显示；运行中插话与排队消息沿用官方 inbox，只显示用户消息正文，不附加收到、排队或处理时点提示；入账后接管同一消息且不重复。尚未接收进回合的输入保留官方队列顺序，不因本地回显退出、客户端时钟不同或队列编辑而按旧时间重新排序；撤回后跟随官方记录消失，不另存前端队列。内部调度、恢复指令、执行输入通知、工具参数与输出不作为用户气泡或普通发送失败展示；Router 经正式发布的自然说明、真实提问与审批仍按各自语义显示。过期内部通知不得阻断同批真实用户插话。上述投影与身份接管已有定向单测及明暗、宽窄屏浏览器验证；真实安装版的网络时序及最终交互仍由用户验收。

渠道会话出现在工作台统一会话列表，带来源标记，可打开并直接回复；呈现可采用旁聊形态，实现复用工作台会话、输入与历史机制，不为飞书或其他渠道创建专属会话实现。适配器不保存自身对话状态；渠道与桌面访问同单时，输入、状态、投递记录与关单条件只认同一工单账。桌面主人手写回复按原文发送、不猜任务或调用 Router；提交保留真实 desktop-owner actor 与 desktop 来源，由 deliveryTarget 指向原渠道目标，不冒充远程发言人。渠道协议与来源标注只在[链接与渠道](链接与渠道.md)维护；会话桥与原文回复已接线，真实账号和完整界面仍待验证。

### 左侧旁聊与 IM 列表

渠道消息沿用普通聊天气泡，正文上方不重复显示渠道名及“收到消息 / 已交付”标签；来源由会话列表识别，发送失败仍按真实结果提示。

左侧会话区域提供「旁聊 / IM」简单双选切换：旁聊只列用户手动创建的旁聊，IM 只列真实已连接渠道的既有固定来源会话，带渠道与来源标识。连接可用性取统一接入服务的实际连接状态，不凭启用配置、会话标题或已有历史推断在线；空列表明确区分尚未连接与尚无真实来源会话，并保留现有接入入口。断开连接只影响筛选及可发送性，原会话和历史保持可查，不删除或迁移记录。

切换行采用紧凑分段控件，与右侧新建和折叠按钮垂直居中；折叠按钮保持固定方形点击区域和明确的箭头方向。收起列表后点击任一分段即展开对应列表，切换不跳转聊天。每个侧栏实例使用独立的折叠区域标识。IM 条目以「飞书私聊 · 联系人」或「飞书群聊 · 群名称」等简短名称呈现，名称来自渠道可信元数据；缺少名称时仅保留渠道与类型，不把平台 ID 当作名称。右侧只保留活动时间，不重复显示私聊、群聊或话题类型，完整来源可在悬停说明中查看。

切换只改变左侧会话列表，不改变主聊、当前已打开会话、草稿或全局工单看板范围，也不创建 session、请求模型或发送消息。点击 IM 条目打开同一真实来源 session，继续复用既有历史、消息渲染与回复桥。每个真实私聊、群聊及适用的话题分别绑定稳定来源键，不把整个平台全部来源合并为一个会话；来源与连接映射唯一正文见[统一会话与原路交付](链接与渠道.md#统一会话与原路交付)。此列表切换已实现；浏览器验证覆盖四态、窄栏与键盘操作，真实账号收发及桌面最终视觉由用户验收。

普通 Router text 可作为正文或进度流式显示，必须绑定真实 session/turn/request；需要等待工具或派工时，简短自然的前置回应也沿同一普通 text 流呈现，不增设假回复、独立回应工具或额外模型调用，不用 assistant_reply 提前结束实际执行。具体表达规则只在[Router 对话准则](Router对话准则.md#先接住内容少占注意力)维护。正式出口为 assistant_reply 或官方 completed 回合的公开正文。同一轮按实际模型消息/step 分为多个气泡；工具前说明、后续说明及最终结论可各自成泡，不把整轮全部正文拼进一个气泡，也不按空行或 token 人为拆泡。同段文字增量更新原气泡，无新正文时保留此前各段。实时流与历史使用同一分段身份，正式消息原位接管，刷新、重连及分页不重复或重新合并。显式 assistant_reply 接管本段暂存正文，不擦掉此前独立说明；取消/失败清除未提交正文，已提交正文保留，流式片段不是任务完成。

### 顶部身份与活动指示

主聊与旁聊顶部只保留当前助手形象、姓名与真实工作状态，复用现有形象及身份入口；不渲染完整自定义 HTML 名片。身份页与侧栏名片的配置、编辑及预览保持原职责，见[身份与形象](身份与形象.md)。顶部工作状态与消息尾部指示共用同一活动投影，不从名字、头像动作或选中态推测运行状态。

模型等待和推理期间使用轻量三点活动指示，不显示“等待模型响应”等技术过程句。搜索或调用工具时使用简短“搜索中”或“工作中”标签，不暴露原始工具名、参数及协议值。正文生成时保持已输出内容，不以活动提示替代正文。真实待答、待审批、重试故障和连接错误保留原交互及恢复入口，不能与普通等待提示一起隐藏。活动结束立即清除忙碌指示，减少动态偏好下改为静态指示，不启动额外模型或轮询。

工具参数、工具原始返回、推理、系统提示和 Worker 执行 transcript 不转贴到 Router 主聊或旁聊正文；真实过程仍在原执行会话按官方规则查看。Harness Worker 正常结束且当前要求的成功结果已保存后完成并通知 Router，Router 主动自然提醒，自选摘要或完整回复交付原来源；原稿保留在详情。正常完成后没有效果审核、循环核查或自动返工；结果不满意由用户找 Router 派关联调整单。用户仍可查看原 Worker 或官方子代理会话。聊天不固定报告、标题前缀或状态文案，不另加验收分页；真实选项与动作审批保留各自语义。

桌面主聊和旁聊中的执行受阻、等待恢复等状态由所属 Router 根据真实事实自行决定如何自然说明。状态事件携带工单、状态、要求编号、执行归属及受控原因，成果完成事件同时提供已保存结果引用；不传异常堆栈。通知复用原会话持久消息队列，优先处理人类消息，不打断当前回合，不生成新工单。Router 可按表达需要读取已存成果，不因此验收或重派；派发与正式发布均复检当前状态和授权，状态已经改变则抑制过期说明。说明按同一状态事件幂等，技术原因与真实执行会话入口保留在工单详情。

列表与看板只显示进行中、等待、完成，等待附真实审批、输入、暂停、中断或执行错误原因。不显示效果审核、核查次数、下次核查时间或自动恢复倒计时；正常结束且当前要求的成功结果已保存后完成并通知 Router。结果保存的版本、归属及证据差异由系统内部处理，基础设施写入故障自动补存，不将其转成要求用户处理的等待，目标及实施边界见[结果保存无阻断](自校验与交付.md#结果保存无阻断)。用户不满意时通过 Router 新建关联调整单。停止仍区分“后续动作已拦截”和“执行端已确认退出”，明确续接才按原会话处理执行，已有成果保存不依赖续接；机制见[自校验与交付](自校验与交付.md)。

新回复和主动通知支持本机提示音，入口在“身份 → 回复提示音”，可静音与试听。公开回复只将会话、请求或渠道消息身份写入既有 `chat` 事实流，不复制正文；支持该能力的宿主不为提示音恢复全部闲置会话。快照声明 `publicChatNotifications: true`；旧宿主缺少声明或首次连接失败时兼容原公开会话订阅，能力升级后释放旧引用。按消息身份去重，历史加载、重连、快照和同一回复的流式片段不反复响。浏览器首次交互或点击试听后解锁播放，界面如实显示等待交互、就绪或失败；不依赖 Voice 启用，不启动语音朗读。此路径已实现并有定向回归；物理扬声器听感与当前安装窗口的后台播放仍由用户验收。

聊天容器消息不渲染通用工单等待或“系统状态”块，包括“等待你的答复”、重复问题、“刷新状态”“停止工单”和“查看执行会话”。真实提问与授权卡保留原问题、作答及批准语义，不能随通用状态块一起移除。工单状态、刷新、停止和执行入口统一放在任务列表及工单详情。Router 状态说明无硬文案兜底；暂时无法生成回复时保留真实待交付或异常记录，恢复后只重试表达或投递，不重跑 Worker。真实状态始终可在任务列表与详情查询。Router 的自然状态说明继续正常发布。消息发送失败仍独立呈现，不能与工单状态一起隐藏。渠道投递继续遵循原来源归属，不把渠道故障转发到无关主聊。

普通任务调整作为插话直接写入原工单输入账本，Worker 在下一工具边界将新要求整份切换生效，不打断在途工具；版本号只在后台记账，不要求用户先暂停或确认。暂停中的工单只接收修订，不自动续跑。询问进度或细节只回答，不改要求；超 Mandate 扩权交 Router，才进入真实用户确认及新授权版本流程。Worker 问题经 Router 逐级处理，确需用户决定才发绑定问题编号的选项卡，答复回原单；只暂停受影响部分，其余独立且已授权工作可继续，不能用默认值替代批准。

主聊的自然语言暂停必须调用真实暂停控制并核对落账回执，Router 按实际 `executionControl.pauseRequested/paused` 事实自然说明，工单业务状态保持 waiting，不以“继续等待核查”或口头承诺替代。列表操作与详情提供同一暂停入口，待核实、受阻和可恢复场景也能暂停；已暂停、正在暂停、正在停止及已结束时不重复提供暂停动作。暂停只阻断后续执行与自动续跑，不删除成果、原会话或历史；生命周期权威见[任务与执行](任务与执行.md#工单跟进与目标)。

### 执行会话与直接插话

Router 主聊、手动旁聊与 IM 入口保留在 SuperAgent；Worker 和官方子代理在工作台侧栏可见，可打开原会话并直接输入。原工单内部查看区也进入同一官方 Session，底层工作区、模型和历史不因入口改变。归属未知或读取失败显示真实加载和重试，不创建替身。返回保留草稿、滚动及详情上下文，具体界面见[任务列表交互](../02-工作台与Agent/任务列表交互.md)。

Worker 和官方子代理在工作台侧栏、项目与未分组会话中保持可发现；Router 仍由 SuperAgent 入口展示。目录依据持久归属和官方 parentSession 关联，不按标题猜测。打开与直接输入复用原 SessionProvider、官方消息及输入，不复制 transcript 或建立第二份工单账。运行中的 Worker 输入记入同单输入账，在下一安全边界应用；冷会话应接回原 Run 与会话，不能创建替身执行。官方子代理输入遵循官方生命周期。暂停、停止、已完成与失效运行按真实状态展示可用操作及原因，不把直接输入当作绕过当前任务状态和审核的入口。完成不自动归档，查看不恢复手动归档或重跑执行。冷会话输入与已完成会话的调整路径仍须实际验收。

打开未归档的主聊或旁聊时，若其当前官方 Session 曾被普通列表归档，通过官方工作区接口恢复同一身份；只处理当前 Router，不恢复历史会话、真正已归档的旁聊或 Worker，不重放此前被拦截的输入。列表隔离通过可信身份过滤实现，不以官方归档代替隐藏。

用户通常由 Router 协调，也可在工作台直接向 Worker 或官方子代理发消息；执行会话提供真实过程查看与直接插话入口，直接输入同样进入 Router 跟进协调及原工单输入账本，与主旁聊共用顺序和消费记录，不能形成两套任务要求。普通调整在下一工具边界整份切换，不中断在途工具；暂停中只收件。超 Mandate 的要求由 Router 请求用户确认或分新单，Worker 不自行扩权。执行会话中的问答仍受原授权和问题编号约束，不能借直接输入绕过审批。执行会话可手动收起，工单完成后仍在 SuperAgent 内保留同一会话入口、消息和产物，不自动归档；不得删除记录或把已结束会话冒充仍在执行。

已作答的选项卡问答显示用户侧气泡，含问题与所选答案；跳过题标注已跳过，未答、失败或格式不符不伪造记录。问题等待时提供明确作答提示，答案绑定原问题和版本。

工单提问卡以可选项为主要操作，说明与选中状态有清晰层级，不默认选择。提问卡及原来源正文只保留真实问题、选项和必要说明，Router 自动核对的技术原因与系统状态保留在 Attention 诊断，不拼入问题正文。补充说明按需展开且收起不丢草稿；无选项时直接提供自由答复。提交中防重复操作，失败保留所选内容与草稿并允许重试；已答或失效时收起输入。复用主题与共享组件，兼顾窄屏、明暗主题、键盘和触控；不再附加通用状态卡。

消息工具栏在宽容器中位于正文两侧，窄容器中位于正文下方；从流式开始预留位置，显隐不改变正文宽度和滚动高度。悬停/聚焦/浮层显示，触屏常显。复制纯文本、时间与用量取真实记录，缺失显示未记录。本地表情回应按稳定消息键持久化，不发送渠道，也不授予权限。气泡和渐显统一见[前端视觉规范](../02-工作台与Agent/前端视觉规范.md)。

首页展示真实待关注、推进中与完成任务，快捷起草可编辑、不自动发送或覆盖草稿。设置只提交变更字段，冲突保留草稿；空、加载、错误、有数据四态和窄容器、明暗主题、减少动态均须验证。通用视觉遵循[公共前端规范](../02-工作台与Agent/前端视觉规范.md)。

### 结构化交互回复

交互回复复用基础层内部装配的 `plugins/interactive/`，不增加插件入口。Router 可按内容需要选择表单、选项、表格或图表；主聊与旁聊在原正文内渲染，普通官方聊天沿公开扩展槽追加交互视图并保留原文。普通文字仍由官方 Markdown 渲染，流式连续性与正式发布复用同一消息身份。

协议为受限的 BenchGo UI v1 白名单数据，不接受模型脚本、表达式、任意 HTML 或网络动作。表单与选项通过官方会话提交桥作为普通用户消息回传，保留输入草稿和发送失败重试；它们不批准动作、不录入秘密，也不替代绑定原问题编号的工单问答。空数据、未闭合生成、格式错误和可交互数据分别提供真实反馈；渠道能力不足时附普通文字等价内容。

### 资源文件浏览

产物页使用一个页眉承载标题、刷新和视图切换，分类、已加载文件名称筛选及批量选择放在同一工具区；筛选只覆盖已加载数据，分页尚未结束时须说明范围。下载沿用可信文件 URL，保留原查询参数与片段，再设置下载参数，不用字符串拼接破坏路径。刷新或失败时保留上次文件、筛选和有效选择，错误只提供一个明确重试入口；首次加载、真实空目录和读取失败分开呈现。

系统文件继续只读浏览；目录往返恢复各自筛选、滚动位置和原触发项焦点。文件预览在原资源页内展开，暂时隐藏列表及重复页头，不伪装成模态弹窗；返回或 Escape 恢复原列表位置与焦点。产物与系统文件共用同一预览组件及主题、四态规则，预览失败可重试，不丢失原列表状态。

单次工具拒绝作为真实工具结果供 Router 纠正选择并自然说明，不因此把整轮对话标成模型连接失败，也不要求用户清理聊天记录。只有实际回合或 Agent 失败才进入失败呈现；权限门和原始诊断继续保留。

### 权限与安全输入交互

主聊与旁聊不展示 Harness 权限档位，也不要求用户为日常对话选择访问模式。Main Agent 默认具备内部完整能力，继续承担 Router 职责；环境执行仍委派 Worker。任务内审核与官方执行边界只在[权限与对外审批](任务与执行.md#权限与对外审批)维护。

审批呈现分三层，提醒、卡片与聚合关联同一真实请求，不新建审批账或授权：

1. Router 先在对话中以自己的话提醒待批事项，说明为用户准备了什么、需要批准哪一步，不用系统模板代发。
2. 原官方审批卡挂在 Router 对应提醒处，随对话流呈现，不置顶、不弹窗。用户核对实际网站或接收对象、最终正文与附件、商品/金额、影响及适用提交参数后，选择“允许本次”或“拒绝”。
3. 工作台「任务 → 审核」聚合当前档案主聊、未归档旁聊及其有效 Worker 的全部待批事项，可跳转对应卡片；它只作查找与兜底，不替代 Router 提醒或另造批准入口语义，不把待提问、任务成果或后台技能候选混作动作审核。

聚合列表保留事项、所属会话与真实审批原因，复用同一官方卡；同一会话有多项等待时遵循官方当前交互顺序，前一项处理后后续项再出现，不自建第二队列。卡片绑定冻结快照，一次只允许执行此件；内容变化显示失效并重新出卡，不以“点击确认”代替最终内容核验。高危类别、逐次审批和免审范围只在[权限与对外审批](任务与执行.md#权限与对外审批)维护。

桌面主聊或旁聊的 Worker 高危动作进入正式待批后向所属 Router 发事实信号，Router 在现有消息队列中自然提醒用户，并关联随流卡片；看板审核保留统一查找入口。不抢占在途用户回合，不固定提醒文字，也不把审批卡塞到聊天容器顶部。信号只关联原审批与工单，既不产生许可，也不允许 Router 替用户批准；准备动作尚未请求审批时不提醒，同一请求不重复入队，已决定或工单失效时抑制尚未发表的过期提醒。已发表的自然提醒保留为聊天历史，不随审批结束消失。

审核入口复用执行会话的同一个官方 PendingApproval、SessionProvider 与卡片，不新建审批记录或复制批准令牌。仅当前档案经官方传输认证的 owner 人端可列出和作答（此为现有宿主入口认证，不是核心按渠道使用者划分权限档位）；呈现和点击时均复核所属会话、工单归属、现行授权、工具面、租约及执行代际。停止、撤权或执行替换后旧卡失效，迟到点击不能提交。原官方会话中的卡片保持可查，与审核入口结算同一请求，一处答复后其他入口立即失效；不隐藏或替换官方当前会话审批组件。无待批时呈现清晰空态，读取失败提供重试且不产生许可。审核是动作授权，不增加任务内容验收层。

来源连接须同时核对官方引用的就绪结果与 Session 打开状态；就绪 Promise 返回不等于日志已可读。部分来源失败时保留其他已核实的审核项，并按来源展示标题、失败阶段和原始错误详情供排查；未连接来源的待批情况明确为未知，不显示成“无待审核”。重试只重新连接原会话，不创建替身或推定批准；渠道日志与显示镜像的恢复边界见[统一会话与原路交付](链接与渠道.md#统一会话与原路交付)。

审核页只保留页头右侧的统一刷新入口；空态、读取错误、会话连接错误和有待审核操作时均不在内容区重复放置刷新或重连按钮。刷新保留原授权语义，不提交或批准任何动作。

没有可用高危通道时显示接管点，保留已完成准备、真实页面/应用定位、待提交对象与内容及用户最后一步，明确标注“尚未提交”；提供打开原位置/继续接管入口，不提供脚本自动提交批准。用户完成后展示待核实或真实结果，取消及接管失败保留可恢复入口，不能伪造已提交。终端和浏览器仍可继续其他已授权工作，只有依赖该高危提交的部分等待。

需要审核的动作复用原任务官方卡；同一真实批准不重复索要，不提供网站长期许可。拒绝或动作变化后旧卡保持真实状态。来源不支持可验证审批卡时，跳回已有任务审核入口，不以普通文字“同意”冒充批准。

资源中不再提供独立授权管理入口。凭据由保险库保存，具体动作审核留在任务中；删除凭据和拒绝当前动作分别表达，不建立长期许可表。

凭据缺失时显示安全输入或用户接管入口，具体流程见[保险库与安全输入](链接与渠道.md#保险库与安全输入)。安全输入不使用聊天文本框，普通问题卡不收集密码；录入完成与动作批准分别反馈。卡片只显示脱敏摘要，秘密不进入正文、模型上下文或日志。

### 暂存身份与重连

聊天正文复用官方实时 Session 流；业务变化复用现有 execution-facts Remote 的 chat、delivery、result、attention 事件，100ms 合并触发历史对账。30 秒刷新仅作页面可见时兜底，后台不持续轮询。动态状态来自真实回合、工具和等待事实，工具错误不伪装模型断连；连接错误保留消息及草稿并提供原会话重连。前后台切换、重连与空/加载/错误/有数据四态须实际验收。

流式优先读取官方顶层 assistant_reply 的 runningCalls / PartialArguments.text，否则按官方 turn 边界及已接收用户节点 seq，从同请求的持久 assistant 节点读取公开 text，再追加当前未结算 step 的 partial.blocks 中 kind=text；两路使用包含真实请求与输出段的稳定身份，不再以单个 `reply:<requestId>` 合并整轮。history 的可选 activeReply 提供当前 turn/request，前端核对真实 session/turn/request 才显示正文。同轮接收新的用户插话也会切换请求边界，不能把上一请求正文拼入新请求。

history 刷新延迟时，仅允许已被官方接收的用户节点与持久回执按 seq/rpcId 关联；排队未接收、另一会话、已结束回合或嵌套调用不能串入。成功 publication 可桥接刷新间隔，已提交回复不因随后停止而消失。渠道经统一 outbox 调用来源适配器发送；文本、图片、卡片、增量发布及回执是否支持以适配器能力声明为准，不能由桌面流式能力推定。

普通正文从 partial 结算为官方 assistant 节点后沿用该段身份。工具调用与结果、空片段和纯思考阶段不删除此前段的公开正文；含工具调用的节点只提取 text，不展示参数、返回或 reasoning。当前 step 已结算时不重复追加迟到 partial，其他回合或会话的事件不接入。completed 后，history 从同一官方事件范围逐段投影公开正文，工具后直接结束或最后一步只有思考也不丢前段；刷新前由官方节点桥接，接管不撤除、重复或合并气泡。合成中断节点和取消／错误回合不冒充最终回复；不缓存第二份回复正文。

## 首页与快捷起草

空会话展示正式形象、真实任务简报和三项快捷起草；有会话时展示 QuietChat 发布投影。官方内容容器和输入框继续复用，原始执行 transcript 留在详情。

- 需要关注最多 2 项，展示等待信息、受阻、效果未知或投递失败；已送达的结构性失败以失败历史展示，用户可回话继续或调整，关注不等于可直接批准。
- 正在推进最多 3 项，展示真实执行，排除已完成、暂停与停止中；最近完成最多 2 项，展示正常结束且结果已持久化的任务，送达状态单独呈现，不设自校验或效果审核阶段。
- 阶段与摘要绑定当前要求版本；任务、记忆和档案跳回既有入口。
- 快捷起草用官方 InputActions 插入可编辑文本，不自动发送、不覆盖已有草稿；草稿继续由官方输入框管理。

首页与实时任务面板共享官方执行事实增量流及 tickets / goalList 缓存，健康连接按变化更新相关记录，不做周期全量拉取；断线通过有界退避补偿，隐藏时暂停，最后订阅卸载后取消请求。已有有效快照时传输波动静默保留原内容，首次加载失败、实际操作失败与领域错误保留真实反馈，不把未知说成无任务。主聊和旁聊侧均显示全部工单，不提供会话范围切换。窄容器单列，动效尊重减少动态。首页直接审批与模型生成每日总结未实现。

验证同一回复不重复气泡、取消/失败清除暂存且保留已提交正文、跨会话不串流、问答选项与跳过记录真实、复制/时间/用量来源可靠、本地回应不外发。检验四态、键盘与触屏、窄容器、明暗主题、减少动态、保存冲突和草稿保护；视觉由用户最终验收。

补验 Harness Worker 正常结束且当前要求的成功结果已保存后完成并通知 Router，Router 主动自然提醒、自选摘要或完整回复，原稿在详情可查；不追加效果审核、循环核查或自动返工。等待只来自实际审批、输入、暂停、中断或错误；失败不能说成成功。结果不满意由用户找 Router 派关联调整单，原单保留。生成或投递失败只处理相应阶段，不回退工单完成或重跑 Worker。原会话输入、修订、暂停、停止与显式续接按[任务与执行](任务与执行.md)验证，不能沿用旧自动恢复链的验收结论。

审批与安全输入须使用真实主聊、旁聊及支持的原来源核验：「任务 → 审核」有入口并覆盖空、加载、错误、有数据四态，无待办时提供空态而不造审批卡，加载与操作时防重复提交，错误提供可恢复原因与重试；有数据时核对动作、授权范围、脱敏内容与操作结果。Worker 高危待批先由 Router 自然提醒，同一官方卡挂在提醒处随对话流，不置顶或弹窗；看板聚合全部待批并能跳到对应卡片，不能仅有看板而无提醒。原官方会话与各入口处理同一请求，一处答复后其他入口失效。另验四类高风险逐次审批不吃整站授权、原来源回复免审、整站范围与期限可见、许可与 Mandate 双闸门及审计撤销、拒绝/撤权在下一动作前生效、重启恢复不重复消费单次批准、旧卡不能批准新动作，效果未知时先核实而不靠再次点击重放。安全输入保留自身秘密协议，不混入普通审批正文。
