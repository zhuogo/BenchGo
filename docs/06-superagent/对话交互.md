# SuperAgent 对话交互

本文维护人可见的聊天与工作简报。持续收件和 Router 生命周期见[任务与执行](任务与执行.md)，交付业务见[自校验与交付](自校验与交付.md)，名片与角色见[身份与形象](身份与形象.md)。

## 聊天与正式发布

复用官方输入、草稿、发送、取消、审批与渲染能力，QuietChat 只作受控投影，不创建第二套聊天系统。主聊优先，旁聊隔离来源与上下文，资源页统一承载身份、任务、记忆、产物、接入和系统文件。

渠道会话出现在工作台统一会话列表，带来源标记，可打开并直接回复；呈现可采用旁聊形态，实现复用工作台会话、输入与历史机制，不为飞书或其他渠道创建专属会话实现。适配器不保存自身对话状态；渠道与桌面访问同单时，输入、状态、投递记录与关单条件只认同一工单账。客户端提交携带真实来源归属，不能借本地打开渠道会话升级为桌面主人。渠道协议与来源标注只在[链接与渠道](链接与渠道.md)维护，上述统一路径仍待实施与验证。

普通 Router text 可作为正文或进度流式显示，必须绑定真实 session/turn/request；正式出口为 assistant_reply 或官方 completed 回合的有效终答。显式发布按请求幂等，正式消息替换同一暂存身份，取消/失败清除未提交正文，流式片段不是任务完成。

工具参数、工具原始返回、推理、系统提示和 Worker 执行 transcript 不转贴到 Router 主聊或旁聊正文；真实执行过程仍在所属执行会话按官方渲染规则查看。Worker 轻量自校验后保存的正式结果从工单直接交付原来源，带工单标题区分并行任务；不另加“交付通知”卡框、审核分页或已读按钮。Router 默认只收执行状态，不读取、审核、改写或转发结果正文；用户主动追问细节时可按需读工单或已保存结果直接回答，不重新派工。系统状态注明来源，选项和审批保持各自语义。

普通任务调整作为插话直接写入原工单输入账本，Worker 在下一工具边界将新要求整份切换生效，不打断在途工具；版本号只在后台记账，不要求用户先暂停或确认。暂停中的工单只接收修订，不自动续跑。询问进度或细节只回答，不改要求；超 Mandate 扩权交 Router，才进入真实用户确认及新授权版本流程。Worker 问题经 Router 逐级处理，确需用户决定才发绑定问题编号的选项卡，答复回原单；只暂停受影响部分，其余独立且已授权工作可继续，不能用默认值替代批准。

### 执行会话与直接插话（待实施）

工单的实际 Worker 执行会话归所属项目工作区，不涉及项目的任务归“最近”；会话列表带工单标记，点击进入同一个官方会话，不复制日志或另建聊天。主聊天工单与任务详情均提供直达该执行会话的入口；列表名称、工单标记与真实会话归属一致。

用户通常在执行会话直接插话，与 Router 转来的跟进共用原工单输入账本、顺序和消费记录，不能形成两套要求。普通调整在下一工具边界整份切换，不中断在途工具；暂停中只收件。超 Mandate 的要求转交 Router 请求用户确认或分新单，Worker 不自行扩权。执行会话中的问答仍受原授权和问题编号约束，不能借直接输入绕过审批。执行会话可收起，工单结束后自动沉底或归档进工单记录，保留同一会话入口、消息和产物；不得删除记录或把已结束会话冒充仍在执行。

已作答的选项卡问答显示用户侧气泡，含问题与所选答案；跳过题标注已跳过，未答、失败或格式不符不伪造记录。问题等待时提供明确作答提示，答案绑定原问题和版本。

消息工具栏固定在正文两侧，显隐不改变间距和滚动高度；悬停/聚焦/浮层显示，触屏常显。复制纯文本、时间与用量取真实记录，缺失显示未记录。本地表情回应按稳定消息键持久化，不发送渠道，也不授予权限。

首页展示真实待关注、推进中与完成任务，快捷起草可编辑、不自动发送或覆盖草稿。设置只提交变更字段，冲突保留草稿；空、加载、错误、有数据四态和窄容器、明暗主题、减少动态均须验证。通用视觉遵循[公共前端规范](../02-工作台与Agent/前端视觉规范.md)。

### 权限与安全输入交互（待实施）

主聊与旁聊不展示 Harness 权限档位，也不要求用户为日常对话选择访问模式。Main Agent 默认具备内部完整能力，继续承担 Router 职责；环境执行仍委派 Worker。统一许可与逐层裁剪规则只在[权限与对外审批](任务与执行.md#权限与对外审批)维护。

需要批准的对外效果在原来源显示审批卡，列出实际网站或接收目标、具体动作及影响，提供“允许本次”“拒绝”。支付购买、改密码、删账号、另行对外发送四类高风险动作逐次审批，不提供以整站授权跳过本次审批的路径；另行发送包括向其他对象发邮件、转发、分享、发布，原来源正常回复、进度、问题和成果交付免审。

其他可精确匹配的网站动作可提供整站持续授权，明确站点、动作类别、期限和撤销入口；只有范围内且仍有效的动作可复用，并与当前工单 Mandate 两道门叠加，执行全程留痕、受撤销控制。拒绝、撤销、过期或动作变化后的卡保持真实状态，不允许重复提交旧答案。来源不支持可验证审批卡时，提供跳回已认证桌面 / Link 审批页的入口，不以普通文字“同意”冒充批准。

资源中提供授权管理入口，展示真实站点、动作类别、期限、授权人、创建时间、审计记录与有效 / 撤销状态，支持撤销整站授权；凭据条目管理继续由保险库承担，不把“删除凭据”当作唯一撤权方式。授权记录重载后与实际动作匹配一致，列表只展示脱敏元数据。

凭据缺失时显示安全输入或用户接管入口，具体流程见[保险库与安全输入](链接与渠道.md#保险库与安全输入)。安全输入不使用聊天文本框，普通问题卡不收集密码；录入完成与动作批准分别反馈。卡片只显示脱敏摘要，秘密不进入正文、模型上下文或日志。

### 暂存身份与重连

流式优先读取官方顶层 assistant_reply 的 runningCalls / PartialArguments.text，否则读取 partial.blocks 的 kind=text，两路复用 `reply:<requestId>` 消息身份。history 的可选 activeReply 提供当前 turn/request，前端核对真实 session/turn/request 才显示正文。

history 刷新延迟时，仅允许已被官方接收的用户节点与持久回执按 seq/rpcId 关联；排队未接收、另一会话、已结束回合或嵌套调用不能串入。成功 publication 可桥接刷新间隔，已提交回复不因随后停止而消失。渠道经统一 outbox 调用来源适配器发送；文本、图片、卡片、增量发布及回执是否支持以适配器能力声明为准，不能由桌面流式能力推定。

## 首页与快捷起草

空会话展示正式形象、真实任务简报和三项快捷起草；有会话时展示 QuietChat 发布投影。官方内容容器和输入框继续复用，原始执行 transcript 留在详情。

- 需要关注最多 2 项，展示等待信息、受阻、效果未知或投递失败；已送达的结构性失败以失败历史展示，用户可回话继续或调整，关注不等于可直接批准。
- 正在推进最多 3 项，区分运行、自校验与待交付，排除已关闭、暂停与停止中；最近完成最多 2 项，只展示成功结果已确认送达后关闭的任务。
- 阶段与摘要绑定当前要求版本；任务、记忆和档案跳回既有入口。
- 快捷起草用官方 InputActions 插入可编辑文本，不自动发送、不覆盖已有草稿；草稿继续由官方输入框管理。

首页与实时任务面板共享 tickets / goalList 请求和缓存，每 10 秒更新；隐藏暂停，最后订阅卸载后取消请求。失败显示真实原因并标明保留的旧数据，与加载及真实无任务分开。窄容器单列，动效尊重减少动态。逐任务定位、首页直接审批与模型生成每日总结未实现。

## 实现与验收边界

受控历史投影、正式流式、消息工具栏、本地回应和工作简报已有实现；官方各输入入口、附件、重连、连续请求和真实桌面重启仍须完整验证，不能用接口或浅渲染测试替代。

上述隐藏 Harness 档位、对外审批卡、网站持久授权及安全输入衔接是新目标，尚待实施；复用官方审批能力不等于这些用户路径已经接通。

无独立任务内容验收、Worker 固定快速轻量机械自检、原结果直达用户与 Router 仅收状态、送达后关单、结构性失败报告与恢复、插话整份切换，以及执行会话标记、入口与收纳均为待实施目标。新展示状态须由实际服务字段映射，不能先把目标阶段名当已发布协议。

渠道统一会话列表、来源标记、打开与直接回复路径也须验证四态及重连：同一来源会话不重复创建，不维护渠道专属历史或第二份工单状态；发送经唯一 outbox，回执回同单，不把本地显示成功当原渠道送达。

验证同一回复不重复气泡、取消/失败清除暂存且保留已提交正文、跨会话不串流、问答选项与跳过记录真实、复制/时间/用量来源可靠、本地回应不外发。检验四态、键盘与触屏、窄容器、明暗主题、减少动态、保存冲突和草稿保护；视觉由用户最终验收。

补验结果正文不进入 Router 交付回合、追问按需读取不重派、并行结果按工单标题可辨、待交付与已送达不混同。成功成果送达后 completed，结构性失败报告明确尝试、死因和可变条件，送达后 failed；偶发故障退避，投递失败只补投结果，用户回话可在失败原单继续或调整，超时核实执行并从 checkpoint 原单恢复，效果未知不盲重跑。验证两处插话共用输入账本、下一工具边界整份切换且不打断在途、暂停只收件、越权交 Router、结束收纳、叫停与撤权立即拦截后续动作，旧问题不能回答新问题。

审批与安全输入须在真实主聊、旁聊及支持的原来源核验四态：无待办时不显示空卡；加载时保留目标与处理中状态并防重复提交；错误时展示可恢复原因且不伪造批准或保存成功；有数据时核对动作、授权范围、脱敏内容与操作结果。另验四类高风险逐次审批不吃整站授权、原来源回复免审、整站范围与期限可见、许可与 Mandate 双闸门及审计撤销、拒绝/撤权在下一动作前生效、重启恢复不重复消费单次批准、旧卡不能批准新动作，效果未知时先核实而不靠再次点击重放。
