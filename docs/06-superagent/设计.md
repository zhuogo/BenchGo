# SuperAgent 设计

本文件是 SuperAgent 板块总览。每个小模块在下表对应文档维护一份设计，不重复保存同一机制的平行版本。整体板块关系见[总架构](../总架构.html)。设计与源码核对基线为 2026-11-07；本次文档拆分不代表重新完成真实验收。

## 定位与范围

SuperAgent 是 BenchGo 面向个人的总助手，承担持续对话、事件研判、任务编排和结果交付。连续指对话与任务能够读账续行；持久指身份、记忆与技能可以积累；主动必须受书面规则和当前授权约束；高效以结果可靠为前提。

产品优先完成主聊天与旁聊，项目聊天押后。首轮以单机桌面和飞书闭环为基线；渠道扩展和多端不成为本地任务执行的前置条件。

- 占最少注意力约束后台通知，不限制用户正在聊天时的正常回答。结果可用、明确失败或确需人决定时应及时沟通。
- 确定性动作交给代码：身份、准入、去重、状态、权限、索引、计数和投递。模型负责理解、研判、执行及语义验收。
- 新能力优先组合现有插件、服务和配置，不新增平行会话系统、推理循环、Cron 或任务数据库。
- 原始用户要求、来源和实际执行证据是权威；模型生成的摘要、权限描述和“完成”判断不能自行授予权限或关闭工单。
- 预算闸门已取消：不按执行时长、Goal 请求数、token、金额或期限截停任务；保留用量展示、停止、权限、未知效果与死循环防护。

## 模块与服务边界

仍以五个源码包交付一个 benchgo-plugin。SuperAgent 的 Cordis 入口是 benchgo-plugin/superagent-plugin，提供 assistant 服务，依赖 Harness 聚合的 commander；原 assistant 协议和数据目录不随源码拆包改名。

| 组件 | 职责与边界 |
| --- | --- |
| BenchGo 基础层 | 公共配置、模型目录与凭据、数据根、客户端装配及共享资源 |
| 官方 Harness | Agent、会话、模型调用、工具、审批、Schedule、skills、原始日志与运行环境 |
| Harness 聚合 / commander | 原生 Agent 接入、会话聚合和适配；SuperAgent 工单 Worker 当前直接使用官方 ctx.agents，并非默认启动原生 CLI |
| SuperAgent / assistant | Trigger、研判、工单、授权快照、分派、订阅、验收、交付、学习与恢复协调 |
| Voice | ASR、TTS、通话和语音配置；SuperAgent 不复制音频控制器 |
| Link | 多端认证与既有服务转发，不直接读 SuperAgent 私有数据库 |
| 渠道适配器 | 校验真实来源、归一事件、发送与回执，没有独立授权或调度权 |

Router 与 Worker 是官方 Agent 会话。Assessment、分派领取、验收、交付、学习复盘及监督主要是后台代码服务，部分步骤调用模型；它们不是一批额外常驻人格 Agent。

当前外部研判可直接写入工单，任务验收由编排服务调用模型，交付由 outbox 推进。图中的“Router 研判、验收、交付”表示逻辑职责，不代表每一步都进入桌面主聊天的同一个 Agent 回合。

## 共同验收边界

各模块的已有机制、未完成部分和验收条件在所属文档就地维护，不另立现状或验收流水。源码、生成产物、安装目录和运行实例分别核实；npm run check 只检查版本、工作区与入口一致性。

一次本地文件自检成功不能替代指定原话、原会话和并存旁聊条件的验收。隔离 profile 的真实模型请求也不能替代正式档案验证；未完成的原场景不标可投入使用。

验收按目标类型验证：普通问答不强制开单；执行请求须派工、留证、验收并回原来源；跨会话控制仍拒绝；失败显式呈现；重启不重复副作用。前端另查四态并由用户最终验收。

测试报告注明提交、运行环境、全量串行整跑或分文件、总数与失败，不删除或弱化安全断言。真实验证保留 Trigger/Ticket/Run/Result/Delivery 的关联及实际工具调用，不能以工具目录存在证明联网或其他能力实际可用。
