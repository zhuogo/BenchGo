# SuperAgent 设计

本文是 SuperAgent 板块唯一设计文档，统一记录已定机制、当前实现与未完成边界。总览见[总架构](../总架构.html)；本文不以局部测试通过或已有接口推断完整链路可用。设计与源码核对日期：2026-11-07。

## 定位与范围

SuperAgent 是 BenchGo 面向个人的总助手，承担持续对话、事件研判、任务编排和结果交付。连续指对话与任务能够读账续行；持久指身份、记忆与技能可以积累；主动必须受书面规则和当前授权约束；高效以结果可靠为前提。

产品优先完成主聊天与旁聊，项目聊天押后。首轮以单机桌面和飞书闭环为基线；渠道扩展和多端不成为本地任务执行的前置条件。

- 占最少注意力约束后台通知，不限制用户正在聊天时的正常回答。结果可用、明确失败或确需人决定时应及时沟通。
- 确定性动作交给代码：身份、准入、去重、状态、权限、索引、计数和投递。模型负责理解、研判、执行及语义验收。
- 新能力优先组合现有插件、服务和配置，不新增平行会话系统、推理循环、Cron 或任务数据库。
- 原始用户要求、来源和实际执行证据是权威；模型生成的摘要、权限描述和“完成”判断不能自行授予权限或关闭工单。
- 预算闸门已取消：不按执行时长、Goal 请求数、token、金额或期限截停任务；保留用量展示、停止、权限、未知效果与死循环防护。

## 模块与服务边界

仍以五个源码包交付一个 benchgo-plugin。SuperAgent 的 Cordis 入口是 benchgo-plugin/superagent-plugin，提供 assistant 服务，依赖 Harness 聚合的 commander；原 assistant 协议和数据目录不随源码拆包改名。

| 组件 | 职责与边界 |
| --- | --- |
| BenchGo 基础层 | 公共配置、模型目录与凭据、数据根、客户端装配及共享资源 |
| 官方 Harness | Agent、会话、模型调用、工具、审批、Schedule、skills、原始日志与运行环境 |
| Harness 聚合 / commander | 原生 Agent 接入、会话聚合和适配；SuperAgent 工单 Worker 当前直接使用官方 ctx.agents，并非默认启动原生 CLI |
| SuperAgent / assistant | Trigger、研判、工单、授权快照、分派、订阅、验收、交付、学习与恢复协调 |
| Voice | ASR、TTS、通话和语音配置；SuperAgent 不复制音频控制器 |
| Link | 多端认证与既有服务转发，不直接读 SuperAgent 私有数据库 |
| 渠道适配器 | 校验真实来源、归一事件、发送与回执，没有独立授权或调度权 |

Router 与 Worker 是官方 Agent 会话。Assessment、分派领取、验收、交付、学习复盘及监督主要是后台代码服务，部分步骤调用模型；它们不是一批额外常驻人格 Agent。

当前外部研判可直接写入工单，任务验收由编排服务调用模型，交付由 outbox 推进。图中的“Router 研判、验收、交付”表示逻辑职责，不代表每一步都进入桌面主聊天的同一个 Agent 回合。

## 入口与两档分流

按噪音与来源性质分档，不按渠道名一刀切。可信适配器决定 source、actor、owner 和 policy；正文不能自报身份、替人授权或覆盖来源。

| 入口 | 已定处理 | 当前实现边界 |
| --- | --- | --- |
| 桌面主聊、旁聊 | 用户主动输入直通 Router，完整保留原文；登记 Trigger、去重，跳过“是否接单”的 Eval | 已使用 direct 登记；成功 assistant_delegate 后写 candidate、decision、ticket，不能以桌面无 candidate 直接诊断分诊停摆 |
| 已验证主人一对一 | 同属低噪音直通，不做群聊窗口裁剪 | 外部私聊当前仍进入候选研判，与直达常驻 Router 的目标有差距 |
| 群聊、自动采集、机器事件 | 归一、代码准入、候选研判，合格再汇入工单 | 渠道入口已有实现，真实来源逐渠道验收；抓取和截图等图示不等于已有连接 |
| 已订阅工单的跟进 | 作为原单上下文持久收件，按安全边界应用 | 不附带新权限；改变目标、验收或范围须走修订与授权复核 |
| 定时事件 | 官方 Schedule 触发，按已授权规则形成机器 Trigger | 纯提醒可直接回复，执行型任务仍建单；按来源会话、scheduleId、occurrence 去重 |
| 非主人一对一 | 独立身份与信任边界 | 不能当桌面主人；完整产品规则仍待定 |

群聊新事项默认须实际 @，并复核名单、会话范围与准入强度；未 @ 的讨论可作订阅参考，不能据此自行建单。允许名单内机器消息可进入 inferred，但仅在 auto 模式及有效书面规则下开单。平台成员允许使用机器人，不等于获得桌面主人权限。

高噪音窗口使用确定性卡片与原文指针：初始口径为线程头 5 条、触发前后各 5 条，长文标明全长与裁剪，按需回读；不先用模型摘要替代唯一原文。主人直聊“不压缩”指入口不做这种窗口化，不禁止长期会话使用宿主上下文整理。

## 研判与领域记录

候选按 Thread 攒批，同线程最多一个活跃 Eval，跨线程独立推进。先排除已由订阅持有的上下文与已开单 Trigger。研判只给建议，代码复核身份、policy、规则、范围与版本后才能提交 Decision。

新候选可 accept、answer、ask、ignore；已有工单的挂靠、停止、修订、handback 是独立处置。inferred 接单必须满足 auto 和所引规则全部启用，旧 policy 返回不得落单。Eval 超时最多重排 2 次，再失败保留 unavailable 和重评入口，不把队列等待当模型超时。

| 记录 | 权威内容与不变量 |
| --- | --- |
| Trigger | 稳定来源键、渠道/会话/消息、actor、原文及时间；不可变、去重，同键异内容不能覆盖历史 |
| Candidate / Eval | 上下文引用、准入依据、规则版本、批次、owner、attempt、deadline 与结果状态 |
| Decision / Disposition | 模型建议、代码复核、原因、规则引用与实际去向，支持审计 |
| Ticket | 标题、目标、验收、活摘要、来源、生命周期与 instructionRevision |
| Mandate | 策略版本、范围、强度、规则引用、发起人身份；不可变授权快照，不含资源预算 |
| Assignment / Run | 任务包、执行安排、优先级，以及实际 session、环境、租约、fence、检查点和效果状态 |
| Subscription | Thread 与 Ticket 多对多关系、消息游标、持有/处理/释放状态，不扩权 |
| Result | 当前要求版本的正文、证据、按目标需要的产物、未尽事项及验收结论 |
| Attention | 原问题、请求人、来源、工单与要求/结果版本、回答及处理状态 |
| Delivery / Outbox | 原来源、结果/问题引用、幂等键、尝试、回执、错误与下一次投递 |

instructionRevision 表示工作要求变更，配置 revision 或记录版本表示并发控制，心跳不能让旧结果匹配新要求。业务工单状态、执行状态、等待原因和交付状态分别记录；idle、模型停笔、HTTP 成功都不表示任务完成。

## Router 与持续主会话

Router 是用户对话入口与总调度者，主聊和旁聊各自有官方会话，但共用 SuperAgent 模型配置。旁聊隔离话题和归属，不另建人格或更高权限。

- 普通问答、工单查询、卡片提问、定时协调、记忆记账与受控配置使用协调工具。
- 查网站、查文件、写代码、跑命令和其他环境操作从第一次探查起就委派 Worker；普通派工不再额外询问是否允许创建工单。
- 工单落库后立即返回当前 Router；由 Router 自然回应，继续接受其他请求，不阻塞等待 Worker。
- 不相关新请求独立分诊、查重后并行派工；同会话写入串行，只有冲突资源在冲突处串行。
- 内置层真源为 plugins/superagent/prompts/builtin-layer.md，随插件构建并注入系统 section；它与用户文档层分开，不由用户档案覆盖平台机制。
- 工具失败必须按真实错误码与原因显示明确的系统状态，不能由模型猜测“权限策略”等理由；完整持久错误反馈目前仍是未完成项。

逻辑 thread 与底层模型 session 分离。服务端 send 接受 threadId、text、requestId 和可选 replyContext，先持久收件，再串行启动 Router 回合。同 requestId 同内容幂等，正文或可信引用变化拒绝复用。

回执区分 queued、processing、processed、failed、uncertain、cancelled；processed 仅表示 Router 回合结束。requestState/history.requests 用于重连对账，不能因回执未知自动重发。取消排队请求与当前 Router，不等于撤销后台工单；清空聊天保留工单、去重记录和 sessionLineage 归属。

服务端持久 inbox、取消、恢复和逻辑会话归属已有代码。旧专题曾称官方 composer 全面接入，后续现状与公开接缝核查不支持该结论；当前不能宣称桌面所有发送入口已接持久收件，附件、重连和真实桌面重启仍需完整验证。

## 工单、跟进与目标

标题开单生成，当前统一上限为 10 个 Unicode 字符；完整 target 与 acceptance 不截断，改标题不递增要求版本。活摘要表达当前目标、进展和卡点，供列表、通知和查重使用。

跟进默认先判定是否属于原单：补充或转向走修订，提问直接回答，超出 Mandate 先确认范围。修改执行中工单先安全停止原执行、复核原始用户指令与版本，不能让新旧要求并发写同一会话。

新建前按在办及刚关工单的标题、摘要查重；同 Trigger 一张工单是代码不变量。显式幂等与同 Trigger 去重不能代替跨消息语义查重。已交付工单不回改，后续要求新建关联调整单，只描述差异并引用原结果。

当前已有标题、摘要投影、请求幂等、来源与归属复核及关联调整机制；语义判重、合并和交付后调整的完整用户路径仍需单独验证，不能凭底层字段声明全部完成。

订阅仅传递上下文。忙时先返回“已收到/待应用”，动作边界应用后才确认；多工单持有时不能把一条消息广播成所有工单的新命令。越界 handback 每工单每 Trigger 限一次，释放持有并留原因，禁止无限踢转。

持续目标以 SQLite 结构化记录为本体，叶目标绑定工单，复用同一授权、执行与验收；子目标可成树。创建去重、暂停/停止须等底层执行确认，不能把 pausing/cancelling 当成已经停止。

当前目标偏执行型，需项目、模型与指令；纯跟踪事项、按日期进展账、目标说明与成果目录、活跃目标上下文投影、goalId 与 Schedule 归属仍有缺口。目标存在不自动授权无限执行，GOAL.md 只能作笔记，不能替代结构化状态。

## Worker 与一层子代理

Worker 是按单领取的临时执行者，无长期身份和专长档案；经验积累在记忆与技能中。Router 决策先写 Assignment，后台代码机械领取，当前使用官方 ctx.agents.create/resume。实际并发上限由配置控制，默认缺省为 2，不承诺无限设备资源。

任务包包含目标、验收、授权范围、必要上下文卡片与原文指针。目标要求三重隔离：独立会话、独立工作环境、状态外置。代码项目优先使用独立 worktree，其他任务使用 Worker 目录；目录隔离不等于 OS 安全沙箱。

Worker 可以按效率自主下派独立任务，限制一层：

1. 子任务只拿本工单任务切片与原文指针，权限不超过父 Worker。
2. 子代理不得再委派，不读取 Router 全套开局包，不直接向用户提问或交付。
3. 结果由运行时回送父 Worker；父 Worker 可继续做独立工作，不持续轮询或编造进度。
4. 不因暂时安静而关闭；失败或中断先检查已有产出，再决定替换、恢复或上报。
5. 不可逆动作重复前先核实效果，失败报告不等于动作未发生。
6. Worker 汇总、复核子代理结果后提交本单结果包，并对完整性负责。

当前官方子代理深度与权限门已有实现；真实并发、恢复及审批传递仍须与运行实例核对。

## 权限、执行门与恢复

冻结文档用于理解，磁盘现行规则用于许可。每个受控动作前复核当前 policy、Mandate、工单要求版本、有效执行归属和适用审批；规则收紧立即阻止未执行动作，无法确认权限则拒绝。记忆沉淀不能放宽授权。

不可逆外部动作遵守用户授权及宿主审批，不以模型传 human=true、authorized=true 或旧文档中的许可绕过。配置、当面记忆管理和普通委派按各自契约办理，不把所有协调操作一律升级为额外审批。

单数据根只有一个编排所有者，多窗口是客户端。Assignment 领取和续租有唯一 owner、lease 与 fence；旧执行者不能提交新权属的结果。lease 过期给出核实与接管机会，不自动证明旧进程已停或动作可重做。

恢复前核实原 session writer、Run、工作区、checkpoint、transcript、当前要求/结果版本及权限。保留原 Assignment/Run/session/成果续行；未知外部效果保持 uncertain，不能靠更换调用 ID、重排参数或重建任务重放。

写文件和危险命令前按能力建立检查点，恢复保留用户后续修改；文件快照不能撤销外部发送、付款等效果。停止、撤权和新要求优先于迟到结果、自动重试与恢复。

Watchdog 对 Worker 可核实卡死、异常并恢复或升级；对活着的 Router 只观察、不纠偏改派，对确认失活的 Router 才恢复存续。调度心跳、模型请求 deadline、执行租约与合法异步等待分别判断；请求超时不等于整张工单作废。

## 成果证据与验收

Worker 提交正文成果、做了什么、实际证据和未尽事项。验收以当前 target、acceptance、原始用户要求和授权为准，不临时增加产物条件；代码复核归属、版本、待应用消息和必要检查后，才允许提交完成。

| 任务类型 | 验收依据 |
| --- | --- |
| 纯文本、查询、调研 | 正文满足要求；需要联网核实的内容提供实际来源、时间、覆盖范围、限制与工具证据；允许零文件 |
| 文件、代码、UI、媒体 | 所要求产物或变更可读且符合目标，执行证据可追溯；UI 按要求提供前后视觉证据，用户明确免除时记录边界 |
| 混合成果 | 各部分按各自目标验收，不要求无关附加文件 |
| 外部副作用 | 真实目标、调用回执与效果状态可核实；进程退出和 Worker 自述不足以证明成功 |

宿主从官方会话工具调用与结果生成 toolEvidence，含原工具名、callId、事件序号、参数/结果文本、错误标记与 hash；推理、图片和二进制不复制为验收正文。投影有界，必须标注遗漏、原长度与截断。

验收可按当前 Run 的真实工具序号补读原文，先校验 sessionId、lastSeq、日志 hash 和结果归属；不能读取任意会话或主机文件。当前内部 readEvidence 最多 3 轮补读、每轮最多 8 页、每页最多 8000 字符，仍无可靠结论则等待。

联网证据区分原网址、来源或转载关系、报道时间与抓取时间。同稿转载不算独立多源，只有链接不算读过正文；未核实的标为待确认，不编造链接、star 数或抓取结果。已有替代来源足够时可按用户目标说明限制，工具曾失败不自动否定最终成果。

当前任务验收在 orchestration-runtime 中调用模型，不是把结果交给常驻聊天 Router 再跑一轮。review-worker 另处理学习、记忆和技能复盘，不能混称为任务验收。

## 验收分支、Attention 与交付

| 分支 | 系统动作 | 用户可见行为 |
| --- | --- | --- |
| passed | 结果、验收、完成状态与唯一 outbox 一致提交 | 以自然正文回原来源交付 |
| rework / 可修复 failed | 保留原单和成果，核实原执行后追加修正指令、自动续做再验收 | 说明问题与下一步，同类重复状态去重，不额外问是否继续 |
| blocked | 保持打开或等待，创建绑定工单、版本、来源和请求人的 Attention | 提出具体信息、权限或范围问题，回答后原单续做 |
| review_wait | 保留已执行结果，补读证据或有界重试验收，不重复副作用 | 明示系统待核验及真实原因，不让用户替系统判断事实 |
| continuation_wait | 无进展或不能安全续做时保留等待与恢复入口 | 说明已保留成果与恢复条件，不伪装完成 |
| failed / stopped 终态 | 确认不可继续、授权撤回或用户停止等条件才结束 | 说明原因、已保留结果及后续入口 |

本轮结果失败、重试次数耗尽或模型不可用不能单独等同工单终态。内部待核验和真实用户阻塞分开，预算等待已退役。模型不可用时可用明确标注的系统状态，不伪装成模型回答。

Worker 问题原样逐级上报，子代理先到 Worker；需要用户决定的 Attention 回原请求来源。回答绑定原问题、请求人、instructionRevision、结果版本和 requestId；普通下一条消息不能被随意当作答案，过期或已回答问题拒绝重复应用。

Worker 原生 question 与 Review Attention 是不同来源：前者按官方问题调用恢复，后者将真实答案写回原分派 continuation，不能调用不存在的 Worker question。self/default/user 分类只在原 Mandate 范围内自动解答，权限与范围变化必须交用户。

验收与交付状态分离。发送失败只补投已保存结果，不重跑任务；发送效果未知先查回执，渠道无幂等保证时不承诺绝对仅发一次。不能回原来源时保留结果与明确失败，不悄悄改投别处。

当前桌面结果由持久通知投影到原逻辑会话，渠道由适配器发送，另有 deliveryWorker 向 Link/宿主设备送通知。accepted、sent、设备回执和用户已读分别记录，不能互相替代。

## 上下文管理与三类模型

上下文目标按三个层次装配：固定文档层、近期原文层、按需材料层。开局装配、每回合补材料、长会话整理各有触发点，压缩不删除原文引用、不偷偷刷新冻结文档。

Router 的十项开局包依次为：系统指令、运行信息、五文件全文、对齐总结、关系索引、活跃目标摘要、能力目录、保险库清单、其他对话摘要、本会话窗口。索引与目录只给名单，正文按需取。

Worker 目标只拿任务包，子代理只拿切片，辅助模型只拿本次工作材料。当前 Router 与 Worker 仍共享 getSessionContext 接口，Worker 会序列化通用上下文快照；不能宣称任务切片和全套文档隔离已严格实现。完整开局包、旁聊动态摘要与无感轮换仍待闭环。

| 模型角色 | 配置与行为 |
| --- | --- |
| Router | models 首选与备用队列，主聊/旁聊共用；新消息从本角色首选开始，回合内冻结路由 |
| Worker | workerModels 专用队列；未配置则继承 Router，任务显式选择优先 |
| 辅助模型 | 一个 auxiliary 槽及备用名单，按看图、压缩、总结、review 能力勾选；未启用能力或失败时按规则回 Router |

研判、任务验收与学习复盘当前可走辅助 review 能力，不只是“打杂”。模型角色是配置分工，不要求三个模型或 Agent 同时常驻。

providerId、modelId、工具名和协议值都是不透明标识，不猜别名或静默改写。选择、保存、重载、能力解析和实际请求必须一致，编辑单项保留其他配置；能力不支持要明确告知。

Fallback 按错误分类、有界备用顺序执行：取消、政策或权限拒绝不切换绕过，403 仅在适配器明确判定凭据故障时处理。跨供应商保留对话语义与工具结果，重新解析推理参数，不重放已生效工具。

密钥池仍是已定目标，当前旧 keyPools 已移除，后续复用基础层凭据与供应商路由落实；不能恢复旧字段冒充完成。RouterGo 管其供应商内部线路，本地备用管客户端目标不可用，避免无界叠加重试。

## 文档记忆、原文账本与学习

同一助手有两层记忆：Markdown 提炼正文保存身份、事实、决定和经验；账本保存原始事件与关系。宠物和 Router 不各建记忆。冻结快照管理解，实时执行门管许可。

| 固定文档顺序 | 职责 |
| --- | --- |
| SOUL.md | 性格、表达与底线 |
| IDENTITY.md | 姓名、形象与对外身份 |
| USER.md | 主人称呼、时区与偏好 |
| AGENTS.md | 工作约定、审批红线、渠道与保险库规则 |
| MEMORY.md | 决定、关系与长期结论，每日日志另作流水 |

TOOLS.md 保留兼容管理与用户原文，不作为固定第六项注入；真实工具能力由宿主注册表确定。身份名称以 IDENTITY.md 为准，config.name 仅在缺少 name 字段时回退。

会话按 sessionId 持久冻结文档与 hash，恢复复用快照；人格和记忆即时落盘，下一会话生效，明确遗忘可脱敏派生快照。文档目标为 add/patch/remove 精确修改；当前主要是完整 content 加 expectedHash、版本与 journal，不能说增量编辑协议已完成。

并发写入冲突先重读，不覆盖用户修改；多文件部分成功须显式记录。遗忘同步正文、索引与派生内容，已拒绝或遗忘内容不得被历史候选重新写回。留痕要求不能抵消明确删除要求。

项目规则按 .hermes.md → AGENTS.override.md → AGENTS.md → CLAUDE.md → .cursorrules first-match；同名规则沿适用目录链合并，深层更具体。复用官方上下文能力，在插件侧适配语义，不能同时叠加重复加载器。

Harness 是原生会话日志唯一写入者；SuperAgent 按 sessionId/eventSeq 导入可重建的原文索引。ledger.db 的中文 FTS5、分页与水位已有实现；链式引用连接 Trigger、Thread、Ticket、Run、Result、Attention 和 Delivery，完整业务关系投影仍需补齐。

读取按 ID 返回原文、来源、全长与 nextCursor，不重新总结；memory 的提炼检索与 ledger 的 FTS5 是两条路径，当前未完全统一。检索性能必须实测，参考项目时延不能当 BenchGo 承诺。

学习有三个同源入口：/learn、明确自然语言请求、持久双计数器。默认每 10 个用户 prompt 或单回合第 10 次工具迭代触发 review，去重、保存水位，前后台并行，后台输出不递归触发学习。

用户明确记住、纠正、遗忘直接生效；自动记忆须有可信用户来源、有效正文并符合学习规则，不另开专门工单或逐条审批。排除、关闭学习和遗忘保护继续有效，外部文本不能沉淀成主人授权。大语料按章蒸馏仍属目标。

技能复用官方 skills，SuperAgent 只生产与策展自建内容。标准结构为 When to Use / Procedure / Pitfalls / Verification，只写泛化规则与原因，不写任务日志。管理统一在“工具 → 技能”，资源页不重复。

自建技能目标是系统质量、来源和去重审核后直接管理；当前仍有候选批准/拒绝，完整编辑、归档与回滚界面未齐。Curator 仅处理自建且未固定技能：14 天 stale、30 天归档，永不自动删除，合并前快照，LLM 合并默认关闭。

## 渠道、语音与秘密

入口统一为“资源 → 接入 → 多平台”，目录包含飞书、企业微信、QQ、微信、Telegram、Discord、WhatsApp、Email、Webhook、API Service。适配器存在不代表真实账号可收发，认证、接收、发送与回执分项显示。

配置按渠道 revision 保存，旧连接保持既有限制，留空凭据保留原值。可用性依据实际状态：可用为品牌色，不可用为灰色，不随选中状态改变。外部上下文不混进桌面主人身份，控制工单必须复核原请求人及来源归属。

飞书可显式沿用平台应用人员范围；私聊与群聊独立配置，群选择仅 @、讨论上下文或停用，支持群名称查询分页。讨论补读是有界参考，不因获取历史就获得主动开单权限；自由发现任务仍是目标。

渠道凭据仅保存不透明引用 benchgo-channel:<channel>:<uuid>，由服务映射到宿主合法凭据记录，AES-256-GCM 的 AAD 绑定公开引用。凭据录入与配置提交分步确认，后者失败不能显示连接更新成功；自动迁移与替换后清理未全部完成。

保险库目标为加密存储、Agent 不见明文、句柄与目标绑定、系统代填及脱敏回执，不要求额外口令或手动/闲置锁定。执行前复核目标、方法、当前权限和审批；凭据不进入聊天、记忆、工具参数日志或导出。环境变量引用本身不等于完整保险库。

| 接入 | 特有契约或限制 |
| --- | --- |
| Webhook | HMAC-SHA256 校验 timestamp + "." + 原始请求体；五分钟窗口，正文上限 64 KB，稳定请求键去重 |
| API Service | 复用已认证 owner dispatcher，不接受载荷自报身份 |
| Email | IMAP TLS / SMTP、线程关联与防回复循环；允许发件人还需首行 BenchGo-Token 校验，验证后剥离 |
| WhatsApp | Business Cloud API，验签原始请求体及目标 Phone Number ID；媒体只处理 caption，超客服窗口明确失败，不擅发模板 |
| 微信 | 当前 iLink 私聊范围，不能宣称全部个人微信能力 |
| Discord 语音 | /join、/leave 显式控制，允许用户范围；复用 Voice ASR/TTS，最长 20 秒分段、最多三段排队 |

Discord 语音是分句近实时交互；全双工、打断、多人混音待实施。语音依赖缺失保留文字能力并提示；文字已送达后语音失败不重发文字。语音、渠道账号和打包依赖各自做真实验收，不能用适配器测试代替。

## 对话界面、身份与形象

复用官方输入、草稿、发送、取消、审批与渲染能力，QuietChat 只作受控投影，不创建第二套聊天系统。主聊优先，旁聊隔离来源与上下文，资源页统一承载身份、任务、记忆、产物、接入和系统文件。

普通 Router text 可作为正文或进度流式显示，必须绑定真实 session/turn/request；正式出口为 assistant_reply 或官方 completed 回合的有效终答。显式发布按请求幂等，正式消息替换同一暂存身份，取消/失败清除未提交正文，流式片段不是任务完成。

工具参数、工具原始返回、推理、系统提示和 Worker 原始输出不进入正文。交付按普通助手消息展示，不另加“交付通知”卡框、分类标题或已读按钮；系统状态注明来源，选项和审批保持各自语义。

已作答的选项卡问答显示用户侧气泡，含问题与所选答案；跳过题标注已跳过，未答、失败或格式不符不伪造记录。问题等待时提供明确作答提示，答案绑定原问题和版本。

消息工具栏固定在正文两侧，显隐不改变间距和滚动高度；悬停/聚焦/浮层显示，触屏常显。复制纯文本、时间与用量取真实记录，缺失显示未记录。本地表情回应按稳定消息键持久化，不发送渠道，也不授予权限。

首页展示真实待关注、推进中与完成任务，快捷起草可编辑、不自动发送或覆盖草稿。设置只提交变更字段，冲突保留草稿；空、加载、错误、有数据四态和窄容器、明暗主题、减少动态均须验证。通用视觉遵循[工作台与 Agent 设计](../02-工作台与Agent/设计.md)。

<a id="identity"></a>

BenchGo 是统一产品、Logo 与吉祥物 IP；SuperAgent、Router、宠物是同一个助手。默认正式素材来自 assets/brand/，个人外观不替换应用、托盘与安装品牌，改形象不改名字、模型、权限、记忆或正在执行的任务。

姓名默认可空，身份页和聊天共享 160×40 名片。cardHtml:null 使用当前形象与姓名；自定义 HTML 最多 16000 字符，sandbox 禁止脚本和网络，无有效内容兜底且不改写原文。清空保存即恢复默认显示，不恢复已撤销的模式切换和独立恢复按钮。

形象创作走现有聊天与图像服务：先查真实素材目录，优先复用已有组合，生成后先预览再应用，可取消和回退。上传 PNG/JPEG/WebP 须实际解码为静态 PNG、移除元数据，限制 8 MiB、单边 8192、总像素 32×1024×1024。

动作由真实事件和受控本地配方触发，不从措辞猜任务成功、不为每次表达调用模型、不因缺素材自动生成。外观版本绑定表情，换装不混播旧衣动作。

当前形象管理、基准表情映射与形象页短动作预览已有实现；聊天名片仍静态，原创短表情、完整动作接线、裁切、参考图局部编辑和桌面悬浮未完整实现。桌面形象目标仅为同角色轻窗口、拖动与回到现有聊天，不另造人格、记忆、输入框或任务中心。

## 公共接口与数据契约

人端 HTTP 统一为 POST /api/commander/assistant，机器字段以[OpenAPI](../../plugins/benchgo/openapi.json)为准；模块实现见[服务装配](../../plugins/superagent/src/service.mjs)。旧 action 适配同一领域服务，不另存状态。

| 接口族 | 关键契约 |
| --- | --- |
| state / ensure / history / send / requestState / cancel | 会话、持久收件与回执；接收、处理、任务完成分别表达 |
| assistant_delegate / assistant_tickets / assistant_ticket_control / assistant_ticket_change | 绑定宿主 Agent 与原始用户请求，按逻辑 thread/sessionLineage 限定工单；模型参数不能声明 owner |
| ticketRetryReview | ticketId + expectedResultVersion，只读重审原证据；unchanged 仅表示输入未变 |
| ticketAnswer | ticketId、attentionId、instructionRevision、requestId 与真实答案；校验原问题、来源、版本与状态 |
| ticketResume | 暂停按原恢复契约，续做等待校验 expectedResultVersion；queued:false/code 不是恢复成功 |
| config / profileDocuments / memorySave / memoryDelete | revision 或 expectedHash 冲突保护，秘密不返回；旧记忆候选接口仅弃用兼容 |
| connectionCatalog / connectionConfigure / connectionCredential / connectionAction / connectionStatus / connectionVerify | 配置、凭据、安全操作与运行状态分离，使用真实连接结果 |
| ledgerRead / assistant_ledger_read / assistant_session_search | 依权限分页返回原文，不按摘要伪造来源 |
| ownedSkills 与批准、拒绝、固定、恢复 | 当前候选协议保留；未实现直管操作不能先注册为可用 |
| artifact / system-file / Voice 兼容路由 | 保留鉴权、受控目录、文件类型与大小约束，Voice 生命周期由 Voice 服务负责 |

Router 的 assistant_* 工具只注册给拥有会话的 Agent，不等于全部暴露为外部 MCP。外部 MCP 保持既有委派边界，不新增任意配置、凭据明文、历史读取或消息发布权。人端接管、凭据录入、导入等不能用模型声明代替真实用户权限。

assistant.db 保存控制面、工单及运行记录；ledger.db 保存可重建原文检索；官方会话日志保存原始执行；Markdown 保存提炼正文；state.json 保存逻辑会话映射等状态。默认数据根为 ~/.benchgo/assistant/。

副作用先持久登记，数据库事务不等待模型或网络。完成结果、验收、终态与结果 outbox 一致提交；文件与数据库用 journal/hash 恢复一致，不宣称跨介质原子事务。投递按稳定 id 去重，发送重试与执行重试分别处理。

错误区分参数、认证/权限、版本/幂等冲突、能力不可用和效果未知；成功响应不得同时掩盖未应用、未完成或未送达。停用 SuperAgent 释放自身监听、计时器、worker、路由和数据库，保留用户数据，停止服务不等于撤销外部效果。

## 当前实现与验收边界

以下是设计维护所需的状态摘要，不是历史测试流水或上线承诺。改动源码、生成产物、安装目录和运行实例必须分别核实，npm run check 只检查版本、工作区与入口一致性。

| 范围 | 已有机制 | 尚未完成或必须复验 |
| --- | --- | --- |
| 桌面派工 | direct Trigger、真实来源、工单和官方 Worker | 主聊与未归档旁聊同时在线的原话复验；当前不能证明双模块实例导致的拒绝已根治 |
| 错误沟通 | 部分工具失败事件和临时错误显示 | 全部 Router 失败按真实错误码持久写入聊天；不得按关键词漏报或由模型猜原因 |
| 持久聊天 | 服务端 inbox、请求回执、sessionLineage、正式发布 | 官方输入入口完整接入、附件边界、连续请求与真实桌面重启 |
| 工单恢复 | lease/fence、检查点、证据重审、原成果续做和 Attention | 原环境多轮返工、阻塞回答、暂停/恢复、失活与未知效果的完整真实闭环 |
| 标题与跟进 | 标题、摘要投影、幂等、同 Trigger 唯一归属及调整单基础 | 语义查重/合并、跟进分诊、关联调整完整用户路径 |
| 上下文与模型 | 五文件冻结、角色模型队列、辅助能力路由 | 十项开局包、Worker 严格任务切片、旁聊摘要、官方只读模型选择契约兼容 |
| 记忆与技能 | 记忆直写、来源/版本保护、计数学习、自建策展 | 技能直管、完整版本回滚界面、按章蒸馏、统一业务原文关系 |
| 渠道与 Voice | 适配器、凭据引用、语音及原来源交付代码 | 每种真实账号收发、跨渠道 Attention、语音设备/依赖、重启投递 |
| 治理与供给 | 现行许可、审批、保险库句柄、用量记录 | 目标服务安全代填与密钥池职责、完整健康状态和升级处置 |

一次本地文件自检成功不能替代指定原话、原会话和并存旁聊条件的验收。隔离 profile 的真实模型请求也不能替代正式档案验证；未完成的原场景不标可投入使用。

验收按目标类型验证：普通问答不强制开单；执行请求须派工、留证、验收并回原来源；跨会话控制仍拒绝；失败显式呈现；重启不重复副作用。前端另查四态并由用户最终验收。

测试报告注明提交、运行环境、全量串行整跑或分文件、总数与失败，不删除或弱化安全断言。真实验证保留 Trigger/Ticket/Run/Result/Delivery 的关联及实际工具调用，不能以工具目录存在证明联网或其他能力实际可用。
