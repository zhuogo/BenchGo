# SuperAgent 设计

本文件是 SuperAgent 板块总览。每个小模块在下表对应文档维护一份设计，不重复保存同一机制的平行版本。整体板块关系见[总架构](../总架构.html)。设计与本轮源码接线按 2026-11-08 用户裁决更新；各模块分别说明已接线、定向验证及真实运行未验部分，不把文档或局部测试通过视为完整闭环。

## 定位与范围

SuperAgent 是 BenchGo 面向个人的总助手，承担持续对话、事件研判、任务编排和结果交付。连续指对话与任务能够读账续行；持久指身份、记忆与技能可以积累；主动必须受书面规则和当前授权约束；高效以结果可靠为前提。

产品以主聊天、旁聊和真实工单执行会话形成完整路径。执行会话归所属项目工作区，无项目归官方「未分组」（按最近活动排序），带工单标记并支持直接插话；从任务列表打开工单详情进入同一会话，聊天消息不提供该跳转入口，共用同单输入账，结束自动收纳。首轮以单机桌面和飞书闭环为基线；渠道扩展和多端不成为本地任务执行的前置条件。

渠道只能是适配器：事实标注与协议转换留在适配器，来源核对、准入、研判和后续执行复用 BenchGo 统一机制。渠道会话复用工作台会话列表与回复路径，带来源标记，可采用旁聊形态；渠道不保存独立对话状态或第二份工单账。本轮统一管线、会话桥与主人手写原文回复已接线并通过对应定向测试，真实账号收发及产品界面未完成验收；字段、映射、授权与客户端路径权威见[链接与渠道](链接与渠道.md)。

总架构将调度与执行、上下文管理、模型调度归为 **Super Harness 机制**，描述 SuperAgent 如何运转；权限、持久化与记忆作为横向支撑。该分组沿用现有插件与服务边界，不新增安装包，整体关系只在[总架构](../总架构.html#superagent)汇总。

2026-11-08 权限设计：Main Agent（Router 职责）内部默认完整能力，主聊/旁聊关闭 Harness 权限档位选择；Worker 与一层子 Worker 继承授权并按任务和工具面静默裁剪。终端/浏览器开放完成准备，高危提交经能力声明注册的结构化通道逐次审批，无通道交用户最后一步接管；放弃任意脚本的万能提交识别。动作存储、可信注册表、审批及授权管理和逐工具硬门已接线并通过定向测试；专用适配器、安全输入和完整接管仍有缺口，真实 Harness 卡点击及账号发送未验。规则与当前覆盖只在[任务与执行](任务与执行.md#权限与对外审批)维护，凭据流程见[链接与渠道](链接与渠道.md#保险库与安全输入)。

执行与交付目标：用户始终与 Router 对话，不设独立任务内容验收层。Worker 在原执行会话轻量自校验，优先运行适用的测试、构建与命令输出检查，将成果原稿保存到工单并向 Router 发完成信号。Router 主动自然提醒已完成，自选摘要或完整回复后交付原来源，不固定工单报告、标题前缀或系统状态文案；原稿留在工单详情，Router 不重派或验收。追问可读原稿直接答，实际改成果走修订或关联调整单。成功回复确认送达后 completed；偶发故障先退避重试，结构性无解才由 Router 自然说明失败，确认送达后 failed 关单，用户回话可续原单或开调整单。生成或投递失败保留待交付，只重试表达或投递，不重跑 Worker。新链已接线并有定向测试，安装版真实链路仍待重验，具体流程及旧证据边界见[自校验与交付](自校验与交付.md)。

- 占最少注意力约束后台通知，不限制用户正在聊天时的正常回答。结果可用、明确失败或确需人决定时应及时沟通。
- 确定性动作交给代码：身份、准入、去重、状态、权限、索引、计数和投递。模型负责理解、入口研判、执行、原会话轻量自校验与 Router 自然表达，不另设任务内容评分、语义验收或自动验收返工。
- 新能力优先组合现有插件、服务和配置，不新增平行会话系统、推理循环、Cron 或任务数据库。
- 原始用户要求、来源和实际执行证据是权威；模型生成的摘要、权限描述和“完成”判断不能自行授予权限或关闭工单。
- 预算闸门已取消：不按执行时长、Goal 请求数、token、金额或期限截停任务；保留用量展示、停止、权限、未知效果与死循环防护。

## 模块与服务边界

仍以五个源码包交付一个 benchgo-plugin。SuperAgent 的 Cordis 入口是 benchgo-plugin/superagent-plugin，提供 assistant 服务，依赖 Harness 聚合的 commander；原 assistant 协议和数据目录不随源码拆包改名。

| 组件 | 职责与边界 |
| --- | --- |
| BenchGo 基础层 | 公共配置、模型目录与凭据、数据根、客户端装配及共享资源 |
| 官方 Harness | Agent、会话、模型调用、工具、审批、Schedule、skills、原始日志与运行环境 |
| Harness 聚合 / commander | 原生 Agent 接入、会话聚合和适配；SuperAgent 工单 Worker 当前直接使用官方 ctx.agents，并非默认启动原生 CLI |
| SuperAgent / assistant | Trigger、入口研判、工单、授权快照、分派、订阅、结果持久化、投递与送达关单、学习与恢复协调 |
| Voice | ASR、TTS、通话和语音配置；SuperAgent 不复制音频控制器 |
| Link | 多端认证与既有服务转发，不直接读 SuperAgent 私有数据库 |
| 渠道适配器 | 协议收发转换、渠道账号与 BenchGo 身份映射、消息归一和能力声明；只提供来源事实，不做准入/研判，不保存对话状态或另建会话实现；渠道授权逐适配器绑定，由统一服务判定 |

Router 与 Worker 是官方 Agent 会话。Assessment、分派领取、投递、学习复盘及监督由后台服务协调，入口研判和学习可调用模型；它们不是一批额外常驻人格 Agent。Worker 对自身执行及一层子 Worker 的结果负责，系统仅做归属、版本、有效执行身份和落库等确定性校验，不增加独立内容判定门。

本轮旧独立任务内容 Review 与补审/返工链已移除，统一 outbox 与可信送达关单保留基础职责；Worker 保存原稿并通知、Router 表达后交付的新链已接线并有定向测试，安装版真实链路仍待重验，不能据旧链通过推定新链完成。迁移边界与定向覆盖见[自校验与交付](自校验与交付.md#实现与验收边界)。入口 Assessment、后台学习 review 和软件测试验收各保留自身职责，不能因名称相似被一并取消；真实桌面和渠道端到端仍须验证。

## 共同验收边界

各模块的已有机制、未完成部分和验收条件在所属文档就地维护，不另立现状或验收流水。源码、生成产物、安装目录和运行实例分别核实；npm run check 只检查版本、工作区与入口一致性。

一次本地文件自检成功不能替代指定原话、原会话和并存旁聊条件的验收。隔离 profile 的真实模型请求也不能替代正式档案验证；未完成的原场景不标可投入使用。

软件验收按目标类型验证：普通问答不强制开单；执行请求须派工、原会话机械轻量自校验、保存原稿及证据、通知 Router，由其主动自然表达并交付原来源；成功确认送达后 completed，结构性失败说明确认送达后 failed，用户可续原单或开调整单。验证摘要或完整回复由 Router 按对话判断、原稿可查、无固定报告或硬文案，不重派或增加内容验收。受阻保持等待，偶发故障先退避；执行超时核实后从检查点恢复，外部效果未知必须先核实，生成失败只重试 Router 表达、投递失败只补投回复，两者均待交付且不重 Worker。普通调整在原执行下一工具边界整份切换，不打断在途工具，暂停期间仅收修订；叫停/撤权/收窄立即拦后续动作，超 Mandate 扩权才确认新授权版本。另验真实会话项目工作区/官方「未分组」（按最近活动排序）归属、同会话跳转、统一输入账本和结束收纳；跨会话控制仍拒绝，重启不重复副作用。前端另查四态并由用户最终验收。

测试报告注明提交、运行环境、全量串行整跑或分文件、总数与失败，不删除或弱化安全断言。真实验证保留 Trigger/Ticket/Run/Result/Delivery 的关联及实际工具调用，不能以工具目录存在证明联网或其他能力实际可用。
