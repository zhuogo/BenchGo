# SuperAgent 设计

本文件是 SuperAgent 板块总览。每个小模块在下表对应文档维护一份设计，不重复保存同一机制的平行版本。整体板块关系见[总架构](../总架构.html)。各模块就地说明目标、已实现与待实施边界及验收条件；运行证据保存在 eval/ 或本地 artifacts/。

## 定位与范围

SuperAgent 是 BenchGo 面向个人的总助手，承担持续对话、事件研判、任务编排和结果交付。连续指对话与任务能够读账续行；持久指身份、记忆与技能可以积累；主动必须受书面规则和当前授权约束；高效以结果可靠为前提。

产品以主聊天、旁聊和真实工单执行会话形成完整路径。Router 主聊与旁聊由 SuperAgent 展示；Worker 和官方子代理同时在工作台侧栏与普通会话列表可见，可以打开原会话并直接发消息。执行会话底层归所属项目工作区，无项目保持官方未分组；内部可查看真实过程，输入可用性由服务投影决定；从任务列表打开工单详情进入同一会话，聊天消息不提供该跳转入口，共用同单输入账，完成后工单及执行会话仍在 SuperAgent 内保留，不自动归档，历史入口仍可查。首轮以单机桌面和飞书闭环为基线；渠道扩展和多端不成为本地任务执行的前置条件。

渠道只能是适配器：协议、来源核对和本渠道使用者权限归对应适配器，核心不区分主人与其他人的权限档位。渠道会话复用工作台会话列表与回复路径，不保存独立对话状态或第二份工单账。渠道专用策略已集中，适配器入口准入与按需研判仍有迁移缺口；目标、当前差距与字段边界见[入口与研判](入口与研判.md)及[链接与渠道](链接与渠道.md)。

总架构将调度与执行、上下文管理、模型调度归为 **Super Harness 机制**，描述 SuperAgent 如何运转；权限、持久化与记忆作为横向支撑。该分组沿用现有插件与服务边界，不新增安装包，整体关系只在[总架构](../总架构.html#superagent)汇总。

2026-11-11 已敲定本轮以做减法为原则：移除自有硬性限制和重复前置。一个工单对应一个官方 Worker 会话，会话内部委派完全使用官方 subagents，BenchGo 仅注入适用场景指导，不自定义子代理层级、继承或工具规则。删除独立授权管理与长期许可，需要确认的具体动作复用任务内审核；保险库简化为“地址或名称＋多项自定义凭证”，只负责秘密保存与使用隔离。上述身份、子代理、授权管理与保险库简化已有源码接线与定向回归；安装版实际路径仍待验收。执行与审核边界见[任务与执行](任务与执行.md)，凭据设计见[链接与渠道](链接与渠道.md#保险库与安全输入)，历史证据见[修复清单](../../task/11.11%20superagent修复清单.md)。

执行与交付目标：工单仅「进行中、等待、完成」三态。Harness Worker 正常结束且当前要求的成功原稿已保存，直接记为 completed 并通知 Router；适用测试由 Worker 在执行中完成，不增加结束后的效果审核、自检补回合或循环核查。Router 主动自然表达并交付原来源，原稿留在详情。结果不满意由用户找 Router 新建关联调整单，不自动返工。实际失败、待审批、待输入、暂停和中断保留真实原因，等待的有效范围见[自校验与交付](自校验与交付.md#等待的有效范围)；用户明确要求续接才按原会话处理。表达和送达独立记录，失败只重试对应阶段，不回退已完成工单或重跑 Worker。本轮简化的实现与验收边界见[自校验与交付](自校验与交付.md#实现与验收边界)。

- 占最少注意力约束后台通知，不限制用户正在聊天时的正常回答。结果可用、明确失败或确需人决定时应及时沟通。
- 确定性动作交给代码：身份、准入、去重、状态、权限、索引、计数和投递。模型负责理解、入口研判、执行、原会话轻量自校验与 Router 自然表达，不另设任务内容评分、语义验收或自动验收返工。
- 新能力优先组合现有插件、服务和配置，不新增平行会话系统、推理循环、Cron 或任务数据库。
- 原始用户要求、来源和实际执行证据是权威；模型生成的摘要、权限描述和“完成”判断不能自行授予权限或关闭工单。
- 预算闸门已取消：不按执行时长、Goal 请求数、token、金额或期限截停任务；保留用量展示、停止、权限、未知效果与死循环防护。

## 模块与服务边界

仍以五个源码包交付一个 benchgo-plugin。SuperAgent 的 Cordis 入口是 benchgo-plugin/superagent-plugin，提供 assistant 服务，依赖 Harness 聚合的 commander；原 assistant 协议和数据目录不随源码拆包改名。

初始化失败与热卸载统一清理：每项停止和解绑都捕获同步、异步错误并继续后续独立步骤，最终聚合报告。确认生产者停止后关闭数据库与存储，全部关闭成功才释放数据所有权锁；普通解绑失败不得跳过安全释放，无法确认写入者已停止时保留锁。禁止仅凭同一 PID 夺锁，避免重挂实例与旧写入者并发。

| 组件 | 职责与边界 |
| --- | --- |
| BenchGo 基础层 | 公共配置、模型目录与凭据、数据根、客户端装配及共享资源 |
| 官方 Harness | Agent、会话、模型调用、工具、审批、Schedule、skills、原始日志与运行环境 |
| Harness 聚合 / commander | 原生 Agent 接入、会话聚合和适配；SuperAgent 工单 Worker 当前直接使用官方 ctx.agents，并非默认启动原生 CLI |
| SuperAgent / assistant | Trigger、入口研判、工单、授权快照、分派、订阅、结果持久化、投递与执行完成与送达记录、学习与恢复协调 |
| Voice | ASR、TTS、通话和语音配置；SuperAgent 不复制音频控制器。主聊 / 旁聊通话复用原 Router，不叠加 Voice 轻量模型；接入分流目标与当前边界见[实时通话](../03-实时语音/实时通话.md) |
| Link | 多端认证与既有服务转发，不直接读 SuperAgent 私有数据库 |
| 渠道适配器 | 协议收发转换、账号与来源映射、本渠道身份/准入/权限、消息归一、按需研判与能力声明；可复用共享策略和研判能力，不保存对话状态或另建会话实现。当前入口迁移边界见[入口与研判](入口与研判.md) |

Router 与 Worker 是官方 Agent 会话。Assessment、分派领取、投递、学习复盘及监督由后台服务协调，入口研判和学习可调用模型；它们不是一批额外常驻人格 Agent。Worker 对自身执行及官方子代理的结果负责，系统直接接纳已有成果，归属、版本与执行身份用于内部关联，不增加结果保存准入或独立内容判定门。[结果保存无阻断](自校验与交付.md#结果保存无阻断)已有源码接线，验证边界见该模块正文，自动补存不因次数上限或关联差异转用户等待。

不设独立任务内容 Review 或补审/返工链，统一 outbox 与可信执行完成与送达记录保留基础职责；Worker 保存原稿并通知，Router 表达后交付。实现与迁移边界统一见[自校验与交付](自校验与交付.md#实现与验收边界)。入口 Assessment、后台学习 review 和软件测试验收各保留自身职责，不能因名称相似被一并取消。

## 共同验收边界

各模块的已有机制、未完成部分和验收条件在所属文档就地维护，不另立现状或验收流水。源码、生成产物、安装目录和运行实例分别核实；npm run check 只检查版本、工作区与入口一致性。

一次本地文件自检成功不能替代指定原话、原会话和并存旁聊条件的验收。隔离 profile 的真实模型请求也不能替代正式档案验证；未完成的原场景不标可投入使用。

软件验收按目标类型验证：普通问答不强制开单；执行请求派工后，Harness Worker 正常结束且当前要求的成功原稿已保存即完成并通知 Router，再由 Router 自然表达交付。核对三态、成果原稿、真实错误与等待原因，不出现效果审核、循环核查或自动返工；不满意的结果经 Router 新建关联调整单。真实审批、输入与暂停不被完成信号绕过；显式真人续接复用原会话，不重放未知或已生效外部动作。表达和投递失败只重试各自阶段，不重 Worker。普通执行中修订、停止、权限、会话入口、归档与重启按所属模块验收，前端检查四态并由用户最终验收。

测试报告注明提交、运行环境、全量串行整跑或分文件、总数与失败，不删除或弱化安全断言。真实验证保留 Trigger/Ticket/Run/Result/Delivery 的关联及实际工具调用，不能以工具目录存在证明联网或其他能力实际可用。
