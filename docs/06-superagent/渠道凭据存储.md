# 渠道凭据存储

更新：2026-11-04，按 `plugins/superagent/src/channel-credentials.mjs` 与服务入口校对。

公开引用保持 `benchgo-channel:<channel>:<uuid>`，属于产品不透明标识。官方 CredentialRecord 键必须为 `scope/id`，且每段只允许小写字母、数字、连字符。持久化映射为 `benchgo-plugin/channel-<channel>-<uuid>`，使用 AES-256-GCM，加密 AAD 绑定原公开引用；加密密钥记录为 `benchgo-plugin/channel-key`。

资源 → 接入 → 多平台通过主机已认证接口的 `connectionCredential` 保存密钥，服务只接受该渠道已声明的 `*Ref` 字段，返回 `{ref}`；随后 `connectionConfigure` 按当前 revision 保存引用。留空保留旧凭据；配置保存与凭据写入是两步操作，保存失败不能视为连接已经更新。适配器在实际调用时解析引用，公开配置和响应不返回明文。已有非 `benchgo-channel:` 引用仍交由官方凭据服务解析。

当前实现没有自动迁移旧格式记录或清理替换后的凭据；重录会生成新引用。以下迁移是历史环境修复记录，不能理解为每次启动都会执行的迁移能力。

2026-11-03 飞书真实配置发现旧实现直接用公开引用作为记录键，首次写入后重载失败。已修复存储映射，并将本次产生的一条旧格式加密记录迁移到合法键，未修改密文或其他凭据。配置、实际认证及进程重载需分别验证。
