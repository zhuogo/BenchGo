# 2026-11-05 晚：验收可用性

## 任务书

范围：只改善 Ticket Router 验收的流式调用、故障回退与等待状态；不改变 Mandate 验收条件，不重跑 Worker，不修改定时服务、官方组件或公共辅助任务默认策略。

验收条件：

1. 辅助模型超时、不可用或结构质量不合格时，主模型在独立超时窗口内兜底；取消、政策拒绝、权限与预算门禁不回退。
2. 每轮验收总窗口 360 秒；辅助尝试 45 秒、主模型尝试 120 秒；单次收集最多 3 个请求、含补证的整轮最多 6 个请求。主模型结构不合格最多纠正一次，只发送安全错误分类，不复用不合法输出。重试额度耗尽保留原单与证据，进入系统待核验，不终单。
3. 主辅都不可用时发布 `origin=system` 的明确状态，不将固定系统故障说明伪装成 Router 报告；正常交付、返工和阻塞仍采用 Router 自然正文。
4. 定向测试覆盖超时回退、质量纠正、总请求上限、取消/拒绝/预算不绕过、原证据续做。
5. Attention 本地文档端到端连续通过 3 次，无一死在验收；真实运行由统一验证任务执行并单独留证。受控测试不等同真实通过。

## 设计

原首轮与重审共用 120 秒总信号，辅助调用占满后主模型不能开始；block-11 留存 `INVALID_ASK`，block-13 留存 `INVALID_JSON`。为 Ticket review 增加内部请求策略，独立每次超时、辅助失败直接主模型兜底并保留主模型原始选项。其他辅助任务未传策略时维持原路由行为。

有限重试是单轮调用资源限制，任务状态仍按原 `review_wait`、预算等待、授权及证据恢复链闭环。公开 MCP/OpenAPI 字段不变，无新增配置接口。已记录的故障诊断仅含允许的类别、完成方式和字符数。

接管审核补充：`finish.kind=blocked` 明确按政策拒绝处理，不进入质量回退；主模型的结构纠正独立于网络重试计数，整轮最多一次，且仍受单次 3 个、整轮 6 个请求的硬上限约束。整轮使用同一请求记录，成功、补证和失败均保留安全 `routing.attempts`（模型原始 ID、状态、错误分类、输出上限、尝试时限与耗时），不保存正文、推理、请求内容或供应商错误体。真实三连由统一验证任务记录任务/运行/会话标识、最终状态与实际请求模型选项；本任务不自行发起真实调用。

角色接线：首轮及原证据续审优先使用当前 `policy.model` 作为 Router 主模型；Assignment 的 Worker 选择不能覆盖已配置的 Router。未配置 Router 时兼容沿用 Assignment 显式模型，继续原任务仍保留原 Worker。
