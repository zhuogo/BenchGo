# SuperAgent 服务契约

本文维护跨模块的领域记录、公共接口、存储与一致性约束。行为规则在各模块文档维护（见[板块导航](设计.md#小模块设计)），这里只用链接引用；机器字段以 [OpenAPI](../../plugins/benchgo/openapi.json) 和已发布 schema 为准，目标设计不自动成为可调用能力。

## 领域记录与版本

| 记录 | 权威内容与不变量 |
| --- | --- |
| Trigger | 通过入口后登记的稳定来源键、渠道、来源类型、会话或话题、消息、actor、原文和时间；不可变、去重，同键异内容不覆盖。来源标注见[链接与渠道](链接与渠道.md) |
| Candidate / Eval | 上下文引用、准入依据、规则版本、批次、owner、attempt、deadline 和结果状态 |
| Decision / Disposition | 模型建议、代码复核、原因、规则引用和实际去向 |
| Task | 标题、目标、用户明确的结果条件、当前摘要、来源和 `instructionRevision`；业务状态只有 `running` / `waiting` / `completed`，另有 `executionControl: { pauseRequested, paused, stopRequested, stopped }`，等待原因与恢复条件另记。规则见[任务三态](结果与交付.md#任务三态与简短摘要) |
| Mandate | 策略版本、范围、强度、命中规则、发起人身份五要素和可信原始指令引用；无命中规则时为空列表；授权版本不可变 |
| Assignment / Run | 任务包和已应用的完整要求快照、优先级、真实官方 session、父子关系、执行代际、工作区、租约、fence 和效果状态 |
| 任务输入账 | 原始输入引用、可信来源与发起人、目标任务、幂等键、完整要求快照、要求编号与授权版本、已收到/待应用/已应用，以及实际应用它的 Run 和工具边界；跨入口只应用一次 |
| Subscription | Thread 与 Task 的多对多关系、消息游标、持有/处理/释放状态；不扩权 |
| Result | Worker 的最后一段话（`summary`），加要求版本、Run、官方会话引用和结束事实（`completion`），以及恢复用的会话水位与哈希（`transcript`）、外部效果核实状态（`executionEffects`）和宿主拒绝码（`toolReceipts`）；不含过程文字和工具的输入输出。保存规则见[结果保存无阻断](结果与交付.md#结果保存无阻断) |
| Attention | 原问题、请求人、来源、任务与要求/结果版本、回答和处理状态 |
| Goal | 清单目标：`objective`（1–2000 字）和 `active / completed`，`rowVersion` 校验编辑、完成、恢复和删除；不委派、不绑项目。删除后保留内部去重记录并退出列表和上下文。规则见[目标清单](任务与执行.md#目标清单) |
| 任务动作与审核记录 | 具体动作、注册通道、冻结的目标与提交内容及摘要、任务/Run/调用归属、官方审核请求和真实答复、实际执行回执；不含凭据明文，单次批准只执行这一件 |
| 动作类别与通道注册 | 四类高危类别及默认 handoff；只有可信代码能声明类别、专用操作和提交实现。规则见[通道与接管](任务与执行.md#高危类别注册通道与接管) |
| 用户接管点（待实施） | 目前只返回 handoff 和原因；页面定位、已完成准备、最后一步和接管状态待补 |
| Router 完成信号 | `sa_results` notification 仅存进度与身份，提交事件唤醒所属原 Router 的持久 inbox，1 秒恢复检查兜底；关联任务、来源、要求版本和结果版本，以同任务结果版本幂等。保留消费状态与官方回合关联，普通 Router 公开正文沿正常官方 Session 保存，不另存任务结果正式稿；源码接线及定向验证通过，安装版待用户验收 |
| 执行等待事实 | 真实的审批、输入、暂停、停止、中断或错误原因，以及原 Assignment/Run/fence/要求编号 |
| 自我迭代来源与维护项 | 可信来源类型与原文引用、稳定来源键/版本、任务类别、消费水位、去重键、领取状态和真实处理结果；唯一后台执行器消费，不成为 Task 或工作台会话。机制见[记忆与技能](记忆与技能.md#增量来源与触发) |
| 事实 / 对象 / 行为复盘 | 事实稳定 ID、类型、来源和版本；对象视图引用事实 ID；Dreams 与协作对齐标明行为建议，不冒充用户事实或授权 |
| 技能 / 想法候选 | 技能保留候选采用、正文版本、真实使用与效果证据；Ideas 保留依据、适用条件、不确定性及投递/采纳/失效状态，不自动创建目标或任务 |
| Delivery / Outbox | 外部渠道普通回复或问题的原来源、适配器绑定、回复引用、幂等键、尝试、回执、错误和下一次投递时间；任务结果告知不另建专用正式稿或桌面投递中转 |

版本有三种，各守其义：`instructionRevision` 是要求修订的后台编号，用于顺序、归属和防迟到；Mandate 授权版本只在用户确认扩权时递增；配置 revision 与记录 `rowVersion` 用于并发控制。修订的生效方式见[任务、跟进与目标](任务与执行.md#任务跟进与目标)。

## 公共接口与数据契约

人端 HTTP 统一为 `POST /api/commander/assistant`，按 `action` 分发。源码分工：

| 文件 | 职责 |
| --- | --- |
| `service.mjs` | 装配与生命周期 |
| `engine.mjs` | Router 会话的状态、收发与对外接口 |
| `router-session-setup.mjs` / `router-context.mjs` | Router 会话装配（模型路由、提示词、工具与回合钩子）/ 每轮上下文 |
| `router-task-expression.mjs` | 任务信号进入所属 Router inbox 的身份、上下文与告知恢复；复用普通 Router 回合，不建立独立正式稿轨道 |
| `router-tools.mjs` | Router 的 `assistant_*` 工具注册 |
| `conversation-management.mjs` / `task-management.mjs` / `task-cleanup-store.mjs` | 当前真人会话的设置及任务管理入口 / 同一任务展示投影与重命名 / 有效期冻结清单、归档恢复、CAS 与持久回执 |
| `task-cleanup-continuation.mjs` / `task-cleanup-continuation-store.mjs` | 明确停止后归档的宿主续办 / 同库原来源、精确范围、版本、执行身份戳和状态；复用停止输入及派工前编排巡检，不另建执行任务 |
| `assistant-dispatch.mjs` | 人端 HTTP action |
| `artifacts.mjs` / `profile-documents.mjs` | 产物文件服务 / 档案文档读写 |
| `orchestration-store.mjs` | 任务账 |
| `task-storage-migration.mjs` | 数据库打开时在业务查询前原子迁移持久任务标识与关联；运行时只使用当前契约 |
| `orchestration-runtime.mjs` / `assignment-worker.mjs` / `assignment-executor.mjs` | 创建 Assignment / 领取 / 执行 |
| `goal-checklist.mjs` | 目标清单 |
| `learning-counters.mjs` / `review.mjs` / `review-worker.mjs` | 增量来源引用、定时/静默/显式入队与唯一自我迭代领取循环 |
| `maintenance-processors.mjs` / `maintenance-memory-upkeep.mjs` | 分派五职责、组织材料、校验产出与调用领域写入服务 |
| `maintenance-review.mjs` | 按任务读取五份提示词，共用有界辅助模型调用，不创建后台会话或任务 |
| `maintenance-health.mjs` | 维护执行器的只读监督事实，不接管维护执行 |

| 接口族 | 关键契约 |
| --- | --- |
| state / ensure / history / send / requestState / cancel | 会话、持久收件与回执；接收、处理、任务完成分别表达 |
| assistant_delegate / assistant_tasks / assistant_task_control / assistant_task_change | 绑定宿主 Agent、可信原始指令、同一任务输入账和逻辑会话归属，模型参数不能声明 owner。本机主人在主聊或手动旁聊可全局查询、暂停、停止和恢复已暂停的任务（含其他会话和渠道创建的），保留原 Mandate；answer、supplement、修订和新委派仍按原会话归属。渠道会话、子代理和机器通知没有全局管理权 |
| assistant_tasks | `op=list/get` 只读，列表支持 `query`（展示标题与 target/acceptance 字面关键词）、`createdAfter/createdBefore`（带时区 ISO 日期时间，含起点、不含终点）、`channel/sessionId` 来源，以及状态、项目、`archived:boolean`；全部过滤与可信归属取交集后分页，省略 archived 保留全历史口径。列表和详情共用展示标题、`taskMeta.version`、`archived` 与 `cleanup` 指针。get 默认 `section=overview`，只带有界核心要求、最新结果与当前待答问题预览；原文按 `requirements/results/revisions/assignments/runs/attentions/deliveries` 节读取，`offset/limit` 分页（默认 10、最多 50），`textLimit` 是整页内容预算（默认 4000、最多 12000）。核心字段截断以 `textTruncated` 和 requirements 读取入口标明；长记录给出 JSON 编码、稳定 `identity`、`textOffset`、`contentHash` 与 `nextRead`。续读沿 `nextRead` 的 `recordId/expectedHash/textOffset` 并固定 `limit=1`，记录原地变化、消失或要求指针过期时报 `TASK_READ_CONFLICT`，不能拼接不同版本或一次灌入全部历史 |
| assistant_task_manage | 仅 `op=rename`，参数为 `id/title/version`，`version` 来自新鲜的 `taskMeta.version`；本机主人当前真实主聊或手动旁聊可跨任务来源办理，只改展示标题。缺失、过期版本或不属于本次管理身份时拒绝，不提供人工完成或硬删除操作 |
| assistant_task_cleanup | 复用 `preview/commit/history/restore`，增加 `stop-and-archive/pending/cancel`；普通提交只处理同指令冻结清单的精确 ID 子集，`restore` 先由归档回执准备清单；未消费预览有效 24 小时。明确停止后归档使用宿主持久原来源、版本与 `executionStamp` 续办，按 `operationId` 或任务读待办，取消只撤销未完成归档。身份、来源、确认能力和稳定请求标识由宿主生成，模型不得伪造；不请求高危审批卡，不扩大停止或执行权限。完整语义、冲突、回收及取消边界只在[任务清理与保留](任务与执行.md#任务清理与保留目标)维护 |
| assistant_execution_manage | 只有 `operation: resume`，由当前主聊或手动旁聊中的显式真人指令触发；宿主绑定 taskId、原 Assignment/Run/fence/要求编号并复核当前授权。未知外部动作未完结时不重跑；排队不等于已恢复 |
| taskAnswer | taskId、attentionId、instructionRevision、requestId 和真实答案；校验原问题、来源、版本和状态 |
| taskResume | 明确的恢复动作才继续，先应用暂停期间最新的已授权快照；`queued:false` 或带 code 不是恢复成功 |
| tasks | 同一任务账的只读列表或详情；`archived` 在 `limit` 前筛选，省略则两类都返回；`taskId` 直接定位原记录 |
| goalCreate / goalList / goalGet / goalUpdate；assistant_goals | 创建传 `{ goal: { objective, requestId } }`；更新传 `{ id, rowVersion, patch }`，`patch` 只接受 `objective`、`status: active \| completed` 或 `deleted: true`。工具侧由宿主根据当前真实用户指令生成请求标识 |
| config / profileDocuments / memorySave / memoryDelete | revision 或 expectedHash 冲突保护，秘密不返回；当面记忆由 Router 直写，Worker 不写长期记忆 |
| settingsCatalog / settingsRead / settingsPrepare / settingsCommit / settingsHistory / settingsRollback；assistant_settings | 见[对话管理与统一配置](#对话管理与统一配置目标) |
| connectionCatalog / connectionConfigure / connectionCredential / connectionAction / connectionStatus / connectionVerify | 现有渠道连接适配器的配置、凭据、安全操作与运行状态分离，使用真实连接结果；不代表 Link 出站设备与中继管理已接入 |
| assistant_external_action | Worker 专用的 catalog / prepare / submit；catalog 返回通道 `inputSchema`，prepare 按契约提供 input 和稳定 requestId，submit 只用返回的 actionId；只接受真实 `allowed-once`，固定 `never` 下的新审批拒绝及接管规则见[权限与对外审批](任务与执行.md#权限与对外审批) |
| approvalOrigins | 审核入口的只读会话候选：当前档案的 owner 人端可查主聊、未归档旁聊及其有效 Worker，返回 kind、来源标题和原 session/Task/Assignment/Run 关联，不返回批准令牌。待批请求唯一来自官方 `sessionStatus` 的 PendingApproval；点击前复核来源、现行 Mandate、工具面、租约和 fence |
| sessionSearch / sessionList / sessionHistory / ledgerRead；对应 assistant_* 工具 | 见[检索与定点读取契约](#检索与定点读取契约) |
| assistant_projects | 不传设备选择器时返回 `scope:local` 的本机项目、会话及模型目录；项目 `isDefault` 按侧栏持久身份标记“最近”（未分组），不计入项目数，不改写底层标题或 ID。传 `deviceId/deviceIds` 时调用共享 Link 项目查询，支持 offset/limit，逐设备返回可用性、时间、分页和资源身份；泛问项目的查询范围遵循[内置层](../../plugins/superagent/prompts/builtin-layer.md)，本机结果不代表所有设备 |
| assistant_devices | 查询 Link 出站目录、本机身份与已知连接事实；已保存不等于在线，实际连通及能力通过连接诊断或定向操作核验 |
| assistant_remote_task | delegate/get/control/change/reconcile；真实宿主绑定来源指令，目标按 collaboration 授权核验。委派与跟进只引用目标任务，入口不建立第二个 Worker；reconcile 只核实原请求，不重派，具体语义见[跨设备任务](任务与执行.md#跨设备任务) |
| assistant_device_manage | 已有设备 connect/reconnect/rename/remove/diagnose；远端 status/settings-read/settings-prepare/operation。修改仅为已有中继节点 priority/enabled，prepare 返回待目标主人确认的操作 ID；不接受秘密或自批、不暴露 owner 票据 |
| assistant_device_status | Router 无参数只读查询，复用 `benchgoLink.status()`；仅本机主人会话的真实人类回合可用。成功返回 `available:true`、`enabled`、入站已授权 `devices[{id,name,type?,lastSeenAt}]`、`pendingCount`、`observedAt` 和 `liveConnections:'unknown'`；这是获准访问本机的设备，不是本机保存的出站服务器目录，已授权不等于在线。失败返回 `available:false/code/reason`，不用空列表冒充成功 |
| ownedSkills 及批准、拒绝、固定、恢复 | 自建技能候选管理，见[记忆与技能](记忆与技能.md) |
| artifact / system-file / Voice 路由 | 鉴权、受控目录、文件类型与大小约束；Voice 生命周期由 Voice 服务负责 |

**身份。** 人端 HTTP 复用官方 Connection 的 exact Fetch 路由：宿主先拒绝非 owner，再把官方 `connection.browserPeer` 交给业务层复核；请求正文不能声明或覆盖 principal。Router 的 `assistant_*` 工具只注册给拥有该会话的 Agent，描述与执行共用同一身份白名单，权限门在派发前复检；这些工具不暴露为外部 MCP。

**存储。** 默认数据根为 `~/.benchgo/assistant/`。

| 存储 | 内容 |
| --- | --- |
| `assistant.db` | 原控制面、任务与运行记录；自我迭代的版本/journal、bank 分类/词索引、维护队列/增量水位、技能与 Ideas 属派生/维护面，不复制原文。当前多连接，提交回调唤醒展示变更 |
| `ledger.db` | 业务原文与引用关系 |
| 官方 Session | 对话和原始执行记录；历史索引由官方搜索服务管理 |
| Markdown 档案 | 事实与档案面：稳定档案、memory/日期.md 的详细事实、短 MEMORY、people/groups 视图、Dreams 和主动偏好；白名单路径，正文与来源保留稳定身份 |
| `state.json` | 逻辑会话映射等状态 |

**一致性。** 副作用先持久登记，数据库事务不等待模型或网络。结果先保存，再可靠接入原 Router 持久 inbox；收件失败不回滚结果，重启补齐未收件信号。完成信号按同任务结果版本去重，用户输入优先且不打断当前回合；回复只走普通公开正文及官方 Session 历史，外部发送沿普通回复链路去重与恢复。告知失败不重跑 Worker；已进入或状态不明的回合先核对官方记录，不盲重放。历史专用稿件可读但不继续双轨执行。文件与数据库用 journal/hash 恢复一致，不宣称跨介质原子事务。错误区分参数、认证/权限、版本/幂等冲突、能力不可用和效果未知；成功响应不能掩盖未应用、未完成或未送达。本轮接线状态见[实现与验收边界](结果与交付.md#实现与验收边界)。

**任务命名与迁移。** 当前领域、工具、接口及持久结构统一使用 `Task / task`，中文为“任务”。升级时一次迁移已有任务结构和自有关联标识，保留任务 ID、原始内容、执行归属、未完成投递与恢复信息；不保留工具别名、旧接口或双格式运行时回退。不透明的供应商、模型、外部协议值及官方会话原文不参与术语替换。

**生命周期。** 初始化失败与热卸载按停止、解绑、关闭、释放的顺序清理，每一项都捕获错误并继续，最后聚合报告。确认写入者已停止并且全部关闭成功后才释放数据所有权锁；不凭同一 PID 夺锁。停用 SuperAgent 保留用户数据，不撤销已经发生的外部效果。

## 自我迭代的写入与读取边界

下列契约已有源码接线与定向覆盖；真实付费模型效果和安装版运行尚待验证。唯一机制正文与边界见[记忆与技能](记忆与技能.md)。

- Router 记忆工具的身份来自宿主真实会话；后台执行器使用宿主绑定的维护身份，模型不能自报身份。Worker 与子代理不能直接写长期记忆。
- 固定档案、按日 memory/dreams、people/groups 对象和 INDEX、短协作对齐及主动偏好均经同一受控文档服务，按白名单验证名称，禁止任意路径、遍历、符号链接逃逸和秘密写入。
- 事实写入/纠正/遗忘沿稳定 ID、来源、版本和 expectedHash；新结构保留事实 ID、来源、版本与恢复记录，不增加旧数据兼容层。文件提交与数据库 journal 可恢复，不承诺跨介质原子性；部分成功如实返回。
- 定时/静默/显式请求共用增量来源与去重，单执行器串行领取；成功提交后才推进对应水位。未处理、失败、空材料跳过与效果未知分别返回，不以 queued 冒充完成。
- bank 是数据库分类视图，检索返回事实 ID、摘录、来源和版本；没有四份正文或向量库。纠正/遗忘先限制旧召回，再清理总纲、对象与快照等派生。
- Router 在安全回合边界装配最新有效档案版本；每次启动读取简短 ALIGNMENT_SYNTHESIS，投递决策前读取 PROACTIVE_PREFERENCES。在途请求保持原输入，不因为背景更新重放工具。
- 技能经现有候选服务和官方 SkillProvider；实际采用与效果留证。Ideas 沿现有聊天/投递，去重并记录真实回执；后台不创建工作台聊天、任务或新过程 UI。

## 检索与定点读取契约

工具与 HTTP 共用 `history-search.mjs`，分别传递工具取消信号和 HTTP `Request.signal`。行为与搜索范围的权威正文见[历史会话检索](记忆与技能.md#历史会话检索)，这里只维护服务边界。

| 职责 | 契约 |
| --- | --- |
| 历史搜索 | 复用官方 `sessionQuery.searchSessions(request, { signal })`，同一会话的更多命中用 `searchEvents`。宿主根据可信的主旁聊归属和权限生成过滤条件，不接受模型声明的权限或来源范围 |
| 命中引用 | 有界 `snippet` 加原样的 `sessionId / seq / time`，附会话标题和 `source: official`；跨会话按会话分组，更多命中需显式续页或指定会话 |
| 原文读取 | 按 `seq` 调用官方 `readEvent({ sessionId, seq, before: 0, after: 0 }, signal)` 核对事件，用 `observeSession` 的公开投影返回前后窗口；不指定 `seq` 时读有界的近期窗口。`limit / textLimit` 控制条数和长度，单条消息用 `offset / nextOffset` 续读；不向模型透传原始事件载荷 |
| 分页与取消 | cursor 绑定查询、可信范围和数量参数，不能拼猜或跨查询复用；字符 `offset`、近期窗口 `nextCursor` 和搜索 cursor 互不通用。索引禁用、来源缺失或损坏、权限不足、取消和游标失效各自可辨，不统称空结果 |
| 覆盖说明 | 返回 `matchMode: official-phrase`、`coverage: official-message-text` 和 `limitations`。官方 `unicode61` 不保证连续中文句内的子串命中；不另建索引，也不用全文扫描兜底 |
| 不可用时 | 官方能力不可用就明确说明，不回退到自建索引、全库回放或模型检索 |
| 业务原文 | `ledgerRead` 按 ID 分页返回业务原文和来源，数值 cursor 续读原始字符；历史对话的命中直接引用官方 `sessionId/seq`，账本不保存对话全文 |

官方能力的核对版本为 `0.2.2-rc.1`、提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，与 `upstream.json` 和子模块 pin 一致。

## 对话管理与统一配置

SuperAgent 和 BenchGo 自身的设置与状态由 Router 在对话中直接查询和管理，不为此委派。设置页是同一领域服务的另一个入口，共用身份、版本、校验、应用和审计，不另存第二份配置。目标是所有经可信服务注册的配置默认可对话管理，不逐项增加专用工具。

| 环节 | 契约 |
| --- | --- |
| catalog | 按注册元数据提供名称、类型、取值约束、作用范围、变更影响和确认类别；风险分类由宿主按元数据执行，模型不能自判免确认 |
| read / prepare / commit | 只改用户要求的字段，保留其余配置，版本校验防止覆盖并发修改；运行状态只读 |
| 应用回执 | 保存结果与实际应用分别返回：`applied` / `pending` / `reload-required` / `failed`；保存成功不等于已经生效 |
| 确认 | 普通、明确且有权限的修改直接办理；放宽或关闭审批、增删凭据等安全防线变更，须由可信真人对精确差异明确确认，确认绑定当前真实指令，模型不能传入确认标志。固定 `never` 下，仍要求新宿主批准的提交返回 `APPROVAL_POLICY_NEVER`，查询、预览和普通修改按原规则执行 |
| 秘密 | 只经安全输入和保险库录入与使用，不进聊天、模型读写值或审计明文；涉及秘密的历史不提供普通回滚 |
| history / rollback | 记录操作者、来源、范围、前后版本、脱敏差异、确认依据和应用结果；回滚是基于当前版本的新变更，遵守同样的确认和秘密规则 |

配置观察用批量读取加短事务：同轮共用目录快照，异步读取和脱敏校验全部完成后才进入同步事务；指纹未变不更新版本表。显式读取、保存的 CAS 和写后核验仍读取原服务的实时值。任务清理见[任务清理与保留](任务与执行.md#任务清理与保留目标)。

### 跨设备资源与管理接线

设备与资源查询、远端执行、连接和中继管理的服务契约唯一正文是[跨设备协作](../01-设备与远程连接/跨设备协作.md)。助手与侧栏复用同一领域服务，工具仅包装真实已注册操作，不把目标接口预先宣称为已可调用。

| 接线范围 | SuperAgent 边界与实现状态 |
| --- | --- |
| 设备与资源 | 已接出站目录及按设备查询项目；共享服务同时供侧栏读取会话/最近。携带所属设备、观察时间与覆盖范围，区分空、离线、未授权和不支持；见[资源身份与查询](../01-设备与远程连接/跨设备协作.md#资源身份与查询) |
| 执行与控制 | 已通过 `assistant.collaboration` 和 `executionRef` 桥接，原指令、来源、任务归属和回执继续核验。入口既有编排 tick 有界跟进原问题及结果；具体行为见[跨设备任务](任务与执行.md#跨设备任务) |
| 配置 | 本机继续复用 `assistant_settings`；远端管理独立授权后只开放脱敏中继读取及已有节点 priority/enabled 修改申请，目标主人确认具体差异后执行原配置事务；版本冲突、重启 unknown、拒绝/撤权和过期分别返回 |
| 连接与运维动作 | 已有设备连接、诊断、重连、改名和移除复用设备中心。首次配对、秘密补录及部署返回安全交接入口，不宣称自动完成；不返回 owner 票据、任意转发或通用远端命令入口；见[连接与中继管理](../01-设备与远程连接/跨设备协作.md#连接与中继管理) |

明确且已授权的普通请求直接办理，不重复要求批准；关键目标歧义或超出现有授权时才补问。当前监听地址与中继池等路径仍按既有 `confirm / blocked` 策略执行，本目标不改变现行风险规则或绕过 `APPROVAL_POLICY_NEVER`。凭据继续经安全入口和不透明句柄使用；安全输入与接管未接通时明确引导现有页面，不能要求把秘密发到聊天或声称已自动完成。

## 持久执行事实与增量读取

`execution-facts-store.mjs` 在 `assistant.db` 保存精简的执行投影和展示变更 journal；Task、Assignment、Run 仍是唯一的领域账，官方 Session 保留原始执行记录。`task-execution-progress.mjs` 注册官方 `benchgoExecutionFacts` Projection，以纯同步归约保存受控阶段、有界脱敏的公开进展短句及来源标记、计数、直接子会话关联和最多 64 个关键节点，不保存工具参数、输出、完整模型正文、思维或凭据。短句提取规则见[执行动态观测](任务与执行.md#执行动态观测)。恢复通过官方 `sessionQuery.observeSession(..., { projectionMode: 'all' })` 取同一切面的投影。所核官方版本为 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`。

**身份与水位**

- 执行身份为 `taskId / assignmentId / runId / fence / instructionRevision`；`appliedInstructionRevision` 单独说明 Worker 已应用到哪个版本。
- 子执行另有 `sessionId / parentSessionId / rootSessionId / activationId`；官方子代理 activation 的 `runId` 不等于领域 Run。父子关系只接受官方 `origin: 'subagent'` 和真实父会话，普通 fork 不算。
- 水位分两层：全局 journal 的稠密 `seq` 和每个来源 Session 的 `sourceSeq`，不同会话的 seq 不互相比较。重复和迟到的通知重新读取当前官方投影，不降水位；较旧的投影不覆盖新记录。
- 耐久性：实时来源记 `sourceDurability: 'observed'`，经官方冷读取重建的记 `persisted`；没有独立检查点证明时 `flushedCursor` 保持 -1。
- 官方历史缺失、子历史不可恢复或超出精简容量时返回 `complete: false / missingReason`，不填造零个子任务。Session 计数标为 `counterScope: 'session'`，不代表当前要求版本的新产出。
- 领域表与执行投影的展示变更在同一 SQLite 事务内写 journal，提交成功后才唤醒订阅；回滚不发布，展示流不写通知 outbox。

| 接口 | 返回与约束 |
| --- | --- |
| `runtime.executionFacts.snapshot({ taskId? })` | `{ cursor, tasks, bootId, observedAt, completeness }`；分批读取同一同步切面的完整任务行，含归档；当前 `truncated: false`，海量账本的容量未实测 |
| `page({ after, through?, limit? })` | `{ cursor, through, entries, hasMore }`；固定上界的稠密分页，`cursor` 是本页最后覆盖的水位。entry 只含真实身份、kind、时间、安全计数和证据引用；Goal 的 `taskId` 为 null，`data.goalId` 定位原记录 |
| `subscribe(listener) / currentCursor()` | 提交后合并唤醒；监听只是信号，消费者从 journal 补读 |
| `evidence({ taskId, runId?, instructionRevision?, after?, limit? })` | 同一安全 journal 的有界证据和精简投影，附 `runtime` 白名单机械事实；目标和结果条件只提供限长脱敏投影 |
| `evidenceSnapshot({ limit? })` | `{ cursor, currentCursor, observedAt, bootId, executions, complete, truncated, schedulerHeartbeat }`；外部监督专用的白名单快照，默认和上限 1000。`schedulerHeartbeat: { at, bootId }` 只在编排周期实际成功完成后更新，读取不续心跳 |

`runtime` 包含任务与要求身份、Assignment 租约、Run、官方 Agent 的 `executionAlive`、模型请求 `request`、`wait`、停止确认、真实等待原因和每个 Session 的水位。`evidenceCursor` 是本任务最新的事实水位，用来阻止旧摘要覆盖新执行；`observedAt` 只是读取时间，不是 Worker 心跳。后台任务基于官方 `jobs.list(owner)`，只认原 Worker 及本 Run 已绑定子会话所有、仍在 running/stopping 的任务，投影为 `wait.kind: 'background-job'`。官方没有公布的请求 deadline 和任务预计结束时间保持 null。

人端通过官方 Remote 命名空间 `benchgoExecutionFacts` 使用 `snapshot / page / evidence / stream`，描述符唯一来源是 `execution-facts-contract.mjs`，Host 与 Client 共用；`invocation.peer` 必须是 owner。stream 先订阅、再读 baseline：先返回 `{ type: 'snapshot', snapshot }`，再补齐 `{ type: 'changes', entries, cursor, through, hasMore }`；慢消费者分页追赶，缺口明确失败，断线后重开快照。客户端按 generation 防迟到，只读取发生变化的任务。

任务投影的 `currentSummary / execution.summary` 来自执行摘要，附最多 64 条 `history` 和 `historyTruncated`，规则见[执行摘要与监督判断](模型与上下文.md#执行摘要与监督判断)。

## 接口演进与验收

存储、HTTP 和工具的版本各自管理。模型工具、HTTP、渠道和桌面复用同一套身份、准入、状态和版本校验；尚未部署的操作不注册。每批实现同步领域服务、HTTP 与工具、OpenAPI、能力发现、客户端入口和对应验证。

**已有源码接线**

- 上表各接口族。
- 统一配置管理服务、官方设置适配器和 BenchGo 自有存储适配器；Workbench 偏好提交后可真实重装侧栏并返回 `applied` 或 `pending`。
- 当前主机 Link 连接与中继池的统一配置适配器；实际可操作范围仍由各路径风险、敏感字段与运行时能力决定，不包含完整跨设备管理。
- 历史检索适配。
- 执行事实的精简存储、事务与重启、官方 Registry/Gateway/Client 挂载和流式分页。

**现状限制**

- 官方设置项缺少可核验 schema、含 Loader 表达式、命名空间重复、非唯一可编辑项或插件未活动时，catalog 保留 blocked 项和原因；缺少运行时重装接缝的独立存储适配返回 `reload-required`。启动和部署动作不属于配置管理。
- 尚未所有页面的保存都改接统一管理服务。
- 一次配对协商双向关系、完整 AI 秘密输入、新设备/中继节点与部署仍待实施；当前双方分别授权可双向使用，不自动传递第三设备权限。跨设备实现及真实环境验收统一见[验收条件](../01-设备与远程连接/跨设备协作.md#验收条件)。
- `assistant.db` 多连接；编排控制面为定时轮询。

**待验证（安装版）**

- 目录与真实注册配置一致、只改指定字段、版本冲突、页面与主聊同源、安全确认、秘密不泄露、保存与实际应用的区分、回滚后的实际行为。
- 检索：官方中文匹配语义、过滤与分页、持久索引的首查和重启、真实数据量下的耗时。
- 执行事实：真实浏览器的物理连接、已安装档案、进程故障场景。
- 来源身份不能被载荷或模型声明覆盖；跨会话的任务控制被拒绝；参数、权限、版本冲突、能力缺失和未知效果各自可辨。
- 完整链路的执行、回复生成、持久投递和可信送达，以及停用时的资源释放；HTTP 成功不代表任务完成或投递成功。
