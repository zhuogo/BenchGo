# SuperAgent 服务契约

本文是跨小模块公共接口与数据不变量的唯一说明。具体行为分别见[板块导航](设计.md#小模块设计)，机器字段以 OpenAPI 和已发布 schema 为准，目标设计不自动成为可调用能力。

## 领域记录与版本

| 记录 | 权威内容与不变量 |
| --- | --- |
| Trigger | 统一入口管线通过后登记的稳定来源键、渠道/来源类型/会话或话题/消息、actor、原文及时间；不可变、去重，同键异内容不能覆盖历史；来源标注以[链接与渠道](链接与渠道.md)为准 |
| Candidate / Eval | 上下文引用、准入依据、规则版本、批次、owner、attempt、deadline 与结果状态 |
| Decision / Disposition | 模型建议、代码复核、原因、规则引用与实际去向，支持审计 |
| Ticket | 标题、目标、用户要求与自校验依据、活摘要、来源、生命周期与 instructionRevision；目标不设置独立内容验收结论 |
| Mandate | 每份授权快照完整记录策略版本、范围、强度、命中规则、发起人身份五要素及可信原始指令引用；无命中书面规则时明确为空列表；授权版本不可变，不含资源预算，不新增用户必填授权表 |
| Assignment / Run | 任务包及已应用完整要求快照、执行安排、优先级，真实官方 session、父子关系、执行代际、工作区、租约、fence、检查点和效果状态 |
| 工单输入账本与修订快照（已接线） | 原始输入引用、可信来源/发起人、目标工单、幂等键、完整要求快照、后台要求编号与授权版本、已收到/待应用/已应用、应用该输入的实际 Run 和工具边界；跨入口只应用一次 |
| Subscription | Thread 与 Ticket 多对多关系、消息游标、持有/处理/释放状态，不扩权 |
| Result | 当前要求版本的成果原稿、原文证据、按目标需要的产物、原 Worker 会话轻量自校验记录与未尽事项；保存后向所属 Router 发完成信号，原稿在工单详情保留，不附独立模型评分或内容放行结论 |
| Attention | 原问题、请求人、来源、工单与要求/结果版本、回答及处理状态 |
| 外部动作与授权记录（已接线） | 可信授权人、精确 origin/服务、动作与类别、期限、注册通道、冻结目标与最终提交内容及摘要、工单/Run/调用归属、单次消费键或网站持续许可及撤销状态；授权与执行效果分开，不含凭据明文，单次批准只执行冻结此件 |
| 动作类别与通道注册（已接线） | 四类高危均有类别及默认 handoff；仅可信代码声明类别、专用操作和内容准备/提交实现，核心校验后纳入可执行通道；新增渠道不增加核心渠道特例，当前内置通道范围见[权限实现边界](任务与执行.md#实现与验收边界) |
| 用户接管点（待完善） | 当前无适配器返回 handoff、原因和动作/能力标识；完整页面或应用定位、已完成准备、最后一步及接管状态设计尚待补齐。接管不产生通道许可，不把用户点击推定为实际成功 |
| Router 表达交付（已接线） | 完成信号关联工单、来源、要求与结果版本；Router 读取保存原稿并主动自然表达，自选摘要或完整回复；保存正式稿及原稿引用后由统一 outbox 投递，不设置内容放行结论、重派或验收操作；实现边界见[自校验与交付](自校验与交付.md#实现与验收边界) |
| 执行待核实事实与通报（已接线） | 原因、核查次数、下次时间、是否实际自动核查、升级事实，以及原 Assignment/Run/fence/要求编号；进入、升级、核清后的处置信号只交所属 Router 的原 inbox，不直接形成系统聊天正文。行为权威见[待核实通报与自主处置](自校验与交付.md#待核实通报与自主处置) |
| Delivery / Outbox | 原来源、来源适配器绑定、Router 成果回复/失败说明/问题引用、幂等键、尝试、回执、错误与下一次投递；统一 outbox 调用来源适配器，回执回同一工单；成功回复确认送达才 completed，结构性无解说明确认送达才 failed；生成或投递失败均待交付，不触发 Worker 重跑 |

instructionRevision 是普通要求修订的后台编号，用于顺序、归属和防迟到；配置 revision 或记录版本用于并发控制。原范围输入先写同单账本及完整快照，在原 Worker 下一工具提交边界整份原子切换；在途工具继续使用已固定快照，不为普通修订取消、停跑或重建分派，同一批工具不混用要求编号。暂停只收、不自动恢复。仅超 Mandate 扩权经真实用户确认后生成新授权版本；要求编号与授权版本分别保存。叫停或撤权立即拦新动作并请求取消可取消的在途执行，实际停止事实另记。行为权威见[工单、跟进与目标](任务与执行.md#工单跟进与目标)。

Mandate 的命中规则只引用用户预先授权的书面规则，默认授权不能由模型、机器消息或外部正文产生。Worker 与一层子 Worker 逐层继承并按任务及工具面裁剪，不扩权、不复制凭据，具体边界见[权限与对外审批](任务与执行.md#权限与对外审批)。

业务工单状态、执行状态、等待原因和交付状态分别记录。用户始终与 Router 对话：Worker 原稿先落库并发完成信号，Router 读取后主动自然提醒，自选摘要或完整回复再交付原来源，不重派或增加内容验收。成功回复确认送达后 completed；结构性无解的失败说明确认送达后 failed 关单，保留原稿并可由用户明确继续或调整。生成或投递失败保留待交付，只重试 Router 表达或补投已存回复；超时、临时故障与效果未知先核实或恢复，不盲目关单、重复执行。状态说明由 Router 自行判断，无固定报告、标题前缀、系统状态文案或硬兜底，真实状态留在任务列表。idle、模型停笔、HTTP 成功、播放 ACK、送达与已读分别记账。流程权威见[自校验与交付](自校验与交付.md)。

以上区分领域语义、已接线记录与待完善接管体验；当前字段和返回值以 OpenAPI 为准，不以设计文字冒充已部署行为。

## 公共接口与数据契约

人端 HTTP 统一为 POST /api/commander/assistant，机器字段以[OpenAPI](../../plugins/benchgo/openapi.json)为准；模块实现见[服务装配](../../plugins/superagent/src/service.mjs)。旧 action 适配同一领域服务，不另存状态。

| 接口族 | 关键契约 |
| --- | --- |
| state / ensure / history / send / requestState / cancel | 会话、持久收件与回执；接收、处理、任务完成分别表达 |
| assistant_device_status（已接线） | Router 无参数只读查询，运行时复用 `benchgoLink.status()`；仅当前真实人类回合且绑定本机主人逻辑会话与当前 Agent，外部渠道来源不可读取。成功返回 `available:true`、`enabled`、已授权 `devices[{id,name,type?,lastSeenAt}]`、`pendingCount`、`observedAt` 与 `liveConnections:'unknown'`；已授权及最近访问不等于实时在线，不据此声称当前连接数。不返回令牌、地址、中继配置或原始私有状态。缺服务、状态错误返回 `available:false/code/reason`，不以空设备列表冒充查询成功；不提供配对、撤销等管理动作，不开放通用 ops 工具 |
| assistant_delegate / assistant_tickets / assistant_ticket_control / assistant_ticket_change | 绑定宿主 Agent、可信原始指令、同单输入账本与逻辑 thread/sessionLineage；模型参数不能声明 owner。接单记录标题/活摘要查重依据，普通修订与扩权确认分流 |
| assistant_execution_manage | 仅所属 Router 可按 ticketId 与 operation（wait / check-now / resume / fail）协调当前待核实执行；Assignment/fence/要求编号由宿主当前信号或可信人类会话范围绑定，不由模型声明。复核当前 Mandate 与原归属；wait 保留现有安排，其他操作异步进入既有核查循环或受控原会话续跑接缝，scheduled 不代表已恢复。自动续接遵守原 Run 持久预算（最多两次）与失败后的退避，延期请求由原循环消费，上限转为待核实升级事实；wait/check-now 不清预算。仅宿主核验当前真实用户明确续接后可传内部 automatic:false，模型参数和内部通知不能伪造人工来源，人工单次许可不清自动预算。fail 须已有结构性失败材料和真实自检，不直接伪造结果或跳过送达关单；外部效果未知只核查，用户暂停/停止不得被自动解除 |
| ticketAnswer | ticketId、attentionId、instructionRevision、requestId 与真实答案；校验原问题、来源、版本与状态 |
| ticketResume | 明确恢复动作才继续，先应用暂停期间最新已授权完整快照；校验原执行身份与效果，queued:false/code 不是恢复成功 |
| tickets | 同一工单账本的只读列表或详情；archived 按原单 completed/failed/历史 closed 派生，在 limit 前筛选，省略则保留两类；ticketId 直接定位原记录，不依赖当前列表页。默认界面请求未归档，已归档入口保留原状态与结果；等待、暂停、待交付及 cancelled 不因此归档，失败原单明确续做后回到活动列表 |
| config / profileDocuments / memorySave / memoryDelete | revision 或 expectedHash 冲突保护，秘密不返回；当面记忆目标由 Router 直写，Worker 不写长期记忆，后台计数整理只读已关工单、不经 Router 上下文；旧记忆候选接口仅弃用兼容 |
| connectionCatalog / connectionConfigure / connectionCredential / connectionAction / connectionStatus / connectionVerify | 配置、凭据、安全操作与运行状态分离，使用真实连接结果 |
| actionPermissions / actionPermissionCreate / actionPermissionRevoke | 已接线的真实授权人管理接口；站点许可限定精确 origin、login/private-upload、期限与 actor/profile，列表和审计脱敏，撤销阻止后续提交；许可不代表当前已有对应登录/上传执行适配器 |
| assistant_external_action | 已接线的 Worker 专用 catalog/prepare/submit；catalog 必须返回通道 inputSchema，prepare 按该契约提供 input 和稳定 requestId，submit 仅用返回的 actionId。仅可信注册通道，冻结动作绑定工单/Run/授权/策略，正式审批只接受 allowed-once，无通道 handoff，未知回执 uncertain 不重放 |
| approvalOrigins | 审核入口的只读会话候选投影；仅当前档案可信 owner 人端可查询主聊、未归档旁聊及其有效 Worker，返回 kind、来源标题和原 session/Ticket/Assignment/Run 关联，不返回批准令牌或自建审批记录。官方 sessionStatus 提供唯一 PendingApproval；点击前携原 sessionId/toolName 再读并复核来源、现行 Mandate、实际工具面、租约及 fence，再由原 SessionProvider 下的官方卡答复同一请求。清空、归档、停止、撤权或执行替换后失效；历史工单或会话缺失统一来源类型、来源映射不匹配时，仅跳过该不可核实来源，不推断补全、不阻断其他合法来源的审核读取；候选来源无法 retain/open 时按来源显示错误与阶段，并核对官方 openState，不以 ready 返回或空审批值认定连接成功；列表汇总不允许会话互借授权 |
| ledgerRead / assistant_ledger_read / assistant_session_search | 依权限分页返回原文，不按摘要伪造来源；证据查阅不调用独立语义重审或评分 |
| 执行会话关联与定位（目标） | 项目工作区/官方「未分组」（按最近活动排序）会话、执行会话标记及工单反向定位共用真实 Ticket/Assignment/Run/session/工作区关系；定位不重派，缺记录明确不可用；具体交互见[任务列表](../02-工作台与Agent/任务列表交互.md) |
| ownedSkills 与批准、拒绝、固定、恢复 | 当前候选协议保留；未实现直管操作不能先注册为可用 |
| artifact / system-file / Voice 兼容路由 | 保留鉴权、受控目录、文件类型与大小约束，Voice 生命周期由 Voice 服务负责 |

人端 HTTP 操作复用官方 Connection 的 exact Fetch 路由：宿主先拒绝非 owner，路由回调只接收 `Request`，再以官方 `connection.browserPeer` 交给业务层复核身份。请求正文不得声明或覆盖 principal；RPC 仍使用自身传入的真实 Peer，不套用浏览器身份。审批投影的验收须穿过该真实路由，覆盖 owner 查询、非 owner 拒绝、跨源拒绝以及所属主聊呈现同一官方待批请求；仅直接调用投影函数不能证明主聊入口已闭环。

审批呈现三层共用上述原请求身份：事实信号先交 Router 自然提醒，原官方卡关联该提醒并随对话流，看板聚合并可跳转同一卡片；看板只作兜底，不新增审批记录、令牌或第二队列。信号、提醒或卡片可见都不构成批准，发布与点击仍复核原归属及当前授权。呈现的权威正文与接线边界见[权限与安全输入交互](对话交互.md#权限与安全输入交互)。

Router 的 assistant_* 工具只注册给拥有会话的 Agent，不等于全部暴露为外部 MCP。外部 MCP 保持既有委派边界，不新增任意配置、凭据明文、历史读取或消息发布权。人端接管、凭据录入、导入等不能用模型声明代替真实用户权限。

Router 的模型工具描述与实际执行复用同一定义身份白名单，晚注册到当前 Agent 作用域的通用发现、文件及命令工具也不进入 Router 可见 schema；官方原生执行器继续负责描述和执行本体，权限门在派发前复检。产品状态先用自有只读能力查询；本机设备访问按 Link 的授权与最近访问事实回答，不因历史曾做系统排查就把新的状态问题扩大为 Windows 网络调查。用户明确请求更广的系统调查时才按该范围委派，不用固定问句或回复模板替代 Router 理解。

执行投影的 `execution.uncertainty` 包含 `reasonCode`、`reason`、`attempts`、`nextCheckAt`、`automatic`、`escalated`、必要时的 `recoveryBlocked`，并绑定 `assignmentId`、`runId`、`sessionId`、`fence`、`instructionRevision`。原因枚举为 `session-interrupted`、`worker-incomplete`、`evidence-mismatch`、`external-effects-unknown`、`pause-unconfirmed`；缺少证据时不凭空填下次核查时间。主动复核的 `lastInspection` 独立保存幂等标识、时间、结果、受控原因码及原执行归属，不挪用错误字段表示成功；同一执行 30 秒内重复请求复用最近核查事实，不形成模型信号紧密循环；只读核清不等于已排队续跑。停止投影另给 `stopRequestedAt` 与 `stopConfirmationOverdue`，不将动作门生效等同于执行端已退出。阈值只决定异常呈现和升级通知，不放宽执行或审批门。

恢复通知携带原来源、事项、原因和执行身份，按进入、复核结果、升级、核清后的处置及要求版本幂等，经原持久 inbox 异步交给 Router；人类消息优先，发布前复核事实与权限，过期通知不再发声。具体通报与自主处置以[自校验与交付](自校验与交付.md#待核实通报与自主处置)为唯一行为正文，不另设系统模板兜底或第二核查循环。原会话安全接续保留原 Run、session、工作区与冻结模型，递增 fence；自动次数、延期时点与请求留在原账，跨 fence/重启不重置，耗尽后不再自动续接并异步通知 Router；核查全部工具终局、外部效果、日志/文件边界及当前授权后方可排队，执行前再次复核，已完成动作不得重放。

授权行为唯一正文见[权限与对外审批](任务与执行.md#权限与对外审批)。动作服务接收能力声明、准备结构化动作、生成绑定冻结快照的审批请求、由真实用户答复、复核并单次提交、记录回执；无通道返回可恢复的接管点，不返回可由任意脚本消费的通用批准。注册类别、实际通道及许可匹配均由宿主验证，模型只可提出待审动作，不能注册可信能力、写入许可或回报用户已批准。浏览器/终端保留其他工作能力，不承诺从任意调用中识别高危提交。安全凭据录入是独立人端秘密协议，不作为 ticketAnswer 普通正文；录入与动作获批分别表达。目标记录未发布 schema/API 前不注册为可用接口。

专用动作的执行证据保留原调用操作与对应结构化返回：本地能力发现/准备不等于提交，提交的工具成功也不等于外部已生效；效果判定与恢复规则只在[通道与接管](任务与执行.md#高危类别注册通道与接管)维护。渠道 `targetTriggerId` 取统一账本的完整原始 ID，保险库仅提供凭据，不能承担渠道目标注册。

assistant.db 保存控制面、工单及运行记录；ledger.db 保存可重建原文检索；官方会话日志保存原始执行；Markdown 保存提炼正文；state.json 保存逻辑会话映射等状态。默认数据根为 ~/.benchgo/assistant/。

渠道适配器不保存自身对话状态，不另建渠道工单或渠道专属会话存储。各渠道与桌面都是统一工单的入口，工单输入账、业务状态、投递记录与关单条件全局唯一；统一工作台会话可带来源标记呈现并直接回复，渠道归属不产生第二份记录。适配器只提供来源证据与原生概念映射，规则服务执行来源核对、聊天范围、准入和研判；渠道授权按适配器逐项绑定、可独立撤销，授权校验仍归统一服务。渠道配置不提供专属人设、默认姓名或自我介绍，统一身份来源及出厂空名规则见[身份与形象](身份与形象.md#出厂无名与全渠道一致)。

副作用先持久登记，数据库事务不等待模型或网络。先一致保存 Worker 原稿、实际失败材料及绑定版本的 Router 通知，再异步生成并保存 Router 回复与唯一 outbox；实际送达回执一致记录交付状态及对应关单终态，不能在原稿落库或回复生成时提前 completed/failed。提交只做来源、已应用要求快照、有效执行身份及落库的确定性校验，不设语义 review gate；原文证据按权限查阅。生成失败只重试 Router 表达，投递失败复用已存回复，两者保留待交付，不重跑 Worker。文件与数据库用 journal/hash 恢复一致，不宣称跨介质原子事务。通知、生成与投递按稳定身份去重，发送重试与执行恢复分别处理。

错误区分参数、认证/权限、版本/幂等冲突、能力不可用和效果未知；成功响应不得同时掩盖未应用、未完成或未送达。停用 SuperAgent 释放自身监听、计时器、worker、路由和数据库，保留用户数据，停止服务不等于撤销外部效果。

## 持久执行事实与增量读取

`execution-facts-store.mjs` 在原 `assistant.db` 保存精简执行投影与展示变更 journal；Ticket、Assignment、Run 仍是唯一领域账。官方 Session 保留原始执行记录；`task-execution-progress.mjs` 注册官方 `benchgoExecutionFacts` Projection，以纯同步归约保存受控阶段、计数、直接子会话关联及最多 64 个关键节点，不保存工具参数、输出、模型正文、思维或凭据。恢复通过官方 `sessionQuery.observeSession(..., { projectionMode: 'all' })` 取得同一切面的投影，不新增整份 transcript 副本或恢复状态机。所核官方版本为 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`。

执行身份沿现有 `ticketId / assignmentId / runId / fence / instructionRevision`；`instructionRevision` 就是要求版本，`appliedInstructionRevision` 单独说明 Worker 已应用版本，普通修订等待工具边界期间不能隐去仍在运行的旧快照。子执行另有 `sessionId / parentSessionId / rootSessionId / activationId`；官方子代理 activation 的 `runId` 不等于领域 Run。父子关系只接受官方 `origin: 'subagent'` 与真实父会话，普通 fork 的 `parentSession` 不自动成为子 Worker。

水位有两层：全局 journal 的稠密 `seq` 与每来源 Session 的 `sourceSeq`。不同会话的 seq 不互相比大小；来源水位取官方完整投影切面，不以到达事件的最大 seq 猜测已覆盖缺口。重复和迟到通知重新读取当前官方投影，不降水位；较旧投影不能覆盖新记录。已观测的生命周期终局优先于不带 activation 身份的迟到子任务通知。重启保留已确认子任务事实，正在运行的缓存不冒充当前进程存活；同一 Run 旧 fence 的子记录标为历史。

`session/event` 说明内存日志已提交，不证明官方日志落盘。本地投影提交与官方来源耐久性分开：实时来源为 `sourceDurability: 'observed'`，通过官方冷读取重建的来源为 `persisted`。冷投影可含官方为中断回合补出的只读结束标记，不能把其 cursor 当作已落盘末位；`flushedCursor` 在没有独立成功检查点证明时保持 -1。也不能在 `session/flush` 监听器开始时就宣称全部监听器成功。官方历史缺失、日志落后于曾观测投影、子历史不可恢复或精简容量上限均给 `complete: false / missingReason`，不会填造零个子任务或推定完成。Session 计数标为 `counterScope: 'session'`，不是当前要求版本的新增产出证据。

领域表与执行投影的展示变更在同一 SQLite 事务内写 journal，事务成功后才唤醒订阅；另一连接的任务名称、整理标记与 Goal 也经原 runtime-store 的提交回调唤醒。回滚不发布，展示流不写通知 outbox。摘要发布只写 `summary` 展示变更，摘要消费者忽略该类，避免触发自身。工单完成仍由原结果及送达机制决定。

| 接口 | 返回与约束 |
| --- | --- |
| `runtime.executionFacts.snapshot({ ticketId? })` | `{ cursor, tickets, bootId, observedAt, completeness }`；分批读取同一同步切面的完整领域任务行，包含归档及原整理筛选，不以工具活动重排工单。当前 `truncated: false`，海量账本容量与帧大小尚未实测 |
| `page({ after, through?, limit? })` | `{ cursor, through, entries, hasMore }`；固定上界的稠密分页，`cursor` 是本页最后覆盖水位，不是尚未读完的全局上界。entry 只含真实身份、kind、时间、安全计数及证据引用；Goal 的 `ticketId` 为 null、`data.goalId` 定位原记录 |
| `subscribe(listener) / currentCursor()` | 提交后合并唤醒与全局水位；监听只是唤醒信号，消费者从 journal 补读，释放监听不影响执行 |
| `evidence({ ticketId, runId?, instructionRevision?, after?, limit? })` | 同一安全 journal 的有界证据与精简投影，附 `runtime` 白名单机械事实和有界 `modelEvidence`；目标和验收只提供限长脱敏投影，不提供任务原文、参数、输出或错误原文 |
| `evidenceSnapshot({ limit? })` | `{ cursor, currentCursor, observedAt, bootId, executions, complete, truncated, schedulerHeartbeat }`；外部监督专用白名单快照，不打开主系统数据库或 Session writer。默认/上限 1000；`schedulerHeartbeat: { at, bootId }` 只在本进程既有编排周期实际成功完成后更新，首轮完成前为 null，读取、定时器触发、卡住或失败周期均不续心跳 |

安全 `runtime` 包含工单及要求身份、Assignment 租约、Run、官方 Agent 的当前 `executionAlive`、独立模型请求 `request`、`wait`、停止确认、原核查事实与每 Session 水位。`evidenceCursor` 是本工单最新事实水位（不含纯摘要展示），用于阻止旧摘要或监督判断覆盖新执行；全局水位前进也可能仅来自另一工单。`observedAt` 只说明此次读取时间，不是 Worker 心跳。基于官方 pin `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 的 `jobs.list(owner)`，只认原 Worker 及本 Run 已绑定子 Worker 所有、仍 running/stopping 的后台任务；父 Agent 未运行且无更优先的人端/审批/暂停/续接等待时，投影 `wait.kind: 'background-job'` 与实际注册时刻，不包含命令、进度、输出和 spill 路径。官方列表额外返回的无 owner 任务与其他执行任务均排除。官方 AssistantStreamFrame 未公布模型请求 deadline，JobView 未公布预计结束时间，工具声明预算也不等于实际已启动的截止；请求 deadline 与等待 `expectedUntil` 保持 null。已有工具前后文件检查点完成时复用内存中的前后比较，将安全计数写入同一 `sa_execution_facts` 的 `artifact-observation`，不新增工作区扫描或正文读取。观察绑定原 Ticket/Assignment/Run/session/fence/已应用要求版本，仅含覆盖种类、比较计数、起止时间、检查点序号和事实引用，不含路径、hash、blob、工具参数或输出。`runtime.modelEvidence` 与本地摘要共用白名单投影；`outputObservation` 只说明受保护工作区文件在各工具检查点期间的净变化，不覆盖聊天成果、外部效果或被排除文件。尾部排队/在途、落账失败、恢复后缓存未知、序列缺口、旧 fence/要求或观察过期都返回 unknown；旧 completed 不得掩盖新 pending。观察与元数据聚合是可重建投影，不另立工单账或调度。

人端通过官方 Remote 命名空间 `benchgoExecutionFacts` 使用 `snapshot / page / evidence / stream`；严格描述符唯一来源为 `execution-facts-contract.mjs`，Host 和 Client 共用，实际 `invocation.peer` 必须为 owner，JSON 不能声明 principal。传输复用官方 Remote mux，不新增 WebSocket。stream 先订阅、再读取 baseline，先返回 `{ type: 'snapshot', snapshot }`，再按 baseline cursor 补齐 `{ type: 'changes', entries, cursor, through, hasMore }`；慢消费者只保留一个唤醒标志并分页追赶，缺口明确失败，断线重开权威快照。客户端使用官方 `$stream` 与 `RemoteSnapshotStream`，按 generation 防迟到；增量合并 ticketId 后只读取变化工单，不以周期全量读取作健康更新。列表、详情及原执行会话定位共用同一领域记录。

## 接口演进与验收

存储、HTTP 与工具版本独立管理。旧 action 适配同一领域服务；不兼容配置明确提示升级或只读，不注册尚未部署的操作。模型工具、HTTP、渠道和桌面复用同一身份、准入、状态及版本校验。

统一输入账本、原 Assignment/Run/session 续做、工具批次快照切换、暂停只收件、扩权真实批准回执，以及动作授权存储/注册/审批和管理接口已接线。问答卡持久绑定 sessionId/callId、questions、Attention.id 与要求编号，即时/迟到答案幂等回原问题，跳过不产生许可。执行会话交互见[对话交互](对话交互.md)，渠道与送达关单边界分别见[链接与渠道](链接与渠道.md)、[自校验与交付](自校验与交付.md)。入口 Assessment、后台学习 review 与软件测试验收各保留自身职责。

Router 表达交付已接线；具体机制和实现边界见[自校验与交付](自校验与交付.md#实现与验收边界)。接口验收须覆盖完整的执行、回复生成、持久投递和可信送达路径，并分别核对正式审批卡、真实渠道及重启恢复，不能以静态渲染代替实际业务效果。

待核实信号与协调接口、进度投影和受控半途中断续跑已接线；安装版需另验 Router 主动通报、核清后的原会话接续与报告、外部效果未知不重发及停止确认超时。定向测试和看板渲染不等于真实运行验收，不据此宣称所有恢复场景已闭环。

每批实现同步领域服务、HTTP/工具、OpenAPI、能力发现、客户端入口与对应验证。核对真实源身份不能由载荷或模型声明覆盖，跨会话工单控制被拒；参数、权限、版本冲突、能力缺失和未知效果分别可辨。完成结果与 outbox 的一致性、文件/数据库 journal 恢复和停用释放须独立核验，不能以 HTTP 成功代替任务完成或投递成功。

新增验证无独立内容验收模型或评分返工；Worker 原稿、完成信号、Router 自然回复及回执按版本关联，原稿在详情可查，Router 主动表达、自选摘要或完整回复且不重派或验收。成功/结构性失败说明送达后分别 completed/failed；生成失败只重试表达，投递失败只补投，两者保持待交付且不重 Worker。验证无固定报告、标题前缀、状态硬文案或兜底。验证五要素实存完整、工具范围不超原指令，普通修订在原执行边界整份切换且不打断在途工具、暂停不续跑、叫停撤权优先、扩权才生成新授权版本；统一输入跨入口去重与已应用关联可追溯，真实执行会话双向定位不重派。网站许可按类别/期限匹配，高风险逐次审批，重启不重放未知效果。
