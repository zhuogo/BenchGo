## 1. 服务权威

| 所属 | 权威职责 |
| --- | --- |
| BenchGo 基础层 | 公共配置、模型目录/凭据、数据根、客户端装配及共享资源 |
| Harness / commander | 会话与执行生命周期、工具权限、Schedule、skills、官方日志与运行时 |
| SuperAgent / assistant | Trigger/Gate/Eval、Ticket/Mandate、Assignment/Subscription、账本关系、验收交付、学习和监督协调 |
| Voice | 语音输入、朗读、通话及其配置，不复制助手专用音频控制器 |
| Link | 多端连接与既有认证转发，不直接读 SuperAgent 私有数据库；非首轮单机前置条件 |
| 飞书连接适配 | 接收/校验来源、稳定事件键、消息格式、发送与回执；无自主调度权 |

仍是五个源码包、一个 benchgo-plugin；入口 benchgo-plugin/superagent-plugin，客户端注册 id=benchgo-plugin，既有 assistant 协议和数据根保留。参考仓库和官方源码不修改。新服务尽量用现有插件、服务和配置组合，不增加 Redis、独立工单服务器或第二个推理循环。

资源 → 接入 → 多平台提供飞书接入与实际状态；业务配置仍按现有身份/任务/记忆入口承载，具体页面在实施时复用共享组件。停用 SuperAgent 释放自身 worker、监听、路由、计时器与数据库，保留数据；已运行执行器按真实生命周期核实，不把服务停用当成外部动作撤销。

## 2. 当前接口事实

当前对话发布契约：`history` 返回真实用户消息、`assistant_reply({text})` 显式发布，或官方 completed 回合确认的同一人类请求最后一条无工具调用终答。桌面派工成功后，当前 Router 使用这两个正常出口之一自然回复；工单创建不再自动插入固定接单文案。后台通知接受 `ticket.result` 的合法 `publication`、原样 `ticket.attention`，以及显式人类渠道请求由同次 Router 研判 `replyText` 生成的 `ticket.accepted` 接单回复；没有回复正文时不补固定模板，旧固定待发回执不再投递。过程消息、工具与 Worker 原文不属于聊天输出。`assistant_reply` 仅注册在拥有会话的 Router，绑定当前用户请求并幂等持久化，随后结束回合；它不是外部 MCP 的任意消息发布接口。现有 `assistant_history` 是模型按授权读取会话参考材料的工具，不改变其工具结果不面向人直接发布的边界。结果通知正文与可选回复由同一次验收生成，不另起重复验收。

源码：[service.mjs](../../plugins/superagent/src/service.mjs)、[engine.mjs](../../plugins/superagent/src/engine.mjs)、[orchestration-store.mjs](../../plugins/superagent/src/orchestration-store.mjs)。机器契约：[openapi.json](../../plugins/benchgo/openapi.json)。以下区分已接入 action 与尚待闭环的领域模块。

- POST /api/commander/assistant：主聊 state/ensure/history/send/requestState/cancel、旁聊、配置、档案、记忆、Ticket、Goal、通知、产物等 action。
- 既有 artifact、system-file 与兼容 voice 路由继续保留鉴权与文件边界；共享 Voice API 由 Voice 负责。
- 现有 Router 模型工具按职责包括：会话与参考读取 `assistant_projects`、`assistant_sessions`、`assistant_history`、`assistant_session_search`、`assistant_ledger_read`、`assistant_capabilities`；工单与目标 `assistant_tickets`、`assistant_delegate`、`assistant_ticket_control`、`assistant_ticket_change`、`assistant_goals`；配置与身份 `assistant_config`、`assistant_models`、`assistant_profile`、`assistant_pet`；记忆与学习 `assistant_memory_search`、`assistant_memory`、`assistant_review`、`assistant_learn`；模型能力 `assistant_summarize`、`assistant_analyze_image`、`assistant_generate_image`；正式回复 `assistant_reply`。这些是拥有会话的工具注册，不等于全部暴露为外部 MCP。
- 环境调查与执行通过 Ticket 提交；Router 兼顾正常聊天、直接回答与总调度，不能直接调用继承的网页、文件或 shell 工具，也不再有每请求 8 次探索额度。Router 权限闸门（`router-permissions.mjs`）对官方协调工具 `ask_user_question` 与 `schedule_*` 按工具名放行，宿主重新注册同名工具不撤销该权限；其他继承工具仍按捕获的定义拒绝，拒绝信息写明被拒工具名（2026-11-06）。桌面普通派工 `assistant_delegate` 不额外询问建单许可，成功后由 Router 自然回应，真实受控动作仍执行其授权检查。
- 当前执行结果由 Router 按证据给出 `passed`、`failed`、`wait` 或 `rework`，代码复核授权和版本后提交。本轮 `failed/rework` 不直接终单：须带 AI 自然说明和修正指令，提交后由原 Ticket/Assignment/Run/session/工作区续做，不再使用“两轮非项目只读修正”的旧分支。无进展保留等待与显式恢复，停止、撤权、版本和未知效果的门禁优先。内部模型/证据问题归 `review_wait`；真实用户信息、权限或范围问题归 `blocked`，桌面/飞书复用持久 Review Attention，回答绑定原问题与版本。其他渠道续做仍属 P1；真实返工/阻塞未验收通过。
- `assistant_ticket_control` 对当前逻辑会话工单补充原始用户消息、取消或以 `operation: answer` 回答指定 `attentionId`；答案使用当前真实用户原文，不能由模型另写。`sessionLineage` 保留同一逻辑 thread 的旧/新模型 session 归属，清空后仍可管理原单，旁聊不扩权。收件与应用、`cancelling` 与已停止分开。`assistant_ticket_change` / `ticketChange` 当前仍支持原工单 `revise/reopen`，这与目标“交付后新建关联调整单、原单不重开”仍有差距。2026-11-06 起 `assistant_ticket_change` 与 `assistant_delegate` 一致：绑定当前用户原始指令、复核授权规则与版本，不再额外弹审批；运行中执行仍须先安全停止。
- `send({threadId,text,requestId,replyContext?})` 持久收件并返回 `threadId/sessionId/requestId/messageId/status`；同 requestId、同来源/正文/关联内容幂等，异内容拒绝。`requestState({threadId})` 返回该逻辑 thread 的持久收件数组，`history.requests` 返回当前模型会话及未绑定会话的收件投影；`processed` 只表示 Router 回合结束。官方 composer 已通过公开 Slots 适配接 `engine.send`，主/旁聊文本与可解析引用走持久 inbox；附件明确系统提示并保留草稿，不静默绕过。取消旧队列、断线同 ID 核对及清空归属有定向验证，真实桌面重启仍待验收，详见[持续主会话后端](持续主会话后端.md)。
- 正式回复在生成中读取官方顶层 `assistant_reply` 参数或 `partial.blocks kind=text`，按 session/turn/request 绑定流式暂存，过滤推理与工具参数；正式发布优先替换，completed 后持久终答替换暂存，失败/取消清理未提交正文。流式片段不表示任务完成。真实供应商普通 Router 流式已通过，渠道流式未新增，详见[正式回复流式](正式回复流式.md)。
- 工单独立 `title` 统一限制为最多 10 个 Unicode 字符；持久化、查询、通知与 UI 使用同一 helper，存量缺标题可回退。完整 `target/acceptance` 不截断，改标题不递增 `instructionRevision`。活摘要、语义查重、同 Trigger 唯一工单与合并仍属 P1。
- 新增 connections/connectionConfigure/connectionStatus/connectionVerify action；连接配置使用 revision 做 CAS，密钥仅存引用，状态包含长连接状态。配置入口为资源→链接；真实飞书链路仍待验收。
- 新增 ledgerRead action 与 assistant_ledger_read 工具，按账本 ID 和游标取原文；会话搜索使用 FTS5 投影，暂在检索时同步 Harness 日志。
- 记忆直接管理：`memorySave` / `memoryDelete` 接受可选 `revision` 以校验并发修改；`assistant_memory` 基于宿主会话与真实用户请求直接记住、纠正或遗忘，不再创建专门模型动作工单或逐条审批。`assistant_review` / 自动学习只将有可信用户来源且符合当前学习规则的记忆直接写入；技能仍生成候选。旧 `memoryCandidates` / `memoryCandidateAccept` / `memoryCandidateReject` 标记为弃用兼容入口，新页面不再调用；历史候选按[记忆直接生效契约](记忆与技能.md#51-记忆直接生效2026-11-04-本次实施契约)处理。外部 MCP 不新增记忆工具，现有 `commander_delegate` 契约不变。
- profile 管理/导出仍兼容六文件，运行上下文按五文件顺序冻结；`documents.mjs` 的 session_context_snapshots 持久保存会话快照，恢复复用原快照，明确遗忘可脱敏。身份名称直接写入 IDENTITY.md，config.name 仅作无 name 字段文档的显示回退；统一备份与迁移后续设计。
- Trigger/Gate/Eval、Ticket/Assignment、隔离 Worker、证据验收和 outbox 已有接线；P0 失败续做、桌面/飞书 Review Attention 和桌面持久输入已落代码并有定向记录，不等于真实全链路通过。真实新闻首轮在执行额度耗尽后 uncertain/open 且无交付（历史记录；该执行时长预算已于 2026-11-06 拆除）；真实渠道全链路亦待验收。
- 2026-11-06 决策：预算闸门整体拆除（原因：DeepSeek Harness 原版无预算概念，Mandate 只管授权；执行时长与目标请求/token/金额/期限预算会打断长任务）。Goal 不再有 budget/budgetState，goalBudgetGet/goalBudgetUpdate/goalBudgetResume、`GOAL_BUDGET_EXHAUSTED`、`budget_wait` 退役；金额预算结案。保留 token 用量记录与展示，不拦截执行。
- 自建技能 action 为 ownedSkills、ownedSkillAudit、ownedSkillApprove/Reject/Pin/Restore；当前源码仍先生成 candidate，经 Approve 后发布到官方 skills provider，固定与快照恢复要求版本一致。2026-11-04 的“直管制、自动生效、取消发布审批门”是待实施目标；现有 HTTP 尚无独立的自建技能编辑/归档 action，不能将目标管理项列为已发布接口。目录预览不算使用，第三方技能不纳入自动策展。
- 工具 → 技能通过基础层 `/api/benchgo/skills` 合并官方生效目录与上述自建管理结果，统一搜索、来源筛选和正文预览；不改变自建技能存储及审核协议。全局/项目范围和默认 Agent 预设边界见 [统一技能管理](../04-模型与工具/统一技能管理.md)。该只读管理接口不是新增 MCP 工具。

旧入口由同一领域服务适配，不另存状态。接管、凭据录入、已读与 Profile 导入等人端动作不能靠模型传 human=true 获权。新能力未部署返回明确 unavailable/reason，不把模块存在视为完整能力就绪。

### 验收、回答与安全恢复 action

| action | 当前契约 |
| --- | --- |
| `ticketRetryReview` | 传 `ticketId/expectedResultVersion`，只重审原证据；`unchanged` 是输入去重，不代表任务完成。内部可重试故障按持久退避恢复，不以固定两轮终单；需要新证据须走原单续做 |
| `ticketAnswer` | 绑定 `ticketId/attentionId/instructionRevision/requestId` 和答案；原问题、当前来源/版本、是否已答及停止状态均复核。Review Attention 答案写原分派 continuation，不调用不存在的 Worker 原生 question |
| `ticketResume` | `paused`（用户手动暂停、Attention 阻塞）延用原暂停恢复；续做等待必须传匹配的 `expectedResultVersion`。执行时长预算与 `additionalExecutionMs` 补时已于 2026-11-06 拆除，不改变 Mandate |

`ticketResume` 恢复的是原 Assignment/Run/session/工作区。恢复前确认官方原会话无在途写入者、原执行已停、checkpoint/transcript、fence、当前任务/结果版本与授权均有效；停止或效果未核实返回 `queued:false` 与明确 `code`，不能将 HTTP 成功当作已排队。`EXECUTION_EFFECTS_UNKNOWN` 保留安全等待，不重放未知副作用；重试投递也不重跑任务。首轮 deadline 等待分支随执行时长预算一并拆除；检查点与崩溃恢复保留。

## 3. 目标记录与不变量

以下字段为领域语义草案，实施时锁定 schema/迁移版本，不预先承诺具体工具名。

| 对象 | 最小字段/约束 |
| --- | --- |
| Trigger | id、sourceKey、channel/thread/message、actor、kind、occurredAt、原文或 rawRef、关联事件；不可变、来源键唯一 |
| Candidate | triggerIds、contextRefs、现有 ticketRefs、strength、gateReason、policyVersion |
| Eval | id、threadId、候选范围、policyVersion、attempt、投递时间/deadline、状态；同线程一个活跃批次 |
| Decision | eval/trigger 引用、四处置、规则引用、代码复核结果、原因、去向 |
| Ticket | id、title、summary（活摘要）、objective、acceptance、sourceTriggerIds、mandateRef、生命周期、instructionRevision、rowVersion |
| Mandate | id、policyVersion、scope、strength、ruleRefs、发起人身份（原版五要素）；只管授权、不含预算，不可变，当前许可可否决 |
| Assignment | id、ticketId、任务版本、执行器需求、优先级、任务包、状态；Router 决策先落册 |
| Subscription | threadId、ticketId、消息游标、持有/处理/释放状态；多对多、不扩权 |
| Run | id、assignmentId、sessionId、环境、lease/fence、心跳、checkpoint、attempt、效果状态 |
| Result | id、ticketId、目标版本、summary、evidenceRefs、目标需要时的 artifactRefs、未尽事项、验收结论 |
| Attention | id、ticketId、triggerId、目标来源、问题原文、状态、replyRef |
| Delivery | eventId、result/attentionRef、来源目标、幂等键、尝试、回执、状态、下次重试 |
| Disposition | triggerId、eval/ticket/run 引用、处置及时间，保留可追溯历史 |

source/actor/owner/policy 由可信入口解析，模型只能引用，不能声明自己是谁或修改授权书。外部事件同键异内容为冲突或独立更正事件，不覆盖原事件。instructionRevision 是工作要求版本，rowVersion 是并发更新版本，心跳不能让要求过期。

## 4. 总线、事务与恢复

总线表示统一协议，不要求新部署消息中间件；单机用既有服务事件 + SQLite 持久 inbox/outbox。所有需恢复的副作用先持久落册再执行，数据库事务内不等待模型/网络。

Trigger 去重、归属、Decision、工单与待投递记录在相应事务中一致提交；Worker 领取采用唯一权属/租约。完成结果、验收、终态及结果 outbox 原子提交。投递至少一次，消费按稳定 id 去重；渠道无幂等保证时不承诺绝对只发送一次。

单机单数据根只有一个编排所有者，多窗口只是客户端。重启对照旧 Run、官方会话、工作区与外部回执，不因 lease 到期直接再做一遍。效果未知明确 uncertain/待核实，fencing 只能阻旧写入，不能撤回已经发生的外部效果。

Harness 日志为原始会话权威；assistant.db 保存控制面、外部事件与可重建检索投影。Markdown 为提炼正文权威，文件与数据库通过 journal/hash 恢复一致，不宣称跨存储事务。导入、备份不携带明文凭据。

## 5. 目标操作边界

| 操作族 | 目标行为 |
| --- | --- |
| 来源接收 | 飞书认证/去重 → 统一 Trigger；主人直接输入使用同一账本 |
| 准入/评估 | 代码 Gate、只读模型建议、代码复核、Decision；旧 policy 响应不能提交 |
| 工单/分派 | Router 建单与写 Assignment；机械派活，不由工具直接绕过工单启动 |
| 订阅/补充 | 忙时持久接受、动作边界应用、游标/归属、一次 handback |
| 控制 | 暂停/停止/接管先确认执行状态；交付后调整开关联新单（保留历史、复验授权），原单不重开 |
| 验收/交付 | 按本单目标验收；纯文本无文件也可通过；可修复失败说明后原单续做；真实阻塞通过 Attention 回原来源、回答后继续；内部待核验不转用户拍板；交付状态独立于结果 |
| 文档/学习 | add/patch/remove、expectedHash、冻结 snapshot、双计数器与技能注册 |
| 规则/审批 | 磁盘现行版逐动作校验；收紧立即，无法确认 fail-closed；审批服务执行门 |
| 连接/秘密 | 资源 → 接入 → 多平台；安全录入、引用/代填；不提供模型读明文接口 |

模型工具、HTTP、飞书、桌面须共用相同领域校验，不能各自实现准入或任务状态。旧 assistant_delegate 可适配工单创建，新参数/新权限必须显式表达；旧调用不能自动获更大范围。

结果类型和后续分支优先用现有 target / acceptance / Result / Attention 表达，不为文本任务新增强制产物字段或第二套协议。`blocked` 与 `review_wait` 是目标上的等待原因分类，当前公开 verdict 枚举未因此改变。修正、问题、来源、版本和投递意图可靠持久化；同一问题的回答精确绑定原单，普通“继续”不能丢失工单关联。普通结果未通过或修正次数耗尽不直接等于工单终态；可恢复的资源不足应保留等待与继续入口。

错误须区分参数、认证权限、版本/幂等冲突、能力不可用和效果未知；接收成功、已应用、已完成、已送达、已读分别返回，不以 HTTP 200 假装全部成功。

## 6. 发布约束

存储、HTTP 与工具版本独立管理；不把未部署的设计注册为可用功能。无法安全兼容的配置明确提示升级或只读，不伪造已完成状态。

每批实施同步领域实现、HTTP/工具、OpenAPI、能力发现、桌面/连接入口和定向测试。实现事实更新在第 2 节与《现状》，不以改写目标契约消除交付缺口。
