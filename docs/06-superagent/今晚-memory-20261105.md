# 2026-11-05 晚：记忆格式与来源

## Mandate 与固定验收

1. 自动学习的候选 ID 与正式条目 ID 不相同，正式 ID 不含 `candidate-`；重启、写入回执中断、并发重试仍只保存一条，候选 `memoryId` 与条目 `candidateId` 双向关联。
2. 已有 `candidate-` 条目在启动时迁移为正式 ID，保留 `legacyIds`，旧 ID 仍能用于编辑和遗忘；不捏造旧来源摘录。
3. 新学习记录的 `source.excerpt` 来自宿主核实的原用户消息（最多 6000 字符，`excerptTruncated` 标明截断），保留 session/message 指针。手工保存的来源摘录来自用户本次输入。
4. 修正条目保留正式 ID、递增 revision，`supersedes` 指向上一版 ID/revision；`versionChain` 保存各次替代引用。正文历史沿用文档版本，不复制历史正文。
5. 存储和会话冻结保留完整注释以支持定位、并发与遗忘；送进模型的文档及结构化条目均去掉 HTML 注释。已经送入上下文的干净正文仍能按结构化条目关联被遗忘。
6. 记忆时间线显示本地时间（ISO 时间仅作为机器属性），可展开来源原文与替代版本。不更改既有输入组件和整体视觉。

## 接线与兼容

当前 engine 同时注入 `documents` 原始文档和选中的 `memories` 条目。新增纯函数 `cleanMemoryContext(context)`，由 engine 在冻结之后、构建开局包之前调用。原始管理 API、文档编辑和冻结存储不改为干净正文，避免遗忘失去 ID 定位。

`legacyIds` 属于条目别名；历史 `candidate-` 映射不作为内容纠正，不能误建排除 tombstone。来源只有旧指针时继续兼容，不将模型总结伪装成用户原文。公开响应新增的字段由主代理同步 OpenAPI；MCP 记忆查询沿用现有动态对象返回。

## 已实现

- 正式记忆使用独立 UUID，通过条目 `candidateId` 和候选 `memoryId` 互相定位；恢复以 Markdown 已落盘条目为准。启动迁移旧 `candidate-` ID，并用 `legacyIds` 支持旧 ID 编辑、遗忘及冻结快照清理；ID 迁移不增加条目 revision，也不产生内容排除记录。
- 学习处理器保留宿主提供的用户文本摘录与截断标记。手工编辑将本次输入作为新来源，旧摘录仍由文档版本保留；文档版本的来源元数据只记录指针，避免额外复制摘录而阻碍遗忘。
- 每次条目编辑保留正式 ID，递增 revision，并记录 `supersedes` 与 `versionChain`；链中仅保留 ID、版本号和该版更新时间。
- `cleanMemoryContext(context)` 清洗模型投影中的文档、结构化正文和来源摘录 HTML 注释，不改变存储或冻结对象。遗忘同时处理正式 ID、旧 ID，以及已清洗且未被结构化选择完整保留的文档正文。
- 时间线复用共享 `Disclosure` 显示来源原文与替代版本，时间沿用本地格式，ISO 仅在 `dateTime` 属性保存。保留当前输入组件与布局，文档编辑页无需调整。
