# 2026-11-05 晚：官方输入接缝与等待界面

## Mandate 与验收边界

1. 官方 composer 保持原有输入、附件、引用与审批体验。只有公开的提交扩展点能将提交送入 SuperAgent 持久 inbox；找不到即报告阻塞，不替换组件、不拦截 DOM、不修改官方或私有方法。
2. 主聊天、工单页与活动详情的等待状态展示系统状态、具体原因和可执行下一步；问题沿用 `TicketAttention`，补时/预算沿用现有接口，未知外部效果只核实状态，不能盲目重做。
3. 定时生命周期沿用 `history.notifications` 的 `schedule.lifecycle` 系统事件，卡片展示阶段、时间和关联工单入口；不改定时服务。
4. 聊天连接加载、失败与重试复用 `ResourceState`；工单和活动面板沿用其四态。验证函数与真实组件渲染/操作；真实桌面重启和用户视觉验收不以受控测试代替。

## 等待状态设计

复用当前工单版本的 Attention / Result / continuationWait 投影为统一等待说明。系统说明与 Router 自然报告分开：模型生成原因原样显示；缺少模型报告时只说明系统事实。所有动作绑定 ticketId 与结果版本；`ticketRetryReview` 仅复用既有重验接口，未知效果不显示继续/重试执行。

前端遵循 `docs/02-工作台与Agent/前端视觉规范.md`，保持现有组件与品牌。用户本轮免视觉校验，功能四态另留定向记录。
