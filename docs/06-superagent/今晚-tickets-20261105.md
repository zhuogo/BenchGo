# Tickets 实施授权与验证记录（2026-11-05）

## Mandate

依据《设计》§5.2、§5.4、§8、§19.2、§20，补齐工单活摘要、同 Trigger 唯一归属、关联调整单、新闻来源证据与 Worker 一层子代理权限边界。复用现有工单/分派/官方子代理服务，不修改官方引擎、参考仓库或生成产物。

- completed 工单保持原状态、版本和结果；后续调整创建独立新单，以 adjustmentOfTicketId 回链，仅携带差异与原结果指针。
- Router 负责语义判重，代码核实来源、授权及已有 Trigger 归属；模型 ID 原样保留，桌面省略模型时使用 Worker 配置。
- 活摘要包含目标、进展、卡点，从当前真实工单和执行状态投影；标题保持稳定。
- 工具证据保留 URL、来源、发布时间、抓取时间及失败记录；单次失败不直接否决有其他可用来源的结果。
- Worker 子代理仅一层，受同一工单实时权限与租约围栏约束；问题与结果仅回父 Worker，不扩大 Mandate。
- 验证采用本地定向测试：工单调整/幂等/来源复核、权限收紧/租约围栏、保险库/预算/检查点/Watchdog/重试；不调用真实模型或全量上游测试。

### 第 12 项补充 Mandate：结构化来源保真

仅扩展 `execution-evidence.mjs` 的来源投影，不改 Review 或任何真实请求链路。保留工具 payload 明确提供的 `failureReason` / `error`（字符串或 error.message，清理控制字符并限制 500 字符）、`relatedUrls` / `corroborates`（合法 HTTP(S) URL，去重且每字段最多 16 条）、`relationship`（有界文本或明确 type/url 关系对象）。没有给出的失败原因与关系保持缺失，不根据文本、域名相似或同时出现推断事实。

同 URL 多次出现时合并已观察字段，已记录的明确元数据不被后续 URL 扫描或缺字段条目清空；数组关系合并去重。单条 payload 可同时携带成功与失败来源，逐来源失败标记保留；完整原始工具文本、现有来源引用上限 16、整体证据大小和截断规则继续沿用。验证使用与官方 `tool/result` 相同外层的结构化 JSON payload，覆盖混合成功失败、重复 URL、缺字段未知与有界清理，不请求网络或模型。
### 第 9 项补充 Mandate：取消关键词硬拒

桌面派工入口不以“任务/进度/状态”等词判定用户语义或拒绝新任务。Router 负责判断新建或挂靠，代码继续核对原始主人消息、真实会话、实时授权与 Trigger 单归属。已删除仅用于此硬拒的未复用 helper；新增“做任务进度看板”和“检查网站状态”入单测试，并验证原始 Mandate 未被改写及同 Trigger 不能另开新单。

### 验证边界

- 语义相似性仍由 Router 判断，代码只核对可验证的来源、授权、范围和幂等边界；本轮没有真实模型语义判重评测。
- 子代理覆盖官方本地 registry/执行器链路，不覆盖外部 provider 自有的子代理机制。父回流沿用官方协议；本轮核对提示和父子创建边界，没有真实模型 `send_message` 或最终回答回流的端到端验收。
- `sources` 是宿主从工具结果提取的出处记录，不证明新闻内容真实或两个 URL 在编辑意义上互相独立；抓取时间缺失时保持未知。新闻用例使用本地 transcript fixture，未请求真实新闻站点。
- 调整单的执行、Review 与投递测试使用本地替身，不代表真实模型、真实渠道、桌面重启或用户视觉验收。最终统一构建/热加载由主任务执行，本收尾未生成或手工编辑 `lib/`。
