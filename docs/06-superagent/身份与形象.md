# SuperAgent 身份与形象

本文维护同一助手的名片、个性外观和表现方式。人格与记忆的数据权威见[记忆与技能](记忆与技能.md)，聊天布局见[对话交互](对话交互.md)。

## 身份与现有能力

BenchGo 是统一产品、Logo 与吉祥物 IP；SuperAgent、Router、宠物是同一个助手。默认正式素材来自 assets/brand/，个人外观不替换应用、托盘与安装品牌，改形象不改名字、模型、权限、记忆或正在执行的任务。

姓名默认可空，身份页和聊天共享 160×40 名片。cardHtml:null 使用当前形象与姓名；自定义 HTML 最多 16000 字符，sandbox 禁止脚本和网络，无有效内容兜底且不改写原文。清空保存即恢复默认显示，不恢复已撤销的模式切换和独立恢复按钮。

形象创作走现有聊天与图像服务：先查真实素材目录，优先复用已有组合，生成后先预览再应用，可取消和回退。上传 PNG/JPEG/WebP 须实际解码为静态 PNG、移除元数据，限制 8 MiB、单边 8192、总像素 32×1024×1024。

动作由真实事件和受控本地配方触发，不从措辞猜任务成功、不为每次表达调用模型、不因缺素材自动生成。外观版本绑定表情，换装不混播旧衣动作。

当前形象管理、基准表情映射与形象页短动作预览已有实现；聊天名片仍静态，原创短表情、完整动作接线、裁切、参考图局部编辑和桌面悬浮未完整实现。桌面形象目标仅为同角色轻窗口、拖动与回到现有聊天，不另造人格、记忆、输入框或任务中心。

主人档案以 USER.md 为主；助手的姓名与身份归 IDENTITY.md，人设归 SOUL.md，外观资源留在既有配置与资源存储。界面可以分“主人档案 / 我的档案”，不另建宠物昵称、角色切换、PET_MEMORY 或独立人格。未命名使用占位，不把品牌名当作用户命名；只换外观不推断新人设。

## 名片编辑与保存

入口为资源 → 身份 → 信息；姓名与名片预览共用实际 160×40 渲染组件。编辑 HTML 只展开编辑器，预览和诊断不直接写配置；取消/保存沿外层表单。已有自定义 HTML 优先，应用新形象不自动清空它。清空并保存才恢复当前形象，空白在保存边界归 null。

过滤提示可定位不支持标签、隐藏/零尺寸/越界等常见问题；任意 CSS 无法证明可见时保留实际预览和兜底，不改写保存原文。保存后按服务端 revision 刷新各入口，拒绝旧轮询回写；冲突和保存失败保留草稿，不丢模型等其他配置。

cardMotion 沿统一配置兼容，系统减少动态优先；页面隐藏、名片不可见或关闭动态时暂停 HTML 动画。开关已保存不表示聊天静态名片已经接上动作。名片可键盘进入身份页，窄栏姓名省略但能查看全名；HTML 只作展示，不获得脚本和网络权限。

## 创作、应用与恢复

入口为资源 → 身份 → 形象，聊天承担主要创作。提供当前预览、上传、让 AI 帮我设计、应用/取消与上一有效版恢复；不另建创作工作室或模型选择器。创作引导只显示可关闭提示，不自动填入/发送用户消息，不覆盖已有草稿、引用或附件。

| 用户意图 | 路径与边界 |
| --- | --- |
| 创造新角色 | 核实图像能力，默认生成一个候选；失败保留描述，能力缺失仍可上传 |
| 换装或局部修改 | 先查当前角色兼容素材；参考图/局部编辑不支持时明确说明，不把重新生成冒充局部编辑 |
| 一次表情 | 优先展示已有兼容素材；缺少时须走显式创作，不自动生成 |
| 改默认外观 | 预览完整图、小尺寸与明暗背景，明确应用后切换；未满足要求保持当前形象 |

新资源验证成功才更新引用；配置用 revision 合并，迟到生成结果不覆盖新选择，应用失败保留旧有效版本。当前、上一有效版本和一个待确认结果足够，未应用结果复用聊天产物。用户资源不写回 assets/brand/，不执行上传 SVG/HTML/脚本或外链动画；原创角色不强行套用基准挂点和装饰。

## 表情与动作目标

表情是角色素材，动作是本地 transform/opacity 等受控配方；二者分开，避免为衣服、动作和场景生成全排列。状态来自真实事件，可选对话表达只能沿现有回复附带允许 ID，不另起情绪模型，不允许任意脚本、URL、持续时间或窗口操作。

| 表现 | 触发与播放规则 |
| --- | --- |
| 待机 | 低频或静止，不持续大幅浮动 |
| 回应 | 用户发送或主动轻触，短时重复合并，单次点头/倾身 |
| 专注 | 当前会话真实执行，开始短播后静止，不无限抖动 |
| 开心 | 普通友好回应，不能解释为任务完成 |
| 完成 | 对应任务成功结果确认送达并关单，按结果去重只播一次；Worker 自报完成、执行失败或投递失败均不触发 |
| 等待用户 | 真实问题/审批，提示一次并保留对应工单的问题或审批入口；点击形象不能代替答复或授权 |

同位置只播一个动作，不排长期队列；异常和待确认优先，一条回复最多一次表达，不随 token 重播。普通表达可用约 5 秒冷却作为体验起点；隐藏、关闭动态或减少动态时停止运动。缺表情回退当前角色主图，不自动变回品牌角色；当前主图损坏提示不可用并保留配置，自动回上一版仍待实现。

聊天只设一处主要动态角色，预留空间不挤正文和输入；历史小头像静态。语音复用 Voice，不新增监听或虚构口型。点击角色不等于批准工具，不建设亲密度、养成、饥饿、复杂情绪或额外记忆系统。

## 桌面与多端目标

桌面能力先核实自有包装层扩展点，不能改官方子模块或恢复 runtime patches。目标为默认关闭的轻窗口：拖动、点击回现有聊天、隐藏/恢复；透明空白不挡点击、不抢焦点，换屏/DPI 后可找回，位置按设备保存。

关闭形象不停止助手或工单，退出 BenchGo 一并退出。前台聊天与桌面不重复庆祝，只做本设备可见性判断，不建设跨设备唯一播放协议。Link 复用静态头像和一处轻动作，不做系统悬浮窗；不增加桌面聊天面板、任务中心、独立通知体系或重型动画运行时。

## 实现与验收边界

形象编辑、资源校验、预览应用、基准表情映射与短动作预览已有实现；聊天名片仍静态。聊天动作/原创短表情、完整事件映射、参考图局部编辑、裁切、损坏自动恢复和桌面窗口不能标为已完成。界面不得暴露无效开关或旧名片模式引导。

完成动作绑定“成功结果确认送达后关单”属于待实施的任务事件接线，不设置内容验收触发条件。失败说明送达后以 failed 关单不播放成功动作；后续续跑或调整按真实新状态展示，不能因原单曾关单就播放完成。任务状态与交付规则统一见[自校验与交付](自校验与交付.md)。

验证命名/人设与外观互不覆盖，上传/生成/取消/应用/恢复/重载完整路径，新外观不混播旧表情，缺服务或资源有明确降级。HTML 编辑、过滤、保存、清空和冲突保护使用真实渲染；形象页与聊天尺寸、主题一致。按 CPU、内存、输入响应比较动态开关，隐藏后无持续循环；动作不额外产生模型请求。最终四态、触屏/键盘与视觉由用户验收。

正式品牌规范见[品牌素材](../../assets/brand/README.md)；VI 仅参考，固定版本与许可边界在[板块来源](设计.md#来源与维护规则)维护，不引入其本机服务或运行依赖。
