# SuperAgent 结果与交付

本文维护任务三态、Worker 结果、结果保存、Router 表达交付、问题回路与投递。执行、修订与权限见[任务与执行](任务与执行.md)，聊天呈现见[对话交互](对话交互.md)，字段与接口见[服务契约](服务契约.md)。

## 任务三态与简短摘要

Task 的持久业务状态以及对用户、AI 的返回值只有 `running` / `waiting` / `completed`。暂停与停止用独立字段 `executionControl: { pauseRequested, paused, stopRequested, stopped }` 分别记录请求和确认；等待原因与恢复条件另记。Assignment、Run、Outbox 的机械状态只用于恢复、授权和防重复副作用，不作为业务状态展示。

| 业务状态 | 含义 |
| --- | --- |
| 进行中 | 已受理任务，正在排队、执行或自动保存结果；无需用户操作 |
| 等待 | 当前不能自主推进：需要用户答复、审批或输入，被暂停或停止，或执行异常结束。附一段说明写清原因和下一步 |
| 完成 | Worker 正常结束并交回了结果，结果已保存。含义是“跑完并有结果”，不表示事情一定办成；送达另记 |

默认只读三态和一段摘要（界面至多 240 字，AI 列表至多 320 字）：进行中说明当前进展，等待说明原因、恢复条件和下一步，完成取结果的开头。完整结果按需读取，不进入 Router 默认上下文。完成与停止都不自动归档或隐藏，查看不恢复执行；手动归档见[任务清理与保留](任务与执行.md#任务清理与保留目标)。

### 等待的有效范围

`waiting` 只表达当前不能自主推进的具体原因，不作为内部异常的兜底状态。列表、详情、Router 查询与恢复入口读取同一事实，客户端不根据摘要推断。

| 情况 | 状态与下一步 |
| --- | --- |
| 缺少用户信息，或原问题待回答 | 等待；保留原问题和作答入口，答案回原任务 |
| 待动作审批、秘密输入或人工接管 | 等待；保留同一真实交互，模型回答不能代替批准 |
| 用户暂停、停止或撤销授权 | 等待；区分“请求已生效”与“执行端已暂停或退出”，不自动恢复 |
| 模型、配置、能力或授权不可用，系统不能自行恢复 | 等待；说明实际错误和所缺条件 |
| 执行报错、中断、截断、失联，或在途外部效果未知 | 等待；保留首因和原会话，核实后由用户明确续接，不盲目重跑 |
| 正常排队、执行、后台任务或有界自动退避 | 进行中；显示实际活动 |
| 已正常结束，结果正在自动补存 | 进行中；内部收尾，不转等待 |
| Worker 正常结束且结果已保存 | 完成；包括 Worker 在结果里说明没做成的情况 |
| Router 表达、通知或投递失败，或效果未知 | 执行状态不变，独立记为待交付，只恢复对应阶段 |

“正常结束”依据官方回合的真实完成原因；会话句柄释放、单个工具结束、子代理返回或只有部分正文都不算。正常结束先于随后的停止请求时仍按完成收尾；没有可靠时间或原执行确已取消时，保留停止控制和已有结果，不猜测成功。

## Worker 结果

Worker 的结果提示要求：结束时用几句话写清做成了什么、产出在哪、还剩什么问题，不复述过程。执行中的简短公开进展另见[执行动态观测](任务与执行.md#执行动态观测)。测试、构建等验证由 Worker 按任务需要在执行中自行完成；没有独立的自检步骤、自检记录或结构化失败上报。

| 事项 | 规则 |
| --- | --- |
| 结果是什么 | 只有一份：Worker 的最后一段话。不拼接过程文字，不保存工具记录副本；完整过程在官方执行会话 |
| Result 还存什么 | 要求版本、Run、官方会话引用与结束事实，用于关联和追溯；另有恢复用的小事实：会话水位与哈希、外部效果是否已核实（含待核实的调用编号）、宿主拒绝码。不含工具的输入输出 |
| 没做成 | 正常结束仍记完成。Router 读结果后如实告诉用户，不改任务状态、不自动重派；用户要继续时让 Router 开关联调整任务 |
| 界面 | 详情只有一块“结果”和执行会话入口；列表卡片取结果开头 |
| 外部效果未知 | 如实保留，只约束后续动作能否重放，不建立结束后的第二道审核 |

## 结果保存无阻断

保存路径上没有业务拒绝门。Worker 已产生的结果（含部分内容）先保存到宿主已知的任务，不因内容、要求版本、执行归属、Run/session/fence、官方结束记录、授权变化、任务暂停/停止/完成、待消费输入、幂等冲突或重试次数而拒收；差异如实记录，由系统内部关联，不要求 Worker 重交或用户修正内部编号。

| 规则 | 说明 |
| --- | --- |
| 保存、处理要求、标记完成分别记账 | 迟到、旧要求或已停止执行返回的结果照样保留；不覆盖其他任务或较新结果，不把旧结果当作新要求已完成 |
| 重复提交 | 同键同内容复用已有记录；同键异内容都保留，不抛冲突 |
| 无法关联 | 没有宿主任务可关联时如实返回未保存，不凭模型提供的身份写入其他任务 |
| 物理写入失败 | 如实报告尚未持久化；保留可用的结果与官方日志，启动和运行期间自动补存，适度退避，不设次数或时长截止 |
| 保存不等于授权 | 保存成功不带来新执行、续跑或对外发送权限；不因保存问题重跑 Worker、重放工具、重发外部动作，也不要求用户点继续 |

主编排器负责补存；Watchdog 只负责发现该链路或宿主失活并通知 Router，“已告警”不等于“已恢复”。通知或投递失败不回滚已保存的结果和完成状态。用户的暂停、停止与真实待答、待审批保持各自语义，不阻断已有结果的保存。

## 结果保存与 Router 表达交付

流程：Worker 正常结束 → 保存结果并记 `completed` → 持久完成信号进入所属原 Router 的 inbox → 用户消息优先、当前回合结束后，由普通 Router 回合读取结果 → 公开正文流式回复，沿正常官方 Session 历史保存。外部渠道沿既有普通回复的发送与失败处理交回原来源。

完成信号绑定任务、所属 Router / 来源、要求版本和结果版本；同一任务结果版本只进入一次告知流程。`sa_results` 的 notification 仅保存进度与身份；结果提交事件唤醒原 Router inbox，1 秒恢复检查只作兜底，成功路径不等 30 秒读稿。原持久 inbox 负责去重、用户优先与串行消费。保留必要事件身份、消费状态和官方回合关联，不建立结果专用回复正文副本。

- Router 只表达和交付：自行决定给摘要还是完整内容，没做成就直说；不判定内容能否放行，不重派，不追加验收，不用固定报告、标题前缀或状态文案。用户追问时可读结果直接回答。
- 图片交付沿既有提示链装配：[assignment-executor.mjs](../../plugins/superagent/src/assignment-executor.mjs) 要求 Worker 在最终结果保留真实可访问图片地址及来源；[router-permissions.mjs](../../plugins/superagent/src/router-permissions.mjs) 的 `ui:deliverable-file-references` 系统段指导 Router 用独立 Markdown 图片段直接展示。仅有本地文件或来源网页时说明预览限制，不编造地址，也不将找图转为生图。图片渲染、提示装配及结果表达已有定向测试；真实模型是否稳定保留图片引用仍需端到端验证。
- Worker 结果留在任务详情，Router 回复以 `source.replyMode: conversation` 沿普通 Session / Voice 公开流呈现，最终官方历史原位接管。不生成隐藏 `kind=task-reply` 正式稿，不再二次领取读稿，也不经桌面投递中转；新结果不创建专用 outbox。
- 适配器只转换收发协议，不另存投递状态或关单条件。渠道分工见[链接与渠道](链接与渠道.md)。
- 外部渠道复用普通 direct reply 的来源校验、发送、去重和失败恢复；实际发送返回 `accepted` 后才记录送达，已在普通官方历史中的回复不再镜像一份。回调失败只补事实或外部发送入队，不重调模型；发送状态未知不盲重播。
- 用户通常由 Router 协调，也可在工作台直接向 Worker 或官方子代理发消息。

| 情况 | 任务与执行处理 | 用户可见行为 |
| --- | --- | --- |
| Worker 正常结束 | 结果落库即 completed，持久完成信号进入原 Router inbox | Router 按用户优先顺序自然告知，正文正常流式显示 |
| 原来源确认送达 | 只记送达回执，不再改执行状态；迟到回执不覆盖新要求 | 不要求用户点“验收通过” |
| Router 回复生成失败 | 保留结果与信号的真实失败事实，只重试普通回复；已进入或状态不明的回合先核对官方记录，不盲目重放 | 原会话沿正常失败语义呈现 |
| 回复完成后的回调失败 | 仅补写完成事实或外部发送入队，不重调模型 | 不重复已经形成的正文 |
| 外部渠道发送失败 | 沿普通回复链路保留发送与回执事实，只处理该次发送 | 如实显示发送失败，不重跑 Worker |
| 缺用户信息或许可 | 按问题编号等待，只停受影响部分 | Router 能据已有依据回答就答，否则发具体选项卡 |
| 偶发网络、限流或临时服务故障 | 在原任务保留上下文并退避恢复 | 显示真实恢复状态，不把暂时故障报为无解 |
| 执行报错、超时或失联 | 等待；先核实原执行是否仍在运行，按官方会话记录在原任务续接，不并发启动第二份执行 | 标明真实异常，不因请求超时把整单作废 |
| 外部效果未知 | 核实实际效果与回执，确认前不重跑或重复提交 | 标明待核实，不猜成功或失败 |
| 用户停止 | 立即拦截新动作；执行端确认退出后才记已停止 | 说明后续动作已拦、正在结束执行；逾时未退出单独显示 |

“确认送达”指原逻辑会话已持久接收结果，或原渠道返回可信的发送成功回执；本地排入 outbox 不算送达，也不要求用户已读或听完语音。accepted、sent、设备接收、播放 ACK 和用户已读是不同事实。发送效果未知先查回执，渠道无幂等保证时不承诺绝对只发一次；不能回原来源时保留结果和原因，不改投别处。状态说明由 Router 按真实情况组织，没有硬文案兜底。

普通插话与修订的生效方式见[任务、跟进与目标](任务与执行.md#任务跟进与目标)；原来源回复免审、高危动作逐次审批的规则见[权限与对外审批](任务与执行.md#权限与对外审批)。

## 中断等待与原会话续接

正常结束后没有效果审核，也不自动续跑 Worker。结果保存按[上节](#结果保存无阻断)自动收尾，该阶段属于进行中，不需要用户授权或点击。没有正常结束事实时仍保存已有内容，但不把它当作执行成功。

用户明确要求继续时，复用原任务恢复入口，一次性核对当前授权、执行归属、原 session writer、工具终局和待答交互。这些检查只决定能否发起新的执行动作，不限制已有结果的保存。条件满足时沿官方 resume/followup 在原 Assignment、Run、session 继续，保留冻结模型和已有成果，不重放已完成动作；条件不足时返回具体原因，不换会话重跑。执行侧不变量见[动作边界与恢复](任务与执行.md#动作边界与恢复)。

停止与撤权的动作门立即生效，执行端退出另记：先表达“后续动作已拦、正在结束执行”，超过确认阈值仍未退出时明示执行端未确认退出，不提前报告已停止。

## 外部观察信号与 Router 通报

Watchdog 的机器观察走同一持久 inbox，通知类型为 `watchdog`，来源由认证路由提供。观察正文只作资料，不产生授权，不能冒充真实用户。接收成功只表示已持久记录；排队、抑制、失败和已形成 Router 正式回复分别保留。

- 接收、派发、工具调用和最终发布都读取统一执行事实，核对原 Task、Assignment、Run、session、fence、要求版本与证据水位；合法等待和已失效的观察不通报。
- 同一故障阶段复用稳定通知身份；较新的恢复阶段抑制尚未报告的旧警告。宿主恢复后的摘要只说明接口恢复，不代表所有 Worker 健康。
- 观察回合只能自然回复，不能委派、暂停或续接；用户要继续时走正常恢复入口。
- 尚未进入 Router 的表达失败可沿投递恢复补表达；已进入或状态含糊的回合不自动重放。

监督进程本身见[外部 Watchdog 监督](任务与执行.md#外部-watchdog-监督)。

## 问题逐级回原任务

委派任务中的子代理先向父 Worker 上报，Worker 汇总后交 Router，不直接找用户或另开任务。Router 能根据原始指令、已存记录和确定依据回答的直接答；不能确定或必须用户拍板时才在原来源发选项卡。回答绑定真实问题编号、任务、来源和请求人，回原任务续做。Router 不直接调用官方 subagents，执行拆分由 Worker 负责；角色工具范围见[自有会话角色装配](模型与上下文.md#自有会话角色装配)。

- 只暂停依赖该答案的部分；其余独立、仍在授权内的工作继续。未知事实、权限、外部提交和范围扩展不能靠默认选项推断同意。
- 问题、动作审批与安全输入是三种协议：卡片答复不能由模型生成或用正文关键词冒充；缺密码走[保险库安全输入](链接与渠道.md#保险库与安全输入)；问题答案不能代替动作批准。
- 过期、重复、来源不符或指向其他任务的回答拒绝；尚未被原 Worker 消费的回答不显示为已续做。

## 证据与追溯

官方会话日志是实际执行过程的唯一原件；Result 只保存结果及其关联，按权限从原执行会话有界补读。推理、秘密和不适合公开的工具输出不进入结果。

自我迭代按统一增量来源读取真实对话、纠正和执行证据，不以“闭单且已送达”限制全部材料。完成、结果版本、来源与可信送达回执用于界定执行成功经验；失败、等待、未送达和未知效果保留各自语义，不提炼成已经做成的经验。后台整理不审核当前任务能否交付，也不是交付前置，见[记忆与技能](记忆与技能.md#增量来源与触发)。开发时的软件测试、真实渠道验证和用户对产品的验收与本文无关，照常保留。

## 实现与验收边界

**已有源码接线**

- 三态与 `executionControl`；正常结束即完成；结果只保留 Worker 最后一段话。
- 保存无业务拒绝门，原稿、生命周期和通知分别收尾，自动补存不设次数截止。
- Watchdog 信号经持久 inbox 交 Router；问答卡绑定原问题并幂等回原任务。

**本轮已有源码接线与定向验证**

- 结果完成信号通过提交事件直接唤醒原 Router inbox，1 秒恢复检查兜底；复用普通公开正文、官方 Session / Voice 历史与外部 direct reply。已删除 `prepareTaskReply`、`saveOutboxReply`、`resultDelivery` 旧接口及结果专用稿件、二次领取和桌面中转执行路径。
- 同任务结果版本幂等、用户优先、不打断当前回合、来源绑定、重启后的回调恢复、回复失败只恢复告知及回调失败不重调模型已有定向验证。状态提醒继续通过自身持久信号进入 Router，不另建结果执行轨道。
- 历史记录保持可读。确定未外发的旧 queued 及过期 claimed 通知迁入当前路径；旧隐藏稿仅在确定未发时一次进入普通回复，已送达或外发效果未知不盲重播，不保留旧发送执行器。
- 客户端 34 项单测、8 项真实 headless 渲染检查，以及公共 Chat / Voice、engine、runtime / store、direct reply、学习及 Link 定向测试通过；渲染检查覆盖空、加载、错误、有数据四态、明暗宽窄和流式历史接管。构建、安装运行和真实外部渠道不据此视为已验收。

**待实施**

- 数据库完全不可写且进程立即退出时，只存在于官方会话日志中的结果尚不能全部自动发现和补存，不承诺零丢失。
- 官方动作审批目前主要投影为待批交互，尚未全部写入 Task 的业务 `waiting`。
- Router 侧请求与结束钩子的错误首因记录仍在整合。

**待验证（安装版）**

- 主路径：委派、执行、完成、原 Router inbox 唤醒、公开正文流式显示和刷新后官方历史一致，以及运行中重启恢复；新用户消息优先，不打断当前回合，同任务结果版本不重复告知。
- 没做成的结果由 Router 如实说明，任务保持完成，经 Router 开关联调整任务。
- 异常结束、提问后原任务续跑、暂停与人工继续、停止的动作门与执行端退出确认、未知外部效果不重发。
- 存储故障：真实磁盘耗尽、断电、官方日志与数据库同时不可写、Watchdog 监督收尾。
- 表达须保留创建任务确认、中途通报、完成交付三处 Router 原文，确认都在讲用户的事情；界面核对空、加载、错误、有数据四态，视觉由用户最终验收。
