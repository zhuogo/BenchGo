## 设计与边界

只给 Router 引擎注册内置层，不把 Router 开局包传给 Worker 或子代理。沿用现有内联功能接线规则，不在本项擅自改定稿正文。冻结上下文保留原始文档供遗忘与追溯，模型收到的文档和结构化记忆在最后投影时去除 HTML 注释元数据，接口由记忆模块统一提供。

无新增 MCP/OpenAPI 参数；三角色配置及跨渠道接口由各专题统一约定后接线。官方 composer 无已确认公开提交接缝，本项不作替换或私有补丁。

### 接管增补

- 记忆模块统一导出 `cleanMemoryContext(context)`：在 Engine 的 `agent/pre-step` 中冻结原始上下文后创建干净投影，文档、身份、用户资料及结构化记忆（含来源摘录）均从该投影取值。原快照不改写，普通编辑仍需新会话加载，遗忘仍走已有实时清除链路。
- 旧会话已有 runtime-context 在 `context-privacy.mjs` 中复用同一清洗接口，通过官方 session surface replacement 隐去注释，原始事件与其他插件 section 保留。重启首次检查，后续沿用遗忘 revision 的扫描优化。
- 三角色契约保留 `config.models` 为 Router 队列；`workerModels` 仅作用于 Worker，缺省继承 Router。Engine 无需另造 Router 配置或改写模型 ID。
- 第 18 项安全审阅：当前 `message-inbox` 与 `agent/pre-step` 将用户消息记为 `desktop-owner`，工具闭包及持久授权记录也依赖桌面身份；main 还持有私人冻结记忆。仅给 `engine.send` 加来源字段无法隔离权限与上下文。外部私聊并入 main 暂不接通，需先统一持久来源、工具授权、私密上下文及原渠道回投契约，不能把外部消息默认为桌面所有者。

### Router 公开入口兼容修复（已实现）

- 复用 `message-inbox` 的 `beforeDispatch`：在 `followup` 前读取并复制当前 Router 队列，以官方 `agent.model.select()` 选择首项；`agent/pre-step` 只接收已准备的本条消息队列，配置修改不会改变当前工具循环。未复制或改写模型 ID，Worker 和辅助队列不参与此选择。
- `recoverMain` 的宿主续接通知也在 `followup` 前准备队列，以已记录模型和 reasoning effort 为首项，并保留原请求输出上限；随后新的入箱消息重新选择当前配置首项。已完成回合与未知外部效果仍不自动重放。
- 官方 composer 直接提交可绕过本项目 inbox。当前没有已确认的公开 pre-followup 接缝，本次不宣称覆盖该入口的首模型复位，也不替换其提交实现。
