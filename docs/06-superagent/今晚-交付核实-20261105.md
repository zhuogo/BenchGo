# 2026-11-05 晚：交付核实与集成

## Mandate

仅输送层能证明未发出的请求可自动重新排队；网络超时、无确定回执、部分分片已成功都保持 uncertain。主人核实操作携带当前 attempts、结论与证据；结果未知不重投，确认已发须有确定消息回执，确认未发才回队列。核实不能重新执行 Worker，不能改变原工单结果。已有成功分片时禁止整条重投。

## 实现契约

- 复用现有 outbox/receipt 表，增加 `reconcileOutbox(id, { attempts, outcome, evidence, receipt? })`，结论为 `sent | not_sent | unknown`。证据 1–2000 字符，attempts 为正整数。
- 宿主认证 owner 才能调用核实 API；不开放模型工具自动宣称核实。
- 用 attempts 与 uncertain 状态防陈旧核实覆盖新一轮发送；在同库独立核实表保留审计，投递 payload 保持不变以保护幂等，部分分片回执不丢弃。
- 默认 Worker 选择不冻结为 Router，验收优先使用 Router 角色模型；未配置 Router 的既有桌面显式模型用法，兼容使用显式执行模型验收。

## 固定验收

定向验证明确未发重排、未知不自动重排、确认已发保留回执、不确定仍等待、陈旧 attempts 拒绝、有成功分片拒绝整条重投、关闭重开后核实记录保留。服务认证及 OpenAPI 与实现一致。模拟输送测试不算真实渠道发送验收。
