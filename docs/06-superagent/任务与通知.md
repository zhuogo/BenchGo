## 1. 入口、配置与用户路径

飞书接入配置放在 **资源 → 接入 → 多平台**，不是另开独立设置应用。入口提供飞书连接的启停、配置、实际连接状态、失败原因与重试；敏感凭据通过安全录入和引用保存，不在聊天或日志回显。已配置不等于可用，连接状态以实际认证、订阅和发送能力为准。

路径：资源 → 接入 → 多平台 → 配置飞书 → 验证连接/事件接收/发送范围 → 群内 @ BenchGo → 自动受理与执行 → 原对话提问或交付。群、话题、消息、发送人和机器人身份取飞书实际元数据，身份不能由模型声明；主人身份在可信配置中绑定。群聊其他发言不是主人授权。

桌面主聊天仍是本体入口，直接输入全文到 Router；资源中的任务入口可查工单、证据、来源和控制。默认不展示流水日志；正常聊天、派工回应、失败原因及必要阻塞说明由 Router 自然表达，重复后台状态去重。注意力面板具体形态未定，不阻挡原来源提问闭环。

当前桌面复用官方 composer，经公开适配进入持久 `send`；`requestState` 与 `history.requests` 供收件对账，`processed` 只表示 Router 回合结束。文本和可解析引用已接；附件提示限制并保留草稿。取消同时处理当前 Router 与排队请求，`/clear` 不撤销后台工单，清空后的管理沿逻辑 thread/sessionLineage 验证归属。普通 text 与 assistant_reply 通过官方实时流显示，持久终答替换暂存正文；推理和工具参数不发布。真实桌面重启和用户路径仍需验收。

首轮不接微信、邮箱、日程或多设备部署，不因此删掉统一来源协议。飞书机器人权限、群范围、回调/长连接的具体接入方式在实施时依官方能力选择；优先复用现成渠道插件/服务，不复制渠道 SDK、消息队列或消息协议。

## 2. 统一事件与分流

| 路径 | 处理 | 不能跳过 |
| --- | --- | --- |
| 主人一对一 | 无损结构化封装，explicit，跳过是否接单的 Eval | 来源认证、Trigger 留痕、幂等、授权、该建单时建单 |
| 飞书群聊新事项 | 按量窗口 → Trigger → Gate → Candidate → Eval | @ 准入、policy 依据、代码复核 |
| 已订阅线程后续消息 | Trigger → 订阅上下文入箱 → 原 Worker | 来源标识、去重、范围检查；不是新授权 |
| 定时/系统事件 | 合成 Trigger，按已配置 explicit 规则 | 事件身份、规则启用状态与副作用核实 |
| 非主人一对一 | 身份与信任细则尚未定版 | 未确认前不可当作主人直通 |

所有来源的 Trigger 不可变，按渠道事件稳定键去重；重试回调不产生第二次执行。编辑、撤回等独立事件保留关系而非覆盖历史。外部内容与转述不冒充用户指令。

群聊窗口化是确定性裁剪与编号，不先调用模型总结：线程头 5 条、Trigger 前后各 5 条作为初始口径，正文限长时标全长及原文指针，其余给存根；迟到上下文作为新输入补齐，不改不可变 Trigger。个体入口不做 Inline & Spill；长期会话上下文管理另见记忆专题。

Gate 只决定新事项准入：人类消息被实际 @ 才可成为候选，名单与强度同时裁决；未 @ 只记录。名单内机器来源走独立机器门，一律 inferred，不能因伪造 @ 升级为 explicit。系统定时事件不伪装成人类消息。

## 3. Eval 与 Decision

同 Thread 最多一个 Eval 批次，先排除已归工单持有的 follow-up 和已开单 Trigger；候选携带原文卡、窗口、线程工单、准入依据与 policy 版本。

跨 Thread 的 Eval 独立推进，不等待其他线程的模型请求完成；同线程仍保持单批次、顺序与现有批量上限。重复调度复用该线程在途请求，新到独立线程可立即启动，不增加全局并发限流。单线程失败不阻挡其他线程提交，停止服务时取消全部在途研判，并阻止迟到结果落单。

Router 只读研判给出接单/挂靠/停单/忽略。代码复核身份、版本、范围与权限，inferred 接单须 auto 模式且引用规则全部启用；否则拒绝并记 notExplicit。无具体意图或仅讨论时静默忽略。

Eval 带 deadline，超时最多重排 2 次，再超时置 unavailable，保留人工重评/忽略入口；排队与已投递研判分开计时，不因 Worker 容量不足消耗模型超时次数。policy 变化使在跑 Eval 失效并重评，旧模型响应不得落单。

Decision 持久保存建议、代码复核、命中规则、去向及原因。主人直通不假装经过一轮 AI 准入裁决，直接记录 explicit 来源与分诊结果。

## 4. Ticket、授权书与分配

用户可见阶段：开单 → 已分派 → 执行中 → 待确认 → 关闭。业务工单、执行尝试、等待原因和交付状态分开记录，不能把模型停笔、执行器 idle 或连接关闭当成完成。

| 记录 | 职责 |
| --- | --- |
| Ticket | 标题（开单生成）、活摘要（随进展更新）、目标、验收、来源 Trigger 集合、授权书、版本和生命周期 |
| Mandate | 开单时不可变：policy 版本、授权范围、强度、命中规则；当前规则可否决旧授权 |
| Assignment | Router 落册的执行类型、优先级、任务包及调度决定 |
| Run | 每次实际执行的会话、工作区、租约、检查点、尝试与结果 |
| Disposition | 每个 Trigger 的评估、持有、挂靠、退回及处理结果 |
| Subscription | Thread ↔ Ticket 多对多、消息游标、未读/已处理、持有与释放 |

当前独立标题统一为最多 10 个 Unicode 字符，存量回退、查询、通知与 UI 复用同一 helper；完整目标/验收条件不截断，改名不递增任务要求版本。活摘要维护、新建前语义查重、同 Trigger 唯一单与合并是 P1 待实施目标，不因短标题落地宣称完成。

Router 决策写回 Assignment，机械调度器提交后凭记录领活。领单、容量、资源锁与幂等是代码职责，不要求 Router 在线等投递结果。Worker 一单一执行者、无永久身份；“派给谁”指执行能力与临时实例，不建额外人格队伍。

待确认区分 Router 验收与等待用户决定；由 Router 根据验收标准核销，不沿用旧实现“一律人工点通过”。审批红线仍先过人，不以自动验收绕过审批。此阶段在交付之前：不设「已交付待确认」，交付后调整见 §7 末条。

关闭带原因（验收完成、停止、失败等）。交付后用户一句话反馈，不重开原单：新开关联调整单（链回原单、只写差异、Router 凭原单与结果包恢复上下文），原单记录不覆盖；新单须取得有效新授权记录，旧 Mandate 不原地改写、已撤销授权不随单复活。未交付前的补充与纠正走修订（§5），不另开单。

## 5. 订阅与忙时补充

已绑定线程的后续消息直接进入相应工单上下文，不再重复送 Router 做接单研判；即使未 @ 也能提供上下文，但不能凭此新建工单或扩大权限。同一线程可以关联多个工单，各自有处理游标与归属，不能任意广播为所有工单的新命令。

同线程消息入账、评估和同一执行上下文写入串行。确需同线程并行任务由显式要求和 Router 分工登记，隔离执行，不并发写同一会话；资源冲突另由锁处理。

忙时先持久收件，返回“已收到/待应用”；安全动作边界确认后才标“已应用”。新要求改变目标/验收时递增 instructionRevision，旧版本结果不能自动核销新版要求。

Worker 越界时 handback，每工单每 Trigger 最多一次；保存退回原因、解除对应持有，再回评估，不能在两个 Worker 间无限踢转。多工单持有的输入在所有权释放前不重复接单。关闭订阅须明确未处理消息去向，不能静默丢弃。

## 6. Worker 池与动作边界

三重隔离：独立上下文、独立工作环境、状态外置。任务包包括 Inline 卡、原文指针、验收标准和授权范围。仅开新会话不等于环境隔离；代码工作优先用独立 worktree/工作目录，不能并行修改同一用户工作树。目录隔离不等于 OS 安全沙箱。

并行架构不设固定天花板，运行上限由设置控制，并受模型供给、设备、资源锁和验收带宽约束。Router 只用协调类工具（查工单与状态、定时、配置、记忆记账）；一切环境操作——包括只读的查网站、查文件——一律开工单下放（2026-11-04 口径，取代旧「小而确定可直做」）。所有持久副作用必须工单留痕。

每个受控动作前读取磁盘现行规则并复验：当前 policy、Mandate、审批与工单版本。收紧立即阻止未执行动作，运行 Worker 在下个动作边界停下来；规则不可读或许可不明则 fail-closed。已提交外部请求不能靠回滚假称撤销。

写文件/危险命令前建立检查点（影子 Git），恢复须保留用户后续改动；外部发送、付款等不可逆效果不能回滚。检查点不是审批替代品。

## 7. 提问、验收与交付

Worker 提问生成结构化 Attention，问题原样送到当初提问人写消息的原处，保留 questionId、原文和具体 Trigger/message 引用；不能只用最初群 ID 猜收件人。用户原地回复回到同一工单，由订阅续行，不重复开单。Attention 不是进度汇报。

Worker 结果包含正文成果、做了什么、证据及未尽事项；产物文件按本单目标需要提供。Router 按当前目标版本验收，不能自行增加“必须生成文件”的条件。纯文本/新闻/查询任务以正文、实际抓取的来源与时间及证据引用交付，`artifactRefs=[]` 或 checkpoint 无文件不构成失败。文件/代码/UI 等成果才检查对应产物及适用的检查点；UI 按要求提供 Before + After，用户明确免除时记录限制，不伪造图片。完整规则见[任务结果验收矩阵](任务结果验收矩阵.md)。

验收未通过时先区分原因：可修复失败由 Router 在原来源自然说明并自动续做原工单、原会话及原成果；真正缺用户信息、权限或范围决定时创建绑定版本与来源的 Attention，告知等待原因，用户回答后原单继续。内部证据读取或模型故障属于待核验，由系统补证/重试，不向用户提出“是否修正证据”的选择题。固定修正次数耗尽不能单独终止仍可恢复的工单。

本轮已实现上述 `failed/rework` 原成果续做与 AI 说明，不再限制“两轮非项目只读修正”；代码仍复核当前授权、版本、原执行与 fence。桌面/飞书 Review Attention 问题和真实答案持久绑定原单/来源/版本，答案写原分派续做；Worker 原生提问保留独立调用语义。内部 `review_wait` 不创建让用户判断事实的问题；无进展/额度不足使用资源等待。其他渠道关联与续做仍属 P1，真实返工和阻塞闭环未验收通过。

资源等待恢复使用 `ticketResume(ticketId, expectedResultVersion, additionalExecutionMs?)`：新增时长为安全整数 0..600000、缺省 0，执行额度耗尽必须显式给正数，不自动加时。原执行停止、效果、官方 session writer、checkpoint/transcript、版本、权限和 Goal 预算未核实时保留等待，`queued:false` 不表示恢复成功；效果未知不重放。首轮 Worker deadline 等待分支已补代码并有定向覆盖；真实新闻失败历史保留，首轮无 Result 的恢复仍需另跑验证，见[P0 验收记录](P0验收记录.md)。

验收通过与交付成功分开：结果/验收/状态/唯一事件/outbox 同事务提交，提交后回来源线程。发送失败只补投结果，不重跑工作；未知发送结果先查渠道回执，不能盲重发。无法回原消息时保留结果与明确失败状态，不静默投给别处。

分级交付：后台无新情况不重复报告；有结果给结论 + 证据；需要人拍板才摆问题。明确任务的失败、返工和阻塞由 AI 自然说明原因与下一步，不使用固定报告模板，不因没有文件静默。详情保留工具日志和公开证据，不显示模型私有思维。飞书、桌面引用同一份结果，不生成各自可改写的结果权威。

主聊天中的交付正文按普通助手消息显示，不使用独立「交付通知」卡片、分类标题或「标记已读」按钮；必要问题与选项随正文保留。持久通知仍记录原来源、工单版本、去重和投递状态，属于交付账本，不要求用户逐条确认阅读；外部渠道回执与审批授权语义不变。

交付后的调整：用户指出交付结果不对，新开关联调整单处理（见 §4），不在原单上重开或改写；新单只写差异，沿用原单成果与证据，独立验收、独立交付。

## 8. Watchdog、重启与定时

Watchdog 对 Worker 可处理卡死、超时与异常；对活 Router 不纠偏、不改派；对确认失活 Router 只恢复存续，由新 Router 读工单、账本、文档自主续上。

调度心跳、Worker 租约/作业心跳、请求 deadline、工单 deadline 分开：心跳新鲜只证明进程活着，不证明模型请求完成；合法异步等待不算 Router 卡死。工单久挂或 Eval 超时进入既定升级流程，不由 Watchdog 替 Router 决策。

重启先取得单机数据根调度所有权，核对旧会话写入者、执行进程、worktree 和外部回执；租约过期取得核实权，不代表副作用可重放。确认旧执行已停、授权仍有效才续行；未知效果转待核实。不承诺任意进程杀死均零损失。

时间规则与触发复用 Harness Schedule。Schedule 到期形成合成 Trigger，进 SuperAgent 编排；会话 follow-up 入队不是任务完成。业务心跳/重试计时不另建 Cron 体系。

## 9. 首轮验收

- [ ] 桌面主人直聊留痕、跳接单 Eval；仅依已有上下文的简单回答不强制开单，网页/文件调查与执行均走工单，并完成持久消息回执的桌面接入。
- [ ] 飞书真实群消息：未 @ 不新开工单，@ 后候选/研判/复核/开单全链可查；回调重送不重复。
- [ ] 同 Thread 单 Eval、超时 2 次重排及 unavailable；policy 变更后旧响应不能落单。
- [ ] Router 只写分配，Worker 机械领取；独立工单隔离并行，同会话/共享写资源不竞争。
- [ ] 已订阅线程未 @ 续问直达、忙时收件、应用确认、越界 handback 一次、停单未读不丢。
- [ ] 纯文本任务无文件可验收交付；可修复失败说明后自动原单续做；真实阻塞原来源提问、回答续行；内部待核验可恢复，交付失败只补投。
- [ ] 中途收紧红线/撤权在动作边界生效；普通记忆仍冻结；审批与保险库不泄露明文。
- [ ] 重启后不重复派活/发送；确认失活 Router 自动恢复，未知副作用先核实。
