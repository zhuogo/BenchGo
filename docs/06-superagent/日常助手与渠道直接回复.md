# 日常助手与渠道直接回复

2026-11-05 校对：目标以[全链路架构](全链路架构.html)和[任务结果验收矩阵](任务结果验收矩阵.md)为准。P0 已替换“两轮非项目只读返工”旧分支，失败自然说明后沿原单/原会话/原成果继续；桌面/飞书真实阻塞绑定 Attention，纯文本成果不强制文件。代码与定向验证不等于真实闭环通过；新闻首轮失败和待复测项见[P0 验收记录](P0验收记录.md)。

## 设计

BenchGo 首先是日常全能助手。搜索、写作、整理和文件处理均为有效委派，不要求项目归属或用户预先书写验收标准。仅仓库操作需要项目绑定。普通细节可合理补齐，关键歧义需要澄清。不开设高级提示词编辑页面。

参照 `reference/dsh-superagent-prototype` 的 `6337fc823ce20251c8de8085948165c81aaa701e`：明确请求与主动候选分别处理；`orchestrator_reply` 允许无工单回答；Worker 从原请求负责执行。该原型的仓库定位不作为 BenchGo 的日常请求限制。

## 路由与权限

- 明确指向助手的人类消息：可 `answer`（问候、无需工具的回答）或 `ask`（关键澄清），无需创建工单；需要搜索、当前信息、执行或副作用时 `accept` 交 Worker。
- 未指向助手的群讨论、自动化来源：不得通过 `answer/ask` 主动发言；继续使用现有规则与准入门禁。
- 既有工单的事实追问仍走 Worker，直接回答不得编造执行状态或结果。
- `answer/ask` 只接受非空、有界文本，绑定原 trigger、当前策略版本与来源；模型不得指定收件人。所有来源身份及渠道范围在提交、发送前由代码复核。
- 明确的简单委派不能因缺少项目或正式验收标准被忽略；拒绝或能力限制应向明确请求者解释。Router 记录范围内的结果要求，不扩张用户需求。

## 持久交付

飞书迟到消息保护：同一应用、群/私聊及同一人类发送人，若已有比该消息更新超过五分钟的消息，迟到消息只作为历史记录，不新建候选、不答 attention、不送入活动工单。五分钟容忍正常乱序；按原始消息时间而非本地入库序号比较，水位复用持久触发记录，重启仍有效。直接回复发送前再检查，过时回复标记 suppressed；不撤回已发消息，不影响工单最终结果交付。不同发送人、群和应用互不影响。

直接回复与候选处置同事务保存，以候选唯一键去重。使用独立、无工单外键的直接回复队列，复用既有渠道传输，不伪造工单。状态区分 queued/claimed/sent/suppressed/uncertain；过期发送租约为 uncertain，避免自动重复发送。只对确定未发出的失败重试，发送前策略失效则 suppressed。队列随运行时启动/停止；保留回执及诊断，不向聊天推执行过程。

已认证的主人接口 `connectionReplies` 可按 channel/threadId 查询最近直接回复及回执；API Service 等拉取式渠道使用它获取无需工单的答案。主聊天的模型工具仍只读取本会话工单，不增加可跨渠道窥视的 MCP 工具。

研判上下文按来源线程附带最近已确认发送的直接回复，最多六条、每条两千字符；用于理解澄清后的用户答复。未确认发送的内容不伪装成用户已看到的对话。

## 验证

### 内部修正（P0 代码已接，真实闭环待验收）

验收先读取已有证据，不能将截断当作缺失。可修复的 `failed/rework` 须给出 AI 自然说明和明确修正指令，提交后恢复原 Ticket/Assignment/Run/session/工作区；不创建新修正分派或以“两轮耗尽”终单。完整 taskContract 以本单目标、验收与原要求为准，最终修正正文优先于历史草稿。无进展或资源不足进入可恢复等待，不要求用户确认已授权的补查；停止、撤权和版本门始终优先。

真正需要用户提供权限、信息或决定范围时才进入 blocked Attention。桌面/飞书 Review Attention 绑定原问题、版本与来源，真实答案写入原分派；内部模型/证据问题使用 review_wait 退避核验，无进展使用 continuation_wait，不冒充用户问题。此项属于 BenchGo 的验收扩展，不声称 DSH 原型具备独立模型验收。没有合法 AI 正文时显示明确系统身份的状态，不伪装固定助手报告；不保证基础设施必然自动恢复。

原会话/目录成果和真实 Git worktree 续做已有官方 Harness 定向记录，原产物、checkpoint 与源目录用户未提交变更保留。续做不再靠一份固定只读工具白名单替代原授权；执行仍逐动作复核权限、审批、原结果/指令版本、run/session、transcript、checkpoint 与 fence。未知外部效果先核实，不因失败重放发送、交易或其他已发生动作；新副作用仍须符合现有授权门。

续做恢复经 `ticketResume`，须匹配 expectedResultVersion；停止未确认或效果未知回 queued:false 并保留等待。2026-11-06 决策：预算闸门整体拆除，执行时长补时与 Goal 预算移除。真实新闻首轮 10 分钟 deadline 后无交付失败为历史记录；项目/文本真实返工也未据定向测试宣布通过。

真实搜索发现验收输入截断与日期缺失：独立验收不得将省略的工具记录视为不存在，不得用模型知识截止日期判断系统当天。验收输入注入可信当前时间、时区及工单时间；保留工具结果有界索引，通过原会话、run 身份及 transcript hash 校验后分页补证。系统读取故障属于待核验；缺实际抓取但原授权可补查时自动续做，禁止把系统补证或确定日期转成用户拍板问题。任务允许说明渠道缺失时，部分站点无法访问不自动阻塞其他已验证结果的交付。旧结果修复须经版本校验和显式恢复流程，不自动重放已发生的外部效果。

覆盖问候直接答、日常搜索接单、关键歧义提问、无项目请求、未提及群聊静默、机器与越权拒绝、旧策略拒绝、重复事件去重、重启恢复及不确定发送。更新受影响协议说明。真实渠道验证与模型验证分别记录，不回放用户旧消息。
