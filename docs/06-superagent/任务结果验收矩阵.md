# SuperAgent：任务结果验收矩阵

校对日期：2026-11-05。本文是《全链路架构》和《设计》的实施补充，专门规定结果包、验收状态和用户可见的后续动作。它不以当前源码的缺口降低目标路线。

## 一、通用不变量

验收只核对本单的目标、验收条件、授权和真实执行证据。`artifactRefs`、checkpoint 文件数和工作区产物不是所有任务的通用通过条件。

纯文本或信息检索任务可以在没有文件产物的情况下完成。新闻摘要、资料调研、解释说明等任务的成果是可读正文；来源、发布时间或抓取时间、覆盖范围、访问限制和可追溯证据是验收依据。`artifactRefs=[]` 或 checkpoint 中有 0 个文件，不构成失败。

文件、代码、UI、图片或其他媒体只有在任务目标要求相应成果时，才核对对应产物及适用的检查/检查点；用户不必自行填写正式验收规范。checkpoint 是文件状态与恢复证据，不等于成果质量，也不要求所有文件任务新增文件或非空变更。外部副作用任务必须核对调用回执和效果状态；仅有进程退出或 Worker 自述成功不能证明效果已发生。未知效果进入待核实，不盲目重放。

## 二、任务类型矩阵

| 任务类型 | 通过条件 | 不应作为失败理由 |
| --- | --- | --- |
| 纯文本 / 新闻 / 查询 | 正文满足目标；需要联网核实的任务附来源与时间、覆盖范围、限制说明及工具证据引用 | 没有 `artifactRefs`；checkpoint 无文件 |
| 文件 / 代码 / UI / 图片 | 任务要求的文件或变更存在，内容与目标一致，工具证据可追溯；UI 按要求提供 Before / After，或记录用户明确免除 | 没有额外要求的文件；无关的附加产物缺失 |
| 混合成果 | 文本部分和文件部分分别满足各自条件 | 某一类没有被任务要求的证据 |
| 外部副作用 | 目标、调用回执和效果状态可核实；不可逆效果保留来源与时间；仅凭模型声称完成或进程退出不足以证明成功 | 没有目标未要求的文件产物 |

## 三、验收分支与工单状态

验收模型的本轮 `failed` 表示当前结果没有通过，不直接等于 Ticket 终态。下表是目标行为分类，`blocked`、`review_wait` 是等待原因的区分，不宣称当前 API 已新增这些枚举；优先在现有结果、Attention、等待原因及版本字段中表达，不另建状态系统。Router 应按原因选择以下分支：

| 分支 | 工单处理 | 用户可见行为 |
| --- | --- | --- |
| `passed` | 结果提交为完成，Ticket 进入 `completed` | Router 生成自然交付正文并回原来源 |
| `rework` / 可修复的本轮 `failed` | 保持原 Ticket 和原成果，核实并恢复原 Assignment / Run / session / 工作区，追加修正指令，自动续做后重新验收 | 首次发现需要返工时由 Router 自然说明原因和接下来的处理；重复同类状态去重，不要求用户确认继续 |
| `blocked` | Ticket 保持打开或等待，创建与工单、结果版本、指令版本和原来源绑定的 Attention | Router 在原来源说明缺少的信息、权限或范围决定；用户回答后恢复原单续做 |
| `review_wait` | 结果保留 `waiting`，内部补证或重试验收，不重跑已产生副作用 | Router 说明核验尚未完成及系统将如何恢复；模型不可用时显示明确标注的系统状态，不伪装 AI 回复，不要求用户替系统判断证据 |
| 工单终态 `failed` / `stopped` | 仅在确认不可继续、授权撤回或用户停止等情形结束工单；本轮结果失败、固定次数耗尽均不能单独触发 | Router 说明原因、已保留的结果和可用的后续入口；正文由 AI 组织，不使用固定失败话术 |

预算、期限或自动修正次数是防止无界循环的控制条件，不应把仍可恢复的任务强行变成终态。自动额度耗尽但可恢复时保留等待状态；需要调额或改变范围才向用户提出具体问题。停止、撤权、新版本和未知外部效果优先于自动续做，不允许绕过门禁。

原因说明、续做/等待意图与 outbox 必须可靠持久化并去重，不因通知失败重跑任务。对一个明确请求，完成交付和失败/阻塞沟通都回原来源；“只交付通过验收的成果”不意味着验收未通过就静默。系统能自行修正时不能把“是否修正”转给用户；也不能把任意下一条消息当成答案，回答必须绑定真实问题和工单版本。

## 五、新闻摘要示例的正确处置

用户要求 6–10 条而结果给出 14 条，是明确的条数不符，应原单压缩修正。部分“多源”条目只展示一个链接，需读取实际抓取记录核实：有多个网站转同一稿不等于独立多源；证据不足则补查或改标“单一来源/待确认”。正文写了“多源”不等于已经验证，也不能仅凭链接数量断言抓取从未发生。

示例报告搜索 API 余额不足、Reuters 返回 401 等限制；若实际日志证实这些情况，且已有来源和抓取证据足以完成目标，就应在摘要中如实说明缺失并交付；不能因为缺少某一渠道或没有文件产物而阻塞。“已验证”须由证据支持，单一来源可按用户要求如实标注后纳入摘要。

内部模型、证据读取或基础设施暂不可用时进入 `review_wait`；可恢复的预算、期限等资源限制保留等待/升级路径。只有需要用户提供信息、权限或决定范围时，才建立 `blocked` 与 Attention；必须有可回答的原来源入口，不能只显示“待确认”而让用户猜下一步。

示例分析仅依据用户提供的记录，未读取该历史 Run 的完整原始日志或逐条重新核实新闻，不能据此宣布这份摘要内容均真实或应直接通过。P0 本地夹具验证与真实新闻调研验收分开记录；完整任务通过后才标记完成，可用的部分结果可明确标注范围后沟通，不冒充整单完成。
