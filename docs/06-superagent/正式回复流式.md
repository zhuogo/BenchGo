# 正式回复流式

主聊与旁聊复用官方实时会话投影，展示 Router 的用户可见 `text` 增量。Router 提示明确约定：普通 `text` 是面向用户的正文或进度，不能用于内部思考；推理块、工具参数、工具结果和 Worker 原始输出保持隔离。流式暂存内容不等于任务完成或持久正式交付。

优先读取官方 chat projection 的顶层 `assistant_reply` `runningCalls` 与 `PartialArguments.text`；未使用该工具时，直接读取官方 `partial.blocks` 中的 `kind=text`，不再等待完整回合结束。两条路径共用同一个 `reply:<requestId>` 身份，正式发布优先替换先前可见进度，避免重复气泡。

后端 history 提供当前未结束、含真实用户消息的 turn/request 身份；前端核对会话、turn 与 request 后展示暂存正文。history 刷新稍慢时，仅允许官方已接收的用户节点与持久消息/回执按 `seq/rpcId` 关联恢复身份，不能把排队尚未接收、另一会话、已结束 turn 或嵌套调用的内容串入当前回复。

显式发布工具执行成功后的 publication 是持久交付；成功工具回执可桥接 history 刷新间隔，使用同一 `reply:<requestId>` 身份替换暂存内容。普通终答由下述 completed 历史投影持久交付。取消、失败、切换会话清除未提交正文。已提交回复不因随后停止而消失。

普通终答在生成时实时展示，成功 completed 后仍由后端历史投影保存并替换暂存正文；取消或失败清除未提交正文，不能残留成完成答复。`assistant_reply` 仍支持明确发布并结束回合，不把模型是否选择该工具当成流式前提。后台 Worker 仍必须经 Router 验收，不改变订阅直通与验收权限。

实现范围：工作台主聊、旁聊。渠道保持既有发送协议，本次不新增渠道流式接口。history 新增可选 `activeReply`（requestId、turn）；不产生新的 API 动作。

状态（2026-11-05）：代码存在；`reply-stream.test.mjs` 与 `engine-stream.test.mjs` 10/10，流式/发布联合批次 22/22，通过真实 Harness 可控适配器覆盖 start/chunk/end、正文增长、推理隔离、取消清除及刷新延迟关联，两批重叠不相加。另有真实 `routergo / deepseek-v4.1-flash` 经官方 loader 的普通 Router 流式通过：55 次文字增长，首段比 committed end 早 2.103 秒，持久终答 325 字符，普通聊天未建票。证据见[router-stream-evidence.json](../../eval/superagent-p0-20261105/real-router-stream-01/router-stream-evidence.json)和[P0 验收记录](P0验收记录.md)。用户明确免 GUI 截图/视觉校验，未宣称用户视觉验收；这也不能证明新闻交付、返工或阻塞已打通。
