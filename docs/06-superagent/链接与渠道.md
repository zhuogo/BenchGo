# SuperAgent 链接与渠道

本文是渠道适配器定位、来源标注与映射、统一会话路径的权威正文，并维护渠道配置和凭据。统一管线的准入与研判规则见[入口与研判](入口与研判.md)，问题和结果投递见[自校验与交付](自校验与交付.md)。源码实现与真实平台验收分别在文末说明。

## 渠道适配器与统一机制

渠道只能是适配器，接入新渠道只新增协议与来源映射适配，不改 Router、工单、执行会话或投递核心机制。适配器承担以下职责；高噪音研判的入口调整为目标设计，当前实现差异见文末：

1. 协议收发转换：处理平台认证、验签、协议连接、收发与平台回执转换；协议验签不代替业务授权。
2. 渠道账号与 BenchGo 身份映射：提供可信的发送者、来源形态及会话/话题标识等事实证据；不自行决定主人资格、聊天范围或工单权限。
3. 消息归一：将消息及附件转换为统一格式，保留来源事实与原文指针。
4. 能力声明：声明实际支持的文本、图片、卡片、回执等能力，供统一会话与投递机制使用；声明自身可提供的高危类别、结构化专用通道及最终内容预览/执行回执，交核心注册表统一校验，不自行授权。未支持的能力明确提示；字段契约见[服务契约](服务契约.md)，动作规则唯一正文见[权限与对外审批](任务与执行.md#高危类别注册通道与接管)。

5. 高噪音入口研判：群组、话题等确需降噪的来源，在对应适配器入口按配置调用共享模型研判能力；复用统一来源枚举、书面规则与版本校验，不为每个平台复制模型提示词或规则实现。研判只在消息进入 Router 前进行，不能在 Router 派工后再审核。

适配器不另建 Agent、对话状态或工单存储，不自行授予主人资格、扩权或直接控制工单，也不为渠道新建专属会话实现。模型建议由统一服务确定性复核身份、范围、规则与版本；Router 接收可信输入后负责对话理解和派工。协议验签与格式校验属于协议职责，不替代管线的身份、范围与规则判断。协议连接与认证状态不等于对话状态；统一存储中的来源索引、原文、工单和投递记录仍由 BenchGo 机制维护。

渠道源码按 `plugins/superagent/src/channels/<渠道>/` 收拢，每个渠道以 `index.mjs` 提供适配器入口；飞书的 REST 收发、长连接、专属定义与名称查询缓存统一放在 `channels/feishu/`，Discord 语音放在 `channels/discord/`，WhatsApp 不再通过外层文件转发实现。目录外只保留跨渠道共享的授权调用、协议边界、消息分段和投递回执工具，以及核心渠道目录、运行时与统一管线。旧入口不保留重导出兼容壳，真实源码和测试直接引用新路径。

平台特有的认证、签名、应用权限、接口范围及权限不足回执由对应 IM 适配器解释与检查，不向核心添加飞书等平台专属权限分支。核心仍统一核对连接授权、BenchGo 身份、来源范围、准入和工单 Mandate；适配器调用统一授权复检，平台权限与工单权限互不替代，也不把统一业务规则复制到各平台目录。

渠道不预设人格、助手自称或自我介绍，渠道会话配置仅提供来源、路由、权限与真实协议能力上下文，不另造身份提示词或兜底名字。所有渠道与主聊天共用内置层及 SOUL.md / IDENTITY.md；出厂空名、用户正式命名及身份回答规则只在[身份与形象](身份与形象.md#出厂无名与全渠道一致)维护。

### 来源标注与统一枚举

适配器先解析协议头与来源元数据并提供身份证据；这一步是来源事实提取，不是消息正文归一。每条事件携带以下统一元数据，原生标识按不透明值保留，并绑定到当前已认证适配器连接，避免不同账号的同名标识混用。当前机器值以 `channel-policy.mjs` 的统一枚举为准。

| 字段 | 内容与约束 |
| --- | --- |
| `channel` | 渠道标识；对应当前接入的适配器连接 |
| `sourceType` | 统一来源类型：`direct` 私聊、`group` 群组、`topic` 话题、`system` 系统事件；不能把平台原生类型直接当作规则枚举 |
| `actor` | 发送者原生身份及其 BenchGo 身份映射证据；人或系统身份据实表达，主人资格由统一管线核验，消息正文不能自报主人 |
| `conversationId` | 来源会话标识；聊天范围允许名单据此匹配，保留适配器连接归属；系统事件无聊天会话时明确为空 |
| `topicId` | 来源话题标识；话题事件必须提供，并保留所属 `conversationId`；其他来源无话题时为空 |
| `connectionId` / `connectionRevision` | 由统一入口绑定当前适配器连接及配置版本，归一不得改写；当前配置每渠道保存一条连接 |

适配器说明维护平台原生来源形态到上述枚举的映射；适配器保留原始事实，禁止写死“群组消息丢弃”“私聊才放行”等授权规则。@、引用等协议事实供统一服务及按需入口研判使用，模型输出不能替代身份与准入核验。

| 渠道协议事实 | 统一映射 |
| --- | --- |
| 企业微信单聊/群聊、钉钉 `conversationType=1/2` | 私聊/群组 |
| QQ C2C、机器人私信 / 群 @、频道 @ | 私聊 / 群组；目标类型只保留为发送协议事实 |
| 微信 iLink、WhatsApp Business 私信、Email 邮件往来 | 私聊；Email 自动回复、自发消息另标事实，统一管线防循环 |
| Telegram private / group、supergroup / message_thread_id | 私聊 / 群组 / 话题 |
| Discord 无 guild / guild 普通频道 / 平台 Thread | 私聊 / 群组 / 话题；话题保留父频道范围和实际发送频道 |
| Slack im / 普通 channel、group / 明确 thread_ts | 私聊 / 群组 / 话题；回复原消息的 `replyThreadId` 不自动改变来源类型 |
| 已认证 API Service 主人 / 签名 Webhook | 私聊人类来源 / 系统机器来源；不接受载荷自报主人 |

飞书的详细映射在下节维护。协议没有提供的来源类别不能靠正文、普通引用或内部 Thread 推断。

### 统一入口管线

外部事件统一按以下顺序进入：

**来源核对（统一服务：身份、聊天范围） → 消息归一（适配器） → 确定性准入（统一服务） → 按需研判（适配器入口调用共享能力，统一服务复核） → Trigger → Router 分诊与派工。**

来源核对使用归一前已提取的可信事实与身份映射证据；聊天范围按适配器给出的会话/话题标识匹配允许名单。管线规则只引用统一来源枚举和身份、会话等统一字段，不引用 `p2p` 等渠道原生概念；新渠道只补映射，不复制或改写一套渠道规则。桌面主聊/旁聊的主人直通不因此改变；外部私聊仍需来源核对与确定性准入，是否研判按噪音与配置选择，不把外部私聊一概视为高噪音。派工不设置第二次模型语义审核。

**“停”只认 `sourceType` 为私聊、且发送者经管线核实为主人本人的事件**，再复核原工单归属与控制权限。群组、话题和系统事件中的停类内容不直接停单，降级为提请 Router 注意。该判定依赖适配器正确区分并标注来源类型与发送者；不能仅凭正文包含“停止”或平台原生字符串判断。缺少可信标注不能认定满足停单条件。桌面显式叫停及已授权撤权、收窄仍按统一动作门立即拦截后续动作。

通过管线的消息才成为 Trigger，随后复用 Router 分诊、统一工单、真实执行会话与投递。工单只有一本账：**输入账、状态、投递记录和关单条件全局唯一**；各渠道是同一张工单的不同入口，来源与归属仍须核对，不能跨渠道借用授权，也不在渠道侧复制记录。

### 统一会话与原路交付

渠道会话出现在工作台统一会话列表，带来源标记，可打开、查看和直接回复；可以采用旁聊形态，但列表、消息流、输入、存储与恢复全部复用工作台会话机制，不创建渠道专属会话系统，也不在适配器内另存上下文。渠道对话与工单执行会话各保留本身职责；涉及同一工单的输入都归入同一本工单输入账，不因入口不同建立第二份状态。

来源会话按连接、平台账号、会话与话题生成稳定键，不随重连或配置 revision 改变。一个真实私聊、群聊或适用的话题对应一个稳定来源 session，不将同平台的所有来源拼成一个总会话。左侧「IM」列表只读投影当前实际已连接渠道的既有来源线程，「旁聊」列表只显示手动创建线程；具体切换交互只在[左侧旁聊与 IM 列表](对话交互.md#左侧旁聊与-im-列表)维护。列表切换或查询不得调用建会话、入站或投递钩子；仅真实渠道事件按既有桥接规则建立新来源会话，断开或重新连接不换来源键、不删历史。当前连接事实来自 `connectionCatalog` 的 `channels[].id/status`：启用、无错误、认证为 `verified` 或 `host-authenticated`（`connection.authenticated === true` 视为已验证），且连接状态为 `connected` 或 `listening` 才列为已连接。来源线程须为非 desktop，且其 `sourceKey` 与 `channelSessionKey(thread.source)` 精确一致；通过原 `thread.id/sessionId` 打开，不能按标题补猜。IM 可见时复用现有状态刷新读取目录，不另增定时器；读取失败或数据过期不冒充已连接。`onInbound` 只将已持久原文投影到官方会话；重复事件使用同一原文 ID 补偿投影。工作台来源线程中的主人手写消息就是对该渠道的直接回复，不猜测正文是否任务、不另调 Router；派新任务使用主聊或旁聊。此类回复保留 `desktop-owner` 本地身份、官方 session/message 引用和独立 `deliveryTarget`，进入同一本输入账及现有 direct reply outbox，不伪造远程发送人。发送前仍复核原连接授权及范围。

渠道原文和已确认送达的回复仅以同一官方 Session 内的 `plugin:benchgo-plugin/channel-message` 可忽略插件记录镜像，携带镜像键、方向、统一来源与正文；客户端通过官方会话事件投影和现有消息组件展示。实际旁聊入口 `FixedChatView → QuietChat` 与官方原生会话视图都须消费该镜像，不能只注册官方 context 渲染而让实际旁聊为空。历史接口从同一 session 的合法记录投影专用 `kind: channel-message` 展示行，明确镜像键、方向与来源；客户端只接受这一可信类型，不放开任意 context、Worker 输出或工具记录。镜像不直接追加模型 `user/message`，不占用首条系统消息的受保护位置，不调用 `followup` 或 `inject`，也不额外发起模型回合。模型需要的原文仍按统一入口与受控读取进入，不由显示镜像授予权限。实时记录和历史补载使用同一镜像键去重，刷新及重连由持久行接管原位展示，不新增会话、消息缓存或另一份投递账；来源绑定必须与当前官方 session 及稳定来源键一致，不能把其他渠道或普通旁聊的镜像混入。插件记录可在格式迁移中丢失，因此不能替代中央输入账、工单和 outbox；合法历史消息只作回放、审计和幂等去重，不继续双写旧格式。

IM 导航标题为「飞书私聊 · 联系人」或「飞书群聊 · 群名」，右侧不再重复来源类型；缺少名称时保留简短类型，不把平台不透明 ID 当作友好名字。名称仅是展示元数据，不参与来源键和权限判断。飞书适配器优先复用已配置群名，历史私聊从已有真实消息锚点核对会话和发送者后查询联系人；权限不足或查询失败保留短标题，不影响消息收发和渠道健康。`connectionCatalog` 复用现有刷新只读返回名称缓存，首次查询后台执行，不阻塞列表，不逐行由浏览器请求平台；最多 3 个在途查询、512 个缓存项，成功缓存 10 分钟，失败缓存 5 分钟，配置变化清空缓存，结果回写前复核授权和配置。

友好标题只表示来源会话已建立，不证明真实消息已落盘或显示。诊断分别核对中央 intake/outbox、同一官方 session 的持久镜像、历史投影及实际旁聊渲染；镜像或读取失败明确显示真实错误，不把有来源标题的空白当作同步成功。历史与实际旁聊的渠道投影已补齐并通过定向及浏览器四态验证，既有真实会话的持久镜像已只读验证可恢复显示；真实飞书账号的新接收、显示、回复及回执仍须按实际来源验收。

会话恢复沿用官方校验与持久化接口。日志损坏时保留原文件与来源关联，明确报告不可读取及原因；不得用空列表冒充恢复成功，也不得自动清空、重排系统消息、补造受保护头或创建替身会话。当前官方公开接口不能无损恢复完整但语义非法的当前版本日志时，恢复项保持受阻，须取得受支持恢复通道或明确的数据修复裁决后再处理。

用户明确选择删除损坏的旧会话历史时，可以按既有删除语义移除对应来源线程关联并作废旧日志与派生缓存；其他聊天、身份配置、凭据及中央工单输入、状态、投递与回执账保持原样。之后仅由新的真实渠道事件沿统一入口自然创建新来源会话，使用新会话身份；这是删除旧历史后重新开始，不宣称原会话已恢复，不补投历史结果、不重放旧工单或审批。已产生的外部效果不因历史删除而撤销或获准重做。

已送达记录的后台显示补偿只写当前已存在的来源会话，不创建来源线程；送达时间早于该会话创建时间或缺少可核时间的旧记录不回填新历史。删除与重建来源历史均不改变中央回执，不能用历史镜像补偿重新出现已删除的会话或旧消息。

Worker 将成果原稿保存到工单并通知所属 Router；用户始终与 Router 对话，由其主动自然提醒、自选摘要或完整回复。生成回复保存后进入统一 outbox，由来源适配器按原会话/话题路由送回原渠道；原稿留工单详情，回执回到同一本工单账，由统一交付机制核对送达及关单条件。Router 只表达交付，不重派或验收，不固定工单报告、标题前缀或系统状态文案。适配器只转换发送协议与回执，不决定结果完成、送达或关单。生成或投递失败保持待交付，只重试表达或补投已存回复，不重跑 Worker；外部效果未知先核实，具体见[自校验与交付](自校验与交付.md)。

### 渠道授权

渠道接入授权绑定适配器连接，一条一个，可独立撤销，不跨渠道或服务借用。授权记录、有效性及撤销由统一授权服务管理，在调用该适配器读取或发送前复检；适配器不自行判定准入或扩大工单 Mandate。撤销后阻止该连接的后续读取与发送，保留统一记录供追溯，不影响其他已授权连接。渠道接入授权、工单 Mandate 与具体对外动作许可各守其边界，不互相替代；对外动作规则见[任务与执行](任务与执行.md#权限与对外审批)。

## 渠道、语音与秘密

入口统一为“资源 → 接入 → 多平台”，目录包含飞书、企业微信、QQ、微信、Telegram、Discord、Slack、钉钉、WhatsApp、Email、Webhook、API Service。适配器存在不代表真实账号可收发，认证、接收、发送与回执分项显示。品牌色要求连接已启用、认证成功且实际处于连接或监听状态，仅保存启用配置不代表可用。

配置按渠道 revision 保存，旧连接保持既有限制，留空凭据保留原值。可用性依据实际状态：可用为品牌色，不可用为灰色，不随选中状态改变。连接状态只在页面可见时定时同步；离开页面、切到后台或同步失败时保留上次记录并标明待确认，品牌色与验证项随之灰化，恢复可见后重新核实。状态同步不覆盖尚未保存的配置草稿，切换渠道或离开时取消在途读取，过期响应不得回写。外部上下文不混进桌面主人身份，控制工单必须复核原请求人及来源归属。

飞书可显式沿用平台应用人员范围；私聊与群组的范围和接单规则独立配置，群可选择仅 @、讨论上下文或停用，支持群名称查询分页。这些是统一管线的规则配置，适配器仅返回名单查询、会话标识和 @ 等事实。讨论补读是有界参考，不因获取历史就获得主动开单权限；自由发现任务仍是目标。

渠道凭据仅保存不透明引用 benchgo-channel:<channel>:<uuid>，由服务映射到宿主合法凭据记录，AES-256-GCM 的 AAD 绑定公开引用。凭据录入与配置提交分步确认，后者失败不能显示连接更新成功；自动迁移与替换后清理未全部完成。

保险库的目标与安全输入流程见[保险库与安全输入](#保险库与安全输入)。对外动作许可统一遵循[权限与对外审批](任务与执行.md#权限与对外审批)，渠道凭据存在不等于动作已获授权。

| Webhook | HMAC-SHA256 校验 timestamp + "." + 原始请求体；五分钟窗口，正文上限 64 KB，稳定请求键去重 |
| API Service | 复用已认证 owner dispatcher，不接受载荷自报身份 |
| Email | IMAP TLS / SMTP、线程关联事实与认证证据由适配器提供；允许发件人与防回复循环由统一管线判定，首行 BenchGo-Token 验证后剥离，不向模型传秘密 |
| WhatsApp | Business Cloud API，验签原始请求体及目标 Phone Number ID；媒体只处理 caption，超客服窗口明确失败，不擅发模板 |
| 微信 | 当前 iLink 私聊范围，不能宣称全部个人微信能力 |
| Slack | Socket Mode，无公网回调；校验原始 Team ID 与 Bot 身份，App Token 仅用于建立连接。提供私聊/群组/话题及 @ 事实，统一管线判范围与准入；线程及引用标识保留原值，群内回复不自动获得新任务权限。统一入站持久化后 ACK；chat.postMessage 的 channel 与 ts 作为回执证据回统一账 |
| 钉钉 | 企业内部应用机器人 Stream 模式；校验 Robot Code，以 senderStaffId 提供身份映射证据。提供群组/私聊与 @ 事实，人员和接单范围由统一管线判定；业务 msgId 交统一入口去重，Stream messageId 仅用于持久化后的 ACK。群/私聊发送分别使用官方 robot API，processQueryKey 作为回执证据回统一账；不持久化临时 sessionWebhook |
| Discord 语音 | 适配器报告 /join、/leave 及用户身份，允许范围由统一机制判定；复用 Voice ASR/TTS，最长 20 秒分段、最多三段排队；语音连接控制不等于工单“停” |

Discord 语音是分句近实时交互；全双工、打断、多人混音待实施。语音依赖缺失保留文字能力并提示；文字已送达后语音失败不重发文字。语音、渠道账号和打包依赖各自做真实验收，不能用适配器测试代替。

## 飞书配置契约

### 飞书来源形态映射

下表是飞书适配器的源码映射，不以兼容 `kind` 或内部线程分组替代统一 `sourceType`。发送者从经验证事件的 `sender` / `sender_id` 提取并映射，`chat_id` 保留为会话标识；`@` 由平台 mentions 字段提供事实。

| 飞书原生来源形态与识别证据 | 统一来源类型 | 标识映射 |
| --- | --- | --- |
| `message.chat_type = p2p` 的一对一消息 | 私聊 | `conversationId = chat_id`，无独立话题时 `topicId` 为空；普通引用不把私聊变成话题 |
| `message.chat_type = group` 的普通群消息，未标识为话题 | 群组 | `conversationId = chat_id`，`topicId` 为空 |
| 群消息携带平台明确的话题标识 `thread_id` | 话题 | `conversationId = chat_id`，`topicId = thread_id`，保留原生引用关系 |

`root_id`、`parent_id` 是引用关联证据，不能仅凭当前代码为其生成内部 Thread 就宣称平台来源是话题。没有 `thread_id`、仅有 `root_id` 的事件是否能够稳定识别所有飞书话题，平台协议覆盖及映射尚待核实，不擅自将其全部判成话题或私聊。系统事件使用统一枚举“系统事件”；飞书非消息回调的逐事件映射尚未核实，不宣称普通消息回调已经覆盖。

### 配置保存与规则归属

以下键是现有配置兼容契约；人员范围、私聊开关、群模式、允许名单和规则启用的判定都归统一管线。适配器只读取协议连接所需配置、提供群查询与事实映射，不因配置与协议保存在同一连接设置中而执行规则。旧 `p2p/group` 等值仅在适配器映射处解释，不成为新规则条件。

| 配置 | 语义 |
| --- | --- |
| accessMode | owners 或 platform；缺省 owners 兼容旧配置，新连接由界面显式保存 platform，不因此赋予桌面 owner 身份 |
| directMessages | 缺省 true；私聊规则不被群规则替代 |
| groups | null 兼容原 chatIds；数组元素为 chatId、可选 name、mode（mentions/all/disabled） |
| otherGroups | disabled 或 mentions，缺省 disabled；显式群规则优先 |

connectionAction 的 listChats 只查机器人已加入的群，接受 pageToken，返回 chats 和可选 nextPageToken。已存凭据可在连接停用时验证认证/机器人身份，不自动发测试消息。统一服务在停用或撤销范围后立即阻止新的读取与交付；历史补读锚定已认证入站消息，管线复查现行规则与同一适配器、会话范围后，由适配器执行有界协议读取。

允许名单机器消息的 inferred 接单还需 auto、非空唯一的书面 `## rule: <id>` 定义及启用规则 ID 同时成立。它不授予机器直接回复、控制旧工单或主人权限。界面提供明确中文选项，能力不支持的渠道不显示无效群配置。

## 凭据映射与保存

公开 benchgo-channel 引用映射到合法记录键 `benchgo-plugin/channel-<channel>-<uuid>`；每段使用宿主允许的小写字母、数字与连字符，加密密钥记录为 `benchgo-plugin/channel-key`。connectionCredential 仅接受该渠道声明的 *Ref 字段，返回 ref 后再以当前 revision 提交 connectionConfigure。已有其他引用交由宿主凭据服务解析，不重写标识。

## 保险库与安全输入

保险库由基础层统一提供，不要求额外口令或手动/闲置锁定。基础层保留加密保存、精确 HTTPS 目标绑定及底层代填能力；SuperAgent 已整段删除任意 HTTP 凭据执行工具 `assistant_vault_execute`，不再注册同名兼容工具。Worker 仅保留 `assistant_vault_list` 读取不透明句柄及非秘密元数据，无专用通道统一由 `assistant_external_action` 目录/准备返回 handoff。Agent 不见密码、密钥、Cookie 等明文。动作授权存储与管理已接线，完整安全输入衔接、浏览器代填及接管导航仍待完善；环境变量引用或已保存渠道凭据本身不等于这些路径已完成。

需要凭据时按以下流程衔接原任务：

1. 优先查找当前目标可用的保险库条目，由系统通过句柄绑定实际目标并代填，向 Agent 返回脱敏结果。凭据目标校验防止秘密被填往错误站点；动作许可另按站点、动作类别和期限匹配，不能用凭据适用范围替代动作许可。
2. 没有匹配凭据、凭据失效或需要用户完成验证时，在原来源提供安全输入或用户接管入口，明确实际目标和缺失信息。用户在专用安全界面录入，秘密直接交凭据服务；来源不支持安全输入时跳转已认证的安全界面或接管，不退回聊天索取明文。
3. 安全录入成功后只返回句柄和脱敏状态，保存失败保留可重试入口并明确失败；取消则保留原任务等待。用户接管完成须核实实际登录/认证结果，不因关闭接管窗口就标记成功。
4. 凭据录入与对外动作审批分别完成。已有凭据不自动批准登录、发送或其他对外效果；安全输入成功也不产生动作许可。系统在代填及结构化提交边界复核工单 Mandate、现行规则、目标与动作许可；高危提交使用注册通道或交用户完成最后一步，不把保险库代填当通用提交通道。审批及免审范围只在[权限与对外审批](任务与执行.md#权限与对外审批)维护。

许可匹配、可信站点映射、单次审批及管理入口只在[权限与对外审批](任务与执行.md#权限与对外审批)维护。凭据仅经保险库保存、句柄解析与系统代填，不因用户接管或持续授权提供模型可读取的秘密通道。

秘密不得进入聊天、模型上下文、记忆、工具参数与返回日志、错误回执或导出；Agent 的工具参数只携带句柄，系统代填发生在实际调用边界。重定向或目标变化重新校验凭据适用目标与动作许可，跨站不沿用原站授权。撤销授权阻止后续动作，不擅自删除保险库凭据；凭据替换或删除后，旧句柄与在途安全输入不得继续使用失效记录。

## 实现与验收边界

渠道统一会话已有代码接线：复用中央助手的旁聊 Thread 与官方 Agent Session，可信入站原文和已确认送达的统一交付记录通过同会话插件记录与官方聊天投影展示，不进入模型消息面。官方会话列表通过 summary projection 提供渠道来源标记，打开和输入沿用工作台；此会话中的主人输入明确作为向原渠道发送的原文回复，重新核验来源范围后进入既有交付账，不另开 Router 研判。镜像复用真实官方 Agent、JSONL 持久化、来源投影与会话列表，不产生额外模型请求；验收须覆盖首个真实模型回合前后恢复、镜像幂等、真实平台账号收发及完整产品界面。已有语义非法日志的恢复不由防复发接线代替，缺少官方恢复接口时保持受阻。

适配器入口按噪音调用共享模型研判为本轮目标，尚未迁移实现；当前渠道仍复用统一研判管线，本轮删除桌面派工范围复审不等于已完成该迁移，也不新增飞书专项审查实现。十二适配器已移除人员、会话、@ 的业务放行逻辑，统一入口先核对可信来源，再调用懒归一；归一不能改身份和来源，异步归一后再次核对连接版本。统一能力目录明确文字、图片、附件、卡片、回执、历史等支持状态；向外发送声明 `externalActions: ['external-send']`，API/Webhook 仅提供结果拉取，不冒充对外发送能力。任意 Agent 外发只使用已通过研判的真实来源记录及完整正文冻结审批；原来源正常交付和官方会话主人手写回复沿各自受信路径。

原文、候选与领域 Trigger 共用同一物理输入行：渠道准入后先保存 `pending` 原文，只能通过内部 `readIntakeEvent` 研判读取；`getTrigger` 只返回已通过的 `admitted` 行。Decision 通过或可信订阅/问题答复匹配后原行提升，略过或拒绝为 `rejected` 审计原文，不复制第二本账。旧输入行迁移保留原有已准入阶段，但缺统一来源枚举的旧来源不补猜身份或授权，控制及重评须重新收取可信事件。旧 direct reply 表迁移仅放宽候选外键为空以容纳真实主人手写回复，保留历史回执与核实记录；不制造伪候选或第二套 outbox。

验收覆盖来源先于正文读取、群未 @ 不新建 Trigger、可信私聊主人停门、其他来源提请 Router、版本撤销、逐连接收发复检、同账直接回复及迁移。真实平台账号收发、实际权限和网络条件、语音设备及完整界面四态须分别核对，不以协议测试代替。

十二渠道适配、凭据引用、语音与原来源交付已有代码；每种真实账号收发、跨渠道 Attention、语音设备/依赖和重启投递分别验收。Slack、钉钉目前接入文字，附件明确提示不支持；本地协议测试不代表平台权限、真实收发与网络条件已验收。基础层保险库保留 AES-256-GCM 加密、精确 HTTPS URL/方法/字段绑定及一次性 OTP 等能力；Worker 已移除任意凭据执行工具，专用通道或接管统一使用动作目录，没有浏览器 DOM 登录接线。凭据自动迁移与替换后清理、安全输入联动和完整健康升级机制仍有缺口；模型密钥池边界见[模型与上下文](模型与上下文.md)。

动作存储、精确 origin/actor/profile 的 login/private-upload 许可、期限匹配、撤销与脱敏审计及授权管理页面已接线；许可规则和覆盖只在[权限实现边界](任务与执行.md#实现与验收边界)维护。管理页将有效许可与过期/撤销历史分开展示，新建许可与脱敏动作记录使用独立弹窗；刷新保留已读列表并明确陈旧状态，操作后回到可继续使用的焦点。这里只管理已有许可账本，不生成审批决定，也不扩展许可覆盖范围。当前没有内置登录/上传执行适配器，未分类凭据请求必须改走可信专用通道或接管；不能把基础层底层代填、整站许可已保存或管理页可用误称为浏览器登录已受控。正式审批卡、桌面安全输入和真实账号路径须分别验收。

统一 outbox、成功回复可信送达后 completed、失败说明送达后 waiting、发送失败只补投及未知效果核实已有基础接线。Worker 保存原稿并通知、Router 自然表达并保存正式稿后原路交付复用该链；状态、恢复及投递边界只在[自校验与交付](自校验与交付.md#实现与验收边界)维护，真实渠道端到端须使用对应账号验收。

Slack、钉钉的融合参考 [`@xmanrui/dsh-im@5.10.0`](https://github.com/xmanrui/dsh-im) 声明能力及其公开渠道实现、[`dingtalk-stream@2.1.4`](https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs) 公开协议；复用 BenchGo 既有 HTTP/WebSocket 生命周期、凭据和统一工单入口，不引入参考插件的独立 Agent 会话。发送超时或成功响应缺少回执按结果未知处理，不自动重发业务消息。

验证旧配置不扩权、配置草稿和留空凭据保留、选择/保存/重载一致、分页群列表、停用范围撤销、有界历史读取及失败提示；配置保存、实际认证、接收、发送和重载分开记录。微信、WhatsApp 和 Discord 语音的限制按上表验证，不用适配器单测替代真实服务。

另验新渠道只需适配器映射即可复用原管线；来源事实先核对再归一；群组/话题/系统事件的停类内容只提醒 Router，主人私聊仍复核身份与原单控制权限；缺少事实不默认放行。渠道会话须在统一列表可见、可打开并直接回复，来源标记和能力差异真实呈现；空时有接入入口、加载时保留结构、失败时说明连接或投递原因、有数据时显示真实消息和回执。用“你是谁”对照主聊天与真实渠道私聊，按身份文档核对未命名或正式姓名，不能用适配器单测替代真实回复验证。跨入口同工单只有一份输入、状态、投递和关单记录；重连、重启或重复回执不复制会话或工单，撤销一个连接不借其他连接继续收发。

保险库界面须核验真实四态：无匹配凭据时有安全输入/接管入口，加载时防重复录入，失败时明确原因且不显示成功，有条目时只展示脱敏信息与真实可用性。验证安全输入取消、保存失败、接管失败、秘密不进入模型及日志、跨站跳转不误填、录入不代替批准、撤权与凭据替换在调用边界生效；整站许可的动作类别、期限及高风险逐次审批不得被凭据代填绕过。重启后恢复原任务与有效授权，不恢复失效秘密、不重复已确认外部效果；效果未知先查认证状态或调用回执，不能重复提交业务动作来探测。
