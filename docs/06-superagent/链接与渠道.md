# SuperAgent 链接与渠道

本文维护多平台接入、渠道配置和凭据；来源准入见[入口与研判](入口与研判.md)，跨渠道问题和结果投递见[验收与交付](验收与交付.md)。

## 渠道、语音与秘密

入口统一为“资源 → 接入 → 多平台”，目录包含飞书、企业微信、QQ、微信、Telegram、Discord、WhatsApp、Email、Webhook、API Service。适配器存在不代表真实账号可收发，认证、接收、发送与回执分项显示。

配置按渠道 revision 保存，旧连接保持既有限制，留空凭据保留原值。可用性依据实际状态：可用为品牌色，不可用为灰色，不随选中状态改变。外部上下文不混进桌面主人身份，控制工单必须复核原请求人及来源归属。

飞书可显式沿用平台应用人员范围；私聊与群聊独立配置，群选择仅 @、讨论上下文或停用，支持群名称查询分页。讨论补读是有界参考，不因获取历史就获得主动开单权限；自由发现任务仍是目标。

渠道凭据仅保存不透明引用 benchgo-channel:<channel>:<uuid>，由服务映射到宿主合法凭据记录，AES-256-GCM 的 AAD 绑定公开引用。凭据录入与配置提交分步确认，后者失败不能显示连接更新成功；自动迁移与替换后清理未全部完成。

保险库目标为加密存储、Agent 不见明文、句柄与目标绑定、系统代填及脱敏回执，不要求额外口令或手动/闲置锁定。执行前复核目标、方法、当前权限和审批；凭据不进入聊天、记忆、工具参数日志或导出。环境变量引用本身不等于完整保险库。

| 接入 | 特有契约或限制 |
| --- | --- |
| Webhook | HMAC-SHA256 校验 timestamp + "." + 原始请求体；五分钟窗口，正文上限 64 KB，稳定请求键去重 |
| API Service | 复用已认证 owner dispatcher，不接受载荷自报身份 |
| Email | IMAP TLS / SMTP、线程关联与防回复循环；允许发件人还需首行 BenchGo-Token 校验，验证后剥离 |
| WhatsApp | Business Cloud API，验签原始请求体及目标 Phone Number ID；媒体只处理 caption，超客服窗口明确失败，不擅发模板 |
| 微信 | 当前 iLink 私聊范围，不能宣称全部个人微信能力 |
| Discord 语音 | /join、/leave 显式控制，允许用户范围；复用 Voice ASR/TTS，最长 20 秒分段、最多三段排队 |

Discord 语音是分句近实时交互；全双工、打断、多人混音待实施。语音依赖缺失保留文字能力并提示；文字已送达后语音失败不重发文字。语音、渠道账号和打包依赖各自做真实验收，不能用适配器测试代替。

## 飞书配置契约

| 配置 | 语义 |
| --- | --- |
| accessMode | owners 或 platform；缺省 owners 兼容旧配置，新连接由界面显式保存 platform，不因此赋予桌面 owner 身份 |
| directMessages | 缺省 true；私聊规则不被群规则替代 |
| groups | null 兼容原 chatIds；数组元素为 chatId、可选 name、mode（mentions/all/disabled） |
| otherGroups | disabled 或 mentions，缺省 disabled；显式群规则优先 |

connectionAction 的 listChats 只查机器人已加入的群，接受 pageToken，返回 chats 和可选 nextPageToken。已存凭据可在连接停用时验证认证/机器人身份，不自动发测试消息。停用或撤销范围立即阻止新的读取与交付；历史补读锚定已认证入站消息，限同应用、同群并复查现行规则。

允许名单机器消息的 inferred 接单还需 auto、非空唯一的书面 `## rule: <id>` 定义及启用规则 ID 同时成立。它不授予机器直接回复、控制旧工单或主人权限。界面提供明确中文选项，能力不支持的渠道不显示无效群配置。

## 凭据映射与保存

公开 benchgo-channel 引用映射到合法记录键 `benchgo-plugin/channel-<channel>-<uuid>`；每段使用宿主允许的小写字母、数字与连字符，加密密钥记录为 `benchgo-plugin/channel-key`。connectionCredential 仅接受该渠道声明的 *Ref 字段，返回 ref 后再以当前 revision 提交 connectionConfigure。已有其他引用交由宿主凭据服务解析，不重写标识。

## 实现与验收边界

十渠道适配、凭据引用、语音与原来源交付已有代码；每种真实账号收发、跨渠道 Attention、语音设备/依赖和重启投递分别验收。凭据自动迁移与替换后清理、保险库目标绑定安全代填与完整健康升级机制仍有缺口；模型密钥池边界见[模型与上下文](模型与上下文.md)。

验证旧配置不扩权、配置草稿和留空凭据保留、选择/保存/重载一致、分页群列表、停用范围撤销、有界历史读取及失败提示；配置保存、实际认证、接收、发送和重载分开记录。微信、WhatsApp 和 Discord 语音的限制按上表验证，不用适配器单测替代真实服务。
