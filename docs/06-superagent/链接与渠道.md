# SuperAgent 链接与渠道

本文是渠道适配器定位、来源标注与映射、统一会话路径的权威正文，并维护渠道配置、凭据与保险库。准入与研判规则见[入口与研判](入口与研判.md)，结果投递见[结果与交付](结果与交付.md)。

## 渠道适配器与统一机制

渠道只能是适配器：接入新渠道不改 Router、工单、执行会话或投递核心。使用者身份与渠道准入权限归对应适配器，核心不设主人 / 普通使用者档位，边界见[入口与研判](入口与研判.md#已敲定的身份边界与当前差距)。

| 适配器职责 | 内容 |
| --- | --- |
| 协议收发 | 平台认证、验签、连接、收发与回执转换；协议验签不代替业务授权 |
| 渠道身份与权限 | 在本渠道配置内核对账号、发送者、允许范围、可执行操作和撤权，输出可信准入结果与会话 / 话题关联 |
| 消息归一 | 把消息与附件转成统一格式，保留来源事实与原文指针 |
| 能力声明 | 声明实际支持的文本、图片、卡片、回执等能力，以及可提供的高危类别与结构化通道；交核心注册表校验，不自行授权。动作规则见[通道与接管](任务与执行.md#高危类别注册通道与接管) |
| 高噪音入口研判 | 群组、话题等来源在进入 Router 前按配置调用共享研判能力，不为每个平台复制提示词或规则 |

适配器不另建 Agent、对话状态或工单存储，不自行扩权或直接控制工单。渠道不预设人格、自称或自我介绍，身份来源见[出厂无名与全渠道一致](身份与形象.md#出厂无名与全渠道一致)。

源码按 `plugins/superagent/src/channels/<渠道>/` 收拢，每个渠道以 `index.mjs` 提供入口；目录外只保留跨渠道共享的授权调用、消息分段、投递回执工具，以及渠道目录、运行时与统一管线。

当前与目标的两处差距：

- 渠道身份、来源范围与准入规则已集中在共享的 `channel-policy.mjs`，但仍由统一 `intake` 调用；适配器入口自行完成准入和按需研判待实施。
- 飞书在服务装配中走独立的 adapter 与 stream（`channels/feishu/index.mjs`、`stream.mjs`），其余渠道经 `channel-runtime.mjs`；并入统一运行时待实施。

### 来源标注与统一枚举

适配器先解析协议头与来源元数据并提供身份证据。每条事件携带下列元数据，原生标识按不透明值保留并绑定到当前已认证的连接；机器值以 `channel-policy.mjs` 的枚举为准。

| 字段 | 内容与约束 |
| --- | --- |
| `channel` | 渠道标识，对应当前接入的适配器连接 |
| `sourceType` | `direct` 私聊、`group` 群组、`topic` 话题、`system` 系统事件；平台原生类型不直接当规则枚举 |
| `actor` | 发送者原生身份及其 BenchGo 身份映射证据；消息正文不能自报主人 |
| `conversationId` | 来源会话标识，聊天范围允许名单据此匹配；系统事件无聊天会话时为空 |
| `topicId` | 来源话题标识；话题事件必须提供并保留所属 `conversationId` |
| `connectionId` / `connectionRevision` | 由统一入口绑定当前连接及配置版本，归一不得改写；当前每渠道保存一条连接 |

| 渠道协议事实 | 统一映射 |
| --- | --- |
| 企业微信单聊 / 群聊、钉钉 `conversationType=1/2` | 私聊 / 群组 |
| QQ C2C、机器人私信 / 群 @、频道 @ | 私聊 / 群组；目标类型只作发送协议事实 |
| 微信 iLink、WhatsApp Business 私信、Email 往来 | 私聊；Email 自动回复和自发消息另标事实，由统一管线防循环 |
| Telegram private / group、supergroup / message_thread_id | 私聊 / 群组 / 话题 |
| Discord 无 guild / guild 普通频道 / 平台 Thread | 私聊 / 群组 / 话题；话题保留父频道范围和实际发送频道 |
| Slack im / 普通 channel、group / 明确 thread_ts | 私聊 / 群组 / 话题；`replyThreadId` 不自动改变来源类型 |
| 已认证 API Service 主人 / 签名 Webhook | 私聊人类来源 / 系统机器来源；不接受载荷自报主人 |

飞书的映射见[飞书配置契约](#飞书配置契约)。协议没有提供的来源类别不能靠正文、普通引用或内部 Thread 推断；@、引用等协议事实供准入和研判使用，模型输出不能替代身份核验。

### 统一入口管线

外部事件按以下顺序进入：

**来源核对（身份、聊天范围） → 消息归一 → 确定性准入 → 按需研判 → Trigger → Router 分诊与派工。**

- 来源核对使用归一前已提取的可信事实；归一不能改身份和来源，异步归一后再次核对连接版本。
- 管线规则只引用统一来源枚举和统一字段，不引用 `p2p` 等原生概念；新渠道只补映射。
- 准入前被拒绝的事件不登记 Trigger。原文、候选与领域 Trigger 共用同一输入行：准入后先以 `pending` 保存原文，只供内部研判读取；研判通过或可信订阅 / 答复匹配后同 ID 提升为 `admitted`，忽略或拒绝记为 `rejected` 保留审计。`getTrigger` 只返回 `admitted` 行。
- 渠道中的“停”如何判定见[候选研判与决定](入口与研判.md#候选研判与决定)；它依赖适配器正确标注来源类型与发送者，缺少可信标注不满足停单条件。
- 桌面主聊 / 旁聊不经此管线。通过管线的消息才成为 Trigger，其后复用 Router 分诊、统一工单、执行会话与投递；工单的输入账、状态、投递记录全局唯一，不跨渠道借用授权。

### 统一会话与原路交付

渠道会话出现在工作台统一会话列表，带来源标记，可打开、查看和直接回复。列表、消息流、输入、存储与恢复全部复用工作台会话机制，不建渠道专属会话系统；界面交互见[左侧旁聊与 IM 列表](对话交互.md#左侧旁聊与-im-列表)。

| 事项 | 规则 |
| --- | --- |
| 来源会话 | 按连接、平台账号、会话与话题生成稳定来源键，不随重连或配置 revision 改变；一个真实私聊、群聊或话题对应一个来源 session。仅真实渠道事件建立新来源会话，列表切换或查询不建会话、不触发入站或投递 |
| 已连接判定 | 取 `connectionCatalog` 的 `channels[].id/status`：启用、无错误、认证为 `verified` 或 `host-authenticated`，且连接状态为 `connected` 或 `listening`。读取失败或数据过期不冒充已连接 |
| 打开 | 来源线程须为非 desktop 且 `sourceKey` 与 `channelSessionKey(thread.source)` 一致；通过原 `thread.id/sessionId` 打开，不按标题补猜 |
| 显示镜像 | 可信入站原文和已确认送达的回复以 `plugin:benchgo-plugin/channel-message` 插件记录镜像到同一官方 Session，历史接口投影为 `kind: channel-message`。镜像不追加模型 `user/message`、不调用 `followup` 或 `inject`、不起模型回合、不授予权限；实时与历史按同一镜像键去重。它不能替代中央输入账、工单和 outbox |
| 主人手写回复 | 工作台来源线程中的主人输入就是对该渠道的原文回复，不猜是否任务、不调用 Router；派新任务用主聊或旁聊。回复保留 `desktop-owner` 身份和独立 `deliveryTarget`，进入同一输入账与 direct reply outbox，发送前复核原连接授权及范围 |
| 标题 | 「飞书私聊 · 联系人」或「飞书群聊 · 群名」；缺名称时保留简短类型，不把平台 ID 当名字。名称只是展示元数据，不参与来源键和权限判断。名称查询后台执行：最多 3 个在途、512 个缓存项，成功缓存 10 分钟、失败 5 分钟，配置变化清空 |
| 诊断 | 友好标题只表示来源会话已建立。诊断分别核对中央 intake / outbox、持久镜像、历史投影和实际旁聊渲染，读取失败显示真实错误 |
| 日志损坏 | 保留原文件与来源关联并报告原因；不以空列表冒充恢复，不自动清空、补造或建替身会话。官方接口无法无损恢复时保持受阻 |
| 删除损坏历史 | 用户明确选择后，移除来源线程关联并作废旧日志与派生缓存；中央工单输入、状态、投递与回执账不变。此后由新的真实渠道事件自然建立新会话，不补投历史结果、不重放工单或审批 |
| 显示补偿 | 已送达记录的后台补偿只写已存在的来源会话；送达时间早于会话创建或缺少可核时间的记录不回填 |

工单结果由 Router 表达后经统一 outbox 按原会话 / 话题交回原渠道，适配器只转换协议与回执；规则见[结果落单与 Router 表达交付](结果与交付.md#结果落单与-router-表达交付)。

### 渠道授权

渠道接入授权绑定适配器连接，一条一个，可独立撤销，不跨渠道借用。授权记录、有效性和撤销由统一服务管理，在调用适配器读取或发送前复检；撤销后阻止该连接的后续读取与发送，不影响其他连接。渠道接入授权、工单 Mandate 与具体对外动作审核各守其边界，对外动作规则见[权限与对外审批](任务与执行.md#权限与对外审批)。

## 渠道、语音与秘密

入口为“资源 → 接入 → 多平台”，目录包含飞书、企业微信、QQ、微信、Telegram、Discord、Slack、钉钉、WhatsApp、Email、Webhook、API Service。适配器存在不代表真实账号可收发，认证、接收、发送与回执分项显示。

- 可用性依据实际状态：已启用、认证成功且处于连接或监听状态显示品牌色，否则灰色，不随选中状态改变。
- 配置按渠道 revision 保存，留空凭据保留原值。连接状态只在页面可见时定时同步；离开、切到后台或同步失败时保留上次记录并标明待确认。状态同步不覆盖未保存的草稿，过期响应不回写。
- 渠道凭据只保存不透明引用 `benchgo-channel:<channel>:<uuid>`，映射到宿主凭据记录 `benchgo-plugin/channel-<channel>-<uuid>`，AES-256-GCM 的 AAD 绑定公开引用，密钥记录为 `benchgo-plugin/channel-key`。`connectionCredential` 只接受该渠道声明的 *Ref 字段，返回 ref 后再以当前 revision 提交 `connectionConfigure`；两步分别确认，后者失败不显示连接更新成功。
- 渠道凭据存在不等于动作已获批准。

| 接入 | 特有契约或限制 |
| --- | --- |
| Webhook | HMAC-SHA256 校验 timestamp + "." + 原始请求体；五分钟窗口，正文上限 64 KB，稳定请求键去重；只提供结果拉取 |
| API Service | 复用已认证 owner dispatcher，不接受载荷自报身份；只提供结果拉取 |
| Email | IMAP TLS / SMTP；允许发件人与防回复循环由统一管线判定；首行 BenchGo-Token 验证后剥离，不向模型传秘密 |
| WhatsApp | Business Cloud API，验签原始请求体及目标 Phone Number ID；媒体只处理 caption，超客服窗口明确失败，不擅发模板 |
| 微信 | 当前为 iLink 私聊范围，不代表全部个人微信能力 |
| Slack | Socket Mode，无公网回调；校验 Team ID 与 Bot 身份。统一入站持久化后 ACK；`chat.postMessage` 的 channel 与 ts 作为回执证据。当前只接文字 |
| 钉钉 | 企业内部应用机器人 Stream 模式；校验 Robot Code，以 senderStaffId 作身份映射证据。业务 msgId 交统一入口去重；群 / 私聊分别用官方 robot API 发送，processQueryKey 作为回执证据；不持久化临时 sessionWebhook。当前只接文字 |
| Discord 语音 | 适配器报告 /join、/leave 及用户身份；复用 Voice 的 ASR / TTS，最长 20 秒分段、最多三段排队；语音连接控制不等于工单“停” |

Discord 语音是分句近实时交互；全双工、打断、多人混音待实施。语音依赖缺失时保留文字能力并提示，文字已送达后语音失败不重发文字。发送超时或成功响应缺少回执时按结果未知处理，不自动重发。

Slack、钉钉的接入参考 [`@xmanrui/dsh-im@5.10.0`](https://github.com/xmanrui/dsh-im) 的公开渠道实现和 [`dingtalk-stream@2.1.4`](https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs) 公开协议，复用 BenchGo 既有的连接生命周期、凭据和统一工单入口，不引入参考插件的独立 Agent 会话。

## 飞书配置契约

发送者从经验证事件的 `sender` / `sender_id` 提取并映射，`chat_id` 作会话标识，`@` 由平台 mentions 字段提供。

| 飞书原生形态 | 统一来源类型 | 标识映射 |
| --- | --- | --- |
| `message.chat_type = p2p` | 私聊 | `conversationId = chat_id`，`topicId` 为空；普通引用不把私聊变成话题 |
| `message.chat_type = group`，未标识话题 | 群组 | `conversationId = chat_id`，`topicId` 为空 |
| 群消息携带 `thread_id` | 话题 | `conversationId = chat_id`，`topicId = thread_id` |

`root_id`、`parent_id` 只是引用关联证据。没有 `thread_id`、仅有 `root_id` 的事件能否稳定识别为话题尚待核实；飞书非消息回调的逐事件映射也未核实。

| 配置 | 语义 |
| --- | --- |
| accessMode | owners 或 platform，缺省 owners；platform 沿用平台应用人员范围，不赋予桌面 owner 身份 |
| directMessages | 缺省 true；私聊规则不被群规则替代 |
| groups | 数组元素为 chatId、可选 name、mode（mentions / all / disabled）；为 null 时沿用 chatIds 允许名单 |
| otherGroups | disabled 或 mentions，缺省 disabled；显式群规则优先 |

- 这些规则归渠道边界，由共享 `channel-policy.mjs` 处理；平台原生值只在适配器映射处解释。
- `connectionAction` 的 listChats 只查机器人已加入的群，接受 pageToken，返回 chats 和可选 nextPageToken。已存凭据可在连接停用时验证认证与机器人身份，不自动发测试消息。
- 停用或撤销范围后立即阻止新的读取与交付。讨论补读锚定已认证入站消息，复查现行规则后做有界读取；它是参考，不带来主动开单权限。自由发现任务待实施。
- 允许名单机器消息的 inferred 接单需要 auto 模式、非空唯一的书面 `## rule: <id>` 定义和已启用的规则 ID 同时成立；它不授予机器直接回复、控制已有工单或主人权限。

## 保险库与安全输入

保险库只负责秘密保存与使用隔离，不承担授权管理。模型只传凭据引用，真实值在实际使用处取用。

- 一条凭据由“地址或名称”和多项自定义凭证组成：前者可以是链接、服务名或设备名，后者是自定义名称和值。表单可增删多项，不要求固定类型或请求协议字段，编辑单项保留其他凭证；不设保险库口令或闲置锁定。
- 凭证值经安全表单交宿主加密保存，不进入聊天、模型上下文、记忆、工具公开参数与结果、日志或错误回执；名称 / 地址不存放秘密。
- Worker 的 `assistant_vault_list` 只返回句柄与元数据。没有专用通道时统一经 `assistant_external_action` 返回接管。

需要凭据时衔接原任务：

1. 按地址或名称查找已有条目，系统通过引用使用指定凭证，向 Agent 返回不含秘密的实际结果。
2. 没有匹配、凭据失效或需要用户验证时，在原来源提供安全输入或用户接管入口；来源不支持安全输入时跳转已认证的安全界面，不退回聊天索取明文。
3. 录入成功只返回句柄和脱敏状态；保存失败保留重试入口，取消则原任务保持等待。接管完成须核实实际登录或认证结果。
4. 录入凭据不批准任何动作；需要确认的操作走[任务内审核](任务与执行.md#权限与对外审批)，审批和实际执行分开回报。

凭据替换或删除后不继续使用失效记录；使用失败或能力缺失时如实返回，不以重复提交业务动作来试探。

## 实现与验收边界

已实现（源码接线，安装版与真实平台未据此验收）：

- 十二个渠道适配器、凭据引用、统一入站（来源核对、懒归一、准入、研判授权）与原来源交付。多数适配器只有本地协议测试，未经真实账号验收。
- 统一会话：来源线程复用旁聊 Thread 与官方 Session，镜像记录、历史投影与实际旁聊渲染，主人手写回复进入既有交付账；有定向与浏览器四态验证。
- 能力目录声明文字、图片、附件、卡片、回执、历史的支持状态；可外发的渠道声明 `externalActions: ['external-send']`。
- 保险库的“地址或名称 + 多项凭证”存储与表单（基础层 `vault.mjs`、共享 `vault-settings.jsx`），秘密加密、公开接口脱敏。基础层仍带精确 HTTPS URL / 方法 / 字段绑定与一次性 OTP 能力，Worker 侧未接入。

待实施：

- 适配器入口自行完成准入与按需研判；飞书并入统一渠道运行时。
- 浏览器登录、上传与秘密取用的完整路径，安全输入联动，凭据替换后的清理，完整健康升级机制。
- Slack、钉钉的附件；Discord 语音的全双工、打断与多人混音；自由发现任务。

待验证：
