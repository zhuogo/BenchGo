## 产品路径

统一入口为 **资源 → 接入 → 多平台**（原文档称“链接”，内部 `connections` 标识保持兼容）。渠道 Tab 使用官方品牌素材与文案；Email、Webhook、API 是协议/通用能力，使用现有正式图标库，不虚构品牌 Logo。素材本地打包并记录官方来源。产品约定是真实可用显示品牌色，未启用、未连接或不可用显示灰色；选中状态不改变品牌色。当前着色偏差见“源码复核待闭合项”。

覆盖飞书、企业微信、QQ、微信、Telegram、Discord、WhatsApp、Email、Webhook、API Service。复用已有服务与成熟 SDK；统一保存、重载、认证验证和状态反馈，必填项优先，高级设置折叠。密钥仅通过凭据服务保存引用，不进入模型或公开配置。

## 服务边界

所有渠道由同一个 SuperAgent Router 研判，经来源校验与准入后，日常问答和澄清可通过 `answer` / `ask` 直接回复，不创建 Ticket；需要执行的事项才进入工单委派，结果回原会话。直接回复与工单交付分别持久化、去重并复验来源权限，见[日常助手与渠道直接回复](日常助手与渠道直接回复.md)。渠道、账号、私聊/群聊、话题和发送人保持来源身份；上下文按来源线程隔离，同一群/话题内可共享相关讨论，不承诺按发送人再建立独立聊天线程。外部消息不直接混入桌面主聊天日志。项目明确自动路由，歧义通过原渠道追问。

连接配置按渠道独立保存，revision CAS 防止覆盖；修改单项不丢失其他渠道或字段，旧飞书无 channel 参数接口保持兼容。状态区分配置存在、认证通过、接收正常与发送成功，未实际验证不得显示已连接。外部来源不能声明主人身份。

Webhook 使用签名/时间戳、事件幂等和受限接收体积；API Service 复用官方已认证入口，不新建旁路服务。Email 使用 IMAP/SMTP 和邮件线程标识，防止自动回复循环。微信优先 iLink 机器人私聊，不承诺普通微信群；WhatsApp 优先 Business Cloud API。

Discord 实时语音优先复用 Voice 的转写、对话与播放服务及成熟语音 SDK，必须有显式加入/离开与权限控制。语音附件不等同于实时语音；环境、SDK 或供应商不足时明确报告不可用，不伪造支持。

## 验证边界

企业微信群回复受平台上下文窗口限制（约六分钟）；长任务超过窗口可能无法回原群，结果仍保存在工作台工单，可重新 @ 机器人查询。Discord 语音还需要可加载的 DAVE 原生依赖；当前 Linux seed 不携带该依赖时明确显示语音不可用。

本轮进行配置隔离、来源授权、收发适配与界面操作的定向测试，并运行 reload:plus。真实渠道认证、外部收发与实时语音需具备用户账号及运行环境，模拟测试不能替代真实验收。

参考：只读 Hermes `50d2adf1cd` 的平台插件协议和适配方式，不引入参考仓库运行依赖。

## 核心实现记录

链接页使用渠道图标与文案切换，Email 使用信封语义图标。当前飞书启用开关位于渠道标题同行，其他渠道位于配置区；标题保留“未启用”提示，认证、收发状态与验证操作在各渠道内分别展示。图标不随选中状态改色，但当前实现仍只按 `enabled` 着色，尚未满足“真实可用才显示品牌色”的产品约定，见下文待闭合项。

已实现资源 → 接入 → 多平台：十渠道图标+文案切换、独立配置保存/重载/验证、状态与能力限制提示。品牌图标取自各官方网站，来源和哈希见 `plugins/shared/client/assets/channel-brands/sources.json`；通用协议使用既有 Iconsax 素材。所有素材本地打包。

密钥在链接页直接安全录入，通过官方 credential records 加密存储；仅 opaque 引用进入配置。微信支持扫码、手动检查状态、取消及过期清理，登录成功后保存配置生效。普通微信群不在支持范围。

Email 支持 IMAP TLS / SMTP、线程回复与自动回复防循环。由于 From 可伪造，专用邮箱的允许发件人仍须在正文第一行填写 `BenchGo-Token: <指令校验码>`；校验码在链接页录入，可保存到用户邮件模板。适配器验证后剥离，不进入 Router 文本、主题或日志。媒体附件正文当前不解析，界面及消息明确提示。

Webhook 支持 HMAC-SHA256，签名覆盖 `timestamp + "." + 原始请求体`；请求头为 `X-BenchGo-Timestamp`（秒）和 `X-BenchGo-Signature`（hex），五分钟窗口，正文上限 64 KB。JSON 字段为 `requestId`、`conversationId`、`text`，其中文字上限 32000 字节；固定绑定配置中的唯一主人，不接受输入声明身份。稳定 requestId 复用持久 Trigger 去重。工单结果与日常直接回复分别保存在工单和回复邮箱中，由已认证 API 读取，不向任意 URL 推送。

API Service 通过既有 `/api/commander/assistant` 的 `connectionAction`、`channel: api`、`operation: submit` 接收同样三个字段，只接受主机已认证 owner principal；工单查询、回答、取消复用 `tickets`、`ticketAnswer`、`ticketStop`。`connectionReplies` 查询 `answer` / `ask` 直接回复，可按 `channel`、`threadId` 过滤，返回最近 100 条及投递状态；这类回复不会出现在工单列表。OpenAPI 同步请求/响应与公开平台回调。现有 MCP 只暴露 `commander_delegate`，本轮不扩大渠道凭据或主人控制权限给模型，MCP 契约不受影响。

Discord 使用 `discord.js`、`@discordjs/voice` 与纯 JS/WASM `opusscript`。启用语音并配置 Voice 后，主人在其所在语音频道对应文字会话发送 `/join`、`/leave`；只接收允许列表主人的语音，分句转写进入同一 Router，交付经共享 Voice TTS 播放。每段最多 20 秒、至多三个待处理片段。这是分句近实时交互，不是供应商端到端 Realtime 会话；当前要求 HTTP ASR 与 PCM TTS，不宣称支持其他渠道实时通话。文字已经送达后的语音失败不重发文字。

长文字按 UTF-8 安全分段，连续交付前复验配置版本；送达未知保存为待核实，不盲目重发。正式打包仅增加唯一 `benchgo-plugin` 的成熟依赖，不引用 Hermes 运行代码。

十个渠道共用按渠道 revision 保存的配置目录、凭据解析与运行时。旧的无 `channel` 调用仍读取飞书。新适配器仅接收自身声明的配置，配置撤销后旧事件来源不能继续交付。当前外部私聊通过 `routeDirect:true` 进入持久候选研判批次，尚非架构要求的持久 Router 主会话直通；群聊保留 @、身份与会话准入限制。目标按噪声分流：已验证的用户主动私聊登记后直达 Router，高噪声才筛选。不能把候选已入队等同于主会话已接通。

Webhook、WhatsApp 与飞书 HTTP 回调挂载在现有 `webServer` 的精确路径 `/api/commander/assistant/channels/{channel}`，由各适配器验签；API Service 只使用已认证 dispatcher。没有 HTTP 载体时状态明确返回回调不可用。Discord 语音复用 Voice 的 ASR/TTS，经同一入站入口进入 Router，语音配置或依赖不可用时不显示可用。
