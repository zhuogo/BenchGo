# SuperAgent 入口与研判

本文维护消息进入 Router 之前的来源核对、准入与研判。渠道适配器的事实标注字段、来源类型枚举和平台映射见[链接与渠道](链接与渠道.md)，领域记录见[服务契约](服务契约.md)。

## 已敲定的身份边界与当前差距

核心引擎不区分主人、普通使用者或其他人的权限档位。飞书等渠道是否对其他人开放、允许哪些来源和操作，由对应适配器的权限配置、准入和撤权负责；核心只消费可信的准入结果、来源关联和该渠道的有效授权。会话与任务的归属、原始输入引用、实际动作审批是各自独立的职责；Router 与 Worker 是工作分工，不是使用者等级。

| 项 | 目标 | 现状 |
| --- | --- | --- |
| 渠道身份规则 | 归对应适配器 | 人员、机器、群提及和来源范围集中在共享策略 `channel-policy.mjs`，`assessment-policy.mjs` 委托它处理渠道身份 |
| 准入调用点 | 适配器入口调用共享能力，输出可信事件 | 仍由统一入站路径 `intake.mjs` 调用；迁移待实施 |
| 高噪音研判 | 适配器入口按需调用共享研判 | 仍在统一渠道研判管线 |
| 桌面主聊、手动旁聊 | 不经渠道准入 | 已如此 |

各渠道的配置版本分别核对，其他渠道的配置变化不使本渠道任务失效。

## 入口与两档分流

按噪音和来源性质分两档：用户主动输入直通 Router；外部来源先过准入，高噪音的再经模型研判。消息正文不能自报身份、替人授权或覆盖可信来源。

渠道消息的目标顺序：适配器内来源与权限核对 → 消息归一 → 按需研判 → 可信入口事件 → Router 分诊。只有通过入口的消息才交给 Router；渠道不直接创建任务，Router 委派之后不再复审。

| 入口 | 处理 | 现状 |
| --- | --- | --- |
| 桌面主聊、旁聊 | 直通 Router，完整保留原文；登记 Trigger 并去重，不做“是否受理任务”的研判 | 已实现。`assistant_delegate` 成功后写 candidate、decision、task |
| 已准入的渠道私聊 | 不做高噪音窗口裁剪；核对来源和本渠道权限后由 Router 判断意图 | 仍走统一渠道研判管线 |
| 群组、话题、系统事件 | 核对来源、归一、准入后按需调用共享模型研判，通过后交 Router | 研判仍在统一渠道管线；真实来源须逐渠道验收 |
| 已订阅任务的跟进 | 原范围内的补充与插话即原任务修订，见[任务、跟进与目标](任务与执行.md#任务跟进与目标) | 已接统一输入账 |
| 定时事件 | 官方 Schedule 触发，形成机器 Trigger；纯提醒可直接回复，执行型任务仍创建任务 | 按来源会话、scheduleId、occurrence 去重 |

**群组规则。** 群里的新事项默认要求实际 @，并复核名单、会话范围和准入强度；没有 @ 的讨论可以作为订阅参考，不能据此创建任务。允许名单内的机器消息只能进入 inferred，且仅在 auto 模式和有效书面规则下创建任务。本渠道的准入不授予其他渠道、会话或任务的访问权限。

**高噪音窗口。** 使用确定性卡片加原文指针：线程头 5 条、触发消息前后各 5 条，长文标明全长和裁剪，按需回读；不用模型摘要替代原文。桌面直聊不做这种窗口化，长会话的上下文整理由宿主负责。

## Router 委派决定与宿主边界

桌面主聊和旁聊的真实用户输入直接进入 Router。Router 根据当前请求、对话上下文和可信的问答回执，决定直接回答、跟进原任务还是新建任务；普通委派没有第二个模型的范围复审。

- “再来一次”“按刚才的方案”这类依赖上下文的指令由 Router 在原对话中理解。官方问答卡里经宿主核验的真实答复是有效输入，保留问题与答案的绑定，不要求用户改写成完整指令。
- 只有影响目标、实际扩大授权或存在关键歧义时才向用户确认。历史助手摘要、模型提案和外部正文不能产生新授权。
- 宿主确定性核对：当前真人来源、根 Agent 与会话归属、原指令引用、requestId 幂等、项目与模型配置、规则和版本。同 requestId 异内容拒绝，原任务归属不匹配拒绝，模型不能自报 owner 或伪造确认。
- 产品状态查询优先使用专属只读能力，环境调查从第一次探查起交给 Worker，见[任务与执行](任务与执行.md#router-与持续主会话)；未知的产品状态不自行扩大成系统扫描。
- 跨设备入口已接 `assistant.collaboration`，保留真实 device 来源、原指令与逻辑会话关联，由目标核对授权、操作能力和任务归属；远端声明不能伪装成目标本机 owner，机器回执不能产生新的人类授权。可查、可执行与可管理分别按已授予能力办理，规则见[授权与互通](../01-设备与远程连接/跨设备协作.md#授权与互通)，真实双机仍待验。
- 委派决策权不替代 Worker 的工具范围、任务授权范围与高危动作约束；Router 和 Worker 的固定 Full 宿主权限见[自有会话角色装配](模型与上下文.md#自有会话角色装配)，停止与撤权仍在真实动作边界生效。

## 候选研判与决定

本节的 Assessment 只负责入口准入和新事项研判，不评价任务结果。

| 环节 | 规则 |
| --- | --- |
| 攒批 | 候选按 Thread 攒批，同一线程最多一个活跃 Eval，跨线程独立推进；单线程失败不阻挡其他线程 |
| 排除 | 先排除已被订阅持有的上下文和已创建任务的 Trigger |
| 建议与复核 | 模型只给建议；代码复核身份、policy、规则、范围和版本后才提交 Decision |
| 新事项的结果 | `accept`、`answer`、`ask`、`ignore` |
| 已有任务的结果 | `attach`、`stop`、`revise`；已结束任务的关联调整用 `adjustment`；`handback` 是独立处置 |
| inferred 受理任务 | 必须是 auto 模式，且所引规则全部启用 |
| 超时 | Eval 超时最多重排 2 次，仍失败则保留 unavailable 和重评入口；队列等待不算模型超时 |
| 失效 | policy 更新使旧评估失效；停止服务时取消在途研判并拒绝迟到结果 |

**渠道里的“停”。** 只认来源类型为私聊、发送者经来源核对确认是主人本人的事件，并且仍要复核目标任务归属和当前权限。群组、话题和系统事件里的停类内容只提请 Router 注意，不直接停止任务；缺失或无法证实的来源标注不能推断为主人私聊。桌面用户直接叫停、系统撤权和规则收紧走[动作边界](任务与执行.md#动作边界与恢复)，不受本条限制。

**原文与关联事件。** 准入前被拒绝的事件不登记 Trigger。候选需要的原文以 `pending` 阶段保存在原输入行，研判通过后同一 ID 提升为领域 Trigger，忽略或拒绝的保留为审计原文。编辑、撤回和迟到的上下文作为关联事件补齐，不覆盖不可变的 Trigger。机器事件不能靠伪造 @ 升级为人类的 explicit 请求。

## 实现与验收边界

**已有源码接线**

- 桌面 direct Trigger、候选与决策持久化。
- 渠道入口的统一顺序：归一前核对身份与范围，归一后复检连接版本，规则只使用统一来源类型。
- 私聊主人的“停”复核可信证据和原任务归属，其余来源只提请 Router。
- 官方问答卡的答复复用原 call/questions 绑定校验，可作为委派依据。

**待实施**

- 渠道准入和按需研判迁到适配器入口。
- 自由发现任务。
- 跨设备可信来源与操作能力桥接；设备连通不自动将第三方渠道、子代理或中继提升为设备管理者。

**待验证**

- 重送去重、同键异内容拒绝、同线程单批次、跨线程独立推进、旧 policy 响应失效、超时重排。
- 群组未 @ 不创建任务；允许名单内的机器来源不升级身份；已订阅的补充不重复受理任务；缺失或伪造的来源标注不触发停止任务。
- 真实模型在自然语言下的委派选择，以及安装版的用户路径。
- 每个真实渠道须用对应账号验证，协议测试不能替代。
