# SuperAgent 入口与研判

本文维护统一入口管线的来源核对、准入与研判规则。渠道适配器的事实标注字段、来源类型枚举及原生概念映射只在[链接与渠道](链接与渠道.md)维护，领域记录字段见[服务契约](服务契约.md)。

## 入口与两档分流

按噪音与来源性质分档，不按渠道名一刀切。适配器只提供经过协议校验的来源证据、身份映射和事实标注；来源是否可信、是否属于主人、聊天范围与 policy 的判定归统一管线，正文不能自报身份、替人授权或覆盖来源。

渠道入口的固定顺序为：来源核对（身份、聊天范围）→ 归一 → 准入 → 研判（接 / 挂 / 停 / 略）。来源核对使用适配器提供的身份与会话证据，先于消息格式归一；归一由适配器完成，核对、准入与研判由统一管线完成。通过管线的消息才成为 Trigger，交统一 Router 分诊；渠道不直接开单或维护独立接单逻辑。聊天范围以适配器给出的会话标识匹配允许名单，规则使用统一来源类型枚举，不引用飞书等渠道的原生来源概念。

| 入口 | 已定处理 | 当前实现边界 |
| --- | --- | --- |
| 桌面主聊、旁聊 | 用户主动输入直通 Router，完整保留原文；登记 Trigger、去重，跳过“是否接单”的 Eval | 已使用 direct 登记；仅 Router 拟新开单时核实范围，见下节；成功 assistant_delegate 后写 candidate、decision、ticket，不能以桌面无 candidate 直接诊断分诊停摆 |
| 已验证主人私聊 | 不做高噪音窗口裁剪，仍走统一来源核对、归一、准入与研判，通过后由 Router 分诊 | 统一管线与适配器职责拆分已接线；真实平台账号路径须分别验收 |
| 群组、话题、系统事件 | 统一来源核对、归一、准入、研判，通过后交 Router；适配器不得按来源类型自行过滤 | 渠道入口已有实现，真实来源逐渠道验收；抓取和截图等图示不等于已有连接 |
| 已订阅工单的跟进 | 原范围内补充、调整与插话即原单修订，持久收件后在下一安全执行边界自然接收；暂停期间只收修订、不自动恢复 | 已接统一输入账本与原执行工具批次切换；不附带新权限，仅超 Mandate 扩权才确认新授权版本，跨入口行为须分别验收 |
| 定时事件 | 官方 Schedule 触发，按已授权规则形成机器 Trigger | 纯提醒可直接回复，执行型任务仍建单；按来源会话、scheduleId、occurrence 去重 |
| 非主人私聊 | 同走统一管线，按独立身份和当前规则判定 | 不能当桌面主人；具体可执行范围不得由适配器或正文自行扩大 |

统一管线对来源类型为“群组”的新事项默认要求实际 @，并复核名单、会话范围与准入强度；未 @ 的讨论可作订阅参考，不能据此自行建单。适配器只报告 @ 等事实，不决定放行或丢弃。允许名单内机器消息可进入 inferred，但仅在 auto 模式及有效书面规则下开单。平台成员允许使用机器人，不等于获得桌面主人权限。

高噪音窗口使用确定性卡片与原文指针：初始口径为线程头 5 条、触发前后各 5 条，长文标明全长与裁剪，按需回读；不先用模型摘要替代唯一原文。主人直聊“不压缩”指入口不做这种窗口化，不禁止长期会话使用宿主上下文整理。

## 桌面拟新单的范围核实

桌面消息仍直接进入原 Router，不逐句调用额外分类器。仅 `assistant_delegate` 准备新建工单时，在原 admission 内检查拟派范围；已建工单的幂等回执、原单挂靠及可信人端表单保留各自原校验，不增加一次新事项分诊。普通提问、直接调用只读工具与日常对话不触发此检查，也不创建新 Agent、Session 或第二条 Router 回复路径。

输入只包含当前真实人类消息原文、该消息明确引用且经原会话归属和要求版本核实的工单上下文、拟派事项及验收条件，以及当前 Agent 实际可见、注册定义仍有效的只读产品能力。历史调查、模型自行总结的意图及拟派文本不能产生新授权；显式引用只是理解材料，是否继续仍由当前原话决定。无法核实的引用明确不可确认，不回读无关聊天来补授权。

检查仅返回范围结论：符合当前明确请求的实际调查、文件工作或实现等沿原路径建单；纯产品状态查询退回同一 Router，按工具回执调用现有只读能力后直接解释；范围增加或证据不足返回不可确认，未创建工单。Link 的授权设备、记录访问时间及实时在线是否可知属于产品状态；未知或服务不可用不能自动扩大为网络扫描。用户明确要求局域网、远程登录或系统网络调查时仍正常派工，不按设备、连接等关键词阻断。判定不是工具执行、用户审批或新的 Mandate 授权，原宿主与高危动作权限门继续生效。

模型调用复用 `collectAuxiliaryText` 的 `review` 路由：启用辅助 `review` 时使用配置的辅助队列，按现有规则退回 Router 队列；未启用时使用 Router 队列，不使用 Worker 路由，不另加回退策略。请求不开放工具，受 30 秒总期限约束；不能完整核实输入、模型失败、超时或无效响应时明确未完成，不默认放行，也不由检查器代答用户。

判定留在同一 `assistant.db` 的小型范围审计表，绑定真实 session/thread、人类 message、turn、requestId、拟派 payload 与原指令摘要、策略/路由、能力清单及显式引用摘要；不复制会话全文。只复用完全一致绑定的已完成判定，落单前再次复核当前指令、能力、引用和策略。改变请求内容或人类消息不能复用原 requestId；暂时失败可由原调用重试同一 requestId，保留每次失败证据，仍须重新完成检查，不自动无限重试。成功开单的 Mandate 保存对应判定绑定，幂等回执保留来源 Trigger。

上述服务端接线及官方 AgentLoop 脚本模型定向测试已覆盖产品问句变体的“派工退回→同回合设备工具→零新单”、明确网络调查正常建单，以及来源、版本、幂等、失败和取消边界。脚本模型只验证管线与领域行为；真实模型对自然语言和既有历史的判断仍须安装版另验，不能以该测试宣称语义验收已通过。

## 候选研判与决定

候选按 Thread 攒批，同线程最多一个活跃 Eval，跨线程独立推进。先排除已由订阅持有的上下文与已开单 Trigger。研判只给建议，代码复核身份、policy、规则、范围与版本后才能提交 Decision。

新候选结果使用 accept、answer、ask、ignore，已有工单使用 attach、stop、revise；已结束工单的关联调整使用 adjustment，删除旧 reopen 别名。handback 是独立处置；这些协议值不代表渠道自行研判或直接开单。inferred 接单必须满足 auto 和所引规则全部启用，旧 policy 返回不得落单。Eval 超时最多重排 2 次，再失败保留 unavailable 和重评入口，不把队列等待当模型超时。

渠道研判的“停”只认统一来源类型为“私聊”、且发送者经来源核对确认为主人本人的事件，同时仍复核目标工单归属与当前权限。群组、话题和系统事件中的停类内容仅提请 Router 注意，不直接停单。此判定依赖适配器逐条提供可信的来源类型、发送者和会话/话题标识；缺失或不能证实的标注不能推断为主人私聊。事实标注及映射权威见[链接与渠道](链接与渠道.md)。桌面用户直接叫停、系统撤权及规则收紧继续遵循既有动作边界，不由本条渠道研判规则替代。

已有工单的普通修订不重新走“是否接单”的候选研判，不要求额外确认或先停止执行；要求版本只是后台顺序与防迟到编号。叫停或撤权立即传到动作边界拦截，不等待下一次 Eval。具体工单控制见[任务与执行](任务与执行.md)。本节 Assessment 只负责入口准入与新事项研判，不承担任务结果内容验收；取消独立任务验收不删除这条入口链路。

同线程新消息沿既有批次顺序处理，跨线程请求独立推进；单线程失败不阻挡其他线程提交。停止服务取消在途研判并拒绝迟到结果。policy 更新使旧评估失效，重评仍须遵守当前规则。

编辑、撤回与迟到上下文作为关联事件补齐，不覆盖不可变 Trigger；窗口裁剪保留稳定原文指针。机器事件不能通过伪造 @ 升为人类 explicit 请求。

## 实现与验收边界

桌面 direct Trigger、候选与决策持久化已有实现。渠道入口已统一来源核对、懒归一、准入及研判授权：归一前核对身份与范围，归一后复检连接版本，规则只使用统一来源类型；私聊主人“停”复核可信证据与原单归属，其余来源只提请 Router。准入前拒绝的事件不登记领域 Trigger；候选所需原文以 `pending` 阶段保存于原输入行，研判通过后同 ID 提升为领域 Trigger，忽略/拒绝保留原始审计。内部原文读取与对外 Trigger API 分开，阶段、旧记录与迁移契约见[链接与渠道](链接与渠道.md#实现与验收边界)。自由发现任务仍待实施。

普通插话即修订、后台编号、原 Assignment/Run/session 续做、下一工具批次整份切换、暂停只收及超 Mandate 才确认已完成服务端接线；修订前停止或版本确认不作为普通用户流程。跨入口修订和运行中重启应分别验收，具体机制见[任务与执行](任务与执行.md#实现与验收边界)。

验证重送去重、同键异内容拒绝、同线程单批次、跨线程独立推进、旧 policy 响应失效与超时重排。验证适配器不按私聊/群组/话题自行过滤，来源核对先于归一，聊天范围与准入使用统一标注；群组未 @ 不新开单、允许名单机器来源不升级身份、已订阅补充不重复接单。补验只有经核对的主人私聊可研判为“停”，群组/话题/系统事件仅提请 Router 注意，缺失或伪造标注不得触发停单；真实渠道行为须用对应账号验证。

另验原单普通调整不重复建候选、不弹确认、不先停跑，下一安全边界接收且不混入其他工单；暂停收修订后仍暂停，叫停/撤权立即阻断后续动作，只有扩权才申请新 Mandate 授权版本。
