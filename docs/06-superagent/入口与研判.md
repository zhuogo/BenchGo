# SuperAgent 入口与研判

本文维护统一入口管线的来源核对、准入与研判规则。渠道适配器的事实标注字段、来源类型枚举及原生概念映射只在[链接与渠道](链接与渠道.md)维护，领域记录字段见[服务契约](服务契约.md)。

## 已敲定的身份边界与当前差距

2026-11-11 已敲定：核心引擎不区分主人、普通使用者或其他人的权限档位。飞书等渠道是否开放给其他人、允许哪些来源和操作，由对应适配器的权限配置、准入和撤权负责；共享能力可复用，但不将渠道身份规则变成整个引擎的硬条件。核心只消费可信准入结果、来源关联及对应渠道的有效授权。会话与工单归属、原始输入引用、实际动作审批仍是独立职责，Router/Worker 是工作分工而非使用者等级。

渠道人员、机器、群提及和来源范围已集中于渠道专用共享策略 `channel-policy.mjs`，`assessment-policy.mjs` 委托该策略处理渠道身份，`intake.mjs` 仍在共享渠道入站路径调用它。该路径只处理外部渠道，桌面主聊和手动旁聊不经此准入，不是整个引擎的使用者等级门。共享代码集中不等于适配器入口迁移完成；来源核对、准入、撤权与按需研判应由对应适配器入口调用共享能力后输出可信事件，核心不再解释渠道身份等级。渠道版本分别核对，其他渠道配置变化不使本渠道任务失效。已准入输入继续保留真实来源、工单归属与官方审核边界，真实平台路径仍须验收。

## 入口与两档分流

按噪音与来源性质分流；适配器校验协议、来源身份和渠道权限。飞书等高噪音群组的研判按需放在对应适配器入口，可复用共享研判能力，不在核心重新区分主人与其他使用者。正文不能自报身份、替人授权或覆盖可信来源。

渠道目标顺序为：适配器内来源与权限核对 → 消息归一 → 按需研判 → 可信入口事件 → Router 分诊。通过入口的消息才交 Router；核心不重读渠道人员名单或叠加身份等级，渠道不直接开单或维护独立工单逻辑，Router 派工后不再复审。下表及后续统一准入细节保留当前接线说明，以本节新边界为迁移目标。

| 入口 | 已定处理 | 当前实现边界 |
| --- | --- | --- |
| 桌面主聊、旁聊 | 用户主动输入直通 Router，完整保留原文；登记 Trigger、去重，跳过“是否接单”的 Eval；Router 自主决定派工，无二次模型复审 | 已使用 direct 登记；派工范围复审已撤除，见下节；成功 assistant_delegate 后写 candidate、decision、ticket，不能以桌面无 candidate 直接诊断分诊停摆 |
| 渠道适配器已准入的私聊 | 不做高噪音窗口裁剪；经适配器核对来源和本渠道权限后由 Router 判断意图，不设普通派工复审 | 当前仍接统一渠道研判管线；适配器入口准入与按需研判的拆分待实施，真实平台账号路径须分别验收 |
| 群组、话题、系统事件 | 对应适配器核对来源、归一与准入后，按需调用共享模型研判，通过后交 Router；不在主调度层再审派工 | 当前研判仍在统一渠道管线，适配器入口接线待实施；真实来源逐渠道验收，抓取和截图等图示不等于已有连接 |
| 已订阅工单的跟进 | 原范围内补充、调整与插话即原单修订，持久收件后在下一安全执行边界自然接收；暂停期间只收修订、不自动恢复 | 已接统一输入账本与原执行工具批次切换；不附带新权限，仅超 Mandate 扩权才确认新授权版本，跨入口行为须分别验收 |
| 定时事件 | 官方 Schedule 触发，按已授权规则形成机器 Trigger | 纯提醒可直接回复，执行型任务仍建单；按来源会话、scheduleId、occurrence 去重 |

渠道准入策略对来源类型为“群组”的新事项默认要求实际 @，并复核名单、会话范围与准入强度；未 @ 的讨论可作订阅参考，不能据此自行建单。适配器报告 @ 等事实并复用渠道策略；按需模型研判不能替代渠道边界对身份、范围与规则的核对。允许名单内机器消息可进入 inferred，但仅在 auto 模式及有效书面规则下开单。本渠道准入不授予其他渠道、会话或工单的访问权限，也不产生核心使用者等级。

高噪音窗口使用确定性卡片与原文指针：初始口径为线程头 5 条、触发前后各 5 条，长文标明全长与裁剪，按需回读；不先用模型摘要替代唯一原文。主人直聊“不压缩”指入口不做这种窗口化，不禁止长期会话使用宿主上下文整理。

## Router 派工决定与宿主边界

桌面主聊、旁聊的真实用户输入直接进入 Router；Router 根据当前请求、相关对话上下文及可信问答回执决定直接回答、跟进原单或新建工单。普通派工不经过第二个模型的范围复审，不新增语义裁决、复审等待、复审缓存或复审审计依赖；不把群组降噪机制套到主调度层，也不保留开关或兼容双轨。

“再来一次”“按刚才的方案”等依赖上下文的指令由 Router 在原对话中理解。官方问答卡经宿主核验的真实用户答复应作为有效输入，保留问题与答案绑定，不因其不是普通文字消息就要求重写完整指令。只有影响目标、实际扩大授权或存在关键歧义时才向用户确认；历史助手摘要、模型提案与外部正文不能自行产生新授权。

宿主继续确定性核对当前真人来源、根 Agent 与会话归属、原指令引用、requestId 幂等、项目与模型配置、规则及版本；模型不能自报 owner 或伪造确认。已建工单回执、原单挂靠及可信人端表单复用同一接单服务，保留原校验；同 requestId 异内容拒绝，原单归属不匹配拒绝。工单保留原始来源、任务、验收与 Mandate，删除仅供派工范围复审使用的运行路径及存储接口；旧审计数据仅保留为惰性历史证据，不再建表、读写或参与准入，不另加迁移或兼容双轨。

产品状态查询优先使用当前可用只读能力，环境调查交 Worker，由 Router 依实际请求判断；未知产品状态不自行扩成系统扫描。派工决策权不替代 Worker 的工具范围、宿主沙箱、真实扩权确认或高危动作审批，停止及撤权仍在真实动作边界生效。

派工范围复审及专用提示词、能力目录与存储接口已删除，不保留开关双轨；官方问答输入已复用原 call/questions 绑定校验。定向测试覆盖零额外模型请求、上下文短句重试及即时/迟到卡片答复可建单，来源伪造、跨会话、同键异内容、配置变化与取消仍由原宿主边界拒绝。真实模型的自然语言选择和安装版用户路径仍须实际验收。

## 候选研判与决定

候选按 Thread 攒批，同线程最多一个活跃 Eval，跨线程独立推进。先排除已由订阅持有的上下文与已开单 Trigger。研判只给建议，代码复核身份、policy、规则、范围与版本后才能提交 Decision。

新候选结果使用 accept、answer、ask、ignore，已有工单使用 attach、stop、revise；已结束工单的关联调整使用 adjustment，删除旧 reopen 别名。handback 是独立处置；这些协议值不赋予渠道直接开单权，适配器入口按需研判复用本节规则，提交仍由统一服务核验。inferred 接单必须满足 auto 和所引规则全部启用，旧 policy 返回不得落单。Eval 超时最多重排 2 次，再失败保留 unavailable 和重评入口，不把队列等待当模型超时。

渠道研判的“停”只认统一来源类型为“私聊”、且发送者经来源核对确认为主人本人的事件，同时仍复核目标工单归属与当前权限。群组、话题和系统事件中的停类内容仅提请 Router 注意，不直接停单。此判定依赖适配器逐条提供可信的来源类型、发送者和会话/话题标识；缺失或不能证实的标注不能推断为主人私聊。事实标注及映射权威见[链接与渠道](链接与渠道.md)。桌面用户直接叫停、系统撤权及规则收紧继续遵循既有动作边界，不由本条渠道研判规则替代。

已有工单的普通修订不重新走“是否接单”的候选研判，不要求额外确认或先停止执行；要求版本只是后台顺序与防迟到编号。叫停或撤权立即传到动作边界拦截，不等待下一次 Eval。具体工单控制见[任务与执行](任务与执行.md)。本节 Assessment 只负责入口准入与新事项研判，不承担任务结果内容验收；取消独立任务验收不删除这条入口链路。

同线程新消息沿既有批次顺序处理，跨线程请求独立推进；单线程失败不阻挡其他线程提交。停止服务取消在途研判并拒绝迟到结果。policy 更新使旧评估失效，重评仍须遵守当前规则。

编辑、撤回与迟到上下文作为关联事件补齐，不覆盖不可变 Trigger；窗口裁剪保留稳定原文指针。机器事件不能通过伪造 @ 升为人类 explicit 请求。

## 实现与验收边界

桌面 direct Trigger、候选与决策持久化已有实现；本轮派工范围复审及其活跃依赖已撤除。渠道身份、来源范围与准入规则已收敛到渠道专用策略 `channel-policy.mjs`，入站编排复用该策略并保留来源；核心通用政策不再区分主人与其他使用者。高噪音候选仍复用共享研判，实际平台路径须分别验收。现有渠道入口已统一来源核对、懒归一、准入及研判授权：归一前核对身份与范围，归一后复检连接版本，规则只使用统一来源类型；私聊主人“停”复核可信证据与原单归属，其余来源只提请 Router。准入前拒绝的事件不登记领域 Trigger；候选所需原文以 `pending` 阶段保存于原输入行，研判通过后同 ID 提升为领域 Trigger，忽略/拒绝保留原始审计。内部原文读取与对外 Trigger API 分开，阶段、旧记录与迁移契约见[链接与渠道](链接与渠道.md#实现与验收边界)。自由发现任务仍待实施。

普通插话即修订、后台编号、原 Assignment/Run/session 续做、下一工具批次整份切换、暂停只收及超 Mandate 才确认已完成服务端接线；修订前停止或版本确认不作为普通用户流程。跨入口修订和运行中重启应分别验收，具体机制见[任务与执行](任务与执行.md#实现与验收边界)。

验证重送去重、同键异内容拒绝、同线程单批次、跨线程独立推进、旧 policy 响应失效与超时重排。验证适配器入口研判不能绕过统一身份、范围与规则服务，来源核对先于归一，聊天范围与准入使用统一标注；群组未 @ 不新开单、允许名单机器来源不升级身份、已订阅补充不重复接单。补验只有经核对的主人私聊可研判为“停”，群组/话题/系统事件仅提请 Router 注意，缺失或伪造标注不得触发停单；真实渠道行为须用对应账号验证。

另验原单普通调整不重复建候选、不弹确认、不先停跑，下一安全边界接收且不混入其他工单；暂停收修订后仍暂停，叫停/撤权立即阻断后续动作，只有扩权才申请新 Mandate 授权版本。
