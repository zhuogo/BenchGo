## 消息边界

### 普通问答无回复修复（2026-11-03）

前版将 `assistant_reply` 作为唯一发布通道，普通模型以标准文本正常结束时，答案被当作过程过滤。这是发布协议过窄的产品缺陷；测试提示用户必须调用工具掩盖了真实使用路径。

修正为两种正式出口：显式 `assistant_reply`，或官方 `turn/end.reason.kind=completed` 确认的当前人类请求最后一条无工具调用的助手终答。后者直接从官方持久日志投影，不增加模型请求或重复存储。只取同一 turn，显式发布优先且每请求一条；工具前说明、思维链、原始工具返回、失败/取消/截断回合、无新用户请求的后台续行均不晋升为终答。历史已完成的普通回答也按同一结构规则恢复展示，不重跑模型。

验收必须使用普通问法（如“你是什么模型？”），不要求用户知道发布工具。

主聊和旁聊统一使用 SuperAgent 模型设置；旁聊只隔离主题与上下文，不支持独立模型队列。删除 threadConfig 与 assistant_config 的 thread scope；历史线程 models 在状态加载迁移时清理，不影响其他线程字段、会话记录或工单明确指定的执行模型。辅助操作同样跟随统一主模型与用途配置。

chat 仅展示用户消息、主助手正式回复、已验收交付、审批、attention 和已复核主动消息。工具调用、原始返回、Worker 原始摘要、过程文字默认不发布。思维链、系统提示、凭据不得进入 chat 或活动明细。发布入口由代码校验类型、来源、当前用户请求/工单版本和唯一键，不能只靠提示词或 CSS 隐藏。

主助手正式回复通过明确发布协议进入聊天；沿用官方会话存储持久化，不复制推理循环。发送、取消、审批、问题回答继续复用现有入口。主聊天不直接渲染官方原始执行记录，原生输入组件在可行时保留。

2026-11-04 派工回复调整：Router 同时承担正常聊天与总调度。桌面派工工具成功返回后，由当前 Router 根据对话自行组织回复，沿用正常文本终答或 `assistant_reply`，不套固定句式、不等待 Worker，宿主不再另发固定接单确认。渠道显式人类请求的接单回复复用同次 Router 研判生成的 `replyText`，开单复核成功后经持久 outbox 投递；没有正文时不补固定模板，旧固定待发回执不再投递。后台主动通知的少打扰规则不限制用户正在进行的聊天。

主聊与旁聊应用同一发布白名单和模型配置。旁聊保留独立上下文，任务、attention、交付只回原旁聊；main 不再隐式包含其他 threadRefs。跨会话汇总必须另有明确用户请求，不因身份统一自动合并。

## 主动与工作记录

已实现路径复用官方调度器：用户明确委派的定时任务进入工单，后台结果经来源、授权、版本、取消和重复交付复核后发布。一次性 Schedule 触发后 inactive 不代表结果过期，不应吞掉用户要求的交付。

尚未开放自由主动候选、新机会推送与安静时段/类别偏好；当前没有通用候选复核服务，身份名片中的 proactive 声明也不是通知授权。后续开放此入口前，必须接入最新对话与记忆、实时状态、有效期和用户偏好检查，skip 时零通知。本次不增加无入口的占位框架。

活动按今天/昨天/更早分组，状态、时间线、证据和产物按需展开，支持查看与停止。保留 Upcoming/Goals/成果入口，不新增平行任务库。动作记录可查，不展示内部推理或凭据。

## 接口与存储

`engine.history` 提供受控会话投影；`service` 将当前来源的通知合并进 history。`runtime-store` 的桌面和设备发送队列复用同一通知白名单。非法历史待发记录持久标记为 suppressed，不发送、不阻塞新通知；原始日志作为审计数据保留。

`ticket-review` 与 `review-continuation` 使用同一 delivery 契约，`orchestration-runtime` 发送前重核授权与版本。外部渠道不支持选项卡时，将选项作为可回复文本降级；不改变审批含义。源码、MCP 说明与 OpenAPI 同步，证据集中 `eval/`，发布由 `reload:plus` 重建，不重启 Web。

### 主聊天正式发布协议（已实现）

Router 可使用 `assistant_reply({text})` 显式发布正式回复。宿主绑定当前真实用户消息 ID，正文非空且最多 16000 字符；每个请求最多一条，同文重复幂等、不同正文拒绝。记录使用官方 `appendPluginRecord` 写入 `plugin:benchgo-plugin/chat-publication`，不另建聊天数据库。正常文本终答使用上文 completed 回合投影；单独的 assistant/message、流式片段和工具结果不足以构成发布许可。

`history` 先对完整日志执行白名单投影，再分页；只持久输出用户内容和有效终答，保留稳定游标。生成中的正式正文使用官方顶层 assistant_reply 或 partial.blocks text 实时投影，绑定 session/turn/request；它是暂存正文，completed/正式 publication 后才由持久终答替换，失败/取消清除未提交内容。engine 自身订阅不转发推理或原始工具流，前端复用官方会话实时源；审批与 Attention 沿用各自正式协议，文本不授予权限。

正式发布成功后使用官方 concludeTurn 结束当前回合，避免为发布后的空回执再调用模型。发布投影与引擎回归 59/59 通过；发布结束回合的追加定向验证 2/2 通过。

## 选项回复约束

交付选项紧随普通助手正文显示，点击只发送选项原文作为普通用户意愿，不产生审批授权。notificationOption 从持久通知读取可选文字，核对原 thread、当前工单 instructionRevision/resultVersion 和工单状态；过期通知拒绝。使用 notification-option:<eventId> 作为官方发送幂等键，同一选项重试不重复发送，不同选项不能覆盖首次选择。界面错误可见，可继续使用普通输入表达新意愿。

P0 已保留选项关联：有 attentionId 时可信读取原问题并用 ticketAnswer 绑定工单/问题/版本保存答案；其他选项经持久 send 携带可信 replyContext（eventId/ticketId/原问题及版本），不将裸“继续”丢给 Router 猜工单。系统状态不是 Attention，不伪造可回答问题；过期、已回答、停止或版本不符拒绝。模型不能靠选项文字扩大原授权，其他渠道问题关联仍待逐一接通。

统一模型配置已实现：旧旁聊覆盖落盘迁移，旧 thread scope 的持久动作拒绝执行，防止误改全局配置。定向模型/迁移验证 4/4，store 与辅助操作回归 19/19。
