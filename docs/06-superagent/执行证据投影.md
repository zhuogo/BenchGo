# 执行证据投影

2026-11-04 目标补充：按[任务结果验收矩阵](任务结果验收矩阵.md)区分成果与证据。纯文本/新闻任务的正文可以直接成为成果，URL、报道时间、抓取记录等是证据；checkpoint 只描述文件/环境状态，0 文件不代表没有成果或未执行。文件和代码任务也不能仅凭 checkpoint hash 判定质量。

2026-11-03：修复结果只有摘要与日志 hash、验收模型无法读取真实工具结果的问题。

宿主从官方 Session 的 `assistant/message` 工具调用与 `tool/result` 生成 `toolEvidence`，包含调用 ID、工具原名、事件序号、参数与结果文本、错误标记及完整条目 hash。思考内容、图片和二进制不复制到验收上下文。投影有总量和单项长度边界，截断必须显式标识，不能把遗漏当作检查通过。原始日志仍由 Session 持久化，不创建第二套日志库。

正常执行将投影随结果包提交；只读重审在持有官方会话锁且核对原始日志 hash 后重新生成投影，旧结果包可获得原日志已有的工具证据，不重新运行 Worker 或重复副作用。已保存的投影若与日志不符，拒绝恢复。

2026-11-04 源码校对补充：`review-evidence-reader.mjs` 已支持验收内部按真实工具结果序号补读正文，先校验当前提交的 `sessionId`、`lastSeq`、日志 hash 和摘要完全一致。索引最多返回最近 256 项并注明遗漏数；正文默认每页 4000、最多 8000 字符，参数最多 2000 字符，返回原长度、截断标记与 `nextOffset`。它只读取当前执行的官方日志，不能任意读取其他会话或主机文件。

`ticket-review.mjs` 通过内部 JSON `readEvidence` 申请补读，每次最多 8 页，单次验收最多 4 轮模型决策（前三轮可补读，第四轮必须给出结论；模型路由重试另计）。证据读取失败或达到轮次上限仍无可靠结论时返回 `wait`，不能把截断当作证据不存在。可在原授权内修正的问题返回 `rework` 交 Worker 处理，真实用户权限、信息或范围问题才进入询问。

后续补齐：联网证据保留原 URL、来源/转载关系、页面中的报道时间、可信抓取时间和失败原因。报道时间与抓取时间分别标注；同稿转载不计为独立多源，只有 URL 而没有读取到正文不能算已核验。未能验证的标注“单一来源/待确认”，不为通过验收编造证据。投影截断时先分页补读，确需新增抓取才进入原单续做。

这是证据载荷补齐，不改变 Router 验收职责或代码关闭门禁；工具调用成功本身也不代表目标完成。此载荷属于已有结果对象，无新增 MCP 工具或 HTTP 路由。
