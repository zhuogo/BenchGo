## 契约

Worker 执行、自检并交付结构化结果及实际工具证据；Router 对照目标和验收标准研判；宿主代码复核授权、任务/执行归属、目标版本、必要检查和待应用消息后决定关闭。ready、idle 和模型 passed 均不能绕过代码校验。工具执行历史中的失败不一律等于最终失败：允许修复重试，最终结论须有对应证据。

验收条件由用户目标决定，不以产物文件作为通用门禁。新闻摘要等纯文本成果可以仅由正文和可追溯的联网证据组成，checkpoint 0 文件合法；只有目标要求文件/代码/UI/媒体成果时才检查相应产物。不能因搜索工具失败而否定已成功抓取的替代来源，也不能只看 Worker 的“已验证”标签就通过。

可修复的本轮失败由 Router 说明原因并自动原单续做；需要用户的信息、权限或范围决定才建立 Attention，回答后继续原单。验收服务或证据读取故障属于内部待核验，不让用户确认新闻真假或同意补证。P0 已接 failed/rework 自然正文、原 Assignment/Run/session/工作区续做与桌面/飞书 Review Attention；不以固定修正次数终单。内部 review_wait 与资源 continuation_wait 分开，真实闭环仍待验收。

结果证据复用官方会话事件、产物 checkpoint 和现有 ID 账本，使用有界内容及追溯引用，避免整段日志重复注入。缺证据先从已有执行记录补取，不重新执行副作用；重审相同结果不应形成无界模型循环。自由文本质量仍需语义验收，hash 不能证明任务质量。

当前只读重审先核验原日志和适用的产物，再比较验收输入指纹（目标、标准、授权、证据、所选模型及路由配置）。若与上次 wait 完全一致且非可重试/预算等待，返回既有结果并标记 unchanged，不再次调用模型、递增结果版本或重复投递；预算不足导致的 wait 允许预算调整后重试。这是防重复核验机制，不能充当补查、纠错或回答后的续做。需要改变证据时应由 Router 在原授权内安排原单继续，而不是反复要求用户改任务。

现有 Router 权限门禁、准入复核、订阅直达、批量研判、lease/fence 和原子 outbox 保留并回归，不新增并发限流或编排框架。订阅不授予额外权限。

## 主辅模型用户路径

在「资源 → 身份 → 模型」同页配置主模型、辅助模型及各自首选/备用顺序。复用现有 auxiliary 协议；看图、上下文压缩、总结、研判与复盘四项用途分别勾选，研判与复盘涵盖接单、成果验收和学习。未配置或未勾选跟随当前主模型；主聊与旁聊共用此设置。保留不透明模型 ID、显式选择和其他配置，验证保存、重载、真实路由一致。沿用 BenchGo 品牌和现有组件，不新增安装包。
