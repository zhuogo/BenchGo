# SuperAgent 自校验与交付

本文维护 Worker 自校验、结果落单、Router 表达交付、问题回路与投递关单；执行与普通修订见[任务与执行](任务与执行.md)，聊天呈现见[对话交互](对话交互.md)。实现边界与验收条件见文末。

## 工单三态与简短摘要

2026-11-10 已实现并通过定向验证，真实安装版闭环仍待验收：Ticket 持久化业务状态及对用户、AI 的返回值仅有 `running` / `waiting` / `completed`（进行 / 等待 / 完成），不只在界面合并，也不再保留其他工单状态分支。旧 `open`、`failed`、`paused`、`pausing`、`cancelled`、`cancelling`、`closed` 等只作一次性迁移输入，不保留永久兼容双轨。暂停、停止请求与确认采用独立机械布尔字段 `executionControl: { pauseRequested, paused, stopRequested, stopped }`，不将旧 status 改名搬家；等待原因与恢复条件另记；Assignment、Run、Outbox 的机械状态继续用于恢复、授权及防重复副作用。

| 业务状态 | 条件与呈现 |
| --- | --- |
| 进行 | 已接单并正常排队、正在执行或自动保存结果；成功结果持久化后退出进行，表达和发送重试不占执行状态 |
| 等待 | 无法自主解决的真实阻塞，或需要用户答复、授权及审核；明确暂停、停止按原控制保留，一段简短说明写清原因和下一步 |
| 完成 | 官方 Harness 正常结束，当前要求的成功结果持久化后直接完成，交付状态另列；失败报告、人工整理标记或停止确认均不能冒充成功 |

正常调度排队、容量暂占及已有结果的自动持久化属于 `running`，用短进度说明所在环节，不要求用户额外继续。失败只作为一次执行的结果保留；结构性失败报告送达后工单仍为等待，保存已有成果、尝试与恢复条件。等待须说明所缺条件以及用户补充、决定或明确继续的入口；条件没有变化时不重复执行。看门狗发现停滞后报告实际观察，不仅凭超时推断任务成功或失败。主动停止通过独立控制记录保持取消请求与确认语义，业务展示为等待并标注已停止，必须真实用户明确继续且复核授权，不能自动唤醒。

### 等待的有效范围

`waiting` 只表达当前不能自主推进的具体原因，不能作为任何内部异常的兜底状态。以下为状态判定的权威清单；列表、详情、Router 查询与恢复入口复用同一事实，不由客户端根据摘要推断。

| 情况 | 状态与下一步 |
| --- | --- |
| 缺少真实用户信息或待回答原问题 | 等待；保留原问题及作答入口，答案回原单 |
| 待动作审批、秘密输入或人工接管 | 等待；保留同一真实交互及入口，不以模型回答代替批准 |
| 用户明确暂停、停止或撤销执行授权 | 等待；区分请求已生效与执行端实际暂停/退出，不自动恢复 |
| 当前模型、配置、能力或授权确实不可用，系统不能自行恢复 | 等待；说明实际错误、恢复所缺条件及调整入口 |
| 执行异常中断、失联或在途外部效果未知，无法安全继续 | 等待；保留首因和原会话，核实后由用户明确续接，不盲重跑 |
| Worker 明确报告无法完成的失败结果 | 等待；保留原稿、已有成果与恢复条件，允许原单调整 |
| 正常排队、执行、后台任务或有界自动退避 | 进行；显示当前实际活动，无需用户点击继续 |
| 已正常结束，原稿正在自动补存 | 进行；内部自行收尾，不能因证据差异或重试次数转等待 |
| Worker 已正常结束、成功原稿已保存 | 完成；工具效果诊断、旧核验批次或会话尾标记不得降为等待 |
| Router 表达、通知或投递失败/效果未知 | 保留执行状态，独立记待交付；只恢复对应阶段 |

“正常结束”依据官方回合的真实完成原因及成功结果；仅会话句柄释放、工具结束、子 Worker 返回、失败报告或部分正文不构成整单成功。外部效果未知仍如实写在结果中；它约束后续动作是否可重放，不建立正常结束后的第二道结果审核。

### 删除、调整与实现边界

- 删除：独立结果效果审核、核验专用领取与轮询、缺自检强制补回合，以及证据差异/重试上限导致永久 blocked 的结果接纳分支；不恢复旧核验执行链。
- 调整：成功原稿保存与执行完成、Router 表达、原来源送达分别记账；hash、版本和身份用于追溯关联，不拒收已有原稿，不覆盖较新结果，也不替代真实执行结束原因。
- 开发处理：旧核验租约与真实执行身份的一次性迁移、正常结果自动补存、迟到及重复原稿保留、停止确认恢复和上述等待来源的回归验证。具体实现及验证状态在文末维护，前端多气泡、活动指示与顶部身份见[对话交互](对话交互.md)。

旧版核验曾推进 Assignment/Run 的 fence，同时保留原执行的 executionFence/executionOwner。迁移须将原执行退出确认与可信原 Run 绑定，不要求一个仅用于核验的新 fence 产生执行退出回执；不修改原始会话日志、不伪造执行成功。官方会话在正常回合后追加的 `session/end-seed` 等生命周期标记不代表新任务，也不能单凭全日志 hash 改变而否定既有成果。

正常完成先于后来停止请求时，已有可信完成时间、同一要求和真实成功原稿的结果仍按完成收尾，不因用户随后整理或归档时发出的取消而倒退。没有可靠时间或原执行实际取消时，保留停止控制和已有成果，不猜测成功。

默认读取三态与一段简短摘要（界面至多 240 字、AI 列表至多 320 字）：进行说明当前进展，等待说明原因、恢复条件和下一步，完成说明做了什么、结果及限制；成果与证据仅保留指针，按需读取，不把全文报告塞入 Router 默认上下文。状态和结果事实使用已有结构记录，AI 不仅凭摘要文字猜测成功。Router 收到绑定结果的表达信号后可按需读取原稿形成正式回复；这不扩大日常工单查询上下文。

完成项保留在完成分组，分组内沿用最近活动排序，保留同一执行会话、消息和成果入口。完成与停止均不自动归档或隐藏，查看不自动恢复执行。用户主动归档仍走既有管理入口。

## Worker 轻量自校验

每次派工固定附带要求：“完成任务后，先按本工单要求做一次快速轻量自校验，优先运行适用的机械测试、构建和输出检查，修正明显错误和漏项，通过后才可报告执行完成；不能解决的如实报告受阻或失败。”这一步由原 Worker 在原执行上下文完成，不新增自检 Agent、独立模型评分或后台语义验收，也不把结果送回 Router 审内容。

自校验以当前原始用户要求和已应用的跟进为准，派工摘要不能删去显式步骤、数量、格式、来源与必要验证。轻量指不额外扩大检查范围；用户要求的测试、浏览器操作或其他验证仍须实际执行，不能以自述“已自检”代替。明显问题在原单内修好；无能力解决时保留已有成果和真实原因，不能凑数或谎报完成。

| 任务类型 | 快速检查重点 |
| --- | --- |
| 文本、查询、调研 | 主要问题、数量和格式是否覆盖，事实与来源是否明显冲突；联网结论区分来源时间、抓取时间及未核实内容，允许零文件 |
| 文件、代码、UI、媒体 | 所要求成果是否存在、可读，显式要求的必要验证是否执行，是否存在明显错误或漏项；不强制无关附加文件 |
| 混合成果 | 各部分是否满足各自要求，缺项与限制如实说明 |
| 外部效果 | 目标、实际回执和效果状态是否可核实；进程退出、工具自述或批准记录不证明动作已成功 |

自校验结论随结果记录，用于追溯，不再由另一个模型判定“通过”。结果先接纳保存，归属、要求编号、执行身份及证据差异由系统内部关联与记录，不作为拒绝保存的条件，具体见[结果保存无阻断](#结果保存无阻断)。正常结束的结果不再因 `effectsVerified: false` 或效果诊断缺项进入额外审核、反复回读或核查循环；真实限制保留在结果中。仍在执行、等待审批、截断或中断产生的已有内容同样保存，执行状态另按真实原因处理，不据存在部分正文判为完成。

自校验由原 Worker 按任务要求轻量完成并记录，不用 `agent/turn-stopping` 强制补一轮，不因缺少记录单独阻塞正常结果。官方结束事实与要求关联用于如实表达完成情况，不作为结果保存门槛；截断、取消、确定性配置错误等按原始原因记录，不能靠补回合掩盖失败。Router 与 Worker 的错误都沿官方请求/结束钩子记录首因；确定性模型、配置或能力错误不作为可无限重试的执行故障，但不影响已有成果保存。Router 对应钩子仍在本轮整合，须分别验证。

## 结果保存无阻断

2026-11-12 已接入并进行定向验证，安装版故障闭环仍须单独验收：删除 BenchGo 结果接纳与保存路径上的业务拒绝门。Worker 已产生的原稿、部分成果、失败报告和产物引用均先保存到宿主已知工单；不以内容、自检或失败字段完整度、要求版本、执行归属、Run/session/fence、证据及 hash 匹配、工具回执、官方结束记录、授权变化、工单暂停/停止/完成状态、待消费输入、幂等冲突或重试次数拒绝保存。字段缺失与差异如实记录，关联信息优先复用宿主已知记录补齐，不要求 Worker 重交或用户修正内部编号；不新增独立审查、补证或人工放行流程。没有宿主工单可关联或存储实际不可写时如实返回未保存，不凭模型提供的身份将原稿写入其他工单。

保存原稿、处理要求和标记完成分别记账。版本与归属用于追溯和内部关联，不再是保存准入门；迟到、旧要求或已停止执行返回的结果仍保留，未消费的新要求继续在原单处理，不丢成果、不覆盖其他工单或较新结果，也不把旧结果冒充新要求已完成。重复提交复用已有保存记录并返回引用；同一幂等键携带不同内容时保留不同内容及关联差异，由系统内部消解，不抛冲突阻断保存、不覆盖原稿。正常结束且满足当前要求的成功结果保存后完成工单；部分内容、失败报告及停止事实照实呈现。保存成功不代表获得新执行、续跑或对外发送权限。

系统自行处理关联、状态更新、通知或投递失败，不反向拒绝已经产生的成果。复用现有工单存储、官方会话日志与持久调度收尾，不新增第二套工单或大型恢复框架；仅因结果保存问题不得重跑 Worker、重放工具或重发外部动作，也不得将工单转成要求用户点击继续的等待。用户明确的暂停、停止与真实待答、待审批保持自身语义，已有成果保存不受这些控制阻断。

结果保存不设业务拒绝条件；物理写入失败须如实报告尚未持久化，不能返回虚假成功。数据库、磁盘、内存或进程等基础设施暂不可用时，保留仍可用的原稿及官方日志，优先完成可用的持久写入，启动和运行期间从现有记录自动补存。重试采用适度退避，不设次数、时长截止或永久 blocked；介质恢复可写后继续收尾。原始内容完全未能持久化且介质损坏时如实说明可恢复范围，不承诺已丢失数据仍能恢复。

主编排器负责自动补存，看门狗负责发现该链路或宿主失活并通知 Router；不能把“已告警”当作“已恢复”。恢复链路无需用户新增授权或点击继续，基础设施仍不可用时保留真实系统故障信息，不归因于用户要求。当前接线复用 Run 原稿、官方日志和进程内待存结果，移除永久 blocked 与次数截止；新执行保存真实结束事实，旧原稿仅在缺少结束事实时读取原会话补关联，不再按整份 hash 拒收原稿。原稿、生命周期和通知分别收尾，通知失败不回滚已存原稿或完成状态。实际不可写、重启补存及监督链路的验证边界见文末。

## 结果落单与 Router 表达交付

用户通常由 Router 协调，也可在工作台直接向 Worker 或官方子代理发消息。Worker 将正文成果、产物引用、实际证据、自校验摘要和未尽事项保存到工单，随后向所属 Router 发绑定工单、来源及结果版本的完成信号。原稿保留在工单详情；保存成功与执行完成信号不能代替用户可见交付。

Router 收到信号后读取已存成果，主动用自己的话说明已完成的事情与产出，自行选择摘要或完整回复，保存为正式稿后向原来源交付，不等用户追问。Worker 原稿供表达与追溯，不再原样直投；表达按当前对话组织，不固定工单报告、标题前缀或系统状态文案，也不另加交付卡框。Router 只负责表达与交付，不判定内容是否放行，不重派 Worker 或追加验收；用户追问时仍可读原稿直接回答。真实的新执行请求按在办修订或关联调整处理，不能把表达失败当成重做任务的理由。

Router 正式稿保存后，统一 outbox 按稳定幂等键调用原来源适配器，回执回到同一本工单账；原逻辑会话同样使用持久接收事实。适配器只转换收发协议，不另存投递业务状态或关单条件。保存的 Worker 原稿、Router 正式稿及其关联版本分别保留，已生成回复的投递重试复用原回复；生成失败只重试 Router 表达。渠道分工与统一会话呈现见[链接与渠道](链接与渠道.md)。

官方正常结束且成功结果持久化后工单直接为 completed，失败结果保持 waiting；送达另记。界面优先采用真实工单与 Run 终态，旧会话活动或摘要不得把完成项显示成“正在保存执行结果”或“待核实”；完成不等于已送达。均保留原列表、执行会话、原稿、正式稿与回执，不自动归档、隐藏或在查看时自动恢复会话。手动清单归档和恢复只改变展示元数据，不重跑执行，见[任务列表](../02-工作台与Agent/任务列表交互.md#列表与详情)。

| 情况 | 工单与执行处理 | 用户可见行为 |
| --- | --- | --- |
| 官方 Worker 正常结束并返回成功结果 | 当前要求的成功原稿落库后直接记 completed 并通知 Router；无额外结果效果审核，交付另记待表达或待发送 | Router 主动自然告知已完成，自选摘要或完整回复 |
| 原来源确认送达成功成果 | 仅记录送达回执，不再次改变执行状态；迟到回执不得覆盖新要求 | 原会话中成果可用；不要求用户点“验收通过” |
| Router 回复生成失败 | 保留待交付与成果原稿，只重试 Router 表达，不重跑 Worker | 真实状态留在任务列表，Router 可用时自行决定如何说明 |
| 投递失败 | 保留待交付、成果原稿与已生成回复，只补投同一回复，不重跑 Worker | 任务列表呈现真实投递状态，Router 按情况自然说明 |
| 缺用户信息或许可 | 按问题编号保留等待，只停受影响部分 | Router 能据现有依据回答就答，否则发具体选项卡 |
| 偶发网络、限流或临时服务故障 | 在原单保留上下文并退避恢复，不能仅凭重试次数耗尽判定结构性失败 | 显示真实恢复状态，不把暂时故障报为无解 |
| 结构性无解，确认无法完成 | 保存已有成果、实际尝试、失败原因与恢复条件并通知 Router；其回复待交付，结果保存后保持 waiting，送达另记，记录失败结果与恢复条件 | Router 自行组织自然说明，不套固定报告；用户回话后可在原单继续或调整，保留此前失败及送达记录 |
| 执行超时或失联 | 先核实原执行是否仍在运行，按官方会话记录在原单续做；不备份或还原目录，不并发启动第二份执行 | 标明真实异常和恢复状态，不因请求超时把整单作废 |
| 外部效果未知 | 核实实际效果与回执，确认前禁止盲重跑或重复提交 | 标明待核实效果，不猜成功或失败 |
| 用户明确停止或结束 | 立即拦截新动作，确认原执行已停止后记录结束；不把 executionControl 中的暂停/停止请求当作已确认退出 | 明确后续动作已拦截、正在结束执行；执行端逾时未确认退出时单独显示，不庆祝为成功 |

“确认送达”指原逻辑会话已持久接收结果，或原渠道返回可信发送成功回执；仅本地排入 outbox 不算送达。不要求用户已读、点批准或实际听完语音；缺少可靠回执时保持待交付或投递未知，不能猜测成功。

回复生成或发送失败均保留待交付，不回到 Worker 执行；生成重试沿用原成果，发送重试只补投已保存的 Router 回复。发送效果未知先查回执，渠道无幂等保证时不承诺绝对仅发一次，不以再次提交业务动作试探效果。不能回原来源时保留结果与明确原因，不悄悄改投别处。accepted、sent、设备接收、播放 ACK 和用户已读是不同事实。状态说明由 Router 根据真实情况自行判断，无硬文案兜底；真实状态始终可在任务列表查询。

普通插话记入原工单输入账本，在下一工具边界把新要求整份切换生效，不打断已经在途的工具；编号只作后台记账，不增加确认或先停跑流程。切换前已收到的修订未被消费时，旧要求结果仍立即接纳保存，由系统继续消费新要求，不据旧结果抢先认定新要求已完成或已送达。暂停期间只收修订、不自动续跑；叫停和收权立即拦截后续动作，扩权交 Router 经真实用户确认并生成新授权版本。成功交付后用户要求调整，新开关联调整单；失败后等待的工单收到用户回话时可原单续做或调整，不回写已经交付的历史结果。

原来源正常回复、进度、问题和成果交付免审；支付购买、改密码、删账号、另行对外发送四类高风险动作逐次审批，不被整站授权覆盖。另行对外发送包括向其他对象发邮件、转发、分享和发布。其他对外动作按[对外审批规则](任务与执行.md#权限与对外审批)匹配授权，整站授权明确站点、动作类别和期限，与工单 Mandate 两道门叠加，留痕且可撤销。原来源归属与渠道撤权仍有效，不能借交付名义获得其他目标的发送权。

## 中断等待与原会话续接

正常结束后不设置结果效果审核或自动续跑 Worker。成果保存及提交收尾统一遵循[结果保存无阻断](#结果保存无阻断)：已有内容直接接纳，关联差异在内部处理；基础设施故障由启动及运行期间的既有调度自动补存，不因连续失败或证据差异转等待，不设重试次数截止。该阶段为进行中，不要求用户授权或点击继续；只保存原结果、补齐账目与通知，不重新执行工具、不重发外部动作。没有正常结束事实仍保存部分正文，但不把它冒充执行成功。

用户明确继续时，复用原单恢复入口，一次性核对当前授权、执行归属、原 session writer、工具终局和待答交互，这些检查只决定能否发起新的执行动作，不限制已有成果保存。已有内容无需用户继续就自动接纳；确实中断且满足续接条件时，沿官方 resume/followup 在原 Assignment、Run、session 继续，保留冻结模型和已有成果，禁止重放已完成动作。续接条件不足就返回具体原因，不换会话重跑，不另排循环核查；暂停、停止与待审批仍按原控制处理。

等待只用于当前无法自主解决的具体阻塞或需要用户信息、授权及审核；用户明确暂停、停止仍遵守原控制。系统能自行完成的结果持久化不作为等待理由。界面以进度为主，真实等待按需展示原因及可用的继续、调整、刷新或停止入口，不新增核查次数、下次核查时间或自动核查卡。Router 按实际情况自然说明已有成果、限制与恢复条件，不承诺正在自动续跑。未知外部效果仍如实保留，不能据正常结束把未知改写成成功，也不能重发或更换通道试探。执行恢复不变量见[任务与执行](任务与执行.md#动作边界与恢复)。

停止与撤权的动作门立即生效，执行端退出另记：看板表达后续动作已拦、正在结束执行；超过确认阈值仍未退出时，明示执行端未确认退出，不能提前报告已停止。

## 外部观察信号与 Router 通报

Watchdog 的机器观察复用上述持久 inbox，另有 `watchdog` 通知类型，不能冒充真实用户或已有执行待核实。认证路由闭包提供机器来源，观察正文始终只作资料，不产生授权。接收成功仅表示已持久记录；是否排队、抑制、失败或已经形成 Router 正式回复分别保留，不能以 HTTP 回执冒充已通报。

接收、派发、每次工具调用及最终发布均读取统一执行事实，核对原 Ticket、Assignment、Run、session、fence、要求版本与证据水位。旧模型无进展告警仅保留历史，不再消费或重发；机械故障须排除合法等待及已失效观察；`claimed` 不因此改为 `uncertain`。同一故障阶段复用稳定通知身份，较新的恢复阶段抑制尚未报告的旧警告；失效观察仍留在原 inbox 回执，不改工单账。宿主恢复后的观察摘要绑定主 Router 的机器来源，只说明接口恢复，不据此宣称所有 Worker 健康。

观察回合只提供自然回复，不再提供 `check-now`、核查调度或自动续接入口，也不能借观察派工或自动暂停。用户明确要求继续时使用正常人工恢复入口。未进入 Router 的表达启动失败可沿既有投递恢复补表达，已进入或交付状态含糊的回合不自动重放。

信号接线的定向验证覆盖真实官方 AgentLoop 的自然正文及显式回复、重复与失效观察、只读工具闸门和后续正常对话。独立宿主巡检、辅助判断及安装版真实故障恢复须另行验收，不能由此推定完成。

## 问题逐级回原单

子 Worker 先向父 Worker 上报问题，由 Worker 汇总后交 Router；不得直接找用户或另开工单。Router 根据原始指令、已存记录和确定依据能回答的直接答，不能确定或必须用户拍板时才在原来源发选项卡。回答绑定真实问题编号、工单、来源和请求人，回原单续做；普通插话不是必须先答卡的修订申请。

只暂停依赖该答案的部分，其余独立、仍在授权内且有稳妥默认的工作继续。未知事实、权限、外部提交和范围扩展不能靠默认选项推断同意。只有超 Mandate 扩权走“用户确认 + 新授权版本”；动作审批仍按统一规则检查，不能用问题答案代替批准。

问题、动作审批与安全输入是不同协议。真实用户卡片答复不能由模型生成或正文关键词冒充；缺密码按[保险库安全输入](链接与渠道.md#保险库与安全输入)处理，不收集为普通问题答案。回答过期、重复、来源不符或指向其他工单时拒绝误用；实际未被原 Worker 消费不能显示已经续做。

## 证据与追溯

官方会话日志保留实际执行；Result 与工单保存来源指针、工具证据和必要产物。toolEvidence 的工具名、callId、事件序号、参数/结果、错误标记与 hash 用于事实追溯，按权限有界补读，注明遗漏和截断；不恢复独立模型“补证 → 判通过 → 自动返工”的链路。推理、秘密和不适合公开的原始工具输出不作为成果正文。

后台学习整理只消费已关工单，见[记忆与技能](记忆与技能.md)；它不审核本单是否允许交付，不能成为交付前置。开发时的软件测试、真实渠道验证及用户对产品的验收继续保留，与取消任务内容验收层无关。

## 实现与验收边界

原 Worker 轻量自检、结果落库与持久投递账已有基础；本轮取消强制补回合及正常结果的效果审核门，官方正常结束与当前成功结果持久化后直接 completed，失败结果为 waiting，投递状态独立记录。定向结果和安装版实际行为须分别验证，不能沿用旧“送达才完成”的验收结论。“保存原稿 → 通知 Router → 自然表达并保存正式稿 → outbox 原来源交付”已接线；已存正式稿的异常恢复只补投，不重跑 Worker。执行身份、要求应用、权限与恢复边界见[任务与执行](任务与执行.md)。验收应分别核对主路径、原单提问续跑、执行会话整份修订、叫停拦截、真实渠道收发、动作批准/拒绝及运行中重启恢复，不能由局部能力推定完整链路。

完成后不再进行效果核查或自动续跑；[结果保存无阻断](#结果保存无阻断)已有源码接线，自动补存与人工原会话续接分别验证。定向回归覆盖正常成功、失败及部分原稿、真实待答与暂停、同键重复及异内容、旧要求及运行身份差异、会话尾标记、旧核验 fence 的退出迁移、完成先于取消、收尾新输入与跨事务新要求保护。SQLite 拒写模拟覆盖原稿插入失败不伪报成功、Run 原稿保留，以及通知插入失败不回滚完成、重开存储后幂等补通知；调度测试覆盖超过旧次数上限后恢复，不重跑 Worker。真实磁盘耗尽、系统断电、官方日志与数据库同时不可写、安装版重启及看门狗监督收尾仍须实际验收，不据这些定向检查宣称已闭环。验收需保留开单确认、中途通报、完成交付三处 Router 原文，确认都在讲用户的事情；真实中断另核等待原因、人工续接或收尾。外部效果未知独立验证不重发；停止独立验证动作门生效与执行端退出确认，不能以其中一个代替另一个。

原会话续接曾在安装版观察到，但本轮精简后的完整恢复验收仍待完成。自然语言暂停落账、等待中的暂停与人工继续仍须验证；不能以一句暂停说明代替生命周期控制，也不能用定向测试代替真实中断恢复。表达还须按实际证据区分文件已创建、内容已保存与尚未产出，不得把模型自述的部分完成当成文件事实。

Worker 成果原稿保留在 Result 与工单详情，Router 回复另存，不覆盖原稿。升级时只把尚未发送的旧 `queued` 原结果 outbox 原行转换为待表达完成信号，沿用原投递身份；`sent`、`uncertain` 历史不改写、不自动重发。Router 表达生成与发送分别恢复：已确认失败的表达回合退避后只重试表达，含糊或取消回合不自动重放；已保存回复的发送失败只补投同一回复，未知发送效果先核实，不重 Worker。旧 `benchgo-ticket-state` 排队项在恢复时作废，不继续旧状态投影与新表达两条链；其原 outbox 仍是唯一交付身份，可按当前事实生成新的内部表达回合。

正式稿交付前通过官方会话服务完成持久检查点，插件须显式声明该服务依赖；不能用根上下文测试代替真实插件注入作用域。回复准备与投递记录保存失败分别保留有界诊断标识，仅在任务详情和日志可查，不把原始异常或固定失败文案作为聊天消息。状态文件替换复用官方原子写入能力及其 Windows 有界重试，保持原有版本校验与串行写入，不另造替换协议。恢复时优先补投已经生成的 Router 正式稿，不重生成、不重执行。若内部成果表达或当前有效的恢复通报在收件或会话准备落盘阶段失败、尚未关联 Router 会话身份，须机械核对原 Router 会话及其历史和实时记录中均无该表达消息或准备记录，才能按原退避、原事件身份重试一次新的表达；已有准备或提交证据、状态含糊或取消时不得据缺少会话字段重放。已进入 Router 回合的恢复通报不得重放，防止重复恢复处置。此恢复只补尚未进入 Router 的通知，不重跑 Worker 或任何业务外发。

验收须核对正常结束缺少自检记录时无强制补回合；提问、暂停、截断、身份失效与确定性错误保留首因，不无限续接。成功结果持久化与表达、投递各自关联同一结果，不能由单一路径推定所有恢复、渠道或审批场景。

旧任务内容 Review 已移除；数据库一次性删除 `review_retry` 调度字段，取消旧待发结论与未开始的补审/返工分派，活动身份不明的旧分派保持 uncertain；历史 Result、Run、证据及可信已送达结果保留。既有迁移曾将未送达旧结论置为等待；当前有原稿的 Run 由[结果保存无阻断](#结果保存无阻断)路径自动收尾，旧版本或退役标记不阻断接纳，不恢复旧审核调度。仅有旧审计而缺失可恢复原稿或真实成功结束事实的条目，不推定完成。系统按已有执行事实整理结果与交付关联，实际新执行仍遵守当前授权及暂停、停止控制；旧问题不再接受答复或触发执行。后台学习队列保留，不属于被取消的内容验收。

官方动作审批目前主要投影为真实待批交互，尚未全部统一写入 Ticket 的业务 `waiting`；临时故障退避与已中断待人工续接也须按具体执行事实区分，不能仅凭错误类别宣称自动恢复。上述等待清单是统一判定契约，残余入口需继续逐项接线验收。旧执行型 Goal 的送达依赖边界见[任务与执行](任务与执行.md#工单跟进与目标)。

数据库全不可写、Run 原稿未能保存且进程立即退出时，官方会话日志仍是恢复依据；当前自动候选优先处理已有 Run 原稿，尚未覆盖全部“仅日志中有原稿”的自动发现。该极端故障的自动发现与补存需继续开发，不能承诺零丢失或用存在日志冒充已完成自动恢复。

验证无独立任务内容验收模型调用，自检不新增 Agent，适用的测试、构建和输出检查真实执行；纯文本零文件可交付，显式验证不遗漏，旧要求结果不抢先关闭。原稿、完成信号、Router 回复、outbox 和回执幂等关联；Router 无需用户追问即可自然提醒，自行选择摘要或完整回复，详情保留原稿，不能重派或验收。成功执行结果持久化后 completed，送达独立记录，结构性失败结果为 waiting，说明送达另记；生成失败只重试表达，投递失败只补投回复，两者均待交付且不重 Worker。验证无固定报告、标题前缀、系统状态硬文案及兜底；偶发故障退避、失败后等待的原单续做、超时后的官方原会话续接与未知效果不盲重跑。

验证问题编号与真实来源绑定，内部可答不打扰用户，只有受影响部分等待；普通插话在下一工具边界整份切换、不打断在途，暂停不续跑。原来源免审，其他发送按现行许可，安全输入不泄密。真实界面检查无任务/问题、加载、失败、有结果或卡片四态，业务层仅展示进行、等待、完成，短原因区分待交付、执行失败与停止，不把失败或停止显示成功，视觉由用户最终验收。
