# SuperAgent 自校验与交付

本文维护 Worker 自校验、结果落单、Router 表达交付、问题回路与投递关单；执行与普通修订见[任务与执行](任务与执行.md)，聊天呈现见[对话交互](对话交互.md)。实现边界与验收条件见文末。

## 工单三态与简短摘要

2026-11-10 已实现并通过定向验证，真实安装版闭环仍待验收：Ticket 持久化业务状态及对用户、AI 的返回值仅有 `running` / `waiting` / `completed`（进行 / 等待 / 完成），不只在界面合并，也不再保留其他工单状态分支。旧 `open`、`failed`、`paused`、`pausing`、`cancelled`、`cancelling`、`closed` 等只作一次性迁移输入，不保留永久兼容双轨。暂停、停止请求与确认采用独立机械布尔字段 `executionControl: { pauseRequested, paused, stopRequested, stopped }`，不将旧 status 改名搬家；等待原因与恢复条件另记；Assignment、Run、Outbox 的机械状态继续用于恢复、授权及防重复副作用。

| 业务状态 | 条件与呈现 |
| --- | --- |
| 进行 | 已领取并正在执行、保存或交付；已知发送失败的受控交付重试可保持进行，结果未可信送达前不显示完成 |
| 等待 | 新单排队、暂停、等待答复或授权、需外部条件恢复的故障、效果待核实、结构性失败或主动停止；一段简短说明写清原因和下一步 |
| 完成 | 当前要求已成功完成且成果确认送达；失败报告、人工整理标记或停止确认均不能冒充成功 |

新单排队为 `waiting`，实际领取执行才切为 `running`。失败只作为一次执行的结果保留；失败报告送达后工单仍为等待，保存已有成果、尝试与恢复条件。等待必须明确由系统核查/恢复、用户补充/决定或用户明确继续，重试按既有退避与上限收敛；条件没有变化时不得无限重试。看门狗发现停滞后发信号并核实或恢复，不仅凭超时推断任务成功或失败。主动停止通过独立控制记录保持取消请求与确认语义，业务展示为等待并标注已停止，必须真实用户明确继续且复核授权，不能自动唤醒。

默认读取三态与一段简短摘要（界面至多 240 字、AI 列表至多 320 字）：进行说明当前进展，等待说明原因、恢复条件和下一步，完成说明做了什么、结果及限制；成果与证据仅保留指针，按需读取，不把全文报告塞入 Router 默认上下文。状态和结果事实使用已有结构记录，AI 不仅凭摘要文字猜测成功。Router 收到绑定结果的表达信号后可按需读取原稿形成正式回复；这不扩大日常工单查询上下文。

完成项保留在完成分组，分组内沿用最近活动排序，保留同一执行会话、消息和成果入口；取消工单结束时自动归档、隐藏，以及查看时自动恢复会话。用户主动归档仍走既有管理入口。

## Worker 轻量自校验

每次派工固定附带要求：“完成任务后，先按本工单要求做一次快速轻量自校验，优先运行适用的机械测试、构建和输出检查，修正明显错误和漏项，通过后才可报告执行完成；不能解决的如实报告受阻或失败。”这一步由原 Worker 在原执行上下文完成，不新增自检 Agent、独立模型评分或后台语义验收，也不把结果送回 Router 审内容。

自校验以当前原始用户要求和已应用的跟进为准，派工摘要不能删去显式步骤、数量、格式、来源与必要验证。轻量指不额外扩大检查范围；用户要求的测试、浏览器操作或其他验证仍须实际执行，不能以自述“已自检”代替。明显问题在原单内修好；无能力解决时保留已有成果和真实原因，不能凑数或谎报完成。

| 任务类型 | 快速检查重点 |
| --- | --- |
| 文本、查询、调研 | 主要问题、数量和格式是否覆盖，事实与来源是否明显冲突；联网结论区分来源时间、抓取时间及未核实内容，允许零文件 |
| 文件、代码、UI、媒体 | 所要求成果是否存在、可读，显式要求的必要验证是否执行，是否存在明显错误或漏项；不强制无关附加文件 |
| 混合成果 | 各部分是否满足各自要求，缺项与限制如实说明 |
| 外部效果 | 目标、实际回执和效果状态是否可核实；进程退出、工具自述或批准记录不证明动作已成功 |

自校验结论随结果记录，用于追溯，不再由另一个模型判定“通过”。宿主只做归属、当前要求编号、有效执行身份、结果落库等确定性检查；发现旧结果或未应用修订时同步状态与原执行，不另设内容审核门。

原 Worker 试图结束回合但缺少当前要求的自检记录时，插件通过官方 `agent/turn-stopping` 接缝，在同一执行会话内最多提醒补全一次：沿用已完成的工作与真实证据，完成轻量自检、登记记录并输出完整最终正文，不重做已生效动作。等待问题、暂停、叫停、执行身份失效或本回合输出截断时不补充；补充前后复检租约和工单身份。仍未登记时保留 `WORKER_SELF_CHECK` 原因并等待处理。普通交付还须有官方 `turn/end` 的正常完成记录，截断等异常终局即使已有自检也不得交付为完成；此项只核对执行状态，不引入 Router 内容验收。

## 结果落单与 Router 表达交付

用户始终与 Router 对话。Worker 将正文成果、产物引用、实际证据、自校验摘要和未尽事项保存到工单，随后向所属 Router 发绑定工单、来源及结果版本的完成信号。原稿保留在工单详情；保存成功与执行完成信号不能代替用户可见交付。

Router 收到信号后读取已存成果，主动用自己的话说明已完成的事情与产出，自行选择摘要或完整回复，保存为正式稿后向原来源交付，不等用户追问。Worker 原稿供表达与追溯，不再原样直投；表达按当前对话组织，不固定工单报告、标题前缀或系统状态文案，也不另加交付卡框。Router 只负责表达与交付，不判定内容是否放行，不重派 Worker 或追加验收；用户追问时仍可读原稿直接回答。真实的新执行请求按在办修订或关联调整处理，不能把表达失败当成重做任务的理由。

Router 正式稿保存后，统一 outbox 按稳定幂等键调用原来源适配器，回执回到同一本工单账；原逻辑会话同样使用持久接收事实。适配器只转换收发协议，不另存投递业务状态或关单条件。保存的 Worker 原稿、Router 正式稿及其关联版本分别保留，已生成回复的投递重试复用原回复；生成失败只重试 Router 表达。渠道分工与统一会话呈现见[链接与渠道](链接与渠道.md)。

成功成果确认送达后工单为 completed，失败说明送达后保持 waiting；均保留原列表、执行会话、原稿、正式稿与回执，不自动归档、隐藏或在查看时自动恢复会话。手动清单归档和恢复只改变展示元数据，不重跑执行，见[任务列表](../02-工作台与Agent/任务列表交互.md#列表与详情)。

| 情况 | 工单与执行处理 | 用户可见行为 |
| --- | --- | --- |
| Worker 自检后报告执行完成 | 原稿落库并通知 Router，进入待交付，不能先记整单 completed | Router 主动自然告知已完成，自选摘要或完整回复 |
| 原来源确认送达成功成果 | 记录送达回执并以 completed 关单，防止迟到回执重复关账 | 原会话中成果可用；不要求用户点“验收通过” |
| Router 回复生成失败 | 保留待交付与成果原稿，只重试 Router 表达，不重跑 Worker | 真实状态留在任务列表，Router 可用时自行决定如何说明 |
| 投递失败 | 保留待交付、成果原稿与已生成回复，只补投同一回复，不重跑 Worker | 任务列表呈现真实投递状态，Router 按情况自然说明 |
| 缺用户信息或许可 | 按问题编号保留等待，只停受影响部分 | Router 能据现有依据回答就答，否则发具体选项卡 |
| 偶发网络、限流或临时服务故障 | 在原单保留上下文并退避恢复，不能仅凭重试次数耗尽判定结构性失败 | 显示真实恢复状态，不把暂时故障报为无解 |
| 结构性无解，确认无法完成 | 保存已有成果、实际尝试、失败原因与恢复条件并通知 Router；其回复待交付，确认送达后保持 waiting，记录失败结果与恢复条件 | Router 自行组织自然说明，不套固定报告；用户回话后可在原单继续或调整，保留此前失败及送达记录 |
| 执行超时或失联 | 先核实原执行是否仍在运行，保存可恢复 checkpoint，在原单恢复上下文续做；不得并发启动第二份执行 | 标明真实异常和恢复状态，不因请求超时把整单作废 |
| 外部效果未知 | 核实实际效果与回执，确认前禁止盲重跑或重复提交 | 标明待核实效果，不猜成功或失败 |
| 用户明确停止或结束 | 立即拦截新动作，确认原执行已停止后记录结束；不把 executionControl 中的暂停/停止请求当作已确认退出 | 明确后续动作已拦截、正在结束执行；执行端逾时未确认退出时单独显示，不庆祝为成功 |

“确认送达”指原逻辑会话已持久接收结果，或原渠道返回可信发送成功回执；仅本地排入 outbox 不算送达。不要求用户已读、点批准或实际听完语音；缺少可靠回执时保持待交付或投递未知，不能猜测成功。

回复生成或发送失败均保留待交付，不回到 Worker 执行；生成重试沿用原成果，发送重试只补投已保存的 Router 回复。发送效果未知先查回执，渠道无幂等保证时不承诺绝对仅发一次，不以再次提交业务动作试探效果。不能回原来源时保留结果与明确原因，不悄悄改投别处。accepted、sent、设备接收、播放 ACK 和用户已读是不同事实。状态说明由 Router 根据真实情况自行判断，无硬文案兜底；真实状态始终可在任务列表查询。

普通插话记入原工单输入账本，在下一工具边界把新要求整份切换生效，不打断已经在途的工具；编号只作后台记账，不增加确认或先停跑流程。切换前已收到的修订未被消费时，旧要求结果不能抢先送达关单。暂停期间只收修订、不自动续跑；叫停和收权立即拦截后续动作，扩权交 Router 经真实用户确认并生成新授权版本。成功交付后用户要求调整，新开关联调整单；失败后等待的工单收到用户回话时可原单续做或调整，不回写已经交付的历史结果。

原来源正常回复、进度、问题和成果交付免审；支付购买、改密码、删账号、另行对外发送四类高风险动作逐次审批，不被整站授权覆盖。另行对外发送包括向其他对象发邮件、转发、分享和发布。其他对外动作按[对外审批规则](任务与执行.md#权限与对外审批)匹配授权，整站授权明确站点、动作类别和期限，与工单 Mandate 两道门叠加，留痕且可撤销。原来源归属与渠道撤权仍有效，不能借交付名义获得其他目标的发送权。

## 待核实通报与自主处置

执行待核实不是让用户代查的操作要求。宿主保存并区分五类原因：会话中断或重启、Worker 尚未完整结束、证据不一致、外部效果未知、暂停恢复未确认。进入待核实、核查长期无结论及核清后的处置分别发所属 Router 信号，携带具体事项、原因、原执行身份、已核查次数、下一次时间及真实处置；不把内部状态词或原始异常直接拼成聊天正文。

信号复用原会话的持久 inbox，由 Router 按[事情本位的表达口径](对话交互.md)主动自然说明：替用户做的哪件事受影响、已知原因、系统正在做什么、已核查几次、下次何时及后续安排，以及当前是否需要用户补充信息；无需用户操作时明确说明。通报与处置全程异步，人类消息优先，不打断正在进行的正常对话；派发和发布前复核当前要求、执行归属和权限，去重并抑制已经过期的通报。用户干预始终优先。

已有完整可核实结束证据时，继续使用原自动核查循环：只读核对原执行记录，退避由 30 秒起翻倍至 15 分钟，不因重复检查启动第二份执行。看板直接显示原因、次数与下次核查时间；达到长期无结论阈值时明确异常，并再次通知 Router 升级说明。没有完整证据或实际未排入核查时，明确展示缺少的恢复条件，不伪称自动核查仍在运行，也不显示“请先核实状态”。暂停确认保留自身的核查与退避，不把等待用户主动恢复写成自动续跑。

Router 在原授权内可继续等待、安排一次立即只读核查、请求经安全核验的原会话续跑，或根据已保存的结构性失败材料收尾；处置后按真实结果向用户说明。只有可信且仍有效的恢复信号回合可调用恢复协调工具，调用时复核原来源、要求与授权；成果、审批及普通状态通知仍只允许表达，不能借内部通知开启其他动作。工具可见性与实际执行闸门须遵循同一白名单，不能把工具已列出当作已可执行。安排核查或请求续跑只表示已排队，不等于已恢复或已完成；立即复核的真实结果独立留痕，再经同一信号路径回到 Router 主动报告，不将一次只读复核自动变成续跑。结构性失败须有实际尝试、确定原因、用户可改变的恢复条件及真实自检记录，仍经 Router 表达、可信送达后保持 waiting 并保存恢复条件；不得用重试耗尽或模型判断替代失败证据。

没有完整结束证据的半途中断，只允许受控窄续跑：独占原官方 Session writer，核清全部原生与 PTC 工具终局及外部效果，复核原 Mandate、当前要求、日志与文件边界；确认没有待答问题、未完成动作检查点、用户暂停或停止，并保留创建时冻结的工作模型后，沿官方 resume/followup 在原工单、原 Run、原 session 接续，递增 fence。实际执行前再次核对证据与授权，禁止重放已完成动作。任一条件不满足则保留待核实及明确原因，不换会话重跑。执行恢复的其他不变量见[任务与执行](任务与执行.md#动作边界与恢复)。

自动续接与只读核查分别计数：原 Run 的自动续接请求最多尝试两次，预算随成功入队或预检失败回执持久保存，跨 fence、进程重启及普通修订累计；旧回执没有来源字段时按自动尝试计入。第一次续接可立即核验；会话锁、核查超时、证据或模型条件等预检失败也计入预算；用户暂停、停止、撤权或要求版本变化造成的取消不计入。再次续接须从上次执行失败或预检失败时起至少退避 30 秒，后续按指数规则计算且不超过 15 分钟，但达到两次上限后不再排第三次。延期请求落在原输入执行账，由既有异步循环到点消费，不能因重启丢失安排或重新获得预算；入队事务再次复核上限和时点。上限后保留待核实，不判结构性失败，发同一恢复信号的升级事实，由 Router 自然说明已停止自动尝试。wait、只读 check-now 和重复信号既不重置预算，也不能绕过退避；不得反复核查制造新的自动续接机会。当前真实用户明确要求继续时，只能由宿主可信来源标记本次人工续接，可单次绕过自动等待和上限，但不清空自动次数或授予未来自动许可；模型参数与内部通知均不能声明人工来源。暂停同事务清除尚未执行的延期请求，恢复仍须用户明确决定。

外部效果未核清时只允许核查，禁止恢复业务执行、重发或更换通道试探；批准记录本身不证明外部已生效。超原 Mandate 的处置先取得真实用户确认。停止与撤权的动作门立即生效，执行端退出另记：看板表达后续动作已拦、正在结束执行；超过确认阈值仍未退出时，明示执行端未确认退出，不能提前报告已停止。

## 外部观察信号与 Router 通报

Watchdog 的机器观察复用上述持久 inbox，另有 `watchdog` 通知类型，不能冒充真实用户或已有执行待核实。认证路由闭包提供机器来源，观察正文及模型理由始终只作资料，不产生授权。接收成功仅表示已持久记录；是否排队、抑制、失败或已经形成 Router 正式回复分别保留，不能以 HTTP 回执冒充已通报。

接收、派发、每次工具调用及最终发布均读取统一执行事实，核对原 Ticket、Assignment、Run、session、fence、要求版本与证据水位。疑似无进展还须排除合法等待、证据缺口及其后出现的新执行事件；`claimed` 不因此改为 `uncertain`。同一故障阶段复用稳定通知身份，较新的恢复阶段抑制尚未报告的旧警告；失效观察仍留在原 inbox 回执，不改工单账。宿主恢复后的观察摘要绑定主 Router 的机器来源，只说明接口恢复，不据此宣称所有 Worker 健康。

观察回合只提供自然回复；绑定执行时另允许对原单调用 `check-now`。该调用只复用既有异步只读核查，禁止 `wait`、`resume`、`fail`、派工或其他动作，也不让 Router 等待后台核查。现有核查只适用于真实待核实身份时，运行中的 `claimed` 观察返回明确不适用及当前事实；不补造核查执行器、恢复循环或自动暂停。未进入 Router 的启动失败可沿既有退避核对原日志后补表达，已进入或交付状态含糊的回合不自动重放。

信号接线的定向验证覆盖真实官方 AgentLoop 的自然正文及显式回复、重复与失效观察、只读工具闸门和后续正常对话。独立宿主巡检、辅助判断及安装版真实故障恢复须另行验收，不能由此推定完成。

## 问题逐级回原单

子 Worker 先向父 Worker 上报问题，由 Worker 汇总后交 Router；不得直接找用户或另开工单。Router 根据原始指令、已存记录和确定依据能回答的直接答，不能确定或必须用户拍板时才在原来源发选项卡。回答绑定真实问题编号、工单、来源和请求人，回原单续做；普通插话不是必须先答卡的修订申请。

只暂停依赖该答案的部分，其余独立、仍在授权内且有稳妥默认的工作继续。未知事实、权限、外部提交和范围扩展不能靠默认选项推断同意。只有超 Mandate 扩权走“用户确认 + 新授权版本”；动作审批仍按统一规则检查，不能用问题答案代替批准。

问题、动作审批与安全输入是不同协议。真实用户卡片答复不能由模型生成或正文关键词冒充；缺密码按[保险库安全输入](链接与渠道.md#保险库与安全输入)处理，不收集为普通问题答案。回答过期、重复、来源不符或指向其他工单时拒绝误用；实际未被原 Worker 消费不能显示已经续做。

## 证据与追溯

官方会话日志保留实际执行；Result 与工单保存来源指针、工具证据和必要产物。toolEvidence 的工具名、callId、事件序号、参数/结果、错误标记与 hash 用于事实追溯，按权限有界补读，注明遗漏和截断；不恢复独立模型“补证 → 判通过 → 自动返工”的链路。推理、秘密和不适合公开的原始工具输出不作为成果正文。

后台学习整理只消费已关工单，见[记忆与技能](记忆与技能.md)；它不审核本单是否允许交付，不能成为交付前置。开发时的软件测试、真实渠道验证及用户对产品的验收继续保留，与取消任务内容验收层无关。

## 实现与验收边界

已实现原 Worker 固定轻量自检要求与结构记录、确定性结果检查、持久投递账、成功回复可信送达后 completed、失败说明送达后 waiting，以及发送失败只补投与未知发送核实。“保存原稿 → 通知 Router → 自然表达并保存正式稿 → outbox 原来源交付”已接线；已存正式稿的异常恢复只补投，不重跑 Worker。执行身份、要求应用、权限与恢复边界见[任务与执行](任务与执行.md)。验收应分别核对主路径、原单提问续跑、执行会话整份修订、叫停拦截、真实渠道收发、动作批准/拒绝及运行中重启恢复，不能由局部能力推定完整链路。

待核实原因与进度投影、进入/升级/核清信号、Router 异步处置工具及受控原会话续跑已接线；不据定向检查推定安装版真实中断已闭环。验收需保留长任务开单确认、中途通报、完成交付三处 Router 原文，确认都在讲用户的事情；真实中断另核主动通报、看板进度、核清后的原会话接续或收尾及后续报告。外部效果未知独立验证只核查、不重发；停止独立验证动作门生效与执行端退出确认，不能以其中一个代替另一个。

原会话核清后续接已在安装版观察到，但完整恢复验收尚未通过。自然语言暂停落账、待核实暂停入口，以及自动续接的持久预算、延期与上限信号均已接线，但尚待安装版真实验收；不能以 `wait` 或一句暂停说明代替生命周期控制，也不能用定向测试代替真实中断后的有界恢复。表达还须按实际证据区分文件已创建、内容已保存与尚未产出，不得把模型自述的部分完成当成文件事实。这些缺口未闭环前，不宣称用户干预与自主恢复完整落地。

Worker 成果原稿保留在 Result 与工单详情，Router 回复另存，不覆盖原稿。升级时只把尚未发送的旧 `queued` 原结果 outbox 原行转换为待表达完成信号，沿用原投递身份；`sent`、`uncertain` 历史不改写、不自动重发。Router 表达生成与发送分别恢复：已确认失败的表达回合退避后只重试表达，含糊或取消回合不自动重放；已保存回复的发送失败只补投同一回复，未知发送效果先核实，不重 Worker。旧 `benchgo-ticket-state` 排队项在恢复时作废，不继续旧状态投影与新表达两条链；其原 outbox 仍是唯一交付身份，可按当前事实生成新的内部表达回合。

正式稿交付前通过官方会话服务完成持久检查点，插件须显式声明该服务依赖；不能用根上下文测试代替真实插件注入作用域。回复准备与投递记录保存失败分别保留有界诊断标识，仅在任务详情和日志可查，不把原始异常或固定失败文案作为聊天消息。状态文件替换复用官方原子写入能力及其 Windows 有界重试，保持原有版本校验与串行写入，不另造替换协议。恢复时优先补投已经生成的 Router 正式稿，不重生成、不重执行。若内部成果表达或当前有效的恢复通报在收件或会话准备落盘阶段失败、尚未关联 Router 会话身份，须机械核对原 Router 会话及其历史和实时记录中均无该表达消息或准备记录，才能按原退避、原事件身份重试一次新的表达；已有准备或提交证据、状态含糊或取消时不得据缺少会话字段重放。恢复通报复用既有核查循环调度，重入前复检原来源、授权及当前事实；已进入 Router 回合的恢复通报不得重放，防止重复恢复处置。此恢复只补尚未进入 Router 的通知，不重跑 Worker 或任何业务外发。

关闭前一次自检补全通过上述官方接缝接入原 Agent、原会话和原回合，并限制退出次数。验收须核对正常结束但缺少自检记录、已提问或暂停、输出截断和身份失效等分支；分别关联保存原稿、完成信号、Router 正式稿、送达与对应终态，不能由单一路径推定所有恢复、渠道或审批场景。

旧任务内容 Review 已移除；数据库一次性删除 `review_retry` 调度字段，取消旧待发结论与未开始的补审/返工分派，活动身份不明的旧分派保持 uncertain；历史 Result、Run、证据及可信已送达结果保留。旧问题不再接受答复或触发执行，未送达旧结论停在明确等待状态，须用户明确继续后按新要求和当前授权处理。后台学习队列保留，不属于被取消的内容验收。

验证无独立任务内容验收模型调用，自检不新增 Agent，适用的测试、构建和输出检查真实执行；纯文本零文件可交付，显式验证不遗漏，旧要求结果不抢先关闭。原稿、完成信号、Router 回复、outbox 和回执幂等关联；Router 无需用户追问即可自然提醒，自行选择摘要或完整回复，详情保留原稿，不能重派或验收。成功回复送达后 completed，结构性失败说明送达后仍为 waiting；生成失败只重试表达，投递失败只补投回复，两者均待交付且不重 Worker。验证无固定报告、标题前缀、系统状态硬文案及兜底；偶发故障退避、失败后等待的原单续做、超时 checkpoint 恢复与未知效果不盲重跑。

验证问题编号与真实来源绑定，内部可答不打扰用户，只有受影响部分等待；普通插话在下一工具边界整份切换、不打断在途，暂停不续跑。原来源免审，其他发送按现行许可，安全输入不泄密。真实界面检查无任务/问题、加载、失败、有结果或卡片四态，业务层仅展示进行、等待、完成，短原因区分待交付、执行失败与停止，不把失败或停止显示成功，视觉由用户最终验收。
