# SuperAgent 自校验与交付

本文维护 Worker 自校验、结果落单、Router 表达交付、问题回路与投递关单；执行与普通修订见[任务与执行](任务与执行.md)，聊天呈现见[对话交互](对话交互.md)。2026-11-08 定版由 Router 面向用户表达和交付，具体实现与运行验证边界见文末。

## Worker 轻量自校验

每次派工固定附带要求：“完成任务后，先按本工单要求做一次快速轻量自校验，优先运行适用的机械测试、构建和输出检查，修正明显错误和漏项，通过后才可报告执行完成；不能解决的如实报告受阻或失败。”这一步由原 Worker 在原执行上下文完成，不新增自检 Agent、独立模型评分或后台语义验收，也不把结果送回 Router 审内容。

自校验以当前原始用户要求和已应用的跟进为准，派工摘要不能删去显式步骤、数量、格式、来源与必要验证。轻量指不额外扩大检查范围；用户要求的测试、浏览器操作或其他验证仍须实际执行，不能以自述“已自检”代替。明显问题在原单内修好；无能力解决时保留已有成果和真实原因，不能凑数或谎报完成。

| 任务类型 | 快速检查重点 |
| --- | --- |
| 文本、查询、调研 | 主要问题、数量和格式是否覆盖，事实与来源是否明显冲突；联网结论区分来源时间、抓取时间及未核实内容，允许零文件 |
| 文件、代码、UI、媒体 | 所要求成果是否存在、可读，显式要求的必要验证是否执行，是否存在明显错误或漏项；不强制无关附加文件 |
| 混合成果 | 各部分是否满足各自要求，缺项与限制如实说明 |
| 外部效果 | 目标、实际回执和效果状态是否可核实；进程退出、工具自述或批准记录不证明动作已成功 |

自校验结论随结果记录，用于追溯，不再由另一个模型判定“通过”。宿主只做归属、当前要求编号、有效执行身份、结果落库等确定性检查；发现旧结果或未应用修订时同步状态与原执行，不另设内容审核门。

原 Worker 试图结束回合但缺少当前要求的自检记录时，插件通过官方 `agent/turn-stopping` 接缝，在同一执行会话内最多提醒补全一次：沿用已完成的工作与真实证据，完成轻量自检、登记记录并输出完整最终正文，不重做已生效动作。等待问题、暂停、叫停、执行身份失效或本回合输出截断时不补充；补充前后复检租约和工单身份。仍未登记时保留 `WORKER_SELF_CHECK` 原因并等待处理。普通交付还须有官方 `turn/end` 的正常完成记录，截断等异常终局即使已有自检也不得交付为完成；此项只核对执行状态，不引入 Router 内容验收。

## 结果落单与 Router 表达交付

用户始终与 Router 对话。Worker 将正文成果、产物引用、实际证据、自校验摘要和未尽事项保存到工单，随后向所属 Router 发绑定工单、来源及结果版本的完成信号。原稿保留在工单详情；保存成功与执行完成信号不能代替用户可见交付。

Router 收到信号后读取已存成果，主动自然提醒用户任务已完成，自行选择摘要或完整回复并向原来源交付，不等用户追问。表达按当前对话组织，不固定工单报告、标题前缀或系统状态文案，也不另加交付卡框。Router 只负责表达与交付，不判定内容是否放行，不重派 Worker 或追加验收；用户追问时仍可读原稿直接回答。真实的新执行请求按在办修订或关联调整处理，不能把表达失败当成重做任务的理由。

Router 回复保存后，统一 outbox 按稳定幂等键调用原来源适配器，回执回到同一本工单账；原逻辑会话同样使用持久接收事实。适配器只转换收发协议，不另存投递业务状态或关单条件。保存的 Worker 原稿、Router 回复及其关联版本分别保留，已生成回复的投递重试复用原回复；生成失败只重试 Router 表达。渠道分工与统一会话呈现见[链接与渠道](链接与渠道.md)。

| 情况 | 工单与执行处理 | 用户可见行为 |
| --- | --- | --- |
| Worker 自检后报告执行完成 | 原稿落库并通知 Router，进入待交付，不能先记整单 completed | Router 主动自然告知已完成，自选摘要或完整回复 |
| 原来源确认送达成功成果 | 记录送达回执并以 completed 关单，防止迟到回执重复关账 | 原会话中成果可用；不要求用户点“验收通过” |
| Router 回复生成失败 | 保留待交付与成果原稿，只重试 Router 表达，不重跑 Worker | 真实状态留在任务列表，Router 可用时自行决定如何说明 |
| 投递失败 | 保留待交付、成果原稿与已生成回复，只补投同一回复，不重跑 Worker | 任务列表呈现真实投递状态，Router 按情况自然说明 |
| 缺用户信息或许可 | 按问题编号保留等待，只停受影响部分 | Router 能据现有依据回答就答，否则发具体选项卡 |
| 偶发网络、限流或临时服务故障 | 在原单保留上下文并退避恢复，不能仅凭重试次数耗尽判定结构性失败 | 显示真实恢复状态，不把暂时故障报为无解 |
| 结构性无解，确认无法完成 | 保存已有成果、实际尝试、失败原因与恢复条件并通知 Router；其回复待交付，确认送达后以 failed 关单 | Router 自行组织自然说明，不套固定报告；用户回话后可在原单继续或调整，保留此前失败及送达记录 |
| 执行超时或失联 | 先核实原执行是否仍在运行，保存可恢复 checkpoint，在原单恢复上下文续做；不得并发启动第二份执行 | 标明真实异常和恢复状态，不因请求超时把整单作废 |
| 外部效果未知 | 核实实际效果与回执，确认前禁止盲重跑或重复提交 | 标明待核实效果，不猜成功或失败 |
| 用户明确停止或结束 | 立即拦截新动作，确认原执行已停止后记录结束；不把 pausing/cancelling 当作已停 | 如实显示停止中与已停止，不庆祝为成功 |

“确认送达”指原逻辑会话已持久接收结果，或原渠道返回可信发送成功回执；仅本地排入 outbox 不算送达。不要求用户已读、点批准或实际听完语音；缺少可靠回执时保持待交付或投递未知，不能猜测成功。

回复生成或发送失败均保留待交付，不回到 Worker 执行；生成重试沿用原成果，发送重试只补投已保存的 Router 回复。发送效果未知先查回执，渠道无幂等保证时不承诺绝对仅发一次，不以再次提交业务动作试探效果。不能回原来源时保留结果与明确原因，不悄悄改投别处。accepted、sent、设备接收、播放 ACK 和用户已读是不同事实。状态说明由 Router 根据真实情况自行判断，无硬文案兜底；真实状态始终可在任务列表查询。

普通插话记入原工单输入账本，在下一工具边界把新要求整份切换生效，不打断已经在途的工具；编号只作后台记账，不增加确认或先停跑流程。切换前已收到的修订未被消费时，旧要求结果不能抢先送达关单。暂停期间只收修订、不自动续跑；叫停和收权立即拦截后续动作，扩权交 Router 经真实用户确认并生成新授权版本。成功交付后用户要求调整，新开关联调整单；failed 工单收到用户回话时可原单续做或调整，不回写已经交付的历史结果。

原来源正常回复、进度、问题和成果交付免审；支付购买、改密码、删账号、另行对外发送四类高风险动作逐次审批，不被整站授权覆盖。另行对外发送包括向其他对象发邮件、转发、分享和发布。其他对外动作按[对外审批规则](任务与执行.md#权限与对外审批)匹配授权，整站授权明确站点、动作类别和期限，与工单 Mandate 两道门叠加，留痕且可撤销。原来源归属与渠道撤权仍有效，不能借交付名义获得其他目标的发送权。

## 问题逐级回原单

子 Worker 先向父 Worker 上报问题，由 Worker 汇总后交 Router；不得直接找用户或另开工单。Router 根据原始指令、已存记录和确定依据能回答的直接答，不能确定或必须用户拍板时才在原来源发选项卡。回答绑定真实问题编号、工单、来源和请求人，回原单续做；普通插话不是必须先答卡的修订申请。

只暂停依赖该答案的部分，其余独立、仍在授权内且有稳妥默认的工作继续。未知事实、权限、外部提交和范围扩展不能靠默认选项推断同意。只有超 Mandate 扩权走“用户确认 + 新授权版本”；动作审批仍按统一规则检查，不能用问题答案代替批准。

问题、动作审批与安全输入是不同协议。真实用户卡片答复不能由模型生成或正文关键词冒充；缺密码按[保险库安全输入](链接与渠道.md#保险库与安全输入)处理，不收集为普通问题答案。回答过期、重复、来源不符或指向其他工单时拒绝误用；实际未被原 Worker 消费不能显示已经续做。

## 证据与追溯

官方会话日志保留实际执行；Result 与工单保存来源指针、工具证据和必要产物。toolEvidence 的工具名、callId、事件序号、参数/结果、错误标记与 hash 用于事实追溯，按权限有界补读，注明遗漏和截断；不恢复独立模型“补证 → 判通过 → 自动返工”的链路。推理、秘密和不适合公开的原始工具输出不作为成果正文。

后台学习整理只消费已关工单，见[记忆与技能](记忆与技能.md)；它不审核本单是否允许交付，不能成为交付前置。开发时的软件测试、真实渠道验证及用户对产品的验收继续保留，与取消任务内容验收层无关。

## 实现与验收边界

既有实现包括原 Worker 固定轻量自检要求与结构记录、确定性结果检查、持久投递账、可信回执后 completed/failed 关单、发送失败只补投与未知发送核实。新的“保存原稿 → 通知 Router → 自然表达 → 原来源交付”链已接线并有定向测试；安装版真实档案已验证本地文件任务和全新 GitHub 调研的自检、Router 自然回复、原来源接收与 completed 关单，且已保存正式稿的异常恢复只补投，未重跑 Worker。联网主路径在主聊与未归档旁聊并存条件下通过；提问续跑、插话修订、叫停、渠道及审批仍需按新链逐项验证。执行身份、要求应用、权限与恢复的完整边界见[任务与执行](任务与执行.md)。定向测试与生产组件四态检查不等同真实桌面重启或真实渠道端到端验证。

Worker 成果原稿保留在 Result 与工单详情，Router 回复另存，不覆盖原稿。升级时只把尚未发送的旧 `queued` 原结果 outbox 原行转换为待表达完成信号，沿用原投递身份；`sent`、`uncertain` 历史不改写、不自动重发。Router 表达生成与发送分别恢复：已确认失败的表达回合退避后只重试表达，含糊或取消回合不自动重放；已保存回复的发送失败只补投同一回复，未知发送效果先核实，不重 Worker。旧 `benchgo-ticket-state` 排队项在恢复时作废，不继续旧状态投影与新表达两条链；其原 outbox 仍是唯一交付身份，可按当前事实生成新的内部表达回合。

正式稿交付前通过官方会话服务完成持久检查点，插件须显式声明该服务依赖；不能用根上下文测试代替真实插件注入作用域。回复准备与投递记录保存失败分别保留有界诊断标识，仅在任务详情和日志可查，不把原始异常或固定失败文案作为聊天消息。恢复时优先补投已经生成的 Router 正式稿，不重生成、不重执行。

真实桌面调研曾暴露模型正常结束但未登记自检的缺口；关闭前一次补全已接入上述官方接缝，定向测试覆盖同一 Agent、同一会话、同一回合的补全与有界退出。过去安装版主路径与提问续跑已真实通过，但属于旧直投链证据，不能证明 Router 表达交付链，也不能声称全部六项均已通过；新链须重新取得保存原稿、完成信号、Router 回复、送达及关单证据。

旧任务内容 Review 已移除；数据库一次性删除 `review_retry` 调度字段，取消旧待发结论与未开始的补审/返工分派，活动身份不明的旧分派保持 uncertain；历史 Result、Run、证据及可信已送达结果保留。旧问题不再接受答复或触发执行，未送达旧结论停在明确等待状态，须用户明确继续后按新要求和当前授权处理。后台学习队列保留，不属于被取消的内容验收。

验证无独立任务内容验收模型调用，自检不新增 Agent，适用的测试、构建和输出检查真实执行；纯文本零文件可交付，显式验证不遗漏，旧要求结果不抢先关闭。原稿、完成信号、Router 回复、outbox 和回执幂等关联；Router 无需用户追问即可自然提醒，自行选择摘要或完整回复，详情保留原稿，不能重派或验收。成功回复送达后 completed，结构性失败说明送达后 failed；生成失败只重试表达，投递失败只补投回复，两者均待交付且不重 Worker。验证无固定报告、标题前缀、系统状态硬文案及兜底；偶发故障退避、失败原单续做、超时 checkpoint 恢复与未知效果不盲重跑。

验证问题编号与真实来源绑定，内部可答不打扰用户，只有受影响部分等待；普通插话在下一工具边界整份切换、不打断在途，暂停不续跑。原来源免审，其他发送按现行许可，安全输入不泄密。真实界面检查无任务/问题、加载、失败、有结果或卡片四态，区分执行完成、待交付、成功关单、失败关单与停止中，视觉由用户最终验收。
