# SuperAgent 验收与交付

本文维护成果、证据、验收、问题与投递；执行恢复见[任务与执行](任务与执行.md)，聊天展示见[对话交互](对话交互.md)。

## 成果证据与验收

Worker 提交正文成果、做了什么、实际证据和未尽事项。验收以当前 target、acceptance、原始用户要求和授权为准，不临时增加产物条件；代码复核归属、版本、待应用消息和必要检查后，才允许提交完成。

| 任务类型 | 验收依据 |
| --- | --- |
| 纯文本、查询、调研 | 正文满足要求；需要联网核实的内容提供实际来源、时间、覆盖范围、限制与工具证据；允许零文件 |
| 文件、代码、UI、媒体 | 所要求产物或变更可读且符合目标，执行证据可追溯；UI 按要求提供前后视觉证据，用户明确免除时记录边界 |
| 混合成果 | 各部分按各自目标验收，不要求无关附加文件 |
| 外部副作用 | 真实目标、调用回执与效果状态可核实；进程退出和 Worker 自述不足以证明成功 |

宿主从官方会话工具调用与结果生成 toolEvidence，含原工具名、callId、事件序号、参数/结果文本、错误标记与 hash；推理、图片和二进制不复制为验收正文。投影有界，必须标注遗漏、原长度与截断。

验收可按当前 Run 的真实工具序号补读原文，先校验 sessionId、lastSeq、日志 hash 和结果归属；不能读取任意会话或主机文件。当前内部 readEvidence 最多 3 轮补读、每轮最多 8 页、每页最多 8000 字符，仍无可靠结论则等待。

联网证据区分原网址、来源或转载关系、报道时间与抓取时间。同稿转载不算独立多源，只有链接不算读过正文；未核实的标为待确认，不编造链接、star 数或抓取结果。已有替代来源足够时可按用户目标说明限制，工具曾失败不自动否定最终成果。

当前任务验收在 orchestration-runtime 中调用模型，不是把结果交给常驻聊天 Router 再跑一轮。review-worker 另处理学习、记忆和技能复盘，不能混称为任务验收。

### 原日志补读与只读重审

只读重审持有官方会话锁并核对原日志 hash 后重建投影，不重跑 Worker；已保存投影与日志不符时拒绝恢复。索引最多返回最近 256 项并注明遗漏数，正文默认每页 4000、最多 8000 字符，参数最多 2000 字符，附原长度、截断标记与 nextOffset。单次最多四轮模型决策，前三轮可申请补读，最后一轮必须给结论；无可靠依据返回等待。模型路由重试另计，不能以补读掩盖截断或虚构证据。

## 验收分支、Attention 与交付

| 分支 | 系统动作 | 用户可见行为 |
| --- | --- | --- |
| passed | 结果、验收、完成状态与唯一 outbox 一致提交 | 以自然正文回原来源交付 |
| rework / 可修复 failed | 保留原单和成果，核实原执行后追加修正指令、自动续做再验收 | 说明问题与下一步，同类重复状态去重，不额外问是否继续 |
| blocked | 保持打开或等待，创建绑定工单、版本、来源和请求人的 Attention | 提出具体信息、权限或范围问题，回答后原单续做 |
| review_wait | 保留已执行结果，补读证据或有界重试验收，不重复副作用 | 明示系统待核验及真实原因，不让用户替系统判断事实 |
| continuation_wait | 无进展或不能安全续做时保留等待与恢复入口 | 说明已保留成果与恢复条件，不伪装完成 |
| failed / stopped 终态 | 确认不可继续、授权撤回或用户停止等条件才结束 | 说明原因、已保留结果及后续入口 |

本轮结果失败、重试次数耗尽或模型不可用不能单独等同工单终态。内部待核验和真实用户阻塞分开，预算等待已退役。模型不可用时可用明确标注的系统状态，不伪装成模型回答。

Worker 问题原样逐级上报，子代理先到 Worker；需要用户决定的 Attention 回原请求来源。回答绑定原问题、请求人、instructionRevision、结果版本和 requestId；普通下一条消息不能被随意当作答案，过期或已回答问题拒绝重复应用。

Worker 原生 question 与 Review Attention 是不同来源：前者按官方问题调用恢复，后者将真实答案写回原分派 continuation，不能调用不存在的 Worker question。self/default/user 分类只在原 Mandate 范围内自动解答，权限与范围变化必须交用户。

验收与交付状态分离。发送失败只补投已保存结果，不重跑任务；发送效果未知先查回执，渠道无幂等保证时不承诺绝对仅发一次。不能回原来源时保留结果与明确失败，不悄悄改投别处。

当前桌面结果由持久通知投影到原逻辑会话，渠道由适配器发送，另有 deliveryWorker 向 Link/宿主设备送通知。accepted、sent、设备回执和用户已读分别记录，不能互相替代。

## 实现与验收边界

证据投影、只读重审、原成果续做、桌面/飞书 Review Attention 和持久 outbox 已有代码。其他渠道问题关联、真实多轮返工、阻塞回答与重启投递仍须逐场景验证，不能由一次局部成功推断闭环完成。

验证纯文本零文件可验收、证据截断后补读、旧要求版本结果拒绝、错误工具结果不伪装成功。验证返工保留原成果、用户问题精确绑定来源和版本、内部待核验不变成用户审批、发送失败只补投结果、效果未知先核回执以及无法回原来源时明确失败。
