# 渠道轻配置与飞书讨论上下文

更新：2026-11-04，按源码校对；实施与验证记录仍为 2026-11-03。当前入口为资源 → 接入 → 多平台 → 飞书。本轮已实现，验证边界见文末。参考 DSH `6337fc823ce2`、Hermes `50d2adf1cd07`，仅借鉴交互与服务契约，不引入参考仓库依赖。

## 本轮范围

基础流程为填写凭据、验证机器人、选择群、开始对话。飞书组织在平台侧管理应用可见范围，新连接默认沿用平台可访问人员；BenchGo 不再要求再次填写主人 Open ID。平台可访问人员可以提出任务，不因此成为桌面主人或获得配置修改权限。旧连接保留既有人员与群范围，不能静默放宽。

私聊与群聊分开。群配置显示名称，每群选择“仅 @ 时响应”“接收讨论作为上下文”“停用”。接收全部消息不意味着每条都调用模型、回复或创建任务。明确请求触发研判；话题内后续补充作为上下文。主动发现并自动创建任务属于后续能力，不以现有 `auto` 冒充。

## 配置与接口契约

飞书增加 `accessMode: owners | platform`，缺省为 owners 保持旧配置行为；新建连接由界面显式保存 platform。owners 沿用 ownerOpenIds，平台模式不自动赋予 owner 身份。

增加 `directMessages`（缺省 true）、`groups`（null 表示兼容原 chatIds；数组元素 `{chatId,name?,mode: mentions|all|disabled}`）、`otherGroups: disabled | mentions`（缺省 disabled）。新连接使用 groups 数组；显式列出的群规则优先，其他群按 otherGroups。群规则不限制私聊；旧 groups=null 时保留原 chatIds 行为。停用/撤销规则应立即阻止新的读取与交付。

`connectionAction` 增加飞书 `listChats`，返回 `{chats:[{chatId,name}],nextPageToken?}`；输入可带 `pageToken`，只查询机器人已加入的群。认证与机器人识别允许在凭据已保存但连接未启用时验证，不向群发测试消息。返回信息区分认证与真实收发。

群上下文读取由飞书适配器提供有界只读能力，以已认证入站消息为锚点，限制同应用、同群，重新检查现行范围。优先读取话题/引用及少量邻近历史；失败返回明确可见限制，不伪装已读。历史只作为模型参考，不作为新的触发、身份或授权。复用现有研判、工单、执行器链路，禁止新建第二套调度。

界面不再暴露原始 manual/auto，普通渠道高级选项使用说明明确的中文标签；飞书既有书面准入规则在高级设置配置。允许列表内机器消息可无 @ 进入 inferred，但只有 `auto`、非空且唯一的 `## rule: <id>` 书面定义和启用规则 ID 同时满足时才能授权开单；机器不能因此直接回复、控制已有工单或获得主人权限。自由发现群聊任务仍待实施，不能与这条已落地的规则链路混同。回调凭据和原始 ID 仅在必要的高级区域显示。各渠道遵循真实能力，不为私聊专用渠道提供群设置。

## 验收

验证旧配置不扩权、平台模式人类请求不成为主人、群选择/保存/重载一致、分页群列表、私聊隔离、停用范围撤销、未 @不新开任务、历史读取限界与失败降级；界面验证凭据保存保留和未保存保护。同步 OpenAPI；MCP 不新增渠道配置或凭据入口，现有委派契约不变。运行定向测试及 reload:plus，不做视觉验收和真实群自动发消息。

## 实施记录

连接验证返回认证结果及当前长连接状态，两者分别展示；认证通过不代表实际收发已验证。重复验证不重启健康连接，仅在已启用且连接停止或失败时尝试恢复，避免清空接收记录。界面读取状态不会改写未保存配置。

已实现：新连接显式使用飞书应用可用范围；旧连接保留人员和会话限制，界面提供明确的按群迁移操作。私聊独立设置，群支持分页发现、名称搜索及手填 ID 后备入口。机器人身份自动识别且只读；停用态可以验证已保存凭据和查询群，不发送测试消息。认证结果在持久化机器人 ID 后保留。

“仅 @”接收明确请求及任务话题/回复链的补充；“接收讨论”同时保存普通消息作为参考，不为每条消息调用模型或创建任务。默认至多读取 20 条同应用、同群的本地记录和飞书近期消息，按触发消息锚定，补读引用消息；历史失败保留本地已接收内容并明确阅读限制。研判与执行均使用独立参考资料，字符预算和读取超时有界。不是全群历史无限扫描，也不承诺任意附件解析。

平台成员可以发起自己的任务，不成为桌面主人；控制已有任务须为同应用同群的原请求人。既有受控动作审批保持不变。范围关闭同时约束入站、研判、执行和交付。

明确的人类请求经研判可直接回答或追问（`answer` / `ask`），不要求每次创建工单；执行请求才委派。群内未 @ 的普通讨论仍只作为已有任务或研判的参考，直接回复不能绕过准入与现行范围检查。依据为 `src/intake.mjs`、`src/assessment-policy.mjs`、`src/assessment-runner.mjs`（均位于 `plugins/superagent/`）。

本轮相关测试覆盖飞书适配、长连接、配置持久化、界面保存、来源权限、研判/执行参考资料、追问和任务修订、服务入口及 OpenAPI；未执行真实群消息发送或视觉验收。后续主动发现任务、可视化规则和其他平台历史适配仍为待实施能力，本轮没有将 `auto` 解释为群聊主动接单。
