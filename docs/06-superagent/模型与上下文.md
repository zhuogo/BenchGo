# SuperAgent 模型与上下文

本文维护角色模型与上下文装配。共享供应商和不透明 ID 的基础规则见[模型与工具](../04-模型与工具/设计.md)，文档权威和冻结规则见[记忆与技能](记忆与技能.md)。

## 上下文管理与三类模型

上下文目标按三个层次装配：固定文档层、近期原文层、按需材料层。开局装配、每回合补材料、长会话整理各有触发点，压缩不删除原文引用、不偷偷刷新冻结文档。

Router 的十项开局包依次为：系统指令、运行信息、五文件全文、对齐总结、关系索引、活跃目标摘要、能力目录、保险库清单、其他对话摘要、本会话窗口。索引与目录只给名单，正文按需取。

Worker 目标只拿任务包，子代理只拿切片，辅助模型只拿本次工作材料。当前 Router 与 Worker 仍共享 getSessionContext 接口，Worker 会序列化通用上下文快照；不能宣称任务切片和全套文档隔离已严格实现。完整开局包、旁聊动态摘要与无感轮换仍待闭环。

| 模型角色 | 配置与行为 |
| --- | --- |
| Router | models 首选与备用队列，主聊/旁聊共用；新消息从本角色首选开始，回合内冻结路由 |
| Worker | workerModels 专用队列；未配置则继承 Router，任务显式选择优先 |
| 辅助模型 | 一个 auxiliary 槽及备用名单，按看图、压缩、总结、review 能力勾选；未启用能力或失败时按规则回 Router |

研判、任务验收与学习复盘当前可走辅助 review 能力，不只是“打杂”。模型角色是配置分工，不要求三个模型或 Agent 同时常驻。

providerId、modelId、工具名和协议值都是不透明标识，不猜别名或静默改写。选择、保存、重载、能力解析和实际请求必须一致，编辑单项保留其他配置；能力不支持要明确告知。

Fallback 按错误分类、有界备用顺序执行：取消、政策或权限拒绝不切换绕过，403 仅在适配器明确判定凭据故障时处理。跨供应商保留对话语义与工具结果，重新解析推理参数，不重放已生效工具。

密钥池仍是已定目标，当前旧 keyPools 已移除，后续复用基础层凭据与供应商路由落实；不能恢复旧字段冒充完成。RouterGo 管其供应商内部线路，本地备用管客户端目标不可用，避免无界叠加重试。

## 实现与验收边界

五文件冻结、角色模型队列和辅助能力路由已有实现；十项开局包、Worker 严格任务切片、旁聊动态摘要、无感轮换，以及官方只读模型选择契约兼容仍须闭环。配置存在不等于运行链路已使用该角色。

验证显式选择、保存、重载、能力解析与实际请求一致；更改默认值不改变在途请求所记录的配置版本。用真实错误分类验证备用顺序、取消/权限拒绝不切换、跨供应商工具结果保留且不重复副作用。压缩必须保留原文引用与冻结版本；任务切片隔离要检查实际装配内容。
