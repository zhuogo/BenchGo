# SuperAgent 模型与上下文

本文维护角色模型与上下文装配。共享供应商和不透明 ID 的基础规则见[模型与工具](../04-模型与工具/设计.md)，档案权威与冻结规则见[记忆与技能](记忆与技能.md)。

本文的“角色”只指 Router 协调、Worker 执行和辅助模型的配置分工，不是使用者身份或权限等级；渠道使用者的访问权限由对应适配器处理，见[入口与研判](入口与研判.md#已敲定的身份边界与当前差距)。

## 上下文装配

上下文分固定层、会话层和按需层。压缩只改变会话上下文，不删除原文引用，不刷新已冻结的档案。

| 角色 | 自动装配 | 按需读取 |
| --- | --- | --- |
| Router | 官方 preset 与角色工具、BenchGo 内置层；SOUL.md、IDENTITY.md、USER.md、AGENTS.md 正文；本会话历史；每轮匹配记忆；主聊另带最多 20 条未完成目标摘要 | MEMORY.md 与 TOOLS.md 整文、其他会话历史、工单与业务原文、技能正文；名片 HTML 仅在名片相关请求注入 |
| Worker | 本单任务包：executionScope、目标、用户要求、Mandate、已应用的输入、原文指针、目录与请求时间 | 运行时可用的搜索、读取和浏览工具，官方 subagents |
| 辅助模型 | 本次生成、压缩、研判、摘要或整理所需材料 | 无 |

Router 侧规则：

- 首次取上下文时按 sessionId 冻结档案与记忆快照，后续回合复用；档案修改在下一会话生效，明确遗忘会擦除快照中的相关内容。
- 每轮从当前真人消息及可信问答回执取文本，在已冻结的结构化记忆中做字面包含匹配：最多 8 条、每条 2000 字符、合计 8000 字符，无命中不补。USER.md 已全文注入，其条目不参加匹配。这是匹配正文的上限，不是整个请求的 token 预算；整包上下文总预算待实施。
- 历史检索不是开局、每轮或派工前的固定步骤。确需补历史时走[历史会话检索](记忆与技能.md#历史会话检索)，只把相关摘录加入本轮；环境取材由 Worker 完成。
- 能力目录反映真实可用性，保险库清单只给非秘密元数据和句柄。
- 目标清单的定义见[工单、跟进与目标](任务与执行.md#工单跟进与目标)；目标文字是参考数据，不产生授权。
- 用户当面交代的记住、纠正、遗忘由 Router 当场直写，规则见[记忆与技能](记忆与技能.md)。

Worker 侧规则：

- 首条输入使用本单已应用的 executionScope，缺省为本单目标。完整原始用户要求只作来源核对和适用约束，不把其他工单的任务交给本 Worker；动态任务包与首条输入保持一致。
- 普通修订在原会话下一工具批边界整份替换任务包，规则见[任务与执行](任务与执行.md#工单跟进与目标)。
- 不注入 Router 的四份档案和全量记忆。原来源历史目前只有飞书可补取：最近最多 20 条、每条最多 4000 字符、合计默认 12000 字符，读取失败标明不可用；它是参考资料，不是授权。
- 提示词只要求结束时用几句话写清做成了什么、产出在哪、还剩什么问题；验证由 Worker 按任务需要自行完成。结果的保存与交付见[结果与交付](结果与交付.md)。
- 是否拆分由 Worker 使用官方 subagents 决定，子会话的上下文、模型、工具与结果回送全部复用官方能力；BenchGo 只在提示词中鼓励适当拆分，并通过官方事件把子会话关联到原工单。
- Worker 与子代理不写长期记忆。

## 三角色模型与会话归属

### 自有会话角色装配

Agent preset、permission preset 与模型路由分别管理。`session-role-assembly.mjs` 为 Router 和 Worker 装配官方 `standard` 能力组合及 `workspace-write + ask` 权限 bundle，并保留 Router 工具身份白名单、Worker 工单权限门和角色模型路由。

| 事项 | 规则 |
| --- | --- |
| 权限核对 | 核对真实 bundle，不按预设名称推测；官方 `danger-full-access` 默认附带 `never`，不用于本装配。宿主服务、预设或 bundle 不可用时明确受阻，不回退到用户当前档位 |
| 会话归属 | 来自持久主聊 / 旁聊状态、Assignment / Run 和官方子会话的 parentSession，不依赖标题、当前页面或模型声明 |
| 装配记录 | `sa_session_roles` 保存身份、预期装配与最后实测配置（preset、插件模块、工具面、沙箱、审批策略、模型及正式请求中的模型 / 工具身份），不复制对话、工具参数或输出；普通会话查询返回空 |
| 原会话恢复 | 以持久归属和官方 Session 生命周期为准，内存装配标记只是缓存。标记缺失时在安全边界自动恢复上下文、模型路由与工具装配，不要求用户手动结束会话 |
| 单写入者 | 运行中的回合与在途工具不被取消或重放，重新装配不与原写入者同时修改会话；真实归属冲突、会话损坏或装配失败给出具体原因 |
| 界面 | 自有会话通过官方插槽隐藏预设与模型选择器，不展示角色标签；普通用户会话保留官方选择器 |
| 子代理 | 官方 `subagent` 工具经 `ctx.subagents` 建立子会话，生命周期由官方运行时持有。当前官方委派审批策略为 `never`，如实呈现官方结果 |

工作区之外的操作仍受宿主沙箱与真实审批约束，业务授权不会让底层自动放行；对外动作规则见[权限与对外审批](任务与执行.md#权限与对外审批)。

### 模型角色

| 模型角色 | 配置与行为 |
| --- | --- |
| Router 对话模型 | 系统 models 首选与备用队列，主聊、旁聊共用；新回合按本角色路由，回合内冻结实际请求参数 |
| Worker 工作模型 | 取系统工作角色 workerModels 及参数，在执行会话创建时冻结首选、备用顺序与参数；项目或工作区的默认模型不参与覆盖，单工单不接受 provider / model 覆盖 |
| 辅助模型 | 系统 auxiliary 槽及备用名单，按生成、看图、压缩、研判、总结与后台整理等能力使用，不对工单结果评分 |

- 已有执行会话续跑沿用创建时冻结的路由与参数，不随之后的配置改写。运行故障在冻结的备用队列内有界切换，切换后持久记录实际选择，后续续跑沿用。
- 会话的展示归属与模型归属分别确定：移动或恢复所属工作区不改变其模型，插话与普通修订也不重新选模型。
- 子代理的模型选择复用官方 subagents 的配置，BenchGo 不覆盖。
- 模型角色是配置分工，不要求三个模型同时常驻。未配置工作角色或辅助能力不可用时给出明确状态或配置中可见的回退规则，不借用项目默认模型。
- providerId、modelId、工具名和协议值都是不透明标识。选择、保存、重载、能力解析和实际请求必须一致，编辑单项保留其他配置，能力不支持时明确告知。
- Fallback 按错误分类和有界备用顺序执行：取消、政策或权限拒绝不切换，403 仅在适配器明确判定为凭据故障时处理。跨供应商保留对话语义与工具结果，不重放已生效工具。
- 密钥池待实施，后续复用基础层凭据与供应商路由。RouterGo 管供应商内部线路，本地备用管客户端目标不可用，避免叠加重试。

资源导航中的「模型」页管理三个角色，身份页只管名字与形象。角色区域可折叠，摘要显示首选与备用数；保存按完整草稿校验，出错时展开对应角色并保留草稿；目录读取失败可重试或手填完整 ID，不把显示名称当作协议值。

## 执行摘要与监督判断

执行摘要由服务端消费统一执行事实自动生成，不占用 Router 回合，也不由 Worker 自报。它只改变展示，不修改工单状态或通知 outbox。

| 事项 | 规则 |
| --- | --- |
| 触发 | 接单、阶段或工具组结束、子 Worker 派出与返回、受阻与等待、暂停停止、显式续接及终态；先展示确定性粗状态，再合并成约 30 字、最多 40 字的摘要 |
| 模型路由 | `auxiliary-only`，使用 `auxiliary.summary` 能力及其辅助队列；未配置、超时、失败或输出无效时不回落到 Router。取消及权限、政策拒绝不靠切换模型绕过 |
| 限额（可配置） | 4 秒合并窗口，最长等待 12 秒；每单最多 1 个在途请求，全局 2 个；单单最小间隔 15 秒，全局启动间隔 1 秒；输入上限 8000 字符，单次超时 20 秒 |
| 输入 | `executionFacts.evidence()` 的白名单结构：脱敏后的目标与要求、受控状态、事件类别与计数、证据引用、上一版摘要，以及从官方 Session 临时读取的有界 Worker 公开文本。不传工具参数、完整输出、凭据或思维链，不把执行文本当指令 |
| 绑定 | 摘要绑定 Ticket、Run、要求版本、证据水位与状态阶段，更新时复核归属和水位单调性；新的运行、要求版本或阶段会阻止迟到结果覆盖 |
| 存储 | `assistant.db` 只保存派生摘要、有界去重的摘要历史、待处理水位和辅助调用审计；消费水位持久化，重启或查看详情不批量重放历史请求 |

工具计数是会话累计值，不能当作当前要求版本的新进展；证据不足时只描述已知活动。这些限额只约束后台开销，不是工单执行预算。数据契约见[持久执行事实与增量读取](服务契约.md#持久执行事实与增量读取)。

Watchdog 只观察真实机械故障、去重并调度信号，不使用模型判断进展；工具计数不能说明无进展或偏离。其生命周期见[任务与执行](任务与执行.md)。

## 实现边界与验证

已实现（源码接线，安装版未据此验收）：

- `worker-model-route.mjs` 冻结工作角色队列；未单配 workerModels 时沿用配置层明确的 Router 队列继承规则，没有有效模型才报错。队列、参数和当前选择保存在 `sa_worker_execution_state`，不向官方日志追加自定义记录。
- 角色装配已接入主聊、旁聊与 Worker，只影响持久归属的 SuperAgent 会话。
- 项目执行会话在官方 create / resume 后通过 `workspaceRegistry` attach 到同一项目工作区；无项目会话保持官方未分组归属。不自动创建 worktree。
- Worker 任务包只含本单要求快照、executionScope、必要上下文与来源引用；Router 固定档案与有界匹配已接线。
- 执行摘要已接入真实执行与工具事件的白名单输入、辅助队列、合并、限额与持久水位。
- 官方参考版本为 `0.2.2-rc.1`、提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，与根目录 `upstream.json` 和子模块 pin 一致。

待实施：整包上下文总 token 预算、密钥池、旁聊动态摘要和长会话无感轮换。

待验证：

- 角色选择、保存、重载、能力解析与实际请求一致；修改系统与项目配置后续跑，已有会话仍用冻结路由和参数；故障切换后保留实际选择。
- 取消和权限拒绝不切换模型，跨供应商工具结果保留且不重复副作用。
- 空闲恢复、运行中插话、并发发送、工作台跨入口和热重载后的实际角色装配。
- Worker 只取任务包，子代理上下文遵循官方 subagents，压缩保留原文引用和冻结档案。
- 真实宿主沙箱、外部工具、真实供应商请求和安装实例；摘要的安装版事件更新与真实辅助请求。
