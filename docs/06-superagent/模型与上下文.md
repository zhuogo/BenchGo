# SuperAgent 模型与上下文

本文维护角色模型与上下文装配。共享供应商和不透明 ID 的基础规则见[模型与工具](../04-模型与工具/设计.md)，档案权威与刷新规则见[记忆与技能](记忆与技能.md)。

本文的“角色”只指 Router 协调、Worker 执行和辅助模型的配置分工，不是使用者身份或权限等级；渠道使用者的访问权限由对应适配器处理，见[入口与研判](入口与研判.md#已敲定的身份边界与当前差距)。

## 上下文装配

上下文分固定层、会话层和按需层。压缩只改变会话上下文，不删除原文引用，也不承担自我迭代。快照记录该次实际装配版本；持久档案纠正与后续回合的刷新按安全边界处理，不一律等新会话。

| 角色 | 自动装配 | 按需读取 |
| --- | --- | --- |
| Router | 官方 preset 与角色工具、BenchGo 内置层；SOUL.md、IDENTITY.md、USER.md、AGENTS.md 正文；预算内的短 MEMORY 总纲、people/groups INDEX；每次启动读取简短 ALIGNMENT_SYNTHESIS；本会话历史与每轮相关记忆；主聊另带最多 20 条未完成目标摘要 | TOOLS.md、按日详细事实、人物/群组对象页、Dreams 日复盘、其他会话历史、任务与业务原文；PROACTIVE_PREFERENCES 在主动投递决策前读取 |
| Worker | 当前任务包：executionScope、目标、用户要求、Mandate、已应用的输入、原文指针、目录与请求时间 | 运行时可用的搜索、读取和浏览工具、技能正文与官方 subagents |
| 辅助模型 | 本次生成、压缩、研判、摘要或整理所需材料 | 无 |

Router 侧规则：

- 每次 Router 启动装配当前简短对齐总结；档案与记忆按版本建立快照，后续回合在安全边界刷新已纠正或更新的材料，当前在途请求不被改写。明确遗忘会擦除受影响快照并立即限制旧召回。实现与验证边界见[记忆与技能](记忆与技能.md#实现与验收边界)。
- 每轮从当前真人消息及可信问答回执取文本，在当前有效版本的结构化记忆中做字面包含匹配：最多 6 条、每条 2000 字符、合计 4000 字符，无命中不补。USER.md 已全文注入，其条目不参加匹配。自动档案正文合计不超过 12000 字符，并对常驻总纲、对齐和对象目录分别限长；总纲已引用的事实不再重复匹配，来源去重。这些是正文字符上限，不是整个请求的 token 预算；整包上下文总预算待实施。
- 历史检索不是开局、每轮或委派前的固定步骤。确需补历史时走[历史会话检索](记忆与技能.md#历史会话检索)，只把相关摘录加入本轮；文件、网页等环境取材交给 Worker，分工见[Router 与持续主会话](任务与执行.md#router-与持续主会话)。
- 能力目录反映真实可用性，保险库清单只给非秘密元数据和句柄。
- 目标清单的定义见[任务、跟进与目标](任务与执行.md#任务跟进与目标)；目标文字是参考数据，不产生授权。
- Router 主动识别耐久信息，用户当面交代的记住、纠正、遗忘当场直写，规则见[记忆与技能](记忆与技能.md)。

Worker 侧规则：

- 首条输入使用当前任务已应用的 `executionScope`，缺省为当前任务目标。宿主随任务包携带 `mandate.instruction` 原文和 `mandate.triggerId`、`mandate.source` 来源引用。Worker 用原文核对本任务范围内的要求。历史任务可用已保存的 `source` 定位原消息。
- 普通修订在原会话下一工具批边界整份替换任务包，规则见[任务与执行](任务与执行.md#任务跟进与目标)。
- 不注入 Router 的四份档案和全量记忆。原来源历史目前只有飞书可补取：最近最多 20 条、每条最多 4000 字符、合计默认 12000 字符，读取失败标明不可用；它是参考资料，不是授权。
- 提示词只要求结束时用几句话写清做成了什么、产出在哪、还剩什么问题；验证由 Worker 按任务需要自行完成。结果的保存与交付见[结果与交付](结果与交付.md)。
- 是否拆分由 Worker 使用官方 subagents 决定，子会话的上下文、模型、工具与结果回送全部复用官方能力；BenchGo 只在提示词中鼓励适当拆分，并通过官方事件把子会话关联到原任务。
- Worker 与子代理不写长期记忆。

## 三角色模型与会话归属

### 自有会话角色装配

Agent preset、permission preset 与模型路由分别管理。`session-role-assembly.mjs` 为 Router 和 Worker 装配官方 `standard` 能力组合，权限固定为 `danger-full-access + never`；新建、恢复和权限校正均通过官方 `permissionPresets` 服务应用同一组合。Router 再由角色工具门排除继承的通用执行工具，只保留专属产品管理、任务协调与已装配的上下文工具；文件、命令、网页、技能、插件、MCP 与官方 subagents 等执行能力交给 Worker。工具身份与动态变化沿当前注册表核对，不按名称前缀放行插件工具；功能提示随本角色实际工具面装配，不向 Router 宣称已隐藏的能力。BenchGo 内置层补充身份与分工原则，不复制另一份能力说明。来源授权、产品管理工具归属、Worker 任务权限门和角色模型路由继续分别生效。

| 事项 | 规则 |
| --- | --- |
| Router 工具面 | `router-tools.mjs` 原有专属产品与任务工具、`ask_user_question`、官方 Schedule 四工具，以及经 Efficiency 所有权验证的 `context_status` / `compact_now`；按已捕获的定义身份校验，不凭 `assistant_*` 名称前缀放行其他注册 |
| 权限核对 | 核对官方 `danger-full-access` 对应的真实 bundle 必须为 `danger-full-access + never`，不按显示名称推测；宿主服务、预设或 bundle 不可用时明确受阻，不回退到普通会话的当前档位 |
| 会话归属 | 来自持久主聊 / 旁聊状态、Assignment / Run 和官方子会话的 parentSession，不依赖标题、当前页面或模型声明；任务修订使用引擎提供的逻辑会话 lineage，主聊清空或模型 session 更换后仍可跟进原任务，不放宽无关旁聊归属 |
| 装配记录 | `sa_session_roles` 保存身份、当前预期装配与最后实测配置（preset、插件模块、工具面、沙箱、审批策略、模型及正式请求中的模型 / 工具身份）；存储初始化及绑定时更新预期值，配置变化使旧实测缓存失效，冷会话标为待核验，实际装配后才记录实测值；不伪造历史观察，不复制对话、工具参数或输出；普通会话查询返回空 |
| 原会话恢复 | 以持久归属和官方 Session 生命周期为准，内存装配标记只是缓存。标记缺失时在安全边界自动恢复上下文、模型路由与工具装配，不要求用户手动结束会话 |
| 单写入者 | 运行中的回合与在途工具不被取消或重放，重新装配不与原写入者同时修改会话；真实归属冲突、会话损坏或装配失败给出具体原因 |
| 界面 | 自有会话通过官方插槽隐藏预设与模型选择器，不展示角色标签；普通用户会话保留官方选择器 |
| 子代理 | 官方 `subagent` 工具经 `ctx.subagents` 建立子会话，生命周期由官方运行时持有。进程内子代理在创建时继承父会话的 Full 权限与 `never` 审批策略，其他提供方按其官方契约执行，如实呈现能力限制 |

Full 取消 DSH 文件沙箱的目录范围限制，Worker 目录只组织工作与产物，不是唯一可写位置；操作系统权限和工具自身能力仍以实际结果为准。`never` 表示不发起宿主权限审批，不等于自动批准业务动作，也不决定已有待批请求。任务范围、停止、撤权与对外动作约束见[权限与对外审批](任务与执行.md#权限与对外审批)。Watchdog 使用独立只读装配，不随 Router / Worker 的 Full 设置变化。

### 模型角色

| 模型角色 | 配置与行为 |
| --- | --- |
| Router 对话模型 | 固定官方 DeepSeek Harness，主聊和旁聊共用系统 models 首选与备用队列，继续使用 BenchGo 任务协作工具。新回合按角色路由，回合内冻结实际请求参数 |
| Worker 工作模型 | Worker 角色选择官方 DeepSeek Harness、Codex 或 Claude Code。其模型槽复用共享 API 目录。本机与跨设备创建执行时冻结 Harness、供应商、模型和参数 |
| 辅助模型 | 固定官方 Harness 的 API 请求路径。设置只显示供应商、模型及能力和备用名单，按生成、看图、压缩、研判、总结与后台整理使用 |

- 已有执行会话续跑使用冻结的组合与参数。官方 Worker 保留有界备用机制。外部 Worker 提交后按原执行身份核实和恢复，切换 Harness 或供应商须由明确的新执行动作发起。
- 会话的展示归属与模型归属分别确定：移动或恢复所属工作区不改变其模型，插话与普通修订也不重新选模型。
- 子代理的模型选择复用官方 subagents 的配置，BenchGo 不覆盖。
- 本机官方 Worker 优先使用显式工作队列。工作队列为空时，按 Router 设置中保存的首选及备用顺序继承模型和请求参数。Codex 与 Claude Code 需要一个显式兼容的 API 模型。
- 辅助用途缺少专用队列或未启用时使用主模型。会话压缩沿用本次会话请求的模型，后台执行摘要等独立请求沿用 Router 设置。
- providerId、modelId、工具名和协议值都是不透明标识。选择、保存、重载、能力解析和实际请求必须一致，编辑单项保留其他配置，能力不支持时明确告知。
- 本机角色 Fallback 按错误分类和有界备用顺序执行：取消、政策或权限拒绝不切换，403 仅在适配器明确判定为凭据故障时处理。跨供应商保留对话语义与工具结果，不重放已生效工具；远端 v2 只冻结一个模型，不继承该备用队列能力。
- 密钥池待实施，后续复用基础层凭据与供应商路由。RouterGo 管供应商内部线路，本地备用管客户端目标不可用，避免叠加重试。

资源导航中的「模型」页管理三个角色，身份页只管名字与形象。只有 Worker 行显示 Harness 选择，复用 [API 执行目录](../04-模型与工具/模型与供应商.md#共享-api-目录与执行选择)。保存按完整组合校验，出错时保留草稿并展开对应角色，目录失败可重试。

### 跨设备模型归属

A 的 Router 使用 A 的对话模型并固定走官方 Harness。跨设备业务任务仍属于 A；`assistant_devices({ deviceId })` 经 Link 读取 B 的真实执行目录，A 在 `assistant_delegate` 显式提交 `deviceId`、可选 `projectId` 与 `executionConfig: { harness, models:[{ providerId, modelId, params? }] }`。A 将所选组合冻结在 Mandate / Assignment；B 核验后使用本机 API 凭据、工具和项目目录执行，无需启用 B SuperAgent。

B 发布其真实可用的官方 Harness、Codex 和 Claude Code 组合。A 每张工单仍冻结一个明确组合。B 复用与本机 Worker 相同的执行入口。外部工具按 [Full access 与隔离配置](../04-模型与工具/原生工具与会话.md#会话权限)启动。B 的模型设置与工具凭据为执行依据，A 不读取或同步 B SuperAgent 配置和密钥。

远端单任务的显式执行选择不同于本机模型覆盖：模型及参数必须与 B 本次目录逐项一致，再由 B 精确解析 provider / model 并核对能力；目录未声明的参数也不能临时添加。A 的供应商标识不能未经核验当作 B 的同名供应商使用；缺少明确配置返回 `EXECUTION_CONFIG_REQUIRED`，不猜别名、不自动套用 B SuperAgent 工作角色。凭据保留在 B，A 只保存选择及必要参数，不同步密钥。普通修订、关联调整与暂停恢复保持原设备和执行配置，不以修订静默换项目或模型；选择、保存、重载与实际请求须一致。

远端不可达或能力不足时返回明确状态，不跨设备静默回退；确认暂停后的恢复保留原执行、原会话和冻结配置，不确定中断只核实原记录。B 使用官方 standard / Full 或 Commander Full access，传入 A 冻结的要求、Mandate 约束、必要上下文与来源引用，不装配 B Router 的人格、记忆、目标清单、研判或任务工具，也不同步 A 全量记忆或凭据。官方 Worker 的远端工具门拒绝 `assistant_*`、`commander_*`、子代理与调度类工具；本机官方 subagents 规则不据此宣称跨设备已支持。执行定位与授权以[跨设备协作](../01-设备与远程连接/跨设备协作.md#项目归属与远端执行)为准。

## 执行摘要与监督判断

任务线的具体动作优先使用执行者自己公开撰写的短句，提取、脱敏与保留规则统一见[执行动态观测](任务与执行.md#执行动态观测)。服务端仍消费统一执行事实生成有界阶段摘要，不占用 Router 回合；这条既有辅助路径用于汇总，不是逐动作摘要的前置条件。两者只改变展示，不修改任务状态或通知 outbox。

| 事项 | 规则 |
| --- | --- |
| 触发 | 受理任务、阶段或工具组结束、子 Worker 派出与返回、受阻与等待、暂停停止、显式续接及终态；先展示确定性粗状态，再合并成约 30 字、最多 40 字的摘要 |
| 模型路由 | `auxiliary-only`，启用 `auxiliary.summary` 且配有专用模型时仅使用辅助队列。缺少专用配置或用途关闭时使用 Router 首选与备用。取消及权限、政策拒绝终止请求；队列用尽后保留确定性摘要 |
| 限额（可配置） | 4 秒合并窗口，最长等待 12 秒；每项任务最多 1 个在途请求，全局 2 个；单项任务最小间隔 15 秒，全局启动间隔 1 秒；输入上限 8000 字符，单次超时 20 秒 |
| 输入 | `executionFacts.evidence()` 的白名单结构：脱敏后的目标与要求、受控状态、事件类别与计数、证据引用、上一版摘要，以及从官方 Session 临时读取的有界 Worker 公开文本。不传工具参数、完整输出、凭据或思维链，不把执行文本当指令 |
| 绑定 | 摘要绑定 Task、Run、要求版本、证据水位与状态阶段，更新时复核归属和水位单调性；新的运行、要求版本或阶段会阻止迟到结果覆盖 |
| 存储 | `assistant.db` 只保存派生摘要、有界去重的摘要历史、待处理水位和辅助调用审计；消费水位持久化，重启或查看详情不批量重放历史请求 |

工具计数是会话累计值，不能当作当前要求版本的新进展；证据不足时只描述已知活动。这些限额只约束后台开销，不是任务执行预算。数据契约见[持久执行事实与增量读取](服务契约.md#持久执行事实与增量读取)。

Watchdog 只观察真实机械故障、去重并调度信号，不使用模型判断进展；工具计数不能说明无进展或偏离。其生命周期见[任务与执行](任务与执行.md)。

## 实现边界与验证

已实现（源码接线，安装版未据此验收）：

- 本机派发、任务调度和 `worker-model-route.mjs` 复用同一模型选择规则。Run 冻结队列、参数及当前选择，记录在 `sa_worker_execution_state` 中，续跑继续使用这份记录。
- 角色装配已接入主聊、旁聊与 Worker，只影响持久归属的 SuperAgent 会话。
- 项目执行会话在官方 create / resume 后通过 `workspaceRegistry` attach 到同一项目工作区；无项目会话保持官方未分组归属。不自动创建 worktree。
- Worker 任务包只含当前任务要求快照、executionScope、必要上下文与来源引用；Router 固定档案与有界匹配已接线；本轮短总纲、对齐/对象目录装配和安全边界刷新按[记忆与技能](记忆与技能.md#实现与验收边界)区分接线与待验。
- 执行摘要已接入真实执行与工具事件的白名单输入、辅助队列、合并、限额与持久水位。
- 官方能力的参考版本见[服务契约](服务契约.md#官方能力参考版本)，候选官方引擎的运行兼容性仍待核验。

跨设备执行配置已由 `execution-catalog.mjs`、统一受理及 B `remote-execution.mjs` 接线；旧目标 SuperAgent 工作模型解析已删除。定向 fixture 覆盖无 B SuperAgent 的官方单模型执行、精确标识和参数核验；实际双机供应商请求与目标文件权限仍按[模块清单](任务与执行.md#跨设备实施顺序与删除清单)验收，不以目录可读代替真实执行。

待实施：整包上下文总 token 预算、密钥池、旁聊动态摘要和长会话无感轮换。

待验证：

- 角色选择、保存、重载、能力解析与实际请求一致；修改系统与项目配置后续跑，已有会话仍用冻结路由和参数；故障切换后保留实际选择。
- 取消和权限拒绝不切换模型，跨供应商工具结果保留且不重复副作用。
- 空闲恢复、运行中插话、并发发送、工作台跨入口和热重载后的实际角色装配。
- Worker 只取任务包，子代理上下文遵循官方 subagents，压缩保留原文引用和实际装配版本。
- 关闭或不启用 B SuperAgent 后，在真实部署验证 A 的目录选择、冻结配置和 B 本地凭据实际请求；改动 B SuperAgent 模型设置不影响该执行。缺配置、额外模型/目录外参数和同名供应商误配明确受阻，不以配置页面或目录返回代替实际请求。
- 真实宿主沙箱、外部工具、真实供应商请求和安装实例；摘要的安装版事件更新与真实辅助请求。
