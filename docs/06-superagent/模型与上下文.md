# SuperAgent 模型与上下文

本文维护角色模型与上下文装配。共享供应商和不透明 ID 的基础规则见[模型与工具](../04-模型与工具/设计.md)，文档权威和冻结规则见[记忆与技能](记忆与技能.md)。

本文“角色”仅指 Router 协调、Worker 执行和辅助模型的配置分工，不是使用者身份或权限等级。已确定核心引擎不区分主人与其他用户；飞书等外部使用者的访问权限由对应渠道适配器处理。通用层不再区分使用者权限等级，渠道身份规则由适配器处理，边界见[任务与执行](任务与执行.md#router-与持续主会话)。

## 上下文装配

上下文目标按三个层次装配：固定文档层、近期原文层、按需材料层。开局装配、每回合补材料、长会话整理各有触发点，压缩不删除原文引用、不偷偷刷新冻结文档。

上下文分类用于说明职责，并非每次请求必须填满的十项固定包：系统指令、运行信息、四份固定档案正文（SOUL、IDENTITY、USER、AGENTS）、对齐总结、关系索引、活跃目标摘要、能力目录、保险库清单、其他对话摘要、本会话窗口。索引与目录只给名单，正文按需取。

历史检索不作为开局、每次对话或委派前的固定步骤。Router 已有足够上下文时直接回答或按既有规则派工；确需补历史时走[历史会话检索](记忆与技能.md#历史会话检索)的官方索引与定点读取，仅把相关摘录或原文切片加入本轮。连接资料、文件调查等环境取材由 Worker 在授权范围内完成，不为了开单先在 Router 全面搜索。工具与 HTTP 已共用官方检索适配，实际部署、持久索引和中文覆盖限制按所属模块验证，不将源码接线等同于全部公开历史可检索。

能力目录反映当前真实可用性，保险库清单只给非秘密元数据和句柄。Main Agent 内部完整能力不代表 Worker 获得全套上下文；Worker 的上下文切片与工具面按[权限继承规则](任务与执行.md#权限与对外审批)同步裁剪，授权记录由服务读取，不以提示词或历史摘要代替。

Worker 只拿本工单任务包：本单 executionScope、目标、必要上下文、轻量自校验要求、Mandate、当前输入及原文指针。首条 followup 使用本单已应用 executionScope，缺省使用本单目标；原始用户整段要求仅供来源核对与提取适用约束，不把其他工单任务再次交给每个 Worker。动态任务包与首条执行输入必须一致，避免同一批请求重复分工。已确定由 Worker 官方会话自行决定是否使用官方 Harness subagents；BenchGo 只在提示词中鼓励适当拆分，不自定义子代理层级、历史继承、工具白名单、通信或模型装配规则，不另建子工单或执行器。这些自有附加限制已移除，真实宿主委派路径仍需安装验收。辅助模型只拿本次生成、压缩、研判或整理所需材料。

Worker 在原执行中按任务需要运行测试、构建或检查。Harness 正常结束且有结果后直接保存原稿、完成工单并通知 Router，不追加自检补回合、效果审核或循环核查。用户通常由 Router 协调，也可在工作台直接向 Worker 或官方子代理发消息；Router 读取已存成果，主动自然提醒已完成，自选摘要或完整回复，再向原来源交付。Router 只负责表达，不重派、不做内容验收，不固定报告、标题前缀或系统状态文案；原稿保留在工单详情，追问仍可按需读取直接回答。结果保存无阻断是已定待实施目标，接纳原稿不依赖自检、证据或版本校验通过，唯一规则见[结果保存无阻断](自校验与交付.md#结果保存无阻断)。在办要求走修订，已完成结果不满意由用户找 Router 派关联调整单；生成或投递失败保持待交付，只重试表达或投递，不重跑 Worker。具体见[任务与执行](任务与执行.md)与[自校验与交付](自校验与交付.md)。

用户当面交代的记住、纠正、遗忘由 Router 当场直写，不开工单。Worker 与子代理不直接写长期记忆；后台整理流程按计数器从已关工单的持久材料中提炼，不经 Router 上下文，整理结果可纠正、可回滚。具体规则见[记忆与技能](记忆与技能.md)。

当前源码按 sessionId 冻结六档案目录与记忆；Router 正文只注入 SOUL.md、IDENTITY.md、USER.md、AGENTS.md，MEMORY.md 与 TOOLS.md 按需读取。IDENTITY/USER 不再复制额外字段，USER 条目不重复参加自动匹配。匹配仅保留有命中的归一化去重正文，最多 8 条、每条 2000 字符、合计 8000 字符，无命中不拼末尾记忆；名片 HTML 仅在相关请求注入。此预算不等同于完整模型请求的总 token 上限。历史显示复用事件水位缓存，不重复投影未变化回合。

## 三角色模型与会话归属

### 自有会话角色装配

Agent preset、permission preset 与模型路由分别管理。`session-role-assembly.mjs` 统一配置 Router / Worker 的官方 `standard` 能力组合及 `workspace-write + ask` 权限 bundle，保留既有 Router 工具身份白名单、Worker 工单权限门和角色模型路由。装配核对真实 bundle，而非根据预设名称推测权限；官方 `danger-full-access` 默认附带 `never`，不用于本装配。宿主服务、预设或 bundle 不可用时明确受阻，不回退用户当前档位。工作区之外的操作仍受宿主沙箱与真实审批约束，业务授权本身不会使底层自动放行。

会话归属来自持久主聊 / 旁聊状态、Assignment / Run 和官方子会话 parentSession；不依赖标题、当前页面或模型声明。`sa_session_roles` 只保存身份、预期装配与最后实测配置，普通会话查询返回空；旧自有会话尚无装配记录时仍按持久归属恢复，不将缺记录当作普通会话或拒绝聊天的权限条件。记录包括实际挂载与日志选择的 Agent preset、插件模块、工具面、沙箱及额外可写目录、审批策略、当前模型和正式 request/header 的模型 / 工具身份；不复制对话、工具参数或输出。

原会话恢复的权威是上述持久归属与官方 Session 生命周期，内存装配标记仅为缓存。热重载、工作台打开原会话或实例交接后缺少标记时，应自动在安全边界恢复所需上下文、模型路由与工具装配，不以“未装配角色”要求用户手动结束会话。复用官方单写入者约束：正在运行的回合与在途工具不被强制取消或重放，重新装配不得与原写入者同时修改会话；原 Agent 可在官方空闲维护阶段复用，写入者已释放时才续接持久会话，两者均沿原 sessionId 和历史接续。真实归属冲突、官方会话损坏或宿主装配失败须给出具体原因，不能仅凭缓存缺失判断冲突。该恢复契约须分别验证空闲恢复、运行中插话、并发发送、工作台跨入口和热重载后的实际装配，不以代码接线代替安装版验收。

新会话挂载时通过官方 preset 装配；已运行旧会话续用其持久保存的 preset 并挂载同一组合，不改写历史、不重放、不因与新默认值不同而触发 ROLE_MIGRATION_UNAVAILABLE。permission bundle 仍核对真实 workspace-write + ask，setter 不回答或替换未决审核。移除每步、每工具及请求前的重复全量装配扫描；正式 request/header 继续记录实际模型与工具身份，真实任务范围与官方工具边界仍生效。Worker 使用创建时冻结工作路由，官方子代理不额外装配。

官方 `subagent` 工具经 `ctx.subagents` 的 provider 建立子会话，创建、激活、结果回送和清理由官方运行时持有，独立 Session 不表示独立宿主进程。BenchGo 通过官方事件关联原工单；已删除一层、工具白名单、模型覆盖和子角色装配，委派完全复用官方服务，不新建子 Worker 运行时。当前官方委派审批策略为 `never`，应如实呈现官方结果，不把拒绝当批准。

| 模型角色 | 配置与行为 |
| --- | --- |
| Router 对话模型 | 系统 models 首选与备用队列，主聊、旁聊共用；新回合按本角色路由，回合内冻结实际请求参数 |
| Worker 工作模型 | 新执行会话取系统工作角色 workerModels 及参数，在会话创建时冻结首选、备用顺序与参数；所属项目或工作区的默认模型不参与覆盖 |
| 辅助模型 | 系统 auxiliary 槽及备用名单，按生成、看图、压缩、研判、总结与后台整理等能力使用；只处理本次工作材料，不承担工单内容验收 |

执行会话底层属于任务所在项目的工作区，无项目任务保持官方未分组归属；Worker 和官方子代理在工作台侧栏可见，可直接发消息；任务详情也打开同一官方会话。Router 主聊与旁聊保留 SuperAgent 入口。会话的展示归属与模型归属分别确定：移动或恢复所属工作区不将其模型改成该工作区或项目默认值。执行会话输入与主聊天归入该工单的输入共用同一份记录，模型路由不因插话或普通修订重新选择；会话入口及保留规则见[任务与执行](任务与执行.md)。

已有执行会话续跑使用创建时冻结的工作角色路由与参数，不随之后的系统、项目或工作区配置改写。运行故障可在该冻结备用队列内有界切换；切换后持久记录实际选择，后续续跑沿用该选择，不每次退回首选模型。恢复时不得用最新配置重新拼接备用名单或替换旧参数。

工单 Worker 模型按本节配置；会话内子代理模型选择复用官方 Harness subagents 的能力和配置，BenchGo 不额外覆盖或装配。子会话不再强制套用父 Worker 冻结路由和参数，实际选择遵循官方配置。

入口研判与后台整理可使用辅助模型，不对工单结果评分或决定放行；Worker 自校验留在原执行会话，不另开验收模型会话。模型角色是配置分工，不要求三个模型或 Agent 同时常驻。未配置工作角色、辅助能力不可用等情况须给出明确状态或配置中可见的回退规则，不默默借用项目默认模型；辅助路由兜底不将后台结果注入 Router 聊天上下文。

providerId、modelId、工具名和协议值都是不透明标识，不猜别名或静默改写。选择、保存、重载、能力解析和实际请求必须一致，编辑单项保留其他配置；能力不支持要明确告知。

资源导航中的「模型」独立管理三个角色；身份页仅管理名字与形象。角色区域可折叠，折叠摘要展示首选与备用数；完整供应商和模型 ID 可展开、选择与复制。保存按完整草稿校验，缺失、重复或非法 ID 自动展开对应角色并保留草稿；目录读取失败允许重试或手填完整 ID，不将显示名称当作协议值。编辑与排序后保持键盘焦点，保存失败在原页重试，不丢失其他角色配置。

Fallback 按错误分类、有界备用顺序执行：取消、政策或权限拒绝不切换绕过，403 仅在适配器明确判定凭据故障时处理。跨供应商保留对话语义与工具结果，重新解析推理参数，不重放已生效工具。

密钥池仍是已定目标，当前旧 keyPools 已移除，后续复用基础层凭据与供应商路由落实；不能恢复旧字段冒充完成。RouterGo 管其供应商内部线路，本地备用管客户端目标不可用，避免无界叠加重试。

## 执行摘要与监督判断

执行摘要由服务端消费统一执行事实自动触发，不占用 Router 对话回合，也不由 Worker 自报进度。接单、阶段或工具组结束、子 Worker 派出与返回、受阻与等待、暂停停止、显式续接及终态等关键事件先展示确定性粗状态，再合并为约 30 字、最多 40 字的当前摘要；列表与详情读取同一派生投影。摘要只改变展示，不修改工单状态、验收结论或通知 outbox。

后台执行摘要显式使用 `auxiliary-only` 路由，复用配置中的 `auxiliary.summary` 能力及其有序辅助队列。辅助角色可以选择与 Router 相同的模型 ID，但使用自身参数；未配置、能力未启用、超时、失败或输出无效时，不追加或跳回 Router。既有用户主动总结、入口研判等调用保留各自原有路由规则，不能把后台严格路由概括为所有辅助调用都禁止既有回退。取消及权限、政策拒绝不靠切换模型绕过。

摘要默认按 4 秒窗口合并，最长等待 12 秒，关键事件达到阈值也可提前处理；每单最多一个在途请求，全局最多 2 个，单单最小调用间隔 15 秒、全局启动间隔 1 秒，输入上限 8000 字符、单次超时 20 秒。窗口、阈值、并发、频率、输入及超时均可配置。消费水位持久化；启动先对齐历史事实，不因重启或查看详情批量重放历史模型请求，后续新执行事件才触发自动摘要。持续事件不会无限推迟发布。同阶段的新事件保留已绑定旧水位的有效文字，新的运行、要求版本或状态阶段则阻止迟到结果覆盖。此类限额只约束后台开销，不构成工单执行预算或截停条件。

模型输入复用 `executionFacts.evidence()` 的白名单结构：脱敏目标和验收、受控状态、事件类别与计数、证据引用、上一版摘要；按该执行的 session 与证据水位，从官方 Session 服务临时读取有界的 Worker 公开文本作为业务进度线索。公开文本先脱敏、限长并绑定原事件引用，不另存原文副本，也不把模型自述当作已核验结果。目标与要求自由文本同样脱敏，不传原始工具参数、完整工具输出、凭据或思维链，不把执行文本当成指令。当前工具计数明确为会话累计，不能推定为当前要求版本的新进展；不传 `artifactCoverage`、`outputObservation`、`zeroFileChangeWindow` 等无真实数据源的文件观察字段。证据不足只描述已知活动，不编造完成、原因或效果。

摘要绑定 Ticket、Run、要求版本、证据水位及状态阶段，更新时复核归属和水位单调性。`assistant.db` 只保存派生摘要、有界且去重的摘要历史、待处理水位和辅助调用审计，不复制官方 transcript 或另立工单账。摘要历史保留时间和证据引用，截断时明确标记，完整记录仍以官方执行会话为准；没有历史摘要的旧工单不补造阶段进展。调用、完成、迟到丢弃、失败和降级均可查；模型失败保留仍有效的文字，并公开确定性降级及真实错误类别。纯摘要展示事件不再次触发模型，展示更新与对外通知分离。

Watchdog 仅观察真实机械故障、去重并调度既有信号；不再装配辅助模型进展判断、`watchdogAuxiliary` 或无数据源的文件零变化协议。旧模型告警只保留历史，不消费或重发。工具计数仅说明活动，不能判断无进展或偏离；外部监督的信号与检查生命周期见[任务与执行](任务与执行.md)。

## 实现边界与验证

以上是目标设计，以下按仓库源码区分现状，不代表已打包运行实例已经验证：

- 新执行会话只读取统一配置层解析后的工作角色队列，再由 `worker-model-route.mjs` 冻结；未单配 `workerModels` 时沿用配置层明确的 Router 队列继承规则，没有有效模型才报错。单工单、修订及目标节点不接受 provider/model 覆盖，旧字段请求明确拒绝，项目默认值不参与路由。执行器在实际请求边界应用冻结的模型与角色参数，保持供应商 ID 原样。
- 当前统一角色装配接入主聊、旁聊与 Worker；官方子代理不再附加自有装配与一层限制；只影响持久归属的 SuperAgent 会话，普通会话保留官方选择路径。定向验证使用锁定版本真实 Agent / preset / permission / Session 服务与脚本化模型适配器，覆盖首轮纠正、旧 preset 原会话续接、原审批身份保留及持久角色恢复；不等于实际宿主沙箱、外部工具、安装实例或真实供应商请求已验。旧会话沿保存的 preset 原地续用，安装版历史兼容仍须实际验收。
- 工作队列、参数、当前选择和自检记录持久化在 BenchGo 自有 `sa_worker_execution_state`，不向官方日志追加自定义插件记录。备用切换后保存 index，恢复沿用同一队列。旧 Run 首次恢复时只读迁移旧队列并记录 `legacy-queue`；没有队列的记录只保留官方保存的选择及可恢复请求参数，记录 `legacy-selection`，不拼接当前备用模型。迁移后只读新表，旧日志保留历史证据，不改写。
- 当前子代理完全复用官方 subagents 的模型与工具配置，BenchGo 仅保留工单关联。官方参考版本为 `0.2.2-rc.1`、提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，与当前根目录 `upstream.json` 和子模块 pin 一致。
- Worker 动态任务包仅装配原工单已应用的本单要求快照与 executionScope、必要任务上下文和来源引用，不再序列化 Router 通用上下文；普通修订在原会话下一工具批边界整份替换，窄 Assignment 保留任务切片。Router 固定档案与有界匹配已接线，旁聊动态摘要和长会话无感轮换仍需独立验证。
