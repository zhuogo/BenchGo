# SuperAgent 任务与执行

本文维护 Router 协调、任务与修订、目标清单、Worker 执行、权限审批、恢复与监督。准入见[入口与研判](入口与研判.md)，三态、结果与交付见[结果与交付](结果与交付.md)，字段与接口见[服务契约](服务契约.md)。

## Router 与持续主会话

Main Agent 是用户的对话入口和总调度者，Router 是它的职责名称。主聊和每个旁聊各有一个官方会话，共用 SuperAgent 模型配置和能力基线；旁聊只隔离话题与归属。Router、Worker 是职责分工，不是使用者权限等级；渠道使用者的身份与准入归适配器，见[入口与研判](入口与研判.md#已敲定的身份边界与当前差距)。角色的 preset、权限组合与模型路由见[自有会话角色装配](模型与上下文.md#自有会话角色装配)。

| Router 做什么 | 规则 |
| --- | --- |
| 直接办理 | 普通问答、任务查询与整理、卡片提问、定时提醒、当面记忆，以及产品自身的状态与设置；任务重命名、归档和恢复展示复用原任务服务，不创建 Worker 任务；角色工具范围见[自有会话角色装配](模型与上下文.md#自有会话角色装配) |
| 委派执行 | 文件调查、命令执行、网页浏览、代码修改、技能调用、插件和 MCP 工具等环境操作，从第一次探查起交给 Worker；不因只有一两步而直做，不经第二个模型复审，也不额外询问是否允许创建任务 |
| 委派之后 | 任务落库即返回，Router 自然回应并继续接受其他请求，不阻塞等待 Worker |
| 结果回来 | 读结果后主动自然告知，没做成就直说；不重派、不验收，见[结果保存与 Router 表达交付](结果与交付.md#结果保存与-router-表达交付) |
| 多个请求 | 不相关的新请求各自分诊、查重后并行委派；同一会话的写入串行 |
| 工具失败 | 真实错误码、原因和有界诊断保留在实际执行会话、任务详情与日志；Router 按真实情况说明，不猜测原因，不将能力或审批受阻说成必须重启 |

Router 负责对话、研判和协调，环境执行统一由 Worker 承担。产品专属的设置、记忆和任务控制仍沿原领域工具办理；设置服务可管理的 MCP 配置沿设置工具处理，实际连接验证和 MCP 工具调用交给 Worker。

效率重点是缩短委派与执行链路：Router 根据现有对话和必要的任务查询尽快委派，不先开展环境预调查，不轮询等待结果；任务受理即返回对话。Worker 接单后按真实任务范围及时执行，无关任务在现有并发限额内独立推进；不增加复审、固定报告或重复探查。

Router 的产品工具在 `router-tools.mjs` 注册，角色工具门排除继承的通用执行工具，仅保留已装配的专属产品与上下文工具；Worker 复用官方 preset 和当前可用插件。内置提示词真源是 `plugins/superagent/prompts/builtin-layer.md`，与用户档案分层，用户档案不能覆盖平台机制。表达原则见[Router 对话准则](Router对话准则.md)。

**收件与回执。** 逻辑 thread 与底层官方 session 分离。`send` 接受 threadId、text、requestId 和可选 replyContext，先持久收件，再串行启动 Router 回合；同 requestId 同内容幂等，内容变化则拒绝。回执区分 queued、processing、processed、failed、uncertain、cancelled，processed 只表示 Router 回合结束；回执未知时不自动重发。取消只作用于排队请求和当前 Router 回合，不撤销后台任务；清空聊天保留任务、去重记录和会话归属。

Worker 结果保存后，提交事件唤醒所属原 Router 的同一持久 inbox，按任务结果版本幂等，1 秒恢复检查兜底。人类消息优先，信号不打断当前回合；消费后使用普通公开正文及官方历史告知，不生成新的执行任务。回复失败只恢复告知，回调失败只补事实或外部发送入队，不续跑或重派 Worker。源码接线及定向验证通过，安装版仍待用户验收；历史兼容边界见[结果与交付](结果与交付.md#实现与验收边界)。

## 任务、跟进与目标

任务账在 `orchestration-store.mjs`。一项任务记录标题、目标（target）、用户明确的结果条件（acceptance）、当前摘要、来源和授权快照（Mandate）。

| 事项 | 规则 |
| --- | --- |
| 标题与摘要 | 标题至多 10 个 Unicode 字符，写清替用户做的具体事情，不用“执行任务”这类占位；用户指定的标题优先。target 与 acceptance 不截断；acceptance 只承接用户明确提出的结果条件，不是验收门。改标题不改要求版本 |
| 分诊与查重 | 直接问题当场答，执行请求创建任务，在办任务的相关消息走原任务，无关新事独立创建任务。新建前按在办和最近完成任务的标题与当前摘要查重；同一 Trigger 只生一项任务，标题相近不强行合并任务 |
| 授权快照 | 用户指令是授权源头。Mandate 保存策略版本、范围、强度、命中规则、发起人身份五要素和可信原始指令引用；没有适用书面规则时命中规则为空，模型不能生成默认授权。宿主确定性核对真人来源、归属、幂等和版本；范围内的自然语言理解由 Router 负责 |
| 一条消息多项任务 | 每个 Worker 的首条输入只取当前任务的 `executionScope`（缺省为当前任务目标）；完整原话只作来源与适用约束 |
| 普通修订 | 原范围内的补充、调整和插话直接记入同一任务，生成完整的当前要求快照；在途工具不打断，Worker 在下一工具提交边界把目标、要求、上下文和工具范围整份切换。要求编号只作后台顺序与防迟到，不需要用户确认。询问进度或细节只回答，不修改任务 |
| 暂停 | Router 对原任务调用 `assistant_task_control pause`。`pauseRequested` 表示后续动作已拦截，`paused` 才是执行端确认暂停。暂停期间只收修订、不启动工具；用户明确恢复后先应用最新快照再执行 |
| 扩权 | 只有超出 Mandate 才列出具体差异请真实用户确认，确认后生成新的授权版本，与要求编号分开保存；未确认部分不执行，原范围照常进行 |
| 叫停与收权 | 立即拦截后续动作，同时请求取消可取消的在途执行；执行端确认退出前不报告已停止，不宣称能撤回已生效果 |
| 完成后的调整 | 已完成的结果不回改。用户不满意时由 Router 新建关联调整任务，保留原结果并复核当前授权 |
| 订阅与越界 | 订阅材料只是上下文，不是修订；持有多项任务时一条消息不广播成所有任务的命令。越界 handback 每项任务每 Trigger 限一次。关闭订阅时未处理的消息要有明确去向 |
| 执行会话里的输入 | 宿主绑定真实消息、会话、Assignment/Run 和 fence 后归入原任务，再分为普通修订、询问、叫停或扩权；扩权原文不交给 Worker，改由 Router 向用户确认 |

### 目标清单

目标是用户这一阶段想做成的事，是 Router 的关注清单，也是主动性的源点。模块为 `goal-checklist.mjs`，记录在 `assistant_goals` 表。

- 一条目标只有一句文字（1–2000 字）和“未完成 / 已完成”，不委派、不绑项目、不带授权。
- 用户在对话里提出，Router 通过 `assistant_goals` 创建、编辑、完成、恢复未完成或删除，操作校验记录版本；界面可勾选、编辑和删除。
- 主聊每轮带最多 20 条未完成目标的摘要，完整清单按需读取；主聊重置后保留。手动旁聊可读，外部渠道读不到。
- 目标驱动的主动回合（定时回看、对照新信息后决定是否开口）：待实施，另行设计。

<a id="任务清理与保留目标"></a>

### 任务清理与保留

清理是归档式整理：把选中的任务从当前列表移入归档，不改业务状态，不删成果、文件或执行记录；完成后不自动归档。

| 步骤 | 规则 |
| --- | --- |
| 定位与查询 | 结合当前对话定位任务；`assistant_tasks` 可按展示标题及要求关键词、创建时间、来源渠道或会话，以及状态、项目和 `archived` 筛选，所有条件与可信归属取交集后分页。归档筛选省略则包含当前及归档任务；列表只带有界摘要、版本和回执指针，历史原文按节、按稳定记录续读，仅在目标或范围确有歧义时询问 |
| 重命名 | `assistant_task_manage` 的 `op=rename` 只改展示标题，以新鲜读取的 `taskMeta.version` 做冲突保护；不改原始要求、Mandate、要求版本或实际完成状态 |
| 预览 | `assistant_task_cleanup preview` 在当前真人指令下生成冻结清单、当前状态和影响，只纳入已机械确认执行退出的任务（完成、已停止、执行记录已终结的等待）；已知明确 ID 可直接预览，不逐项读取完整结果；用户可缩小到子集。未消费预览有效 24 小时，过期须重预览；初始化及创建预览时回收过期未消费项，已消费预览和正式回执保留 |
| 排除 | 普通归档请求默认排除仍在排队、运行或退出不确定的条目，并说明待停止或待核实。请求不隐含停止权限；只有用户明确要求“停止后归档”时，才可进入下述持久续办 |
| 提交 | 本机主人当前明确要求可授权本次可撤销的展示整理，无需额外口头同意或宿主审批卡，固定 `never` 不阻断该操作。宿主只接受同一真人指令下准备的冻结清单和不扩大的精确 ID 子集，绑定真实消息、会话与幂等请求标识；模型不能提供 owner、source 或确认标志 |
| 冲突与回执 | 状态、执行或展示版本变化时拒绝提交，重新预览；只按持久回执报告归档事实。相同请求重读原回执，不重复归档，也不将整理当成任务执行成功 |
| 停止后归档 | `assistant_task_cleanup stop-and-archive` 只接受本机主人当前明确授权的精确 ID。宿主保存原真人来源、Trigger、要求/结果/展示版本及 `executionStamp`，绑定 Assignment/Run 身份与 fence、Run owner、暂停原因和该任务后续输入（排除本次停止 Trigger）；沿既有编排巡检在派工前复用停止输入，真正退出后重新冻结并归档，跨回合或重启可续办。自然状态流转、租约释放和退出不冲突；新执行、fence 或绑定该任务的新输入、暂停、恢复及要求变化使待办失效。不轮询模型、不新增 timer、Worker 或业务状态 |
| 待办与取消 | `pending` 查询持久整理记录，可按 `operationId/taskId/status` 筛选并以 `offset/limit` 分页；状态为 `pending/completed/cancelled/conflict`。`cancel` 指定原 `operationId`，可用 `ids` 缩小到其任务子集，只撤销尚未完成的归档待办。取消不逆转已发出的停止，也不把已完成归档改回当前列表；后者沿恢复流程。完成与冲突按真实回执表达；通知发送前在同库冻结不超过 50 项的批次，收件失败或重启重试原成员，成功后整批事务确认，后续终态不混入旧批。内部通知只报告事实，不成为新授权；原旁聊已删除时抑制通知，不重建旁聊 |
| 恢复 | 用原归档回执生成当前指令下的恢复清单，按冻结版本和明确子集恢复展示标记，回到普通列表，不重启执行；同样复用 `assistant_task_cleanup restore`，不另建恢复协议 |
| 硬删除 | 不提供。用户在任务列表语境说“删掉”“清掉”时，按上述可恢复归档办理并如实说明；要求永久删除成果、文件或会话时明确说明此工具不支持，不把归档回执说成物理删除 |

本机主人在主聊或手动旁聊可查询、重命名和整理其他会话及渠道创建的任务；外部渠道、Worker、子代理及纯机器通知不获得这份全局管理权。全局暂停、停止、恢复执行沿原任务控制边界，保留原 Mandate，不扩大任务范围。归档请求不隐含停止执行，不能为凑齐清理数量顺手停止任务。界面清单仍由用户在原容器核对提交，见[任务列表交互](../02-工作台与Agent/任务列表交互.md)；会话管理的字段契约见[服务契约](服务契约.md#公共接口与数据契约)。

## Worker 与官方 subagents

一项任务对应一个官方 Worker 会话。`orchestration-runtime.mjs` 为任务创建 Assignment，`assignment-worker.mjs` 领取，`assignment-executor.mjs` 通过官方 `ctx.agents.create/resume` 建立或续接执行会话。并发上限由配置控制，缺省为 2。

- 执行会话默认复用任务展示标题，不额外调用模型；任务改名后同步仍由系统管理的标题。通过官方标题事件的版本记录区分系统设置与真人改名，即使真人改为相同文字也保留其选择。历史主 Worker 会话仅补无标题或精确匹配原内部执行目录的自动标题，不覆盖已有真人标题与有意义的自动标题；冷会话在官方单写者锁内追加标题并刷新官方投影缓存，不恢复执行者。子代理沿用官方命名；任务编号、执行目录和续接关系不变。写入失败记录日志，后续改名、会话载入或插件重载可重试，不撤回已保存的任务名称。
- Worker 没有长期身份。任务包含当前任务目标、用户要求、授权范围、必要上下文和原文指针；执行中有实质变化时公开写简短进展，结束时写清做成了什么、产出在哪、还剩什么问题，见下方执行动态观测与[Worker 结果](结果与交付.md#worker-结果)。
- 绑定项目的任务直接在该项目工作区执行，否则使用独立 Worker 目录；文件优先放在任务明确指定的位置，未指定时使用 Worker 目录。不自动创建 worktree，只有用户明确要求隔离开发时才用。工作目录用于组织内容，在 Full 权限下不构成唯一可写范围。
- 会话内是否拆分、如何委派，由 Worker 和官方 Harness subagents 决定；BenchGo 只在提示词里鼓励适当拆分，不设层级、继承、白名单或模型装配规则。“子 Worker”只是官方子会话的显示称呼，不是额外的任务、Assignment 或 Run；`worker-subagents.mjs` 只通过官方事件把子会话关联回原任务。
- Worker 与官方子代理的入口及直接输入规则见[执行会话与直接插话](对话交互.md#执行会话与直接插话)。

<a id="跨设备任务"></a>

### 跨设备任务（已接线，真实双机待验）

入口 Router 继续负责当前对话；项目任务交由项目所属设备上的 SuperAgent 执行服务创建或续接 Worker，使用该设备的文件、Harness、工具与工作模型。未绑定项目的任务明确执行设备，省略时使用入口主机；目标服务缺失或能力不支持时直接说明，不静默切换设备或改用自由 SSH 执行。设备和项目的唯一定位、能力探测见[项目归属与远端执行](../01-设备与远程连接/跨设备协作.md#项目归属与远端执行)。

- 目标设备保存唯一的执行任务与原始记录，入口侧只保存关联投影和原来源交付关系，以 `executionRef` 定位真实执行；聚合展示不额外派发任务，也不复制另一份可独立推进的执行账。
- 委派、补充、修订、暂停、取消和恢复沿可信原指令与已有归属规则桥接。目标端核对当前能力、原任务及要求版本，再返回实际执行回执；收到请求不等于已经应用。入口断线不停止目标任务，控制效果未知时先核对原执行，不重发新任务。
- 成果、问题与结果回到原对话，目标主机保留可查看的真实执行会话；结果与投递继续分开记录。换项目或换执行设备属于显式调整，不因页面切换、设备离线或显示范围变化而迁移在途任务。

远端操作使用 `assistant_remote_task`，本机仍用 `assistant_delegate`。`device-collaboration.mjs` 将经过配对授权的设备请求交给既有接收和执行链，来源为 `link`，不冒充目标 desktop owner。入口只保存原来源与执行引用，复用编排 tick 读取目标问题/结果并投递原对话；未知接收先 lookup，不重新创建任务。传输、幂等、断线与授权规则只在[跨设备协作](../01-设备与远程连接/跨设备协作.md)维护。

## 执行动态观测

编排控制面复用现有调度 tick：桌面委派持久受理成功后异步唤醒，不等待 Worker 执行；重复受理不重复唤醒，唤醒失败由原定时轮询兜底，不改写受理结果。空闲时先用只读数据库探针判断有没有待派发、过期租约、待答或待补存的工作，没有就不加载策略文档和任务列表；探针只用于跳过空转，真实的领取、续租、恢复和提交仍各自核验。

`task-execution-progress.mjs` 通过官方 Session Projection 和生命周期事件维护可重建的最小执行事实索引，供任务列表、摘要和监督读取同一份 `execution` 投影，不复制 transcript，也不另立状态机。

| 内容 | 规则 |
| --- | --- |
| 投影包含 | 关联标识、执行阶段、受控活动文案、有界脱敏的公开进展摘要及来源标记、执行会话与子会话状态、计数、更新时间和记录缺失说明 |
| 不包含 | 工具参数、返回正文、错误原文和模型任务全文 |
| 状态优先级 | 真实的任务与 Run 终态优先于旧会话活动和进度摘要；完成不等于已送达 |
| 子会话 | 以官方结束事件为准；父 Worker 空闲只表示在等待 |
| 缺口 | 重启和冷历史通过官方持久 Session 投影补偿；不可恢复的历史标明未知，不当作零 |

数据契约见[持久执行事实与增量读取](服务契约.md#持久执行事实与增量读取)，执行摘要见[执行摘要与监督判断](模型与上下文.md#执行摘要与监督判断)，界面见[聊天任务线](../02-工作台与Agent/任务列表交互.md#聊天任务线与执行动态)。

执行动作摘要复用官方 `assistant/message`，不新增汇报工具或逐动作模型请求。执行者在动作、发现或下一步有实质变化时，以独立短行「进展：动作 + 对象或结果」公开说明，区分计划、进行中与已完成；投影只提取明确标记且不超过 120 字的短句，脱敏后进入 `activity` 与有界历史，并标记 `activitySource: report`。长回复不截断冒充动作，思维、流式草稿、失败尝试和嵌套工具文本不作来源。新一轮清空旧摘要，普通步骤与成功工具事件保留本轮摘要，真实失败、等待和结束事件优先。公开摘要是执行者报告，不是独立验证，也不改变任务状态；旧会话没有公开短句时仍回退已知活动，不补写历史。

### 真实执行会话与同一任务输入账本

任务持久关联真实的 Assignment、Run、官方 session、父子关系、工作区和执行代际。从任务详情进入的就是这个官方会话；跳转只定位既有会话，不创建另一个执行者，不重派。会话不可用时明确提示，不用 Router、合成日志或其他任务顶替。

来自 Router、渠道、任务详情和执行会话的同一任务消息进入同一本任务输入账：记录真实来源、发起人、原文引用、幂等键、要求编号、授权版本，以及已收到、待应用、已应用三种状态。跨入口的重复消息只应用一次；账本关联到实际应用它的 Run 和工具边界。同一原始真人输入若先作为上下文被消费，Router 后确认其暂停或停止意图时，复用原输入身份，在 `snapshot.contextReceipt` 保留完整旧消费证据并保存新的控制应用回执，不重复投递上下文。执行会话的输入不能绕过身份、范围、暂停和审批规则。各渠道只是同一项任务的不同入口，不保存第二份任务或对话状态。

## 权限与对外审批

需要审批的业务动作只接受真实的单次批准，没有独立授权管理、整站许可或长期许可。Router / Worker 固定为 `danger-full-access + never` 后，新的显式宿主审批请求由官方服务直接拒绝，不生成审批卡，也不自动放行；需要批准但未取得有效回执的动作明确受阻或交给用户完成。已有待批请求保留原身份和官方生命周期，权限校正不替用户决定。

### 内部能力与继承

- Router 和 Worker 的宿主权限固定为官方 `danger-full-access + never`，新建、恢复与权限校正一致，装配规则见[自有会话角色装配](模型与上下文.md#自有会话角色装配)。文件沙箱不限制可写目录，但不赋予操作系统额外权限；失败必须按真实工具回执说明。`never` 不自动批准业务动作，也不取消、批准或替换已有待批请求。
- Worker 的有效能力受宿主限制、当前任务范围、可用工具、现行规则和实际动作许可共同约束。子代理的能力继承与审批由官方 Harness 管理；单次许可不因派生会话变成多次，停止与撤权对所有会话生效。
- 产品自身的状态和设置由 Router 通过统一配置契约直接管理，见[对话管理与统一配置](服务契约.md#对话管理与统一配置目标)。
- 记忆、技能、文档、模型输出和历史问答都不能代替用户的真实答复。

### 具体动作的批准要求

| 动作 | 处理 |
| --- | --- |
| 浏览公开网页、搜索、下载公开资料 | 免审批 |
| 向原来源正常回复、通报进度、提问、交付成果 | 按已认证来源和任务归属免审批；不能借回复路径另投其他对象 |
| 登录、上传私有内容等常规敏感提交 | 需要具体动作许可；当前 `never` 不提供新的宿主批准，无法取得有效许可时明确受阻或接管，同一已批准动作不重复索要 |
| 支付或购买、修改密码、删除账号、另行对外发送 | 只能由已注册的结构化通道持真实单次批准提交；新的审批请求在 `never` 下被拒绝，没有通道或有效许可时由用户完成最后一步。另行发送包括向其他对象发邮件或消息、转发、分享和发布 |
| 凭据缺失 | 走[保险库安全输入](链接与渠道.md#保险库与安全输入)或用户接管；密码不作为聊天答案，录入不等于批准动作 |

实际存在的官方待批请求按三层呈现：Router 先自然提醒，原官方卡随对话流挂在提醒处，看板审核聚合并可跳到卡片。被 `never` 直接拒绝的请求没有待批卡，界面不能伪造批准入口。交互见[权限与安全输入交互](对话交互.md#权限与安全输入交互)。

### 高危类别注册、通道与接管

系统不尝试从任意脚本、终端命令、浏览器点击或网络请求里识别真实的提交语义。四类高危提交只能走已注册的结构化通道；终端和浏览器保持开放，用于查找、编辑、登录后操作和提交前准备，到高危提交前停下。

| 环节 | 规则 |
| --- | --- |
| 注册 | 四类高危类别都在核心动作注册表登记，没有可用通道的类别默认 `handoff`。能力提供方声明自己支持的类别、专用操作、站点或服务映射、内容预览和回执能力；核心统一校验后放行，不按渠道名写特例。声明不完整或无法核验最终内容时退回接管 |
| 输入契约 | 能力目录返回 `inputSchema`。渠道另行发送的输入是真实已准入来源的 `targetTriggerId`（原样保留账本中的完整值）和完整最终正文 `text`；渠道目标来自统一入口账本，与保险库无关 |
| 三步操作 | `catalog` 只发现能力；`prepare` 只在本地保存冻结动作；`submit` 才核对单次批准并尝试外部提交。权限策略拒绝批准时不提交，不把 Full 当成业务许可 |
| 批准内容 | 冻结真实目标、接收对象、正文与附件、商品与金额、影响及提交参数；秘密只引用保险库句柄。内容、目标、金额或参数变化须重新准备并取得本次有效许可 |
| 回执 | 工具传输成功不代表动作成功。回执为 `submitted`、`uncertain`、缺结果或无法解析时保持效果未知，不重放 |
| 接管 | 没有通道时完成可做的准备，生成用户最后一步的接管点并明示尚未提交；用户亲自完成后核实实际效果。接管完成不变成可复用的自动提交许可 |

### 动作边界与恢复

- 每次工具调用都复核 policy、已应用的要求快照、Mandate 版本和有效执行归属；结构化动作提交另外复核注册通道、冻结内容和本次审核结果。模型不能靠传参或引用文档绕过。
- 单个数据根只有一个编排所有者，多窗口只是客户端。Assignment 的领取和续租带唯一 owner、lease 和 fence；lease 过期只提供核实与接管的机会，不证明旧进程已停，也不证明动作可以重做。
- 旧执行者返回的结果照常保存并保留实际来源和执行代际，不覆盖新结果，见[结果保存无阻断](结果与交付.md#结果保存无阻断)。
- 续接见[中断等待与原会话续接](结果与交付.md#中断等待与原会话续接)：保留原 Assignment、Run、session、工作区和冻结模型并递增 fence。待批动作核对原审核请求和真实答复；已执行的动作不再提交；未知的外部效果不能靠更换调用 ID、重排参数或重建任务来重放。
- 宿主关闭、卸载以 `WORKER_HOST_STOPPED` 记录，官方会话取消原因为 `disposed`，不冒充用户取消。用户明确续接时，`aborted/disposed` 沿上述核验恢复；真实用户取消仍不进入中断恢复。`executionStopped` 只证明旧执行已释放，续接受理时清理旧回执与中断等待标记，不将它当作用户叫停。
- 文件操作沿用官方工具和权限机制。系统不做任务级文件备份、整轮恢复或全目录哈希；续接保留当前文件状态，不还原或覆盖用户后来的修改。

### 外部 Watchdog 监督

Watchdog 是独立进程，只观察并提交信号：不恢复、停止或改派任何会话，不重启主宿主，不持有任务账的写权限。它不自动启用，由维护者配置和启动，部署见[Watchdog 启动封装](../../scripts/watchdog/README.md)。

| 事项 | 规则 |
| --- | --- |
| 隔离 | 独立的官方 profile、`DSH_HOME` 和 BenchGo 数据目录，只装配 `benchgo-plugin` 基础入口，不加载主系统的 assistant |
| 配置 | 主侧 `watchdogTarget: { enabled, targetId, tokenFile }` 开放本机只读事实和受限信号接口；观察侧 `watchdog: { targetId, targetUrl, tokenFile, ... }`。凭据不进入模型和日志 |
| 调度 | 官方 Schedule 最短每 60 秒投递到固定监督会话；检查按 Schedule 和计划时刻持久去重，在途只保留最新一次；目标不可达时记为未知并指数退避 |
| 检查项 | 事实陈旧、调度停滞、执行不可见、租约过期、真实请求 deadline、停止未确认、恢复未收敛。合法的用户等待、审批等待和暂停不算卡死；缺失或不完整的事实保持未知 |
| 不做什么 | 不用模型判断有没有进展；工具调用次数只说明有活动 |

信号进入主侧后的处理见[外部观察信号与 Router 通报](结果与交付.md#外部观察信号与-router-通报)。原型参考 `dsh-superagent-prototype@6337fc823ce20251c8de8085948165c81aaa701e`；实现复用官方 Harness `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 的 Agent、JSONL 和 Schedule，不引入第二套调度器。

## 实现与验收边界

**已有源码接线**

- Router 持久收件、取消、恢复和逻辑会话归属；direct Trigger、任务、Mandate、lease/fence。
- 同一任务输入账与普通修订：`task-revisions.mjs` 保留原 Assignment/Run/session，`task-input-store.mjs` 记录输入来源、幂等键、完整快照和实际应用的 Run 与工具批次；官方 `agent/pre-step` 整份切换。领域操作只有 `revise` 和 `adjustment`。
- 范围扩展经宿主 `requestExpansion` 校验，只有真实批准回执才能生成新授权版本；固定 `never` 下的新审批被拒绝，不扩大 Mandate。已建立执行会话的任务不能原地更换项目，返回 `PROJECT_REQUIRES_ADJUSTMENT`。
- 目标清单；Router 任务查询的关键词、时间、来源与归档筛选、有界详情续读、展示版本和重命名；清理预览、精确子集归档、审计与恢复复用同一领域服务，明确授权的停止后归档由持久待办跨回合续办，不为可撤销整理新增审批。
- 动作存储、通道注册、冻结内容绑定、只接受 `allowed-once` 的官方审批、单次消费、未知效果不重放。
- Watchdog 的隔离装配、只读观察接口、信号去重与退避。

**现状限制**

- 跨设备委派、查询、补充、修订、问题答复和暂停/恢复/取消已接目标既有执行链；测试覆盖目标模型和来源、单次执行、丢响应查询及问题/结果回传。实际襄阳服务器、真实供应商请求与断线恢复仍待验收。
- 内置高危通道只有渠道另行发送；支付、改密、删号没有专用适配器，目录返回 handoff。受控回执须为 `accepted` 且带 messageId、receiptId 或 transactionId 之一，否则记 uncertain。
- 固定 `never` 下，新业务审批、任务范围扩展或安全边界管理操作如仍要求宿主批准，会得到 `APPROVAL_POLICY_NEVER`，明确没有审批卡、未提交及需要接管；策略拒绝不能记录成真人拒绝。任务重命名、归档和恢复展示是已有领域服务内的可撤销整理，不请求高危业务批准，也不改变审批策略。已有待批请求可沿原官方路径处理。
- 没有内置的登录和上传适配器，浏览器登录不受控；安全输入与浏览器代填未接通。Worker 侧 `assistant_vault_list` 只返回不透明句柄。
- 接管点目前只返回 handoff 和原因；页面定位与完整接管状态待实施。
- 执行会话附件不支持。语义查重与合并、Router 工具失败的完整持久错误反馈、健康状态与异常升级处置未完成。
- 官方各输入入口、附件和重连尚未全部接通；千级以上任务容量未验证。

**待验证（安装版）**

- 主聊与旁聊并存下的委派、并行与隔离；同一 session 单写入者；运行中重启后的恢复。
- 修订整份切换且不打断在途工具；暂停只收件；叫停与撤权在下一动作前生效；扩权生成新授权版本；跨入口输入只应用一次。
- 官方 subagents 的派发、回收与直接输入；冷会话接回原 Run。
- 核对 Full 下新审批明确拒绝且不外发，已有待批卡仍保留原请求身份与真实批准或拒绝；核对有效许可下的渠道发送及撤权后的拦截。页面渲染和接口可用不能代替业务效果。
- 任务整理：自然指代与关键词/时间/来源筛选、有界详情和稳定记录续读、重命名版本冲突、同指令冻结子集、过期回收、停止后归档的异步退出/重启续办/取消、版本冲突和回执重放，不联删成果；真实安装版仍待用户验收。
- Watchdog 对真实 Worker 机械故障的检出，以及 Router 收到信号后的通报。
