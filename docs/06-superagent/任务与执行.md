# SuperAgent 任务与执行

本文维护 Router 协调、工单与修订、目标清单、Worker 执行、权限审批、恢复与监督。准入见[入口与研判](入口与研判.md)，三态、结果与交付见[结果与交付](结果与交付.md)，字段与接口见[服务契约](服务契约.md)。

## Router 与持续主会话

Main Agent 是用户的对话入口和总调度者，Router 是它的职责名称。主聊和每个旁聊各有一个官方会话，共用 SuperAgent 模型配置和能力基线；旁聊只隔离话题与归属。Router、Worker 是职责分工，不是使用者权限等级；渠道使用者的身份与准入归适配器，见[入口与研判](入口与研判.md#已敲定的身份边界与当前差距)。角色的 preset、权限组合与模型路由见[自有会话角色装配](模型与上下文.md#自有会话角色装配)。

| Router 做什么 | 规则 |
| --- | --- |
| 直接办理 | 普通问答、工单查询、卡片提问、定时提醒、当面记忆、产品自身的状态与设置 |
| 派工 | 查网站、查文件、写代码、跑命令等环境操作从第一次探查起就交给 Worker；Router 结合对话上下文自行决定，不经第二个模型复审，也不额外询问是否允许建单 |
| 派工之后 | 工单落库即返回，Router 自然回应并继续接受其他请求，不阻塞等待 Worker |
| 结果回来 | 读结果后主动自然告知，没做成就直说；不重派、不验收，见[结果落单与 Router 表达交付](结果与交付.md#结果落单与-router-表达交付) |
| 多个请求 | 不相关的新请求各自分诊、查重后并行派工；同一会话的写入串行 |
| 工具失败 | 真实错误码、原因和有界诊断留在任务详情与日志，Router 按真实情况自然说明，不猜测原因 |

Router 的工具在 `router-tools.mjs` 注册；内置提示词真源是 `plugins/superagent/prompts/builtin-layer.md`，与用户档案分层，用户档案不能覆盖平台机制。表达原则见[Router 对话准则](Router对话准则.md)。

**收件与回执。** 逻辑 thread 与底层官方 session 分离。`send` 接受 threadId、text、requestId 和可选 replyContext，先持久收件，再串行启动 Router 回合；同 requestId 同内容幂等，内容变化则拒绝。回执区分 queued、processing、processed、failed、uncertain、cancelled，processed 只表示 Router 回合结束；回执未知时不自动重发。取消只作用于排队请求和当前 Router 回合，不撤销后台工单；清空聊天保留工单、去重记录和会话归属。

## 工单、跟进与目标

工单账在 `orchestration-store.mjs`。一张工单记录标题、目标（target）、用户明确的结果条件（acceptance）、活摘要、来源和授权快照（Mandate）。

| 事项 | 规则 |
| --- | --- |
| 标题与摘要 | 标题至多 10 个 Unicode 字符，写清替用户做的具体事情，不用“执行任务”这类占位；用户指定的标题优先。target 与 acceptance 不截断；acceptance 只承接用户明确提出的结果条件，不是验收门。改标题不改要求版本 |
| 分诊与查重 | 直接问题当场答，执行请求开单，在办工单的相关消息走原单，无关新事独立开单。新建前按在办和最近完成工单的标题与活摘要查重；同一 Trigger 只生一单，标题相近不强行合单 |
| 授权快照 | 用户指令是授权源头。Mandate 保存策略版本、范围、强度、命中规则、发起人身份五要素和可信原始指令引用；没有适用书面规则时命中规则为空，模型不能生成默认授权。宿主确定性核对真人来源、归属、幂等和版本；范围内的自然语言理解由 Router 负责 |
| 一条消息多张单 | 每个 Worker 的首条输入只取本单的 `executionScope`（缺省为本单目标）；完整原话只作来源与适用约束 |
| 普通修订 | 原范围内的补充、调整和插话直接记入同单，生成完整的当前要求快照；在途工具不打断，Worker 在下一工具提交边界把目标、要求、上下文和工具范围整份切换。要求编号只作后台顺序与防迟到，不需要用户确认。询问进度或细节只回答，不改单 |
| 暂停 | Router 对原单调用 `assistant_ticket_control pause`。`pauseRequested` 表示后续动作已拦截，`paused` 才是执行端确认暂停。暂停期间只收修订、不启动工具；用户明确恢复后先应用最新快照再执行 |
| 扩权 | 只有超出 Mandate 才列出具体差异请真实用户确认，确认后生成新的授权版本，与要求编号分开保存；未确认部分不执行，原范围照常进行 |
| 叫停与收权 | 立即拦截后续动作，同时请求取消可取消的在途执行；执行端确认退出前不报告已停止，不宣称能撤回已生效果 |
| 完成后的调整 | 已完成的结果不回改。用户不满意时由 Router 新建关联调整单，保留原结果并复核当前授权 |
| 订阅与越界 | 订阅材料只是上下文，不是修订；持有多张工单时一条消息不广播成所有工单的命令。越界 handback 每工单每 Trigger 限一次。关闭订阅时未处理的消息要有明确去向 |
| 执行会话里的输入 | 宿主绑定真实消息、会话、Assignment/Run 和 fence 后归入原单，再分为普通修订、询问、叫停或扩权；扩权原文不交给 Worker，改由 Router 向用户确认 |

### 目标清单

目标是用户这一阶段想做成的事，是 Router 的关注清单，也是主动性的源点。模块为 `goal-checklist.mjs`，记录在 `assistant_goals` 表。

- 一条目标只有一句文字（1–2000 字）和“未完成 / 已完成”，不派工、不绑项目、不带授权。
- 用户在对话里提出，Router 通过 `assistant_goals` 创建、编辑、完成、恢复未完成或删除，操作校验记录版本；界面可勾选、编辑和删除。
- 主聊每轮带最多 20 条未完成目标的摘要，完整清单按需读取；主聊重置后保留。手动旁聊可读，外部渠道读不到。
- 目标驱动的主动回合（定时回看、对照新信息后决定是否开口）：待实施，另行设计。

### 工单清理与保留

清理是归档式整理：把选中的工单从当前列表移入归档，不改业务状态，不删成果、文件或执行记录；完成后不自动归档。

| 步骤 | 规则 |
| --- | --- |
| 预览 | 先列出本次清单、当前状态和影响，只纳入已机械确认执行退出的工单（完成、已停止、执行记录已终结的等待）；用户可缩小到子集 |
| 排除 | 仍在排队、运行或退出不确定的条目默认排除，并说明是待停止还是待核实；要纳入须先真实停止并核实退出，再重新预览 |
| 确认 | 取得本次真人明确确认后只处理确认清单；清单或状态变化后须重新核对，历史上的同意不算本次确认 |
| 恢复 | 按具体清单和版本恢复展示标记，回到普通列表，不重启执行 |
| 硬删除 | 不提供。不可恢复的删除须另行明确要求，普通清理和归档确认都不构成授权 |

本机主人在主聊或手动旁聊可用 `assistant_task_cleanup` 整理其他会话和渠道创建的工单；全局暂停、停止、恢复沿同一管理边界，保留原 Mandate，不扩大任务范围。

## Worker 与官方 subagents

一张工单对应一个官方 Worker 会话。`orchestration-runtime.mjs` 为工单创建 Assignment，`assignment-worker.mjs` 领取，`assignment-executor.mjs` 通过官方 `ctx.agents.create/resume` 建立或续接执行会话。并发上限由配置控制，缺省为 2。

- Worker 没有长期身份。任务包含本单目标、用户要求、授权范围、必要上下文和原文指针；提示词只要求结束时写清做成了什么、产出在哪、还剩什么问题，见[Worker 结果](结果与交付.md#worker-结果)。
- 绑定项目的工单直接在该项目工作区执行，否则使用独立 Worker 目录，任务产物放在 Worker 目录。不自动创建 worktree，只有用户明确要求隔离开发时才用。工作目录隔离不等于 OS 沙箱。
- 会话内是否拆分、如何委派，由 Worker 和官方 Harness subagents 决定；BenchGo 只在提示词里鼓励适当拆分，不设层级、继承、白名单或模型装配规则。“子 Worker”只是官方子会话的显示称呼，不是额外的工单、Assignment 或 Run；`worker-subagents.mjs` 只通过官方事件把子会话关联回原工单。
- Worker 和官方子代理都在工作台侧栏可见，可打开并直接输入。

## 执行动态观测

编排控制面是定时轮询。空闲时先用只读数据库探针判断有没有待派发、过期租约、待答或待补存的工作，没有就不加载策略文档和工单列表；探针只用于跳过空转，真实的领取、续租、恢复和提交仍各自核验。

`task-execution-progress.mjs` 通过官方 Session Projection 和生命周期事件维护可重建的最小执行事实索引，供任务列表、摘要和监督读取同一份 `execution` 投影，不复制 transcript，也不另立状态机。

| 内容 | 规则 |
| --- | --- |
| 投影包含 | 关联标识、执行阶段、受控活动文案、主 Worker 与子会话状态、计数、更新时间和记录缺失说明 |
| 不包含 | 工具参数、返回正文、错误原文和模型任务全文 |
| 状态优先级 | 真实的工单与 Run 终态优先于旧会话活动和进度摘要；完成不等于已送达 |
| 子会话 | 以官方结束事件为准；父 Worker 空闲只表示在等待 |
| 缺口 | 重启和冷历史通过官方持久 Session 投影补偿；不可恢复的历史标明未知，不当作零 |

数据契约见[持久执行事实与增量读取](服务契约.md#持久执行事实与增量读取)，执行摘要见[执行摘要与监督判断](模型与上下文.md#执行摘要与监督判断)，界面见[聊天任务线](../02-工作台与Agent/任务列表交互.md#聊天任务线与执行动态)。

### 真实执行会话与同单输入账本

工单持久关联真实的 Assignment、Run、官方 session、父子关系、工作区和执行代际。从任务详情进入的就是这个官方会话；跳转只定位既有会话，不创建另一个执行者，不重派。会话不可用时明确提示，不用 Router、合成日志或其他工单顶替。

来自 Router、渠道、任务详情和执行会话的同单消息进入同一本工单输入账：记录真实来源、发起人、原文引用、幂等键、要求编号、授权版本，以及已收到、待应用、已应用三种状态。跨入口的重复消息只应用一次；账本关联到实际应用它的 Run 和工具边界。执行会话的输入不能绕过身份、范围、暂停和审批规则。各渠道只是同一张工单的不同入口，不保存第二份工单或对话状态。

## 权限与对外审批

任务内审核是唯一的审批方式：需要确认的具体动作在原任务里用官方审批卡请用户决定，一次批准只执行这一件。没有独立的授权管理，也没有整站或长期许可。

### 内部能力与继承

- 用户指令和工单范围授权的是业务目标，不替代宿主沙箱与审批。Router 和 Worker 都运行在 `workspace-write + ask` 组合下；底层要求审批或不支持时如实记录原因并进入等待。
- Worker 的有效能力受宿主限制、当前任务范围、可用工具、现行规则和实际动作许可共同约束。子代理的能力继承与审批由官方 Harness 管理；单次许可不因派生会话变成多次，停止与撤权对所有会话生效。
- 产品自身的状态和设置由 Router 通过统一配置契约直接管理，见[对话管理与统一配置](服务契约.md#对话管理与统一配置目标)。
- 记忆、技能、文档、模型输出和历史问答都不能代替用户的真实答复。

### 哪些动作走审批卡

| 动作 | 处理 |
| --- | --- |
| 浏览公开网页、搜索、下载公开资料 | 免审批 |
| 向原来源正常回复、通报进度、提问、交付成果 | 按已认证来源和工单归属免审批；不能借回复路径另投其他对象 |
| 登录、上传私有内容等常规敏感提交 | 在原任务内出具体动作的审批卡；同一已批准动作不重复索要 |
| 支付或购买、修改密码、删除账号、另行对外发送 | 有已注册的结构化通道时逐次审批后提交；没有通道则由用户完成最后一步。另行发送包括向其他对象发邮件或消息、转发、分享和发布 |
| 凭据缺失 | 走[保险库安全输入](链接与渠道.md#保险库与安全输入)或用户接管；密码不作为聊天答案，录入不等于批准动作 |

审批的呈现分三层：Router 先自然提醒，原官方卡随对话流挂在提醒处，看板审核聚合并可跳到卡片。交互见[权限与安全输入交互](对话交互.md#权限与安全输入交互)。

### 高危类别注册、通道与接管

系统不尝试从任意脚本、终端命令、浏览器点击或网络请求里识别真实的提交语义。四类高危提交只能走已注册的结构化通道；终端和浏览器保持开放，用于查找、编辑、登录后操作和提交前准备，到高危提交前停下。

| 环节 | 规则 |
| --- | --- |
| 注册 | 四类高危类别都在核心动作注册表登记，没有可用通道的类别默认 `handoff`。能力提供方声明自己支持的类别、专用操作、站点或服务映射、内容预览和回执能力；核心统一校验后放行，不按渠道名写特例。声明不完整或无法核验最终内容时退回接管 |
| 输入契约 | 能力目录返回 `inputSchema`。渠道另行发送的输入是真实已准入来源的 `targetTriggerId`（原样保留账本中的完整值）和完整最终正文 `text`；渠道目标来自统一入口账本，与保险库无关 |
| 三步操作 | `catalog` 只发现能力；`prepare` 只在本地保存冻结动作；`submit` 才进入逐次审批和外部提交 |
| 审批卡 | 冻结真实目标、接收对象、正文与附件、商品与金额、影响及提交参数；秘密只引用保险库句柄。内容、目标、金额或参数变化须重新准备和审批 |
| 回执 | 工具传输成功不代表动作成功。回执为 `submitted`、`uncertain`、缺结果或无法解析时保持效果未知，不重放 |
| 接管 | 没有通道时完成可做的准备，生成用户最后一步的接管点并明示尚未提交；用户亲自完成后核实实际效果。接管完成不变成可复用的自动提交许可 |

### 动作边界与恢复

- 每次工具调用都复核 policy、已应用的要求快照、Mandate 版本和有效执行归属；结构化动作提交另外复核注册通道、冻结内容和本次审核结果。模型不能靠传参或引用文档绕过。
- 单个数据根只有一个编排所有者，多窗口只是客户端。Assignment 的领取和续租带唯一 owner、lease 和 fence；lease 过期只提供核实与接管的机会，不证明旧进程已停，也不证明动作可以重做。
- 旧执行者返回的结果照常保存并保留实际来源和执行代际，不覆盖新结果，见[结果保存无阻断](结果与交付.md#结果保存无阻断)。
- 续接见[中断等待与原会话续接](结果与交付.md#中断等待与原会话续接)：保留原 Assignment、Run、session、工作区和冻结模型并递增 fence。待批动作核对原审核请求和真实答复；已执行的动作不再提交；未知的外部效果不能靠更换调用 ID、重排参数或重建任务来重放。
- 文件操作沿用官方工具和权限机制。系统不做工单级文件备份、整轮恢复或全目录哈希；续接保留当前文件状态，不还原或覆盖用户后来的修改。

### 外部 Watchdog 监督

Watchdog 是独立进程，只观察并提交信号：不恢复、停止或改派任何会话，不重启主宿主，不持有工单账的写权限。它不自动启用，由维护者配置和启动，部署见[Watchdog 启动封装](../../scripts/watchdog/README.md)。

| 事项 | 规则 |
| --- | --- |
| 隔离 | 独立的官方 profile、`DSH_HOME` 和 BenchGo 数据目录，只装配 `benchgo-plugin` 基础入口，不加载主系统的 assistant |
| 配置 | 主侧 `watchdogTarget: { enabled, targetId, tokenFile }` 开放本机只读事实和受限信号接口；观察侧 `watchdog: { targetId, targetUrl, tokenFile, ... }`。凭据不进入模型和日志 |
| 调度 | 官方 Schedule 最短每 60 秒投递到固定监督会话；检查按 Schedule 和计划时刻持久去重，在途只保留最新一次；目标不可达时记为未知并指数退避 |
| 检查项 | 事实陈旧、调度停滞、执行不可见、租约过期、真实请求 deadline、停止未确认、恢复未收敛。合法的用户等待、审批等待和暂停不算卡死；缺失或不完整的事实保持未知 |
| 不做什么 | 不用模型判断有没有进展；工具调用次数只说明有活动 |

信号进入主侧后的处理见[外部观察信号与 Router 通报](结果与交付.md#外部观察信号与-router-通报)。原型参考 `dsh-superagent-prototype@6337fc823ce20251c8de8085948165c81aaa701e`；实现复用官方 Harness `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 的 Agent、JSONL 和 Schedule，不引入第二套调度器。

## 实现与验收边界

**已有源码接线**

- Router 持久收件、取消、恢复和逻辑会话归属；direct Trigger、工单、Mandate、lease/fence。
- 同单输入账与普通修订：`ticket-revisions.mjs` 保留原 Assignment/Run/session，`ticket-input-store.mjs` 记录输入来源、幂等键、完整快照和实际应用的 Run 与工具批次；官方 `agent/pre-step` 整份切换。领域操作只有 `revise` 和 `adjustment`。
- 扩权确认经宿主 `requestExpansion` 取得真实批准回执后生成新授权版本。已建立执行会话的工单不能原地更换项目，返回 `PROJECT_REQUIRES_ADJUSTMENT`。
- 目标清单；工单清理的预览、子集确认、归档、审计和恢复。
- 动作存储、通道注册、冻结内容绑定、只接受 `allowed-once` 的官方审批、单次消费、未知效果不重放。
- Watchdog 的隔离装配、只读观察接口、信号去重与退避。

**现状限制**

- 内置高危通道只有渠道另行发送；支付、改密、删号没有专用适配器，目录返回 handoff。受控回执须为 `accepted` 且带 messageId、receiptId 或 transactionId 之一，否则记 uncertain。
- 没有内置的登录和上传适配器，浏览器登录不受控；安全输入与浏览器代填未接通。Worker 侧 `assistant_vault_list` 只返回不透明句柄。
- 接管点目前只返回 handoff 和原因；页面定位与完整接管状态待实施。
- 执行会话附件不支持。语义查重与合并、Router 工具失败的完整持久错误反馈、健康状态与异常升级处置未完成。
- 官方各输入入口、附件和重连尚未全部接通；千级以上工单容量未验证。

**待验证（安装版）**

- 主聊与旁聊并存下的派工、并行与隔离；同一 session 单写入者；运行中重启后的恢复。
- 修订整份切换且不打断在途工具；暂停只收件；叫停与撤权在下一动作前生效；扩权生成新授权版本；跨入口输入只应用一次。
- 官方 subagents 的派发、回收与直接输入；冷会话接回原 Run。
- 用正式审批卡核对真实批准与拒绝、真实渠道发送、撤权后的拦截；页面渲染和接口可用不能代替业务效果。
- 工单清理：清单缩小、确认后状态变化、默认排除非终态、恢复竞争、不联删成果。
- Watchdog 对真实 Worker 机械故障的检出，以及 Router 收到信号后的通报。
