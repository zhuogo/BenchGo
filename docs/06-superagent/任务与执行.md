# SuperAgent 任务与执行

本文维护协调、派工、目标与执行生命周期，是工单修订、执行关联及权限规则的权威正文；准入见[入口与研判](入口与研判.md)，结果处理见[自校验与交付](自校验与交付.md)。目标设计与实现边界分别说明。

## Router 与持续主会话

Main Agent 是用户对话入口与总调度者，Router 是其职责名称；本文两者指同一角色。主聊和旁聊各自有官方会话，共用 SuperAgent 模型配置与内部能力基线，旁聊仅隔离话题和归属。

2026-11-11 确定边界：核心引擎不建立“主人／其他用户”等使用者权限角色；飞书等渠道是否允许其他人访问机器人、可访问哪些会话和操作，均由对应适配器的权限配置与入口鉴权处理。Router、Worker 仅表示协调层和执行层的职责，模型配置分工、官方沙箱与动作审批也不属于使用者角色。渠道身份规则已有共享专用策略，适配器入口准入与按需研判的迁移边界统一见[入口与研判](入口与研判.md#已敲定的身份边界与当前差距)，不将共享策略已集中写成适配器入口迁移已完成。

主聊和旁聊按可信持久归属装配 Router 角色，执行会话装配 Worker 角色；Agent preset、permission preset 与角色模型路由分别设置并核验。自有会话通过官方插槽隐藏预设与模型选择器，不展示角色标签或配置诊断；实际装配仍在后台核验并留痕。普通用户会话保留官方选择器。当前 Router/Worker 使用 standard 与 workspace-write + ask；官方子代理的模型、工具、继承与审批均遵循官方运行时，不额外装配自有约束。已运行旧会话续用其保存的官方 preset，挂载同一组合并保留原历史，不因与新默认组合不同而阻塞。配置与真实边界唯一见[模型与上下文](模型与上下文.md)，对外效果另走[权限与对外审批](#权限与对外审批)。

- 普通问答、工单查询、卡片提问、定时协调、记忆记账与受控配置使用协调工具。
- 查网站、查文件、写代码、跑命令和其他环境操作从第一次探查起就委派 Worker；由 Router 结合对话上下文决定派工，普通派工不再调用第二个模型复审范围，也不额外询问是否允许创建工单。
- 工单落库后立即返回当前 Router；由 Router 自然回应，继续接受其他请求，不阻塞等待 Worker。
- 用户通常由 Router 协调，也可在工作台直接向 Worker 或官方子代理发消息；Worker 将成果原稿保存到工单并发完成信号，Router 主动自然提醒已完成，自选摘要或完整回复后交付原来源，不固定报告、标题前缀或状态文案。原稿留在详情，Router 不重派、不做内容验收；追问时可读原稿直接回答，不因问进度或细节改动工单。
- 不相关新请求独立分诊、查重后并行派工；同会话写入串行，只有冲突资源在冲突处串行。
- 内置层真源为 plugins/superagent/prompts/builtin-layer.md，随插件构建并注入系统 section；它与用户文档层分开，不由用户档案覆盖平台机制。
- 工具失败的真实错误码、原因和有界诊断保留在任务详情与日志，不能由模型猜测“权限策略”等理由；聊天由 Router 按真实情况自然说明，不固定输出系统状态块。完整持久错误反馈目前仍是未完成项。

逻辑 thread 与底层模型 session 分离。服务端 send 接受 threadId、text、requestId 和可选 replyContext，先持久收件，再串行启动 Router 回合。同 requestId 同内容幂等，正文或可信引用变化拒绝复用。恢复原会话以持久归属和官方单写入生命周期为准，内存装配标记缺失不构成角色权限拒绝；安全交接、上下文装配和验证边界只在[自有会话装配](模型与上下文.md#自有会话角色装配)维护，不通过重建空白会话、重放执行或要求用户手动结束来绕开真实冲突。

回执区分 queued、processing、processed、failed、uncertain、cancelled；processed 仅表示 Router 回合结束。requestState/history.requests 用于重连对账，不能因回执未知自动重发。取消排队请求与当前 Router，不等于撤销后台工单；清空聊天保留工单、去重记录和 sessionLineage 归属。

服务端持久 inbox、取消、恢复和逻辑会话归属已有基础实现；官方全部输入入口、附件、重连和真实桌面重启尚待完整接通与验证。

## 工单、跟进与目标

标题开单生成，当前统一上限为 10 个 Unicode 字符；标题与活摘要共同写清替用户做的具体事情与预期产出，不使用“执行任务”“处理请求”等空泛占位描述。显式指定的具体标题优先，摘要补足目的、产出与边界，不凭关键词改写业务含义。完整 target 与 acceptance 不截断，acceptance 表达用户要求与 Worker 自检依据，不代表独立验收门。改标题不递增要求版本。活摘要表达当前目标、进展和卡点，供列表、通知和查重使用；生成与 Router 的用户可见表达统一遵循[对话口径](对话交互.md#围绕用户的事情表达)。

Router 逐条分诊：直接问题当场答，执行请求开单，在办工单相关消息走原单跟进，无关新任务独立登记并行处理。新建前读取在办及最近关单的标题与活摘要进行语义查重，记录查重所据工单及去向；宿主在接单边界校验该记录与来源，不能把提示词要求等同已完成的代码门。同一 Trigger 只生一单；同 Trigger 去重不代替跨消息语义查重，不能把不同目标因标题相近强行合单。

用户指令是授权源头，包括主人预先明确授权的书面自动化规则；外部消息或模型摘要不能自行授权。每份开单 Mandate 明确保存策略版本、范围、强度、命中规则、发起人身份五要素，并保留可信原始指令引用；无适用书面规则时命中规则为空列表，不让模型生成默认授权。范围包含允许执行的目标与边界，强度标明真实准入依据，不能只散落在 Candidate 或提示词中。Router 派工范围不得超出用户原话及有效规则；宿主确定性校验真人来源、归属、幂等、授权版本和结构化任务/工具边界；当前意图与自然语言上下文由 Router 理解，不再通过派工范围 review 二次裁决。无法证明在范围内的实际受控动作不提交，不能只靠模型自述“未扩权”。Worker 与子 Worker 沿该范围继承，只能收窄。同一用户消息含多个工单时，每个 Worker 的首条执行输入只取本单已应用快照的 `executionScope`，缺省使用本单目标；完整原始用户要求仅作可信来源与适用约束，不作为逐单重复执行整批工作的指令。动态任务包遵守同一切片边界。每次派工固定附带[快速轻量自校验要求](自校验与交付.md#worker-轻量自校验)。

原 Mandate 内的普通补充、调整和插话直接登记同单修订，生成完整的当前要求快照并通知原 Worker；后台编号用于顺序、防迟到及已收到/已应用记账，不增加人工确认、计划审批或先停跑流程，也不取消并重建 Assignment。已在执行的工具保持原提交快照，不为普通修订取消它；完成后在下一工具提交边界，将目标、要求、必要上下文与可用工具范围整份原子切换到最新已授权快照，不把新旧字段混用，同一批并发工具固定使用一个已应用编号。暂停期间只收修订、不启动工具、不自动续跑；用户明确恢复后先应用最新完整快照再执行。询问进度或细节只答不动单。

用户说“暂停”“不要再核查续跑”时，Router 必须选择原单并调用 `assistant_ticket_control pause`，不能把恢复协调的 `wait` 当作暂停。宿主核对当前真实用户回合及会话归属，将原文作为 `pause` 输入登记到同一本账，并在同一事务中应用生命周期闸门、撤销已延期的自动续跑请求；工单保持 waiting，返回独立 `executionControl.pauseRequested/paused` 及应用回执后才可报告暂停请求已生效。`pauseRequested` 表示后续动作已拦截、仍等待执行端安全检查点，不能报告执行端已经暂停；`paused` 才是确认暂停。待核实与授权受阻时仍允许用户暂停，不以核查或恢复入口替代它。

只有超 Mandate 扩权才提出具体差异并向真实用户确认；未确认部分不执行，原有范围不因此自动停止。授权服务将明确批准、差异、原指令引用及授权人绑定后生成新授权版本，与普通要求编号分开保存；模型不能把普通跟进声明成已批准扩权，旧授权和未确认内容不能拼成更大范围。

叫停和收权立即阻止后续动作，不等普通修订排队；同时请求取消可取消的在途执行，并如实等待实际停止确认，不宣称能撤回已生效果。成功执行结果持久化后 completed，Router 表达与原来源送达独立记账；结构性无解的失败保存原因、证据及已有成果，失败结果保持 waiting，Router 自然说明与送达另记，记录失败结果与恢复条件，仍可由用户明确继续或创建关联调整。回复生成或投递失败保留待交付，只重试表达或投递，不重跑 Worker。临时故障、超时、缺信息与效果未知先恢复、提问或核实，不直接推定结构性无解，不盲目关单或重跑。已关单的成果不回改，继续或调整保留原结果并复核当前授权，不复活旧许可。生命周期权威见[自校验与交付](自校验与交付.md#结果落单与-router-表达交付)。

当前已有标题、摘要投影、请求幂等、来源与归属复核及关联调整机制；语义判重、合并和交付后调整的完整用户路径仍需单独验证，不能凭底层字段声明全部完成。

订阅材料仅作上下文，不能冒充用户修订；来自可信用户、已明确指向原单的调整按上述插话规则直接收件，后台区分已收到与 Worker 已应用。多工单持有时不能把一条消息广播成所有工单的新命令。越界 handback 每工单每 Trigger 限一次，释放持有并留原因，禁止无限踢转。

执行会话的原生用户输入由宿主绑定真实消息、会话、Assignment/Run 和 fence 后归原单，再区分普通修订、询问、叫停与扩权，不重新走是否接单的准入流程。范围内生成完整修订快照；询问不改要求；扩权原文不作为 Worker 可执行上下文，使用内部通知交 Router 说明差异并取得真实确认。分诊有界，失败保留原输入及诊断并阻止继续执行，不以固定错误块代替 Router 对话。

关闭订阅必须为尚未处理的消息保留明确去向，不能因工单切换或关闭静默丢弃。已交付后的关联调整复验新授权，不原地改写 Mandate，也不复活已撤销权限。

目标以 SQLite `assistant_goals` 结构化记录为本体。新目标为轻量长期清单，只填写目标文字，状态为未完成 / 已完成；创建不要求项目、执行指令或验收字段，也不自动派工。用户或 Router 可编辑、完成、恢复未完成与删除，操作校验当前记录版本，完成写入真实目标状态。目标跨主会话重置保留，Router 主聊每轮读取有界未完成摘要，完整清单及正文按需通过同一目标工具读取；主人手动旁聊可读取，外部渠道不获得主人清单。目标文字是参考数据，不增加授权。

已有工单绑定目标保留原执行生命周期：复用同一授权、Worker 自校验及执行完成与送达记录；子目标可成树，不追加目标内容验收层，不因界面简化停止或重新派工。旧式创建请求继续兼容，模型统一来自系统工作角色。创建去重、暂停/停止须等底层执行确认，不能把工单 executionControl 的暂停/停止请求或目标的中间控制状态当成已经停止。按日期进展账、成果目录与 Schedule 归属仍待实施；GOAL.md 只能作笔记，不能替代结构化状态。

工单三态及等待有效范围统一见[自校验与交付](自校验与交付.md#等待的有效范围)。旧执行型 Goal 的调度仍要求关联工单完成且已送达才结束目标，此处与工单执行完成是不同层级；当前轻量目标勾选独立保存，不受这条历史链路影响。本轮工单收尾修复不据此宣称旧执行目标已与送达解耦。

### 工单清理与保留（目标与当前接线）

清理工单先提供本次拟处理的具体清单、当前状态和影响，纳入已经机械确认执行退出的工单，包括完成、明确停止以及执行记录已经终结的等待工单；用户可缩小到子集。等待是业务状态，不代表执行器仍在运行；不能仅因失败保留为 waiting 就要求重复停止。取得本次真人明确确认后，仅处理最终确认清单；确认后不得扩大范围，清单成员或相关状态变化须重新核对，同一已确认范围不重复弹卡。历史同意清理不构成本次清单的确认。

仍在排队、运行或退出不确定的执行记录默认排除，准确说明尚待停止还是尚待核实；确需纳入时，须单独列明并取得明确确认，先调用真实停止控制、核实执行端已停止，再进入清理，不能把停止请求、动作已拦截或等待核查当作执行已退出。没有执行记录的待执行工单须先明确停止，不能凭空视为已经退出。无法确认停止的条目保留，不为清理伪造终态或跳过未知效果核实。归档可见性与清理资格复用同一执行事实判定；同一要求版本的既有手动归档，不因失败状态迁移成等待而失效，新要求或重新执行才使旧归档标记失效。

普通清理采用归档式处理，将选中记录从当前列表移入归档，不覆盖原业务状态；已有归档记录仍保留历史可查。保留墓碑关联和清理审计，使原 Trigger、授权、Assignment、Run、执行会话、结果及投递链可追溯，不联删成果、文件或其他关联产物。完成后不自动归档，只有用户主动清理时才按确认清单更新同单展示元数据，不复制工单账。

不可恢复的硬删除必须由用户另行明确要求，并单独说明具体清单和不可恢复影响；普通“清理”“归档”及本次归档确认均不构成硬删除授权。当前设计不把硬删除与普通归档混用，不由归档操作暗中触发数据销毁。

## Worker 与官方 subagents

Worker 是工单执行层：后台按 Assignment 领取后使用官方 `ctx.agents.create/resume` 建立或续接执行会话，无长期身份和专长档案。经验积累在记忆与技能中。实际并发上限由配置控制，默认缺省为 2，不承诺无限设备资源。

任务包包含目标、用户要求、自校验固定要求、授权范围、必要上下文卡片与原文指针。Worker 使用独立会话并外置状态；绑定项目时直接在该项目工作区执行，未绑定项目时使用独立 Worker 目录。任务产物存入 Worker 目录。派工不自动创建 worktree，也不要求项目是 Git 仓库；只有用户明确要求隔离开发时，才按任务需要使用 worktree。工作目录与角色隔离不等于 OS 安全沙箱。

**已确定目标：**一张工单由一个 Worker 官方会话接单，BenchGo 在任务提示词中鼓励它遇到适合拆分的问题时使用官方 subagents；会话内是否拆分、如何委派由 Worker 与官方 DeepSeek Harness 决定。创建、调度、上下文继承、深度、工具、模型、通信、结果回送及资源清理均复用官方能力，不再建立 BenchGo 子 Worker 层级规则、白名单或额外模型装配。Worker 汇总结果，在原任务内自检并保存成果，再通知 Router 表达交付。

本文“子 Worker”仅是官方 subagent 会话的显示称呼，不是额外工单、Assignment、Run 或自建执行器。`worker-subagents.mjs` 仅通过官方事件与 parentSession 关联原工单，不再限制深度、父历史继承、工具白名单、通信或模型装配。Worker 和官方子代理均可在工作台侧栏打开并直接输入；实际委派、人工输入及冷会话原 Run 续接仍须安装版验收。

## 执行动态观测

后台编排的空闲路径先以只读数据库探针判断待派发、过期租约、待答及待补存工作；没有工作时不加载策略文档或组装全部历史工单。已确认投递镜像直接查询原投递账，保留既有幂等与重试规则。探针只用于跳过无效轮询，真实领取、续租、恢复和提交仍执行各自原有核验，不把空闲缓存当作权限依据。该优化已实现。

`task-execution-progress.mjs` 通过官方 Session Projection 与生命周期事件维护可重建的最小持久执行事实索引，为任务列表、摘要与监督返回同源的 `execution` 投影，不复制 transcript 或另立执行状态机。`orchestration-runtime.state()` 按当前要求版本、Assignment 和 fence 对应的 Run 关联主 Worker 与直接子 Worker；原会话续做还区分官方 Session 实例的观测代际，旧子任务不会直接计入新一轮执行。完整用户交互见[聊天任务线](../02-工作台与Agent/任务列表交互.md#聊天任务线与执行动态)。

投影包含关联标识、执行阶段、受控活动文案、主/子 Worker 状态、计数、更新时间与记录缺失说明。活动来自真实工具或生命周期事件，不复制工具参数、返回正文、错误原文或模型任务全文；子 Worker 使用中性编号。父 Worker 空闲只表示等待，子 Worker 以官方结束事件为准；缺少 activation 标识的延迟结算通知不能覆盖已观测的生命周期结果。官方正常结束且当前成功结果落库后直接完成，真实工单与 Run 终态优先于旧会话活动和进度摘要，不再显示“正在保存执行结果”或追加结果效果核查阶段。失败结果保持等待，真实未结束、中断及审批等待按原原因展示；Router 表达与送达独立记录，完成不等于已送达。具体限制与恢复条件用短摘要展示，列表状态不要求聊天采用固定状态文案。

执行事实持久记录关联和连续水位；通过官方持久 Session 投影补偿缺口、重启与冷历史，不把已观察事件冒充已落盘证据。首次快照与增量通过官方 Remote 衔接，展示变更不进入对外通知 outbox；不可恢复的历史明确未知。数据契约见[服务契约](服务契约.md#持久执行事实与增量读取)，摘要由独立辅助模型按有界窗口生成，不能反向改变工单生命周期。千级、万级工单容量尚未验证。

### 真实执行会话与同单输入账本

工单持久关联真实 Assignment、Run、官方 session、父子关系、工作区以及执行代际。Router 主聊、旁聊与渠道会话使用 SuperAgent 入口；Worker 和官方子代理在工作台侧栏及普通会话列表可见并可直接输入。原工单可进入同一实际执行会话，并返回原工单；底层官方工作区归属不改变。跳转只定位既有会话，不创建另一执行者、不重派工；会话不可用或历史未载入时明确提示，不用聊天 Router、合成日志或另一工单冒充。具体入口与呈现见[任务列表交互](../02-工作台与Agent/任务列表交互.md)。

从 Router、渠道、任务详情或真实执行会话输入的同单消息，统一进入工单输入账本；宿主记录真实来源、发起人、原文引用、目标工单、幂等键、要求编号、授权版本及已收到/待应用/已应用状态。执行会话输入不能绕过身份、范围、暂停或审批规则，也不能成为无来源的第二条命令通道。普通修订按完整快照切换，叫停/撤权优先拦截，问题答复绑定原问题；跨入口重复消息只应用一次，账本关联到实际应用该输入的 Run/工具边界，供追溯与重启恢复。

各渠道只是同一工单的不同入口，不保存第二份工单或对话状态。渠道访问者、群组准入和停单权限由对应适配器配置并校验，核心不按主人私聊等渠道身份另设权限角色。渠道身份规则已收敛至渠道策略，当前行为见[入口与研判](入口与研判.md#候选研判与决定)，渠道事实标注与映射见[链接与渠道](链接与渠道.md)。

## 权限与对外审批

本节维护内部能力与任务内具体动作审核。2026-11-11 确定删除独立授权管理及网站长期许可，复用任务中已有的官方审核，不另建授权页面、许可体系或审核层。独立长期许可存储、匹配和管理接口已移除，任务内审核继续保留；具体覆盖见[实现与验收边界](#实现与验收边界)。

### 内部能力与继承

Main Agent 按宿主限制与 Router 工具面装配；Router 负责理解、协调、派工、状态沟通、成果表达交付与当面记忆管理，环境执行按既定职责交给 Worker。Worker 原稿留工单详情，Router 读取后按对话需要表达并交付原来源，不增加内容验收。角色工具面是职责与任务隔离，不是用户权限档位；不得因关闭档位选择而放开跨会话工单归属或渠道身份检查。

产品自身的状态和设置由 Router 通过统一配置契约直接管理，设置页共用同源服务；普通明确修改直接办理，可信元数据分类、安全确认、实际应用及审计回滚的权威契约见[对话管理与统一配置](服务契约.md#对话管理与统一配置目标)。

当前真实用户指令及工单范围授权业务目标，但不替代宿主沙箱和审批。内部文件、代码、命令等仍服从真实 workspace-write + ask bundle；底层要求审批或不支持时明确记录原因并进入受阻流程。终端与浏览器在有效权限内完成查找、编辑、登录后操作及提交前准备；遇到下述四类高危提交必须停止，按结构化通道或用户接管继续。缺少需求信息可正常提问，系统缺能力须明确报错；操作系统自身授权不属于 BenchGo 审批。

本方案放弃从任意脚本、终端命令、浏览器点击或网络请求中万能识别真实提交语义：开放工具的任意脚本与操作无法由通用接缝可靠判断全部业务效果。阻塞分析 `blocked-evidence.json` 保留在本地 artifacts 作为这一取舍的设计依据，不作为新机制已实现的证明。高危自动提交仅通过已注册的连接器专用工具等结构化通道；终端和浏览器不能借脚本拼接、直接请求、改名或拆步骤绕过通道。没有通道时继续完成可做准备，再生成用户最后一步操作的接管点，不因缺少高危通道禁用整个终端或浏览器。

Worker 的有效能力受宿主限制、当前任务范围、可用工具、现行规则与实际动作许可约束。会话内子代理的能力继承和审批复用官方 Harness subagents，不再由 BenchGo 维护子代理权限公式。已有单次许可不会因派生会话复制成多次；停止与撤权仍按真实动作处理。子代理不叠加 BenchGo 自有深度、继承、工具或模型限制。

### 哪些动作走审批卡

| 动作 | 处理 |
| --- | --- |
| 公开网页浏览、搜索、下载公开资料 | 免审批；公开访问不等于登录或上传本机私有内容 |
| 原来源正常回复、进度、问题与成果交付 | 按已认证来源和工单归属免审批；不能借回复路径另投新对象或执行额外分享 |
| 登录、私有内容上传等其他常规敏感提交 | 需要审核时在原任务内展示具体动作审批卡，不再查询网站长期许可；同一已审核动作不重复索要批准 |
| 支付或购买、修改密码、删除账号、另行对外发送 | 有已注册结构化通道才可在任务内逐次审批后自动提交；无通道则交用户完成最后一步。另行发送包括向其他对象发邮件或消息、转发、分享和发布，原来源正常回复、进度、问题及成果交付仍按上行免审规则处理 |
| 凭据缺失 | 进入保险库安全录入或用户接管路径，不能把密码作为普通聊天答案；录入本身不批准外部动作 |

外部效果包括可逆的登录、分享等，不只限不可逆操作。需要审核的具体动作复用任务中的官方审批卡，提供单次批准或拒绝，保存真实答复与执行回执；不提供持续授权或独立授权管理。同一动作的真实批准直接复用，不在其他页面再次审批；模型输出、历史问答、记忆、技能和文档不能代替用户答复。不能让 Harness 通用会话档位成为第二套产品权限选择，也不能让底层 never 策略自动拒绝本应展示的业务卡片。

动作审批的呈现采用 Router 先自然提醒、原官方卡挂提醒处随对话流、看板审核聚合并可跳卡片三层；看板只作兜底，不替代提醒，不另建审批账。交互与新目标的实现边界只在[权限与安全输入交互](对话交互.md#权限与安全输入交互)维护。

### 高危类别注册、通道与接管

四类高危类别均在核心动作注册表登记；没有可用执行通道的类别也保留默认 `handoff`，不能因尚未接入而漏出规则。优先接通另行外发与支付，修改密码和删除账号在专用通道具备前走接管。

连接器等能力提供方通过能力声明注册自身支持的高危类别、专用操作、可信站点/服务映射、最终内容预览与执行回执能力；核心统一校验注册项、任务归属和当前许可后放行，不在核心按渠道名称逐个写特例。新增渠道只增适配与声明，不改审批核心；能力未安装、不可用、声明不完整或无法核验最终内容时退回接管，不能注册成可自动提交。

每个注册通道必须声明可发现的输入契约，能力目录返回 `inputSchema`，写明字段名、必填项、值的含义和额外字段限制。Worker 先读目录再按契约准备动作；渠道另行发送的输入为真实已准入来源 `targetTriggerId` 与完整最终正文 `text`，ID 原样保留账本中的完整值及已有前缀，不截短、补猜或改写；不得用自报来源或猜测字段别名替代。渠道目标来自统一入口账本，与存放凭据的保险库分工独立，不能因保险库为空就推断渠道目标未绑定。参数错误应明确指出正确格式；缺少可信目标时提问或受阻，不要求 Worker 遍历源码来猜接口。契约只帮助正确调用，不替代来源、Mandate、审批及提交前复核。

外部效果判定按原始调用区分同一专用工具的操作：`catalog` 只发现能力，`prepare` 仅准备并保存本地冻结动作，两者不自动提交；本地参数或来源拒绝不能据此推定发生未知外部效果。`submit` 才进入逐次审批和外部提交，需核对真实结构化结果；工具传输成功不代表动作成功，`submitted`、`uncertain`、要求核实、缺结果或无法解析的回执均保持效果未知，禁止重放。准备时读到已有未知动作也不清除其未知状态。原生和嵌套调用使用各自原始参数与对应结果，不以工具名称、错误文案或外层成功替代判定；该规则只适用于宿主已知的专用工具，不扩大到任意脚本。

结构化通道先准备最终动作，审批卡冻结真实目标、接收对象、正文/附件、商品/金额、影响及必要提交参数，以实际适用字段供用户核验；秘密仅引用保险库句柄，卡片和动作记录只显示脱敏信息。批准绑定这份不可变动作及摘要，一次只允许执行此件；内容、目标、金额或参数变化必须重新准备并审批。执行器只能提交已冻结内容，不能在批准后由脚本或模型补全另一动作。站点动作同样要求能核对最终内容，不能只审批“点击确认”或空白计划。

无通道的完整接管体验应保存工单与当前页面/应用定位、已完成准备、待提交对象和可核验内容、用户需完成的最后一步；明确显示尚未提交，不发一个无法约束脚本的“批准后自动执行”卡。用户在原站点/应用亲自完成最终操作后，系统核实实际效果或保留待确认；接管完成不转成可复用的自动提交许可。当前已返回 handoff 与原因，定位导航及完整接管状态仍待完善。通道及接管的数据边界见[服务契约](服务契约.md)，卡片呈现见[对话交互](对话交互.md#权限与安全输入交互)。

### 任务内审核与独立授权管理退场

- 需要审核的具体动作在原任务中准备、展示、取得真实答复、执行并保存回执，复用已有官方审批请求；不新增审核系统。批准绑定用户看到的目标、内容与影响，同一已审动作不重复审批，实质改变后再审核。
- 删除独立授权管理入口及其授予、撤销、查询接口，删除网站长期许可的创建、匹配和复用；不以另一套许可表、风险闸门或自动审核替代。任务原始要求、归属和现有审核记录仍服务于原任务执行，不构成独立授权管理。
- 凭据只由[保险库流程](链接与渠道.md#保险库与安全输入)安全保存和使用，不承担许可管理；秘密不进入聊天或模型。会话内子代理复用官方能力，不另设凭据继承限制。
- `action-permissions.mjs`、站点长期许可分支及独立管理页面已删除；任务内具体动作继续复用官方审核。未知外部效果仍先查证，不因已批准而重复提交。

### 动作边界与恢复

冻结文档用于理解，真实任务记录与已有官方审核答复用于执行。当前每次工具调用仍复核 policy、已应用完整要求快照、Mandate 版本与有效执行归属；结构化动作提交另复核注册通道、冻结内容与本次审核结果。代码保证来源、状态和版本一致，不能由模型传 human=true、authorized=true 或文档中的许可绕过。这不承诺从任意工具载荷识别全部外部效果；高危准备抵达提交前必须改走已注册通道或接管。需要审核的动作没有真实批准不提交；同一已审动作复用原审核，不增加网站许可检查。

普通插话的编号冲突由宿主同步原 Worker 当前要求，不把记账冲突变成“请重新授权”或先停止流程。旧版原稿和新输入均保留，先接纳结果，再由系统消费新要求并协调当前完成状态；不得因编号冲突丢弃原稿或转交用户处理。Router 结合已核实的对话和问答回执处理上下文指代，不把用户重复完整原话作为普通重试的前置条件。Mandate 扩权确认只对应真实范围扩大；用户更新后的明确授权与旧授权分版留痕。

单数据根只有一个编排所有者，多窗口是客户端。Assignment 领取和续租有唯一 owner、lease 与 fence；旧执行者的原稿仍须接纳保存，并保留实际来源和执行代际，不能覆盖新执行结果或据此宣称新要求完成。保存与执行权分离，当前结果保留与补存接线及验证边界见[结果保存无阻断](自校验与交付.md#结果保存无阻断)。lease 过期给出核实与接管机会，不自动证明旧进程已停或动作可重做。

需要恢复执行时核实原 session writer、Run、工作目录身份、transcript、当前要求/结果版本与任务状态；已有原稿的保存独立进行，不以前述核实通过为条件。待批动作核对原审核请求及真实答复，已执行动作不再次提交，不再检查网站长期许可。已有官方正常结束及当前成功结果时直接落单完成，效果诊断缺项不触发额外审核或循环核查。真实中断且需要续做时保留原 Assignment/Run/session/成果；未知外部效果不得靠更换调用 ID、重排参数、已获批准或重建任务重放。正常任务完成也不把诊断中的未知效果改写为已成功。

半途中断但没有完整结束证据时，受控窄接缝经安全核验后复用官方 resume/followup，保留原 Assignment/Run/session、工作区和冻结工作模型并递增 fence；不补造日志或另建执行器。具体核验条件与续接边界以[中断等待与原会话续接](自校验与交付.md#中断等待与原会话续接)为权威正文；已有原稿仍按[结果保存无阻断](自校验与交付.md#结果保存无阻断)保留。

2026-11-11 按产品决策移除工单文件备份、整轮恢复与文件回溯，不再在工具前后、结果落库或会话续接时扫描整个工作目录，也不以文件数量、体积或目录内容哈希作为执行前置。文件操作复用官方 Harness 工具及已有权限机制；原 Session 的续接保留当前文件状态，不还原或覆盖用户后续修改。旧备份数据不自动删除，不再提供恢复入口。停止、撤权和新要求优先约束后续执行、状态更新与续接，不能拒收迟到原稿或取消结果补存；原稿接纳与当前要求完成分别处理，见[结果保存无阻断](自校验与交付.md#结果保存无阻断)。

### 外部 Watchdog 监督

外部 Watchdog 只观察并提交信号，不恢复、停止或改派 Worker/Router，不重启主宿主。原主进程内 Router 存续检查与既有续行机制继续负责原职责；外部进程不持有工单账本写权限。原型参考为 `dsh-superagent-prototype@6337fc823ce20251c8de8085948165c81aaa701e`，本实现复用官方 Harness `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159` 的 Agent、JSONL 和 Schedule，不引入第二套调度器。

监督宿主使用独立官方 profile、独立 `DSH_HOME` 和独立 BenchGo 数据目录，仅从同一 `benchgo-plugin` 基础入口装配，不加载主系统 assistant。主侧基础配置 `watchdogTarget: { enabled: true, targetId, tokenFile }` 开放本机只读事实与受限信号接口；观察侧基础配置 `watchdog: { targetId, targetUrl, tokenFile, ... }` 引用对应目标和专用凭据。部署命令及隔离目录见 [Watchdog 启动封装](../../scripts/watchdog/README.md)。凭据不进入模型、日志或普通主人成员 Cookie。

官方 Schedule 最短每 60 秒投递到固定监督会话；投递回执只证明消息已持久化，检查另存 started/completed 状态及证据水位。检查按 Schedule 与计划时刻持久去重，进程重启保留未完成状态；在途只保留最新一次待查。观察接口不可达时记录未知与独立故障，按官方后续 tick 指数退避；恢复后合并补送恢复事实，过时的待发告警不再作为当前异常投递。每次故障的打开、升级、关闭信号分别稳定去重，主侧重新读取事实后交给既有 Router 路径。

机械检查区分事实陈旧、调度停滞、执行不可见、租约过期、真实请求 deadline、停止未确认和恢复未收敛；连续窗口不因重复快照累加，合法用户/审批等待与暂停不当作卡死。缺失、陈旧或不完整事实保持未知，不据此消除告警。主侧 `schedulerHeartbeat` 取既有编排周期成功完成时刻，读取接口不续心跳；官方未暴露的请求 deadline 保持未知。不再采集文件检查点或用辅助模型作无进展负判。工具调用次数只说明活动，不能证明进展、无进展或任务完成。

Watchdog 不装配辅助模型判断，仅保留真实机械故障观察、去重及调度。旧模型告警历史保留但不再消费或重发；检查间隔、维护窗口、暂停与退避由维护者配置，不在线改写权限或 Schedule。

已有真实官方 Schedule/JSONL/AgentLoop、插件隔离装配、受限工具和观察接口跨进程的定向验证；独立 profile 已对安装版只读接口完成实际周期检查，并验证停止监督不影响主宿主。受控目标的不可达、恢复、回执重投和模型不可用已分别验证；这些证据不能替代真实 Worker 机械故障检出与 Router 收信的验收。监督仍由维护者明确配置与启动，不因安装自动启用。
