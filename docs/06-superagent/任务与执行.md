# SuperAgent 任务与执行

本文维护协调、派工、目标与执行生命周期，是工单修订、执行关联及权限规则的权威正文；准入见[入口与研判](入口与研判.md)，结果处理见[自校验与交付](自校验与交付.md)。目标设计与实现边界分别说明。

## Router 与持续主会话

Main Agent 是用户对话入口与总调度者，Router 是其职责名称；本文两者指同一角色。主聊和旁聊各自有官方会话，共用 SuperAgent 模型配置与内部能力基线，旁聊仅隔离话题和归属。

目标：主聊和旁聊默认具备当前宿主可用的完整内部能力，不采用“仅查看工作区 / 可修改 / 完全权限”等面向用户的 Harness 授权档位，输入框不展示或允许切换这些档位。能力可用性仍以实际安装和运行状态为准；不会因此获得操作系统未授予的权限。底层适配在根目录插件、服务与配置完成，不修改官方引擎。对外效果另走[权限与对外审批](#权限与对外审批)。

- 普通问答、工单查询、卡片提问、定时协调、记忆记账与受控配置使用协调工具。
- 查网站、查文件、写代码、跑命令和其他环境操作从第一次探查起就委派 Worker；普通派工不再额外询问是否允许创建工单。
- 工单落库后立即返回当前 Router；由 Router 自然回应，继续接受其他请求，不阻塞等待 Worker。
- 用户始终与 Router 对话；Worker 将成果原稿保存到工单并发完成信号，Router 主动自然提醒已完成，自选摘要或完整回复后交付原来源，不固定报告、标题前缀或状态文案。原稿留在详情，Router 不重派、不做内容验收；追问时可读原稿直接回答，不因问进度或细节改动工单。
- 不相关新请求独立分诊、查重后并行派工；同会话写入串行，只有冲突资源在冲突处串行。
- 内置层真源为 plugins/superagent/prompts/builtin-layer.md，随插件构建并注入系统 section；它与用户文档层分开，不由用户档案覆盖平台机制。
- 工具失败的真实错误码、原因和有界诊断保留在任务详情与日志，不能由模型猜测“权限策略”等理由；聊天由 Router 按真实情况自然说明，不固定输出系统状态块。完整持久错误反馈目前仍是未完成项。

逻辑 thread 与底层模型 session 分离。服务端 send 接受 threadId、text、requestId 和可选 replyContext，先持久收件，再串行启动 Router 回合。同 requestId 同内容幂等，正文或可信引用变化拒绝复用。

回执区分 queued、processing、processed、failed、uncertain、cancelled；processed 仅表示 Router 回合结束。requestState/history.requests 用于重连对账，不能因回执未知自动重发。取消排队请求与当前 Router，不等于撤销后台工单；清空聊天保留工单、去重记录和 sessionLineage 归属。

服务端持久 inbox、取消、恢复和逻辑会话归属已有基础实现；官方全部输入入口、附件、重连和真实桌面重启尚待完整接通与验证。

## 工单、跟进与目标

标题开单生成，当前统一上限为 10 个 Unicode 字符；标题与活摘要共同写清替用户做的具体事情与预期产出，不使用“执行任务”“处理请求”等空泛占位描述。显式指定的具体标题优先，摘要补足目的、产出与边界，不凭关键词改写业务含义。完整 target 与 acceptance 不截断，acceptance 表达用户要求与 Worker 自检依据，不代表独立验收门。改标题不递增要求版本。活摘要表达当前目标、进展和卡点，供列表、通知和查重使用；生成与 Router 的用户可见表达统一遵循[对话口径](对话交互.md#围绕用户的事情表达)。

Router 逐条分诊：直接问题当场答，执行请求开单，在办工单相关消息走原单跟进，无关新任务独立登记并行处理。新建前读取在办及最近关单的标题与活摘要进行语义查重，记录查重所据工单及去向；宿主在接单边界校验该记录与来源，不能把提示词要求等同已完成的代码门。同一 Trigger 只生一单；同 Trigger 去重不代替跨消息语义查重，不能把不同目标因标题相近强行合单。

用户指令是授权源头，包括主人预先明确授权的书面自动化规则；外部消息或模型摘要不能自行授权。每份开单 Mandate 明确保存策略版本、范围、强度、命中规则、发起人身份五要素，并保留可信原始指令引用；无适用书面规则时命中规则为空列表，不让模型生成默认授权。范围包含允许执行的目标与边界，强度标明真实准入依据，不能只散落在 Candidate 或提示词中。Router 派工范围不得超出用户原话及有效规则；宿主校验来源、授权版本和结构化任务/工具边界，无法证明在范围内的动作不提交，不能只靠模型自述“未扩权”。Worker 与子 Worker 沿该范围继承，只能收窄。每次派工固定附带[快速轻量自校验要求](自校验与交付.md#worker-轻量自校验)。

原 Mandate 内的普通补充、调整和插话直接登记同单修订，生成完整的当前要求快照并通知原 Worker；后台编号用于顺序、防迟到及已收到/已应用记账，不增加人工确认、计划审批或先停跑流程，也不取消并重建 Assignment。已在执行的工具保持原提交快照，不为普通修订取消它；完成后在下一工具提交边界，将目标、要求、必要上下文与可用工具范围整份原子切换到最新已授权快照，不把新旧字段混用，同一批并发工具固定使用一个已应用编号。暂停期间只收修订、不启动工具、不自动续跑；用户明确恢复后先应用最新完整快照再执行。询问进度或细节只答不动单。

用户说“暂停”“不要再核查续跑”时，Router 必须选择原单并调用 `assistant_ticket_control pause`，不能把恢复协调的 `wait` 当作暂停。宿主核对当前真实用户回合及会话归属，将原文作为 `pause` 输入登记到同一本账，并在同一事务中应用生命周期闸门、撤销已延期的自动续跑请求；返回真实 `pausing/paused` 及应用回执后才可报告暂停请求已生效。`pausing` 表示后续动作已拦截、仍等待执行端安全检查点，不能报告执行端已经暂停；`paused` 才是确认暂停。待核实与授权受阻时仍允许用户暂停，不以核查或恢复入口替代它。

只有超 Mandate 扩权才提出具体差异并向真实用户确认；未确认部分不执行，原有范围不因此自动停止。授权服务将明确批准、差异、原指令引用及授权人绑定后生成新授权版本，与普通要求编号分开保存；模型不能把普通跟进声明成已批准扩权，旧授权和未确认内容不能拼成更大范围。

叫停和收权立即阻止后续动作，不等普通修订排队；同时请求取消可取消的在途执行，并如实等待实际停止确认，不宣称能撤回已生效果。Router 成果回复确认原来源送达后 completed 关单；结构性无解的失败保存原因、证据及已有成果，Router 自然说明确认送达后 failed 关单，仍可由用户明确继续或创建关联调整。回复生成或投递失败保留待交付，只重试表达或投递，不重跑 Worker。临时故障、超时、缺信息与效果未知先恢复、提问或核实，不直接推定结构性无解，不盲目关单或重跑。已关单的成果不回改，继续或调整保留原结果并复核当前授权，不复活旧许可。生命周期权威见[自校验与交付](自校验与交付.md#结果落单与-router-表达交付)。

当前已有标题、摘要投影、请求幂等、来源与归属复核及关联调整机制；语义判重、合并和交付后调整的完整用户路径仍需单独验证，不能凭底层字段声明全部完成。

订阅材料仅作上下文，不能冒充用户修订；来自可信用户、已明确指向原单的调整按上述插话规则直接收件，后台区分已收到与 Worker 已应用。多工单持有时不能把一条消息广播成所有工单的新命令。越界 handback 每工单每 Trigger 限一次，释放持有并留原因，禁止无限踢转。

执行会话的原生用户输入由宿主绑定真实消息、会话、Assignment/Run 和 fence 后归原单，再区分普通修订、询问、叫停与扩权，不重新走是否接单的准入流程。范围内生成完整修订快照；询问不改要求；扩权原文不作为 Worker 可执行上下文，使用内部通知交 Router 说明差异并取得真实确认。分诊有界，失败保留原输入及诊断并阻止继续执行，不以固定错误块代替 Router 对话。

关闭订阅必须为尚未处理的消息保留明确去向，不能因工单切换或关闭静默丢弃。已交付后的关联调整复验新授权，不原地改写 Mandate，也不复活已撤销权限。

持续目标以 SQLite 结构化记录为本体，叶目标绑定工单，复用同一授权、Worker 自校验及送达关单流程；子目标可成树，不追加目标内容验收层。创建去重、暂停/停止须等底层执行确认，不能把 pausing/cancelling 当成已经停止。

当前目标偏执行型，需项目与指令；模型统一来自系统工作角色，不提供目标或节点级模型选择，历史模型字段不回流为新授权或覆盖。纯跟踪事项、按日期进展账、目标说明与成果目录、活跃目标上下文投影、goalId 与 Schedule 归属仍有缺口。目标存在不自动授权无限执行，GOAL.md 只能作笔记，不能替代结构化状态。

## Worker 与一层子代理

Worker 是按单领取的临时执行者，无长期身份和专长档案；经验积累在记忆与技能中。Router 决策先写 Assignment，后台代码机械领取，当前使用官方 ctx.agents.create/resume。实际并发上限由配置控制，默认缺省为 2，不承诺无限设备资源。

任务包包含目标、用户要求、自校验固定要求、授权范围、必要上下文卡片与原文指针。目标要求三重隔离：独立会话、独立工作环境、状态外置。代码项目优先使用独立 worktree，其他任务使用 Worker 目录；目录隔离不等于 OS 安全沙箱。

Worker 可以按效率自主下派独立任务，限制一层：

1. Worker 继承 Main Agent 的业务授权，子 Worker 继承父 Worker 的有效授权；系统按本工单任务范围、角色工具面和当前可用能力逐层取交集，静默生效，不要求用户为每层重新选择权限档位。子任务只拿任务切片与原文指针，继承权限不代表复制全量上下文或凭据。
2. 子代理不得再委派，不读取 Router 全套开局包，不提供凭据工具，不直接向用户提问或交付；Worker 与子 Worker 均不直接写长期记忆。
3. 结果由运行时回送父 Worker；父 Worker 可继续做独立工作，不持续轮询或编造进度。
4. 不因暂时安静而关闭；失败或中断先检查已有产出，再决定替换、恢复或上报。
5. 不可逆动作重复前先核实效果，失败说明不等于动作未发生。
6. Worker 汇总子代理结果，在原任务内做快速轻量自校验后将成果原稿保存到工单，并对完整性负责；向 Router 发完成信号，由 Router 自然表达并交付原来源，不另审内容或重派。

当前官方子代理深度与权限门已有实现，仍保留 Worker → 一层子 Worker 的限制，不扩展递归深度。已接入逐工具硬门：按已应用任务快照与现行 Mandate 的工具面取交集，子代理禁凭据和再次委派，并复核当前工单状态、策略与执行归属；不靠提示词作为工具放行依据。真实并发、恢复及审批传递仍须与运行实例核对。

## 执行动态观测

`task-execution-progress.mjs` 只读订阅官方 Session、Agent 与子代理生命周期，为任务列表返回可丢弃的 `execution` 投影。`orchestration-runtime.state()` 按当前要求版本、Assignment 和 fence 对应的 Run 关联主 Worker 与直接子 Worker；原会话续做还区分官方 Session 实例的观测代际，旧子任务不会直接计入新一轮执行。完整用户交互见[聊天任务线](../02-工作台与Agent/任务列表交互.md#聊天任务线与执行动态)。

投影包含关联标识、执行阶段、受控活动文案、主/子 Worker 状态、计数、更新时间与记录缺失说明。活动来自真实工具或生命周期事件，不复制工具参数、返回正文、错误原文或模型任务全文；子 Worker 使用中性编号。父 Worker 空闲只表示等待，子 Worker 以官方结束事件为准；缺少 activation 标识的延迟结算通知不能覆盖已观测的生命周期结果。执行完成、Router 回复待交付、成功/失败说明确认送达关单及等待条件分别展示，不设置“待内容验收”阶段；列表状态不要求聊天采用固定状态文案。

观测缓存最多保留 2048 条，不扫描冷日志、不发模型请求、不引入执行轮询；每次状态查询只扫描一次在线 Agent 列表，停用时释放监听。重启前未载入的历史、缓存淘汰或无法确认归属的动态显示为不完整或未知。这是近期执行观测，不是永久的完整执行树；千级、万级工单容量尚未验证。

### 真实执行会话与同单输入账本

工单持久关联真实 Assignment、Run、官方 session、父子关系、工作区以及执行代际。项目工作区会话列表和官方「未分组」（按最近活动排序）入口按真实记录发现执行会话；会话标记可跳原工单，工单可反向跳实际执行会话。跳转只定位既有会话，不创建另一执行者、不重派工；会话不可用或历史未载入时明确提示，不用聊天 Router、合成日志或另一工单冒充。具体入口与呈现见[任务列表交互](../02-工作台与Agent/任务列表交互.md)。

从 Router、渠道、任务详情或真实执行会话输入的同单消息，统一进入工单输入账本；宿主记录真实来源、发起人、原文引用、目标工单、幂等键、要求编号、授权版本及已收到/待应用/已应用状态。执行会话输入不能绕过身份、范围、暂停或审批规则，也不能成为无来源的第二条命令通道。普通修订按完整快照切换，叫停/撤权优先拦截，问题答复绑定原问题；跨入口重复消息只应用一次，账本关联到实际应用该输入的 Run/工具边界，供追溯与重启恢复。

各渠道只是同一工单的不同入口，不保存第二份输入、状态、投递记录或关单条件；渠道会话复用工作台会话机制与来源标记，适配器不保存自身对话状态。渠道事件先经过统一入口管线，停类内容是否具备直接停单资格按[入口与研判](入口与研判.md#候选研判与决定)判定；不能用群组、话题或系统事件中的停类文字绕过主人私聊限制。渠道事实标注、映射与适配器边界见[链接与渠道](链接与渠道.md)。

## 权限与对外审批

本节维护内部能力、权限继承与对外动作授权；动作存储、注册通道、逐工具门和授权管理已接线，具体覆盖见[实现与验收边界](#实现与验收边界)。内部默认能力、角色分工、外部效果授权分别处理；不以关闭所有审批或保留一套隐藏的通用权限档位替代本机制。

### 内部能力与继承

Main Agent 默认拥有完整内部能力；Router 负责理解、协调、派工、状态沟通、成果表达交付与当面记忆管理，环境执行按既定职责交给 Worker。Worker 原稿留工单详情，Router 读取后按对话需要表达并交付原来源，不增加内容验收。角色工具面是职责与任务隔离，不是用户权限档位；不得因关闭档位选择而放开跨会话工单归属或渠道身份检查。

内部文件、代码、命令、配置、记忆管理、持续目标创建和普通委派在当前真实用户指令及工单范围内不额外弹权限审批。终端与浏览器保留完成这些工作的完整能力，可完成查找、编辑、登录后操作及提交前准备；遇到下述四类高危提交必须停止，按结构化通道或用户接管继续。缺少需求信息可正常提问，系统缺能力须明确报错；操作系统自身授权不属于 BenchGo 审批。

本方案放弃从任意脚本、终端命令、浏览器点击或网络请求中万能识别真实提交语义：开放工具的任意脚本与操作无法由通用接缝可靠判断全部业务效果。阻塞分析 `blocked-evidence.json` 保留在本地 artifacts 作为这一取舍的设计依据，不作为新机制已实现的证明。高危自动提交仅通过已注册的连接器专用工具等结构化通道；终端和浏览器不能借脚本拼接、直接请求、改名或拆步骤绕过通道。没有通道时继续完成可做准备，再生成用户最后一步操作的接管点，不因缺少高危通道禁用整个终端或浏览器。

Worker 的有效能力为父级有效授权 ∩ 当前任务范围 ∩ 角色工具面 ∩ 实际可用能力；子 Worker 同样计算，不能自行扩权。已有对外授权按同一服务继承和匹配，单次授权不会因派生会话复制成多次。停止、撤权和规则收紧立即拦截后续动作；普通要求版本变化按插话自然并入，不触发停跑审批。内部不允许的工具由系统直接拦截，不向用户弹档位选择。

### 哪些动作走审批卡

| 动作 | 处理 |
| --- | --- |
| 公开网页浏览、搜索、下载公开资料 | 免审批；公开访问不等于登录或上传本机私有内容 |
| 原来源正常回复、进度、问题与成果交付 | 按已认证来源和工单归属免审批；不能借回复路径另投新对象或执行额外分享 |
| 登录、私有内容上传等其他常规敏感提交 | 未同时触发下行高风险动作时，匹配实际站点、动作类别、期限与当前任务范围；无有效授权时展示具体动作审批卡 |
| 支付或购买、修改密码、删除账号、另行对外发送 | 有已注册结构化通道才可在逐次审批后自动提交；无通道则交用户完成最后一步。网站持续授权不能覆盖；另行发送包括向其他对象发邮件或消息、转发、分享和发布，原来源正常回复、进度、问题及成果交付仍按上行免审规则处理 |
| 凭据缺失 | 进入保险库安全录入或用户接管路径，不能把密码作为普通聊天答案；录入本身不批准外部动作 |

外部效果包括可逆的登录、分享等，不只限不可逆操作。卡片提供批准单次、拒绝；适用的网站动作还可明确选择站点、动作类别与期限的持续授权，高风险动作只提供逐次批准。模型输出、普通问答、记忆、技能和文档不能创建许可；审批绑定真实用户操作，由宿主统一授权服务保存并校验。可复用官方审批交互与审计接缝，不能让 Harness 通用会话档位成为第二套产品权限选择，也不能让底层 never 策略自动拒绝本应展示的业务卡片。

### 高危类别注册、通道与接管

四类高危类别均在核心动作注册表登记；没有可用执行通道的类别也保留默认 `handoff`，不能因尚未接入而漏出规则。优先接通另行外发与支付，修改密码和删除账号在专用通道具备前走接管。

连接器等能力提供方通过能力声明注册自身支持的高危类别、专用操作、可信站点/服务映射、最终内容预览与执行回执能力；核心统一校验注册项、任务归属和当前许可后放行，不在核心按渠道名称逐个写特例。新增渠道只增适配与声明，不改审批核心；能力未安装、不可用、声明不完整或无法核验最终内容时退回接管，不能注册成可自动提交。

每个注册通道必须声明可发现的输入契约，能力目录返回 `inputSchema`，写明字段名、必填项、值的含义和额外字段限制。Worker 先读目录再按契约准备动作；渠道另行发送的输入为真实已准入来源 `targetTriggerId` 与完整最终正文 `text`，ID 原样保留账本中的完整值及已有前缀，不截短、补猜或改写；不得用自报来源或猜测字段别名替代。渠道目标来自统一入口账本，与存放凭据的保险库分工独立，不能因保险库为空就推断渠道目标未绑定。参数错误应明确指出正确格式；缺少可信目标时提问或受阻，不要求 Worker 遍历源码来猜接口。契约只帮助正确调用，不替代来源、Mandate、审批及提交前复核。

外部效果判定按原始调用区分同一专用工具的操作：`catalog` 只发现能力，`prepare` 仅准备并保存本地冻结动作，两者不自动提交；本地参数或来源拒绝不能据此推定发生未知外部效果。`submit` 才进入逐次审批和外部提交，需核对真实结构化结果；工具传输成功不代表动作成功，`submitted`、`uncertain`、要求核实、缺结果或无法解析的回执均保持效果未知，禁止重放。准备时读到已有未知动作也不清除其未知状态。原生和嵌套调用使用各自原始参数与对应结果，不以工具名称、错误文案或外层成功替代判定；该规则只适用于宿主已知的专用工具，不扩大到任意脚本。

结构化通道先准备最终动作，审批卡冻结真实目标、接收对象、正文/附件、商品/金额、影响及必要提交参数，以实际适用字段供用户核验；秘密仅引用保险库句柄，卡片和动作记录只显示脱敏信息。批准绑定这份不可变动作及摘要，一次只允许执行此件；内容、目标、金额或参数变化必须重新准备并审批。执行器只能提交已冻结内容，不能在批准后由脚本或模型补全另一动作。站点动作同样要求能核对最终内容，不能只审批“点击确认”或空白计划。

无通道的完整接管体验应保存工单与当前页面/应用定位、已完成准备、待提交对象和可核验内容、用户需完成的最后一步；明确显示尚未提交，不发一个无法约束脚本的“批准后自动执行”卡。用户在原站点/应用亲自完成最终操作后，系统核实实际效果或保留待确认；接管完成不转成可复用的自动提交许可。当前已返回 handoff 与原因，定位导航及完整接管状态仍待完善。通道及接管的数据边界见[服务契约](服务契约.md)，卡片呈现见[对话交互](对话交互.md#权限与安全输入交互)。

### 单次授权与网站持续授权

- 单次授权绑定实际站点或服务、目标对象、动作与不可变提交内容；执行前再次校验。更改收件人、购买内容、提交参数等后须重批，不能先批空计划再填内容。审批与动作登记幂等，未知效果先查证，不能自动重复消费授权。
- 网站持续授权保存精确站点、用户明确批准的动作类别与有效期限，可撤销；自用场景可一次覆盖较宽的常规敏感类别（如本站登录、私有资料上传及常规设置），仍须完整显示所选类别。只在三者及当前任务范围均匹配时静默通过；四类高危始终除外。未批准类别、过期或范围变化须重新批准，不存在无边界的“全站所有动作”许可。授权本身不创造新任务，也不允许 Agent 无事主动执行。
- 支付或购买、修改密码、删除账号、另行对外发送始终逐次审批，不受持续授权放行。单次批准绑定真实目标、影响和不可变提交内容；不得拆步骤、换工具、改调用名或借原来源回复通道绕过。
- 凭据代填仍校验目标和适用动作许可；凭据工具只给拥有该任务的 Worker，不能下放子 Worker。连接器和外部服务逐项匹配本服务授权，不跨服务挪用；可信适配器可将本站连接器映射到同一站点，不能由模型自报映射。
- 网站以卡片展示并持久保存的精确 origin（协议、主机、有效端口）匹配，不用模糊字符串或顶级域名推断范围。跳转其他网站、子域名或外部收款站不自动继承；同站连接器映射须由可信适配器声明。非网站服务默认使用单次审批，不猜测“始终授权”的网站范围。
- 持续授权绑定真实授权人和数据档案，在主聊、旁聊及同属工单的 Worker 间复用，跨重启保留并重新检查期限及撤销状态；其他渠道使用者不能借用桌面主人的授权。可从资源中的授权管理入口查看站点、类别、期限并撤销，也可由明确的撤销指令触发服务撤销；撤销阻止尚未提交动作，不能撤回已产生的外部效果。
- 卡片明确显示本次目标与动作；创建持续授权时完整显示站点、类别、期限和高风险逐次审批例外。许可命中后保留脱敏审计与实际回执。凭据始终由[保险库流程](链接与渠道.md#保险库与安全输入)处理，不因站点授权暴露明文。

### 动作边界与恢复

冻结文档用于理解，磁盘现行规则与授权服务用于许可。每次工具调用复核当前 policy、已应用的完整要求快照、Mandate 授权版本与有效执行归属；结构化动作提交另复核注册通道、冻结内容与适用许可。代码保证来源、状态和版本一致，不能由模型传 human=true、authorized=true 或文档中的许可绕过。这不承诺从任意工具载荷识别全部外部效果；高危准备抵达提交前必须改走已注册通道或接管。无法确认授权的结构化动作不提交；有效网站授权仅免除其覆盖的非高危动作重复审批。

普通插话的编号冲突由宿主同步原 Worker 当前要求，不把记账冲突变成“请重新授权”或先停止流程。Mandate 扩权确认只对应真实范围扩大；用户更新后的明确授权与旧授权分版留痕。

单数据根只有一个编排所有者，多窗口是客户端。Assignment 领取和续租有唯一 owner、lease 与 fence；旧执行者不能提交新权属的结果。lease 过期给出核实与接管机会，不自动证明旧进程已停或动作可重做。

恢复前核实原 session writer、Run、工作区、checkpoint、transcript、当前要求/结果版本及权限；待批动作重查内容和授权状态，已消耗单次许可不重新发放，持续授权重查撤销状态。保留原 Assignment/Run/session/成果续行；未知外部效果保持 uncertain，不能靠更换调用 ID、重排参数、已获批准或重建任务重放。

半途中断但没有完整结束证据时，受控窄接缝经安全核验后复用官方 resume/followup，保留原 Assignment/Run/session、工作区和冻结工作模型并递增 fence；不补造日志或另建执行器。具体核验条件与 Router 异步处置以[待核实通报与自主处置](自校验与交付.md#待核实通报与自主处置)为权威正文。

写文件和危险命令前按能力建立检查点，恢复保留用户后续修改；文件快照不能撤销外部发送、付款等效果。停止、撤权和新要求优先于迟到结果、自动重试与恢复。

Watchdog 对 Worker 可核实卡死、异常并恢复或升级；对活着的 Router 只观察、不纠偏改派，对确认失活的 Router 才恢复存续。调度心跳、模型请求 deadline、执行租约与合法异步等待分别判断；请求超时不等于整张工单作废。

## 实现与验收边界

已有 direct Trigger、真实来源、工单、官方 Worker、持久 inbox、sessionLineage、lease/fence、检查点与续做机制。当前接线与需核实边界：

- 权限代码接线已完成：动作与授权持久化、可信代码注册类别/专用通道、冻结 target/content/submission 及工单/Run/Mandate/策略绑定、仅接受 `allowed-once` 的正式审批、单次消费、撤权与未知效果不重放，以及 Worker/子代理逐工具硬门。终端与浏览器保持开放，系统指令禁止四类高危提交和脚本绕过，不宣称对任意脚本的实际效果存在万能拦截。
- 当前内置高危通道为渠道另行发送，只向已持久化来源目标准备冻结正文；支付、改密、删号没有专用适配器，目录返回 handoff。受控回执必须为 `accepted` 且含 messageId/receiptId/transactionId 之一，否则记 uncertain。站点许可已按真实 actor/profile、精确 origin、login/private-upload 类别及期限持久保存并支持撤销；当前没有内置登录/上传适配器，不能宣称浏览器登录已受控。授权管理页面已接线；完整安全输入与浏览器代填仍未接通。旧任意 HTTP 凭据执行工具 `assistant_vault_execute` 已整段删除、不再注册；仅保留 `assistant_vault_list` 返回不透明句柄，无专用通道统一通过 `assistant_external_action` 目录/准备返回 handoff，不保留同名兼容路径。
- 验收应覆盖主聊与未归档旁聊并存、不同工具、并发和恢复，不由单一路径推定其他场景；自检与交付机制见[自校验与交付](自校验与交付.md#实现与验收边界)。
- Router 工具失败按真实错误码持久保留在任务详情与日志，不能按关键词漏报；临时事件或模型解释不能替代系统记录，不把固定错误状态作为聊天正文。
- 官方输入入口完整接入、附件、连续请求与真实桌面重启；服务端收件能力不代表各客户端均已接通。
- 原环境自检修正、提问后原单续跑、执行会话整份修订、暂停/恢复、失活与未知效果须分别验收；停止确认前不报告已停止。
- 语义查重/合并、跟进分诊、交付后关联调整以及持续目标缺口；完整健康状态与异常升级处置。

权限与审批验收须使用正式 Harness 审批卡核对真实用户批准/拒绝，并验证真实渠道发送、拒绝及撤权后的拦截；页面渲染和接口可用不能代替业务效果。

验收覆盖不同工单隔离并行、同一 session 单写入者、子代理深度和权限传递、收紧规则在动作边界生效、重启前核实效果及原执行归属。任务列表交互复用[工作台任务列表设计](../02-工作台与Agent/任务列表交互.md)。

普通修订的服务端边界已实现：`ticket-revisions.mjs` 保留原 Assignment/Run/session，原始 Mandate 与普通要求编号分离；`ticket-input-store.mjs` 在同一数据库中持久输入来源、幂等键、完整快照与实际应用的 Run/工具批次。官方 `agent/pre-step` 将完整目标、要求、上下文及工具范围一次切换，同一模型步派生的并发或串行工具共用该快照；窄分派保留原执行范围。暂停及正在暂停只收输入，明确恢复后再应用；停止和撤权仍优先走逐动作门。主聊补充、渠道订阅、原问题回答与执行会话文字输入共用该账本，执行会话原始用户消息先登记再过滤，由统一收件投影进入 Worker。结构化授权范围扩大必须提供宿主绑定真实用户、原指令与批准编号的回执，普通修订不产生新许可，也不使用正则判断自然语言扩权。验收覆盖快照批次、同执行续做、暂停不续跑、来源去重与实际应用记录，以及跨渠道端到端和运行中重启；执行会话附件当前明确不支持。

修订服务的扩权确认通过宿主 `requestExpansion` 异步取得真实批准回执；返回后重新核对规则、原指令、要求编号、工单状态和原 Mandate，再将回执绑定到精确差异并递增独立授权版本。同一请求重试不重复申请许可。尚无 Run 的排队工单可确认新项目后沿原 Assignment 首次启动；已经建立真实执行会话的工单不能假装原地改变官方工作区，明确返回 `PROJECT_REQUIRES_ADJUSTMENT`，需停止后创建关联调整。领域操作只保留 `revise` 和 `adjustment`，已结束工单统一关联调整，不保留 `reopen` 双轨别名。

Worker 原会话自检、Router 表达交付和送达关单的实现边界见[自校验与交付](自校验与交付.md#实现与验收边界)。Mandate 五要素持久化、工具级范围校验和查重接单门不能由现有字段或提示词推定已完整部署。

验收另覆盖主/旁聊均无档位选择、内部动作与公开查询免审、原来源回复免审；结构化通道无授权必出卡，冻结内容变化失效，一次只提交此件；网站授权按精确 origin/类别/期限匹配并跨会话/重启复用，跨站不扩展、跨人不借用、撤销立即生效，四类高危即使命中持续授权也逐次审批。验证能力声明经核心注册表校验、新渠道不改审批核心、未接通高危类别默认 handoff；通用终端/浏览器完成准备后在高危提交前停下，无通道生成接管点，不能靠脚本拼接绕过，也不把提示词遵守误报为万能提交识别。凭据输入不泄密、不替代批准，未知效果不重放；子 Worker 不扩权且仍只一层。普通修订不取消在途工具，同一工具批次不混用快照；暂停收件不续跑，执行会话与项目工作区/官方「未分组」（按最近活动排序）入口双向跳转真实，同单跨入口输入去重与已应用记录可追溯。
