## 1. 双记忆与数据权威

产品身份统一约定（已接入，具体边界见宠物文档）：SuperAgent 就是宠物助手，并承担 Router 职责。面向用户分为主人档案（以 USER.md 为主）与宠物档案（复用 IDENTITY.md、SOUL.md 及外观配置），不建立可切换的独立陪伴身份。下述记忆与账本就是这个助手的一套连续记忆，涵盖主人认识、共同经历与工作经验；“双记忆”指提炼层与账本层，不是助手记忆与宠物记忆两套系统。换外观不改变身份或清空记忆，具体边界见[宠物设计](宠物.md#8-统一身份两类档案一套记忆一个助手)。

提炼层保存人格、事实、决定与经验，账本层保存事件原文及关系；两层互补。模型决定提炼什么、顺引用查多远，系统负责版本、索引、触发、引用与无损读取。

| 文档链（固定顺序） | 职责 |
| --- | --- |
| SOUL.md | 性格、表达与底线，变化最慢 |
| IDENTITY.md | 名字、形象、标志与对外身份 |
| USER.md | 主人称呼、时区、关心事项与偏好 |
| AGENTS.md | 工作约定、经验、审批红线、渠道与保险库使用规矩 |
| MEMORY.md | 决定、偏好、关系、项目结论；每日日志另存流水并提炼 |

五文件已是当前上下文顺序；旧 TOOLS.md 不再是必注入第六文件，但仍作为第六个受管理文件保留用户原文、兼容读取及导入，不直接删除，工具使用笔记可按需读。真实工具能力仍由宿主注册表确定，不能把笔记当可用性证明。

身份展示和自然语言改名统一写入 IDENTITY.md；config.name 仅作为缺少 name 字段时的显示回退。统一备份与迁移方案后续设计，不为身份单独提供冲突迁移或回滚流程。

## 2. 冻结理解、实时许可

会话开始冻结 SOUL → IDENTITY → USER → AGENTS → MEMORY，记录内容哈希与 snapshotId。人格、偏好和记忆写入即时落盘，当前会话不热刷新，下一会话使用新快照。主聊天稳定入口与底层推理会话分开：需要换会话时保留入口、账本和工单引用，由新会话读账续上。

冻结快照只管理解，磁盘现行版本才是执法依据。每次受控动作前执行层读取当前规则、校验 policy 版本与 Mandate；授权收紧/撤回立即阻止未执行动作，Worker 下个动作边界复验。放宽可立即生效，但无需强制刷新模型读本；无法解析或确认许可时拒绝受控动作。规则由文档表达，审批卡和执行门复用宿主实现，不能仅依赖模型自觉。

持久文档可以即时写回，但不能借记忆沉淀悄悄放宽权限。规则修订保留来源、版本与差异；引用历史、群消息和工具结果都不能伪造主人授权。

主人直聊“不压缩”特指入口不做群聊窗口化/Inline & Spill；不禁止超长运行会话使用 Harness 上下文整理。整理必须保留原文账本和引用，不能用摘要替换唯一原文，也不能在整理时偷偷刷新本会话冻结文档。

## 3. 编辑与项目规则

目标是正文按 add / patch / remove 精确修改，超限明确报错，同回合由调用者腾挪，不自动概括重写用户资料。当前 `assistant_profile` 和文档编辑器仍以完整 `content` 加 `expectedHash` 更新；版本、journal、同目录原子替换与冲突检测已存在，但不能据此宣称增量编辑协议已完成。多文件更新记录部分成功，文件与 SQLite 不谎称跨介质原子事务。

手工编辑可被识别并入账；并发 review 使用版本校验，冲突重新读取，不覆盖用户修改。遗忘须同步当前正文、索引、派生候选及允许保留的历史范围；“全量留痕”不用于抵消用户明确的删除要求。凭据不进任一层。

项目规则按 first-match 候选次序选择一种来源：.hermes.md → AGENTS.override.md → AGENTS.md → CLAUDE.md → .cursorrules；同名规则沿适用目录链合并，深层更具体，SOUL 独立恒在文档链首位。该次序是 BenchGo 方案，不宣称与 Hermes 当前实现完全相同。

项目规则发现优先使用 Harness 已有上下文能力；若宿主选择语义不同，在插件适配层解决并验证只注入一份，不直接更改上游或同时叠加两种冲突加载器。

## 4. 账本、FTS5 与链式回忆

Harness 继续是其原生会话日志唯一写入者；SuperAgent SQLite 保存外部 Trigger 原文、工单及关系，并为 Harness 会话建立可重建原文投影/索引。既保留统一 SQLite + FTS5 检索入口，也不新建可编辑聊天副本。导入按 sessionId/eventSeq 去重，有索引水位和恢复游标。

关系在写入时建立：Trigger ↔ Thread ↔ Ticket ↔ Disposition，另关联 Assignment、Run、结果、Attention、交付回执。引用读取返回原文和来源，不重新调用模型总结；长原文可分页但带完整长度、nextCursor 与完整性标识，不能截断后假装完整。编号失效明确报错。

Inline 卡片只负责上下文预算，溢出原文可按 ID 取回；没有稳定引用不允许只保留摘要。FTS5 做字面检索，不把向量语义检索作为首轮依赖。`ledger.mjs` 的中文 FTS5 与原文分页已实现；`memory.mjs` 的提炼记忆搜索仍使用 `memory_terms` 索引加正文匹配，两条检索路径尚未统一。搜索性能需在单机真实数据量测量，“约20ms”仅为来源描述。

## 5. 即时写回与后台 review

三个入口齐备：开局读快照，干活/输出时即时写入，后台 review 定额沉淀。双计数器默认用户 prompt 每 10 个、单回合工具迭代 10 次；任一达到阈值触发同一 review 流程，一次处理记忆和技能，前后台并行，不等空闲。

计数和触发持久化并按原始事件去重；同一来源范围不重复入队，成功后推进水位，失败有限重试。后台自身输出不递归增加用户 prompt 计数，不无限派生 review。并行不代表无资源上限：受辅助模型额度、队列和文档写锁约束，但不能以“前台忙”无限延后定额工作。

三个沉淀入口共用流水线：/learn 确定性指令、明确自然语言沉淀请求、自动计数器。大语料走精益索引及按章蒸馏，不把原文全部塞入记忆。保留来源、差异和回退点；不将不确定猜测冒充用户事实。

一个辅助模型槽位 + 能力勾选（看图/压缩/总结/review），未勾选归主模型；更改即时影响后续请求，已在途请求保持记录的配置版本。辅助模型有独立备选，效果不足回主模型。实际能力不足需明确提示，不能通过改写模型 ID 猜能力。

### 5.1 记忆直接生效（2026-11-04 本次实施契约）

- 用户明确要求记住、纠正或遗忘时即时执行；记忆操作不再生成专门的模型动作工单或逐条确认。后台 review 提炼的记忆也直接写入，前提是真实用户消息来源、有效正文与当前学习规则校验通过。自动学习无需额外的 explicit / durable / risk 标记；无可信来源不写入，也不转交用户逐条批准。
- 复用现有 Markdown 权威正文、SQLite 索引、文档锁、版本冲突和内容去重，不建立另一套记忆存储。学习关闭、排除内容/范围、拒绝、纠正与遗忘屏蔽继续有效；记忆写入不能修改权限规则。显式管理和后台学习的权限边界保持清楚。
- 历史 pending / saving 候选按相同来源和学习规则自动处理；已拒绝、已遗忘的内容不恢复。重复处理、并发处理或写入后重启不得重复生成记忆；写入失败保留可重试记录并返回真实错误，不显示成功或要求用户批准。
- 页面只展示已保存的记忆时间线，保留来源、更新时间、编辑与遗忘。新增和编辑共用保存流程；移除候选列表请求、接受/拒绝操作及专用样式。单条遗忘直接执行，未保存草稿离开提示保留。复用现有四态组件与整体加载/错误重试入口，本次视觉由用户验收。
- HTTP / MCP 使用现有记忆工具与 CRUD 契约；同步描述直接生效的语义。旧 memoryCandidates / memoryCandidateAccept / memoryCandidateReject 仅保留为已弃用兼容入口，不用于新页面或正常学习流程。自建技能审批、工单验收和其他受控动作不在本次范围。
- 定向验证覆盖自动沉淀、明确记住、旧候选处理、去重/重启、学习排除与遗忘、保存失败及既有工具契约；构建并执行 reload:plus，不修改官方引擎。

## 6. 技能与 Curator

管理入口为主导航「工具 → 技能」，资源中不再重复展示。技能发现、注册、加载和管理继续复用 Harness skills；SuperAgent 负责生产与策展自己的技能，不重建平行安装体系。标准节序 When to Use / Procedure / Pitfalls / Verification；只写可泛化规则及原因，不写任务流水账。

管理目标为直管制（2026-11-04，尚未全部实现）：记忆与自建技能提供直接 CRUD（查看、搜索、编辑、删除、最近变更、版本回滚），对话里说记住/纠正/遗忘即时生效，不设逐条人工确认；大范围删除先摆明影响范围。记忆本次落地边界见 §5.1；技能候选仍需批准，完整最近变更和版本回滚界面不作为本次已交付行为。

与已定[全链路架构](全链路架构.html)对齐时，“候选审核”保留为系统质量/来源审核，不默认逐条人工批准；当前技能发布需人批准是待对齐差距。记忆直写本轮已完成，不重复改造；后续学习入口若纳入已验收成果，仍须区分用户事实与执行经验，不把网页指令或 Worker 自述变成主人授权。

review 为轻型定额工作；Curator 为重型闲时工作。自建技能按使用记录：14 天不用标 stale、30 天归档，永不自动删除；合并前快照、可回滚与审计，LLM 合并默认关闭。第三方和用户固定技能不擅自归档/改写。阈值与使用水位持久化，不能因重启重算出重复归档。

## 7. Fallback 与秘密

目标与实现分开：图中的密钥池职责继续保留，当前旧 keyPools 已移除属于实现差距，不是本轮重新拍板删除目标。后续复用基础层凭据/供应商路由服务落实，不直接恢复旧字段；角色/工作/辅助模型的完整分工见[开发清单](全链路对齐开发清单.md)。

当前实现（2026-11-03）：凭据路由池已移除，旧配置读取时剔除；按显式模型、首选及备用列表顺序进行故障切换。聊天每条新消息从首选开始，消息内冻结模型队列，可依次尝试全部备用。Worker 在同一会话内保留显式模型优先；评估、验收及辅助请求使用完整备用队列。身份的模型页统一配置主模型顺序、辅助模型顺序及看图/压缩/总结/review 用途；未配置辅助模型或未勾选用途时跟随当前主模型。取消、政策或权限拒绝、不可恢复请求错误不切换；403 仅在适配器明确提供认证错误分类时允许切换。

跨供应商保留完整对话语义、工具结果与证据引用，重新解析推理参数，不能重放已完成工具或重复副作用；“原样带过去”不承诺不同供应商 wire format 一致。显式模型选择优先，ID 原值保存，配置选择/保存/重载/实际请求需一致。

RouterGo 管供应商池内部线路，本地 Fallback 管客户端目标失效后的替代目的地；不能用客户端无界重试放大网关重试。是否可切取决于配置与实际错误，政策拒绝不能当作可绕过错误。

保险库录入、句柄和系统代填由基础层/宿主服务承担；Agent 不见密码、Key、OTP 明文，代填绑定真实目标、返回脱敏。凭据持久化必须加密，但不要求用户输入保险库口令，也不设置手动或闲置锁定；运行期间由保险库服务管理解密状态。仅有环境变量引用不等于完成保险库目标。

## 8. 完整目标验收（不代表以下能力全部未实现）

- [ ] 五文件按序冻结；即时写入落盘，下一会话生效；规则收紧不受冻结延迟。
- [ ] FTS5 中文查询命中真实原文，长消息按 ID 全量续读，索引可重建，链不悬空。
- [ ] 双计数器跨重启去重，前台忙仍执行 review，/learn 三入口同流程。
- [ ] 辅助能力选择、保存、重载、请求一致；模型回退按 turn 有界且不重放工具。
- [ ] 策展只处理自建技能、归档可恢复、LLM 合并默认关；秘密无明文泄露。
