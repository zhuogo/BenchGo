# SuperAgent 记忆与技能

本文维护记忆权威、文档快照、原文账本与学习策展；角色模型见[模型与上下文](模型与上下文.md)，统一身份见[身份与形象](身份与形象.md)。

## 文档记忆、原文账本与学习

同一助手有两层记忆：Markdown 提炼正文保存身份、事实、决定和经验；账本保存原始事件与关系。宠物和 Router 不各建记忆。冻结快照管理解，实时执行门管许可。

| 固定文档顺序 | 职责 |
| --- | --- |
| SOUL.md | 性格、表达与底线 |
| IDENTITY.md | 姓名、形象与对外身份 |
| USER.md | 主人称呼、时区与偏好 |
| AGENTS.md | 工作约定、审批红线、渠道与保险库规则 |
| MEMORY.md | 决定、关系与长期结论，每日日志另作流水 |

TOOLS.md 保留兼容管理与用户原文，不作为固定第六项注入；真实工具能力由宿主注册表确定。身份名称以 IDENTITY.md 为准，config.name 仅在缺少 name 字段时回退。

会话按 sessionId 持久冻结文档与 hash，恢复复用快照；人格和记忆即时落盘，下一会话生效，明确遗忘可脱敏派生快照。文档目标为 add/patch/remove 精确修改；当前主要是完整 content 加 expectedHash、版本与 journal，不能说增量编辑协议已完成。

并发写入冲突先重读，不覆盖用户修改；多文件部分成功须显式记录。遗忘同步正文、索引与派生内容，已拒绝或遗忘内容不得被历史候选重新写回。留痕要求不能抵消明确删除要求。

项目规则按 .hermes.md → AGENTS.override.md → AGENTS.md → CLAUDE.md → .cursorrules first-match；同名规则沿适用目录链合并，深层更具体。复用官方上下文能力，在插件侧适配语义，不能同时叠加重复加载器。

Harness 是原生会话日志唯一写入者；SuperAgent 按 sessionId/eventSeq 导入可重建的原文索引。ledger.db 的中文 FTS5、分页与水位已有实现；链式引用连接 Trigger、Thread、Ticket、Run、Result、Attention 和 Delivery，完整业务关系投影仍需补齐。

读取按 ID 返回原文、来源、全长与 nextCursor，不重新总结；memory 的提炼检索与 ledger 的 FTS5 是两条路径，当前未完全统一。检索性能必须实测，参考项目时延不能当 BenchGo 承诺。

后台整理保留 /learn、明确自然语言请求和持久双计数器入口；现有默认阈值为每 10 个用户 prompt 或单回合第 10 次工具迭代。计数只触发整理调度，不表示执行中的工单已经完成，也不启动任务内容验收。目标为后台仅从已关工单的持久结果、原始指令和实际证据中提炼；尚在运行、等待或待交付的工单不作为已关工单学习。失败说明确认送达后以 failed 关单的记录也只能提炼实际失败经验，不得写成成功经验；失败与续跑边界统一见[自校验与交付](自校验与交付.md)。没有新闭单材料时记录水位并等待，不为凑计数读取 Router 的当前上下文。后台输出不递归触发学习。

主人当面明确交代记住、纠正、遗忘，由 Router 当场直接写入，不开工单；保存成功与失败须如实反馈。Worker 与子 Worker 不直接写长期记忆，值得沉淀的任务内容交后台整理流程处理。自动记忆须有可信用户来源、有效正文并符合学习规则，不另开专门工单或逐条审批。排除、关闭学习和遗忘保护继续有效，外部文本不能沉淀成主人授权。大语料按章蒸馏仍属目标。

后台整理不经过 Router 的模型回合，不将工单正文或整理过程回灌当前 Router 上下文，也不成为交付或关单前置条件；保存的稳定记忆仍按既有后续会话装配规则使用。整理结果保留来源与版本，可由用户事后纠正、遗忘或回滚；回滚不得恢复已明确遗忘的内容。

单次或整站持续许可由[动作授权服务](任务与执行.md#权限与对外审批)保存、校验与撤销，记忆、技能及 AGENTS.md 不能创建、扩展或恢复这类许可。整站许可和工单 Mandate 是叠加的执行门；记住用户习惯不能代替任一执行门，也不能把必须逐次审批的动作改为免审。

技能复用官方 skills，SuperAgent 只生产与策展自建内容。标准结构为 When to Use / Procedure / Pitfalls / Verification，只写泛化规则与原因，不写任务日志。管理统一在“工具 → 技能”，资源页不重复。

自建技能目标是系统质量、来源和去重审核后直接管理；当前仍有候选批准/拒绝，完整编辑、归档与回滚界面未齐。Curator 仅处理自建且未固定技能：14 天 stale、30 天归档，永不自动删除，合并前快照，LLM 合并默认关闭。

## 管理路径与兼容边界

记忆页展示已保存的时间线、来源、更新时间、编辑与遗忘；新增和编辑共用保存流程，保留未保存草稿提醒。旧 memoryCandidates / memoryCandidateAccept / memoryCandidateReject 仅作弃用兼容，新页面和正常学习不再使用逐条批准流程。

历史 pending/saving 记忆候选按相同来源、学习规则和去重要求处理；已拒绝或遗忘的不恢复。保存失败保留可重试记录并返回真实原因，不显示成功，也不要求用户用批准代替失败恢复。原文按编号失效时明确报错，不拿摘要冒充原文；首轮检索不依赖向量服务。

学习 review 为定额轻工作，Curator 为闲时重工作；两者均不是已取消的任务内容验收层，不对 Worker 结果打分或阻止交付。使用水位、学习阈值和策展状态持久化，重启不重复写回或归档；目录预览不计为实际技能使用。第三方技能与用户固定技能不被自动改写或归档。

## 实现与验收边界

记忆直写、可信来源与版本保护、计数学习、自建技能候选和策展已有实现；完整技能直管、编辑/归档/版本回滚界面、按章蒸馏、统一业务原文关系与检索仍未全部完成。文档增量 add/patch/remove 和统一档案备份迁移不能由现有整文保存推定实现。

待实施目标：Worker 长期记忆写入的完整工具面裁剪、后台只从已关工单取材、整理过程与 Router 上下文隔离，以及整理结果的完整纠正/回滚操作路径。当前学习处理器仍读取来源会话的用户消息，未按已关工单取材；已有计数学习不等于满足闭单来源与隔离约束。记忆纠正、遗忘及底层文档版本恢复已有实现，不能将完整整理结果回滚界面标为完成。任务目标不设置内容验收层，学习与策展能力独立保留。

验证明确记住/纠正/遗忘、学习关闭与排除、旧候选处理、并发冲突、重启去重、遗忘保护、保存失败与冻结快照。用真实数据量验证分页完整性和检索性能；技能固定保护、使用水位、归档与恢复分别核验。工具页目录与只读服务只在[统一技能管理](../04-模型与工具/统一技能管理.md)维护。

补验当面记忆不派工、Worker 与子 Worker 不能直写长期记忆、未关工单不会被当作已完成经验、计数触发不重读当前 Router 上下文；整理不阻塞交付，纠正与回滚可追溯，明确遗忘不被旧材料重新写回。
