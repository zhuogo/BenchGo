# 语音媒体管线

本文维护语音输入、朗读和实时通话共用的采集、降噪、ASR、TTS 与媒体生命周期。板块入口见[设计](设计.md)，通话交互与模型分工见[实时通话](实时通话.md)，模型与供应商规则见[模型与供应商](../04-模型与工具/模型与供应商.md)。通话交互层共用本文媒体管线，不改变普通转录和朗读路径。

## 职责与依赖

Voice 为现有会话增加语音输入、朗读回复与实时通话，实际工作仍进入原会话 Agent；普通增强通话可先由轻量模型沟通。语音不另建助手人格、工具执行器或审批体系。

- 源码位于 `plugins/voice/`，随唯一安装包 `benchgo-plugin` 交付，Cordis 入口为 `benchgo-plugin/voice-plugin`。
- 依赖基础层和官方连接、设置、凭据、模型服务；不硬依赖 Harness 聚合或 SuperAgent，独立启停。
- 复用官方输入框、消息流、模型选择、Agent 和人工审批。关闭 Voice 后，基础层保留媒体设置入口，并明确说明语音模块不可用。
- 桌面复用本机 Harness 鉴权；移动端复用 Link 已配对设备的工作台身份和现有直连或中继通道，不另部署语音中继。

## 用户路径

在“设置 → 媒体 → 语音”分别开启语音输入、朗读和通话，选择共享供应商及准确模型 ID，语音合成另填音色。三项能力默认关闭，不预填或猜测模型；共享供应商继续使用既有地址与凭据，不重复建立一套供应商连接。

媒体类型与语音方式在宽屏同排显示，窄屏换行；实时通话将交互模型、语音识别与语音合成分为子标签。用户选择模型与音色后，点击模型栏右侧“自动匹配”图标，检测当前用途的候选并将优选的具体接口类型与协议填入草稿；保存后直接使用该协议。“高级设置”只提供具体接口类型、协议、测试、独立连接和实时路由设置，不提供“自动”选项。刷新、手动填写、匹配、测试与取消使用有清晰交互边界的图标按钮和气泡提示；不可用时真正禁用。普通页面保持紧凑，高级区域展示实际候选结果、首输出耗时与失败原因，不展示固定“自动匹配”说明段落。

标签切换保留同一份未保存草稿，保存仅提交实际修改字段。协议与模型下拉复用共享选择器，在弹窗门户中按可用视口向上或向下展开并限高滚动，避免被内容裁切或底部保存栏遮挡。

| 功能 | 入口与行为 | 结束与恢复 |
| --- | --- | --- |
| 语音输入 | 输入工具栏麦克风开始/停止；增量转录进入可编辑草稿，不自动发送 | 草稿被用户编辑时不覆盖；结束转录后将保留文字插入原会话草稿 |
| 朗读回复 | 独立扬声器开关；只跟随当前会话新生成正文，按句合成、有序播放 | 按 turn/step 关联流式输出，最终消息只补尚未播出的后缀，不重读历史 |
| 实时通话 | 通话按钮启动；停说、最终识别完成后按会话能力进入原对话层或轻量交互模型 | 插话先清空播放并按接入模式处理生成；挂断释放采集、识别、合成、播放和租约，不据此停止已接受执行 |

浏览器需要 HTTPS 或 localhost 及麦克风授权。拒绝授权、模型不可用、断网和发送失败须说明实际状态并提供对应恢复入口。工具权限仍在原屏幕界面确认，语音不得自动批准。

实时通话提供轻量本地效果音：媒体与会话成功就绪后播放一次短上扬连接音，用户主动结束播放一次短下降结束音；启动失败或启动中取消不播放连接成功音。使用现有浏览器音频能力合成约 250ms 的短提示，不请求 TTS、加载远程音源或写入会话记录；采用低音量，结束音不延迟麦克风与租约释放，音频设备不可用时不阻碍挂断。重复点击、迟到启动和重试按通话代次去重；页面销毁与离线等被动清理不伪装主动结束。连接音期间不接纳语音起始，避免提示音进入判断或正式对话。已实现并通过通话生命周期与真实浏览器 Web Audio 验证，设备音量与听感须验收。

## 当前媒体运行流程（已实现）

```text
麦克风 → 浏览器回声消除 → RNNoise 降噪 / 语音概率 → AudioWorklet 重采样 / VAD → ASR
       → 最终转录 → 可编辑草稿 或 通话交互入口
原会话正式正文 / 增强通话表达 → 可朗读过滤 / 分句 → TTS → 有序 PCM 播放
用户插话 / 挂断 → 按通话模式取消对应媒体及生成，隔离迟到结果
```

应用级通话已将媒体生命周期与页面视图分离：应用内切页、失焦和最小化不主动挂断，也不改变媒体归属；普通转录与独立朗读仍随原页面清理。桌面后台调度需要更新后的桌面包，真实最小化通话仍待设备验收；完整行为和运行边界只在[应用级通话与收起](实时通话.md#应用级通话与收起)维护。

识别增量仅用于展示，不提前触发工具。发送给 Agent 的内容只有真实转录，不追加内部播放状态。播放 ACK 表示本地播放器消费了片段，不保证用户听到，也不向模型声称用户听到了哪些文字。

ASR 最终语段与用户整轮结束分离，续说等待及合并提交语义见[连续说话与轮次提交](实时通话.md#连续说话与轮次提交)；该窗口只延后尚未提交的通话文字，不改变已接受执行的真实状态。

增强通话插话只停止通话生成与播放，不自动停止原执行；直通与 SuperAgent 的插话沿原对话取消协议，待审批时不代替用户处理审批。所有模式挂断均释放媒体，不以结束通话取消原 Agent。停止工作须由相应执行机制确认，具体边界只在[实时通话](实时通话.md#插话挂断与执行生命周期)维护；SuperAgent 的后续业务处理见[任务与执行](../06-superagent/任务与执行.md)。

## 协议合同

协议以实际线格式划分，接口兼容时复用通用实现，只有不兼容部分才新增厂商适配。供应商在大语言模型接口上兼容 OpenAI，不证明其 ASR/TTS、SSE 或 WebSocket 也兼容。模型 ID、协议值、音色均为不透明标识，不以 `step`、`mimo` 等前缀推断厂商、不替换用户选择。

协议实现按 `plugins/voice/src/protocols/openai/`、`stepfun/` 和 `shared/` 分目录；共享目录只维护解析、错误和音频合同，注册入口统一分发。前后端共用 `plugins/voice/shared/protocol-catalog.mjs` 的接口类型和协议目录，不复制枚举或按厂商再复制一套兼容实现。原 ASR/TTS 入口保留必要调用门面，避免双份实现。

| 协议值 | 上游接口 | 数据与行为 |
| --- | --- | --- |
| `transcriptions-sse` | `POST <baseURL>/audio/transcriptions` | multipart WAV、model、response_format=json、stream=true；必须实际响应 SSE 增量 |
| `transcriptions` | 同上 | 分段 WAV 上传，返回 JSON text |
| `stepfun-sse` | `POST <baseURL>/audio/asr/sse` | JSON Base64 WAV、audio.input.transcription.model 与 format；将阶跃原生事件归一为现有增量与最终转录 |
| `openai-websocket` | 默认 `<baseURL>/realtime?intent=transcription` | 持续 PCM 输入、转录增量和最终文本，可自动检测或显式选择 |
| `speech` | `POST <baseURL>/audio/speech` | 通用 HTTP 音频；model、voice、input、speed、response_format=pcm，收到 PCM 即播放；不以分块读取证明边合成边传输 |
| `speech-stream` | 同上 | 在相同 PCM 请求中显式发送 stream=true，仅用于支持此扩展的供应商 |
| `stepfun-speech-sse` | 同上 | stream_format=sse；解码 speech.audio.delta 的 Base64 PCM，验证完成与错误事件 |
| `stepfun-speech-websocket` | `<baseURL>/realtime/audio?model=<原始模型 ID>` | 阶跃原生文本与音频事件；提交文本、增量接收 PCM，归一为相同播放合同 |

ASR 的 HTTP/SSE 路径首片约 0.9 秒，后续约每 1.5 秒上传 WAV 预览片段；停说后按下述规则决定最终识别。SSE 是上传后的流式文字输出，不等同持续音频输入。

阶跃的普通 `/audio/transcriptions` 可复用通用 HTTP 实现；其 `/audio/asr/sse` 的请求体不兼容 OpenAI multipart，需要独立适配。标准 `/audio/speech` 复用通用 TTS，SSE 音频事件与 WebSocket 合成在阶跃目录独立适配并归一到同一 PCM 媒体流。小米等实际兼容通用接口的供应商不因品牌单独复制代码。对照官方[ASR SSE](https://platform.stepfun.com/docs/zh/api-reference/audio/asr-sse)、[语音合成](https://platform.stepfun.com/docs/zh/api-reference/audio/create-audio)与[WebSocket 合成](https://platform.stepfun.com/docs/zh/api-reference/audio/ws-audio)，文档核对日期为 2026-11-11；文档兼容性不代替所选路由、模型与凭据的实测。

当前仍将 Agent 输出按句分段，每段独立合成播放。WebSocket 适配使用完整句模式，文本仅按协议每条最多 1000 字符的上限切分，全部提交后直接结束文本，不人为二分或额外强制刷新。支持协议内分段提交文本，不代表已将整轮模型输出持续写入同一长连接。

### 自动匹配与测试

自动匹配是用户主动点击的配置动作，不是持久协议值。新配置的接口类型、协议为空，界面提示待匹配；旧 `auto` 配置只作加载兼容，不能直接用于媒体请求，也不静默转为某个具体协议。匹配只选择接口类型与协议，不选择或改写模型、音色、凭据。已知官方地址或用户选择的接口类型可用于安排候选，自定义供应商名称、模型名前缀均不能据此推断厂商。用户也可直接手动选择具体协议并测试。

| 用途与接口类型 | 匹配范围与约束 |
| --- | --- |
| 通用 ASR | 通用 WebSocket、SSE、HTTP JSON；按实际用途筛选 |
| 阶跃官方地址或明确选择阶跃类型的 ASR | 已接入的阶跃 SSE 与兼容通用协议，不将未实现的阶跃原生 WebSocket 作为失败候选 |
| 实时通话 ASR | 只接受持续输入或增量转录，排除整段 HTTP JSON |
| 渠道等 HTTP 音频文件上传 | 排除 WebSocket，使用具体 HTTP/SSE 转录协议 |
| 通用 TTS | 标准 `speech` 与显式 `speech-stream` 扩展分别测试，不因品牌复制实现 |
| 阶跃 TTS | 原生 WebSocket、SSE 与通用 HTTP 音频分别验证，记录真实首音频与完成时刻 |

候选在资源约束内逐项检测，不能遇到第一个成功就结束。择优先满足用途；ASR 仍按持续输入、增量输出能力分档。TTS 当前逐句完整提交，所有流式输出协议同档，不能仅因 WebSocket 支持增量文本就优先；使用固定公开连续语句测试，在同等输出能力内先比较观测欠供风险，相近风险再比较累计 80ms PCM 的 `firstPlayableMs`、首输出与完成耗时。风险按 `ceil(max(0, observedPlaybackGapMs−40)/80)` 分档，供给倍率不足 0.95 再加一档；完整不足 80ms 的短音频以完成时刻计为可播。`observedPlaybackGapMs` 从首次累积 80ms 后模拟消费，后包到达时确认此前储备不足的时间，迟到完成事件不算欠供；`audioSupplyRatio` 为总 PCM 时长除以首末非空包到达间隔，单批音频无倍率。另记录非空 PCM 块间最大间隔 `maxAudioGapMs`，它本身不等于缺音。这只是本轮配置建议，不承诺任意网络与文本下最快或无欠载。WebSocket ASR 检测须完成会话设置、提交测试语音并收到最终转录，不能只凭握手成功确认可用。TTS 须校验真实音频、完成事件与媒体合同，并记录首输出及完成时间；分块读取或 SSE 包装本身不能证明模型内部边生成边输出。

检测使用内置短合成语音或固定短合成文本，不上传真实会话录音、不调用交互 LLM。每次结果列出尝试的协议、状态和可操作原因，测试取消、草稿变化或配置换代后隔离迟到结果。检测成功仅证明这次协议与媒体响应有效，不证明所有音色、语言、延迟、设备条件或任意模型均可用。

认证失败、限流、超时、连接失败与未检测到语音不能直接归为“不支持协议”；认证失败、限流和无有效语音停止当前轮检测，后续候选标记“未测试”。接口不存在或响应格式明确不匹配才记为不支持，其余失败保留为“暂时无法确认”。实时通话不能把完整 JSON 转录静默当作 SSE，也不能在通话中临时更换协议。

只有点击“自动匹配”或“测试当前协议”才发送探测请求；填写、加载、切换标签、功能开关、保存、重启服务和首次使用均不触发。匹配成功填入具体协议并标记未保存，失败保留原选择，测试只验证当前协议。影响请求的草稿变化、切换页面、保存或取消隔离迟到结果，不能覆盖用户后续编辑。匹配用途按当前页面区分语音转文本、朗读与实时通话，不由全局通话开关改变普通输入的要求。

运行只读取已保存的具体协议，不依赖探测缓存；未选择或旧 `auto` 返回明确配置提示，不能在首句前补做探测。通话固定使用启动时的明确协议，后续路由变更需重新开始。探测请求有取消、并发与超时限制，测量及错误不暴露凭据；测试结果只代表当次实际请求，不能把尚未测试的协议显示成不支持。

### 降噪与流式采集（已实现，真实设备待验收）

- 通话只接受持续音频 WebSocket 或实际返回增量的 SSE（`transcriptions-sse`、`stepfun-sse`），HTTP JSON 转录保留给语音输入；不把非流式响应静默当实时通话。供应商实时协议不可用时可显式选择 SSE，不猜测或改写模型标识。SSE 事件到达即发布文字，保留有界并行、顺序合并、取消与背压。
- 降噪复用成熟 RNNoise 的本地 WASM，在音频工作线程按 48 kHz / 10 ms 处理，再重采样到既有 24 kHz PCM；沿用浏览器回声消除。模型与处理资源随插件本地交付，不访问第三方 CDN，不增加云端语音服务。
- VAD 结合降噪后的音量与模型语音概率，采用起音/停音迟滞与前卷保留；不再只凭 RMS 判断语音。普通起音累计 100ms 有效语音，非播放保护且语音概率至少 0.9 时采用 0.001 RMS 能量底线，其余普通语音为 0.002，避免轻声短词在降噪后达不到固定能量门槛。允许总计最多 40ms、模型仍判为语音的低能量音节间隙保留计时，间隙不计入有效语音；真实静音、低概率噪声或过长间隙清零。停说判定保留 320ms；真实 RNNoise 的离线短“你好”、静音尾与底噪尾已有回归，实际麦克风与外放仍需用户验收。纯静音或无有效语音的尾包不得再次请求 ASR，不删“嗯、啊”等合法转录文字掩盖上游幻听。
- 播放中的插话使用独立保护门槛：语音概率至少 0.85、RMS 大于 0.009 且连续 320ms；未确认前不触发取消。保护期间保留 420ms 前卷以覆盖确认时间，不截掉起始音节；播放/尾音保护切换清除尚未确认的候选计时。此调整针对近麦呼吸、喝水等短促声音误触发，保留普通聆听的轻声门槛，不继续提高插话音量门槛；从原 0.6 / 200ms 门槛迁移及短脉冲、持续输入、前卷和生命周期回归已通过。它不是喝水分类器，较长且被模型误判为高置信人声的声音仍可能触发；很短的“嗯”“停”等也可能达不到确认窗，既有短“你好”录音不足以验证播放插话，真实连续讲话、近麦和外放体验须验收。
- HTTP/SSE 的采集窗口按实测准确率、请求频率和首字延迟调整，不以极短片段牺牲短词完整性；用户停说即提交有效尾段，不额外等固定窗口。已检测到语音的 WAV 文件不足 1 秒时，仅在文件尾立即补零采样至 1 秒以满足短文件识别窗口，原语音采样不改、不增加录音等待；此规则复用于 HTTP/SSE，不修改连续 WebSocket 音频，也不为纯静音另发请求。分别记录采集等待、供应商首字/最终文字、本地转发与首音延迟。
- HTTP/SSE 多片语段的分片文字只作即时预览；停说后用保留的完整降噪语段做一次最终 SSE 识别，替换预览，只有最终成功的文本才交给 Agent。单片直接复用，原生 WebSocket 不重复识别。完整音频最多保留 15 秒，停说即取消本语段未完成的预览请求，让最终识别优先；失败保留可恢复预览并说明失败，不把分片拼接冒充成功结果。这会增加最多一份语段音频上传，须以停说到最终文字的实际延迟与准确率共同验收。
- 降噪资源准备、初始化、错误和释放必须可观测；失败明确提示，不静默以未经降噪的输入继续通话。播放初始化最长 12 秒，麦克风权限、恢复和降噪初始化合计最长 20 秒；挂断立即取消等待，浏览器迟到的采集轨道和处理器单独释放，不影响后一次通话。静音、挂断及时清理对应处理器状态并隔离迟到帧；仅切换正在浏览的会话不重置活跃通话的媒体。

参考源码位于 `reference/pipecat/`（`dea65430bed0f3d1317a66d2edd200263ab8b67d`）与 `reference/livekit-agents/`（`8adbeedf35670fc9d87708e086ecc08438457b87`），只供研究，不参与产品依赖或构建。媒体层采用其音频预处理先于 VAD/STT、概率与音量联合判定、分阶段测量延迟的机制，不引入完整 Python 服务或房间服务；Pipecat 的模型交接机制另见[实时通话](实时通话.md#参考边界)。

本地降噪采用精确锁定的 `@jitsi/rnnoise-wasm@0.2.1` 同步包内 RNNoise 0.2 模型，构建时核验二进制摘要、分发独立工作线程与 WASM，并保留完整 Apache/BSD 声明，来源见 `plugins/voice/licenses/SOURCE.md`。浏览器保留 AEC，避免重复叠加强降噪与自动增益；输入处理中 RNNoise 概率必须存在，失效不退回旧音量判话。降噪不能保证滤除所有声音，尤其近似人声的纯谐波或旁人说话；真实设备、外放回声、口音与弱声仍须单独验收。

TTS 播放合同固定为 PCM16LE、24 kHz、单声道。响应声道或采样率元数据冲突时拒绝，不把 MP3/WAV 当原始 PCM。`tts.stream=false` 只对当前片段有界缓冲，不等待整轮回复。标准 `speech` 不发送 stream；解析为 `speech-stream` 才发送 stream=true，请求供应商边合成边返回音频，两者均不发送 sample_rate。协议检测不替换模型或音色，不支持时明确报错。

延迟须分别测量采集分片、上游首包、BenchGo 转发及本地起播，不能以 HTTP 分块数量判断模型边生成边输出，也不能只凭 `stream=true` 参数宣称已验证流式生成。2026-11-11 阶跃官方 `stepaudio-3-tts` 的原生 SSE 与 WebSocket 均已实测在终态前持续输出音频；这是该路由与配置的当次验证，不推广为所有供应商或模型的保证。`mimo-v2.5-asr` 的 SSE 文字增量正常；HTTP 分片采集等待依然存在，原生持续音频须单独验证 WebSocket 协议。

实时路由允许显式 `asr.realtime.url` 和非敏感 `query`，支持 `{model}` 占位符；切换供应商清理旧路由覆盖。API Key、token、用户名密码和授权字段不得进入 URL 或查询串。

## 实时传输与资源约束

已鉴权的 `asr.start` 发放一次性、10 秒有效 ticket，浏览器连接 `/api/voice/realtime`。Desktop 复用官方 `connection.openWebSocket`，Link 复用设备身份。代理须透传 WebSocket Upgrade，不新增公开端口或绕过鉴权。

- 上行二进制帧：epoch、utteranceId、sequence 三个 little-endian uint32，随后为 PCM16；控制消息为 attach/commit/clear。
- 返回 ready/ack/partial/final/error/closed；取消和 clear 隔离旧 epoch，迟到音频或文本不得进入新轮。
- AudioWorklet 持续采集与播放，重采样保留相位；浏览器 AEC 配合本地 RNNoise 降噪与语音概率 VAD，不重复叠加浏览器强降噪或自动增益。
- 当前上行队列最多 600ms / 30 帧；超过容量、帧龄或收到拒收 ACK 时结束识别，未提交预览保留为原会话可恢复草稿，不能丢帧后继续把残缺识别当最终成功。上游单段 commit/final 屏障仍按协议保留；下行有背压，不静默丢弃朗读正文。
- TTS 采用统一的三路有界预合成窗口（当前段与最多两个后续段），按原文顺序向同一 PCMPlayer 投递；首段不等合成结束。适配器只归一协议、参数、音频格式、取消与错误，不携带厂商专属起播水位，兼容接口复用实现。
- 公共播放器按实际 PCM 供给学习起播与恢复储备，80ms 仅为下限；连续稳定供给走快速路径，成批供给按已观察的批间隔、批音频量和欠载学习有界储备。冷启动不能预知后续断供，须用短观察窗口区分连续与批量供给；观察与攒音频同时进行，不串联固定睡眠。完整短段立即放行，恢复避免刚够少量音频就反复播空；不得按厂商名写水位，不保留旧固定 80–240ms 的第二套播放策略。实现参数：储备水位 80～1200ms，在同一合成段且当前队列少于 240ms、前次到包后的队列少于 1200ms 时，按至少 40ms 的已观测到包间隔 ×1.2 上调；连续消费 2 秒后估计及水位衰减 10%，下限仍为 80ms。冷启动在首次攒足 80ms 后最多观察 160ms；同路由下一轮按已学习水位给出 160～400ms 的有界观察。已呈现至少 80ms 的密集持续供给或已有 500ms PCM 且满足水位可提前起播，完整短段直接放行。缺音恢复在再次到音频且可用量至少 80ms 后，满足水位即恢复，否则最长额外观察 240ms；这些观察与积累重叠，不是每段叠加的固定睡眠。旧样本、未参与调节的供给和正常连续流均参与验证，不能以事后全量时序决定在线起播。
- 新轮次保留同一媒体路由已学习的供给估计，清空旧音频、轮次统计和待恢复状态；媒体路由或语速改变清空估计；检测报告变化不清空。未送出后续文本不是网络欠载：每段渲染结束与下一段渲染开始单独记录句间等待，音频流内未结束且队列耗尽记为句内缺音。整段已结束且不足储备也完整播放；不丢采样追赶，不逐包新建播放器。保留现有 2 秒投递背压与约 20ms 消费确认，取消及迟到通知按 epoch 隔离。
- 分句共用可朗读过滤：自然句界优先，软长度 60、硬长度 120；首段生成预算 250ms，至少 10 个可朗读字符并有安全分句或词边界；持续生成 1200ms 后允许至少 10 字的安全汉字切分。首段空闲 300ms、后续 650ms，4～9 字且无句界不因空闲直接切分；正常结束立即输出剩余。逗号、顿号不无条件拆成独立请求，数字和英文单词不可切坏；已有后句且合计不超过 60 字时合并；首句少于 8 个可朗读字符时，仅与同一任务内已经到达的下一段合并，合计不超过 60 字符；一次微任务立即释放独立短句，正文过滤完成后、TTS 请求发出前处理，不为候合并另等 180ms，也不重写已发请求。25ms 刷新仅在有待处理文字时运行。
- 缓冲针对实际供给，不保证任意 TTS 均可无欠载。区分供应商首包慢、批量断供与音频内原生停顿；现有时序指标不检测源 PCM 内的静音，不能仅凭缺音次数解释原生停顿；不通过统一添加 500/900ms 储备掩盖供给问题，不自动改协议、模型、音色或语速。先前真实时序回放保留在测试证据中，用于检查延迟与欠载的权衡，不再把固定路由水位当作通用解法。
- 单会话只有一个主动通话设备；租约 45 秒、心跳 15 秒、最长通话 30 分钟。进程重启不恢复旧音频或重放工具。

这些是实现参数，不是端到端延迟保证。网络、供应商排队、模型计算、蓝牙和设备音频链均影响实际体验。

## 低延迟调度与观测

目标为极低接话延迟，同时保留转录准确率、音频完整性与真实取消语义。参考用户在本次会话提供的 DraftGo 实时通话实现说明（2026-11-12，无源码版本），采纳单一路径、公共小缓冲、有界预合成与分阶段计时；不引入端到端 Realtime 模型代理，也不照搬厂商专属变速或预缓冲。

实施状态：分句、公共供给学习、句间观测与短句同批调度已接入源码。真实设备和供应商听感仍待验收。既有 ASR 完整语段校正保留，不能以预览拼接代替权威结果；原生连续音频 ASR 不重复识别。

采集应在最终结果附带最后有效人声与停说确认时间；通话续说预算从最后有效人声计算，与 VAD、ASR 并行消耗，细则只在[连续说话与轮次提交](实时通话.md#连续说话与轮次提交)维护。最终识别前不触发 Agent 或工具。新语音取消待提交计时，过期采集、文字、合成与播放通知不得污染新轮次。

统一在浏览器本地单调时钟观测（通话注入 `performance.now`，正式消息日期仍用墙钟）：`endpoint_ms`（最后有效人声到停说确认）、`transcript_ms`（到最终识别）、`submit_ms`（到发送给 Agent）、`first_token_ms`（到首段可见文本）、`first_audio_ms`（到首次收到 PCM）、`first_playback_ms`（提交到渲染线程报告起播）、`speech_to_playback_ms`（最后有效人声到起播）。合成段记录请求到首 PCM 的耗时，不能混作整轮锚点指标。播放记录起播采用水位（`first_buffer_ms`，受可用音频量限制）、当前目标水位（`buffer_ms`）和实际队列时长（`queued_ms`）、句内欠载次数及已恢复缺音等待，以及逐段首次渲染、渲染完成和句间空档，不能把正常段尾等待或源音频内静音混算为句内欠载。TTS 以 `tts.queued/start/first_audio/audio/end` 记录文本入队、请求开始、首包、累计音频量、最大到包间隔和合成结束；`request_wait_ms` 表示排队到请求，`first_byte_ms` 表示请求到首 PCM，`elapsed_ms/audio_ms/chunks` 表示请求累计耗时、音频时长与包数，`max_audio_gap_ms` 扣除本地容量等待，`backpressure_ms` 单独累计。音频进度最多每 100ms 一条，无轮询定时器，首包和结束立即报告。阈值与队列时长明确区分。每段首次实际渲染及完成分别报告 `segment_started/segment_ended`，用同一渲染时钟 `render_time_ms` 计算前段结束到后段开始的 `previous_gap_ms`，累计为 `playback.segment_gap_ms`；段内原生静音不算句间空档。首次实际渲染报告 `segment_started`，连续播放中也能区分前置通知与本轮首段，不能只等整条队列由空闲变播放。控制器 `state.metrics` 暴露当前轮与最多 16 条近期轮次，逐轮最多 32 条合成段耗时，字段为不可用时保留 null；样本不包含录音、转录、凭据；中断与新轮次隔离旧指标。浏览器起播通知不是物理声卡出声时间，缺失时间不填成零或推测成功。

## 配置、凭据与取消

决策配置与后续研讨边界见[决策配置与说话对象判断](实时通话.md#决策配置与说话对象判断)。当前通话恢复直接对话，沿既有插话逻辑，最终识别不调用决策服务。VAD 只判断人声；环境人声仍可能上传 ASR。

配置默认保存于 `~/.benchgo/voice/config.json`；可由模块 `dataDir` 覆盖。目标不存在时才迁移旧 `$DSH_HOME/voice/`。文件和目录采用受限权限，API Key 只在服务端使用，前端获得配置标记与掩码；留空保留，明确清除才删除。

共享供应商解析与可用性展示使用同一请求路由。修改一项只提交变更字段，不丢失其它配置；选择、保存、重载和实际请求必须一致。可用性由模块、开关、模型、协议、路由和凭据共同决定，不以被选中代表可用。

当前代码在挂断、断网、页面销毁和模块卸载时清理媒体与交互生成，不自动取消原执行；活跃通话不随应用内会话切换或页面组件卸载清理。ASR/TTS 配置变化按影响范围清理，未变化的保存不打断媒体。取消不撤销已经完成的工具操作，也不自动叫停已独立领取的工单。已接受执行的保留、停止与重连处理，以[通话生命周期](实时通话.md#插话挂断与执行生命周期)为准。

转录冲突或发送失败保留完整文本；结束语音后自动插入原会话草稿，折叠当前选区以保留已有输入，不自动发送。识别文字不再附带独立的复制、转入草稿、丢弃或重试发送操作框。草稿暂不可编辑时保留文本并显示简短错误，恢复编辑或再次启动前重试写入；未写入草稿的恢复文本只在页面内存中保存。静音不丢弃已识别的待发文字，不将恢复内容转入其它会话。

## 内容与界面

朗读过滤消费正式可见正文，去掉 Markdown 标记，只读可表达的内容；不朗读代码块、HTML code/pre、反引号标记的代码或命令、内部工具参数和推理。代码、表格可每轮给一次简短略过提示，不声称尚未展示的内容已发到聊天。链接有标题时只读标题，不读 URL、协议和查询串；没有标题时用“这个链接”代称。模型提示词同时约束不生成供朗读的裸代码或命令，解析器不根据普通自然语言猜测任意程序语法。

Windows 本地路径按真实盘符、目录与文件转换成口语，例如 `C:\Users\Lin\报告.md` 表达为“C 盘的 Users 文件夹下，Lin 文件夹下，报告点 md”；斜杠不逐字朗读，文件行号可表达为“第几行”。反引号内的明确 Windows 路径属于文件位置而非代码，仍按路径表达；带标题的文件链接优先读标题，标题本身是路径时才转换路径。转换只影响语音，不改界面原始路径或链接，不推断缺失位置。

解析跨流式分片保留未完成的代码、链接目标和路径，空闲刷新也不能提前泄露或截断这些内容；有界保留，过长未闭合内容丢弃而非旁路朗读。正文首句仍即时分句，不等待整篇回复。该过滤不等同完备的敏感信息防护。

入口、开关、状态、错误与恢复动作遵循[统一视觉规范](../02-工作台与Agent/前端视觉规范.md)。会话未开始、连接中、错误和正常收发均有明确呈现；挂断与静音可触达，禁用状态必须说明原因。

## 实现与验收边界

当前代码提供上述通用协议、阶跃 ASR SSE 与 TTS SSE/WebSocket 适配、主动匹配、媒体流水线、取消、租约、会话事件桥接和恢复入口；不修改官方引擎，也不把独立 ASR + Agent + TTS 架构称作原生端到端语音模型。本地降噪、概率 VAD、首片提速、完整语段最终校正、流式通话准入和失败草稿恢复已实现；真实浏览器合成音与 RouterGo SSE 已验证，不能据此推定真实麦克风和所有设备条件已验收。主动匹配的协议与状态测试也不代替真实供应商逐项验收。

真实供应商完整音频会话、真实手机麦克风、外放回声、蓝牙、移动后台和弱网长通话仍需分别验收。历史握手或专用协议探测不证明当前标准协议可用。

交付需验证配置往返与实际请求一致、草稿不被覆盖、朗读不重复、插话隔离迟到结果、审批不被跳过、设备租约正确，以及空/加载/错误/有数据四态实际渲染。源码定位：`plugins/voice/src/{plugin,config,availability,web,realtime,protocol-detection}.mjs`、`src/protocols/`、`shared/protocol-catalog.mjs` 与 `plugins/voice/client/`。
