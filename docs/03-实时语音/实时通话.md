# 实时通话交互与执行

本文维护实时通话的会话分流、模型分工和交接机制。板块入口见[设计](设计.md)，可视化见[架构](架构.html)，音频协议与资源约束只在[媒体管线](媒体管线.md)维护。会话分流、轻量交互、交接桥与界面已接入源码；下文分别说明实现和仍待完善的边界，真实设备与供应商验收不由源码存在推定完成。

## 目标与职责

实时通话需要快速、自然地接话，也需要保留强模型的推理和工作能力。语音流式传输不能消除执行模型生成首句之前的长思考，提示词也不能保证所有模型提前输出正文，因此将普通会话的通话表达与实际执行分工。

- Voice 负责媒体、通话交互和交接协调，不引入工单、Worker 调度器、独立工具执行器或审批体系。
- 普通会话的轻量模型负责寒暄、澄清需求、判断何时交接、表达真实进度与结果；只获得受限的交接能力，工作工具仍归原执行 Agent。
- 原 Agent 保留当前会话、工作区、执行模型、思考设置、工具与审批。通话设置不替换或降低执行模型，不要求其支持关闭思考。
- SuperAgent 主聊、旁聊已有 Router 对话层，直接复用原有表达与执行机制；Voice 不在其外面再叠轻量模型。
- 普通转录只写草稿，普通朗读只读既有回复，两者均不进入本文的新交互层。

## 会话接入

通话开始前由宿主解析当前 session 的可信归属与能力，绑定本次通话和原会话；不按标题、模型 ID、页面位置或模型声称的身份猜测。仅安装或启用 SuperAgent 不代表所有会话属于 SuperAgent。

| 会话与配置 | 通话路径 |
| --- | --- |
| SuperAgent 主聊、旁聊，确认具备原有 Router 对话层 | 最终转录 → 原对话层 → 原有执行与交付 → TTS；不使用 Voice 交互模型配置 |
| 普通 Harness 工作区会话，已配置可用交互模型与执行适配 | 最终转录 → Voice 交互模型 → 按需交接原 Agent → 事件回传 → 交互模型表达 → TTS |
| 普通会话未配置交互模型 | 保留现有直通通话，配置明确显示未启用交互增强，可能等待原模型思考 |
| 归属无法确认、执行子会话或适配能力不足 | 明确展示实际接入能力；不把 SuperAgent Worker / 子 Worker 当作 Router，不自动套用未经核验的增强路径 |

会话能力描述至少区分可信归属、是否已有对话层、是否可交接执行和是否有回传；这是语义合同，不预设新的公开 API 名称。SuperAgent 提供自身身份适配，Voice 消费通用描述；模块未启用时不请求其专属服务。普通会话不因这项能力依赖 Harness 聚合的 commander。

通话固定绑定发起它的原会话；浏览另一个会话不迁移语音输入、执行关联或播放来源，也不结束当前通话。应用级持续通话的实现与运行边界见[应用级通话与收起](#应用级通话与收起)。通话期间归属或必需模块发生变化须结束当前接入并说明原因，不能悄悄从直通切为双模型，或将旧请求送入新会话。

当前在开始通话时读取可信身份并固定接入模式；每次增强转录提交前及通话心跳（约 15 秒）重新核对角色与适配能力，变化或不可用即结束当前接入并明确报错，不静默切模型、不取消原工作。交互路由变化、媒体关闭和模块卸载也会清理相应通话；角色复核依赖上述边界，不是持续实时监听。

成功绑定后以同一可忽略事件保存 `call-start`，按原 session 与 callId 幂等，不伪造用户发言、不触发模型。独立 `benchgoVoice` 官方会话投影仅公开是否使用过语音及活动时间，并兼容旧语音记录；自有侧栏据此保留纯语音历史。BenchGo 的“新聊天”入口显式创建新 session，不复用官方仍视为空白的语音会话；官方快捷键和其他原生入口的空白复用规则不在此改写。

## 对话与交接

轻量模型通过当前用户原话、必要近期对话和已收到的执行事实决定如何回应；不设额外常驻分类模型，不让所有话语都跑执行 Agent。

| 用户表达 | 行为 |
| --- | --- |
| “你好”“谢谢” | 轻量模型直接自然回应，不启动执行 |
| “帮我查今天的热点” | 发起一次明确交接，简短接话；查询结果回来后继续表达 |
| “优化这个前端页面”，但无法确定页面或目标 | 结合当前工作区上下文判断，确有歧义时只问必要问题，不自行扩展任务 |
| “现在怎么样了？” | 从已有执行事实回答，无更新就如实说明，不重新派发同一任务 |
| “改成深色”“先别做了” | 关联当前执行发修订或停止请求；区分请求已接收和执行已改变，确认已停止须核实执行退出 |

语音层先整理自包含任务，执行层据此工作，最近聊天仅作有界补充。原始转录仍在原会话保留并绑定来源和请求标识，任务整理不能扩大用户授权、遗漏明确限制或把模型建议伪装成真人批准；不再要求每次将整段近期原文复制给执行层。实现与验收边界统一见下文[任务整理与有界委派](#任务整理与有界委派)。工具参数、日志与网页内容作为数据处理，不能升级为新的用户指令。

同一次请求交接一次，以关联标识和服务端接收记录防止网络重试重复启动。桥接至少区分已接受、明确拒绝和结果未知；未知时查询原接收记录，不盲目重发。单会话沿用原 Agent 的并发限制，忙碌时不得静默打断或另建执行；修订与停止由适配器明确支持，缺少能力时说明限制，不能伪装成已送达。

接话与执行可以重叠：“我来查一下”表达接下来要做的事；“已经开始查询”必须有真实执行开始事实，请求已接收不等于已经运行。已经接话后不再重复“已开始、稍后告诉你”，不把执行模型的每段计划、每个工具步骤逐条播报。

### 任务整理与有界委派

**已实现于源码**：普通会话 `enhanced` 双层通话的 `delegate` 与 `revise_execution` 均要求 `task` 正文，可选 `contextSourceSeqs` 从宿主候选中选择必要原文证据。语音层先梳理任务；桥校验真实来源、预算与接收回执，按来源事件去重，不再自动转发整段近期聊天。SuperAgent `native` 复用原对话层，`direct` 直接发往原会话，不叠加这里的整理工具。真实供应商的整理质量仍需通话验收。

语音层负责理解和整理，执行层负责落实；生成的 task 直接作为执行层正式消息正文，工作层聊天记录显示这段任务文本。最近最多 **5 条**必要发言单独作为补充上下文注入。此处一条指一条用户或助手发言，不是五轮；原始口述保留在语音记录，通过来源和请求标识关联，不再作为正式消息重复提交。五条是补充上限，不要求凑满，也不缩短语音层用来理解需求的自身上下文。

任务正文应让执行层不翻语音聊天也能开始工作：说清做什么、对哪个对象做、必要已知事实、必须遵守的限制和期望交付；只写与本任务有关的信息，不机械填充空字段或转发闲聊。“第二个方案”“那个插件”“刚才说的页面”等指代由语音层根据其已有上下文消解；文件路径、模型 ID、插件名、数字、否定和排除要求按原意保留。若目标、对象或关键约束确实无法确定，先问一个必要问题；普通实施细节交给执行层判断，不把“完整”变成每次都要用户确认长清单。

不能保证模型永远整理无误，也不能以固定长度或字段齐全证明语义完整。语音提示词须明确保留约束、纠正和最终选择；工具开放明确的任务文本和修订文本，宿主负责绑定真实 session、requestId、当前原话和原始记录来源，校验形状、预算与幂等。宿主不按关键词重新解释任务，不引入第二个常驻模型。模型整理与原始授权矛盾时不能据摘要扩大执行，执行层仍沿原权限与审批；需要精确原文时按来源回查，不默认灌入整段记录。

补充从当前句之前最近 5 条双方发言中选取，限于任务正文仍需要的原文细节；没有必要则为空。先确定五条窗口再排除执行层已有或已接收来源，不用更早的聊天补足。聊天原文只是证据，不成为额外任务或授权。按原会话事件标识去重，原文顺序及说话者不变；不因当前句相同而误删用户再次提出的新任务。补充预算为合计 4000 字符，实际发送的任务正文与补充统一按合计 16000 字符预算控制，未发送的原始口述不计入；这些都是字符预算，不等于 token 数。不能为满足预算截断关键限制：由语音层重新组织任务，精确长原稿保留来源引用，仍无法无损表达时明确说明并澄清，不静默裁剪或扩大窗口。

桥通过官方 `prompt` 直接提交 task 纯文本，修订沿官方 `steer` 通道提交任务变化；不附加 JSON 包装或固定说明前缀，也不把任务再塞进上下文。只有选择了必要聊天证据时才调用官方 `inject`，内容仅为带说话者与来源的补充聊天。宿主在原 session 的交接记录关联原话来源、正式任务消息及请求；原始口述仍供语音层恢复和回查，不用任务文本替换语音记录。删除旧的任务注入发送路径；已有注入记录仍按非用户内容过滤，停止时兼容清理旧队列。

首次委派提交当前完整任务；同一执行的后续修订仅提交新增或替换的要求并关联原执行，不重发整份任务或相同五条聊天。任务正文可以包含来自较早发言的仍有效约束，不受补充窗口限制；这些已整理的约束不再用历史全文反复证明。只有真实接受回执才能推进已交接来源标记，失败或送达未知不能提前标为已交付；未知沿既有接收记录核对后处理，不盲目重发。复用原 session 记录和 handoff 关联，不新增任务数据库或长期摘要系统。

验收须同时观察任务质量与实际执行请求大小：覆盖多轮讨论后明确委派、无称呼的指代、连续补充和纠正、跨越五条窗口仍有效的限制、同一任务修订、多个独立任务，以及失败/未知/重试。比较执行模型实际收到的正文与来源，确认约束未丢、任务不扩大、补充最多五条且预算受控、已交接原文不重复、新任务不误去重。自动化验证覆盖工具契约、真实请求来源、预算与幂等；真实模型能否充分整理语义仍须实际通话验证。上下文仍会随真正的新任务、工具结果和执行回复增长，过长沿官方压缩处理；目标是去除冗余输入，不承诺执行历史永不增长。

## 执行事件与表达

执行桥订阅原会话事件并归一为通话需要的事实；事件由宿主推送，不让轻量模型轮询或持续评判思考过程。下表是语义分类，不是新增工单状态，也不要求另建任务数据库。

| 事件事实 | 通话处理 |
| --- | --- |
| 请求已接受、正在运行、工具或阶段变化 | 更新有界进度上下文，默认不唤起模型讲话；用户追问时可读 |
| 正式可表达内容或阶段成果 | 按关联标识送入交互模型，流式口语表达；合并零碎内容，不必等整个执行结束。中间计划默认作静默进度，不把任意 text-delta 当作成果 |
| 需要用户澄清或审批 | 提出真实问题；审批仍使用原界面，不将语音确认转为批准 |
| 完成、失败、明确拒绝 | 主动说明实际结论、必要结果或下一步，不根据模型计划推断成功 |
| 取消、修订回执 | 更新当前请求事实；旧版本成果不混入新请求，不宣称已撤回已经生效的操作 |

事件至少带原 session、通话代次、请求及执行关联、顺序与来源；迟到、重复、取消旧版本和重连补发按关联去重。只有可验证的正文、工具生命周期和终态才作为结果依据，内部思考不直接朗读，也不作为完成证据。

当前执行桥以原 session 事件和持久关联记录核对接收、运行、审批/提问及终态；普通进度进入上下文，完成、失败、取消和需用户处理的事件触发表达。同一终态不重复播报。上表的“阶段成果”仍是目标：当前不将任意执行正文增量作为可表达成果，也未建立执行结束前的独立阶段成果发布接缝。

普通会话增强模式下，交互模型是唯一通话发言者：执行 Agent 的原文和工具仍可在界面查看，但不同时直送自动朗读，避免两套语音抢播。SuperAgent 路径沿用原对话层，普通朗读功能在通话结束后按原用户开关恢复，不重播通话期间的历史。

**主动消息与输入判断分离**：语音通话不仅响应最近一句输入，也接收所属会话里新产生、真实用户可见的助手正式消息与发布事件。工单完成只是其中一种，失败、澄清、审批提醒及其他正式主动消息沿同一通道；不按任务类型硬编码，不另建通知系统或轮询。决策 只筛选环境输入，不过滤已接受工作的主动输出。原消息始终保留；麦克风静音不等于关闭播放，挂断后停止语音投递。

用户正在说话、最终识别或续说等待时，新正式消息进入有界队列，输入轮次交接后按原顺序投递，不因 `blocked` 直接丢弃。队列最多 32 条、32000 字，超限明确提示未全部朗读，原消息仍保留在所属对话。重复发布按请求或渠道镜像标识去重；已被用户插话打断的当前正文不自动重播，后来到达的其他正式消息仍可排队。普通进度、工具日志、内部推理不直接朗读；增强通话仍由交互模型表达执行事实，不同时播放执行 Agent 原文。上述接线已实现，覆盖正式回复、公开提醒、渠道交付、模型后备续接，以及续说、静音、挂断和跨页回归。

SuperAgent 的通话幕布与历史沿其既有公开消息投影读取，涵盖正式回复、已公开的提醒和渠道出站镜像；不把内部结果草稿当作助手发言。历史由可信会话角色解析到原 thread，沿现有 `history` 服务分页，拒绝线程已换会话或服务不可用时回落到私有事件；不复制工单业务或维护第二份历史。

转述须保留成功/失败、未完成范围、需要用户处理的事项以及关键数字、文件或链接；需要逐字内容时按原稿表达或引导查看原文，不编造、润色为成功。转述失败保留执行结果，允许重试表达或查看原文，不重新执行。

交互模型的认证、额度、限流、服务异常、连接中断、超时、回复截断与拒绝生成分别显示明确原因，不统一掩盖为“未完整回复”。错误事件只保留白名单错误分类、有效 HTTP 状态、经校验的供应商请求 ID 和准确路由，不公开上游原始响应、提示正文或凭据。服务异常后允许同一通话继续下一句，不自动重试已交接执行；本地取消仍按通话代次隔离。

## 内置沟通提示词与听觉表达

**精简沟通提示**：正文直接从理解需求、自然回应和完成工作开始，不增加“你是……”身份开场。只保留交流、行动、事实与权限三组规则，不主动解释内部角色或模型分工。完整任务整理、早期有效约束、精确名称与否定限制仍须保留，执行状态以真实回执为准。候选条数、字符预算、参数、工具调用细节由现有工具定义与宿主校验承载，不在系统正文重复。实际模型口吻和工具选择仍需真实通话验收。

模型可见的任务工具说明也使用“当前任务、当前会话”的中性措辞，不再注入分层角色。每轮宿主状态附带准确的 `currentModel: { providerId, model }`，与本轮实际请求使用同一路由；询问模型时按该配置标识回答，不从工具差异推断底层模型或内部架构。通话恢复时，过去最多 40 条、12000 字符的公开对话以标明来源的历史参考资料提供，不把旧助手发言重标为当前所选模型的 `assistant` 自述；历史中有效的用户要求与事实仍可用于理解任务，原始界面记录不删改。当前通话新产生的双方发言继续按正常角色延续。系统提示每次回复从同一权威 Markdown 读取一次，本轮工具循环复用；更新不依赖模块首次导入时的提示词缓存。

普通会话轻量交互模型使用 `plugins/voice/prompts/conversation.md` 作为唯一提示词正文，服务端通过 `src/conversation-prompt.mjs` 的 `readVoiceConversationPrompt()` 读取。文件随 Voice 发布；缺失或空白明确报错，不让客户端传入系统提示词。`src/conversations.mjs` 将其装入所选供应商与模型的流式请求，并只开放交接、修订、停止及语音设置工具。SuperAgent 的主聊、旁聊复用其原有对话提示词，普通转录和朗读不调用这套交互模型。

表达参考 SuperAgent 的[Router 对话准则](../06-superagent/Router对话准则.md)：温暖、有判断、尊重用户、少占注意力，以认真理解和真实结果体现朋友般的交流感；不复制其身份、文档链、记忆、工单或权限，不表演亲密或虚构人类经历。默认一到两句直接回应，不固定开场、等待话术或结尾追问；长解释先讲关键结论，按用户需要展开，失败与限制仍必须保留。

| --- | --- |
| Markdown 表格 | 按行保留可理解的文字与数字，去掉竖线和对齐分隔行；继续执行秘密、链接和代码过滤，不插入“表格内容略过”等播报 |
| 其他 Markdown 标记、代码、命令、结构化工具参数 | 不读格式或载荷，必要时简短说用途；精确内容保留界面，实际可见后才说明已提供 |
| 带标题的链接 | 只说真实标题，不读 URL 或查询串；无标题时说“这个链接”，不编造标题 |
| Windows 文件路径 | 按真实盘符、目录与文件说位置，如“D 盘项目文件夹里的说明文件”；必要时保留扩展名区分，完整路径仍在界面 |
| 中间计划、普通进度、原始推理 | 不逐条播报；普通进度静默供追问，推理不进入语音 |

模型提示词与进入 TTS 前的流式文本处理共同保证朗读规范；不能只靠模型自行遵守。流式链接和路径须识别跨片段内容，不将半个协议、盘符或代码标记提前读出；口语转换不能改写原会话的链接、路径与执行原文。这里规定通话口语目标，共用媒体过滤的实现与验收仍在[媒体管线](媒体管线.md)维护。

## 自然语言语音设置

普通会话增强通话通过已注册工具读取和调整语音设置，不把设置要求委派成开发工作。`get_voice_settings` 返回实际语速与音色，`set_voice_speed` 按服务端校验修改语速；“调到一点五倍”对应 1.5，“说快一点 / 慢一点”先读取现值再小幅增减 0.1。当前范围为 0.25–4 倍、精度 0.01，越界明确说明，不静默改成另一个目标。仅保存语速字段，保留 ASR、TTS 模型、音色、凭据与交互模型等其他配置。

只有设置工具成功并回传实际值后，交互模型才确认改变；按真实回执区分已保存、当前生效或下次生效。失败保留原值、说明失败；“工作快一点”不当成语速指令。保存成功后服务端推送配置，客户端更新后续 TTS 请求；不改变采集和执行模型，不承诺已经播放的音频变速。该独立工具路径不依赖 SuperAgent。SuperAgent 通话沿用其统一设置工具和 Voice 设置适配器的 `tts.speed` 配置，不额外加载上述轻量工具；真实模型是否正确选择并调用工具仍须实测。

## 上下文与界面

### 应用级通话与收起

已实现应用级通话控制与呈现：插件级 `controller.mjs` 通过官方 `sessions.retain` 保留原会话 scope、事件订阅与发送能力，结束、启动失败或模块卸载时释放；页面只订阅和操作同一份状态。`call-presentation.mjs` 维护展开、收起和原会话导航，`call-host.jsx` 通过 `shell.overlay` 统一挂载通话界面；不靠隐藏挂载整个聊天页维持连接，不增加安装包、常驻模型或系统悬浮窗。

- 应用内切换会话、任务、设置或路由，以及窗口缩放、失焦和最小化，不主动结束实时通话。原会话视图离开时自动收起；采集、识别、交互、执行事件与播放仍使用原 session 和 callId。普通语音转文本与独立朗读保持原页面边界。
- 保留现有圆球与幕布大视图，收起后恢复当前页面的工作层记录，由 `shell.overlay` 呈现一个全局胶囊，不再将语音幕布自动嵌入并遮盖执行正文。胶囊显示所属会话、真实通话状态及麦克风状态，并提供展开、文字显隐、静音、挂断；没有通话时不占位，不允许把仍在采集的通话完全隐藏。完整语音记录仍从原幕布查看，不建立第二份通话状态。
- 收起时胶囊上方默认显示最近 3 条用户／助手发言，直接投影同一控制器的对话和临时识别行，包含 ASR 增量、续说及助手流式回复；不额外请求模型、轮询或复制历史。稳定转录标识保持临时行到正式记录的原位交接。新条目柔和进入并将旧条目向上推移，最顶部退出渐隐；同条流式追加不反复播放整行入场，减少动效时关闭非必要动画。
- 浮动文字采用无气泡的纯文本，用户靠右、助手靠左，发言之间以浅分割线区分。收起字幕采用 14px 字号；整个字幕容器共用随主题变化的磨砂底，背景以主题底色与透明各 50% 混合，柔化后方页面。透明度与磨砂只作用于背景，不降低文字清晰度，保留柔和边缘渐隐与有限高度。长发言截断预览，完整内容仍在幕布；随胶囊拖动且受视口与安全区约束，不覆盖一整页或阻断工作层操作。文字隐藏按钮只改变这层预览，同次通话内展开、收起和切页保留选择；隐藏时新发言也不弹出，恢复后显示最新 3 条。新通话默认显示，空记录不占位；静音、播报和通话生命周期独立于文字显隐。
- 桌面胶囊默认靠右下角，避开输入和通知；窄屏抬到输入区与安全区上方，限制宽度，保持触控可达。复用现有圆球、主题、Tooltip、按钮与状态色，低对比边界和轻阴影。圆球与标题区域兼作拖动区，短按展开，位移达到 6px 才拖动；静音、挂断和审批按钮不启动拖动，拖动结束不误触展开。支持鼠标、触摸及键盘方向键，Home 恢复默认位置；位置仅在当前窗口内保留，切页、展开后收起仍保持，缩放后约束在可见安全区域，不另增面板或配置项。
- 同一客户端最多一路实时通话。在其他会话点击通话入口先展示当前通话及归属；更换目标必须明确结束当前通话后再开始，不能悄悄替换。待审批时显示“处理确认”，返回原会话的真实审批区，收起或挂断不批准、不取消已接受执行。
- 收起只改变视图；静音只关闭麦克风输入，已在进行的回复仍可播放；挂断释放媒体与租约。连接中可取消，错误状态保留恢复或关闭入口；重试不自动重发未知送达的任务。语音记录按原会话保存，迟到结果不能流入正在浏览的其他会话。
- 页面刷新或销毁（`pagehide`）、离线和模块卸载仍结束媒体；缩小、最小化和失焦不主动挂断。Desktop 的关闭按钮沿官方行为隐藏到后台，页面仍存活，通话继续；托盘“退出”等真正退出销毁页面并结束通话。系统睡眠、手机锁屏或浏览器强制冻结不承诺持续运行；恢复后必须按真实连接状态呈现，不能假装仍在聆听。

桌面后台调度由 `scripts/desktop/prepare-background.mjs` 在现有打包链中注入，仅为主工作台窗口关闭 `backgroundThrottling`，其余窗口和安全选项保持原行为，不修改官方子模块。此策略已进入源码与产物校验，但必须重新打包并重启桌面应用才能生效；`npm run reload:plus` 仅刷新插件产物，不能更新已运行旧包的主进程。网页切页支持不等于旧安装包已具备持续后台运行能力。

实现验收覆盖切页时连续收发、启动中切页、返回原会话、其他会话入口、静音/挂断、审批跳转、断线与迟到结果、会话资源释放，以及胶囊空/连接中/错误/通话四态的宽窄明暗渲染。控制器定向测试、浏览器渲染和桌面编译产物校验分别验证其负责边界；真实安装包最小化后的麦克风、音频播放和长通话仍待设备验收，不能用页面隐藏事件或编译测试代替。

### 通话内容与记录

界面按来源区分原 Agent 的执行记录和用户实际听到的通话发言。交互模型寒暄、交接回应和口语结果只在语音记录显示，执行聊天保留正式交接后的用户任务与执行回复；不以口语摘要覆盖执行原稿。数据仍保存于原 session，不创建一份隐藏的平行工作会话。原生语音记录只投影来源为真实用户的正式消息、助手正文与正式发布，排除模型专用上下文、宿主注入及压缩替换副本；文件和图片保留显示名称。

交互上下文由当前原话、必要近期通话、活跃请求、最新进度和待表达结果组成，这是语音层自身理解用的上下文，与发送到执行层的任务及最多五条补充不同，不能整体转发。进度合并覆盖为有界摘要，保留原事件指针；完整工具输出、文件及执行历史按需读取。使用已有会话记录及可恢复插件记录保存关联和表达事实，不复制原 Agent 的完整历史或思考链，不新增长期记忆系统；委派的具体预算和去重仅在[任务整理与有界委派](#任务整理与有界委派)维护。

增强通话将用户原话、交互回复、交接和执行关联写入原 session 的 `plugin:benchgo-plugin/voice-conversation` 可忽略事件，复用官方持久化与分页。语音专用发言在执行聊天中隐藏，语音记录仍完整投影用户与交互模型对话。通话成功绑定原 session 后，持久化一次 `call-start` 并在执行聊天显示简洁的开始时间记录。仅开启通话不生成标题；增强通话完成首个有效回复后，从真实用户语音中异步生成有界摘要，使用已选交互模型的精确路由，将结果写入正式 `session/title` 并持久化，统一侧栏与官方会话顶部标题。摘要不阻塞接话或首音，不注入虚假正式用户消息、不触发执行 Agent；已有正式标题或正式用户消息时交回官方标题机制。每个 session 同时只生成一次，提交前再次保护已有及用户手改标题；失败不影响通话，可在下次有效回复后重试。直通及 SuperAgent 路径从原会话正式用户消息、助手回复与发布记录读取，不复制工具历史，也不宣称能从旧记录准确区分所有键盘与语音输入。

全局胶囊订阅正式会话列表的标题更新，摘要完成或手动改名后同步刷新，不重建或中断通话。摘要输入限前五条可用用户语音、合计 1800 字符，输出最多 64 token；失败至少冷却 30 秒后随下一次有效回复重试，每次服务生命周期内同一会话最多失败两次，避免每轮请求失败。

点击通话入口后，入口位置过渡到屏幕中央的动态圆球；球体使用采集或播放的真实音量反馈，连接、聆听、识别、回应和错误有对应文字。“幕布”、麦克风和结束通话位于同一行；展开幕布后，圆球缩为状态条，精简对话在透明无框区域显示，连接和错误仍可见，不另弹记录窗口。幕布复用官方 Markdown 渲染器，支持安全链接和代码块；ASR 临时字幕随增量更新，并按同一转录标识原位交接为正式发言，不重播每个字符动画。

顶部不显示左侧标题与状态点，仅在右侧保留“收起”（历史查看为“关闭”）：所有通话路径均关闭大视图并露出当前页面的工作层记录，控制由全局胶囊承载，近 3 条实时文字显示在胶囊上方并可单独隐藏。收起不强制跳回原会话或切换正在浏览的页面，原执行树、草稿与滚动保留挂载。官方审批或提问未处理时，全屏与胶囊提供“处理确认”，回到原会话的审批与输入区；挂断不代表批准。完整语音幕布通过展开后查看；Windows 通话视图避开原生标题栏，移动端保留安全区。减少动效时关闭非必要动画。

幕布记录区隐藏滚动条，保留鼠标滚轮、触摸和键盘滚动；记录区可聚焦，查看旧记录时新消息不抢回底部，不用 `overflow:hidden` 裁掉内容。

增强通话的事件流在建立后立即发送不入记录、不朗读的 `ready` 握手，不能等待用户首句才响应。客户端仅对握手设置 12 秒期限，已连接的静默通话不受此期限影响；麦克风采集真正就绪后才显示聆听状态。原会话直通和独立交互模型均保留原有接入语义。

输入栏只保留同一个通话入口。桌面悬停或键盘聚焦显示入口上方的“语音记录”菜单；触屏短按启动，长按 550 ms 以圆环进度反馈后显示同一菜单，松手不再启动。移动、取消、多指和卸载均中止长按。菜单复用官方 `Menu` 的定位、指针宽限、键盘和关闭行为，挂断后可直接回看，通话配置不可用时也不影响记录入口。

已生成、已显示、已播放是不同事实，不能收到文字就标记用户已听完。当前持久记录保存回复文字与被打断标记，尚未精确持久化每段已播放及未播放范围；该能力仍待完善。重新通话读取近期文字和原执行状态，不自动重放历史语音或工具；断流明确提示重新开启，不自动重发已接收任务。

## 插话、挂断与执行生命周期

### 连续说话与轮次提交

ASR 最终语段与用户整轮提交分离，但不重复支付停顿时间。已实现：续说预算统一为最后有效人声后 450ms，VAD 的 320ms 及最终识别等待计入该预算；最终结果返回时预算已耗尽则立即安排提交，否则只等待剩余时间，不再从识别完成重新等待固定 900ms。缺少采集时间的宿主兼容输入只做一次零延时可取消调度，不凭空增加等待。

新语音开始取消待发送计时，保留前句与新增文字；全部相关语段最终成功且用户当前未讲话才合并提交一次。等待中已识别文字仍属同一条未提交发言；新开口、取消、静音和挂断均使旧计时失效。原文顺序、转录标识、草稿恢复和迟到隔离沿用现有机制，不让 ASR 临时分片启动执行。450ms 是响应速度与续说保护的公共预算，不能保证任意较长停顿都不提前提交；已接纳任务后的补充仍走原插话与修订机制。

普通语音转文本只写草稿，独立朗读不受影响。待审批时不自动取消或批准，未发送文字可恢复；失败不迟送、不把部分识别冒充完整结果。验收覆盖快速最终结果仅等待剩余预算、慢最终结果不再等、预算内续说恰好一次交接，以及迟到结果、错误、静音、挂断和旧计时隔离。三种通话模式都沿原发送入口，增强模式保留全部转录标识，直通及 SuperAgent 成功后由原会话正式消息承接。

### 插话与取消

增强通话中，插话先停止当前语音播放和交互模型生成，原执行是否变化由用户新话语与真实回执决定。

播放期间先由本地人声概率与持续时长共同确认插话，避免近麦短促噪声立即取消回复；阈值与前卷规则统一见[降噪与流式采集](媒体管线.md#降噪与流式采集已实现真实设备待验收)，不为此增加远程决策调用，也不把降噪等同于说话意图识别。

正常插话触发的本地取消、旧通话代次或旧回复流关闭不是供应商失败，不展示 `MODEL_ERROR`。取消竞态已修正：先识别本地信号和代次，再映射供应商错误，避免把 `AbortError.code=20` 当成供应商错误码；错误携带回复标识以隔离迟到结果，同一请求的后续真实执行结果仍可表达。有效当前请求的认证、限流、断网、服务异常仍按真实分类报告。

- 寒暄、询问进度和等待期间另聊，不取消已接受执行。
- 修订、停止须发往原请求并等待执行桥回执；“停止请求已接收”不等于“执行已退出”，只有宿主确认执行终结后才说已停止。适配器不支持时明确告知，不仅口头答应。普通确认不替代工具审批。
- 挂断、断网、页面销毁和模块卸载结束媒体和交互生成，停止主动语音投递；应用内切页保持原通话，运行边界见[应用级通话与收起](#应用级通话与收起)。所有模式的已接受执行均遵守宿主生命周期，Voice 不因结束通话默认停止它。须核验普通会话执行在通话租约结束后可继续，不能只由工单已有后台能力推定成立。
- 未确认送达的转录绑定原 session，挂断后按[媒体管线的草稿恢复规则](媒体管线.md#配置凭据与取消)保留；不自动重试发送或开新通话。
- 再次通话时只读取原会话真实运行状态；未表达结果可供用户恢复，不自动把旧成果当作新任务再次执行。

SuperAgent 原有任务修订、停止和交付继续由自身机制维护，Voice 不复制其工单控制逻辑；相关边界见[任务与执行](../06-superagent/任务与执行.md)。

直通和 SuperAgent 模式未使用 Voice 交互桥，插话仍沿原对话协议取消当前对话生成后顺序发送新转录；待审批时保留文字并提示在原界面处理，不自动取消或批准。此处的对话生成取消不等于停止已独立执行的 SuperAgent 工单，也不能据此宣称直通模式具备增强通话的并行闲聊语义。

## 决策配置与说话对象判断

配置与独立测试已实现：入口为“设置 → 媒体 → 语音 → 实时通话 → 决策”，沿用现有保存与加载。`listening` 保存启用开关、完整决策接口地址、可选原始模型 ID、独立 API 密钥、唤醒词来源与自定义词。产品只呈现“决策”，不预设供应商、地址、模型或称呼；新配置默认关闭且连接字段为空，既有用户配置原样保留。模型是否必填由所选接口合同决定，不按域名猜测。页面不重复显示标题，数据发送和生效条件收进默认折叠的“使用说明”。测试连接只发送固定样例，草稿变化隔离旧结果，测试成功不代表判断准确率。凭据复用 Voice 的敏感字段、权限文件和脱敏快照，不回传浏览器、不宣称额外加密；经用户明确要求才将其提供的连接信息保存到个人运行配置。

**已实现范围**：当前通话统一直接交流，不提供“对话／静默”切换，也不调用决策服务筛选用户输入。决策配置及固定样例测试保留，既有地址、模型、凭据和称呼来源不清空；即使配置开关已开启，也不接入当前通话。测试沿用 SystemOne `state + questions` 协议，不绑定厂商或底层模型，不复用聊天补全接口。决策配置变更只影响测试，不结束正常通话。

当前输入链路为：本地 VAD → 续说窗口合并的 ASR 最终文字 → 现有 `deliver`。三种通话路径均沿原行为处理输入、插话与主动播报；正常通话租约仍为 30 分钟硬上限、45 秒租约与约 15 秒心跳。不会因保留的决策配置授予长监听租约。

独立测试服务保留一道 `choice`：`addressed`（对当前助手说）、`background`（对别人或环境内容）、`uncertain`（证据不足），严格校验概率、弃权和超时。已有 0.85 的接纳阈值仅用于测试结果解释，不是实际准确率，也不控制当前通话。设置测试只发送固定示例，真实通话转录不会送到决策服务。

**待研讨、未接入通话**：须先找到说话对象与“当前是否希望助手回应”的判断边界，用自然续话、突然换题、对旁人说话、广播，以及“先别说话／可以说了”等上下文验证。用户的暂不回应要求应优先探索由模型理解上下文，不新增关键词或固定静默状态。仅凭话题相关不能证明在对助手说话，换话题本身也不能证明没有对助手说话。

候选上下文设计包括：本句、近期已接纳双方对话、助手最近公开回复、播放与生成状态、交流间隔及有效称呼；未知时间为 null，不假定用户已听完回复。材料区分历史背景与当前发言，不上传内部推理、完整工作区或全量历史。自然回答、补充约束、纠正和指代应无需逐句叫称呼；时间窗口不能自动放行所有人声。具体范围和提示词须完成边界评估后再确认。

称呼配置提供自定义唤醒词或跟随 SuperAgent 正式称呼。跟随只在 SuperAgent 已启用、身份服务可用且正式称呼非空时可选，读取现有 `store.getConfig()` 从 `IDENTITY.md` 派生的称呼，不复制称呼权威、不把“未命名”占位作为唤醒词。来源失效在设置中提示并保留选择，Voice 不因此硬依赖 SuperAgent；称呼不改变助手身份、会话归属或授权。

后续若重新接入，判断须位于正式记录和执行之前，并解决背景人声误打断、上下文误接纳与漏接纳的取舍；已接受任务的结果及审批不应因输入判断而丢失。纯文本没有声纹、方向或视线证据，不能承诺全天零误触。实测接口延迟与少量人工样例不能代替真实设备和环境评估。

## 配置与源码边界

“设置 → 媒体 → 语音 → 实时通话”增加可选交互 LLM 配置，复用现有供应商、模型目录、凭据与请求服务。仅用于普通会话实时通话；不覆盖 ASR、TTS、原 Agent 或 SuperAgent 的主模型。模型 ID 原样保存，不以名称猜测能力。

ASR/TTS 的自动匹配、厂商兼容边界与测试只在[媒体管线](媒体管线.md#自动匹配与测试)维护。用户点击匹配后选择并保存具体协议，通话启动直接使用相同协议，不隐式探测；未匹配或旧 `auto` 明确提示配置。普通完整转录不能作为实时流式识别，通话中不临时换协议；高级设置允许手动选择，修改一项仍保留其他媒体与交互模型配置。

交互模型请求固定使用 `reasoningEffort: 'off'`，通话启动前和每次调用均通过官方 `prepareCall` 校验，并用同一个已绑定适配器的 handle 流式请求。未声明关闭能力、不支持 `off` 或适配器改写该选择时明确拒绝增强通话，不静默回退为思考模式；普通转录、朗读与未配置交互模型的直通路径保持独立。自定义 DeepSeek 协议由供应商该精确模型的 `reasoningEfforts` 与 `compat.thinkingFormat` 显式声明，复用官方适配器将 `off` 编码为 `thinking: { type: 'disabled' }`；不根据模型 ID 自动注入协议，也不修改上游。提示词继续约束简短口语、按需交接和真实表达。

保存和重载须与实际请求一致，编辑交互项保留其他媒体设置。未配置走明确标注的原直通模式；已选模型不可用或不支持所需交接能力时给出具体错误、保留转录，不静默换执行模型或将未知请求再发送一遍。通话内固定已解析的交互路由，修改该路由先结束受影响通话，下次启动使用新值；无变化的保存不打断通话。

## 实现边界与验收

当前源码已按宿主会话身份选择 `native`、`enhanced`、`direct` 路径。增强路径由服务端调用所选交互 LLM，通过原会话服务交接真实用户原文及有界引用上下文；请求关联、持久接收记录与会话事件用于防重和核对状态。完整任务整理、最近五条补充及跨委派去重仍为[待实施设计](#任务整理与有界委派)，不能把本文目标描述当作已生效。原执行 Agent、模型与工具不由 Voice 重建。直通与原生路径继续由 `conversation.send` 和 `agent-feed.mjs` 使用已有对话层。

已覆盖本地受控模型、官方 Cordis / AgentLoop / Session 接缝及客户端定向验证；这类验证不使用真实供应商音频会话。阶段成果即时表达、精确播放范围持久化仍待完善；安装版真实模型工具调用、麦克风到执行再回声的完整链路、长通话和真实设备体验须另行验收。

交付时应核验以下行为，证据留在本地 `artifacts/` 或 `eval/`，不在 docs 新建验收流水：

- 普通会话“你好”只调用交互模型；真实任务恰好交接一次，重试、未知送达和页面重连不重复执行。
- SuperAgent 主聊、旁聊不调用额外交互模型；普通工作区、Worker 与身份不可确认场景不误判，模块关闭不产生硬依赖。
- 执行模型和真实工具请求保持原配置，权限和待审批不变；轻量模型不能伪造授权。
- 执行期间追问进度、闲聊、修订和停止各走正确路径；挂断清媒体且不错误停止已接受执行，迟到结果不串会话。
- 首次接话、后续进展、结果、失败与审批均按真实事件表达，原稿保留；画面与实际通话发言一致，不重复朗读。
- 交互模型缺失、慢响应、调用失败、交接不支持、事件断流均有明确状态和恢复；转录与普通朗读不受影响。
- 设置空/加载/错误/有数据四态、宽窄明暗、配置保存重载与实际路由一致；分别测量停说到最终转录、转录到首句、交接到执行、结果到首音，不用接话延迟代替任务完成速度。
