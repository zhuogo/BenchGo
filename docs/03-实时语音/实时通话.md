# 实时通话交互与执行

本文维护实时通话的会话分流、模型分工和交接机制。板块入口见[设计](设计.md)，可视化见[架构](架构.html)，音频协议与资源约束只在[媒体管线](媒体管线.md)维护。会话分流、轻量交互、交接桥与界面已接入源码；下文分别说明实现和仍待完善的边界，真实设备与供应商验收不由源码存在推定完成。

## 目标与职责

实时通话需要快速、自然地接话，也需要保留强模型的推理和工作能力。语音流式传输不能消除执行模型生成首句之前的长思考，提示词也不能保证所有模型提前输出正文，因此将普通会话的通话表达与实际执行分工。

- Voice 负责媒体、通话交互和交接协调，不引入工单、Worker 调度器、独立工具执行器或审批体系。
- 普通会话的轻量模型负责寒暄、澄清需求、判断何时交接、表达真实进度与结果；只获得受限的交接能力，工作工具仍归原执行 Agent。
- 原 Agent 保留当前会话、工作区、执行模型、思考设置、工具与审批。通话设置不替换或降低执行模型，不要求其支持关闭思考。
- SuperAgent 主聊、旁聊已有 Router 对话层，直接复用原有表达与执行机制；Voice 不在其外面再叠轻量模型。
- 普通转录只写草稿，普通朗读只读既有回复，两者均不进入本文的新交互层。

## 会话接入

通话开始前由宿主解析当前 session 的可信归属与能力，绑定本次通话和原会话；不按标题、模型 ID、页面位置或模型声称的身份猜测。仅安装或启用 SuperAgent 不代表所有会话属于 SuperAgent。

| 会话与配置 | 通话路径 |
| --- | --- |
| SuperAgent 主聊、旁聊，确认具备原有 Router 对话层 | 最终转录 → 原对话层 → 原有执行与交付 → TTS；不使用 Voice 交互模型配置 |
| 普通 Harness 工作区会话，已配置可用交互模型与执行适配 | 最终转录 → Voice 交互模型 → 按需交接原 Agent → 事件回传 → 交互模型表达 → TTS |
| 普通会话未配置交互模型 | 保留现有直通通话，配置明确显示未启用交互增强，可能等待原模型思考 |
| 归属无法确认、执行子会话或适配能力不足 | 明确展示实际接入能力；不把 SuperAgent Worker / 子 Worker 当作 Router，不自动套用未经核验的增强路径 |

会话能力描述至少区分可信归属、是否已有对话层、是否可交接执行和是否有回传；这是语义合同，不预设新的公开 API 名称。SuperAgent 提供自身身份适配，Voice 消费通用描述；模块未启用时不请求其专属服务。普通会话不因这项能力依赖 Harness 聚合的 commander。

会话切换先结束旧通话，再解析新会话。通话期间归属或必需模块发生变化须结束当前接入并说明原因，不能悄悄从直通切为双模型，或将旧请求送入新会话。

当前在开始通话时读取可信身份并固定接入模式；每次增强转录提交前及通话心跳（约 15 秒）重新核对角色与适配能力，变化或不可用即结束当前接入并明确报错，不静默切模型、不取消原工作。交互路由变化、媒体关闭和模块卸载也会清理相应通话；角色复核依赖上述边界，不是持续实时监听。

成功绑定后以同一可忽略事件保存 `call-start`，按原 session 与 callId 幂等，不伪造用户发言、不触发模型。独立 `benchgoVoice` 官方会话投影仅公开是否使用过语音及活动时间，并兼容旧语音记录；自有侧栏据此保留纯语音历史。BenchGo 的“新聊天”入口显式创建新 session，不复用官方仍视为空白的语音会话；官方快捷键和其他原生入口的空白复用规则不在此改写。

## 对话与交接

轻量模型通过当前用户原话、必要近期对话和已收到的执行事实决定如何回应；不设额外常驻分类模型，不让所有话语都跑执行 Agent。

| 用户表达 | 行为 |
| --- | --- |
| “你好”“谢谢” | 轻量模型直接自然回应，不启动执行 |
| “帮我查今天的热点” | 发起一次明确交接，简短接话；查询结果回来后继续表达 |
| “优化这个前端页面”，但无法确定页面或目标 | 结合当前工作区上下文判断，确有歧义时只问必要问题，不自行扩展任务 |
| “现在怎么样了？” | 从已有执行事实回答，无更新就如实说明，不重新派发同一任务 |
| “改成深色”“先别做了” | 关联当前执行发修订或停止请求；区分请求已接收和执行已改变，确认已停止须核实执行退出 |

交接须包含用户原始转录及原文引用、必要上下文、目标 session 和请求关联标识；轻量模型可补充理解，但不能用摘要替换原话、添加用户未给出的授权。执行桥绑定真实用户和原会话权限，不把轻量模型生成的文字伪装成新的真人批准。工具参数、日志与网页内容作为数据处理，不能升级为新的用户指令。

同一次请求交接一次，以关联标识和服务端接收记录防止网络重试重复启动。桥接至少区分已接受、明确拒绝和结果未知；未知时查询原接收记录，不盲目重发。单会话沿用原 Agent 的并发限制，忙碌时不得静默打断或另建执行；修订与停止由适配器明确支持，缺少能力时说明限制，不能伪装成已送达。

接话与执行可以重叠：“我来查一下”表达接下来要做的事；“已经开始查询”必须有真实执行开始事实，请求已接收不等于已经运行。已经接话后不再重复“已开始、稍后告诉你”，不把执行模型的每段计划、每个工具步骤逐条播报。

## 执行事件与表达

执行桥订阅原会话事件并归一为通话需要的事实；事件由宿主推送，不让轻量模型轮询或持续评判思考过程。下表是语义分类，不是新增工单状态，也不要求另建任务数据库。

| 事件事实 | 通话处理 |
| --- | --- |
| 请求已接受、正在运行、工具或阶段变化 | 更新有界进度上下文，默认不唤起模型讲话；用户追问时可读 |
| 正式可表达内容或阶段成果 | 按关联标识送入交互模型，流式口语表达；合并零碎内容，不必等整个执行结束。中间计划默认作静默进度，不把任意 text-delta 当作成果 |
| 需要用户澄清或审批 | 提出真实问题；审批仍使用原界面，不将语音确认转为批准 |
| 完成、失败、明确拒绝 | 主动说明实际结论、必要结果或下一步，不根据模型计划推断成功 |
| 取消、修订回执 | 更新当前请求事实；旧版本成果不混入新请求，不宣称已撤回已经生效的操作 |

事件至少带原 session、通话代次、请求及执行关联、顺序与来源；迟到、重复、取消旧版本和重连补发按关联去重。只有可验证的正文、工具生命周期和终态才作为结果依据，内部思考不直接朗读，也不作为完成证据。

当前执行桥以原 session 事件和持久关联记录核对接收、运行、审批/提问及终态；普通进度进入上下文，完成、失败、取消和需用户处理的事件触发表达。同一终态不重复播报。上表的“阶段成果”仍是目标：当前不将任意执行正文增量作为可表达成果，也未建立执行结束前的独立阶段成果发布接缝。

普通会话增强模式下，交互模型是唯一通话发言者：执行 Agent 的原文和工具仍可在界面查看，但不同时直送自动朗读，避免两套语音抢播。SuperAgent 路径沿用原对话层，普通朗读功能在通话结束后按原用户开关恢复，不重播通话期间的历史。

转述须保留成功/失败、未完成范围、需要用户处理的事项以及关键数字、文件或链接；需要逐字内容时按原稿表达或引导查看原文，不编造、润色为成功。转述失败保留执行结果，允许重试表达或查看原文，不重新执行。

交互模型的认证、额度、限流、服务异常、连接中断、超时、回复截断与拒绝生成分别显示明确原因，不统一掩盖为“未完整回复”。错误事件只保留白名单错误分类、有效 HTTP 状态、经校验的供应商请求 ID 和准确路由，不公开上游原始响应、提示正文或凭据。服务异常后允许同一通话继续下一句，不自动重试已交接执行；本地取消仍按通话代次隔离。

## 内置沟通提示词与听觉表达

普通会话轻量交互模型使用 `plugins/voice/prompts/conversation.md` 作为唯一提示词正文，服务端由 `src/conversation-prompt.mjs` 读取并提供 `VOICE_CONVERSATION_PROMPT`。文件随 Voice 发布；缺失或空白明确报错，不让客户端传入系统提示词。`src/conversations.mjs` 将其装入所选供应商与模型的流式请求，并只开放交接、修订、停止及语音设置工具。SuperAgent 的主聊、旁聊复用其原有对话提示词，普通转录和朗读不调用这套交互模型。

表达参考 SuperAgent 的[Router 对话准则](../06-superagent/Router对话准则.md)：温暖、有判断、尊重用户、少占注意力，以认真理解和真实结果体现朋友般的交流感；不复制其身份、文档链、记忆、工单或权限，不表演亲密或虚构人类经历。默认一到两句直接回应，不固定开场、等待话术或结尾追问；长解释先讲关键结论，按用户需要展开，失败与限制仍必须保留。

| 内容 | 听觉表达 |
| --- | --- |
| Markdown 标记、表格、代码、命令、结构化工具参数 | 不读格式或载荷，必要时简短说用途；精确内容保留界面，实际可见后才说明已提供 |
| 带标题的链接 | 只说真实标题，不读 URL 或查询串；无标题时说“这个链接”，不编造标题 |
| Windows 文件路径 | 按真实盘符、目录与文件说位置，如“D 盘项目文件夹里的说明文件”；必要时保留扩展名区分，完整路径仍在界面 |
| 中间计划、普通进度、原始推理 | 不逐条播报；普通进度静默供追问，推理不进入语音 |

模型提示词与进入 TTS 前的流式文本处理共同保证朗读规范；不能只靠模型自行遵守。流式链接和路径须识别跨片段内容，不将半个协议、盘符或代码标记提前读出；口语转换不能改写原会话的链接、路径与执行原文。这里规定通话口语目标，共用媒体过滤的实现与验收仍在[媒体管线](媒体管线.md)维护。

## 自然语言语音设置

普通会话增强通话通过已注册工具读取和调整语音设置，不把设置要求委派成开发工作。`get_voice_settings` 返回实际语速与音色，`set_voice_speed` 按服务端校验修改语速；“调到一点五倍”对应 1.5，“说快一点 / 慢一点”先读取现值再小幅增减 0.1。当前范围为 0.25–4 倍、精度 0.01，越界明确说明，不静默改成另一个目标。仅保存语速字段，保留 ASR、TTS 模型、音色、凭据与交互模型等其他配置。

只有设置工具成功并回传实际值后，交互模型才确认改变；按真实回执区分已保存、当前生效或下次生效。失败保留原值、说明失败；“工作快一点”不当成语速指令。保存成功后服务端推送配置，客户端更新后续 TTS 请求；不改变采集和执行模型，不承诺已经播放的音频变速。该独立工具路径不依赖 SuperAgent。SuperAgent 通话沿用其统一设置工具和 Voice 设置适配器的 `tts.speed` 配置，不额外加载上述轻量工具；真实模型是否正确选择并调用工具仍须实测。

## 上下文与界面

界面按来源区分原 Agent 的执行记录和用户实际听到的通话发言。交互模型寒暄、交接回应和口语结果只在语音记录显示，执行聊天保留正式交接后的用户任务与执行回复；不以口语摘要覆盖执行原稿。数据仍保存于原 session，不创建一份隐藏的平行工作会话。原生语音记录只投影来源为真实用户的正式消息、助手正文与正式发布，排除模型专用上下文、宿主注入及压缩替换副本；文件和图片保留显示名称。

交互上下文由当前原话、必要近期通话、活跃请求、最新进度和待表达结果组成。进度合并覆盖为有界摘要，保留原事件指针；完整工具输出、文件及执行历史按需读取。使用已有会话记录及可恢复插件记录保存关联和表达事实，不复制原 Agent 的完整历史或思考链，不新增长期记忆系统。

增强通话将用户原话、交互回复、交接和执行关联写入原 session 的 `plugin:benchgo-plugin/voice-conversation` 可忽略事件，复用官方持久化与分页。语音专用发言在执行聊天中隐藏，语音记录仍完整投影用户与交互模型对话。通话成功绑定原 session 后，持久化一次 `call-start` 并在执行聊天显示简洁的开始时间记录；未有正式标题的语音会话在侧栏显示“语音对话”，不以工作目录名作标题，不注入虚假的用户消息或触发初始化模型调用。直通及 SuperAgent 路径从原会话正式用户消息、助手回复与发布记录读取，不复制工具历史，也不宣称能从旧记录准确区分所有键盘与语音输入。

点击通话入口后，入口位置过渡到屏幕中央的动态圆球；球体使用采集或播放的真实音量反馈，连接、聆听、识别、回应和错误有对应文字。“幕布”、麦克风和结束通话位于同一行；展开幕布后，圆球缩为状态条，精简对话在透明无框区域显示，连接和错误仍可见，不另弹记录窗口。幕布复用官方 Markdown 渲染器，支持安全链接和代码块；ASR 临时字幕随增量更新，并按同一转录标识原位交接为正式发言，不重播每个字符动画。

顶部仅保留“收起”：独立交互模型将同一个幕布组件嵌入所属会话正文，原执行树保留挂载、草稿与滚动；原会话模型返回原消息流。官方审批或提问未处理时释放嵌入接管，全屏入口显示“处理确认”，回到原审批与输入区；完成后恢复语音记录，挂断不代表批准。展开、切换和挂断恢复对应视图，无匹配承载框时保留全屏入口；Windows 通话视图避开原生标题栏，移动端保留安全区。减少动效时关闭非必要动画。

增强通话的事件流在建立后立即发送不入记录、不朗读的 `ready` 握手，不能等待用户首句才响应。客户端仅对握手设置 12 秒期限，已连接的静默通话不受此期限影响；麦克风采集真正就绪后才显示聆听状态。原会话直通和独立交互模型均保留原有接入语义。

输入栏只保留同一个通话入口。桌面悬停或键盘聚焦显示入口上方的“语音记录”菜单；触屏短按启动，长按 550 ms 以圆环进度反馈后显示同一菜单，松手不再启动。移动、取消、多指和卸载均中止长按。菜单复用官方 `Menu` 的定位、指针宽限、键盘和关闭行为，挂断后可直接回看，通话配置不可用时也不影响记录入口。

已生成、已显示、已播放是不同事实，不能收到文字就标记用户已听完。当前持久记录保存回复文字与被打断标记，尚未精确持久化每段已播放及未播放范围；该能力仍待完善。重新通话读取近期文字和原执行状态，不自动重放历史语音或工具；断流明确提示重新开启，不自动重发已接收任务。

## 插话、挂断与执行生命周期

增强通话中，插话先停止当前语音播放和交互模型生成，原执行是否变化由用户新话语与真实回执决定。

- 寒暄、询问进度和等待期间另聊，不取消已接受执行。
- 修订、停止须发往原请求并等待执行桥回执；“停止请求已接收”不等于“执行已退出”，只有宿主确认执行终结后才说已停止。适配器不支持时明确告知，不仅口头答应。普通确认不替代工具审批。
- 挂断、断网、切换会话结束媒体和交互生成，停止主动语音投递；所有模式的已接受执行均遵守宿主生命周期，Voice 不因结束通话默认停止它。须核验普通会话执行在通话租约结束后可继续，不能只由工单已有后台能力推定成立。
- 未确认送达的转录保留恢复入口，绑定原 session；主动挂断后不自动重试、发送或开新通话。
- 再次通话时只读取原会话真实运行状态；未表达结果可供用户恢复，不自动把旧成果当作新任务再次执行。

SuperAgent 原有任务修订、停止和交付继续由自身机制维护，Voice 不复制其工单控制逻辑；相关边界见[任务与执行](../06-superagent/任务与执行.md)。

直通和 SuperAgent 模式未使用 Voice 交互桥，插话仍沿原对话协议取消当前对话生成后顺序发送新转录；待审批时保留文字并提示在原界面处理，不自动取消或批准。此处的对话生成取消不等于停止已独立执行的 SuperAgent 工单，也不能据此宣称直通模式具备增强通话的并行闲聊语义。

## 配置与源码边界

“设置 → 媒体 → 语音 → 实时通话”增加可选交互 LLM 配置，复用现有供应商、模型目录、凭据与请求服务。仅用于普通会话实时通话；不覆盖 ASR、TTS、原 Agent 或 SuperAgent 的主模型。模型 ID 原样保存，不以名称猜测能力。

ASR/TTS 的自动匹配、厂商兼容边界与测试只在[媒体管线](媒体管线.md#自动匹配与测试)维护。用户点击匹配后选择并保存具体协议，通话启动直接使用相同协议，不隐式探测；未匹配或旧 `auto` 明确提示配置。普通完整转录不能作为实时流式识别，通话中不临时换协议；高级设置允许手动选择，修改一项仍保留其他媒体与交互模型配置。

交互模型请求固定使用 `reasoningEffort: 'off'`，通话启动前和每次调用均通过官方 `prepareCall` 校验，并用同一个已绑定适配器的 handle 流式请求。未声明关闭能力、不支持 `off` 或适配器改写该选择时明确拒绝增强通话，不静默回退为思考模式；普通转录、朗读与未配置交互模型的直通路径保持独立。自定义 DeepSeek 协议由供应商该精确模型的 `reasoningEfforts` 与 `compat.thinkingFormat` 显式声明，复用官方适配器将 `off` 编码为 `thinking: { type: 'disabled' }`；不根据模型 ID 自动注入协议，也不修改上游。提示词继续约束简短口语、按需交接和真实表达。

保存和重载须与实际请求一致，编辑交互项保留其他媒体设置。未配置走明确标注的原直通模式；已选模型不可用或不支持所需交接能力时给出具体错误、保留转录，不静默换执行模型或将未知请求再发送一遍。通话内固定已解析的交互路由，修改该路由先结束受影响通话，下次启动使用新值；无变化的保存不打断通话。

| 位置 | 边界 |
| --- | --- |
| `plugins/voice/src/` | `conversations.mjs` 集中交互路由、受限工具和通话生成；`conversation-bridge.mjs` 负责原会话交接、持久关联与事件归一，不增加 Cordis 入口 |
| `plugins/voice/client/` | `controller.mjs` 协调采集与播放；`conversation.mjs` 处理交互事件流；`call-stage.jsx` 呈现通话舞台，`conversation-records.*` 投影持久文字 |
| 原会话 / SuperAgent 适配接缝 | 提供可信身份、既有对话能力和可用执行事件；各自业务仍在所属源码包，不向 Voice 复制执行系统 |
| `plugins/benchgo/` 与共享服务 | 沿用单包装配、供应商与凭据；不另建供应商配置或安装包 |

按这些职责维护小模块，不预建空目录或兼容壳；不修改官方 `deepseek-harness/` 源码，不新增隐藏进程或常驻分类 Agent。

## 实现边界与验收

当前源码已按宿主会话身份选择 `native`、`enhanced`、`direct` 路径。增强路径由服务端调用所选交互 LLM，通过原会话服务交接真实用户原文及有界引用上下文；请求关联、持久接收记录与会话事件用于防重和核对状态。原执行 Agent、模型与工具不由 Voice 重建。直通与原生路径继续由 `conversation.send` 和 `agent-feed.mjs` 使用已有对话层。

已覆盖本地受控模型、官方 Cordis / AgentLoop / Session 接缝及客户端定向验证；这类验证不使用真实供应商音频会话。阶段成果即时表达、精确播放范围持久化仍待完善；安装版真实模型工具调用、麦克风到执行再回声的完整链路、长通话和真实设备体验须另行验收。

交付时应核验以下行为，证据留在本地 `artifacts/` 或 `eval/`，不在 docs 新建验收流水：

- 普通会话“你好”只调用交互模型；真实任务恰好交接一次，重试、未知送达和页面重连不重复执行。
- SuperAgent 主聊、旁聊不调用额外交互模型；普通工作区、Worker 与身份不可确认场景不误判，模块关闭不产生硬依赖。
- 执行模型和真实工具请求保持原配置，权限和待审批不变；轻量模型不能伪造授权。
- 执行期间追问进度、闲聊、修订和停止各走正确路径；挂断清媒体且不错误停止已接受执行，迟到结果不串会话。
- 首次接话、后续进展、结果、失败与审批均按真实事件表达，原稿保留；画面与实际通话发言一致，不重复朗读。
- 交互模型缺失、慢响应、调用失败、交接不支持、事件断流均有明确状态和恢复；转录与普通朗读不受影响。
- 设置空/加载/错误/有数据四态、宽窄明暗、配置保存重载与实际路由一致；分别测量停说到最终转录、转录到首句、交接到执行、结果到首音，不用接话延迟代替任务完成速度。

## 参考边界

参考 Pipecat `dea65430bed0f3d1317a66d2edd200263ab8b67d` 的 `examples/multi-worker/llm-with-backend/README.md` 及 `src/pipecat/pipeline/llm_with_backend/`：轻量 frontend 自行处理日常对话，`delegate` 立即交接后台 worker；普通进度静默进入上下文，需表达的输出触发 frontend 继续说话，修订与停止也必须真实传给 backend。文本前端可交接自上次以来的原始对话，不能只靠丢失约束的改写。采纳这些分工与推送机制，不引入 Python worker、消息总线、工单或额外常驻分类模型，也不照搬其后台思考摘要进入通话上下文的做法。
