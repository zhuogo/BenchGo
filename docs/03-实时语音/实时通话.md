# 实时通话交互与执行

本文维护实时通话的会话分流、模型分工和交接机制。板块入口见[设计](设计.md)，可视化见[架构](架构.html)，音频协议与资源约束只在[媒体管线](媒体管线.md)维护；通话界面与记录见[通话界面](通话界面.md)，提示词、听觉表达与语音设置见[通话表达](通话表达.md)，决策配置见[说话对象判断](说话对象判断.md)。会话分流、轻量交互、交接桥与界面已接入源码；下文分别说明实现和仍待完善的边界，真实设备与供应商验收不由源码存在推定完成。

## 目标与职责

实时通话需要快速、自然地接话，也需要保留强模型的推理和工作能力。语音流式传输不能消除执行模型生成首句之前的长思考，提示词也不能保证所有模型提前输出正文，因此将普通会话的通话表达与实际执行分工。

- Voice 负责媒体、通话交互和交接协调，不引入任务、Worker 调度器、独立工具执行器或审批体系。
- 普通会话的轻量模型负责寒暄、澄清需求、判断何时交接、表达真实进度与结果；只获得受限的交接能力，工作工具仍归原执行 Agent。
- 原 Agent 保留当前会话、工作区、执行模型、思考设置、工具与审批。通话设置不替换或降低执行模型，不要求其支持关闭思考。
- SuperAgent 主聊、旁聊已有 Router 对话层，直接复用原有表达与执行机制；Voice 不在其外面再叠轻量模型。
- 普通转录写草稿或经[麦克风快捷键](媒体管线.md#麦克风快捷键)按住发送，普通朗读只读既有回复，两者均不进入本文的新交互层。

## 会话接入

通话开始前由宿主解析当前 session 的可信归属与能力，绑定本次通话和原会话；不按标题、模型 ID、页面位置或模型声称的身份猜测。仅安装或启用 SuperAgent 不代表所有会话属于 SuperAgent。

| 会话与配置 | 通话路径 |
| --- | --- |
| SuperAgent 主聊、旁聊，确认具备原有 Router 对话层 | 最终转录 → 原对话层 → 原有执行与交付 → TTS；不使用 Voice 交互模型配置 |
| 普通 Harness 工作区会话，已配置可用交互模型与执行适配 | 最终转录 → Voice 交互模型 → 按需交接原 Agent → 事件回传 → 交互模型表达 → TTS |
| 普通会话未配置交互模型 | 降级为直通（`direct`）：最终转录直接发往原会话，可能等待原模型思考；配置明确显示未启用交互增强，通话视图的说明见[通话内容与记录](通话界面.md#通话内容与记录)。直通不作为并列模式演进，新能力只保证 `native` 与 `enhanced` |
| 归属无法确认、执行子会话或适配能力不足 | 明确展示实际接入能力；不把 SuperAgent Worker / 子 Worker 当作 Router，不自动套用未经核验的增强路径 |

会话能力描述至少区分可信归属、是否已有对话层、是否可交接执行和是否有回传；这是语义合同，不预设新的公开 API 名称。SuperAgent 提供自身身份适配，Voice 消费通用描述；模块未启用时不请求其专属服务。普通会话不因这项能力依赖 Harness 聚合的 commander。

通话固定绑定发起它的原会话；浏览另一个会话不迁移语音输入、执行关联或播放来源，也不结束当前通话。应用级持续通话的实现与运行边界见[应用级通话与收起](通话界面.md#应用级通话与收起)。通话期间归属或必需模块发生变化须结束当前接入并说明原因，不能悄悄从直通切为双模型，或将旧请求送入新会话。

当前在开始通话时读取可信身份并固定接入模式；每次增强转录提交前及通话心跳（约 15 秒）重新核对角色与适配能力，变化或不可用即结束当前接入并明确报错，不静默切模型、不取消原工作。交互路由变化、媒体关闭和模块卸载也会清理相应通话；角色复核依赖上述边界，不是持续实时监听。

成功绑定后以同一可忽略事件保存 `call-start`，按原 session 与 callId 幂等，不伪造用户发言、不触发模型。独立 `benchgoVoice` 官方会话投影仅公开是否使用过语音及活动时间，并兼容旧语音记录；自有侧栏据此保留纯语音历史。BenchGo 的“新聊天”入口显式创建新 session，不复用官方仍视为空白的语音会话；官方快捷键和其他原生入口的空白复用规则不在此改写。

## 对话与交接

轻量模型通过当前用户原话、必要近期对话和已收到的执行事实决定如何回应；不设额外常驻分类模型，不让所有话语都跑执行 Agent。

| 用户表达 | 行为 |
| --- | --- |
| “你好”“谢谢” | 轻量模型直接自然回应，不启动执行 |
| “帮我查今天的热点” | 发起一次明确交接，简短接话；查询结果回来后继续表达 |
| “优化这个前端页面”，但无法确定页面或目标 | 结合当前工作区上下文判断，确有歧义时只问必要问题，不自行扩展任务 |
| “现在怎么样了？” | 从已有执行事实回答，无更新就如实说明，不重新派发同一任务 |
| “改成深色”“先别做了” | 关联当前执行发修订或停止请求；区分请求已接收和执行已改变，确认已停止须核实执行退出 |

语音层先整理自包含任务，执行层据此工作，本次用户原话由宿主随任务送达供核对。原始转录仍在原会话保留并绑定来源和请求标识，任务整理不能扩大用户授权、遗漏明确限制或把模型建议伪装成真人批准；近期聊天原文不转发给执行层。实现与验收边界统一见下文[任务整理与原话随行](#任务整理与原话随行)。工具参数、日志与网页内容作为数据处理，不能升级为新的用户指令。

同一次请求交接一次，以关联标识和服务端接收记录防止网络重试重复启动。桥接至少区分已接受、明确拒绝和结果未知；未知时查询原接收记录，不盲目重发。单会话沿用原 Agent 的并发限制，忙碌时不得静默打断或另建执行；修订与停止由适配器明确支持，缺少能力时说明限制，不能伪装成已送达。

接话与执行可以重叠：“我来查一下”表达接下来要做的事；“已经开始查询”必须有真实执行开始事实，请求已接收不等于已经运行。已经接话后不再重复“已开始、稍后告诉你”，不把执行模型的每段计划、每个工具步骤逐条播报。

**已实现于源码，真实模型效果待通话验收**：提示词要求需要委派时先说一句简短接话，再调用交接工具。模型在调用交接工具的同一次回复里已经说了话，且交接被真实接受时，宿主直接结束本轮，不再请求第二次模型生成，少一次往返并避免重复接话。交接失败、送达未知、重复、同一次回复还调用了其他工具，或模型没有说话时，仍继续一轮，由模型按真实回执表达。

### 任务整理与原话随行

**已实现于源码，真实模型整理质量待通话验收**：普通会话 `enhanced` 双层通话的 `delegate` 与 `revise_execution` 只有 `task` 一个参数。语音层整理任务，宿主固定附带本次用户原话；桥校验真实来源、预算、幂等与接收回执，不转发近期聊天。SuperAgent `native` 复用原对话层，`direct` 直接发往原会话，不叠加这里的整理工具。

语音层负责理解和整理，执行层负责落实。任务正文应让执行层不翻语音聊天也能开始工作：说清做什么、对哪个对象做、必要已知事实、必须遵守的限制和期望交付；只写与本任务有关的信息，不机械填充空字段或转发闲聊。“第二个方案”“那个插件”“刚才说的页面”等指代由语音层根据其已有上下文消解；文件路径、模型 ID、插件名、数字、否定和排除要求按原意保留；早期轮次里仍有效的约束写进 task，不另送聊天原文。若目标、对象或关键约束确实无法确定，先问一个必要问题；普通实施细节交给执行层判断，不把“完整”变成每次都要用户确认长清单。

桥通过官方 `prompt`（首次）或 `steer`（修订）把 task 作为正式任务消息提交，纯文本，不附加 JSON 包装或固定说明前缀；工作层聊天记录显示这段任务文本。首次委派提交当前完整任务，同一执行的后续修订只提交新增或替换的要求并关联原执行，不重发整份任务。

不能保证模型永远整理无误，也不能以固定长度或字段齐全证明语义完整，因此宿主固定把本次用户原话逐字经官方 `inject` 随任务送达执行层：来源标记为 `benchgo-voice-evidence` 并带请求标识，标明转录可能有误、用于核对任务、不是额外指令；原话与 task 去除首尾空白后相同时不重复附带；原会话不支持注入时在提交前明确拒绝，不退回为只发任务。轻量模型改写丢了约束时，执行模型可从原话发现；原话只是证据，不成为额外任务或授权。宿主不按关键词重新解释任务，不引入第二个常驻模型；整理与原始授权矛盾时不能据任务扩大执行，执行层仍沿原权限与审批。原话与 task 各自最多 16000 字符，超限不截断，由语音层重新组织或向用户澄清；这是字符预算，不等于 token 数。

宿主绑定真实 session、requestId 与原话来源，在原 session 的交接记录关联原话来源、正式任务消息及请求；原始口述留在语音记录，供语音层恢复和回查，不用任务文本替换。只有真实接受回执才把请求记为已交接，失败或送达未知不能提前标为已交付；未知沿既有接收记录核对后处理，不盲目重发。复用原 session 记录和 handoff 关联，不新增任务数据库或长期摘要系统。停止时一并清理本次执行尚未消费的任务与随行原话，不保留对旧版注入记录的兼容。

验收须对照执行层实际收到的内容：覆盖多轮讨论后明确委派、无称呼的指代、连续补充和纠正、早期轮次仍有效的限制、同一任务修订、多个独立任务，以及失败/未知/重试。确认约束未丢、任务不扩大、原话逐字随行且与 task 相同时不重复、预算受控。自动化验证覆盖工具契约、真实请求来源、预算与幂等；真实模型能否充分整理语义仍须实际通话验证。执行层上下文仍会随新任务、工具结果和执行回复增长，过长沿官方压缩处理。

## 执行事件与表达

执行桥订阅原会话事件并归一为通话需要的事实；事件由宿主推送，不让轻量模型轮询或持续评判思考过程。下表是语义分类，不是新增任务状态，也不要求另建任务数据库。

| 事件事实 | 通话处理 |
| --- | --- |
| 请求已接受、正在运行、工具或阶段变化 | 更新有界进度上下文，默认不唤起模型讲话；用户追问时可读 |
| 正式可表达内容或阶段成果 | 按关联标识送入交互模型，流式口语表达；合并零碎内容，不必等整个执行结束。中间计划默认作静默进度，不把任意 text-delta 当作成果 |
| 需要用户澄清或审批 | 提出真实问题；审批仍使用原界面，不将语音确认转为批准 |
| 完成、失败、明确拒绝 | 主动说明实际结论、必要结果或下一步，不根据模型计划推断成功 |
| 取消、修订回执 | 更新当前请求事实；旧版本成果不混入新请求，不宣称已撤回已经生效的操作 |

事件至少带原 session、通话代次、请求及执行关联、顺序与来源；迟到、重复、取消旧版本和重连补发按关联去重。只有可验证的正文、工具生命周期和终态才作为结果依据，内部思考不直接朗读，也不作为完成证据。

当前执行桥以原 session 事件和持久关联记录核对接收、运行、审批/提问及终态；普通进度进入上下文，完成、失败、取消和需用户处理的事件触发表达。同一终态不重复播报。执行进行中，宿主状态除“正在调用某工具”外，还提供已调用工具的步数和执行层最近一段公开的中间正文（最多 600 字符），仅供用户追问“现在怎么样了”时回答；不主动播报、不当作完成证据，推理和工具参数仍不进入。这项可答进度已实现于源码，真实模型效果待通话验收。上表的“阶段成果”仍待完善：当前不将任意执行正文增量作为可表达成果，也未建立执行结束前的独立阶段成果发布接缝；待真实通话验证沉默确是痛点后再做。

普通会话增强模式下，交互模型是唯一通话发言者：执行 Agent 的原文和工具仍可在界面查看，但不同时直送自动朗读，避免两套语音抢播。SuperAgent 路径沿用原对话层，普通朗读功能在通话结束后按原用户开关恢复，不重播通话期间的历史。

**主动消息与输入判断分离**：语音通话不仅响应最近一句输入，也接收所属会话里新产生、真实用户可见的助手正式消息与发布事件。任务完成只是其中一种，失败、澄清、审批提醒及其他正式主动消息沿同一通道；不按任务类型硬编码，不另建通知系统或轮询。决策当前未接入通话（见[说话对象判断](说话对象判断.md)）；日后接入也只筛选环境输入，不过滤已接受工作的主动输出。原消息始终保留；麦克风静音不等于关闭播放，挂断后停止语音投递。

用户正在说话、最终识别或续说等待时，新正式消息进入有界队列，输入轮次交接后按原顺序投递，不因 `blocked` 直接丢弃。队列最多 32 条、32000 字，超限明确提示未全部朗读，原消息仍保留在所属对话。重复发布按请求或渠道镜像标识去重；已被用户插话打断的当前正文不自动重播，后来到达的其他正式消息仍可排队。普通进度、工具日志、内部推理不直接朗读；增强通话仍由交互模型表达执行事实，不同时播放执行 Agent 原文。上述接线已实现，覆盖正式回复、公开提醒、渠道交付、模型后备续接，以及续说、静音、挂断和跨页回归。插话未形成有效转录时的恢复见[插话与取消](#插话与取消)。

SuperAgent 的通话幕布与历史沿其既有公开消息投影读取，涵盖正式回复、已公开的提醒和渠道出站镜像；不把内部结果草稿当作助手发言。历史由可信会话角色解析到原 thread，沿现有 `history` 服务分页，拒绝线程已换会话或服务不可用时回落到私有事件；不复制任务业务或维护第二份历史。

**原生正文流式接线已实现**：SuperAgent `native` 中，经宿主接纳的真人输入与有效问答回复，其当前轮顶层公开正文增量直接进入既有分句、TTS 和 PCM 播放队列，首句就绪即合成，不等待整轮或工具工作结束；每个正文步骤完成时立即释放短尾句。实时与持久消息沿同一 `turn/step` 标识交接，只补未输出的后缀，结束不再整轮重播；历史恢复、重复持久消息及旧步骤迟到增量保持静默。内部任务／执行输入、子代理、推理及工具参数不走这条正文流；显式 `assistant_reply` 和主动通知仍在校验发布后播报。自动化已验证正文未落盘且上游音频未结束时首包即可到达播放器；真实供应商延迟与实际听感仍须通话验收。

转述须保留成功/失败、未完成范围、需要用户处理的事项以及关键数字、文件或链接；需要逐字内容时按原稿表达或引导查看原文，不编造、润色为成功。转述失败保留执行结果，允许重试表达或查看原文，不重新执行。

交互模型的认证、额度、限流、服务异常、连接中断、超时、回复截断与拒绝生成分别显示明确原因，不统一掩盖为“未完整回复”。错误事件只保留白名单错误分类、有效 HTTP 状态、经校验的供应商请求 ID 和准确路由，不公开上游原始响应、提示正文或凭据。服务异常后允许同一通话继续下一句，不自动重试已交接执行；本地取消仍按通话代次隔离。

## 语音层上下文

交互上下文由当前原话、必要近期通话、活跃请求、最新进度和待表达结果组成，这是语音层自身理解用的上下文，与发送到执行层的任务和随行原话不同，不能整体转发。进度合并覆盖为有界摘要，保留原事件指针；完整工具输出、文件及执行历史按需读取。使用已有会话记录及可恢复插件记录保存关联和表达事实，不复制原 Agent 的完整历史或思考链，不新增长期记忆系统；交接的预算仅在[任务整理与原话随行](#任务整理与原话随行)维护。

**已实现于源码，真实模型与设备效果待通话验收**：语音层上下文预算为 18000 字符。执行结果表达完成后，语音层上下文只保留该结果的有界摘录（每条事实最多 600 字符，标明已截断）和已说出的口语回复，完整结果仍在原会话；一次长结果（最长 16000 字符）不应把历史和早期约束挤出预算。每轮随宿主状态提供的最近执行结论限制在 2000 字符内。表达失败时结果仍按原规则暂存待下次表达，不在上下文里留重复副本。执行中的可答进度见[执行事件与表达](#执行事件与表达)，通话恢复时的历史参考见[通话表达](通话表达.md#内置沟通提示词与听觉表达)。

## 插话、挂断与执行生命周期

### 连续说话与轮次提交

ASR 最终语段与用户整轮提交分离，但不重复支付停顿时间。已实现：续说预算统一为最后有效人声后 450ms，VAD 的 320ms 及最终识别等待计入该预算；最终结果返回时预算已耗尽则立即安排提交，否则只等待剩余时间，不再从识别完成重新等待固定 900ms。缺少采集时间的宿主兼容输入只做一次零延时可取消调度，不凭空增加等待。

新语音开始取消待发送计时，保留前句与新增文字；全部相关语段最终成功且用户当前未讲话才合并提交一次。等待中已识别文字仍属同一条未提交发言；新开口、取消、静音和挂断均使旧计时失效。原文顺序、转录标识、草稿恢复和迟到隔离沿用现有机制，不让 ASR 临时分片启动执行。450ms 是响应速度与续说保护的公共预算，不能保证任意较长停顿都不提前提交；已接纳任务后的补充仍走原插话与修订机制。

普通语音转文本不经过通话的轮次提交，独立朗读不受影响。待审批时不自动取消或批准，未发送文字可恢复；失败不迟送、不把部分识别冒充完整结果。验收覆盖快速最终结果仅等待剩余预算、慢最终结果不再等、预算内续说恰好一次交接，以及迟到结果、错误、静音、挂断和旧计时隔离。三种通话模式都沿原发送入口，增强模式保留全部转录标识，直通及 SuperAgent 成功后由原会话正式消息承接。

### 插话与取消

增强通话中，插话先停止当前语音播放和交互模型生成，原执行是否变化由用户新话语与真实回执决定。

播放期间先由本地人声概率与持续时长共同确认插话，避免近麦短促噪声立即取消回复；阈值与前卷规则统一见[降噪与流式采集](媒体管线.md#降噪与流式采集已实现真实设备待验收)，不为此增加远程决策调用，也不把降噪等同于说话意图识别。

正常插话触发的本地取消、旧通话代次或旧回复流关闭不是供应商失败，不展示 `MODEL_ERROR`。取消竞态已修正：先识别本地信号和代次，再映射供应商错误，避免把 `AbortError.code=20` 当成供应商错误码；错误携带回复标识以隔离迟到结果，同一请求的后续真实执行结果仍可表达。有效当前请求的认证、限流、断网、服务异常仍按真实分类报告。

- 寒暄、询问进度和等待期间另聊，不取消已接受执行。
- 插话会暂停执行结果的主动表达并暂存，用户下一句成功提交后恢复。这次插话没有产生有效转录（咳嗽、噪声、识别为空，或随后静音且无待发文字）时，客户端通知服务端恢复，暂存结果随即按原顺序表达，不重新执行任务。同一批结果在没有真实发言的情况下最多自动恢复两次，避免外放回声反复打断造成循环播报，此后留待用户下一句提交时表达；有界队列与溢出提示沿用[执行事件与表达](#执行事件与表达)的规则。无有效转录时的恢复已实现于源码，真实设备效果待通话验收。
- 修订、停止须发往原请求并等待执行桥回执；“停止请求已接收”不等于“执行已退出”，只有宿主确认执行终结后才说已停止。适配器不支持时明确告知，不仅口头答应。普通确认不替代工具审批。
- 挂断、断网、页面销毁和模块卸载结束媒体和交互生成，停止主动语音投递；应用内切页保持原通话，运行边界见[应用级通话与收起](通话界面.md#应用级通话与收起)。所有模式的已接受执行均遵守宿主生命周期，Voice 不因结束通话默认停止它。须核验普通会话执行在通话租约结束后可继续，不能只由任务已有后台能力推定成立。
- 未确认送达的转录绑定原 session，挂断后按[媒体管线的草稿恢复规则](媒体管线.md#配置凭据与取消)保留；不自动重试发送或开新通话。
- 再次通话时只读取原会话真实运行状态；未表达结果可供用户恢复，不自动把旧成果当作新任务再次执行。

SuperAgent 原有任务修订、停止和交付继续由自身机制维护，Voice 不复制其任务控制逻辑；相关边界见[任务与执行](../06-superagent/任务与执行.md)。

直通和 SuperAgent 模式未使用 Voice 交互桥，插话仍沿原对话协议取消当前对话生成后顺序发送新转录；待审批时保留文字并提示在原界面处理，不自动取消或批准。此处的对话生成取消不等于停止已独立执行的 SuperAgent 任务，也不能据此宣称直通模式具备增强通话的并行闲聊语义。

## 配置与源码边界

“设置 → 媒体 → 语音 → 实时通话”增加可选交互 LLM 配置，复用现有供应商、模型目录、凭据与请求服务。仅用于普通会话实时通话；不覆盖 ASR、TTS、原 Agent 或 SuperAgent 的主模型。模型 ID 原样保存，不以名称猜测能力。决策设置收在交互模型面板底部默认折叠的区域，不再是独立子标签，见[说话对象判断](说话对象判断.md)。

ASR/TTS 的自动匹配、厂商兼容边界与测试只在[媒体管线](媒体管线.md#自动匹配与测试)维护。用户点击匹配后选择并保存具体协议，通话启动直接使用相同协议，不隐式探测；未匹配或旧 `auto` 明确提示配置。普通完整转录不能作为实时流式识别，通话中不临时换协议；高级设置允许手动选择，修改一项仍保留其他媒体与交互模型配置。

交互模型请求固定使用 `reasoningEffort: 'off'`，通话启动前和每次调用均通过官方 `prepareCall` 校验，并用同一个已绑定适配器的 handle 流式请求。未声明关闭能力、不支持 `off` 或适配器改写该选择时明确拒绝增强通话，不静默回退为思考模式；普通转录、朗读与未配置交互模型的直通路径保持独立。自定义 DeepSeek 协议由供应商该精确模型的 `reasoningEfforts` 与 `compat.thinkingFormat` 显式声明，复用官方适配器将 `off` 编码为 `thinking: { type: 'disabled' }`；不根据模型 ID 自动注入协议，也不修改上游。提示词继续约束简短口语、按需交接和真实表达。

保存和重载须与实际请求一致，编辑交互项保留其他媒体设置。未配置时降级为明确标注的直通路径，定位见[会话接入](#会话接入)；已选模型不可用或不支持所需交接能力时给出具体错误、保留转录，不静默换执行模型或将未知请求再发送一遍。通话内固定已解析的交互路由，修改该路由先结束受影响通话，下次启动使用新值；无变化的保存不打断通话。

## 实现边界与验收

当前源码已按宿主会话身份选择 `native`、`enhanced`、`direct` 路径；`direct` 是未配置交互模型时的降级路径，新能力只保证 `native` 与 `enhanced`。增强路径由服务端调用所选交互 LLM，通过原会话服务提交语音层整理的任务并随行本次用户原话；请求关联、持久接收记录与会话事件用于防重和核对状态。[任务整理与原话随行](#任务整理与原话随行)、委派轮同轮接话、由模型判断的语速工具、无效插话后的结果恢复、有界的[语音层上下文](#语音层上下文)与可答进度均已实现于源码，真实模型与设备效果待通话验收。原执行 Agent、模型与工具不由 Voice 重建。直通与原生路径继续由 `conversation.send` 和 `agent-feed.mjs` 使用已有对话层。

已覆盖本地受控模型、官方 Cordis / AgentLoop / Session 接缝及客户端定向验证；这类验证不使用真实供应商音频会话。阶段成果即时表达、精确播放范围持久化仍待完善；安装版真实模型工具调用、麦克风到执行再回声的完整链路、长通话和真实设备体验须另行验收。

交付时应核验以下行为，证据留在本地 `artifacts/` 或 `eval/`，不在 docs 新建验收流水：

- 普通会话“你好”只调用交互模型；真实任务恰好交接一次，重试、未知送达和页面重连不重复执行。
- SuperAgent 主聊、旁聊不调用额外交互模型；普通工作区、Worker 与身份不可确认场景不误判，模块关闭不产生硬依赖。
- 执行模型和真实工具请求保持原配置，权限和待审批不变；轻量模型不能伪造授权。
- 委派轮已接话且交接被接受时不产生第二次生成；执行层实际收到 task 与逐字原话；无效插话后暂存结果恢复表达且不重复执行；长结果表达后语音层仍保有早期约束。
- 执行期间追问进度、闲聊、修订和停止各走正确路径；挂断清媒体且不错误停止已接受执行，迟到结果不串会话。
- 首次接话、后续进展、结果、失败与审批均按真实事件表达，原稿保留；画面与实际通话发言一致，不重复朗读。
- 交互模型缺失、慢响应、调用失败、交接不支持、事件断流均有明确状态和恢复；转录与普通朗读不受影响。
- 设置空/加载/错误/有数据四态、宽窄明暗、配置保存重载与实际路由一致；分别测量停说到最终转录、转录到首句、交接到执行、结果到首音，不用接话延迟代替任务完成速度。
