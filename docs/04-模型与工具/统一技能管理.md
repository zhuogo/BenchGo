# 统一技能管理

本模块维护“工具 → 技能”的目录、范围与管理入口；产品入口见[模型与工具设计](设计.md)。自建技能的沉淀机制属于[SuperAgent](../06-superagent/记忆与技能.md)，这里复用其管理服务，不另建存储。

## 统一技能目录与自建技能

“工具 → 技能”复用官方 `ctx.skills.list/get`，展示实际生效的用户、项目、内置和插件技能，不新增全盘扫描器，不读第三方 CLI 私有目录。

- 默认全局，可选已有项目；服务端由 `workspaceRegistry` 解析路径，按官方最近 `.git` 根规则查询，不接受任意 cwd/path。
- 使用默认 Agent 预设 standing scope，避免只查宿主全局漏项；不创建 Agent/会话，查询结束释放预设租约。
- 只返回同名最终生效项，不声称枚举被覆盖副本；按 provider 与名称关联自建项并去重。
- SuperAgent 停用仍能浏览安装技能；服务不可用与空目录分开显示。
- 文件/内置技能可看正文、复制真实路径；任意文件读取、编辑、删除、禁用或卸载不在当前范围。
- 自建项按服务返回能力展示管理操作；候选与自动沉淀的现行机制、目标和未完成边界统一见[记忆与技能](../06-superagent/记忆与技能.md)。官方提供方只暴露 active/stale。

技能页使用列表/详情切换，返回保留域、来源和搜索筛选；默认工作区展示“最近”，不改变路径和 ID。标题 24px，工具栏同排、窄屏换行，路径和技能源文保留等宽字体；加载、空、错误、重试与键盘焦点齐全。

### 技能服务契约

基础层 owner-only `POST /api/benchgo/skills` 沿用同源校验、JSON 和 no-store：

| 操作 | 契约 |
| --- | --- |
| `list { projectId? }` | 返回 `available, skills, projects, scope { projectId?, title, cwd? }`，列表不加载正文 |
| `get { projectId?, name, provider }` | 返回 `{ skill }`，只读所选注册表生效项；provider 不一致返回冲突，避免错误同名预览 |
| skill | `name, description, source, provider, path?, invocation, content?` |
| 服务缺失 | list 返回 `available:false`，get 明确失败 |

自建管理沿用 `/api/commander/assistant`，不复制持久化。OpenAPI 同步只读接口，不增加模型工具或 MCP 操作。

技能目录与外部工具的原生命令目录分开。页面说明同名优先级，候选、待整理、归档与未生效状态明确区分；详情随选择打开，不常驻空白占位。视觉基线见[前端视觉规范](../02-工作台与Agent/前端视觉规范.md)。

## 实现边界与验收

目录查询、自建候选管理和 scoped registry 接入已有实现，自建管理的待实施项随上述机制文档维护。全部安装副本枚举、第三方 CLI 私有技能目录导入和文件技能编辑/卸载不在当前范围。历史 standing-scope 验证引擎为 `571902028a`，当前引擎以根 `upstream.json` 为准，历史验证不能替代当前验收。

1. 全局与项目查询遵守最近 .git 根、默认预设作用域和项目 ID 限制；不接受任意 cwd/path，不创建会话。
2. 同名项按 provider 与名称关联；provider 冲突、服务缺失、跨源访问和正文读取按契约处理。
3. 列表、正文、冲突、失败或取消后释放预设租约；项目和正文切换时丢弃过期请求，不错显其他范围的技能。
4. SuperAgent 停用仍可浏览已安装项；自建管理遵循当前批准/拒绝、固定、历史及恢复能力，不把待实施操作展示为可用。
5. 返回保留筛选，窄屏工具栏、键盘焦点、空/加载/错误/有数据四态实际核验。历史构建与定向测试不等于浏览器交互已验收。
