# 原生工具与会话

本模块维护外部编码工具的接入、会话连续性、配置隔离和系统安装生命周期。账号与供应商认证见[模型与供应商](模型与供应商.md)，产品共同原则与主路径见[模型与工具设计](设计.md)。

## 工具设置与能力表达

每个工具页先呈现检测与登录状态，再提供常用方案和高级操作：

| 内容 | 设计约束 |
| --- | --- |
| 工具身份 | 官方入口、真实路径、安装来源、版本、重复安装及能力状态 |
| 登录 | 显示官方订阅、API Key、未登录或不可检测等真实来源 |
| BenchGo 默认方案 | 模型、推理强度、上下文/并发等已验证快捷项；高级项与原生 JSON 折叠 |
| 原生配置 | 只读显示路径、存在状态、外部变化和最近同步时间，不默认展示密钥或完整文件 |
| 会话记录 | 原生历史发现、导入、隔离目录及共享说明 |
| 高级动作 | 登录/退出、按安装来源安装/更新/卸载、恢复、同步预览及备份管理 |

卡片和会话页说明动态换模、原生恢复、实时 steer、审批问题、历史发现和隔离配置等真实能力；统一入口不承诺工具功能等价。不支持时给出替代路径，不把普通文本伪装成原生命令。

## 原生会话、连续性与记录

每个 BenchGo 会话保存 ID、工具、原生 session/thread ID、项目、模型、路由快照、模式和状态。原生会话是恢复的事实来源；BenchGo 保存索引、关联和运行事件，不伪造第二份历史。

- 同一原生会话只允许一个写入者；终端或其他客户端运行时只读观察、等待或明确接管，不静默抢占。
- 同一工具支持原生动态换模才在原会话换模；供应商、认证模式或上下文变化时创建新原生会话。
- “从某会话继续”可携带项目和用户确认的摘要/选定消息，须标识新会话，不伪装跨供应商原生上下文。
- 同工具分支复用原生 fork，不支持则明确说明；旧会话保留，可回原供应商继续。
- 历史缺失或损坏报告真实原因，不自动创建替代会话。

| 记录 | 可见性与约束 |
| --- | --- |
| 官方订阅会话 | 使用原生账号与历史目录，两端可读取同一记录 |
| 导入会话 | 建索引和句柄映射，不复制历史；原写入者必须停止 |
| API 隔离会话 | 默认在隔离目录，原工具不会自动看到；打开/导出/共享须说明范围和并发限制 |
| BenchGo 事件 | 用于状态、审批、短期回放，不替代原生长期历史 |

删除列表项、归档会话、删除原生历史、删除项目文件是四个操作，不能合并为一个“删除”。跨工具摘要迁移、隔离记录向原工具打开/导出的完整路径仍待实施或完善。

## 配置隔离与显式同步

默认通过进程环境、命令行覆盖或每会话隔离目录注入配置，如 Codex 的 `CODEX_HOME`、Claude Code 的 `CLAUDE_CONFIG_DIR`。隔离配置，不复制可执行文件；正常使用不修改用户终端工具的账号、默认模型、插件、全局配置或历史。

```text
显式同步：展示文件、字段、影响范围与校验和 → 备份 → 用户确认
         → 写前复查外部变化 → 应用 → 重新读取验证
```

冲突拒绝覆盖，恢复使用逆向备份。同步后记录校验和与时间，后续提示外部修改，不自动合并或写回。BenchGo 不与其他管理器后台双向同步，谁执行显式同步谁负责该次写入。

## 系统工具生命周期

管理系统真实安装，不复制可执行文件，不维护专用安装前缀或副本凭据。探测返回命令解析后的真实路径、版本、来源、平台、可执行性与登录状态；重复安装全部列出，标记命中项、优先级和冲突。

- 安装、更新、卸载绑定已识别来源和具体实例；未知来源只读，不用裸 `npm install` 猜测替代。
- 当前已有 npm、uv、Homebrew 探测与操作；官方安装器、自更新命令及更多平台管理器按能力清单接入。
- npm 系列复用对应 Node/包管理器，Homebrew 绑定 formula/cask，uv 绑定原环境。前后重新探测，版本未变或路径异常报告失败/冲突。
- 卸载先预览路径、来源、包名/公式、命令和保留范围，确认后复查路径、版本和来源；归属不明、外部变化或权限不足时拒绝。
- 卸载只移除安装，保留账号/OAuth、配置、历史、插件、项目和 BenchGo 索引；官方清理数据动作单独展示确认。
- 操作具备互斥、超时、取消与幂等收据；完成刷新目录、登录和能力，不静默提权。
- Windows、macOS、Linux、WSL 按环境区分路径与实例，不跨环境卸载；权限不足给官方命令或系统授权入口。

BenchGo 只保存会话索引、原生句柄、路由快照、幂等收据、短期事件和备份元数据；凭据由已有凭据服务或对应工具管理。不读取 CC Switch 私有状态，不创建工具独立副本。

## 实现边界与参考依据

已有基础：Codex、Claude Code、Pi、OpenCode 原生接入、索引/句柄、按会话 API 路由、配置预览/备份/显式应用/恢复、工具探测、用量扫描、历史读取与原生 fork。实际能力按运行检测。

待补齐跨工具新会话与摘要迁移、隔离记录完整导出、更多安装来源，以及真实 Windows 全新安装、权限、WSL 和多工具并行验收。统一登录发起的边界见[模型与供应商](模型与供应商.md)。历史定向测试不代表当前版本或这些环境已验收。

CC Switch 仅只读参考：历史设计依据 `reference/cc-switch@7da2553`，文档校对时检出为 `300453be2ea33ca9785b9313fb0b109846a6079c`，不可互换为验证版本，不参与依赖或构建。

## 验收条件

1. 新用户可发现、安装/接入至少一个工具并完成首轮会话；已有终端命令、账号、模型、配置和历史继续可用。
2. 同一原生会话仅一个写入者；旧会话可恢复，跨工具继续明确标注新会话，缺失历史不被替代会话掩盖。
3. API 会话隔离配置，默认保存方案不写原生全局配置；记录可见性、共享和导出边界清楚。
4. 显式同步具备预览、校验和、备份、外部变化拒绝和恢复验证；原生配置写入同步更新文案、冲突验证及工具兼容说明。
5. 生命周期按来源且前后探测，卸载先预览并复查归属，保留账号、配置、历史、项目与索引；跨环境、未知来源和归属异常被拒。
6. OpenAPI/MCP 的工具状态、安装计划与生命周期结果和真实路径、版本、来源一致；各工具差异及 Windows/macOS/Linux/WSL 边界明确。
