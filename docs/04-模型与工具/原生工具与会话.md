# 原生工具与会话

本模块维护外部编码工具的接入、会话连续性、配置隔离和系统安装生命周期。账号与供应商认证见[模型与供应商](模型与供应商.md)，产品共同原则与主路径见[模型与工具设计](设计.md)。

## 工具设置与能力表达

设置 → Harness 工具按设置面板宽度排列卡片，桌面每行两到三张，窄屏单列。卡片显示品牌、名称及版本，可用性决定品牌色。安装保留文字按钮，更新、卸载与工具配置使用带悬停和键盘提示的图标按钮。路径、安装来源和重复实例由后台解析，维护操作按需展示目标、进度与失败原因。

产品接入范围为有可自动化 CLI 协议的编码或底层 Harness。Claude Desktop、OpenClaw 和 Hermes 退出 BenchGo 工具目录及新建路由，现有系统安装、配置与历史保留。首批外部执行验收 Codex 和 Claude Code，其余编码 CLI 在工具探测、API 隔离与对应入口验证后开放。工作台按驱动能力显示换模、恢复、实时追加、附件和提问。

## 调度边界

工作台提交绑定了原生工具的会话输入，经官方 Harness 适配器交给 Commander。Commander 根据项目、工具、模型绑定和会话归属启动或续接原生会话，核对权限，按 `requestId` 去重普通消息，并回传活动、审批与完成事件。协议驱动负责进程和会话通信，Codex 使用 App Server 的 stdio JSON-RPC，Claude Code 使用 Agent SDK，兼容 ACP 的工具复用 ACP 驱动。

工作台统一通过官方会话创建入口和共享 API 模型目录建立绑定。已委派的子会话可以用原 API 路由接入同一项目中的独立对话。

会话内委派使用 `commander_delegate`，在同一项目启动子会话。首次默认最多等待 55 秒，运行中的结果凭子会话 ID 查询。创建子会话前持久去重，父轮取消传给对应子执行。

工作台普通聊天与 [SuperAgent Worker](../06-superagent/任务与执行.md#worker-与官方-subagents)复用 Commander 的原生会话能力。普通聊天校验直接用户消息，Worker 通过受信任的工单执行入口携带已冻结要求、执行身份、项目和路由。驱动报告文本、活动、提问、结束和真实停止状态，调用方按自身职责保存事件和结果。

## 原生会话、连续性与记录

每个 BenchGo 会话保存 ID、工具、原生 session/thread ID、项目、模型、路由快照、模式和状态。原生会话是恢复的事实来源；BenchGo 保存索引、关联和运行事件，不伪造第二份历史。

- 同一原生会话只允许一个写入者；终端或其他客户端运行时只读观察、等待或明确接管，不静默抢占。
- 同一工具及供应商下，驱动支持动态换模才在空闲原会话切换。切换工具或供应商进入新会话，原记录仍可访问。Worker 执行按工单冻结的绑定恢复。
- “从某会话继续”可携带项目和用户确认的摘要/选定消息，须标识新会话，不伪装跨供应商原生上下文。
- 同工具分支复用原生 fork，不支持则明确说明；旧会话保留，可回原供应商继续。
- 历史缺失或损坏报告真实原因，不自动创建替代会话。

| 记录 | 可见性与约束 |
| --- | --- |
| 历史订阅会话与退役工具记录 | 保留原始数据。使用 BenchGo 执行时需新建会话并选择可用的 API 组合 |
| 导入会话 | 建索引和句柄映射，不复制历史；原写入者必须停止 |
| API 隔离会话 | 默认在隔离目录，原工具不会自动看到；打开/导出/共享须说明范围和并发限制 |
| BenchGo 事件 | 用于状态、审批、短期回放，不替代原生长期历史 |

删除列表项、归档会话、删除原生历史、删除项目文件是四个操作，不能合并为一个“删除”。跨工具摘要迁移、隔离记录向原工具打开/导出的完整路径仍待实施或完善。

支持工具调用的原生会话通过 `assistant_server_ssh` 使用当前宿主的设备登记。工具核对当前用户指令，以设备 ID 解析目标并返回执行结果。与现有原生 Agent 命令调度的分工见[本机 AI 运维](../01-设备与远程连接/SSH服务器运维.md#本机-ai-运维)。

## 会话权限

BenchGo 启动的外部 Harness 默认使用 Full access 和无需工具审批的模式，覆盖工作台、本机 Worker 与跨设备 Worker。驱动以原生参数表达该模式，执行仍受系统账号权限约束。项目目录是进程的工作起点。无法落实运行权限或工单要求时返回具体限制。已有会话的已保存权限、待审批、Link 授权、业务许可和真实提问继续按原有身份及规则处理。

## 隔离配置与工具选项

工具卡片负责安装、更新和卸载。模型选择器提供所选模型与工具共同支持的推理档位。新建隔离会话默认开启 Codex 多代理和 Claude Code 代理团队。Codex 沿用数值范围兼容的 Harness 子代理并发和委派深度，以及模型声明的上下文窗口。其他参数沿用原生默认。已有会话恢复时使用保存的运行快照。普通对话切换模型或档位后，下次请求使用新选择，必要时重新连接原生会话。

API 会话使用隔离目录，例如 Codex 的 `CODEX_HOME` 和 Claude Code 的 `CLAUDE_CONFIG_DIR`。使用系统现有可执行文件，API 凭据只在执行时注入。工具选项与会话配置只写 BenchGo 管理目录，终端工具的原生配置及历史由原工具管理。

## 系统工具生命周期

管理系统真实安装，后台探测实际可执行入口、版本、来源、平台与重复实例。目录、版本探测及会话启动使用同一套启动解析。

- 安装、更新、卸载绑定已识别来源和具体实例；未知来源只读，不用裸 `npm install` 猜测替代。
- 当前已有 npm、uv、Homebrew 探测与操作；官方安装器、自更新命令及更多平台管理器按能力清单接入。
- npm 系列复用对应 Node/包管理器，Homebrew 绑定 formula/cask，uv 绑定原环境。前后重新探测，版本未变或路径异常报告失败/冲突。
- 卸载先预览路径、来源、包名/公式、命令和保留范围，确认后复查路径、版本和来源；归属不明、外部变化或权限不足时拒绝。
- 卸载只移除安装，保留账号/OAuth、配置、历史、插件、项目和 BenchGo 索引；官方清理数据动作单独展示确认。
- 操作具备互斥、超时、取消与幂等回执。完成后重新探测并刷新执行目录。
- Windows、macOS、Linux、WSL 按环境区分路径与实例，不跨环境卸载；权限不足给官方命令或系统授权入口。

BenchGo 持久化会话索引、原生句柄、路由快照、高级配置、幂等回执与运行事件，复用现有凭据服务。

## 实现边界与参考依据

源码已接通工具卡片、共享 API 路由、隔离工具配置、统一启动解析、委派去重与取消，以及本机和跨设备 Worker。Windows 已实测 Codex 和 Claude Code 的版本启动入口。真实 API 与双设备由对应模块验收。跨工具摘要迁移和隔离记录导出仍需单独设计与验证。

CC Switch 仅只读参考，设计依据固定为 `reference/cc-switch@7da2553`；参考仓库不参与产品依赖或构建，其他检出版本不自动替代本设计依据。

## 验收条件

1. 新用户可发现、安装/接入至少一个工具并完成首轮会话；已有终端命令、账号、模型、配置和历史继续可用。
2. 同一原生会话只有一个写入者，按原句柄恢复。跨工具新开会话，历史缺失明确报错。重复委派执行一次，取消回执对应实际停止。
3. API 会话和工具配置 仅写入 BenchGo 管理范围，保存、重载和实际启动一致。无效或覆盖保留项的配置有明确反馈。
4. 工作台和本机、跨设备 Worker 的外部执行均验证 Full、真实提问和取消，且使用执行设备对应的 API 绑定。
5. 生命周期按来源且前后探测，卸载先预览并复查归属，保留账号、配置、历史、项目与索引；跨环境、未知来源和归属异常被拒。
6. OpenAPI/MCP 的工具状态、安装计划与生命周期结果和真实路径、版本、来源一致；各工具差异及 Windows/macOS/Linux/WSL 边界明确。
