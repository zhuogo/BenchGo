# 模型与供应商

本模块维护账号来源、供应商路由和模型参数。供应商 ID、模型 ID 与协议值的共同规则见[模型与工具设计](设计.md#职责与基本约束)；原生会话切换、隔离与恢复见[原生工具与会话](原生工具与会话.md)。

## 共享 API 目录与执行选择

模型页集中维护供应商 ID、端点、凭据引用、协议和模型 ID。各 Harness 从这份 API 目录取用配置；外部 CLI 的原有账号和配置由工具自行管理。BenchGo 内的外部 Harness 新执行统一使用模型页 API，退出现有官方订阅入口及供应商「适用工具」勾选。

- 工作台和 Worker 通过共享执行目录按「Harness → 供应商 → 模型」选择。目录包含执行设备上实际可启动、协议匹配且具备所需能力的组合，未满足的条件提供明确原因。Router 和辅助请求固定走官方 Harness，界面只选供应商和模型。
- 普通对话使用供应商配置的协议。RouterGo 默认使用 Responses，账号同步保留显式设置。Codex 直连 Responses，Claude Code 直连 Anthropic Messages，媒体走对应的生成接口。RouterGo 模型选择和请求入口按账号声明检查协议可用性。按模型自动选择协议待实施，优先顺序为 Responses、Chat Completions、Anthropic Messages。
- 目录只返回标识、能力和可用状态。原始协议值和模型 ID 完整传递，预检及启动再次核验。会话绑定保存工具、供应商、模型、协议、端点、凭据引用和必要配置版本，密钥仅在执行设备运行时读取。
- 恢复沿用原绑定。配置失效时返回具体原因。旧「适用工具」和默认方案退出新执行路由，既有 API 会话按原绑定恢复，旧订阅会话保留历史与原生句柄，界面引导使用 API 新建会话。

### 厂商模板与供应商连接

在「设置 → 模型 → 添加供应商」搜索并选择厂商，填写连接名称、API 地址和密钥，再通过上游目录或手动输入添加模型。目录发现时由用户确认导入范围，保存原始模型 ID。已配置的连接在模型页列表编辑。同一厂商可创建多条连接，每条使用独立的路由 ID、凭据引用和模型列表。

添加菜单使用一份 BenchGo 厂商目录，同一网格包含 21 个模板和自定义供应商入口。已配置的官方连接继续在列表编辑。OpenAI 预填 Responses，Anthropic 预填 Messages，Google Gemini 预填 Gemini 原生协议，其余模板预填 Chat Completions。Meta 使用 Meta Model API，OpenCode 使用 Console 的 Chat Completions 接口，New API 和 Sub2API 由用户填写部署地址。官方百炼域名填写根地址时补齐 `/compatible-mode/v1`，填写完整路径时沿用该路径。其他厂商和自定义连接沿用填写的地址。

每条模板连接通过官方 Harness 的 pi-ai 自定义路由保存，路由 ID 由 BenchGo 生成并关联厂商品牌。厂商目录随 `benchgo-plugin` 装配，密钥通过官方凭据服务写入。模型发现取决于上游目录，具体协议和型号能否调用取决于账号和端点。视频生成和 TypeSafe 接入待实施。

### RouterGo 内置身份

共享供应商 ID 为 `routergo`，展示名 RouterGo，默认地址 `https://routergo.cn/api/v1`，默认对话协议为 `openai-responses`。品牌素材来自 XiaoJiao VI 1.0.0，随包发布。已有手填连接保留原地址、协议、模型和凭据。可配置的「API 协议」直接显示在新增和编辑表单中。

内置入口省去路由 ID、展示名等重复输入，运行仍用官方 pi-ai 已声明路由机制，不冒充上游原生目录成员，不增加引擎补丁；其他自定义供应商不变。

模型页可以移除已有 DeepSeek 官方 API 连接。移除仅断开该路由的凭据引用，原模型参数和可能在别处使用的旧凭据保留。

### 供应商选择器的品牌与排序

工作台会话、SuperAgent 资源 → 模型（身份、工作、辅助和备用项）、媒体 → 媒体生成（图片、视频、音频）、媒体 → 语音（识别、朗读、通话模型），以及模型设置中的供应商选择入口，已统一采用以下规则。其他设备上的同类选择器应用同一规则。

- 选项与已选值都显示供应商品牌标志。复用基础层 `ProviderBrandIcon` 和随包品牌目录，有官方彩色版本就用彩色版本，RouterGo 使用正式彩色方标。无品牌素材的自定义供应商用名称首字母。品牌只按已知 ID 和目录声明解析。用禁用状态和原因文本区分不可用，品牌标志不随选中态改色；工具安装和可用性标识继续按视觉规范处理。
- 供应商列表将精确 ID `routergo` 固定在第一行，搜索时固定行仍保留，其余结果按原规则筛选和排序。未配置、目录不可用或当前能力无兼容模型时，固定行显示实际原因，已有配置入口可以复用。独立配置、手动输入、使用原会话等保留为单独操作，排在固定行之后。
- 置顶属于展示规则。进入、刷新和搜索都保留当前已选值，保存后的首选和备用队列、实际能力筛选及请求路由沿用各模块规则。先复用基础层品牌组件和一处共享排序逻辑，各入口保留自己的领域校验。

### RouterGo 账号授权

模型页顶部常驻 RouterGo，分割线下展示恒为品牌色的标志和名称，两者带外链标识并可前往 RouterGo 官网。未配置时，品牌行右侧并排显示「登录」与「使用密钥」的图文按钮。已有可用手填凭据直接使用供应商编辑器。账号模式突出连接账号和可用余额，余额刷新使用带提示的图标按钮，充值和模型同步使用图文按钮。刷新失败时保留上次可用余额，具体错误通过短暂浮层反馈；等待授权时可重新打开授权页或取消。充值跳转 RouterGo 的 `/workbench/recharge`。登录绑定属于执行设备，由该设备持有模型凭据。

BenchGo 服务端向 RouterGo 自定义服务申请短期设备授权。已有 RouterGo 会话时直接确认，首次进入时沿用站内登录并回到授权页。RouterGo 复用已有可用的「BenchGo 专用」，有空余密钥名额时自动创建专用密钥。名额已满且无可用专用密钥时，可选择现有密钥，或前往密钥管理腾出名额再回来刷新。设备秘密、账号查询令牌和模型调用密钥通过 BenchGo 服务端交接。余额查询令牌与推理密钥用途独立，模型推理继续通过当前供应商协议使用 API 密钥。

首次连接以账号的 `/models` 返回为导入范围，原样保存可调用的模型 ID。公共资料库按原始 ID 补齐缺失元数据；保留用户已编辑的模型字段和其他供应商配置。既有自定义地址和手工凭据由用户明确选择后变更。保存冲突或目录失败可以重试，界面显示真实连接状态。

登录后由账号管理显示名称、官方 API 地址、默认协议和凭据。模型编辑入口只显示模型设置。需要手填 API 密钥时，先删除账号连接，再通过「使用密钥」添加。已有账号在成功同步时更新连接字段。账号模式启动时及每 60 秒同步可调用模型，进入或返回模型页也会触发检查，用户可以立即同步。同步按原始 ID 导入新增模型和更新仍由目录管理的字段。下架时移除未改动且无能力覆盖的自动导入条目。手工条目、字段和删除操作保留。同步失败时使用最近一次目录。

#### 站内连接页品牌图

RouterGo `/benchgo/authorize` 的双品牌插图采用等宽品牌列和中间连接列，两侧正式图标保持原始宽高比，按可见主体做等重对齐，品牌名基线一致。中间红绿线共用连续路径与同一笔宽，颜色在居中状态章后交接，边缘无错位或断缝。图标与连接列在窄屏同步收缩，保留两品牌和状态章的可辨性。反馈图标沿用真实授权状态。

### 模型能力标签

媒体目录从账号的 `/models` 接口读取候选型号。普通连接中手工配置的型号即使未出现在上游目录中，仍能通过能力标签进入对应目录。RouterGo 的 `capabilities` 和 `media_constraints` 提供操作能力和约束，公开目录按原始 `model_id` 精确补充模态、思考档位和缺失的长度数据。账号条目中更具体的能力优先。通用端点可提供结构化任务或模态字段，模型 ID 和显示名作为不透明标识。

点击模型选项内的能力标签即可选中或取消，并立即保存。BenchGo 按供应商 ID 和原始模型 ID 保存显式覆盖，空覆盖表示清除全部标签。能力覆盖的读取和保存可在供应商目录加载期间操作，写入失败时恢复上次的选择。视觉理解通过文本模型的「输入类型 → 图片」配置。语音识别和语音合成的标签用于筛选，执行仍需选择对应服务支持的协议。百炼原生语音协议待接入。

### 公开模型参数

已有和新增模型读取固定公共目录 `https://routergo.cn/api/x/public/models`，只按顶层 `model_id` 精确匹配。浏览器经 `/api/commander/tooling` 的只读 `modelProfiles` 操作请求。

- 用户明确保存的选择继续生效。其余字段按公开目录、引擎默认值的顺序解析输入类型、思考档位、上下文窗口和最大输出。
- 能力标签「文本」统一原「聊天」和「Responses」，旧配置读取时自动归一。供应商声明的协议用于执行路由，协议设置中的 Responses 显示为「OpenAI 响应」。
- 仅启用「文本」能力的模型展示对话输入，顺序为 PDF、音频、视频、图片、文本。文本必选，图片可同步和编辑，PDF、音频和视频按目录声明显示只读勾选状态。媒体模型通过各自接口处理输入。
- RouterGo Responses 已实测 `gpt-6.2-sol` 可读原生 PDF。当前官方引擎把 PDF 作为文件引用交给模型，原生 PDF、音频和视频发送待接入。
- 思考档位按模型声明保存，`off` 只在明确提供或手动配置时可用。用户可将供应商的自定义值映射到引擎档位，具体请求按适配器协议编码。
- 会话恢复与模型配置更新时，按现行模型能力清理已失效的档位，后续发送沿用同一模型的现行默认行为。
- 模型目录按大语言、图片生成与编辑、语音、知识库和视频筛选。搜索匹配显示名称、原始 ID 和能力，图片输入可通过能力词搜索。模型默认收起，同一目录一次展开一项，切换时保留编辑草稿。手动添加会展开新模型。目录宽度决定卡片列数，草稿排序随保存生效。
- 目录第一行放模型分类、搜索和保存，第二行放模型厂商图标筛选、同步模型和上下文窗口优化。通用连接在当前目录内显示同步候选，勾选后更新草稿，再保存。DeepSeek 原生连接用已配置连接读取目录，按原始 ID 补充缺失的模型。RouterGo 账号同步立即更新其托管目录，完成后刷新当前目录。
- 添加和保存独立于外部目录请求。迟到的响应按当前模型 ID 和字段状态合并。

公共目录通过既有工具服务访问，OpenAPI 同步描述只读 `modelProfiles` 操作，不增加 MCP 工具。品牌素材随包发布，不依赖远程图片；供应商查询与设置保持一致品牌身份。

### 上下文窗口与重试策略

模型目录的标价图标打开当前连接的上下文建议。弹窗按原始型号列出当前值、建议值和原因，「应用到草稿」后通过目录的「保存」提交。公开或发现的容量达到 100 万时建议取一半。确认有长上下文计费档的 OpenAI 直连型号建议使用 272,000。建议只下调上下文，同时给最大输出和默认压缩策略留出空间。300K 至 400K 型号沿用公开容量或用户配置。

模型请求采用引擎的仅临时错误重试，默认最多重试 5 次。BenchGo 通过官方设置服务清理旧的逐连接覆盖，保留连接的其他配置。

### 配置页加载与刷新

配置页继续使用官方 controller、设置版本与凭据写入通路，厂商模板按官方实现 `2e39e70496aa02986ca6a820c5d497e816b69d7e` 验证。首次加载复用[共享文字动效](../02-工作台与Agent/前端视觉规范.md#四态)，后台刷新保留内容与草稿。旧刷新及卸载后的结果作废。

模型页 CSS 随客户端作用域挂载、计数与释放，重挂时重新确保样式存在，不依赖模块重新求值。模块可用性探测遇到网络、超时或服务暂时错误时保留最后确认的界面并重试；明确停用、入口不存在或失去访问权限仍卸载对应界面。

选择器复用工具服务已核验的启动能力和当前配置，完整安装来源探测留在工具服务。服务端并发读取供应商身份，目录请求共享在途构建，后续选择和启动继续校验当前配置与凭据。

客户端共享 30 秒有效的成功缓存和在途请求，有效期内重新打开选择器不重复拉取目录，置顶仅更新本地排序；供应商设置、凭据及连接变化使缓存失效，手动重试发起新读取。失败不写入成功缓存，过期响应不得覆盖新目录，后台刷新保留内容与草稿。此机制仅优化目录展示，实际选择和请求仍走原校验通路，不改变模型 ID 或认证边界。

### 配置写入保护

BenchGo 的 profile 与 home 补丁由 Router 通过 `assistant_settings` 的官方读取、准备和提交事务修改。Desktop 启动前及工具执行前后复用 YAML 结构校验和权限为用户私有的最近有效原始快照；发现写坏时先保留拒绝内容，再原子恢复，并将本次操作报告为失败。缺少有效快照时不清空或猜测配置，停止启动并明确报错。Worker 仅负责连接探测、只读检查和实际请求验证。提示与运行时守护可减少误操作与数据丢失；保留任意权限 shell 时，应用内守护不构成操作系统级写入隔离。

## 实现边界与验收

源码已实现共享 API 目录、按协议筛选和隔离的 Codex、Claude Code 会话路由。RouterGo 管理账号复用一个连接，按调用方选择原生端点。逐模型的 Messages 可用性由供应商实际请求确认。

1. 选择、保存、重载与实际请求一致，单项修改保留其他配置，显式选择优先；普通重渲染、保存、删除或离开不会被过期补全结果覆盖。
2. 模型页只维护一份 API 配置。兼容组合可选，缺少协议、凭据或工具时能定位原因。BenchGo 新执行始终使用绑定的 API 凭据。
3. 已创建 API 会话按原绑定恢复，失败明确指出原因。旧订阅会话保留历史并提供 API 新建路径。
4. RouterGo 已有自定义连接和模型选择保留。公开目录精确匹配 ID 并优先于引擎默认参数，目录故障时可继续添加和保存。
5. 密钥不进入前端响应、会话列表、日志或原生历史；公共参数目录不转发凭据、不接受任意 URL。

6. RouterGo 账号授权覆盖首次配置、已有凭据、拒绝、过期和目录读取失败。分别验证授权后模型读取、凭据保存和重载、充值跳转与实时余额，并核对手填 API 密钥入口可独立使用。同步验证精确 ID 新增、字段更新、下架、手工修改和目录故障恢复。
7. 供应商选择器统一后逐入口验证空、加载、错误、有数据四态，以及搜索、键盘、窄屏和明暗主题。验证 RouterGo 配置前后都位于首行、原因准确、同名自定义供应商不被置顶、原有选择保存和重载一致，代表性请求使用保存的原始供应商与模型 ID。
8. 使用百炼北京工作空间根地址发现并显式选择模型，保存后重载，验证兼容地址与原始模型 ID 发往上游。按同一厂商创建两条连接，编辑其中一条并核对另一条的地址、凭据引用与模型列表。模拟配置已保存但凭据写入失败，验证重试只写入凭据。
