# 模型与供应商

本模块维护账号来源、供应商路由和模型参数。供应商 ID、模型 ID 与协议值的共同规则见[模型与工具设计](设计.md#职责与基本约束)；原生会话切换、隔离与恢复见[原生工具与会话](原生工具与会话.md)。

## 账号、供应商与模型

选择器区分 Codex 官方订阅、Claude Code 官方订阅、第三方 API 供应商，保留真实来源。

- 官方订阅由对应工具认证和请求；不复制 OAuth、不转换通用 API Key、不跨工具使用。
- 未登录、失效或账号类型不匹配时拒绝创建会话，指向对应官方登录路径。
- API 供应商保存 ID、端点、凭据引用、模型和协议能力；密钥不进入前端响应、列表、日志或原生历史。
- 会话创建固化供应商、模型、协议和认证模式；修改默认方案不改变旧会话。
- SuperAgent 目标设计按 Router 对话、Worker 工作、辅助三角色取系统模型配置；执行会话归入项目或“最近”工作区不改用项目默认模型，既有执行会话续跑保留创建时的模型。子代理模型归属与当前实现差异统一见[模型与上下文](../06-superagent/模型与上下文.md)，不能由工作区归属推定已实现。
- 恢复时重新核验路由和订阅，失效报告原因，不静默切换供应商。
- 当前可检测订阅状态并引导回 CLI 登录；BenchGo 内统一发起 Codex/Claude 登录仍待完善，不能宣称统一 OAuth 已接通。

### RouterGo 内置身份

共享供应商 ID 为 `routergo`，展示名 RouterGo，默认地址 `https://routergo.cn/api/v1`，协议 `openai-completions`。品牌素材来自 XiaoJiao VI 1.0.0，随包发布。已有同 ID 配置直接复用，不覆盖自定义地址、协议、模型或迁移凭据。

内置入口省去路由 ID、展示名等重复输入，运行仍用官方 pi-ai 已声明路由机制，不冒充上游原生目录成员，不增加引擎补丁；其他自定义供应商不变。

### 新增模型的快捷参数

新增模型读取固定公共目录 `https://routergo.cn/api/x/public/models`，只按顶层 `model_id` 精确匹配。浏览器经 `/api/commander/tooling` 的只读 `modelProfiles` 操作请求，不转发供应商密钥，不接受自定义 URL。

- 只补缺失的上下文窗口、最大输出、引擎支持输入类型和思考档位；未知保持空，不增加 `off`，不覆盖手动值。
- 页面复用一次成功请求，失败允许后续新增重试；服务端 15 秒、客户端 18 秒超时，不增持久缓存、服务或定时任务。
- 合并草稿，添加和保存不等待目录；保存、删除、离开或编辑后的过期结果不能回写。
- 有效性按模型内容判断，普通重渲染不能取消匹配。
- 不增加匹配按钮或成功/失败提示；无“恢复默认模型”入口，思考继承文案为“使用引擎默认配置”。

公共目录通过既有工具服务访问，OpenAPI 同步描述只读 `modelProfiles` 操作，不增加 MCP 工具。品牌素材随包发布，不依赖远程图片；供应商查询与设置保持一致品牌身份。

## 实现边界与验收

订阅状态识别、工具边界、第三方 API 按会话路由、RouterGo 内置身份与新增模型参数补全已有实现基础。统一发起 Codex/Claude 官方登录仍需完善，真实供应商请求必须单独验证。

1. 选择、保存、重载与实际请求一致，单项修改保留其他配置，显式选择优先；普通重渲染、保存、删除或离开不会被过期补全结果覆盖。
2. 订阅显示真实工具来源，未登录或类型不符拒绝创建；不泄露 OAuth，不把订阅转换成 API Key 或跨工具使用。
3. 默认方案修改不改变已创建会话，恢复失败给出真实原因，不静默切换供应商。
4. RouterGo 已有自定义地址、协议、模型和凭据保留；模型目录只精确匹配 ID、补缺失值，失败不阻塞添加和保存。
5. 密钥不进入前端响应、会话列表、日志或原生历史；公共参数目录不转发凭据、不接受任意 URL。
