## 职责与基本约束

BenchGo 发行包集成官方 DeepSeek Harness；用户无需另装底座，但运行仍依赖官方引擎。Harness 聚合复用 Codex、Claude Code、Pi、OpenCode 等系统原生工具的协议、上下文和历史，不创建另一套原生工具副本。

基础层负责共享供应商、模型、工具目录与设置；Harness 聚合负责原生会话运行、审批与事件。模型设置属于产品层，Agent 委派属于会话层，通过明确服务契约连接。CC Switch 等管理器可共存，不是产品依赖。

- 供应商 ID、模型 ID、工具名与协议值是不透明标识，不猜别名、不静默改写。
- 显式模型选择优先于默认方案；选择、保存、重载和实际请求须一致。
- 修改单项保留其他模型、路由和快捷参数；重复选择当前项不清空设置。
- 已安装且可用用品牌色，不可用用灰色；选中使用中性底色，不改变可用性含义。
- 不支持的能力明确提示；检测到配置文件不等于已登录，普通文本不伪装原生命令。
- 不改官方源码，优先复用插件、服务、配置和成熟原生接口。

## 用户路径与页面职责

```text
安装 BenchGo → 探测系统工具 → 选择/创建项目
→ 选择工具、账号或供应商、模型 → 检查能力 → 开始会话
```

工作台负责项目和会话：选择工具模型、消息与工具活动、审批、停止、恢复、归档和继续工作。设置是工具与模型配置的唯一用户入口：

| 区域 | 展示与操作 |
| --- | --- |
| 外部工具 | 真实路径、来源、版本、重复安装、登录与能力；常用方案和原生入口 |
| 供应商与模型 | 端点、凭据引用、协议、模型目录和适用工具 |
| 订阅账号 | 对应工具官方登录状态与登录/退出路径 |
| 会话记录 | 发现范围、导入规则、隔离目录和共享说明 |
| 高级同步 | 修改预览、校验和、备份、显式应用与恢复 |
| 技能 | 全局/项目生效技能、自建技能和候选管理 |

工具页先显示检测与登录状态，再显示常用参数，高级快捷项和原生 JSON 折叠展示。“保存 BenchGo 方案”和“同步到本机工具”必须明确区分。

## 跨模块验收

新用户应能从工具发现和模型选择进入首轮会话；已有终端账号、配置、模型与历史不变。各模块按自己的契约验证，空、加载、错误、有数据四态与失败替代路径实际可用；定向测试、真实供应商请求与真实设备验收分别报告。
