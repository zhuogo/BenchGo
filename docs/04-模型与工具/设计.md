# 模型与工具设计

本板块统一管理供应商、模型、外部编码工具、原生会话路由和技能目录。总体关系见[总架构](../总架构.html)，界面规范见[工作台与 Agent](../02-工作台与Agent/设计.md)。本文保留已定体验与实现边界，不以目标能力代替当前可用性。

## 1. 职责与基本约束

BenchGo 发行包集成官方 DeepSeek Harness；用户无需另装底座，但运行仍依赖官方引擎。Harness 聚合复用 Codex、Claude Code、Pi、OpenCode 等系统原生工具的协议、上下文和历史，不创建另一套原生工具副本。

基础层负责共享供应商、模型、工具目录与设置；Harness 聚合负责原生会话运行、审批与事件。模型设置属于产品层，Agent 委派属于会话层，通过明确服务契约连接。CC Switch 等管理器可共存，不是产品依赖。

- 供应商 ID、模型 ID、工具名与协议值是不透明标识，不猜别名、不静默改写。
- 显式模型选择优先于默认方案；选择、保存、重载和实际请求须一致。
- 修改单项保留其他模型、路由和快捷参数；重复选择当前项不清空设置。
- 已安装且可用用品牌色，不可用用灰色；选中使用中性底色，不改变可用性含义。
- 不支持的能力明确提示；检测到配置文件不等于已登录，普通文本不伪装原生命令。
- 不改官方源码，优先复用插件、服务、配置和成熟原生接口。

## 2. 用户路径与页面职责

```text
安装 BenchGo → 探测系统工具 → 选择/创建项目
→ 选择工具、账号或供应商、模型 → 检查能力 → 开始会话
```

工作台负责项目和会话：选择工具模型、消息与工具活动、审批、停止、恢复、归档和继续工作。设置是工具与模型配置的唯一用户入口：

| 区域 | 展示与操作 |
| --- | --- |
| 外部工具 | 真实路径、来源、版本、重复安装、登录与能力；常用方案和原生入口 |
| 供应商与模型 | 端点、凭据引用、协议、模型目录和适用工具 |
| 订阅账号 | 对应工具官方登录状态与登录/退出路径 |
| 会话记录 | 发现范围、导入规则、隔离目录和共享说明 |
| 高级同步 | 修改预览、校验和、备份、显式应用与恢复 |
| 技能 | 全局/项目生效技能、自建技能和候选管理 |

工具页先显示检测与登录状态，再显示常用参数，高级快捷项和原生 JSON 折叠展示。“保存 BenchGo 方案”和“同步到本机工具”必须明确区分。

## 3. 账号、供应商与模型

选择器区分 Codex 官方订阅、Claude Code 官方订阅、第三方 API 供应商，保留真实来源。

- 官方订阅由对应工具认证和请求；不复制 OAuth、不转换通用 API Key、不跨工具使用。
- 未登录、失效或账号类型不匹配时拒绝创建会话，指向对应官方登录路径。
- API 供应商保存 ID、端点、凭据引用、模型和协议能力；密钥不进入前端响应、列表、日志或原生历史。
- 会话创建固化供应商、模型、协议和认证模式；修改默认方案不改变旧会话。
- 恢复时重新核验路由和订阅，失效报告原因，不静默切换供应商。
- 当前可检测订阅状态并引导回 CLI 登录；BenchGo 内统一发起 Codex/Claude 登录仍待完善，不能宣称统一 OAuth 已接通。

### RouterGo 内置身份

共享供应商 ID 为 `routergo`，展示名 RouterGo，默认地址 `https://routergo.cn/api/v1`，协议 `openai-completions`。品牌素材来自 XiaoJiao VI 1.0.0，随包发布。已有同 ID 配置直接复用，不覆盖自定义地址、协议、模型或迁移凭据。

内置入口省去路由 ID、展示名等重复输入，运行仍用官方 pi-ai 已声明路由机制，不冒充上游原生目录成员，不增加引擎补丁；其他自定义供应商不变。

### 新增模型的快捷参数

新增模型读取固定公共目录 `https://routergo.cn/api/x/public/models`，只按顶层 `model_id` 精确匹配。浏览器经 `/api/commander/tooling` 的只读 `modelProfiles` 操作请求，不转发供应商密钥，不接受自定义 URL。

- 只补缺失的上下文窗口、最大输出、引擎支持输入类型和思考档位；未知保持空，不增加 `off`，不覆盖手动值。
- 页面复用一次成功请求，失败允许后续新增重试；服务端 15 秒、客户端 18 秒超时，不增持久缓存、服务或定时任务。
- 合并草稿，添加和保存不等待目录；保存、删除、离开或编辑后的过期结果不能回写。
- 有效性按模型内容判断，普通重渲染不能取消匹配。
- 不增加匹配按钮或成功/失败提示；无“恢复默认模型”入口，思考继承文案为“使用引擎默认配置”。

## 4. 原生会话、连续性与记录

每个 BenchGo 会话保存 ID、工具、原生 session/thread ID、项目、模型、路由快照、模式和状态。原生会话是恢复的事实来源；BenchGo 保存索引、关联和运行事件，不伪造第二份历史。

- 同一原生会话只允许一个写入者；终端或其他客户端运行时只读观察、等待或明确接管，不静默抢占。
- 同一工具支持原生动态换模才在原会话换模；供应商、认证模式或上下文变化时创建新原生会话。
- “从某会话继续”可携带项目和用户确认的摘要/选定消息，须标识新会话，不伪装跨供应商原生上下文。
- 同工具分支复用原生 fork，不支持则明确说明；旧会话保留，可回原供应商继续。
- 历史缺失或损坏报告真实原因，不自动创建替代会话。

| 记录 | 可见性与约束 |
| --- | --- |
| 官方订阅会话 | 使用原生账号与历史目录，两端可读取同一记录 |
| 导入会话 | 建索引和句柄映射，不复制历史；原写入者必须停止 |
| API 隔离会话 | 默认在隔离目录，原工具不会自动看到；打开/导出/共享须说明范围和并发限制 |
| BenchGo 事件 | 用于状态、审批、短期回放，不替代原生长期历史 |

删除列表项、归档会话、删除原生历史、删除项目文件是四个操作，不能合并为一个“删除”。跨工具摘要迁移、隔离记录向原工具打开/导出的完整路径仍待实施或完善。

## 5. 配置隔离与显式同步

默认通过进程环境、命令行覆盖或每会话隔离目录注入配置，如 Codex 的 `CODEX_HOME`、Claude Code 的 `CLAUDE_CONFIG_DIR`。隔离配置，不复制可执行文件；正常使用不修改用户终端工具的账号、默认模型、插件、全局配置或历史。

```text
显式同步：展示文件、字段、影响范围与校验和 → 备份 → 用户确认
         → 写前复查外部变化 → 应用 → 重新读取验证
```

冲突拒绝覆盖，恢复使用逆向备份。同步后记录校验和与时间，后续提示外部修改，不自动合并或写回。BenchGo 不与其他管理器后台双向同步，谁执行显式同步谁负责该次写入。

## 6. 系统工具生命周期

管理系统真实安装，不复制可执行文件，不维护专用安装前缀或副本凭据。探测返回命令解析后的真实路径、版本、来源、平台、可执行性与登录状态；重复安装全部列出，标记命中项、优先级和冲突。

- 安装、更新、卸载绑定已识别来源和具体实例；未知来源只读，不用裸 `npm install` 猜测替代。
- 当前已有 npm、uv、Homebrew 探测与操作；官方安装器、自更新命令及更多平台管理器按能力清单接入。
- npm 系列复用对应 Node/包管理器，Homebrew 绑定 formula/cask，uv 绑定原环境。前后重新探测，版本未变或路径异常报告失败/冲突。
- 卸载先预览路径、来源、包名/公式、命令和保留范围，确认后复查路径、版本和来源；归属不明、外部变化或权限不足时拒绝。
- 卸载只移除安装，保留账号/OAuth、配置、历史、插件、项目和 BenchGo 索引；官方清理数据动作单独展示确认。
- 操作具备互斥、超时、取消与幂等收据；完成刷新目录、登录和能力，不静默提权。
- Windows、macOS、Linux、WSL 按环境区分路径与实例，不跨环境卸载；权限不足给官方命令或系统授权入口。

## 7. 统一技能目录与自建技能

“工具 → 技能”复用官方 `ctx.skills.list/get`，展示实际生效的用户、项目、内置和插件技能，不新增全盘扫描器，不读第三方 CLI 私有目录。自建技能复用 SuperAgent 管理服务，职责见[SuperAgent](../06-superagent/设计.md)。

- 默认全局，可选已有项目；服务端由 `workspaceRegistry` 解析路径，按官方最近 `.git` 根规则查询，不接受任意 cwd/path。
- 使用默认 Agent 预设 standing scope，避免只查宿主全局漏项；不创建 Agent/会话，查询结束释放预设租约。
- 只返回同名最终生效项，不声称枚举被覆盖副本；按 provider 与名称关联自建项并去重。
- SuperAgent 停用仍能浏览安装技能；服务不可用与空目录分开显示。
- 文件/内置技能可看正文、复制真实路径；任意文件读取、编辑、删除、禁用或卸载不在当前范围。
- 当前自建候选仍需“批准启用/拒绝”，支持固定、历史和恢复；官方提供方只暴露 active/stale。
- 已定目标是自建技能经系统质量与来源审核后自动沉淀，无需逐条人工批准，并支持查看、编辑、固定、归档、历史与恢复；直管策略和完整编辑/归档 UI 尚未接通。

技能页使用列表/详情切换，返回保留域、来源和搜索筛选；默认工作区展示“最近”，不改变路径和 ID。标题 24px，工具栏同排、窄屏换行，路径和技能源文保留等宽字体；加载、空、错误、重试与键盘焦点齐全。

### 技能服务契约

基础层 owner-only `POST /api/benchgo/skills` 沿用同源校验、JSON 和 no-store：

| 操作 | 契约 |
| --- | --- |
| `list { projectId? }` | 返回 `available, skills, projects, scope { projectId?, title, cwd? }`，列表不加载正文 |
| `get { projectId?, name, provider }` | 只读所选注册表生效项；provider 不一致返回冲突，避免错误同名预览 |
| skill | `name, description, source, provider, path?, invocation, content?` |
| 服务缺失 | list 返回 `available:false`，get 明确失败 |

自建管理沿用 `/api/commander/assistant`，不复制持久化。OpenAPI 同步只读接口，不增加模型工具或 MCP 操作。

## 8. 实现边界与参考依据

已有基础：四类原生工具接入、索引/句柄、订阅状态识别、按会话 API 路由、配置预览/备份/显式应用/恢复、工具探测、用量扫描、历史读取与原生 fork。实际能力按运行检测，不因统一 UI 假定各工具等价。

待补齐统一登录发起、跨工具新会话与摘要迁移、隔离记录完整导出、更多安装来源，以及真实 Windows 全新安装、权限、WSL、多工具并行和技能页交互验收。历史定向测试不代表当前版本或这些环境已验收。

CC Switch 仅只读参考：历史设计依据 `reference/cc-switch@7da2553`，文档校对时检出为 `300453be2ea33ca9785b9313fb0b109846a6079c`，不可互换为验证版本。技能 standing-scope 历史验证引擎为 `571902028a`，当前以根 `upstream.json` 为准。参考代码不参与依赖或构建。

## 9. 验收条件

1. 新用户可发现、安装/接入工具并完成首轮会话；已有终端账号、模型、历史不变。
2. 模型选择、保存、重载、请求一致，改单项保留其他配置，显式选择优先。
3. 订阅不跨工具、不泄露 OAuth；API 配置隔离，恢复不静默换供应商。
4. 同步具备预览、备份、外部变化拒绝和恢复验证；默认保存方案不写原生全局配置。
5. 生命周期按来源且前后探测，卸载保留用户数据；跨环境、未知来源和归属异常被拒。
6. 技能覆盖全局/项目、provider 冲突、服务缺失、跨源拒绝和正文读取，释放查询租约。
7. 四态与失败替代路径实际可用；测试、真实模型和设备验收分别报告。
