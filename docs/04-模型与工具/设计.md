## 职责与基本约束

BenchGo 发行包集成官方 DeepSeek Harness；用户无需另装底座，但运行仍依赖官方引擎。Harness 聚合复用 Codex、Claude Code、Pi、OpenCode 等系统原生工具的协议、上下文和历史，不创建另一套原生工具副本。

基础层提供共享供应商、模型、工具目录与设置。Harness 聚合的 [Commander 原生会话调度](原生工具与会话.md#调度边界)归本板块维护。[工作台与 Agent](../02-工作台与Agent/设计.md)提供项目和会话入口，[SuperAgent](../06-superagent/任务与执行.md)负责业务工单的派发、跟进与结果交付。CC Switch 等管理器可独立使用。

- 供应商 ID、模型 ID、工具名与协议值是不透明标识，不猜别名、不静默改写。
- 外部 Harness 会话使用显式选择的工具、供应商和模型。选择、保存、重载与实际请求须一致。
- 修改单项保留其他模型、路由和参数。重复选择当前项保留原配置。
- 已安装且可用用品牌色，不可用用灰色；选中使用中性底色，不改变可用性含义。
- 明确提示协议、安装或会话能力限制，按实际能力提供原生命令。
- 不改官方源码，优先复用插件、服务、配置和成熟原生接口。

## 用户路径与页面职责

```text
模型页配置 API → 工具页安装或识别 CLI → 工作台打开项目
→ 选择 Harness、供应商、模型 → 校验后执行
```

工作台负责项目和会话：选择工具模型、消息与工具活动、审批、停止、恢复、归档和继续工作。设置页承载工具与模型配置的页面入口；产品自身的注册配置也可在 Router 对话中管理，两种入口共用[统一配置服务](../06-superagent/服务契约.md#对话管理与统一配置目标)，不另存配置。页面按以下区域组织：

| 区域 | 展示与操作 |
| --- | --- |
| 外部工具 | 卡片呈现名称、版本、可用状态，以及安装、更新、卸载和工具配置 |
| 供应商与模型 | 在模型页维护 API 端点、凭据引用、协议与模型目录，使用时自动匹配 Harness |
| 会话记录 | 工作台展示会话、运行状态、停止、恢复和归档入口 |
| 技能 | 全局/项目生效技能、自建技能和候选管理 |

SuperAgent 的 Router 与辅助模型使用官方 DeepSeek Harness。Worker 使用同一执行目录，可选官方或外部 Harness，覆盖本机与跨设备项目。角色与工单规则见 [SuperAgent 模型与上下文](../06-superagent/模型与上下文.md#模型角色)。

共享 API 目录、工具卡片和隔离配置已接入 Codex 与 Claude Code。Worker 的执行范围见 SuperAgent 板块，真实供应商请求及双设备仍按各模块验收。

## 跨模块验收

新用户应能从工具发现和模型选择进入首轮会话；已有终端账号、配置、模型与历史不变。各模块按自己的契约验证，空、加载、错误、有数据四态与失败替代路径实际可用；定向测试、真实供应商请求与真实设备验收分别报告。
