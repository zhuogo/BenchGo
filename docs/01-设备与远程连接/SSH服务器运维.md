# SSH 服务器运维

本文维护自有服务器登记、人工终端、本机 AI 运维和服务器卡片发起的手机配对。Link 信任与传输见[设备与远程连接](设计.md)，跨设备工单见[跨设备协作](跨设备协作.md)。

## 服务器登记与迁移

设备中心保留「添加服务器」和「连接已有设备」。添加服务器填写 SSH 地址、端口与账号，核对主机指纹后认证并探测已有安装。兼容实例直接复用，缺失时调用既有部署服务与签名资源。手动安装、HTTPS 入口和中继配置放入高级设置。实例不兼容或归属不明时保留原数据，并显示原因和维护入口。

SSH 部署由 BenchGo 自动签发隧道内使用的 Link 自签名证书。新证书的生效时间设为签发前五分钟，允许首次连接时的短暂时钟偏差。客户端继续核对证书公钥指纹和有效期，证书尚未生效时提示同步两端系统时间。

设备中心通过已核验的 BenchGo 实例身份关联 SSH 和 Link。已通过 Link 添加的服务器可在原卡补绑 SSH，核验实例、隧道 TLS 与原设备授权。目录将旧 SSH 登记迁入 `connections.json`，保留设备 ID、别名、授权和已有 Link 路线，并清理旧文件。同一主机不同 SSH 账号下的兼容实例可各自登记。双路线设备优先使用已有 Link 路线，路线不可达时尝试 SSH 隧道。证书或授权异常交由用户核对。

SSH 登记与组成员的 BenchGo 公钥指纹相同时，设备中心和侧栏合为一项，沿用服务器图标、SSH 登记 ID 和管理入口，显示设备组中的名称。工作台优先使用组内连接路线，必要时通过已登记的 SSH 隧道使用同一组授权。移除组成员后，合并项随组成员从工作台目录移除。

仅作 SSH 登记的服务器同样进入[设备组目录](设计.md#设备组目录)。已批准的组员可从设备卡片打开终端，由登记主机复用其 SSH 凭据并按原记录核验主机指纹。终端会话绑定组员和登记资产。登记主机移除记录或撤销组员时关闭对应会话。凭据补录、SSH 登记和部署维护继续由登记主机处理。

## 设备卡与人工终端

卡片主体打开工作台，右侧终端图标直达该服务器的交互式 SSH 终端，菜单提供「生成连接码」和诊断。状态、日志、启停及更新等快捷操作收在详情。终端由设备中心的 SSH 服务打开 PTY，复用登记目标和认证入口，标题显示设备名与 `账号@主机`，图标支持键盘和提示。具备 SSH 管理能力的客户端可以打开终端。

SSH 可达、SSH 已认证、工作台可用分别核验和展示。工作台停止时，人工终端与 AI 命令仍可通过可达的 SSH 运行。成功认证后，密码或手动输入的私钥保存在宿主凭据库，并绑定地址、端口、账号和主机指纹。客户端重启或隧道断开后自动使用已保存凭据或本机 SSH agent 重连，并重新核对主机指纹。已有登记首次使用时可补录凭据。移除登记时清除对应凭据。

受管 Linux 服务在 systemd 启动阶段检查 SuperAgent 遗留的空写锁。确认属于当前安装用户、文件稳定且数据所有者已退出后，归档空写锁并继续启动。活动或无法核验的锁保留。升级等待工作台状态和升级前可用的 SuperAgent 恢复，检测到待恢复的空锁时也验证 SuperAgent。设备中心的「重新打开工作台」会获取新的工作台入口，普通设备切换保留已打开页面。

## 本机 AI 运维

登记 SSH 服务器后，桌面、浏览器和已配对设备打开该工作台时，都可在 SuperAgent 主聊、手动旁聊或支持工具调用的原生项目会话中直接提出运维请求。实时语音交接到这些会话时使用同一路径。设备中心不显示运维授权开关或按钮，SSH 命令不经过单独的逐次确认。第三方消息渠道和后台 Worker 沿用各自权限。各工作台宿主使用自己的服务器登记和认证，配对本身不搬运 SSH 凭据。

工具先读取该宿主登记的服务器，再按设备 ID 执行当前真实用户指令。设备中心在提交时复核登记版本与主机指纹。AI 和人工终端共用目标及认证，各自打开 SSH 通道。远端账号权限决定可执行的操作。模型收到命令输出、退出状态或待核实结果。移除登记会关闭本机终端、隧道和对应命令通道。执行中断时先核对远端事实再决定是否重试。

## 服务器签发手机连接码

卡片的「生成连接码」通过获授权的 SSH 管理连接，请目标服务器签发五分钟内有效、单次使用的 Link 配对码。用一次性探测值及真实 `/link/` 页面核验目标的公网 HTTPS 入口，失败时检查目标已接入的中继。缺少可达路线时可在同一面板保存已部署的 HTTPS 地址并检查。旧目标需先更新到支持按连接码审批的版本。

手机扫码后由目标批准，保存独立 Link 设备凭据，通过 HTTPS 或中继打开同一工作台。关闭本机 BenchGo 或 SSH 隧道后，手机仍能独立访问。手机配对由目标工作台管理，SSH 运维随登记生效与移除。

## 实现与验收边界

统一登记、原卡补绑、按需复连、本机 AI 命令、卡片终端及远端连接码已接入源码。以下为真实服务器、客户端与蜂窝网络的验收条件。

1. 香港复用现有实例，襄阳从原 Link 卡补绑后仍只有一条相同实例记录。同主机不同实例可独立登记。迁移保留已有设备数据和 Link 权限。
2. 桌面重启、香港工作台临时停用时，人工终端和该工作台中的 AI 仍能用 SSH。核对真实输出、退出状态、认证失败、指纹变化、移除后失效和断线后待核实。修复后实际打开工作台。
3. Android 用蜂窝网络扫码，经香港批准后打开与电脑相同的项目。关闭电脑和隧道后手机仍能打开。撤销手机授权后访问立即失效。缺入口、证书错误和中继断开时有对应恢复动作。
4. 设备中心覆盖空、加载、错误、有数据四态，验证键盘、提示和窄屏，确认设备卡保留终端与连接码入口。无 SSH 能力的客户端继续使用已有 Link 配对。
