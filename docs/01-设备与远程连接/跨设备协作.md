# 跨设备协作

本模块维护跨设备资源、调用归属、双向协作与设备管理的唯一机制正文。连接信任与选路见[设备与远程连接设计](设计.md)，中继传输与部署见[自建中继](自建中继.md)，界面见[跨设备资源导航](../02-工作台与Agent/跨设备资源导航.md)，任务业务、服务字段与实施顺序见 [SuperAgent 任务与执行](../06-superagent/任务与执行.md#跨设备任务)及[服务契约](../06-superagent/服务契约.md)。**2026-11-15 源码已接通：业务工单留在发起任务的宿主，目标设备只执行。** A 的统一任务受理与管理、B 的独立执行服务及事实回流已有定向验证；真实物理双机、安装版、供应商请求及真实旧数据迁移仍待验收。

## 设计目标与职责

**业务工单归发起宿主，执行跟着项目所属设备走。** 用户从已授权入口查询各设备项目、会话、任务和能力，也能通过 AI 连接设备、配置中继及执行受支持的管理动作。A 的 Router 受理的任务完整保存在 A；B 只保存这次委托的执行实例、官方会话、日志、产物与必要回执，不在 B 创建或维护对应业务 Task。文件、依赖、Git 和模型凭据仍由所属主机负责，不建立中心服务器或全量文件同步。

这项扩展复用各设备已有的开发环境，减少工作台切换和手动配置。查询与操作共用领域服务，不把每次远端查询变成临时 SSH 调查，也不让助手通过模拟点击维护设备。

| 职责 | 所属模块与边界 |
| --- | --- |
| 设备身份、可信路线、能力协商与定向调用 | `plugins/link/` 内复用目录、配对、选路和连接生命周期，提取界面与工具共用的服务，不增加 Cordis 入口或安装包 |
| 项目、会话、能力和产物事实 | 所属工作区、会话、Harness、文件与配置服务分别提供授权投影；业务 Task 资源属于受理宿主，执行会话与产物资源属于执行设备；Link 不复制业务存储或承担推理 |
| 聚合导航 | 基础层统一客户端，只保存显示偏好及有界元数据缓存；交互和四态见界面正文 |
| 对话、工单与协调 | 发起宿主的 SuperAgent 持有唯一业务 Task、要求、授权、输入账及交付关系，Router 与界面使用同一任务服务；切换浏览设备不改变工单归属 |
| 执行与控制 | 执行设备的 Harness 执行服务接收发起宿主的执行委托，不调用目标 SuperAgent 的受理、Router 或任务调度；B 无需启用 SuperAgent，缺少执行能力明确返回 |
| 配置、部署与运维 | 目标统一配置、Link 设备中心与服务器管理服务；保存、应用、部署和运行验证分别返回事实 |

基本设备与项目查询不硬依赖 SuperAgent；执行接收器由现有 Harness 能力装配，Link 只做认证与有限执行协议传输，不增加 Cordis 入口或另建执行器。B 停用 SuperAgent 不影响其已声明的执行能力。执行协议版本与真实 Harness、模型、项目能力分别声明；旧目标只支持目标工单链时明确要求升级，不回退旧链，其他可用资源查询不受影响。

<a id="授权与互通"></a>

## 授权与互通

“设备连通”应使用户自然发现可协作资源；连接、身份可信、操作获准和业务可用分别记录。

- **出站目录**是我添加的目标，**入站授权**是允许谁访问我。统一展示可关联二者，不能拿入站列表回答“我连接了哪些服务器”。
- 同一人的设备建立协作连接时，配对流程一次说明双方身份、方向与能力，允许同时建立双向关系；旧单向访问不能静默升级为反向管理授权，需重新核验或明确启用协作。
- **确认配对是统一权限边界。** 已批准且凭据有效的真人设备可使用目标实际提供的会话、任务协作和连接管理，无需再配置 `collaboration / management` 二次权限；首次批准前展示完整范围。既存配对按同一规则生效，普通数据加载会清除已被替代的逐设备权限字段，不保留双轨判断、开关或补权接口。设备列表保留备注、最近连接和撤销；未批准、错误凭据或已撤销设备始终拒绝。中继修改仍逐次确认，模型与工具继续遵守既有 Harness 审批，不因配对绕过。目标尚无相应服务时明确“不支持”，不把实际能力和授权混为一谈。
- 宿主和认证连接绑定真实发起设备、原用户/会话来源、目标与操作。模型不能自报 owner、伪造批准事实，远端资源文本不能产生新授权。
- 双向协作不要求两端都开放公网端口；需协商复用已认证通道或可信直连/中继路线。旧端不支持反向调用时明确单向，不宣称已互通。
- A 与 B 的关系不自动把 B 的 C 设备和凭据共享给 A，不递归扫描设备网络或转授 owner 身份。纯浏览器、移动端只有客户端能力时不虚构执行服务。
- 撤销阻止新请求、关闭相关流并清除受限缓存。目标已接收任务沿原任务规则继续或经明确控制停止；断网、撤销连接与取消任务不是同一动作。

## 可发现与可操作的范围

下表是设计能力面，操作由目标服务声明，不把规划功能提前标成可用。

| 资源 | 查询 | 可按用户指令执行的操作 |
| --- | --- | --- |
| 设备与连接 | 名称、身份、方向、路线、工作台和协作能力、观测时间 | 添加、配对、重连、改名、配置、移除与撤销 |
| 项目与会话 | 已登记项目、原有最近候选、摘要及授权详情 | 在所属设备打开、创建受支持的项目/会话、继续会话；远端路径不当本地路径 |
| 业务任务 | 各受理宿主自己的工单、要求、状态、等待问题与结果引用 | 在工单宿主统一委派、补充、修订、答复、暂停/恢复/取消和整理；不从执行设备派生另一张工单 |
| 执行与产物 | 执行设备的会话、进度、控制回执与产物引用，标明原工单宿主 | 按原委托读取或控制执行；按需预览或显式获取产物，不直接修改原工单要求 |
| 模型、Harness 与工具 | 目标真实配置、能力、可用性和不透明 ID，不返回密钥 | 按目标配置能力修改明确条目；显式选择原样保存并使用，不支持的设置明确说明 |
| 中继与服务器 | 节点优先级、启停、连接、诊断与部署状态 | 新增/编辑/删除节点、设主节点、测试、部署和受控服务管理，复用原规则 |

文件、Git、终端操作使用所属设备已有工具。按需产物读取可经 Link，自动复制工程、镜像全部历史和同步所有模型配置不在范围。

<a id="资源身份与查询"></a>

## 资源身份与查询

引用由 `deviceId + kind + resourceId` 组成，已接入 Link 资源服务。名称、IP、URL、端口和路径不作为跨设备唯一键；资源 ID、模型 ID、工具名和协议值保持原样。目录记录 ID、入站 `authorizationId` 与 TLS 核验的目标 `hostId` 分开保存，不能假定三者相同。“本机/当前设备”在调用边界解析成具体主机身份。

1. 从已保存且授权的目录取得候选并探测能力与授权范围；暂时离线不等于记录不存在。
2. 并发、逐设备超时、分页与取消均有界，先呈现已返回结果；单台慢机或错误不阻塞全部设备。
3. 结果携带设备来源、`available / code / reason`、`observedAt`、新鲜度与分页覆盖。只有成功查询的空集合才表示该范围没有资源；未查、离线、未授权、不支持及部分失败各自保留。
4. 有界摘要缓存用于导航与重复询问，按需刷新；活跃资源优先复用事件流，重连补读水位，不全量轮询所有设备和会话，不把缓存变成业务真源。
5. 最近列表保留各设备原有候选语义，再做聚合。来源活动时间和入口观测时间分开，跨机时钟差只支持近似排序；稳定资源键用于去重与并列排序。
6. 模型只接收当前问题必要摘要，历史全文、日志和产物按引用逐项读。显示范围只改变侧栏投影，不改变助手获准查询的设备范围。

设备改名、路线切换、重连不改变资源身份。目标身份改变必须重新核验，旧缓存不能附会到新主机；所有打开行为与操作回执保持所属设备。

会话与最近资源仅查询会话摘要，不读取无关的模型目录；模型资源沿既有模型查询，完整工作台状态保留原接口语义。同一会话资源请求只取得一份项目快照，官方会话按会话 ID 索引归属，原生会话按项目 ID 与原始路径的临时索引核验；索引用完释放，实际会话操作仍实时核验归属。

会话与最近查询先按项目及显式归档范围过滤，再以置顶优先、来源活动时间倒序排序，最后分页；归档参数沿定向 RPC 传递且纳入摘要缓存键。`provider` 表示 Harness 品牌，精确 `model` 与 `modelProvider` 分别保留模型 ID 和模型供应商，不互相猜测替换。原生会话资源沿现有 `native:` 命名空间传递，工作台接收器仅在明确原生类型时去掉一层协议前缀，官方 ID 原样传递。旧目标需更新自身资源服务后才能提供新增摘要及完整归档分页；入口更新不代表目标已部署。

### 会话菜单操作

已配对真人入口沿统一配对权限发送有限 `sessionAction`，无需额外权限配置，也不向远端开放 owner API、任意 RPC 或设备目录。入口经 `/api/commander-devices` 指定 `deviceId`，并必填所显示设备的 `expectedHostId / expectedAuthorizationId`（未知显式传 `null`），Link 捕获当前目录后立即严格核验，选路与发送前继续核对当前身份；同逻辑目录 ID 重新配对后，旧界面不能向新授权写入，需先刷新。两个 expected 字段只用于入口核验，不传到目标。

定向请求字段为 `{ action:'sessionAction', id, native, operation, requestId, title? }`。`native` 必须是布尔值，并与 ID、操作和精确名称共同绑定幂等意图；仅 `native:true` 选原生适配器并去掉一层协议前缀，官方 ID 即使以 `native:` 开头也原样路由官方服务。`title` 仅用于重命名。`operation` 白名单是 `pin / unpin / archive / unarchive / rename / delete / fork`；每个状态操作都是明确设值，不使用 toggle。

目标 `capabilities` 分别用稳定 ID `sessionActions`、`nativeSessionActions` 声明实际可用操作。官方会话复用当前 workspace/session 服务执行置顶、归档、重命名；删除与本机菜单一致，为归档后持久 dismiss，保留官方历史，并仅移除最新关联的原生 owner。直接原生会话仅按真实 commander 方法开放归档、取消归档与删除；无现成服务的置顶、重命名和 fork 明确返回 `UNSUPPORTED`，不会伪造支持。旧目标未声明能力时，入口禁用相应操作并提示升级目标。

每次操作及已完成回执重取都实时核验 TLS 绑定设备仍在配对记录中、凭据未变、项目仍已登记、会话仍属于原项目与原路径，并排除私有会话、子代理及已 dismiss 会话；删除自身的重取允许原行已消失。多个副作用之间重新检查授权与归属。撤销后的新动作不会执行，但撤销不回滚此前已成功的步骤。

`requestId` 由入口生成 `sa:<毫秒时间戳>:<UUID>`，按发起设备持久保存，并绑定会话、类型、操作和精确名称；相同请求并发或重投共用原结果，改变意图返回 `SESSION_ACTION_CONFLICT`。先核验实时授权与归属、查已有回执，再对没有回执的新请求校验七天窗口与最多二十四小时未来偏差；时钟变化不会否认尚保留的已接受结果。响应为 `{ accepted:true, id, operation, requestId, refreshRequired:true, deleted?, title? }`，入口据此刷新目标摘要，不拼造完整会话状态。

每个目标按需保留七天、最多 2000 条会话回执，正常容量满时淘汰最早终态；淘汰与该设备时间水位推进在同一次持久保存中完成。已过窗口或不晚于淘汰水位且没有回执的请求返回 `SESSION_ACTION_EXPIRED`，明确刷新核实后发起新动作，绝不把旧重命名当作新请求执行。七天内的执行中、待核实记录不因常规容量清理而丢弃；只有这些记录占满时才临时返回容量限制，不要求重新配对。撤销清理该设备回执与水位。重启前仍在执行、已开始的副作用报错、部分成功或最终回执保存失败均标为 `unknown`，返回 `SESSION_ACTION_UNCERTAIN`，刷新所属设备核实后由用户决定新动作，不自动重放原请求。

<a id="项目归属与远端执行"></a>

## 项目归属与远端执行

```text
A 的用户 → A 的 Router → A 的唯一业务 Task、要求与输入账
                                  ↓ A 的 Assignment / Run 与持久执行命令
                         Link 认证、能力与目标身份核验
                                  ↓
B 的 Harness 执行接收器 → B 的执行实例 → 官方 Worker / 工具 / 项目目录
                                  ↓ 执行事件、问题、应用版本、控制回执、结果引用
A 的同一 Task、结果保存与原 Router 对话 ← Link 按水位补读

B 不创建业务 Task，不进入 B 的 Router、研判或任务调度；B 可不启用 SuperAgent。
```

### 工单与执行的独立边界（源码已接通，真实环境待验）

- **受理宿主 A** 保存唯一完整业务工单及 Assignment/Run 的协调账。稳定 `ownerHostId + taskId` 定位工单，来源逻辑 thread 与 Router 官方 session 分开；清空聊天、重建 Router 会话、切换页面或路线均不转移归属。A 的统一任务工具和列表管理本地及远端执行，不要求模型使用另一套远端任务工具。
- **执行设备 B** 保存持久执行实例及其官方会话、日志、产物、已应用要求版本、操作回执与事件水位，关联 A 的 Task/Assignment/Run 和执行代际。执行实例不拥有业务要求、目标清单、任务三态或交付决策，也不通过 B 的 `acceptDesktop`、研判、Router、任务输入账或任务调度推进。B 保留执行端并发限制与资源排队，不据此自行分诊或创建业务任务；B 自己受理的独立任务不受影响。
- **项目归属** 决定执行设备，从 B 的 Router 受理 A 项目任务时反向成立：业务工单归 B，实际执行在 A。用户只给项目名时先查真实项目目录；唯一匹配直接执行，只有同名或关键缺项才补问。项目语境的“发个 hi”按项目会话消息理解。无项目且未指定设备时默认受理宿主执行，不静默迁移工程或跨机调度。
- **执行配置** 由 A 根据 B 公布的 Harness、模型目录与实际可用性选择并冻结，B 使用自己的模型凭据、工具和项目路径校验执行。当前 v1 仅支持 `official` Harness 与一个明确模型，不支持的组合直接拒绝。精确 provider/model 标识限定在目标目录内，不把 A 的供应商 ID 当作 B 的 ID，不猜别名、不覆盖显式选择。缺配置或能力明确阻断；B 的 SuperAgent 工作模型设置不参与，也不因 B 停用 SuperAgent 改变配置。Router 仍使用 A 的对话配置。

### 定向命令、执行事实与恢复

1. A 先持久保存业务 Task、可信原指令及发往 B 的执行命令，再通过 Link 发送；业务事务不等待网络。命令携带宿主绑定的工单、Assignment/Run、执行代际、要求/授权版本、稳定请求 ID、目标项目及必要上下文，不传全量记忆、历史或凭据。
2. Link 将已认证的来源关系与 `ownerHostId` 核验绑定，并校验目标真实 `hostId`、当前配对授权和执行协议能力；目录 `deviceId`、入站 `authorizationId` 与稳定宿主身份不混用。B 校验资源、配置及代际后持久受理执行，返回自己的 `executionId`。执行引用挂在 A 的正式 Assignment/Run 上，不建立第二份工单旁账。
3. 同一发起宿主、执行委托和操作请求绑定不可变内容摘要；相同请求重取原回执，异内容冲突拒绝。派发响应丢失先核实原请求，不换 ID 重派。旧代际不能启动新动作；只有核实原执行停止或按执行端规则完成栅栏交接后，才允许新的执行代际，不把租约超时当作旧进程已停止。
4. B 持久记录有序、有界分页的执行事件与回执，A 记录已消费水位并按稳定事件/结果身份去重。活跃连接优先复用现有流，重连补读原水位；无流时沿既有调度有界补读，不全量轮询所有设备。事件顺序依据执行代际及序号，不依赖跨设备时钟。A 写入同一 Task 的执行投影、问题和结果后，再沿原 Router inbox 与交付链告知；已完成结果及未确认命令不因摘要缓存淘汰而消失。
5. 补充、修订和问题答复先进入 A 的同一任务输入账，再向原 B 执行实例传递；B 只记录实际应用的版本与回执。暂停、恢复、取消分别表达 A 已登记、B 已接收和 B 已生效。A 发出命令不能代表失联 B 已暂停或已停止，也不能撤回已发生的副作用。
6. A 离线时 B 可在已经受理的授权范围内继续并保存结果；新要求、需补充授权的动作和未回答问题等待 A。B 失联时 A 保留工单、最后已知事实及待核实说明，不判定失败、不另建工单或自动换机。断线、撤销配对和取消执行分别处理；重新配对或目标身份改变不得将旧执行引用绑定给新设备。
7. B 的真实提问带原请求身份回 A，按真实授权答复；既有 Harness 审批不因跨机绕过。当前 B 的受委托执行会话只读，并提供返回 A 原工单的入口；直接输入回 A 的桥尚未实现，不能借 B 会话绕过要求版本。B 的本地执行权限仍可紧急停止实际运行，并回传停止事实，但不接管 A 的业务工单。A 不可达时不在 B 另建任务来接续。
8. 产物留在 B，引用携带执行设备、执行实例与路径/资源 ID，A 保存结果正文和受控引用并向原来源交付；跨设备产物按需获取与传输尚未实现。执行结束、A 保存结果与交付成功是三个不同事实，回流失败仅恢复回流，不重跑 Worker。

数据字段、统一任务接口、一次性旧数据处置与删除清单以[跨设备任务](../06-superagent/任务与执行.md#跨设备任务)和[服务契约](../06-superagent/服务契约.md)为准。旧 `assistant_remote_task`、目标业务 Task 接收链及 `remote-executions` 活跃旁账已退出运行路径，不保留运行时兼容分支。一次性迁移 CLI 已实现；旧在途执行保留 migration blocker 等待核实，不自动接管、续跑或重派。

<a id="连接与中继管理"></a>

## 通过 AI 管理连接与中继

AI 与设备中心共用真实管理能力。`assistant_device_manage` 已注册已有设备连接、重连、改名、移除、诊断，以及远端状态、脱敏中继配置读取、修改申请与原操作查询。新设备配对、部署和秘密补录仍引导现有设备中心；“新增中继节点”等更宽操作不冒充已支持。

**明确目标。** “让 A 连接 B”修改 A 的出站目录；“改 B 的中继池”修改 B 配置。默认管理当前工作台所属主机，不能仅凭上下文出现 B 就改变写入目标。同名设备、身份或范围有歧义时只补问关键缺项。

**共用服务。** 配置读写走统一配置目录，动作走设备中心、Link 和服务器管理服务。清晰且已授权的普通配置直接办理，不逐步重复确认；监听变化、中继切换、撤销、停止或卸载按现有风险策略说明影响并复用一次有效确认。保存配置不自动授权部署或修改其他系统服务。

```text
用户给出目标与连接信息
→ 查询已有记录、能力及配置，优先复用
→ 补齐缺失信息 / 安全凭据 / 必要信任确认
→ 配对或部署，持久化身份与可信路线
→ 差量保存、回读并按原规则应用
→ 验证身份、路线、工作台及请求需要的协作能力
→ 返回已完成阶段、待处理事项与可打开入口
```

| 操作 | 行为与回执 |
| --- | --- |
| 已有设备 | 复用记录和凭据，健康检查、重连、改名或改明确字段；重试不重复新增 |
| 首次连接 | 按信息走配对或既有 SSH 部署；仅有地址且无授权材料时说明缺项，不以可达代替授权 |
| 双向协作 | 一次说明双方范围并协商能力；不支持或缺反向通道时明确单向与原因 |
| 中继池 | 按节点 ID 修改，保留其他节点、顺序与秘密；设主节点遵守现有优先级和切换规则。新增/换密钥经安全入口，保存后回读并验证 |
| 部署与诊断 | 复用已有任务、日志和服务管理，返回阶段与操作 ID；不另写安装脚本，不把进程启动或端口开放当作工作台可用 |
| 远端管理 | 目标授予对应能力后调用有限领域操作并再次核验；普通访问凭据不升级为 owner Cookie、任意 HTTP/SSH 转发或任意管理 API |

**秘密。** 密码、私钥、设备/中继 token 和配对秘密通过安全输入或受控引用交给服务，模型只见必要摘要和句柄。不能要求用户将秘密写入普通聊天，也不能把模型已见过的秘密追溯称为隔离。安全输入未接通时明确引导现有设备中心补录并提供返回入口。新增协作管理消息需加入有限协议白名单，不直接开放 owner 管理接口。

**一致性。** 读取版本后提交差量，冲突先回读，不整池覆盖。副作用使用稳定 `operationId / requestId`，区分已接收、执行中、已应用、验证成功或失败；断线后查询同一操作，状态未知不重复部署、重启或新增节点。多阶段可部分成功，恢复遵循原服务，不宣称跨设备原子事务。

当前管理回执最多保留 128 条，容量满时优先淘汰已结束或已过期记录；未决和 unknown 不自动删除。同请求在保留期内幂等，旧回执已淘汰时查询明确返回不存在，不能据此推断未执行或自动重放。

**验证。** 核对选择、保存、重载与实际连接/请求一致；未验证时说“已保存，连接尚未验证”。AI 和设备中心应看到同一结果。操作影响当前唯一连接时保存操作记录与恢复入口，不能断线后编造完成。

`devices()` 返回目录与已知状态，不把已保存记录说成当前在线；经过认证的资源/操作请求成功后回写可连接状态，网络不可达标为离线，授权或证书失效标为连接失败，不支持能力和业务错误不冒充离线。取消请求不改变可达状态，旧身份或已移除设备的迟到结果不能回写状态或缓存。

资源调用按设备及可信身份复用 HTTPS 连接池，每设备最多 4 条活动连接、2 条空闲连接；并发查询共用选路，成功路线保留最多 60 秒，网络失败后下次重新选路，不重放本次操作。移除、重新配对、身份或路线配置改变时释放旧连接与缓存，设备中心关闭时取消在途请求并释放全部连接；空闲连接实际存活仍受目标服务与网络策略约束，不承诺永久 TCP 连接。

资源列表当前按需读取，侧栏可见时每轮摘要刷新完成后等待 30 秒。新执行回流沿正式 Task/Assignment 的持久关联与水位有界读取；具体批量和退避由实现验证，不沿用旧 128 条引用淘汰和有限次核实后丢出管理链的规则。暂时无法确认的命令保留待核实事实及查询入口，重启后继续可追踪，不自动重派；真实环境验收按下列条件逐项完成。

<a id="验收条件"></a>

## 验收条件

1. A 查询 B 返回真实登记项目，入站、出站、空、离线、无权限、不支持均可辨；同名、同资源 ID、设备改名不串数据。
2. A 开发 B 项目时，完整业务 Task 及协调账仅在 A，普通任务列表、详情和统一工具可查询管理；B 不新增业务 Task、目标清单或 Router 回合，B 停用 SuperAgent 后仍可凭 Link 与实际 Harness 执行能力受理。实际模型请求、目录、文件/Git 变更、官方会话和产物在 B；配置按 A 冻结的目标标识执行，不依赖 B SuperAgent 设置。反向相同，不复制工程或跨机回退。
3. 重复派发、响应丢失、重连、两端重启、旧代际和迟到回执不产生重复执行；修订、提问、控制、结果均归 A 的同一工单，分别核对已登记、已接收、已应用、已保存和已送达。A 离线不丢工单，B 失联不假报失败或取消成功；回流恢复不重跑 Worker。
4. 双向按真实能力和授权工作；旧单向、纯客户端、不兼容、撤销及未经授权的第三设备有明确结果；模型参数不能伪造身份。
5. “连接襄阳服务器”复用或完成受支持流程，设备中心显示实际结果；缺秘密可到安全入口补齐，未接通流程不假装自动完成。
6. AI 改一个中继节点、优先级或目标模型条目后，选择、保存、重载与实际请求一致，其他字段和凭据保留；冲突、部分成功和验证失败如实返回。
7. 远端管理只用授予的有限操作，普通访问不获得 owner API、任意转发或秘密；部署复用原安装器与规则，不改无关服务。
8. 侧栏范围、远端打开及四态按[界面验收](../02-工作台与Agent/跨设备资源导航.md)验证；查询并发、分页、取消与缓存有界，单设备故障不拖垮整个入口。
9. 升级以新执行协议明确协商，旧端能力不足时阻断执行并提示升级，不回退远端 Task；一次性迁移完成后无旧工具、目标 Task 受理或引用旁账运行路径。迁移保留原文、结果、未决控制与在途执行身份，不重跑历史任务、不误迁 B 自己受理的独立任务；开发清单和迁移验收见[跨设备任务](../06-superagent/任务与执行.md#跨设备任务)。
