# 跨设备协作

本模块维护跨设备资源、调用归属、双向协作与设备管理的唯一机制正文。连接信任与选路见[设备与远程连接设计](设计.md)，中继传输与部署见[自建中继](自建中继.md)，界面见[跨设备资源导航](../02-工作台与Agent/跨设备资源导航.md)，任务业务与模型路由沿用 [SuperAgent](../06-superagent/设计.md)。2026-11-13 已接通资源查询、聚合导航、目标设备执行及有限管理；更宽的设计目标与本轮边界在文末分别列明。

## 设计目标与职责

**入口可聚合，执行跟着资源所属设备走。** 用户从已授权入口查询各设备项目、会话、任务和能力，也能通过 AI 连接设备、配置中继及执行受支持的管理动作。文件、依赖、Git、模型配置和执行记录仍由所属主机负责，不建立中心服务器、全量文件同步或第二套任务执行器。

这项扩展复用各设备已有的开发环境，减少工作台切换和手动配置。查询与操作共用领域服务，不把每次远端查询变成临时 SSH 调查，也不让助手通过模拟点击维护设备。

| 职责 | 所属模块与边界 |
| --- | --- |
| 设备身份、可信路线、能力协商与定向调用 | `plugins/link/` 内复用目录、配对、选路和连接生命周期，提取界面与工具共用的服务，不增加 Cordis 入口或安装包 |
| 项目、会话、能力和产物事实 | 目标工作区、会话、Harness、文件与配置服务分别提供授权投影；Link 不复制业务存储或承担推理 |
| 聚合导航 | 基础层统一客户端，只保存显示偏好及有界元数据缓存；交互和四态见界面正文 |
| 对话与协调 | 入口 SuperAgent 的 Router，按真实能力查询、配置或委派，与界面使用同一服务 |
| 执行与控制 | 资源所属设备的现有执行服务与任务链；缺少目标能力明确返回，不因可见就假定可执行 |
| 配置、部署与运维 | 目标统一配置、Link 设备中心与服务器管理服务；保存、应用、部署和运行验证分别返回事实 |

基本设备与项目查询不硬依赖 SuperAgent；任务桥按目标真实存在的任务/执行适配器声明能力。协议或插件版本不兼容时保留可用操作，逐项说明不可用原因。

<a id="授权与互通"></a>

## 授权与互通

“设备连通”应使用户自然发现可协作资源；连接、身份可信、操作获准和业务可用分别记录。

- **出站目录**是我添加的目标，**入站授权**是允许谁访问我。统一展示可关联二者，不能拿入站列表回答“我连接了哪些服务器”。
- 同一人的设备建立协作连接时，配对流程一次说明双方身份、方向与能力，允许同时建立双向关系；旧单向访问不能静默升级为反向管理授权，需重新核验或明确启用协作。
- 资源读取、任务执行/控制、设备与中继管理按目标提供的操作能力核验；可在配对或可信配置中一次授予选定范围，普通已授权操作不重复配对和确认。界面与 AI 不能相互绕过。
- 宿主和认证连接绑定真实发起设备、原用户/会话来源、目标与操作。模型不能自报 owner、伪造批准事实，远端资源文本不能产生新授权。
- 双向协作不要求两端都开放公网端口；需协商复用已认证通道或可信直连/中继路线。旧端不支持反向调用时明确单向，不宣称已互通。
- A 与 B 的关系不自动把 B 的 C 设备和凭据共享给 A，不递归扫描设备网络或转授 owner 身份。纯浏览器、移动端只有客户端能力时不虚构执行服务。
- 撤销阻止新请求、关闭相关流并清除受限缓存。目标已接收任务沿原任务规则继续或经明确控制停止；断网、撤销连接与取消任务不是同一动作。

## 可发现与可操作的范围

下表是设计能力面，操作由目标服务声明，不把规划功能提前标成可用。

| 资源 | 查询 | 可按用户指令执行的操作 |
| --- | --- | --- |
| 设备与连接 | 名称、身份、方向、路线、工作台和协作能力、观测时间 | 添加、配对、重连、改名、配置、移除与撤销 |
| 项目与会话 | 已登记项目、原有最近候选、摘要及授权详情 | 在所属设备打开、创建受支持的项目/会话、继续会话；远端路径不当本地路径 |
| 任务与产物 | 状态、进度、等待问题、结果与产物引用 | 委派、补充、修订、答复、暂停/恢复/取消；按需预览或显式获取产物 |
| 模型、Harness 与工具 | 目标真实配置、能力、可用性和不透明 ID，不返回密钥 | 按目标配置能力修改明确条目；显式选择原样保存并使用，不支持的设置明确说明 |
| 中继与服务器 | 节点优先级、启停、连接、诊断与部署状态 | 新增/编辑/删除节点、设主节点、测试、部署和受控服务管理，复用原规则 |

文件、Git、终端操作使用所属设备已有工具。按需产物读取可经 Link，自动复制工程、镜像全部历史和同步所有模型配置不在范围。

<a id="资源身份与查询"></a>

## 资源身份与查询

引用由 `deviceId + kind + resourceId` 组成，已接入 Link 资源服务。名称、IP、URL、端口和路径不作为跨设备唯一键；资源 ID、模型 ID、工具名和协议值保持原样。目录记录 ID、入站 `authorizationId` 与 TLS 核验的目标 `hostId` 分开保存，不能假定三者相同。“本机/当前设备”在调用边界解析成具体主机身份。

1. 从已保存且授权的目录取得候选并探测能力与授权范围；暂时离线不等于记录不存在。
2. 并发、逐设备超时、分页与取消均有界，先呈现已返回结果；单台慢机或错误不阻塞全部设备。
3. 结果携带设备来源、`available / code / reason`、`observedAt`、新鲜度与分页覆盖。只有成功查询的空集合才表示该范围没有资源；未查、离线、未授权、不支持及部分失败各自保留。
4. 有界摘要缓存用于导航与重复询问，按需刷新；活跃资源优先复用事件流，重连补读水位，不全量轮询所有设备和会话，不把缓存变成业务真源。
5. 最近列表保留各设备原有候选语义，再做聚合。来源活动时间和入口观测时间分开，跨机时钟差只支持近似排序；稳定资源键用于去重与并列排序。
6. 模型只接收当前问题必要摘要，历史全文、日志和产物按引用逐项读。显示范围只改变侧栏投影，不改变助手获准查询的设备范围。

设备改名、路线切换、重连不改变资源身份。目标身份改变必须重新核验，旧缓存不能附会到新主机；所有打开行为与操作回执保持所属设备。

会话与最近资源仅查询会话摘要，不读取无关的模型目录；模型资源沿既有模型查询，完整工作台状态保留原接口语义。同一会话资源请求只取得一份项目快照，官方会话按会话 ID 索引归属，原生会话按项目 ID 与原始路径的临时索引核验；索引用完释放，实际会话操作仍实时核验归属。

<a id="项目归属与远端执行"></a>

## 项目归属与远端执行

```text
A 的用户 → A 的 Router（A 对话模型）
                 ↓ B 项目引用 + 本轮可信任务要求
           Link 定向调用与授权核验
                 ↓
B 执行服务 → B 的 Worker / Harness / 工作模型 / 工具 / 文件目录
                 ↓ 唯一执行引用、进度、提问、结果
A 的原对话与任务投影 ← Link 回传
```

- 项目归属决定执行设备，从 B 操作 A 项目同样使用 A 环境；选择项目后不再选择一个冲突的执行位置。
- Router 使用入口配置；Worker 使用目标工作模型、Harness 与工具，沿目标角色选择和创建时冻结规则。入口不覆盖目标配置，同一设备已有模型回退照常执行，禁止静默跨设备回退。
- 无项目任务默认在入口执行；明确指定设备才定向委派。涉及多设备时按资源归属拆分关联执行，不隐式迁移目录或做设备负载调度。
- 目标只产生一份真实任务/执行记录。入口沿现有任务投影保存 `executionRef`（目标设备、任务及执行标识）和来源关联，不启动第二个 Worker、不复制可独立推进的任务状态机。
- 派发带宿主绑定的原输入引用、目标、稳定请求 ID 与必要上下文；目标核验权限、资源和能力后持久接收。不传入口全部历史、记忆或凭据。
- 接收、启动、控制生效、结果保存和送达分开表达。重试使用相同请求 ID，由目标去重；响应丢失先查原操作，无法确认则显示状态待核实，不盲目重派。
- 补充、修订、答复和控制沿原 `executionRef`、要求版本与真实来源，遵守原任务归属。远端请求不冒充目标本机真人回合。
- 真实提问和审批可回入口，由宿主传递原问题、来源和有效答复；收到消息不等于目标已采用。断线不推断任务停止，重连补读事件和回执不重跑任务。
- 产物引用包含设备与路径/资源 ID，按权限预览或按用户要求传输；结果交付原来源，目标详情仍可直接核验。

<a id="连接与中继管理"></a>

## 通过 AI 管理连接与中继

AI 与设备中心共用真实管理能力。`assistant_device_manage` 已注册已有设备连接、重连、改名、移除、诊断，以及远端状态、脱敏中继配置读取、修改申请与原操作查询。新设备配对、部署和秘密补录仍引导现有设备中心；“新增中继节点”等更宽操作不冒充已支持。

**明确目标。** “让 A 连接 B”修改 A 的出站目录；“改 B 的中继池”修改 B 配置。默认管理当前工作台所属主机，不能仅凭上下文出现 B 就改变写入目标。同名设备、身份或范围有歧义时只补问关键缺项。

**共用服务。** 配置读写走统一配置目录，动作走设备中心、Link 和服务器管理服务。清晰且已授权的普通配置直接办理，不逐步重复确认；监听变化、中继切换、撤销、停止或卸载按现有风险策略说明影响并复用一次有效确认。保存配置不自动授权部署或修改其他系统服务。

```text
用户给出目标与连接信息
→ 查询已有记录、能力及配置，优先复用
→ 补齐缺失信息 / 安全凭据 / 必要信任确认
→ 配对或部署，持久化身份与可信路线
→ 差量保存、回读并按原规则应用
→ 验证身份、路线、工作台及请求需要的协作能力
→ 返回已完成阶段、待处理事项与可打开入口
```

| 操作 | 行为与回执 |
| --- | --- |
| 已有设备 | 复用记录和凭据，健康检查、重连、改名或改明确字段；重试不重复新增 |
| 首次连接 | 按信息走配对或既有 SSH 部署；仅有地址且无授权材料时说明缺项，不以可达代替授权 |
| 双向协作 | 一次说明双方范围并协商能力；不支持或缺反向通道时明确单向与原因 |
| 中继池 | 按节点 ID 修改，保留其他节点、顺序与秘密；设主节点遵守现有优先级和切换规则。新增/换密钥经安全入口，保存后回读并验证 |
| 部署与诊断 | 复用已有任务、日志和服务管理，返回阶段与操作 ID；不另写安装脚本，不把进程启动或端口开放当作工作台可用 |
| 远端管理 | 目标授予对应能力后调用有限领域操作并再次核验；普通访问凭据不升级为 owner Cookie、任意 HTTP/SSH 转发或任意管理 API |

**秘密。** 密码、私钥、设备/中继 token 和配对秘密通过安全输入或受控引用交给服务，模型只见必要摘要和句柄。不能要求用户将秘密写入普通聊天，也不能把模型已见过的秘密追溯称为隔离。安全输入未接通时明确引导现有设备中心补录并提供返回入口。新增协作管理消息需加入有限协议白名单，不直接开放 owner 管理接口。

**一致性。** 读取版本后提交差量，冲突先回读，不整池覆盖。副作用使用稳定 `operationId / requestId`，区分已接收、执行中、已应用、验证成功或失败；断线后查询同一操作，状态未知不重复部署、重启或新增节点。多阶段可部分成功，恢复遵循原服务，不宣称跨设备原子事务。

当前管理回执最多保留 128 条，容量满时优先淘汰已结束或已过期记录；未决和 unknown 不自动删除。同请求在保留期内幂等，旧回执已淘汰时查询明确返回不存在，不能据此推断未执行或自动重放。

**验证。** 核对选择、保存、重载与实际连接/请求一致；未验证时说“已保存，连接尚未验证”。AI 和设备中心应看到同一结果。操作影响当前唯一连接时保存操作记录与恢复入口，不能断线后编造完成。

`devices()` 返回目录与已知状态，不把已保存记录说成当前在线；经过认证的资源/操作请求成功后回写可连接状态，网络不可达标为离线，授权或证书失效标为连接失败，不支持能力和业务错误不冒充离线。取消请求不改变可达状态，旧身份或已移除设备的迟到结果不能回写状态或缓存。

资源调用按设备及可信身份复用 HTTPS 连接池，每设备最多 4 条活动连接、2 条空闲连接；并发查询共用选路，成功路线保留最多 60 秒，网络失败后下次重新选路，不重放本次操作。移除、重新配对、身份或路线配置改变时释放旧连接与缓存，设备中心关闭时取消在途请求并释放全部连接；空闲连接实际存活仍受目标服务与网络策略约束，不承诺永久 TCP 连接。

资源列表当前按需读取，侧栏可见时每轮摘要刷新完成后等待 30 秒；任务跟进复用现有 tick，每轮最多 4 条、3 秒超时、失败退避 30 秒、最多 128 条活跃引用。明确拒绝停止观察，未知接收最多核实 6 次后保留 unverified，可用 `reconcile` 查询原请求，不自动重派。未完成的操作不可伪装已实现，真实环境验收仍按下列条件逐项完成。

<a id="验收条件"></a>

## 验收条件

1. A 查询 B 返回真实登记项目，入站、出站、空、离线、无权限、不支持均可辨；同名、同资源 ID、设备改名不串数据。
2. A 开发 B 项目时，实际模型请求、Harness、目录、文件/Git 变更和执行记录都在 B，反向相同；入口仍用自身对话配置，不复制工程或跨机回退。
3. 重复派发、响应丢失、重连、目标重启和迟到回执不产生重复执行；进度、答复、控制及结果回正确来源，未知不冒充失败或成功。
4. 双向按真实能力和授权工作；旧单向、纯客户端、不兼容、撤销及未经授权的第三设备有明确结果；模型参数不能伪造身份。
5. “连接襄阳服务器”复用或完成受支持流程，设备中心显示实际结果；缺秘密可到安全入口补齐，未接通流程不假装自动完成。
6. AI 改一个中继节点、优先级或目标模型条目后，选择、保存、重载与实际请求一致，其他字段和凭据保留；冲突、部分成功和验证失败如实返回。
7. 远端管理只用授予的有限操作，普通访问不获得 owner API、任意转发或秘密；部署复用原安装器与规则，不改无关服务。
8. 侧栏范围、远端打开及四态按[界面验收](../02-工作台与Agent/跨设备资源导航.md)验证；查询并发、分页、取消与缓存有界，单设备故障不拖垮整个入口。
