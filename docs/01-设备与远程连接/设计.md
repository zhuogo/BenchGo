# 设备与远程连接设计

本板块负责设备保存、可信配对、远程工作台、自托管中继与部署管理。本文维护设备、信任与连接体验；中继协议、TLS 与服务器部署统一见[自建中继](自建中继.md)。总体关系见[总架构](../总架构.html)，界面遵循[前端视觉规范](../02-工作台与Agent/前端视觉规范.md)。已有实现、待实施目标和真实环境验收分开描述。

## 职责与交付边界

| 组成 | 职责 | 边界 |
| --- | --- | --- |
| BenchGo 工作台 | 项目、模型、会话、任务和插件运行 | 数据与任务留在目标主机 |
| Link | 配对、连接路线、远程工作台与撤销 | 源码在 `plugins/link/`，随唯一 `benchgo-plugin` 安装 |
| 设备中心 | 本机连接、设备目录、中继池与部署 | owner 管理仅向具备主机管理权限的客户端开放 |
| `benchgo-relay` | 已授权工作台流量的备用传输 | 独立服务器，不承担模型、项目、账号或 owner 管理 |

Link 通过 `benchgo-plugin/link-plugin` 独立启停，不硬依赖 Harness 聚合或 SuperAgent；访问助手业务时探测 `assistant` 服务。公共配置与组件复用基础层，不复制其他模块的存储或推理逻辑。

`benchgo` CLI 安装完整工作台，`benchgo-relay` CLI 安装独立中继；工作台不得隐式安装中继服务器，不再发布 `@benchgo/server`。这与“五个源码包、一个插件安装包”是不同层面的交付边界。桌面安装包、Android APK 保持平台原生入口。

## 连接与信任模型

设备保存稳定身份、独立授权及多条可信路线。地址、端口与 relay ID 是可变路由信息，不能当作设备身份。

```text
局域网直连 → 公网直连 → 主中继 → 备用中继 → 明确诊断
客户端 ──已批准的设备身份── 目标主机 Link ── 工作台
   └──────── 必要时经自托管 Relay 转发 ────────┘
```

- 目标有可用入站路径时优先直连；无可用入站路径时，主机主动通过 TLS 连出到中继。
- 路线可用须经过 TLS、身份与工作台健康验证，不能依据同 Wi-Fi、端口监听或 SSH 成功判断。
- 证书错误、身份不匹配和授权拒绝立即报告，不降级到下一条路线。
- 网络失败、超时、离线等可恢复错误才允许有限重试和切换；当前中继池按优先级尝试，失败节点冷却 10 秒。
- 最近成功节点不覆盖用户优先级；主中继恢复后新连接回主，活动会话不强制迁移。
- 路线切换不停止主机任务，不重放已提交写请求；保留幂等请求标识、草稿和工作台状态。
- 网络变化、取消、断线与服务关闭须释放连接、事件流和语音流资源。

普通用户自动选路，高级详情查看路线与重试。分别展示主机在线、中继在线、路线可达、工作台可用，不合并成含义不清的“在线”。

设备记录保存名称、稳定设备 ID、路线、证书指纹、设备凭据安全引用、状态和最近错误。连接成功显示“局域网直连”“公网直连”或“经中继”；直连和中继都不可用时给出检查目标主机、中继状态或重新配对的入口。

## 登录、配对与服务契约

公网 owner 入口统一使用已有短时 `launch-token`，不另设 `cloud-access` 密钥链路：

```text
https://工作台地址/?token=短时票据
→ 服务端校验 → HttpOnly / Secure / SameSite 会话
→ 清理地址栏 token → 打开工作台
```

- launch-token 一次性或短时有效，不写日志、设备记录或普通 API 响应。
- 配对码短时、单次、限流，经目标主机批准；短码不能脱离已认证路径全球定位设备。
- 配对后保存设备独立凭据，正常连接不重复输入 owner 登录信息。
- owner 会话、设备凭据、中继接入凭据三者分离，不得互相替代。
- 路线切换保持设备身份与权限；地址、证书、中继身份变化须重新核验，必要时重新配对。
- 设备、主机中继接入与整个中继分别可撤销，撤销立即关闭对应活动会话或隧道。
- SSH 密码和私钥只在操作内存中使用；设备凭据使用安全存储或受限权限文件，不进入不安全浏览器持久存储。

| 接口 | 使用者与含义 |
| --- | --- |
| `POST /api/commander-link` | 本机 owner 管理设备、部署与连接配置 |
| `/link/` | 独立 TLS 远端配对入口 |
| `POST /link/api/workbench` | 已批准设备凭据换取远程工作台会话 |
| `/link/workbench/` | Cookie 保护的页面、API、模块资源与 Gateway 流 |

远程设备不能访问 owner 管理 API。中继/SSH 凭据和任意转发能力不暴露给模型或 MCP；完整字段以 `plugins/link/openapi.json` 为实现契约。

默认入口不保留独立 cloud-access 的 UI、配置、探针或兼容分支；企业级额外防护只能作为独立高级部署能力，不改变 launch-token 默认入口。

## 设备中心与用户路径

页面上方为本机“连接”面板，下方为“设备 / 中继池”两个目录标签；连接管理和部署按主机管理能力显示。

- **设备**：本机第一，与其他设备共用卡片和打开流程；展示名称、路线、最近错误和最后连接时间，不展示密钥。
- **连接**：允许其他设备连接、批准申请、撤销设备和本机连接设置。
- **中继池**：展示优先级、健康状态和最近错误；连接已有中继或 SSH 部署。支持编辑地址、启停、设为主节点与删除，删除最后一个节点时引导停用。

```text
已有设备：添加 → 扫码 / 粘贴连接信息 / 输入地址 → 目标批准
         → 保存身份与路线 → 验证工作台 → 打开
服务器工作台：添加 → SSH 指纹确认 → 认证 → 安装启动
             → 生成短时入口 → 验证工作台 → 加入设备目录
中继：添加 → IP SSL / 域名 SSL → SSH 指纹确认
     → 检查地址、端口、证书 → 部署 → 主机接入 → 客户端验证
```

失败显示具体阶段、脱敏日志和重试动作。移除设备不等于卸载服务器；危险撤销、卸载须说明影响。窄屏、Android 触控、键盘焦点及空、加载、错误、有数据四态遵循统一视觉规范。

中继协议、证书和部署步骤见[自建中继](自建中继.md)，发布版本与回滚机制见[更新与发布](../05-更新与发布/设计.md)。

## 分发与实现边界

GitHub Releases 提供固定版本和校验清单，NPM 分别提供 `benchgo`、`benchgo-relay`。Linux 工作台入口为 `npm install -g benchgo && benchgo install` 或 `npx benchgo install`；中继安装见[自建中继](自建中继.md)。安装脚本固定版本或校验签名，保留已有配置，失败可回滚。

| 范围 | 当前边界 |
| --- | --- |
| 已有实现 | 设备中心、多设备存储、SSH 部署入口、直连优先、有序自托管中继池、配对撤销、诊断与证书管理 |
| 待真实验收 | 家庭 NAT、蜂窝网络、真实 Android/浏览器完整工作台、SSH 首次部署与 NPM 分发；公网 ACME、端口和反代验收见中继设计 |
| 后续目标 | 公共中继控制面、设备组调度、区域/负载选择；macOS 发行及可选 Docker 按平台另验 |
| 不在范围 | 任意端口代理、P2P 打洞、唤醒离线设备、浏览器 LAN 自动扫描、修改官方或参考源码 |

中继池支持多个节点并按优先级有序回退；已有实现不能替代公网真机验收。Android 是 Link 客户端，不作为首版中继主机；Windows、Linux 工作台与 SSH 目标服务器按各自环境验证。

## 验收条件

1. 域名/IP 加 token 可进入工作台，URL 清理、会话属性正确；三类权限不混用。
2. 实测直连优先、有序回退、主节点恢复与新连接回主；证书/授权失败不降级，写请求不重复。
3. 未批准设备、未登记主机和 owner API 被拒；设备撤销立即生效，中继隔离与撤销按[自建中继](自建中继.md)验收。
4. 页面、资源、API、Gateway、交互审批和声明支持的语音协议逐项验证，不只检查进程或端口。
5. 浏览器与原生客户端分别验证 TLS，至少覆盖一种家庭 NAT 和蜂窝网络；部署、端口和证书恢复条件见中继设计。
6. 自动化、真实网络和待验收项分开记录，未验证能力不标完成。
