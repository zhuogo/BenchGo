# 设备与远程连接设计

本板块负责设备保存、可信配对、远程工作台、自托管中继与部署管理。总体关系见[总架构](../总架构.html)，界面约定见[工作台与 Agent](../02-工作台与Agent/设计.md)。已有实现、待实施目标和真实环境验收分开描述。

## 1. 职责与交付边界

| 组成 | 职责 | 边界 |
| --- | --- | --- |
| BenchGo 工作台 | 项目、模型、会话、任务和插件运行 | 数据与任务留在目标主机 |
| Link | 配对、连接路线、远程工作台与撤销 | 源码在 `plugins/link/`，随唯一 `benchgo-plugin` 安装 |
| 设备中心 | 本机连接、设备目录、中继池与部署 | owner 管理仅向具备主机管理权限的客户端开放 |
| `benchgo-relay` | 已授权工作台流量的备用传输 | 独立服务器，不承担模型、项目、账号或 owner 管理 |

Link 通过 `benchgo-plugin/link-plugin` 独立启停，不硬依赖 Harness 聚合或 SuperAgent；访问助手业务时探测 `assistant` 服务。公共配置与组件复用基础层，不复制其他模块的存储或推理逻辑。

`benchgo` CLI 安装完整工作台，`benchgo-relay` CLI 安装独立中继；工作台不得隐式安装中继服务器，不再发布 `@benchgo/server`。这与“五个源码包、一个插件安装包”是不同层面的交付边界。桌面安装包、Android APK 保持平台原生入口。

## 2. 连接与信任模型

设备保存稳定身份、独立授权及多条可信路线。地址、端口与 relay ID 是可变路由信息，不能当作设备身份。

```text
局域网直连 → 公网直连 → 主中继 → 备用中继 → 明确诊断
客户端 ──已批准的设备身份── 目标主机 Link ── 工作台
   └──────── 必要时经自托管 Relay 转发 ────────┘
```

- 目标有可用入站路径时优先直连；无可用入站路径时，主机主动通过 TLS 连出到中继。
- 路线可用须经过 TLS、身份与工作台健康验证，不能依据同 Wi-Fi、端口监听或 SSH 成功判断。
- 证书错误、身份不匹配和授权拒绝立即报告，不降级到下一条路线。
- 网络失败、超时、离线等可恢复错误才允许有限重试和切换；当前中继池按优先级尝试，失败节点冷却 10 秒。
- 最近成功节点不覆盖用户优先级；主中继恢复后新连接回主，活动会话不强制迁移。
- 路线切换不停止主机任务，不重放已提交写请求；保留幂等请求标识、草稿和工作台状态。
- 网络变化、取消、断线与服务关闭须释放连接、事件流和语音流资源。

普通用户自动选路，高级详情查看路线与重试。分别展示主机在线、中继在线、路线可达、工作台可用，不合并成含义不清的“在线”。

## 3. 登录、配对与服务契约

公网 owner 入口统一使用已有短时 `launch-token`，不另设 `cloud-access` 密钥链路：

```text
https://工作台地址/?token=短时票据
→ 服务端校验 → HttpOnly / Secure / SameSite 会话
→ 清理地址栏 token → 打开工作台
```

- launch-token 一次性或短时有效，不写日志、设备记录或普通 API 响应。
- 配对码短时、单次、限流，经目标主机批准；短码不能脱离已认证路径全球定位设备。
- 配对后保存设备独立凭据，正常连接不重复输入 owner 登录信息。
- owner 会话、设备凭据、中继接入凭据三者分离，不得互相替代。
- 路线切换保持设备身份与权限；地址、证书、中继身份变化须重新核验，必要时重新配对。
- 设备、主机中继接入与整个中继分别可撤销，撤销立即关闭对应活动会话或隧道。
- SSH 密码和私钥只在操作内存中使用；设备凭据使用安全存储或受限权限文件，不进入不安全浏览器持久存储。

| 接口 | 使用者与含义 |
| --- | --- |
| `POST /api/commander-link` | 本机 owner 管理设备、部署与连接配置 |
| `/link/` | 独立 TLS 远端配对入口 |
| `POST /link/api/workbench` | 已批准设备凭据换取远程工作台会话 |
| `/link/workbench/` | Cookie 保护的页面、API、模块资源与 Gateway 流 |

远程设备不能访问 owner 管理 API。中继/SSH 凭据和任意转发能力不暴露给模型或 MCP；完整字段以 `plugins/link/openapi.json` 为实现契约。

## 4. 设备中心与用户路径

页面上方为本机“连接”面板，下方为“设备 / 中继池”两个目录标签；连接管理和部署按主机管理能力显示。

- **设备**：本机第一，与其他设备共用卡片和打开流程；展示名称、路线、最近错误和最后连接时间，不展示密钥。
- **连接**：允许其他设备连接、批准申请、撤销设备和本机连接设置。
- **中继池**：展示优先级、健康状态和最近错误；连接已有中继或 SSH 部署。支持编辑地址、启停、设为主节点与删除，删除最后一个节点时引导停用。

```text
已有设备：添加 → 扫码 / 粘贴连接信息 / 输入地址 → 目标批准
         → 保存身份与路线 → 验证工作台 → 打开
服务器工作台：添加 → SSH 指纹确认 → 认证 → 安装启动
             → 生成短时入口 → 验证工作台 → 加入设备目录
中继：添加 → IP SSL / 域名 SSL → SSH 指纹确认
     → 检查地址、端口、证书 → 部署 → 主机接入 → 客户端验证
```

失败显示具体阶段、脱敏日志和重试动作。移除设备不等于卸载服务器；危险撤销、卸载须说明影响。窄屏、Android 触控、键盘焦点及空、加载、错误、有数据四态遵循统一视觉规范。

## 5. 中继协议与隔离

中继验证已登记目标和授权关系，只转发白名单内的工作台 HTTP、事件流、Gateway 与必要 WebSocket。

- 不提供任意 TCP、SOCKS、通用 HTTP 代理或任意上游 URL/IP/端口，防止 SSRF 与内网横向访问。
- 不开放 owner 管理 API、SSH、主机文件系统或未登记目标。
- 不把 owner Cookie、Bearer 或代理身份头当设备授权，重新执行 Host、Origin、路径和方法校验。
- 不保存模型密钥、项目、会话或长期工作台 Cookie；仅保留必要脱敏诊断。
- 处理心跳、租约、断开传播、退避重连、背压、最大帧、超时、并发和超限。
- 无法到达目标时返回受控错误，不泄露内部地址、堆栈或秘密。

当前 TLS 在用户控制的中继终止，运营者可看到转发内容与元数据，不宣称端到端加密。公共托管中继、区域选择、设备组调度和负载均衡是后续目标，不影响自托管使用。

## 6. 端口、证书与部署

Link 配对、工作台和中继只接受 HTTPS，没有远程 HTTP 兼容模式。官方 Harness 的本机 HTTP 监听不代表 Link 明文远程入口。原生客户端可使用自签名证书加 SPKI 信任，普通浏览器不能假定具备同样能力，也不能任意扫描局域网。

默认选择空闲高位业务端口，检测冲突并展示防火墙要求。不停止现有宝塔、Nginx、Apache、Caddy，不抢端口、不自动改防火墙、站点或已有证书；反代只生成用户指定路径的配置片段。

| 模式 | 规则 |
| --- | --- |
| 域名 SSL | 部署前 A/AAAA 至少一条指向目标公网 IP；优先复用现有站点 webroot |
| IP SSL | 使用客户端可验证证书；HTTP-01 经公网 80，业务端口独立 |
| webroot | 显式路径优先、有限候选探测、challenge 公网回读确认；不可写/不可达即停止 |
| 无现有 Web 服务 | 仅在 80 空闲时创建有 BenchGo 归属标记的 challenge 服务 |
| 已有 Web 服务 | 复用明确 challenge 路由，不静默接管；无法验证不能宣告成功 |

现有方案使用 Let's Encrypt `shortlived` IP 证书（160 小时）和 Certbot 5.4+ IP webroot。HTTP-01 必须走 80，TLS-ALPN-01 必须走 443，IP 不支持 DNS-01；高位业务端口不能替代验证端口。依据为 [IP 证书公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability.html)、[Certbot 支持说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot.html)与[验证方式](https://letsencrypt.org/docs/challenge-types/)。

SSH 部署复用 owner 管理接口，检查系统、架构、Node/Python、systemd、磁盘内存、权限和网络。服务最小权限运行、凭据文件受限，只接管归属校验通过的 BenchGo 目录和单元；重部署保留身份，卸载不删除其他服务与用户数据。

证书须可靠续期。SSH 部署可配置受管续期服务；手动证书工具默认不自动安装 timer，须显式启用。仅在证书内容变化时切换版本，重启失败保留待重试标记；“支持续期”不等于当前机器已启用续期。

管理动作包括 `status`、`logs`、`start`、`stop`、`restart`、`renew`、`renew-status`、`diagnose`、`uninstall`。诊断聚合服务、续期 timer、端口和失败单元并脱敏。部署成功以客户端实际打开页面、API、必要 Gateway/WebSocket 为准。

## 7. 分发与实现边界

GitHub Releases 提供固定版本和校验清单，NPM 分别提供 `benchgo`、`benchgo-relay`。安装脚本固定版本或校验签名。Linux 工作台入口为 `npm install -g benchgo && benchgo install` 或 `npx benchgo install`；中继为 `benchgo-relay install --config relay.json`。发布与回滚见[更新与发布](../05-更新与发布/设计.md)。

| 范围 | 当前边界 |
| --- | --- |
| 已有实现 | 设备中心、多设备存储、SSH 部署入口、直连优先、有序自托管中继池、配对撤销、诊断与证书管理 |
| 待真实验收 | 公网 ACME 签发/续期、端口冲突/反代、家庭 NAT、蜂窝网络、真实 Android/浏览器完整工作台、SSH 首次部署与 NPM 分发 |
| 后续目标 | 公共中继控制面、设备组调度、区域/负载选择；macOS 发行及可选 Docker 按平台另验 |
| 不在范围 | 任意端口代理、P2P 打洞、唤醒离线设备、浏览器 LAN 自动扫描、修改官方或参考源码 |

早期单节点清单已由有序多节点设计替代；旧清单不代表当前只支持一个中继，已有源码也不替代公网真机验收。

## 8. 验收条件

1. 域名/IP 加 token 可进入工作台，URL 清理、会话属性正确；三类权限不混用。
2. 实测直连优先、有序回退、主节点恢复与新连接回主；证书/授权失败不降级，写请求不重复。
3. 未批准设备、未登记主机、任意上游与 owner API 被拒；设备/主机/中继撤销立即生效。
4. 页面、资源、API、Gateway、交互审批和声明支持的语音协议逐项验证，不只检查进程或端口。
5. 端口冲突、现有站点、续期失败和离线重连有恢复路径，已有服务及数据保留。
6. 浏览器与原生客户端分别验证 TLS，至少覆盖一种家庭 NAT 和蜂窝网络。
7. 自动化、真实网络和待验收项分开记录，未验证能力不标完成。
