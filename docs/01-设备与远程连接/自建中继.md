# 自建中继

本模块维护自托管 Relay 的协议隔离、TLS、部署与服务管理。设备身份、配对、选路优先级和设备中心入口见[设备与远程连接设计](设计.md)，不在这里重复定义。中继使用独立 `benchgo-relay` 安装包，不随工作台隐式安装。

## 连接与中继记录

目标主机的 Link 主动通过 TLS 连出到已配置中继，客户端经可信中继路线访问已授权工作台。中继记录保存中继身份、接入主机、授权关系、心跳和短期路由状态，不能自行签发设备授权。

## 中继协议与隔离

中继验证已登记目标和授权关系，只转发白名单内的工作台 HTTP、事件流、Gateway 与必要 WebSocket。

- 不提供任意 TCP、SOCKS、通用 HTTP 代理或任意上游 URL/IP/端口，防止 SSRF 与内网横向访问。
- 不开放 owner 管理 API、SSH、主机文件系统或未登记目标。
- 不把 owner Cookie、Bearer 或代理身份头当设备授权，重新执行 Host、Origin、路径和方法校验。
- 不保存模型密钥、项目、会话或长期工作台 Cookie；仅保留必要脱敏诊断。
- 处理心跳、租约、断开传播、退避重连、背压、最大帧、超时、并发和超限。
- 无法到达目标时返回受控错误，不泄露内部地址、堆栈或秘密。

当前 TLS 在用户控制的中继终止，运营者可看到转发内容与元数据，不宣称端到端加密。公共托管中继、区域选择、设备组调度和负载均衡是后续目标，不影响自托管使用。

中继接入凭据与设备授权分离，凭据不进入 URL、日志或列表响应。支持单独撤销主机接入、轮换中继凭据和关闭整个中继，撤销立即关闭对应隧道及会话；节点地址或密钥变化必须重新验证，不能静默导流。

## 端口、证书与部署

Link 配对、工作台和中继只接受 HTTPS，没有远程 HTTP 兼容模式。官方 Harness 的本机 HTTP 监听不代表 Link 明文远程入口。原生客户端可使用自签名证书加 SPKI 信任，普通浏览器不能假定具备同样能力，也不能任意扫描局域网。

默认选择空闲高位业务端口，检测冲突并展示防火墙要求。不停止现有宝塔、Nginx、Apache、Caddy，不抢端口、不自动改防火墙、站点或已有证书；反代只生成用户指定路径的配置片段。

| 模式 | 规则 |
| --- | --- |
| 域名 SSL | 部署前 A/AAAA 至少一条指向目标公网 IP；优先复用现有站点 webroot |
| IP SSL | 使用客户端可验证证书；HTTP-01 经公网 80，业务端口独立 |
| webroot | 显式路径优先、有限候选探测、challenge 公网回读确认；不可写/不可达即停止 |
| 无现有 Web 服务 | 仅在 80 空闲时创建有 BenchGo 归属标记的 challenge 服务 |
| 已有 Web 服务 | 复用明确 challenge 路由，不静默接管；无法验证不能宣告成功 |

现有方案使用 Let's Encrypt `shortlived` IP 证书（160 小时）和 Certbot 5.4+ IP webroot。HTTP-01 必须走 80，TLS-ALPN-01 必须走 443，IP 不支持 DNS-01；高位业务端口不能替代验证端口。依据为 [IP 证书公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability.html)、[Certbot 支持说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot.html)与[验证方式](https://letsencrypt.org/docs/challenge-types/)。

SSH 部署复用 owner 管理接口，检查系统、架构、Node/Python、systemd、磁盘内存、权限和网络。服务最小权限运行、凭据文件受限，只接管归属校验通过的 BenchGo 目录和单元；重部署保留身份，卸载不删除其他服务与用户数据。

证书须可靠续期。SSH 部署可配置受管续期服务；手动证书工具默认不自动安装 timer，须显式启用。仅在证书内容变化时切换版本，重启失败保留待重试标记；“支持续期”不等于当前机器已启用续期。

管理动作包括 `status`、`logs`、`start`、`stop`、`restart`、`renew`、`renew-status`、`diagnose`、`uninstall`。诊断聚合服务、续期 timer、端口和失败单元并脱敏。部署成功以客户端实际打开页面、API、必要 Gateway/WebSocket 为准。

已有中继先展示状态并复用，不能重复安装或覆盖外部服务。中继重启后主机应重新认证接入；版本不兼容、证书过期和连接密钥变化分别报告原因，不静默降低安全约束。

## 安装与实现边界

手动安装使用 `npm install -g benchgo-relay`，再执行 `benchgo-relay install --config relay.json`；完整操作入口见 [Link 说明](../../plugins/link/README.md)。GitHub/NPM/SSH 使用同一服务协议，脚本固定版本或校验签名，展示动作，保留已有配置，失败可回滚。发行流程见[更新与发布](../05-更新与发布/设计.md)。

已有核心通道、自托管多节点接入、SSH 部署、诊断与证书管理实现。公网 ACME 签发/续期、端口冲突与现有反代复用、SSH 首次部署及 NPM 分发仍需真实环境验收，不能由端口监听或历史测试代替。

部署还需明确最低服务器资源、带宽及并发限制、日志保留和流量费用提示；现有背压及帧限制不等于已完成这些产品说明。公共托管控制面与区域/负载调度属于后续目标。

## 验收条件

1. 未登记主机、任意上游 URL/IP/端口、非白名单路径及 owner 管理 API 均被拒；设备凭据不能获得中继或 owner 管理权限。
2. 主机接入撤销、凭据轮换与关闭中继立即清理活动连接，断开和背压正确传播，重连不重复提交写请求。
3. 真实客户端经中继访问页面、资源、API、Gateway 及声明支持的 WebSocket；主机在线或 SSH 成功不能作为交付结论。
4. 域名/IP 证书、续期、过期、端口冲突、现有站点和反代分别验证；错误有恢复路径，已有服务和用户数据保留。
5. 浏览器和原生客户端分别验证 TLS 与信任边界；家庭 NAT、蜂窝网络及跨路线行为按[设备连接验收](设计.md#验收条件)完成。
6. 实测与待验收项分别记录，不因具备续期命令就宣称该机器已启用自动续期。
