# 前端视觉规范

更新：2026-11-04。本规范是 BenchGo 自有前端（plugins/ 下各源码包客户端）的视觉真源；开发与验收均以此为准。与本规范冲突的旧文档风格限制（如「克制、无渐变、无装饰」类表述）一律以本规范为准，不再执行。

## 总原则

- 现代产品质感优先：信息用卡片、图标、状态色与层级承载，不用纯文本堆砌代替设计。
- 品牌色与状态色该用就用：可用/选中/状态区分靠颜色与图标表达；适度渐变、阴影、圆角都是正常手段，不预先禁用。
- 一致性来自复用：同一类信息（任务、状态、空缺）在所有页面长同一种样子，优先复用已有组件与样式类，不逐页现编。

## 四态要求（空 / 加载 / 错误 / 有数据）

每个列表、面板、页面都必须设计四态，缺一不可：

- **空状态**：居中布局，包含图标或 SVG 插画、一行标题、一句说明；有下一步行动时给行动入口。禁止只放一行左对齐的裸文本（如单独的「暂无…」「还没有…」）。
- **加载状态**：有结构地占位（骨架、图标加文案或进度指示），不留白屏、不闪烁跳版。
- **错误状态**：说明发生了什么 + 重试入口，不只报原始错误码。
- **有数据**：任务等信息列表行至少包含标题、摘要、状态徽章（颜色圆点或图标）、时间；状态之间靠颜色与图标区分，不靠文字猜。侧栏对话列表采用单行标题 + 右侧时间和状态，不显示摘要；悬停或键盘聚焦时在右侧显示置顶、归档、更多操作，三者统一图标规格与圆角，行背景透明。

## 组件与图标

- 空状态、状态徽章、列表行优先用共享组件或既有样式类实现；新页面不得另起一套长相。
- 图标用现有图标库（iconsax 目录）或内联 SVG；图标库没有的，用同风格描边 SVG 补，不用表情符号冒充图标。
- 插画优先 SVG；品牌形象与素材以 `assets/brand/` 为唯一来源。

## 对话与卡片

- 聊天里需要操作的结构化事件（定时、审批、提问）用卡片呈现，样式与宿主原生卡片对齐。交付结果按普通助手消息自然表达，不另设“交付通知”标题、卡片外框或已读操作；必要的回答选项保留。
- 过程信息收进工单与看板；聊天只放结论、卡片与必要确认（沿用 SuperAgent 对话层设计）。

## 验收

- 前端改动交付前，逐页自查四态的实际渲染（构建通过不等于长相对）；只验功能、不看长相不算完成。
- 评审发现纯文本占位、未居中的空状态、无图标的状态区分时，直接打回重做。
