# 工作台与 Agent 设计

本文件是工作台、源码装配、公共前端规范与产物预览的唯一板块设计。总机制见[总架构](../总架构.html)，SuperAgent 的任务业务见[总助手设计](../06-superagent/设计.md)。本文区分既有实现、设计约束与待完成边界，不以历史测试数量代替当前验收。

## 1. 产品范围与入口

BenchGo 工作台承载项目与会话导航、Agent 接入、公共设置、模型与工具、统计和更新；SuperAgent、Voice、Link 在同一产品体系内提供各自入口。桌面和移动端沿用同一品牌、共享组件与授权服务。

用户的主要路径是进入工作台、选择项目或会话、使用对应 Agent、查看任务进展与产物，再返回原会话继续。设置中显示真实安装、连接与能力状态；服务缺失或停用时保留必要说明和配置入口，不伪装成可操作能力。

主聊天、旁聊、任务、产物和设置应有明确入口与返回路径。切换列表、打开详情、返回页面不丢失位置或未保存草稿。桌面复用官方工作台接入点，Windows 启动页由 `scripts/desktop/renderer/` 维护，不修改官方欢迎页。

## 2. 源码、服务与发布架构

### 2.1 五个源码包，一个安装包

| 源码位置 | 职责 | Cordis 入口与服务 |
| --- | --- | --- |
| `plugins/benchgo/` | 基础层、公共配置、模型、项目、统计、更新、客户端装配 | `benchgo-plugin`，提供 `benchgo` |
| `plugins/harness/` | 原生 Agent 聚合、会话生命周期、委派、MCP 桥与适配器 | `benchgo-plugin/harness-plugin`，提供 `commander` |
| `plugins/superagent/` | 对话、工单、目标、记忆、媒体与后台工作器 | `benchgo-plugin/superagent-plugin`，提供 `assistant` |
| `plugins/voice/` | 语音服务、输入、播放、协议适配与界面 | `benchgo-plugin/voice-plugin` |
| `plugins/link/` | 设备直连、远端工作台、移动界面与 Android | `benchgo-plugin/link-plugin` |

五个入口随唯一 `benchgo-plugin` 安装，分别管理启停；源码包和规划目录不是额外安装包。基础层必须使用完整包根入口，供官方 `clientModules` 发现统一客户端；客户端注册 ID 也只能是 `benchgo-plugin`。

依赖关系：基础层提供公共服务；Harness 聚合依赖基础层；SuperAgent 依赖基础层、`commander` 和官方会话服务；Voice、Link 不硬依赖 Harness 聚合或 SuperAgent。Link 可选探测并调用 `assistant`，不能读取助手私有存储。

官方 `agents`、`sessionQuery`、`llm`、Schedule、skills 与自有 `commander` 聚合服务职责不同。SuperAgent Worker 直接使用官方 Agent 会话执行；Harness 聚合管理外部原生 Agent，不为总助手再实现一套推理循环。

关闭基础层会使依赖它的模块不可用；关闭 Harness 聚合会影响依赖它的 SuperAgent，不应阻断 Voice、Link 的独立基础能力。用户显式禁用的状态必须保留，不能被默认值重新启用。

### 2.2 公共实现与生命周期

- 公共服务和数据目录解析复用 `plugins/benchgo/src/`、`plugins/benchgo/shared/`，不为拆包复制实现。
- 公共前端在 `plugins/shared/client/`，不是独立插件；唯一客户端负责装配各业务界面。
- 每个 Cordis 入口拥有并释放自己的事件、路由、工作器、定时器与资源；停用不能删除持久化数据。
- 释放 SuperAgent 时关闭它自己的会话写入方和数据库；Harness 管理的独立外部任务按运行时生命周期处理。
- 保留 `commander` 服务与配置键、`commander_*` / `assistant_*` 工具名、HTTP 路由、CLI 兼容命令、环境变量和运行数据格式。`assistant/` 运行目录不随源码改名。
- 保留 `benchgo-plugin/runtime` 导出；MCP 桥与 Pi 扩展必须指向真实资源，不以旧源码空壳或额外别名维持路径。

### 2.3 构建与开发

| 位置或命令 | 边界 |
| --- | --- |
| `deepseek-harness/` | 官方 Git 子模块，只更新 pin，不修改源码；版本真源为根目录 `upstream.json` |
| `reference/` | 参考仓库，不参与产品依赖或构建，不修改 |
| `scripts/desktop/` | Windows 打包、品牌注入、启动页与开发启动 |
| `plugins/benchgo/lib/modules/` | Harness、SuperAgent、Voice 发布源码及动态资源的生成目录 |
| `plugins/benchgo/lib/client.js` | 统一客户端生成产物 |
| `plugins/benchgo/lib/link.mjs`、`lib/link-web/` | Link 服务与网页生成产物 |
| `npm run setup/build/dev/start/check` | 根目录命令封装，实际依赖由子模块锁定的 Corepack pnpm 管理 |

发布包必须在脱离同级源码目录后仍可加载；构建重定位跨模块相对导入，并保留 `import.meta.url` 使用的动态资源。生成目录不手工维护，发布闭包不携带备份、编辑器或补丁临时文件。

Windows `npm run dev` 通过 `scripts/desktop/prepare-dev.mjs` 启动已打包的 BenchGo，不能启动官方 Desktop 替代产品预览。开发同步须同时校验新增依赖：官方服务应使用宿主同一模块实例；第三方 SDK 缺失时可链接已安装且版本兼容的本地目录，不能覆盖用户实体依赖。

修改 BenchGo 或 Link 网页后运行 `npm run reload:plus`，重建模块、统一客户端和 Link 网页；运行中的 Harness 热加载，浏览器刷新。该流程不重启 Web、不构建服务器种子。桌面受管安装副本仍需按既有同步流程核对实际载入版本。

更新引擎从官方 `origin/master` 获取提交，同时更新子模块 pin 和 `upstream.json`，再验证兼容性。`npm run check` 只验证版本、工作区与入口一致性，不证明构建、启动或真实请求成功。

## 3. 公共前端视觉与交互规范

本节是 BenchGo 自有前端的视觉真源，适用于五个源码包的客户端、Link 移动界面和 Windows 启动页。官方界面继续通过适配入口复用；不修改官方子模块样式源码。

### 3.1 视觉原则

现代产品质感、清楚的信息层级和一致交互优先。信息可用卡片、图标、状态色、适度渐变与阴影表达；不执行旧文档中一概禁止渐变、装饰或阴影的限制。页面标题、工具栏和保存区不因为包含按钮就套灰色外框；优先用对齐、留白、字号和字重建立层级。

同类任务、状态、空缺和操作复用已有组件，不逐页建立另一套外观。品牌形象与插画素材以 `assets/brand/` 为唯一来源；PC、移动端与初始化使用同一 BenchGo 形象。图标用既有 iconsax 或同风格描边 SVG，不用表情符号代替图标。

### 3.2 字号、间距和颜色基线

字体继承宿主与既有 BenchGo 字体，不在单页引入新字体体系。下表记录现有共享样式与工作台的明确尺度，优先直接复用组件；业务页面可按内容密度调整，不能据此批量覆盖宿主样式。

| 项目 | 现有基线 |
| --- | --- |
| 共享间距单位 | `0.25rem`；常用组合为 4 / 8 / 12 / 16 / 24px |
| 紧凑侧栏、辅助说明 | 12px；工作台基础与按钮 13px；内容正文按既有页面使用 13–14px |
| 折叠标题与说明 | 标题 14px、字重 550、行高 1.5；说明 12px |
| 通用弹窗标题 | 20px、字重 600、行高 1.4；正文说明 13px、行高 1.65 |
| 默认按钮 | 高度至少 36px，内边距 8px 14px，图文间距 8px，圆角 8px |
| 按钮尺寸 | 小号至少 30px；大号至少 42px；图标按钮宽 36px；移动端保留既有触控尺寸和安全区 |
| 共享圆角 | 6 / 8 / 12px；通用弹窗 14px |
| 焦点反馈 | 2px 清晰焦点轮廓；共享按钮外偏移 3px |
| 文本与背景 | 优先 `--dsw-alias-label-primary/secondary`、`--dsw-alias-bg-base`；共享浅色回退 `#202124` / `#6b6b70` / `#fff` |
| 深色回退 | 主文字 `#ededee`，次文字 `#a3a3a8`，背景 `#19191b` |
| 主动作色 | 优先 `--dsw-alias-state-business-primary` 或 Link 主题；共享回退 `#315be8`，工作台既有回退 `#4d6bfe` |
| 工作台状态色 | 运行/连接 `#438bea`，完成 `#36a36b`，等待 `#b98824`，失败 `#d05c5c`；同时提供图标和文字 |

共享主题变量优先于硬编码回退；上述两种主色回退是现有不同容器的兼容值，不允许据此另造页面主题。边界线和悬停底色使用主题混色，延续明暗模式与减少动画偏好。

**可用性与选中状态分离。** 工具、供应商或连接器已安装且真实可用时显示品牌色，不可用时显示灰色；不能因为选中而变成可用颜色。选中使用单层底色、轮廓或文字强调，连接状态另行显示；保存了 `enabled` 不代表认证成功或服务可用。

### 3.3 四态

| 状态 | 必须呈现的内容 |
| --- | --- |
| 空 | 居中图标或 SVG、一行标题、一句说明；有下一步时给行动入口，不只放左对齐“暂无”裸文本 |
| 加载 | 骨架、图标加文字或进度指示，保留结构，不白屏、不闪烁跳版 |
| 错误 | 说明发生了什么、必要的真实原因与重试入口，不只显示原始错误码 |
| 有数据 | 任务列表提供标题、摘要、状态图标或徽章、时间；信息层级清楚，状态不只靠颜色区分 |

对话侧栏是紧凑导航：单行标题，右侧时间和状态，不显示摘要。悬停或键盘聚焦时显示置顶、归档、更多操作，图标规格和圆角一致，操作区背景透明；触屏仍有可达入口。

### 3.4 共享组件与表单

既有实现采用 React JSX + esbuild、本地维护的 shadcn/ui 组件组合、Radix 行为基础与按需 Tailwind v4。公共组件位于 `plugins/shared/client/ui/`；shadcn `new-york` registry 组合的参考校对日期为 2026-11-03，适配源码保留 MIT 许可，不额外安装一套插件。

- 普通动作使用 `Button variant="ghost"`，主要提交用 `default`，危险动作用 `destructive`。
- 普通按钮默认不提交；表单提交显式设置 `type="submit"`，禁用与忙碌状态遵守真实操作状态。
- 折叠使用 `Disclosure`：完整标题行、右侧 Chevron、悬停和焦点反馈；可用受控或默认展开状态，展开区不重复嵌套卡片。
- 分段控件只保留单层选中底色；输入框、独立内容边界和浮层按需要使用边框。
- 折叠内容可能卸载，必填校验基于完整草稿；错误时展开对应区域，不能只依赖隐藏字段的浏览器校验。
- 对话中的定时、审批、提问等可操作事件使用与宿主一致的卡片。最终交付作为普通助手消息，不另套“交付通知”外框或已读操作。
- 执行过程收进工单与看板；聊天保留结论、提问和必要状态，失败必须如实显示，不能用模型推测替代系统事实。

`plugins/benchgo/scripts/shared-ui.mjs` 扫描 `bg:` 前缀工具类并编译主题，不加载 Tailwind preflight 或全局元素重置。动态拼接类名不能假定被扫描；插件构建保持 React external，Link 明确统一 React 解析位置。共享样式按使用者计数挂载，热加载更新，最后一个使用者卸载后清理。

## 4. 选择器与配置状态

BenchGo 自有页面统一使用 `plugins/shared/client/custom-select.jsx`，不使用浏览器原生下拉菜单。平台接入、宠物表情、保险库、预览与移动资源导航复用同一实现；键盘操作、焦点恢复、弹层定位由共享组件负责。

显示名称和协议值分离；保留原始模型 ID、工具名、协议值、数值转换、禁用与保存语义。移动资源列表用分区名称前缀保留归属。选择、保存、重载与实际请求必须一致，编辑一项不能丢失其他配置。

连接状态轮询不得覆盖配置草稿。启用的当前渠道沿用每三秒串行刷新；切换渠道、操作中与卸载后丢弃旧刷新结果，避免认证结果被过期请求覆盖。不支持的能力要明确提示，不能静默替换选择。

## 5. 任务列表与详情

主对话侧栏的任务卡采用两行：名称与时间、状态与摘要。整项可打开详情，长内容在列表中省略、在详情中完整显示；停止入口放在详情，不另设“查看记录”按钮或“审核”分页。这里的任务卡不同于第 3 节的单行会话导航。

工单、持续目标、待处置评估复用 `plugins/superagent/client/task-list.jsx` 的摘要行与详情容器。业务列表包含完成标记、名称、最多两行摘要和右侧图标操作；标题与摘要都可进入详情。暂停、继续、重开、重命名、删除提供可访问名称与悬停说明，触屏保留入口。

- 重命名只改列表名称，保留原始要求、目标和消息。
- 人工完成是整理标记，不等于自动验收通过；取消标记不能自动重新执行。
- 再次执行使用原有工单重开、目标恢复或重新评估流程，不绕过授权与验收。
- 删除只移出列表，保留执行及处置历史；仍可能运行的条目须先安全停止。
- 修改持久化且校验版本，旧页面不能覆盖新名称或状态；切换分类和关闭详情保护未保存草稿。

详情保留问题答复、要求修订、实际证据、文件检查点、目标关联与评估处置入口。工单通过自动验收后交付原来源，无需用户重复确认；缺少信息、权限或范围决定时显示真实等待状态。目标仍可跟踪，用量仍可统计；金额、执行时长和 Goal 补时预算闸门已移除，不再展示旧预算操作。

## 6. 产物快览与转换服务

### 6.1 已有实现与交互

Desktop 与 Link 共用 `plugins/shared/client/artifact-preview.jsx` 和既有受授权文件接口，在产物卡片、列表和系统文件中只读快览。不引入在线编辑器、任意文件路径/URL 读取能力或外部文档上传服务。

点击文件进入内容页，顶部保留返回、文件名、下载原文件；返回恢复列表位置。正文占主要区域，加载、错误、重试和格式限制在正文区呈现。移动端只展示当前内容，表格在自身区域滚动，沿用品牌字体、主题和按钮。

| 格式 | 渲染与能力边界 |
| --- | --- |
| Markdown | Marked + DOMPurify，支持 GFM，过滤主动内容，可切换原文 |
| JSON | 原文或按需展开树；逐层分页，避免一次创建巨大 DOM |
| XLS/XLSX/CSV/TSV | SheetJS + Worker，工作表切换、搜索、虚拟行、单元格原值；只读已保存结果，不执行公式，不承诺图表/透视表和完整样式还原 |
| DOCX | docx-preview，在隔离 iframe 中排版；失败可尝试 PDF 备用预览 |
| PDF | PDF.js 按页渲染 |
| PPT/PPTX/DOC/ODT/RTF | 可选本机 LibreOffice 转 PDF；默认安装不捆绑转换器 |
| HTML | 无同源权限的 sandbox iframe；禁止脚本、网络、表单与跳转，只预览自包含页面，明确提示外部资源限制 |
| 图片、音频、视频 | 复用浏览器原生展示 |

HTML 完整交互只能下载原文件后打开，不提供宿主内脚本开关。HTML、DOCX 不插入宿主 DOM，文档内容不能读取宿主凭据。

重型解析器作为独立本地 ESM 静态资源，经基础层授权路由按需加载，不进入首屏客户端包，不使用运行时 CDN。直接依赖成熟库，不复制其实现；保留许可证，随唯一插件发布。

| 库 | 既有固定版本与来源 |
| --- | --- |
| Marked | 18.1.2，`markedjs/marked` |
| DOMPurify | 3.4.17，`cure53/DOMPurify` |
| docx-preview | 0.4.1，`VolodymyrBaydalka/docxjs` |
| SheetJS CE | 0.20.3，`git.sheetjs.com/sheetjs/sheetjs` |
| PDF.js | 5.4.624，`mozilla/pdf.js` |

### 6.2 文件和资源边界

沿用授权、根目录、符号链接与文件大小检查。文本快览上限 2 MiB，Office 输入上限 25 MiB，ZIP 声明展开内容上限 64 MiB / 4096 项，表格上限 10000 行 / 100 列；截断或限制必须说明。关闭预览时中止读取、终止解析 Worker、释放 PDF 资源。

现有 artifact 与 system-file GET 接口使用 `preview=pdf` 请求转换。成功返回 PDF；未安装转换器返回 503 / `PREVIEW_CONVERTER_UNAVAILABLE`，不支持格式返回 415；客户端保留原文件下载。HTTP 变更同步 OpenAPI，不新增 MCP 文件读取工具。Link 透传已授权工作台 API，不扩大远端权限。

转换只接收已经通过文件检查的字节。调用 LibreOffice 使用独立临时用户目录、无 shell 参数传递、隐藏 Windows 窗口；60 秒超时，串行转换，最多 8 个排队请求，相同输入合并。

缓存键包含内容哈希、扩展名和 LibreOffice 版本；进程内 LRU 上限 64 MiB，单份输出上限 25 MiB。成功、失败和超时清理临时目录；宿主被强制终止仍可能遗留系统临时目录。`BENCHGO_LIBREOFFICE` 可指定可执行文件，否则查找系统安装位置和 PATH。

## 7. 实现边界与验收要求

五源码包、五入口、统一客户端、公共组件和快览服务已有实现。以下不能由目录收敛、构建成功或历史测试通过推定完成：

- SuperAgent 仍通过 `commander.store.directory` 获取数据目录，迁往基础层公开服务尚未完成；Worker 上下文仍需收窄为任务切片。
