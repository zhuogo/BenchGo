# 工作台与 Agent 设计

本文件维护板块范围与设计导航。各小模块独立维护一份设计，公共规则通过链接引用，不在板块总览重复。整体关系见[总架构](../总架构.html)，SuperAgent 的任务业务见[总助手设计](../06-superagent/设计.md)。各设计区分既有实现、设计约束与待完成边界，不以历史测试数量代替当前验收。

## 产品范围与入口

BenchGo 工作台承载项目与会话导航、Agent 接入、公共设置、模型与工具、统计和更新；SuperAgent、Voice、Link 在同一产品体系内提供各自入口。桌面和移动端沿用同一品牌、共享组件与授权服务。

用量统计已实现本地日期范围、完整区间汇总、分组与分页记录。混合历史中各 Token 字段仅累加已知值，全部缺失时显示“未提供”，不把未知记为零；有缺项时显示“仅汇总已知用量”。缓存命中率只使用同时提供缓存读取和可计算输入总量的同一批记录，避免不同覆盖范围混算。图表与概览按相同去重后的完整区间统计，详细记录保留各项缺失事实；今天、3/7/15/30 天沿本地时区取整日，结束边界排他。安装版数据和最终视觉仍由用户验收。

用户的主要路径是进入工作台、选择项目或会话、使用对应 Agent、查看任务进展与产物，再返回原会话继续。设置中显示真实安装、连接与能力状态；服务缺失或停用时保留必要说明和配置入口，不伪装成可操作能力。

SuperAgent 用户始终与 Router 对话。Worker 保存成果原稿并通知 Router 后，由 Router 主动自然提醒、自选摘要或完整回复并交付原来源；原稿保留在任务详情，真实状态在任务列表可查。聊天不固定工单报告、标题前缀或系统状态文案，保留提问与审批卡；交付和失败重试规则见[结果与交付](../06-superagent/结果与交付.md)。

主聊天、旁聊、任务、产物和设置应有明确入口与返回路径。切换列表、打开详情、返回页面不丢失位置或未保存草稿。桌面复用官方工作台接入点，Windows 启动页由 `scripts/desktop/renderer/` 维护，不修改官方欢迎页；标题与透明吉祥物同步进入、轻表情及全窗口跟随系统主题的唯一视觉正文见[Windows 启动页](前端视觉规范.md#windows-启动页)。

渠道会话同样进入工作台会话列表，带来源标记，可打开并直接回复；可呈现为旁聊，但复用统一会话机制，不为渠道另建会话实现或保存第二份对话状态。渠道与工单的关联、适配器事实标注及统一入口分工只在[链接与渠道](../06-superagent/链接与渠道.md)维护；实现边界统一由该正文维护，不因适配器已有收发能力而推定会话路径完整可用。
