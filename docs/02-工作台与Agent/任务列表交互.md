# 任务列表交互

板块入口见[工作台与 Agent](设计.md)。 本文维护任务列表与详情的用户操作；调度、授权、自校验与交付机制见[SuperAgent](../06-superagent/设计.md)。

## 列表与详情

工单列表、看板与详情的业务状态统一为「进行中、等待、完成」，持久及接口对应 running / waiting / completed。其他进展只作短原因或执行事实，规则唯一正文见[工单三态与简短摘要](../06-superagent/自校验与交付.md#工单三态与简短摘要)。

主对话侧栏的任务卡采用两行：名称与时间、状态与摘要。聊天看板显示未归档、未删除的「进行中 / 等待 / 已完成」工单，展开按钮和任务分页使用同一份去重列表计数；归档工单和持续目标不计入，零项不显示数字。已完成工单保留在看板的「已完成」分组，仍可打开详情；手动归档后从看板移出，归档记录继续在全局任务管理查看。工单在已打开详情期间完成时保留当前详情，返回后仍可在已完成分组查看。整项在同一看板容器内打开详情，长内容在列表中省略、在详情中完整显示。工单详情不使用弹窗，返回时保留筛选、展开、滚动与原行焦点；列表 DOM 保持挂载。详情首屏展示任务进展与统一的「全执行记录」，状态仅保留标题图标，不用通用系统状态块占据首屏。看板不展示要求与验收条件；真实问题、审批或无法自主解决的阻塞仍保留原因与操作入口。正文独立滚动、操作固定在底部；「查看执行会话」「前往任务管理」使用图标与共享 Tooltip，并保留可访问名称。显式续接沿用原领域接口，失败保留原记录；执行会话入口打开同一真实 session，不另设重复的“查看记录”按钮。

聊天看板保留「任务」「身份」，增加「审核」；工作台「任务」分类继续保留原审核入口。两处聚合同一批官方批准/拒绝请求，包含高危动作及 `assistant_ticket_change` Mandate 扩权，普通 question 仍属于等待答复。审核列表显式进入同容器详情，返回保留滚动与焦点；真实计数来源未连接完整或失败时显示未知，不把未知当零。详情复用原官方卡、请求身份与生命周期，冻结对象及内容只做脱敏展示；请求处理、撤回或失效后不自动选择另一张批准卡。审核只作聚合兜底，不替代 Router 提醒，不作成果验收；三层呈现、来源归属与原官方审批卡规则统一见[对话交互](../06-superagent/对话交互.md#权限与安全输入交互)。这里的任务卡不同于[视觉规范](前端视觉规范.md#四态)中的单行会话导航。

工单状态、刷新及执行会话入口由任务列表及详情统一承载；界面不再提供暂停、停止按钮，底层保留历史控制事实与执行边界保护。聊天容器不展示通用等待/系统状态块、重复问题正文和上述操作；真实提问保留原消息答复入口。Worker 待批先由 Router 自然提醒，原官方卡挂在提醒处随对话流；审核 Tab 聚合同一请求并提供定位入口，原官方会话卡仍可查，一处作答后其他入口同步失效。聊天顶部不另堆固定授权块或弹窗。

工作区独立「目标」页面与「任务」并列，仅保留一个页面标题。目标是供 AI 长期参考的轻量清单，创建统一由用户在 SuperAgent 对话中提出，任务页及目标页不提供创建按钮或表单。清单支持勾选完成、恢复未完成、编辑和删除，完成状态持久保存并供 AI 读取；编辑草稿切换资源分区后保留，未保存标记归属目标页。历史已绑定工单的目标保留原执行语义，通过查看工单跟踪，不以人工勾选绕过原执行状态。任务页仅保留「工单 / 审核」。桌面侧栏、移动端资源选择及原有目标跳转入口指向同一页面。已移除待处置评估整个前端板块及专用操作入口。

工单复用 `plugins/superagent/client/task-list.jsx` 的摘要行与详情容器；目标清单复用其图标操作和共享表单组件，直接展示完整目标文字，不增设详情弹窗、用量面板或执行控制。工单列表包含名称、最多两行摘要和右侧图标操作；标题与摘要都可进入详情。列表与看板标签关联同一内容区；搜索支持内置清除与 Escape，清除后焦点保留在搜索框。未同步时不编造工单数量，归档筛选在空、加载和错误状态仍可达。继续、关联调整、重命名及适用的整理操作提供可访问名称与悬停说明，触屏保留入口；工单整理使用归档与恢复展示入口，不以“删除”冒充归档。

工作区 → 任务按最近活动排序，最近在前：优先使用有效 `updatedAt`，缺失或无效时回退有效 `createdAt`；时间相同保留来源次序，均无有效时间的条目排在末尾。任务管理查询先按最近活动取最新 1000 条，再由统一任务投影提供顺序，工单列表、搜索结果与看板各列沿用该顺序；不按执行状态或人工完成标记额外置顶，也不以工具动态更新时间代替任务更新时间。

工单完成后保留 completed 和原会话、成果入口，不自动归档或隐藏。用户主动清理继续使用同单展示元数据，保留“已归档”查询及恢复入口，不创建第二份记录，也不覆盖三态或删除输入、结果和回执。失败、暂停及停止的工单为 waiting，控制和恢复条件另记。手动归档筛选须先于分页和数量截断；查看工单或执行会话不自动恢复归档标记、不重新执行。

任务页标题随当前分类显示「工单」或「审核」，不再显示两类混合的说明。打开具体工单及整理清单后隐藏页面标题和分类切换，返回列表恢复导航与原筛选。工单的显示范围、视图、搜索、归档、定时任务和设置合为一条工具栏；桌面同排对齐，搜索限制宽度，窄屏按空间换行。当前工单 / 已归档是显示范围，列表 / 看板是呈现方式，两组均使用图标标签、可访问名称与共享气泡，保留方向键切换。搜索图标与输入文字保持独立留白；不显示总工单数量，提供「归档已结束工单」图标，气泡说明当前搜索范围内可归档数量。该按钮是批量归档操作，先核对清单，再由用户确认；与只读归档筛选区分。审核内容区不再重复标题、数量和说明，刷新及详情返回统一使用图标与共享气泡。

工单详情使用「记录 / 要求 / 结果」三项图标与短文案分段页签，放在标题栏右侧、修订或关联调整图标左侧；可访问名称保留「执行记录 / 任务要求 / 结果与证据」。复用共享控件的浅中性底色、单层选中块与键盘方向键切换，默认打开执行记录，窄容器允许操作组另起一行并靠右。任务要求按真实要求版本分组为边框折叠卡，当前版本默认展开，旧版本默认收起；不重复展示修订历史。要求、验收条件、变更原因及结果正文复用官方 Markdown 渲染，支持标题、列表、链接、代码及表格；长内容随工作区滚动，代码与表格保留横向滚动，避免内层纵向滚动拦截滚轮。结果摘要、正文、自检、失败说明及证据使用统一边框内容卡，结果保留对应要求版本；尚无结果时显示明确空态。三个面板保持挂载，切换不丢修订草稿及实时记录。修订要求或创建关联调整单点击后自动切到任务要求页并展开表单。等待原因、状态图标、真实交互与错误位于页签外，各页均可见；等待原因与操作保持紧凑单行，过长原因省略并可通过气泡完整读取，额外错误和恢复限制仍如实展示。详情底部不再展示「桌面 · 渠道已接收」、独立修订按钮及其重复提示，原执行会话入口继续保留。

- 重命名只改列表名称，保留原始要求、目标和消息。
- 轻量目标的勾选直接保存完成状态；历史执行条目的人工整理标记不等于成功送达或系统关单，取消标记不能自动重新执行。
- 对已完成结果的调整由用户找 Router 新开关联调整单，不改原单；结构性失败保持 waiting，用户回话可在原单继续或调整并保留历史结果；未关闭工单按原单继续、持续目标按恢复流程处理，不绕过授权或重放已生效动作。
- 工单归档与恢复展示复用同源具体清单，在原容器内联核对并可缩小子集；保留执行及处置历史，不联删成果。仍可能运行的条目默认排除，先另行确认停止并核实退出后重新预览。恢复展示不重启执行，取消按工单状态派生的自动归档，恢复后保留原三态并回到普通列表；生命周期权威见[工单清理与保留](../06-superagent/任务与执行.md#工单清理与保留目标)。其他条目的整理保留原业务语义。
- 修改持久化且校验版本，旧页面不能覆盖新名称或状态；切换分类和关闭详情保护未保存草稿。

详情保留问题答复、执行中要求修订、成果原稿、实际记录与原会话入口。Harness Worker 正常结束且有结果后直接保存完成并通知 Router，不设结束后的效果审核、自检补回合或循环核查。Router 自然表达并交付原来源，送达独立记录；表达或投递失败只处理对应阶段，不回退完成或重跑 Worker。结果不满意由用户找 Router 派关联调整单，原单与原稿保留。真实失败、待审批、待输入、暂停或中断保持等待与简短原因，失败不得显示为成功；显式续接按原会话处理，未知外部动作不盲重发。机制见[自校验与交付](../06-superagent/自校验与交付.md)。

## 执行会话入口

Worker 执行会话底层保留所属项目工作区或官方未分组归属，Router 主旁聊保留 SuperAgent 入口，Worker 与官方子代理在工作台侧栏及普通会话列表可见并可直接输入。用户从 SuperAgent 任务列表打开原工单详情，再进入内部执行查看区，切换同工单的 Worker/子 Worker 并返回；聊天消息不提供该跳转按钮。复用同一官方 session、消息渲染与输入，标题、归属和输入可用性取真实服务投影；缺失时说明无法定位并保留原工单入口。

用户通常由 Router 协调，也可直接向 Worker 或官方子代理发消息；执行会话保留真实过程查看与直接插话入口，直接输入同样纳入 Router 跟进协调，与主旁聊共用原工单输入账本、顺序和消费状态，不形成第二套任务要求。普通调整下一工具边界整份切换，不打断在途工具；暂停只收件不续跑，越权要求由 Router 确认或分新单。执行会话可手动收起；工单完成后仍保留同一会话、消息和成果入口，不自动归档或在查看时自动恢复，工作台与 SuperAgent 原工单均可定位原会话，不能删除执行证据或仍显示为活动执行。交互规则见[执行会话与直接插话](../06-superagent/对话交互.md#执行会话与直接插话)。

来自渠道会话的同单输入也复用这一本工单账，任务列表的状态、投递记录与关单事实均读取统一记录，不维护渠道侧副本。渠道会话在工作台列表带来源标记，可打开并直接回复；其呈现、适配器分工及实现边界统一见[链接与渠道](../06-superagent/链接与渠道.md)。

## 聊天任务线与执行动态

聊天中的助手看板沿用两行任务摘要：名称与任务更新时间、状态与当前活动。有可核实的子 Worker 时固定显示“子任务 已返回数/总数”，活动过长先截断，子任务数量保留。工具活动不改变列表排序，避免执行时任务持续跳位。

助手看板详情顶部只保留任务标题与带气泡的状态图标，不展示任务要求、验收条件或耗时；完整要求保留在原工单，任务管理内默认折叠。正文只保留一个实时「全执行记录」时间线，按时间倒序合并已保存的业务进度摘要、主 Worker 和直接子 Worker 的历史动态与当前状态，后续更新追加节点，不覆盖前面的工作过程；历史节点明确标注当时状态，时间显示到秒。动态从官方会话事件生成并可重建，每个 Worker 最多保留最近 64 条变化，重复活动合并，截断及不可恢复范围在记录范围内说明；不复制正文、工具参数或输出，完整过程仍打开同一官方执行会话。已结束 Worker 仍在同一条线上，不再分成当前状态、最近记录和已结束步骤区块。返回、刷新、继续、原执行会话及任务管理入口统一使用图标与共享 Tooltip，真实阻塞、问题和审批仍有可操作入口。

看板的刷新入口统一放在固定底部操作栏，进行中与等待工单共用同一入口，正文不再重复提供刷新。点击后仅旋转刷新图标，保留当前内容和操作焦点，不显示“更新中”或刷新进度段落；读取结束停止旋转，失败沿已有错误反馈如实说明。快速请求至少呈现一轮旋转，读取期间阻止重复请求；减少动态偏好下保留忙碌语义并关闭旋转。旧记录中已知的英文结果暂存状态只在展示与派生摘要中转为中文，不改写原始记录或推定保存成功。

重复的 step/end 不直接渲染为“完成一个执行阶段”；有证据的业务摘要优先，无摘要时只显示可核实的活动，不推测检查结论。不补造旧工单缺失的阶段历史；时间线范围及截断说明放在信息图标气泡，真实读取缺失或断线保留明确说明，完整原始记录通过同一官方执行会话读取。单个子任务结束只表示返回父 Worker；执行事实与送达分别记录，不单列 Worker 自校验，不设置独立内容核验阶段，不据工具成功或子任务结束推算工单完成，不显示猜测的百分比或剩余时间。工具参数、原始输出、模型思维与凭据不进入任务线。

列表、详情和首页摘要共用同一执行事实投影。客户端挂载官方 `benchgoExecutionFacts` Remote 合同，以官方 `RemoteSnapshotStream` 接收先订阅后快照及后续增量：首次直接使用快照的工单，后续按工单 ID 合并事件并定向读取原账。连续水位去重，缺口重开快照；订阅代次及单工单请求序号阻止迟到响应覆盖新事实。持续目标与整理展示变更也由事实事件触发。健康连接不做周期性全量拉取；连接不可用时才采用有界退避补偿，失败保留最近记录，页面重新可见时重连。工具动态不改领域更新时间或工单终态，不反复重排行；无变化行保留对象与 DOM。日常增量与后台重连静默：已有有效快照时，临时传输故障保留原列表、详情及审核会话，不在内容区提醒或闪烁错误；有界退避与可查诊断继续保留。首次无数据读取失败、领域错误和用户主动刷新或操作失败明确反馈真实原因，不把未知当作空列表或正常状态，不周期闪烁“已同步”。

主聊、旁聊及项目处理会话旁的看板显示全局「进行中 / 等待 / 已完成」有效工单，不提供“本会话 / 全部”切换；全局工单管理保留全部账本、持续目标及归档筛选。窄屏看板和遮罩覆盖完整聊天区域，包括底部输入框及发送操作；打开时底层聊天不可点击或获得键盘焦点，关闭后恢复交互与触发按钮焦点。主聊天建立独立层叠上下文，消息操作与发送容器不能越过看板遮罩。工单来源仍取可信 `Mandate.source.sessionId`，不依标题猜来源。暂停、停止、终态或过期数据在同一记录区标明记录时点与真实限制，不能将旧“运行中”冒充当前状态，也不另建“最近执行记录”区域。重启后无法恢复的历史或无法关联的子任务明确提示记录不完整，不把未观测当作零任务。

等待只展示真实审批、输入、暂停、中断及执行错误原因，不再显示效果审核、核查次数、下次核查时间或自动恢复进度。结果保存问题不转用户等待，不提供要求用户处理版本、归属、证据或点击继续补存的入口；保存故障在现有详情如实说明，系统自动补存，目标及实施边界见[结果保存无阻断](../06-superagent/自校验与交付.md#结果保存无阻断)。Harness Worker 正常结束且有结果后直接保存完成并通知 Router，结果不满意由用户找 Router 派关联调整单。停止后先说明后续动作已拦、正在结束执行，执行端确认退出后才显示已停止；显式要求续接才处理原会话执行，不影响已有成果自动保存。具体规则统一见[自校验与交付](../06-superagent/自校验与交付.md)。

详情中的“前往任务管理”定位原工单，复用提问答复与修订入口。普通调整插话即记入原工单输入账本，后台编号记账，Worker 在下一工具边界把新要求整份切换生效，不打断在途工具，不增加确认或先暂停/停止流程；暂停期间只收修订，不自动续跑。叫停和收权立即拦截后续动作；只有超 Mandate 扩权才由 Router 确认并生成新授权版本。任务线只读展示执行事实，不另建任务控制流程。执行观测边界见[任务与执行](../06-superagent/任务与执行.md#执行动态观测)。

## 实现与验收边界

共享摘要行、详情容器和执行会话入口已有实现，业务状态以服务返回为准。任务详情的“查看执行会话”在 SuperAgent 内打开同一官方 session；查看区提供返回、原工单、同工单 Worker/子 Worker 切换，复用官方消息与输入。Worker 直接输入复用原工单输入账与原 Run，官方子代理遵循官方会话输入；暂停、停止、已完成和失效执行按真实状态提供操作与原因。冷会话续接及完成后调整仍须实际验收。加载、读取失败重试和记录不可定位均有明确反馈；返回保留主旁聊草稿与滚动，不新建会话、不恢复归档或重启执行。底层工作区、Worker 与官方子代理普通列表可见及输入账本的权威规则见[执行会话与直接插话](../06-superagent/对话交互.md#执行会话与直接插话)。

结果持久化、Router 通知与原来源投递沿现有服务接线；本轮移除完成后的效果审核和循环核查，改为正常结束有结果即保存完成，具体实现与验证范围见[自校验与交付](../06-superagent/自校验与交付.md#实现与验收边界)。验收核对三态、真实等待原因、成果入口与关联调整单；提问、审批、暂停、停止及显式续接保留原身份。四态、触屏、主题与重启按下列条件核验，服务端测试或合成渲染不代替实际安装验收。

验证列表入口、触屏操作、详情返回、长内容、停止、问题答复、修订、重命名、完成标记和删除；确认聊天容器消息无“查看执行会话”入口，从任务列表打开工单详情仍能进入原执行会话；检查并发版本冲突及未保存草稿保护。逐入口检查[四态实际渲染](前端视觉规范.md#四态)，浅渲染通过不代表真实交互完成验收。

动态任务线已有组件与运行时接线，需验证主、子 Worker 状态原位更新、子任务失败、执行完成与 Router 表达交付区分、结构性失败自然说明送达后等待及原单续做、暂停旧记录、读取失败重试，以及窄屏和明暗主题。补验完成信号后 Router 主动提醒、自选摘要或完整回复、详情原稿可查、无固定报告/标题前缀/状态硬文案，生成与投递失败均待交付且不重 Worker。补验Worker 与官方子代理在普通列表、项目和未分组中可见并可直接输入，Router 保留专属入口，任务详情在 SuperAgent 内打开同一执行会话并可切换子 Worker、直接插话共用输入账本、下一工具边界整份切换且不打断在途、暂停不被修订唤醒、越权交 Router、完成后保留且不自动归档、已完成结果调整经 Router 新开关联单和投递重试不重跑任务。审批另验具体动作复用原任务审核、同一已审动作不重复审批、独立授权管理及网站长期许可已删除；实际审核边界遵循[权限规则](../06-superagent/任务与执行.md#权限与对外审批)。浏览器组件渲染、正式桌面真实工单运行与海量任务性能分别验收，不能互相替代。

执行事实客户端、容器内工单详情与审核聚合已实现。定向验证覆盖事件去重、缺口补偿、代次与请求序号防迟到、重开与断线退避；Chromium 组件环境覆盖四态、窄屏明暗、列表 DOM/滚动/焦点稳定、详情返回，以及官方 PendingApproval/ApprovalCard 的双入口竞争与旧卡失效。这些是受控客户端与官方组件验证，安装版真实档案、真实 Worker 重启恢复及海量任务性能仍须独立验收，不能据此宣称真实运行全项通过。
