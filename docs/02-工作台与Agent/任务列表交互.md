# 任务列表交互

板块入口见[工作台与 Agent](设计.md)。 本文维护任务列表与详情的用户操作；调度、授权、自校验与交付机制见[SuperAgent](../06-superagent/设计.md)。

## 列表与详情

主对话侧栏的任务卡采用两行：名称与时间、状态与摘要。待处理与进行中分别分组；整项在同一看板容器内打开详情，长内容在列表中省略、在详情中完整显示。工单详情不使用弹窗，返回时保留筛选、展开、滚动与原行焦点；列表 DOM 保持挂载。详情将状态并入标题，展示耗时、任务要求、当前摘要、关键工作流、子 Worker 返回情况与真实等待对象，正文独立滚动、操作固定在底部。暂停、恢复、停止沿用原领域接口，失败保留原记录；执行会话入口打开同一真实 session，不另设“查看记录”按钮。

聊天看板保留「任务」「身份」，增加「审核」；工作台「任务」分类继续保留原审核入口。两处聚合同一批官方批准/拒绝请求，包含高危动作及 `assistant_ticket_change` Mandate 扩权，普通 question 仍属于等待答复。审核列表显式进入同容器详情，返回保留滚动与焦点；真实计数来源未连接完整或失败时显示未知，不把未知当零。详情复用原官方卡、请求身份与生命周期，冻结对象及内容只做脱敏展示；请求处理、撤回或失效后不自动选择另一张批准卡。审核只作聚合兜底，不替代 Router 提醒，不作成果验收；三层呈现、来源归属与原官方审批卡规则统一见[对话交互](../06-superagent/对话交互.md#权限与安全输入交互)。这里的任务卡不同于[视觉规范](前端视觉规范.md#四态)中的单行会话导航。

工单状态与刷新、停止、执行会话入口由任务列表及详情统一承载。聊天容器不展示通用等待/系统状态块、重复问题正文和上述操作；真实提问保留原消息答复入口。Worker 待批先由 Router 自然提醒，原官方卡挂在提醒处随对话流；审核 Tab 聚合同一请求并提供定位入口，原官方会话卡仍可查，一处作答后其他入口同步失效。聊天顶部不另堆固定授权块或弹窗。

工单、持续目标、待处置评估复用 `plugins/superagent/client/task-list.jsx` 的摘要行与详情容器。业务列表包含完成标记、名称、最多两行摘要和右侧图标操作；标题与摘要都可进入详情。列表与看板标签关联同一内容区；搜索支持内置清除与 Escape，清除后焦点保留在搜索框。未同步时不编造工单数量，归档筛选在空、加载和错误状态仍可达。暂停、继续、关联调整、重命名及适用的整理操作提供可访问名称与悬停说明，触屏保留入口；工单整理使用归档与恢复展示入口，不以“删除”冒充归档。

工作区 → 任务按最近活动排序，最近在前：优先使用有效 `updatedAt`，缺失或无效时回退有效 `createdAt`；时间相同保留来源次序，均无有效时间的条目排在末尾。任务管理查询先按最近活动取最新 1000 条，再由统一任务投影提供顺序，工单列表、搜索结果与看板各列沿用该顺序；不按执行状态或人工完成标记额外置顶，也不以工具动态更新时间代替任务更新时间。待处置评估保留既有游标分页，在返回页内沿用这一顺序。

工单确认关单后自动归档，默认活动列表不再展示；提供“已归档”入口查询原单和成果，归档记录仍按最近活动排序。自动归档从同一工单的关闭状态派生，手动清理使用同单展示元数据，不创建第二份记录，也不覆盖 completed/failed 终态或删除输入、结果和回执。生成或投递失败的待交付、等待答复、暂停及仅叫停的工单不因此自动归档；失败原单经用户明确续做后按新要求版本与整理标记重新投影。筛选归档范围须先于分页和数量截断，避免历史关闭工单挤掉在办任务。关联执行会话使用官方归档，查看归档详情或会话不重新执行。

- 重命名只改列表名称，保留原始要求、目标和消息。
- 人工完成是整理标记，不等于成功送达或系统关单；取消标记不能自动重新执行。
- 对成功交付结果的调整新开关联调整单，不改原单；结构性失败关单后，用户回话可在原单继续或调整并保留历史结果；未关闭工单按原单继续、持续目标按恢复流程、准入评估按重新评估流程处理，不绕过授权或重放已生效动作。
- 工单归档与恢复展示复用同源具体清单，在原容器内联核对并可缩小子集；保留执行及处置历史，不联删成果。仍可能运行的条目默认排除，先另行确认停止并核实退出后重新预览。恢复展示不重启执行，原自动归档终态仍留在归档；生命周期权威见[工单清理与保留](../06-superagent/任务与执行.md#工单清理与保留目标)。其他条目的整理保留原业务语义。
- 修改持久化且校验版本，旧页面不能覆盖新名称或状态；切换分类和关闭详情保护未保存草稿。

详情保留问题答复、要求修订、成果原稿、实际证据、文件检查点、目标关联与准入评估处置入口。不设独立任务内容验收：每次派工固定要求 Worker 在原上下文快速轻量自检，优先适用的机械测试、构建和输出检查；保存原稿后向 Router 发完成信号。用户始终与 Router 对话，由其主动自然提醒已完成，自选摘要或完整回复再交付原来源，不固定报告、标题前缀或系统状态文案；详情展示的原稿不作为重派或验收入口。成功回复确认送达后 completed 关单，正常原来源交付免审批；生成或投递失败保留待交付，只重试表达或补投已生成回复，不重跑 Worker。偶发故障退避；结构性失败由 Router 按实际尝试、原因与恢复条件自然说明，送达后 failed 关单，用户回话可原单续做或调整。状态说明无硬文案兜底，真实状态留在任务列表与详情。缺少信息、权限或范围决定时显示真实等待状态；执行超时先核实运行并从 checkpoint 原单恢复，外部效果未知先核实、禁止盲重跑。具体机制见[自校验与交付](../06-superagent/自校验与交付.md)。目标仍可跟踪，用量仍可统计；金额、执行时长和 Goal 补时预算闸门已移除，不再展示旧预算操作。

## 执行会话入口

实际 Worker 执行会话显式归入所属项目的工作区会话列表，不涉及项目的任务归官方「未分组」（按最近活动排序），均带工单标记，与用户自建对话区分。用户从任务列表打开工单详情，再进入执行会话；聊天容器消息不提供“查看执行会话”入口。任务详情与工作区会话列表均跳到同一个官方 session，不复制出第二份聊天。会话标题、工单归属与执行状态取真实记录，缺失时提示无法定位并保留工单详情入口。

用户始终与 Router 对话；执行会话保留真实过程查看与直接插话入口，直接输入同样纳入 Router 跟进协调，与主旁聊共用原工单输入账本、顺序和消费状态，不形成第二个对话对象。普通调整下一工具边界整份切换，不打断在途工具；暂停只收件不续跑，越权要求由 Router 确认或分新单。执行会话可收起；工单确认关单后自动归档，关联执行会话通过官方机制归档，保留同一会话、消息和成果入口，不能删除执行证据或仍显示为活动执行。交互规则见[执行会话与直接插话](../06-superagent/对话交互.md#执行会话与直接插话)。

来自渠道会话的同单输入也复用这一本工单账，任务列表的状态、投递记录与关单事实均读取统一记录，不维护渠道侧副本。渠道会话在工作台列表带来源标记，可打开并直接回复；其呈现、适配器分工及实现边界统一见[链接与渠道](../06-superagent/链接与渠道.md)。

## 聊天任务线与执行动态

聊天中的助手看板沿用两行任务摘要：名称与任务更新时间、状态与当前活动。有可核实的子 Worker 时固定显示“子任务 已返回数/总数”，活动过长先截断，子任务数量保留。工具活动不改变列表排序，避免执行时任务持续跳位。

打开工单详情，以简约纵向任务线展示主 Worker 与缩进的直接子 Worker：当前动作、运行、等待、已返回、失败、停止或未知。当前与异常步骤直接显示，已结束步骤默认折叠、可展开查看；无执行记录时不渲染空步骤占位，记录不完整的真实限制仍保留说明。时间在执行动态处汇总，单个子任务结束只表示返回父 Worker；执行、Worker 自校验、待交付与已送达分别展示，不设置独立内容核验阶段，不据工具成功或子任务结束推算工单完成，不显示猜测的百分比或剩余时间。工具参数、原始输出、模型思维与凭据不进入任务线。

列表、详情和首页摘要共用同一执行事实投影。客户端挂载官方 `benchgoExecutionFacts` Remote 合同，以官方 `RemoteSnapshotStream` 接收先订阅后快照及后续增量：首次直接使用快照的工单，后续按工单 ID 合并事件并定向读取原账。连续水位去重，缺口重开快照；订阅代次及单工单请求序号阻止迟到响应覆盖新事实。持续目标与整理展示变更也由事实事件触发。健康连接不做周期性全量拉取；连接不可用时才采用有界退避补偿，失败保留最近记录，页面重新可见时重连。工具动态不改领域更新时间或工单终态，不反复重排行；无变化行保留对象与 DOM。日常增量与后台重连静默：已有有效快照时，临时传输故障保留原列表、详情及审核会话，不在内容区提醒或闪烁错误；有界退避与可查诊断继续保留。首次无数据读取失败、领域错误和用户主动刷新或操作失败明确反馈真实原因，不把未知当作空列表或正常状态，不周期闪烁“已同步”。

主聊、旁聊及项目处理会话旁的看板默认显示全部活动工单与持续目标，不再提供“本会话 / 全部”切换；全局工单管理保留全部账本及归档筛选。工单来源仍取可信 `Mandate.source.sessionId`，不依标题猜来源。暂停、停止、终态或过期数据明确显示为最近执行记录，不能将旧“运行中”冒充当前状态。重启后无法恢复的历史或无法关联的子任务明确提示记录不完整，不把未观测当作零任务。

待核实直接展示真实原因、核查次数、下次核查时间和长期无结论异常；缺恢复证据时如实说明限制，不显示让用户自行核实的提示或虚构自动核查进度。停止后先说明后续动作已拦、正在结束执行，超过确认阈值则明确执行端未确认退出；实际确认后才显示已停止。主动通报与自主处置由 Router 通过原对话完成，具体规则统一见[待核实通报与自主处置](../06-superagent/自校验与交付.md#待核实通报与自主处置)。

详情中的“前往任务管理”定位原工单，复用提问答复、暂停与修订入口。普通调整插话即记入原工单输入账本，后台编号记账，Worker 在下一工具边界把新要求整份切换生效，不打断在途工具，不增加确认或先暂停/停止流程；暂停期间只收修订，不自动续跑。叫停和收权立即拦截后续动作；只有超 Mandate 扩权才由 Router 确认并生成新授权版本。任务线只读展示执行事实，不另建任务控制流程。执行观测边界见[任务与执行](../06-superagent/任务与执行.md#执行动态观测)。

## 实现与验收边界

共享摘要行、详情容器和执行会话入口已有实现，业务状态以服务返回为准，不能用人工整理标记替代执行结果或交付状态。项目执行会话显式 attach 官方工作区，无项目使用官方未分组列表；工单与渠道标记共用同一组件及官方会话投影，在官方行扩展槽和 BenchGo 自有侧栏子槽呈现；自有侧栏从官方目录补齐未分组并合并到“最近”，不把 Worker 目录挂到默认项目。详情通过官方导航打开同一 session。关单后调用官方归档；用户主动查看历史时先恢复会话展示，再进入原 session，不复活工单或执行。入口包含打开中、不可定位和失败反馈。

固定轻量自检、持久投递与送达关单、原单恢复和插话整份切换已有服务端接线；不设独立任务内容验收链。Worker 保存原稿并通知、Router 主动自然表达与原路交付的机制及实现边界统一见[自校验与交付](../06-superagent/自校验与交付.md#实现与验收边界)。验收覆盖主路径、提问续跑、叫停、插话整份修订、真实渠道与高危审批，不能以服务端测试或合成数据的浏览器渲染代替实际桌面验收。四态、触屏、主题与重启按下列条件核验。

验证列表入口、触屏操作、详情返回、长内容、停止、问题答复、修订、重命名、完成标记和删除；确认聊天容器消息无“查看执行会话”入口，从任务列表打开工单详情仍能进入原执行会话；检查并发版本冲突及未保存草稿保护。逐入口检查[四态实际渲染](前端视觉规范.md#四态)，浅渲染通过不代表真实交互完成验收。

动态任务线已有组件与运行时接线，需验证主、子 Worker 状态原位更新、子任务失败、自校验与 Router 表达交付区分、结构性失败自然说明送达关单及原单续做、暂停旧记录、读取失败重试，以及窄屏和明暗主题。补验完成信号后 Router 主动提醒、自选摘要或完整回复、详情原稿可查、无固定报告/标题前缀/状态硬文案，生成与投递失败均待交付且不重 Worker。补验项目列表/官方「未分组」（按最近活动排序）列表工单标记与任务详情均跳同一执行会话、直接插话共用输入账本、下一工具边界整份切换且不打断在途、暂停不被修订唤醒、越权交 Router、结束后收纳、成功交付调整新开关联单和投递重试不重跑任务。审批另验支付购买、改密码、删账号、另行对外发送逐次审批不被整站覆盖，原来源回复免审；整站范围、期限、审计和撤销遵循[权限规则](../06-superagent/任务与执行.md#权限与对外审批)。浏览器组件渲染、正式桌面真实工单运行与海量任务性能分别验收，不能互相替代。

执行事实客户端、容器内工单详情与审核聚合已实现。定向验证覆盖事件去重、缺口补偿、代次与请求序号防迟到、重开与断线退避；Chromium 组件环境覆盖四态、窄屏明暗、列表 DOM/滚动/焦点稳定、详情返回，以及官方 PendingApproval/ApprovalCard 的双入口竞争与旧卡失效。这些是受控客户端与官方组件验证，安装版真实档案、真实 Worker 重启恢复及海量任务性能仍须独立验收，不能据此宣称真实运行全项通过。
