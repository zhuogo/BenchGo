# 任务列表交互

板块入口见[工作台与 Agent](设计.md)。 本文维护任务列表与详情的用户操作；调度、授权、验收与交付机制见[SuperAgent](../06-superagent/设计.md)。

## 列表与详情

主对话侧栏的任务卡采用两行：名称与时间、状态与摘要。整项可打开详情，长内容在列表中省略、在详情中完整显示；停止入口放在详情，不另设“查看记录”按钮或“审核”分页。这里的任务卡不同于[视觉规范](前端视觉规范.md#四态)中的单行会话导航。

工单、持续目标、待处置评估复用 `plugins/superagent/client/task-list.jsx` 的摘要行与详情容器。业务列表包含完成标记、名称、最多两行摘要和右侧图标操作；标题与摘要都可进入详情。暂停、继续、重开、重命名、删除提供可访问名称与悬停说明，触屏保留入口。

- 重命名只改列表名称，保留原始要求、目标和消息。
- 人工完成是整理标记，不等于自动验收通过；取消标记不能自动重新执行。
- 再次执行使用原有工单重开、目标恢复或重新评估流程，不绕过授权与验收。
- 删除只移出列表，保留执行及处置历史；仍可能运行的条目须先安全停止。
- 修改持久化且校验版本，旧页面不能覆盖新名称或状态；切换分类和关闭详情保护未保存草稿。

详情保留问题答复、要求修订、实际证据、文件检查点、目标关联与评估处置入口。工单通过自动验收后交付原来源，无需用户重复确认；缺少信息、权限或范围决定时显示真实等待状态。目标仍可跟踪，用量仍可统计；金额、执行时长和 Goal 补时预算闸门已移除，不再展示旧预算操作。

## 实现与验收边界

共享摘要行与详情容器已有实现，任务的业务状态仍以实际服务返回为准，不能用人工整理标记替代验收结论。

验证列表入口、触屏操作、详情返回、长内容、停止、问题答复、修订、重命名、完成标记和删除；检查并发版本冲突及未保存草稿保护。逐入口检查[四态实际渲染](前端视觉规范.md#四态)，浅渲染通过不代表真实交互完成验收。
