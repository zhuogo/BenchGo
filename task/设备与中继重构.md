## 0.1. 品牌、仓库与包边界

- [ ] 统一公开项目名为 BenchGo，GitHub 目标仓库为 `BenchGo/benchgo`；仓库改名后保留旧地址跳转并更新所有安装链接。
- [x] 固定包边界：`benchgo` 是工作台，`@benchgo/relay` 是中继服务器。不发布 `@benchgo/server`。工作台可以连接外部中继，不安装中继服务。

## 1. 多路线设备模型

- [x] 设计并实现设备路线结构：局域网、公网、中继、优先级、证书指纹和健康状态。

- [ ] 实现路线探测：真实 TLS/身份校验和轻量工作台健康请求。
- [x] 实现顺序：局域网直连 → 公网直连 → 中继池按优先级。
- [x] 限制单次连接尝试、超时、退避和冷却，避免路由循环与重复写请求。
- [ ] 主中继恢复后新连接回主，不迁移正在运行的会话。
- [x] 区分设备在线、中继在线、路线可达和工作台可用；中继探测成功/失败会更新健康与 10 秒冷却状态。

## 4. 端口、反代和证书

- [ ] 提供域名 DNS、端口和外部真实可达性检查。

- [ ] IP、域名、非标准端口和已有反代分别做集成测试。
