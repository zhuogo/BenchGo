本页介绍浏览器工作台的服务端，不是 Linux 桌面安装器。当前仅支持 Ubuntu / Debian x64 与 systemd，不支持 ARM64。首次安装需联网准备固定版本的官方 Harness，必要时准备 Node.js 24.9+，插件依赖随包提供。

推荐：添加 SSH 服务器

在已有 BenchGo 的「设备中心」打开「设备」页签，点击「我的设备」区域的「添加设备」，选择「安装到服务器」，填写 SSH 连接信息并按引导确认服务器身份、完成安装或连接。日常使用优先采用此入口；以下独立压缩包适用于维护者。

提前准备部署资源（v0.1.5）

在「安装到服务器」中点击「准备离线部署资源」，可先选择下载源、准备并校验资源，再填写服务器信息继续安装。已有完整资源会校验后复用，无需为准备资源先提交 SSH 凭据。

准备过程显示实际进度，失败可重试；资源准备阶段可取消，进入远端上传和安装后不再提供此取消操作。关闭面板会让已开始的准备任务在后台继续。旧版没有该入口时，可先升级到对应新版，或继续使用原 SSH 引导与下方压缩包步骤。

使用服务端压缩包

从下载页获取压缩包与同名 .sha256，核对校验值，解压并进入版本目录。将命令中的「版本」替换成实际版本号。

sha256sum -c benchgo-<版本>-linux-server.tar.gz.sha256
tar -xzf benchgo-<版本>-linux-server.tar.gz
cd benchgo-<版本>-linux-server
(umask 077; bash install.sh github connect > connection.json)

github 可按脚本支持改为 mirror。以日常用户运行，需系统权限时按提示处理。connection.json 含私有连接凭据，不要公开、提交 Git 或随反馈发送。服务默认仅监听 loopback，请通过可信 SSH 隧道连接，不应把内部端口直接暴露到公网。

更新

备份配置与工作数据，核对新包来源，解压进入新版本目录执行：

(umask 077; bash install.sh github update > update-result.json)

检查命令结果与实际服务状态后继续使用。失败时检查网络、系统架构、systemd 与磁盘空间，不要公开敏感连接结果。

工作台与独立 Relay

工作台的统一命令入口见安装指南。BenchGo Relay 使用独立的 benchgo-relay 包，只转发已授权设备的流量，不包含完整工作台，也不会被工作台命令自动安装。

首次部署 Relay 优先使用设备中心的「添加中继」SSH 向导处理服务器、证书与连接配置。已有有效的证书、密钥与 relay.json 后，维护者可在 Linux/systemd 服务器上以 root 身份执行以下独立入口；将配置路径替换为实际绝对路径：

npm install -g benchgo-relay@0.1.1
benchgo-relay install --config /path/to/relay.json
benchgo-relay status

此安装命令创建 systemd 服务，不替你完成首次公网证书申请或生成有效连接配置，也不扩大到 Windows / macOS 中继安装。升级 npm 包本身不会重新创建已有服务；请保留原配置，按实际服务状态检查连接。
